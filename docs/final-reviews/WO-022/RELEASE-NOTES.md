## Release overview

DotLn `v0.11.0` is the minor release above the published `v0.10.1`. It makes a sense something a loadout equips, an envelope grants, an environment mounts, and an audit records. Three perception supports compile in the pure compiler: Beacon Sight decodes the individual Beacon codebook fields and a whole-second modification time, Fine Spectrum adds the sub-second timestamp, and Composition adds the separately mounted phase-group codeword. A role without the sense cannot compile the sweep, sees no sweep affordance in the sparse twin, is refused by the existing Observe guard if it tries anyway, and leaves a `CommandRefused` event naming its envelope without a single metadata read. A role with the sense learns exactly the codebook fields and nothing else: the mounted reader performs only known-name status calls on the host's declared addresses, never a directory listing, a content read, or an extended-attribute read, and the log whitelist rejects anything more. Sparse v3 Beacons add a non-secret key epoch and a 16-bit keyed residue so a host can tell its own projections from naive forgeries, and a deterministic mounted verifier completes the walking skeleton from a capsule that a test proves excludes implementer prose. Audience: operators running several agent worktrees who want cheap, authorized, metadata-only awareness of each other's lifecycle state, and engineers extending the composition system with perception. Native model verification, general write-capable workers, and any UI remain planned.

## Read before upgrading

- **New live sweep requests must declare senses and an environment.** `BeaconSweepRequest` gains `senses` (`beacon-sight`, optionally `fine-spectrum` and `composition`) and `environment` with `profileId: "beacon-perception-v1"`, a matching `audience`, finite `mounts` (each with a stable `mountId`, an absolute `path`, `access: "beacon-metadata"`, a `family`, and the complete `addresses` array), and empty `writableSurfaces`, `modelTools`, and `narrativeSurfaces`. A host-request file for `npm run worktree -- constellation --agent` written before this release is refused with `CommandRefused` even when its envelope allows Observe; add the two fields. `LiveReactorDriver.feed` refuses a `BeaconSweepRequested` draft without `perceptionVersion: 1`; use `observeBeaconSweep`.
- **`observeBeaconSweep` changes signature.** The worktree-list argument is gone; a custom reader and the optional key arrive in a trailing options object. A custom reader must return `observations` plus `groups`, where `groups` is the sensed group set or the literal `not-sensed`.
- **Observation payloads carry new fields and coarser time by default.** `BeaconObserved` gains `perceptionVersion: 1`, `groups`, and `keyEpoch`; every individual observation carries `provenanceCheck` and `fineSpectrum`. Without Fine Spectrum, `mtimeNs` is omitted and `mtimeMs` is floored to a whole second before persistence, so `age` for such sweeps is computed from the coarse value. Replay rejects an observation with extra fields, a sub-second value without Fine Spectrum, or a decoded state that disagrees with its size.
- **Framing tag 3 in the individual family now decodes as v3.** A new sweep that reaches a v3 codeword decodes its inherited v2 fields plus `keyEpoch` and `authenticator` and labels it `residue-matched`, `forged-provenance`, or `unverifiable-provenance`; v1 and v2 Beacons keep their bytes and decode as `unauthenticated-legacy`. Historical observation events without `perceptionVersion` replay through the legacy decoder, where tag 3 stays `unknown-codebook`. The phase-group family is still selected only by its own directory and decoder.
- **`DOTLN_BEACON_KEY_FILE` is optional and, once configured, has no fallback.** Without it, lifecycle transitions keep emitting dense v2 projections and an agent sweep labels any v3 it reaches `unverifiable-provenance`. With it, `resume` transitions emit sparse-required v3 and agent sweeps run the keyed check. The file must be a mode-0600 regular file at a canonical path outside every Git checkout. An invalid key, a non-sparse destination, or a failed maximum-size probe surfaces as the documented optional-emission warning after the transition is recorded; no v2 file is written instead. Rotation increments the epoch, retains no old key, and refuses at epoch 255. Never place the key or its bytes in a request file, prompt, fixture, or log.
- **Restricted Beacon directories are search-only at rest.** `issueBeaconSession` creates its random directory at mode 0111; listing it fails with `EACCES` while a known basename still answers `stat`. `emitControlBeacon` restores owner access only around publication. Worktree teardown restores access through `prepareBeaconDisposal` after its existing gates, and the Beacon fixture snapshot no longer descends into directories without owner read.
- **The 16-bit residue is a weak signal, not authentication.** It detects naive or accidental false host provenance and errors; it does not prove authorship, identify an attacker, or resist enumeration by an actor with path and decoder access. Mounts and the Observe guard remain the security boundary, same-user processes remain outside it, and separate OS-user isolation is the preserved stronger local option.
- **The agent constellation text changed shape.** `worktree constellation --agent` now prints `renderBeaconPerception`: one JSON line for the individual set plus one each for equipped Fine Spectrum and Composition, without the `fresh`, `stale`, `clock-skew`, and group-count rows. The human `worktree constellation` keeps those rows and gains a trailing provenance-check column.
- **Component versions and artifact identity.** `@dotln/compiler` is `0.4.0` and `@dotln/skeleton` is `0.10.0`; `@dotln/kernel` stays `0.2.1`, and the event-envelope schema and compiled-program contract are unchanged. `artifactIdentity.compilerPackageVersion` now reads `0.4.0` while every semantic hash and component definition hash is unchanged. The artifact-identity evidence helper writes and checks its current edition under `docs/evidence/WO-022/artifact-identity/`; the four WO-029 receipts are retained as historical bytes and are no longer regenerated or byte-checked.

## Substantive changes

- **Compiler: perception supports (`@dotln/compiler` 0.4.0).** `beaconSenses` defines Beacon Sight, Fine Spectrum, and Composition as ordinary support facets on the `observe` tag. Each declares its required host capability (`beacons.individual.metadata` or `beacons.group.metadata`), no authority change, a `BeaconObserved` evidence-schema emission, zero prompt tokens, and a measured runtime cost of one context line per sweep. `beaconSenseLoadout` builds the perception-slot graph with the sweep active and the requested links; `compileBeaconSenses` compiles it against an explicit environment, returning `ACTIVE INACTIVE` when Beacon Sight is not equipped and the existing `SUPPORT INACTIVE` diagnostic, with the exact missing capability and a `provide-capability` correction, when the mount is absent. Grants never edit the supplied envelope.
- **Skeleton: host environment profile and perception declaration.** `beacon-perception-v1` joins WO-009's `fixture-inspection-v1` as an explicit execution-environment profile. `declareBeaconPerception` derives compilation capabilities from the host's mount record alone, refuses malformed profiles, bounds the set to twelve individual addresses and one group, and projects a path-free declaration into the request event; physical paths never enter the log.
- **Skeleton: permission gate, sparse twin, and reader.** The reactor's sweep decision runs the existing Observe authorization and then `perceptionGate`, which recompiles the declared senses and refuses with a trace naming the envelope when Beacon Sight or its mount is missing; refusals persist `CommandRefused` before any filesystem call. `projectBeaconSparseTwin` runs the same decision and renders zero or exactly one `sweep` action with the compiled support costs. `readMountedBeacons` performs known-name `lstat` calls only; `projectSenseObservation` whitelists the edge result and floors time without Fine Spectrum; `validatePerception` re-checks the address set, field set, numeric shapes, decoded state, and residue-label consistency on every append and replay; `renderBeaconPerception` emits one physical line per equipped channel.
- **Skeleton: Beacon codebook v3, key handling, and sparse storage.** `beacon-v3-codebook.mjs` declares the field order, radices, `MAX_V3_CODE` (19,327,352,831), `MAX_V3_LOGICAL_BYTES` (1,236,950,589,434), and `MAX_V3_ALLOCATED_BLOCKS` (8) as data, encodes and decodes with `bigint`, and is equality-tested against the normative block in the domain model. `beacon-provenance.mjs` creates, opens, and rotates the external key file and computes the residue as the first two bytes of HMAC-SHA-256 over the documented preimage. `beacon-v3-fs.mjs` probes the destination volume with the full maximum before any emission, verifies the zero tail and allocated blocks, and refuses dense storage, a lowered ceiling, an oversized block, a foreign device, or an unrepresentable size before creating a destination or staging file.
- **Skeleton: control Beacon host.** `issueBeaconSession` creates its restricted directory at 0111; `beaconSessionMount` returns the trusted host's mount record while `restrictedBeaconBriefing` remains the only textual disclosure; `emitControlBeacon` accepts an optional key and emits v3 through the storage probe, restoring 0111 even on failure; `prepareBeaconDisposal` restores owner access for teardown and hands back a restorer for failure; `decodeSignalSize` routes framing tag 3 to the v3 decoder while `decodeLegacySignalSize` preserves the pre-WO-022 meaning for unversioned replay; group counts and phase ranking include host-projected v3.
- **Skeleton: mounted verifier.** `ScenarioVerifier` is an injectable interface on `runScenario` and `finishScenario`; `MountedBeaconVerifier` runs an authorized sweep for the verifier audience and evaluates a detached JSON capsule of candidate paths, independently projected inventory fields, and the sensed perception, so implementer summaries, evidence strings, and log prose are structurally absent from its inputs. It is deterministic; native model verification remains WO-010.
- **Lifecycle scripts.** `projectControlBeacon` and the agent constellation read `DOTLN_BEACON_KEY_FILE` for the command's scope only; `worktree finish` restores restricted-directory access before `git worktree remove` and re-restricts on failure; the Beacon fixture installs the three new modules; the artifact-identity evidence helper writes its current edition under WO-022.
- **Tests.** Nine WO-022 tests: the compiler fixture for criterion 1; the algebraic and boundary suite with 589,824 representative residue round trips and the normative-block equality; the maximum-size sparse fixture with a `Buffer.alloc` witness and unsupported-host refusals; the dynamic external-key suite covering forged, replayed, rotated, never-issued, and exhausted epochs; the nine-shape refusal and affordance suite with zero reads; the legacy and pre-sense replay suite; the metadata-only channel suite over a real 0111 mount with garbage content, an extended attribute, an unrelated file, and tamper cases; the blinded walking-skeleton verifier; and the canonical control-log re-derivation through the production emitter. The WO-021 suites move to the new request shape, the reactor import test admits the two pure modules and forbids Node built-in imports in them, and the artifact-identity test pins every historical field while the package version advances.
- **Documentation.** The domain model gains the sense rows, the normative v3 block with its injectivity argument and preimage, and the forward-migration paragraph; the architecture document gains the Beacon profile and the composition-system example; the interfaces document gains the helmet supports and the sparse-twin projection; the audit document gains the 0111 behavior, the metadata-leak note, and the weak-residue statement; the execution guide gains the host request contract, restricted mounting, and key handling; the IR compatibility document, roadmap, roles lens, planning map, publication index and both edition locks, root README release block (`v0.11.0` above `v0.10.1`), both package READMEs, the work order's completed activation header, and the ledger's dated section are updated. Executor evidence, the fresh host probe, and the focused test transcript are under `docs/evidence/WO-022/`; the WO-029 evidence README carries a dated migration note for the relocated artifact-evidence edition.
