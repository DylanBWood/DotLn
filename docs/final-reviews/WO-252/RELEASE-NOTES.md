## Release overview

A registered target now closes on its first attempt when the instance declared its build output once: a `disposable` entry may carry `**` as a whole segment and `*` within one segment, so one class line such as `["**/node_modules", "**/.vite", "**/.vitest"]` covers every project's caches in an Nx workspace with Vitest, where the close used to refuse sixteen nested caches and be rerun by hand. The close also owns what the kit itself wrote in the target: the session journals and change reviews it left there move into main's retained lane for the order, and a released writer directory, the `.runtime/.metadata_never_index` marker, the files of every harness snapshot the kit installed and the temporary-root ledger are deleted instead of being refused as undeclared, while an operator note, a stray `.env`, a held writer or a file the kit did not write still stop the close as before. When a close does stop, its record names the class of the blocker and the step that raised it, the worktree-removal row says what its minutes went to, and `plan failures` counts stopped closes by class and by order so a planning pass sees a blocker that repeats. A temporary root whose owner checkout a close removed is removable again by `harness prune --apply` after a reboot renumbers its volume, the four interrupted-removal bookkeeping cases WO-237's verification reproduced are repaired, and every role root says the session runs the prune itself and hands the operator the command only after a recorded host denial. This release is for instance operators who register targets, for the sessions that close them, and for planners reading the close feed; the operator's phrases are unchanged.

## Read before upgrading

- A `disposable` entry in a class or registration may now carry `**` as a whole segment, matching any number of segments, and `*` within one segment, matching any characters there, a leading dot included; a path lies under an entry when a leading run of its segments matches the whole entry, and the shortest such run is the matched root. The last segment must keep a literal part: `*`, `**`, `**/*`, `libs/**` and `libs/*/**` are refused at registration naming the floor, `libs/**dist` and `**.tsbuildinfo` are refused because `**` is admitted only as a whole segment, and `**/*.tsbuildinfo` is admitted. A declaration that already closed keeps closing; the floor bounds a pattern's form, and a broad admitted form such as `**/*.*` reaches every ignored file whose name holds a dot, so declare what is regenerable and nothing else.
- A target close now moves and deletes the kit's own residue in the target before judging what remains. Moved into `docs/control/local/retained/WO-NNN/` in main, beside the launchpad worktree's journals: what a session recorded in the target's `docs/control/local/harness/` and the order's `docs/control/local/reviews/WO-NNN/`. Deleted: a writer directory the writer protocol proves released, the `.runtime/.metadata_never_index` marker, the listed files of a `.runtime/harness/HASH` snapshot the kit installed, and the segments of `.runtime/temporary-roots/roots/`, the last of them immediately before Git removes the worktree and written back byte for byte if that removal stops, with the roots they registered carried in the record's `ownedTemporaryRoots` for the close's prune. A held writer (`writer.json` or a non-empty `writer/`) stops the close as `writer-held` before anything moves; a lane or writer directory reached through a tracked link is neither moved nor deleted; any other file in those directories is judged as undeclared material as before. The target cleanup row's `residue` names what moved and what was deleted, and the close summary prints it.
- A snapshot is the kit's by its content, never its name. Every installer now writes `.dotln-snapshot.json`, the name input whose digest is the directory's name, into each snapshot it creates and never rewrites an existing one; the check, the inventory and the gate digest pass over it. A snapshot without a record proves itself by its own package files with a pinned file list: a serving runtime's, or the list its release pinned, which the kit keeps for v0.83.0 to v0.111.1. A snapshot from a release before v0.83.0 is still refused as undeclared, since its name hashes only its pinned files; remove it from the launchpad session by the target's path. A file the repository tracks at a record's path serves only when it is the record byte for byte; otherwise the close stops naming it.
- The release-close record gains `blocker: { class, step, message }`, null when the attempt completes, with `class` from a closed list: `undeclared-ignored-material`, `not-clean`, `writer-held`, `preservation-refused`, `declared-root-unreadable`, `host-denied`, `base-fetch`, `foreign-tag`, `starter-refresh`, `publication` and `other`; each row of `blockers` carries `class` and `step` too, and the summary prints `Close stopped: CLASS in step STEP.`. The `worktree-removal` step row gains `children`: `base-fetch`, `disposable-deletion` (with `files` and `bytes`), `finder-metadata`, `journal-retention`, `git-worktree-remove`, `branch-delete` and `preservation`, each with its `durationMs`, their sum within the row's own `durationMs`; the seven step names and `withReleaseStep`'s nesting are unchanged. A finish or settle prints `Removal timings: {…}`, `Close blocker class: CLASS` and `Derived worktree blocker: {…}` lines that the close reads; a consumer parsing that output sees the new lines. A record written before this release carries no class and is counted under none.
- `npm run plan -- failures` prints `localReleaseCloses.blockers` with `byClass`, `byOrder`, `otherOrderRows` and `repeated`, and `plan start` prints `close blocker repeated: CLASS across N orders` for a class that stopped three or more distinct orders in the window, printed even when the start block must drop it to fit its bound.
- A temporary root whose owner repository no longer exists is re-stamped after a device renumbering on its marker's word, the record's token with the record's inode, and judged by its class and window; one whose inode differs stays refused. The prune gains the `removal-remains` candidate kind for the empty directory a stop between deleting the owner record and the directory leaves under `dotln-removing-TOKEN`, removed with `rmdir`. `@dotln/skeleton` moves to 0.80.0 for the new exports `temporaryRemovalRemains` and `removeTemporaryRemovalRemains` and the changed ledger bookkeeping, with the console's pin and both lockfile entries; no external dependency changes.
- Every emitted role root carries the prune sentence: run `node scripts/harness.mjs prune --apply` yourself under host permissions and record its receipt; hand the operator the printed command only after a recorded host denial of that exact command. The router's roots say instead that the router runs no prune and the phase session it launches does, and a router session still refuses the command. The release-close root says undeclared output is removed from this launchpad session by the target's path, never by a session or writer in the target. `npm run sync` regenerates the installed skills; two new role oracles, `packages/skeleton/fixtures/wo252-role-baseline.json` and `wo252-repair-role-baseline.json`, pin them. The executor, verifier, planner, release-close and router roots exceed their cold-start ceilings after these sentences (41,987 bytes against 40,194; 36,711 against 35,221; 27,664 against 24,576; 26,590 against 26,410; 16,634 against 16,384), boarded for optimization with equivalent usefulness and no ceiling raised (FUP-9d8c66a3ce8654f6).

## Substantive changes

**The glob and the close's judgment.** `scripts/lib/config.mjs` admits the two wildcard forms in `disposable` and refuses a last segment with no literal part or a `**` inside a segment. `scripts/lib/target-worktree-close.mjs` matches a listed path to an entry by segments with the shortest matching run as the root (`disposableMatchRoot`), takes a pattern's roots from the ignored listing, inspects each matched root for links and access as a declared path and names the pattern in a refusal, counts each pattern's matches in the record, deletes listed directories by walking them without following links so a nested repository's files count one by one, and records a deletion's files and bytes even when it stops part way.

**The kit's residue.** The same module judges the kit's writes before either refusal: the journal and review moves `scripts/lib/worktree-removal.mjs` plans (now exported as `journalMoveSources`, with every ancestor of a lane checked as a real directory), the released writer, the marker, the snapshot files a verified snapshot lists and the ledger segments whose first row carries the token their name does; `closeClean` excludes them, the undeclared-material judgment and its named directories pass over them, the journals move first, the ledger is taken last and written back if Git's removal stops, and the ledger's roots are captured through `boundTemporaryRoots` into the record before deletion. `scripts/lib/harness.mjs` adds `RUNTIME_SNAPSHOT_RECORD`, `runtimeSnapshotContent`, `provenRuntimeSnapshot` and the two kept `PRE_RECORD_RUNTIME_FILE_LISTS`, and `preserveHarnessRuntime` writes the record into a new snapshot. `scripts/lib/temporary-prune.mjs` and `scripts/lib/harness-prune.mjs` judge and apply the `removal-remains` kind.
