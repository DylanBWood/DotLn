## Release overview

The Entropy Reducer can be run. It has been a compiled review loadout since 2026-09-04 with five typed APIs and no caller, because dispatching it meant performing five host steps by hand; 121 work orders closed in between with one review to show for it. `npm run entropy` is the missing dispatch host. `review` freezes `HEAD` into a scratch copy under the granted system-temp lane, compiles the reviewer's WorkOrder, authority envelope, lens briefs and residue reference for that exact repository and base with a fresh episode and a finite window, and hands the canonical prompt and closed result schema to one fresh worker. `receipt` binds the return with the loadout's own validators and files a numbered immutable JSON/Markdown pair. `refute` sends only the blinded reproduction subjects the compiled selection rule chooses to a second fresh worker that has seen none of the first one's reasoning, and `refutation-receipt` binds its attempts. `dispose` records the operator's accept, defer or dismiss, landing an accepted finding as a candidate row the follow-up register already harvests. `subject` says which of those a planning pass should do next, and `check` proves the whole chain. The compiled loadout, its residue, actor pin, authority envelope and Program are inputs and are byte-identical to the previous release; `Program.All` remains deferred.

## Read before upgrading

Five things are worth knowing. First, `planning: entropy reducer` is a new operator phrase on the existing planner role — not a new role, skill, scheduler or cadence — and nothing runs unless it is typed: the pass consumes a filed, refuted, undisposed review before it pays for a fresh episode, which costs about 993 s and USD 9.50 at the pinned actor. Second, this is the one inspection profile in the repository that gives a model commands, inside the frozen copy: Claude runs `--safe-mode --restricted` with only the named tools pre-approved and everything else denied without a prompt, Codex adds a `workspace-write` sandbox with network disabled, and because Claude does not path-confine a shell command the receipts and the security document say the boundary there is instructed and then checked, not enforced. Third, identity is a fact and never a default: a receipt reads `entropy-reducer@1` only when a launched `claude-cli-print` episode carried the compiled model, effort and harness on the command line, everything else reads `substitute reviewer` with its reason, and effective model and effort are `unknown` on every route because no harness reports them. Fourth, receipts and their control events are immutable and `entropy check` runs inside `npm run test:docs`, so a hand-edited receipt, a rendering that is not its JSON's projection, or a filed pair with no event fails the shared document gate; a crash between the event and the pair is reported as an interrupted filing to complete rather than a gate failure for unrelated work. Fifth, the application moves to `v0.42.0` and `@dotln/skeleton` to `0.36.0` with the console's exact pin following it; the compiler, kernel, semantic hashing and the external dependency set are unchanged, and no package is added.

## Substantive changes

**One dispatch at a time, and it stays reachable.** The host keeps a single current pointer per dispatch kind, so a second `review` or `refute` while one is pending is refused whatever subject it names — before the roughly 250 MB clone, naming the open episode, its frozen copy and both recovery commands. Without that guard a changed tracked status produced a new subject hash for the same commit, replaced the pointer, and left a paid episode and its copy addressable by neither `receipt` nor `discard`.

**The subject is bound by what can actually hold still.** On the default route the tree was clean at dispatch, so any tracked change during the episode refuses the receipt. On the explicit-commit route — which exists because an executor may not commit before final review and cannot freeze a working tree for a 993 s episode — the subject is the named commit, bound by requiring the same tree object in the repository and in the frozen copy, with the working tree's own drift recorded as `trackedStatusByteIdentical: false` rather than hidden.

**Each episode carries a before-and-after witness.** Review and refutation alike record the source repository's tracked-status hash and the frozen copy's path-and-size inventory on either side of the episode, with the delta, the excluded manifest paths and the observed count of denied tool calls. The rendering emits that line only for receipts that carry the observation, so an earlier immutable pair still projects to itself.

**Blinding and disposition are structural, not procedural.** The refuter receives only `{ findingId, command }` and `{ findingId, steps }` subjects; reviewer narrative, the observed-versus-expected conclusion, severity arguments, proposal packets and any target survival count stay on this side of the boundary. Refuted, blocked and unselected findings remain visible in the report and can never be accepted, denominators report `not-applicable` rather than a fabricated zero, and there is no quota and no vote. An accepted packet is filed under `docs/proposals/` in a directory named by its own suggestion identifier, behind a traversal-safe check on that identifier, and never overwrites an existing one. Filing is not promotion.

**Pre-mechanism evidence is identified by its schema, not its number.** `REVIEW-001` and `REFUTATION-001` carry the 2026-09-04 hand-written shape: their bytes are read and never re-bound. The discriminator is the file's own `schemaVersion`, because in a fresh launchpad the first receipt this mechanism files is also `REVIEW-001` and must be bound like any other.

## Progressive polish

Two new transport request kinds, `entropy-review` and `entropy-refutation`, join the existing typed union with their own protocol file, closed result contracts, argv shapes and timeouts; every existing request shape, argument list and result contract keeps its bytes. The operator guide is rewritten around the command path and keeps the five manual steps verbatim as the recorded fallback. The PLAYBOOK's actor row names the dispatch and the substitute rule instead of a manual procedure; products 03, 05 and 07 and the security document follow. Two shared test registries learn about the new artifacts: the kernel's committed-JSONL protocol list classifies `docs/control/entropy-reducer.jsonl`, and the runner's CLI-selection fixture stubs `scripts/entropy.mjs`. None of this changes observable semantics or any operator action.

Known limitations, each on the record. The confinement witness is coarser than the receipt's wording: `git status --porcelain --untracked-files=no` does not observe a new untracked file in the source repository, and the scratch delta is a net path count rather than a changed-path set, so equal additions and removals read as zero — boarded up with a named follow-up in [D020](../../evidence/WO-151/decisions.md#wo-151-d020) because both honest repairs are design decisions rather than cleanups. The host supports one pending dispatch per kind, not a concurrent addressable set ([D015](../../evidence/WO-151/decisions.md#wo-151-d015)). Both live refuters returned their typed attempts payload as the public session statement rather than prose, so that field adds nothing the bound report does not carry ([D017](../../evidence/WO-151/decisions.md#wo-151-d017)). `REVIEW-002`'s rendered cost line says `unknown` where its own JSON records USD 9.4975; the pair is immutable and every later receipt carries the corrected form ([D010](../../evidence/WO-151/decisions.md#wo-151-d010)). The new protocol file is not itself a registered evidence source, as the mission-check protocol already is not ([D001](../../evidence/WO-151/decisions.md#wo-151-d001)). Effective worker model and effort remain `unknown` on every route, and dollar figures are list-cost observations from the worker result envelope. Finally, nothing invokes the reviewer except an operator typing `planning: entropy reducer`; that is the design, and whether it is enough is D007's own reopening condition.
