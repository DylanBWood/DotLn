## Release overview

Application v0.82.0 lets an exported instance run the whole lifecycle on its own orders and on a registered target's orders. An instance order now prepares, passes its surface checks, publishes and reaches release close from the seeds alone; before this release it failed on the absent `docs/LEGAL.md`, on unversioned seeds and on two core-only inputs the kit did not carry. An order on a registered target repository is gated by the target's own declared tests, binds its reviewed commit at final review, keeps its order file, decisions and reports in the target's documentation root as one records-only commit, and publishes to the target through `worktree publish WO-NNN --target-worktree` under the registered profile and an operator grant; the instance keeps the control segment and a link to each record and publishes them with no release. Target-facing text names only target-native references. It serves the operator of an instance, whose first orders can now close, and the maintainer of a target such as DotLn-Angular, whose repository receives conventional branches, pull requests and its own records.

The visible changes:
- In a kit, `release check-surfaces`, `license-surfaces`, `release prepare`, the publish surface step and `release close` judge the instance's own surfaces: the `docs/LEGAL.md` pins are reported unavailable by name unless the instance declares that file, the tag-manifest template is carried, the schema version comes from the compiled kernel declarations, the seeded first order carries `(v0.1.0)` and a minor classification, the seeded README carries its release block, and `previewReleaseManifest` builds the manifest without a forge.
- The refutation's goal standard in an instance is the marked `dotln-goal-rules` blocks of product 07 plus the instance's `docs/product/purpose.md` block or its named unavailability, never core's purpose or critical path.
- A registered repository declares `gate` and `documentationRoot`; `node scripts/target-gate.mjs WO-NNN [--review]` records rows bound to the target's exact bytes, HEAD and command definitions, and a target order's gate claims stand on those rows alone.
- A passing final review of a target order records `targetSubject` and `targetGate`; `npm run resume -- target-records` makes the records-only commit and records `TargetRecordsCommitted`; `worktree publish WO-NNN --target-worktree` pushes exactly that commit and opens one pull request; the records branch publishes with no release notes and, at an unchanged launchpad code identity, no launchpad product gate; `npm run plan -- target-publish` publishes a planning pass's documents into the same root.
- Release close of a target order fetches the base and fast-forwards the clone's base itself, never moves a base that a gone or reused worktree entry still holds, lists foreign ignored material once with the exact retry command, tolerates regular Finder metadata, refuses to report clean over bundle ownership residue, names each refusal's tree by its role with the rerun command, and records `no-release`.
