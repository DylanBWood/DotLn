# WO-123

A filed intent can now run DotLn's whole delivery loop, from its issue to a pull request, in one persisted continuation. The resident admits the intent on its own when a standing `intent` portfolio entry and admitted operator grants cover it, and `dotln vertical ISSUE --store DIRECTORY` runs the same continuation on demand. Until now every primitive had its own entry and nothing ran the loop end to end. This unblocks WO-112's live proof and then WO-118's unattended run.

**Admission under standing authority.** The resident screens the bound issue, compiles its contract and derives surfaces, then records `IntentAdmitted` before it materializes the order or invokes anything. That record states that the standing authorization supersedes the draft's human-review constraint, and whether surface derivation ran first and under which authority. The portfolio entry, never the draft, supplies the target, and the envelope is the intersection of the portfolio, the phase and the grants. An uncovered, over-ceiling, ambiguous or undecodable input records `IntentHeld` with its reason and dispatches nothing. When two filed drafts could select the same issue entry, both entries now hold or refuse rather than run the issue twice.

**One continuation, two entries.** Fourteen steps run in order, each writing a receipt under the derived order's identity: bundle, contract, surfaces, derived order, baseline, source change, witnesses, verification, review, preparation, lint, publish, observation and resolution. Both entries share one admission ledger and budget and converge at the accepted binding. A restart or a real `SIGKILL` after any durable step resumes at the next step without repeating an effect. A failing step stops with its name, and nothing later runs. Before publication the run writes the delivery preparation and publishes only when the deliverable is ready. A failed review gets one fresh attempt, and a second failure publishes nothing.

**Baseline meaning is a reviewed input.** Four verifications in a row found ordinary bug-report wording that a lexical classifier classed new, so the run changed code without reproducing the defect. The repair removed the classifier. The store's `vertical.json` now carries a `baselineAssessment` per issue, bound to the compiled contract and statement identities. An existing-failure judgment must reproduce, a primitive that claims new against it is a finding, and a missing or unresolved judgment stops before any effect.

**Paths are checked by identity.** The source-change guards and the beacon directory guard refuse a path whose spelling differs from the filesystem's identity by case, volume alias or Unicode form, and a path whose identity cannot be read. The source-change host checks before `git worktree add`, so a refusal leaves no worktree, branch or registration (register row FUP-8369f2b4284e70a8).

**Read before merging.** The composition is proven with external actor doubles and local bare remotes, not a live target. WO-112's and WO-118's producers must supply `baselineAssessment`, or their runs stop at baseline (FUP-faae1df8f1022634). WO-184 D038's G1 remains open: the Claude writer's confined test command can write `.git` and `claude.local.md`. Five smaller items found in review are follow-ups (FUP-82750a69c54c2ced). A running resident reads `vertical.json` once, so restart it after editing. The beacon guard now refuses symbolic-link aliases such as macOS `/tmp`. A behavior repair commits with a fixed conventional message. The skeleton moves to 0.53.0 and the beacons to 0.1.1, and no dependency is added.

**Validation.** VER-001 to VER-004 failed on criterion 5 as ordinary bug-report wording kept beating the lexical classifier, and VER-005 passed the source-bound judgments that replaced it. The final review integrated `main` at `c44ba6c6`. Under the operator's direction it fixed seven defects it reproduced in the order's own code, each with a test that fails on the earlier code. The worst were two runs for one issue, a binding key that depended on the host locale, a child that could launch after a kill, and an unreadable target that became a permanent hold. Read-only reviewer subagents checked each batch of fixes. A fresh `npm test -- --review` at the reviewed subject passed 34 of 34 suites with 84 fresh tasks in 987 s, `npm run test:docs` passes, and the feedback evidence was re-minted from a live audit after the last judged-source edit.
