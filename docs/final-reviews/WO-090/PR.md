# WO-090

DotLn's execution guide is the document every role reads at cold start, and it had grown to 2,016 lines by absorbing harness observations that belong beside the other harness settings. This change moves them out: the Codex sandbox-approval procedure and §Model-specific notes leave for `docs/AI-HARNESS-SECURITY.md` and the playbook, each paragraph landing in exactly one home with a dated pointer where it left, and the guide keeps the executor's operating contract. A relocation table accounts for every paragraph that moved, was retired or stayed. The guide is 83 lines and 6,245 bytes smaller.

**The measurement, and what it actually showed.** The order asked for proof, by WO-039's method, that every role's directed-load total is lower after than before. It is — 252 bytes and one source line for each of the four measured roles, in both skill roots — but not for the reason the order predicted, and this is worth a reviewer's attention. The relocated sections were never in any role's directed read set: the guide enters those sets through exactly one directive, as its `#Goal-aligned decisions` subtree, and neither destination document is a directed input at all. Moving them therefore changed no total. The reduction comes entirely from a different part of the same objective — retiring a paragraph a generated skill already carries. The goal card's **All phases** introduction restated the Goal Alignment and Process Cost procedure that all six generated role skills carry verbatim; it is now a dated pointer, and its four unique qualifications stay in the guide beside the unchanged NoOp paragraph. Every rule keeps a home; 0.7% to 1.1% is the honest size of the measured win, and no latency, token or dollar saving is claimed from it.

**Where each paragraph went.** The security document gains `## Harness version, model and effort readback` — the WO-132 attestation and effort observations, the `ultra` normalization, Codex thread readback with the `--account-label` grammar, and the WO-126 version-line attestation with its session-detection channels — and a `### Selected-session readback, completion and counters` subsection under its Copilot section for the three WO-146 paragraphs, with relative links rebased to the `docs/` level. The playbook gains the WO-028 control-time sentences it did not already carry, and its harness safety baseline now lists `briefing` among the read-only commands and names itself the rule's home. The guide's §Model-specific notes keeps its heading — sixty work orders, four Cites blocks, five anchor links and the publication index all name it — as a stub holding the behavioral-guidance paragraph, the attestation contract sentence and three pointers.

**Validation.** `npm test -- --review` passed **21 suites, 0 failures, 255.55 s, 65 fresh tasks**, run outside the harness sandbox after the last edit. `npm run publication:check` covers 272 of 272 product headings with both editions current, `node scripts/harness.mjs check` matches 31 generated surfaces, and `git diff --check` is clean in the worktree and the index. Final review reproduced criterion 1 from the instrument rather than the records: `measureHarnessContext()` run against the current tree, and again with every changed tracked file overridden to its `f24b5d72` bytes, gives all eight profiles strictly lower and is deep-equal to both recorded measurement files; all twelve `measureColdStarts` profiles are unchanged, so no role's generated cold-start bytes rise. No package, script, test, hook, generated skill or fixture changed. This is a patch release, `v0.35.1`, with every component version unchanged.
