## Release overview

`v1.1.0` rewrites the kit guide, `docs/KIT.md`, so that a reader finds what they came for and can follow it. Each section says first what it is for, a procedure is numbered steps, rules are lists, options are lists or tables, and the decisions behind a passage are linked on one line at the end of its subsection. A table at the guide's head leads from a task to its section. The guide's facts are kept. The documentation map every instance carries, `docs/README.md`, is rewritten the same way. Two things hold later write-backs to the same standard: the document gate lists the long paragraphs a branch writes in standing documents, and the final reviewer returns to repair a changed passage its reader cannot follow. The release adds no refusal and changes no existing command, flag or path.

## Read before upgrading

- The kit guide is rewritten with its facts kept: every heading, command-block line and link target of the earlier guide is in the new one. Dated accounts of how a behavior arrived are no longer in the guide's running text; the linked decisions and the releases hold them.
- The guide's fifteen section headings keep their text, so a link to `docs/KIT.md#first-steps` or to any other section still resolves. The subsection headings are new. The guide is a kit file, so every instance takes it with the update.
- The documentation map changes for an instance that has not edited its own. This release's refresh brings the starter's `docs/README.md` to the new map. An instance whose map is unchanged takes the new one in its update's merge. An instance that edited its map keeps it: the update's preview lists the file as `both changed:`, and the release step's `git checkout main -- docs/README.md` keeps this instance's bytes. The map's text is a new kit file, `scripts/kit/docs-map.template.md`, which the preview lists as an `add` row.
- `npm run test:docs` prints one new line, `long paragraphs: over 120 words (…)`, and after it an `ADVISORY` line for each paragraph over the figure that the branch adds or changes in a standing document. It refuses nothing and keeps no total, and in an instance it leaves out the kit's own documents. The figure is `documents.paragraphWords` in `docs/control/budgets.json`: 120 words when unset, and `null` for no list. An instance's budgets file needs no edit. A value the check cannot use is named in an advisory, the list then uses 120 words, and no command stops.
- The rule every role carries gains a clause: the final reviewer returns to repair a changed standing passage its reader cannot follow, and names it. An instance takes the clause with the role text when it runs `node scripts/harness.mjs emit` on its update branch, as every update does.
- `node scripts/docs-check.mjs --long-paragraphs` is new: it prints the same reading of every standing document, for planning a rewrite. No existing command, flag or path changes.

## Substantive changes

**The kit guide.** All fifteen sections are rewritten in place under their own headings. Six of them list their subsections, a procedure is numbered steps, and flags, options and outcomes are tables: the guide holds 31 tables and 28 numbered lists where it held one of each, and no paragraph over 120 words where it held 63. First steps gains subsections for running and closing an order, the private terms list, the configuration file, registering another repository and publishing a target order's change. Taking upstream updates puts an instance's own procedure first, core's update of the starter last, and what an instance older than `v1.0.0` does in one subsection. The guide is longer, 4,365 lines for 2,765 and about 33,500 words for 27,726: it has 151 more headings and 30 more tables, and the decision links, gathered at the end of each subsection, are labelled where the earlier guide wrote only `decision`.

**Two sentences corrected.** The license section said the export bundles no third-party file; it now names the three it carries, Prettier's Markdown plugin with its license and notices. Where the guide said a context entry of the private terms list never refuses, it now names the two publications into a registered target that stop on one: a target order's publish waits for the reviewer's confirmation, and a planning pass's publication into a target refuses, so the line is reworded. The behavior is unchanged; the sentences are.

**The documentation map and the starter refresh.** The map is three pointers and a table of the roots, each row saying what the root holds, and its text is a kit template the export writes. The export refuses a template that links no README of a root it seeds. A starter refresh treats the map as it treats the front page: a copy that still holds the bytes an export wrote is brought to the current map and named under `seeds published:`, a copy its owner changed is kept and named under `seeds kept:` with the reason, and a missing one is added with the other absent seeds.

**The long-paragraph list.** The document check reads each standing document a branch changes and lists every paragraph the branch adds or changes that runs past the figure. A paragraph is running text, in a list item or a quotation too; a table, a fenced block and a heading are not counted. Length alone is no fault: the list is a smell for the stage at hand to read, and nothing is judged by it.

**The final reviewer's reading.** The reviewer already judged each changed standing document's diff, passing a replacement and returning a dated account. It now also returns a changed passage its reader cannot follow. The execution guide states the same in its section on documentation freshness, where two long paragraphs were split at their sentences.
