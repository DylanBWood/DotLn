## Release overview

DotLn `v0.14.0` is the first slice of the roadmap's projections-and-console rung, a minor release above the published `v0.13.3`. It gives the five UIFA roles their first shared screen: a read-only actor board that shows every actor the repository's recorded sources know about with its build, episode state, authority, the compiled mechanisms that fired for it, and the evidence behind each claim, with the work-order state machine as one panel among five. `npm run console -- board` renders the board in 80 terminal columns, `--json` emits the versioned `uifa-board-v1` view model that any other host can render, and `--html path.html` writes one self-contained page with inline styles, no script, no asset, no network reference, no state, and no command. Every cell traces to a source record and carries an explicit status: `known`, `unknown` (an available record does not support the claim), or `unavailable` (the source is absent, unreadable, or malformed). Audience: the operator and anyone reading this repository's evidence; the sessions that verify and review work orders; and the consumer that will render the same view model in an application shell. The new workspace `@dotln/console` is component `0.1.0`; kernel `0.2.1`, compiler `0.6.0`, and skeleton `0.12.1` are unchanged with byte-identical sources; no dependency, framework, lifecycle phase, legal action, or control-event schema changes.

## Read before upgrading

- **`npm test` builds and tests the new workspace.** The gate removes and rebuilds `packages/console/dist` beside the other packages, runs `packages/console/dist/test/*.test.js` (18 cases in the runtime suite), and its feedback check now reads the WO-032 edition (`--edition WO-032`); `npm run evidence:feedback` selects the same edition. One console case performs live host collection over the current checkout and takes about a minute because it runs the read-only `resume status --json` once per known work order.
- **New root commands.** `npm run console -- board [--json | --html path.html] [--store directory] [--sources recorded.json]`, `npm run test:console`, and `npm run evidence:console -- --check` (the pinned-fixture comparison; `--write` regenerates outputs from the pinned inputs and is never run by tests).
- **The collector is read-only and reads the checkout.** On every invocation it reads the canonical control segments, `docs/work-orders/README.md`, the capability table, the publication index, the roadmap, the refutation receipts, the WO-011 maturity report, and the recorded worker stores, and runs fixed commands (`resume status --json` per order, `resume usage --json`, `worktree constellation`, `release list`). It appends nothing, never creates a missing `--store` directory, reads no intake, account configuration, or private harness settings, and `--html` refuses to overwrite an existing path (a new file, mode 0600).
- **The feedback evidence edition moves to WO-032.** Adding a workspace changes the declared lockfile projection that the feedback audit pins, so a fresh bounded live audit was recorded on base `8b55eca` through the existing Codex transport with effort `unknown`; the WO-011 and WO-041 editions are untouched and remain immutable.
- **Historical sources are shown, not filled.** The WO-011 audit and verifier logs record a `feedback-v1` policy hash and a `verification-v1` input hash, not LoadoutGraph hashes, so those actors show their recorded hash with its kind and `loadoutHash` reads `unknown`. The WO-031 control segment records operator dispatches without a human identity or a release-close event, so the person row reads "Operator — identity not recorded" with `identity` and `authorship` unknown and no presence or attention inference. Control status has no blocker-reason field, so `blockers` is the recorded failure source when a verdict is `fail`, and `dependencyCheck` comes separately from the generated index.
- **Contract for other hosts.** `uifa-board-v1` is `lossy-read-only`; hosts render `cell.label` and address facts through `cell.key`; links target local row, section, panel, or evidence ids, never URLs or commands; a later panel is an additive change; a host must not reconstruct lifecycle legality from the table. The JSON Schema is `packages/console/uifa-board-v1.schema.json`.
- **Repository plumbing.** `tsconfig.json` references the console project; `package-lock.json` gains only the `@dotln/console` workspace link and entry; `.prettierignore` excludes the recorded fixture inputs, the pinned outputs, and the WO-032 feedback report.

## Substantive changes

- **Console (`packages/console`).** `projectBoard(sources)` is a pure projection over host-supplied data: no filesystem, process, clock, randomness, network, input mutation, or lifecycle fold. The Actors panel joins recorded worker episodes (identity, role, phase, transport, selected model and effort, selection source, observed effective values, heartbeat, lease, recorded build hash with its kind, allowed and denied effects, grant expiry, work order) with their acceptance matrices and audit receipts, keeps separate physical verifier attempts as separate actors, links a verifier's recorded implementer to the accepted matrix only when the episode identifies exactly one actor, and adds the control log's completion actors and an operator-role row per order for unattributed dispatches. The Builds panel compiles every saved loadout export through all three editable views, reports the three hashes and their agreement with the compiled semantic hash, and renders the compiler's own tooltip with declared costs. The Mechanisms panel lists all ten compiled feedback units with rung, host boundary, enforcement, intended behavior, rationale, the maturity fold's five counts for fixture and live sources, the last recorded fixture activation, and the next maturity condition; it requires the report's fold to equal a recomputation before showing counts, labels zero eligible episodes `unobserved`, and never computes a rate. The Work panel carries orders with phase, verdict, legal next actions, signed elapsed spans, the recorded failure source, the index's dependency check and evidence links, worktree Beacon observations with liveness explicitly unknown, published releases linked to their orders' evidence, and recorded actor usage. The Blueprint panel carries the latest plan-refutation receipt's plan verdict, hold status, and per-order verdicts with reasons, capability rows with their assessment headings, publication statuses, and pending roadmap rungs. Every panel names the roles it serves and the question it answers, and `roleAnswers` pins the answering cell for each of the five questions in product 13.
- **Renders.** The terminal render accepts 40 to 160 columns, defaults to 80, strips control sequences and bidirectional overrides, and wraps by a deterministic display-width rule for the documented text and CJK glyphs, including a combining-mark regression. The HTML render is one file with a `default-src 'none'` content-security-policy, inline CSS only, escaped text everywhere, in-document anchors only, and no form, input, button, script, image, or external reference.
- **Fixtures and the recorder.** `fixtures/manifest.json` pins 22 inputs by SHA-256 (the skeleton loadout exports and feedback units, control status and usage, the constellation and release list, the generated index, the capability table, the publication index, the roadmap, the recorded WO-009 demonstration store, the original WO-011 audit and verifier logs and maturity report, the WO-031 control segment, and all seven refutation receipts) and five cases (`wo009`, `wo011`, `control`, `refutations`, `missing`) whose JSON, terminal, and HTML outputs are pinned under `fixtures/expected/`. `fixtures/role-answers.json` pins the question-to-cell mapping. `scripts/console-fixtures.mjs` compares or explicitly regenerates the pinned outputs; `fixtures/capture-demo.mjs` reproduces the synthetic WO-009 recording with a deterministic CLI peer and never invokes an authenticated model.
- **Tests (`packages/console/test/board.test.ts`).** Per-fixture purity, schema validity through an independent bounded checker, pinned-output equality, terminal width, HTML safety, link integrity, and cell invariants; negative schema cases; the WO-011 executor and verifier attempts, hashes, and authority; the WO-031 operator row; the compiler render and a fixture export added without console edits; the ten mechanisms with an unobserved unit, a mismatched fold, and an absent report; control facts with a failed verdict and negative elapsed; text-adapter refusals; the manual and versioned refutation receipts; the role mapping compared with product 13 at run time; hostile source text; the CLI's overwrite refusal and conflicting modes; unavailable and corrupt stores; and live host collection that leaves canonical sources unchanged and a missing store uncreated.
- **Documentation.** Product 04 gains §Actor board v0 with the contract and its source limits, §Later console hosts, and the agent-projection paragraph separating the inventory from the sparse twin; product 06 records the activation assignment and marks §UIFA v0 actor board implemented; product 13 adds each role's today clause and §Actor board role service; the README release block, its not-yet-claimed list, and its package map name the board; the capability table gains the dated `projection.uifa-board` row at level 1 (demonstrable); the publication index gains four rows and both edition locks are re-pinned; the ledger records three adopted entries; the skeleton README points the feedback edition at WO-032; the work order carries its activation assignment and the executor's source reconciliation.

- Source: the reviewed `wo-032` branch merged into `main` above `v0.13.3`; the exact commit is named by the annotated `v0.14.0` tag.
- Executor evidence: `docs/evidence/WO-032/README.md` (the acceptance map and the historical-source reconciliation), `checks.txt` (the full gate), `fixtures.txt` (the 18 console cases), and the WO-032 feedback edition under `docs/evidence/WO-032/feedback/`.
- Verification: `docs/verifications/WO-032/VER-001.md` (pass: all eight criteria on the staged tree, with the WO-011 hash axes, the WO-031 event set, the maturity fold, the three view hashes, the terminal widths, and the HTML scan re-derived independently of the console, and the draft's unsupported source facts judged work-order draft defects rather than implementation defects). - Compatibility: `@dotln/console` `0.1.0` is new; `@dotln/kernel` `0.2.1`, `@dotln/compiler` `0.6.0`, and `@dotln/skeleton` `0.12.1` are unchanged with byte-identical `src/`; `package-lock.json` changes only by the console workspace link and entry; no dependency change; lifecycle phases, legal actions, and the control-event schema are unchanged; `uifa-board-v1` is the first version of the view model and later panels are additive.
- Known limitations: the collector calls every `*Loadout`-suffixed export of the skeleton's `reactor` and `loadouts/*` modules as a factory with a fixed inspection expiry, so a future non-factory export with that suffix would make the whole Builds panel unavailable; a projector exception is reported as an unsupported or invalid source rather than distinguished from a source defect; the Blueprint panel shows only the lexicographically latest dated receipt and does not evaluate overrides, staleness, or planning-gate legality; live maturity counts are all zero because no live observation store exists yet, and controlled fixture activations are never promoted to live rates; the recorded WO-009 fixture is a witness of the demonstration and store path with a synthetic CLI peer, not an authenticated model run, and its event payloads carry the recording's temporary directory path; the uncommitted form of `release check-surfaces` cannot see untracked component sources, so the committed form used by publication is the authoritative one; Claude Code attestations remain `self-reported` because no effective-effort readback is recorded for the harness; and `gh` cannot read its configuration inside the Claude Code sandbox, so the publish helper's preflight may refuse there.
