## What this merges

WO-032, the `v0.14.0` minor above the published `v0.13.3` and the first slice of the roadmap's projections-and-console rung. A new zero-dependency workspace, `@dotln/console` `0.1.0`, projects the documented machine interfaces and evidence stores into one versioned, read-only view model, `uifa-board-v1`, and renders it two ways: `npm run console -- board` in 80 terminal columns, and `--html` as one self-contained page with inline styles, no script, no asset, no external reference, no state, and no command; `--json` emits the contract any other host renders. Five panels, each naming the UIFA roles it serves and the question it answers: Actors, Builds, Mechanisms, Work, and Blueprint. Every cell names its source record and carries `known`, `unknown` (an available record does not support the claim), or `unavailable` (the source is absent, unreadable, or malformed); a missing source never becomes an empty success, and nothing is inferred about identity, presence, or liveness. Kernel `0.2.1`, compiler `0.6.0`, and skeleton `0.12.1` are unchanged with byte-identical sources; no dependency, framework, lifecycle, or event-schema change. Two draft acceptance sentences name source facts that do not exist in the historical inputs they cite (LoadoutGraph hashes in the WO-011 logs; a human identity and a release-close event in the WO-031 segment); the implementation renders the recorded facts, labels the gaps `unknown`, and records the reconciliation in the work order and the executor receipt, which the verifier and this review both judged a draft defect rather than an implementation defect.

## Known open items

- **The live host-collection test is sensitive to host load.** It runs the real collector, whose per-command timeout is 60 s, in parallel with the skeleton suite; `release list` alone takes about 17 s quiet and about 30 s under load because it walks every annotated tag through git subprocesses. Hardening candidates: a longer timeout or serial execution for that case, or a cheaper `release list`.
- **`ProjectionContext.section` reports any projector exception as an unsupported or invalid source** (VER-001 O2), which is also why the gate failure above carries no reason.
- **`exportedLoadouts` invokes every `*Loadout`-suffixed export as a factory** with a fixed expiry; a future non-factory export with that suffix would make the whole Builds panel unavailable (VER-001 O1).
- **The Blueprint panel shows the lexicographically latest dated receipt** and does not evaluate overrides, staleness, or gate legality (VER-001 O4).
- **Two saved-build cards share the title "Entropy Reducer"** because card titles use the identity name; the loadout id (`entropy-reducer.review.v1`, `plan-refuter.v1`) is the first cell of each card.
- **The uncommitted form of `check-surfaces` cannot see untracked component sources**, so it reported the console's `src` as unchanged before the series was committed; the committed form used by publication reports the first-version baseline.
- **The WO-009 fixture's event payloads carry the recording's temporary directory path**; a later recapture could sanitize it.
- **The planning map's placement note for WO-032 said no `scripts/` edits**; the order adds one new recorder script and edits the root `package.json` test chain and commands, touching no existing script. WO-039's integrator reconciles `package.json` routinely.
- **Claude Code attestations remain `self-reported`.** No effective-effort readback is recorded for the harness.
- **Publish and release close.** `npm run worktree -- publish WO-032` runs the committed surface check, the body and notes validation, and the sign-off check before any push, then preflights `gh`; inside the Claude Code sandbox `gh` cannot read its configuration, so if the helper refuses there the operator runs the same command from this worktree outside the sandbox.
