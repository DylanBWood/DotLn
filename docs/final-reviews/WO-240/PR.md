# WO-240 — Node 24 beside Node 26 (v0.105.0)

Until now the only runtime any gate had ever run under was the one on the operator's machine, nothing compared the running Node with the `engines` field, and an instance on a Node 24 host was told by `npm ci` that it was unsupported while every script ran. This pull request declares `^24.15.0 || ^26.0.0` in the root and all six workspace packages and the lockfile, refuses any other Node by name at the gate's first task and in `harness check` and `harness evidence`, keeps every gate child on the selected runtime, records one complete gate under Node 24.15.0 beside the Node 26 gate at the same code identity, repairs the four runtime differences that run found, and writes the supported runtimes and the private-clone recipe into the kit README so an operator cloning the starter onto a Node 24 host meets no warning the kit did not predict.

**The range and its reader.** `scripts/lib/node-engines.mjs` judges a version against `engines.node` with no new dependency. It reads only `^major.minor.patch` alternatives joined by `||`, treats every prerelease as outside (stricter than npm, which admits `24.16.0-rc.1`), refuses by name a range it cannot read, an unreadable `package.json` or a version it cannot parse, and reads an absent or null field as no constraint, as npm does. The judgment always reads the checkout whose scripts are running, so a target repository's own `engines` field never governs a launchpad's commands ([D002](../../evidence/WO-240/decisions.md#wo-240-d002--declare-both-node-lines-and-read-the-range-without-a-dependency)). The lockfile diff is seven `engines` lines and nothing else.

**The gate refuses before anything else runs.** `checkHost` compares `process.version` with the range and refuses outside it, naming the range, the version and `node scripts/bootstrap.mjs` as unaffected. On an outside runtime the `host` task leads the structural phase and is the gate's first and only task, and the stale-runtime build does not run, because on real Node 22.2.0 the unchanged gate died inside the `declarations` task without ever reaching the sixth task ([D003](../../evidence/WO-240/decisions.md#wo-240-d003--outside-the-range-the-host-task-leads-because-it-is-otherwise-never-reached)); a Node too old to start the runner at all still has the range printed above the raw error. Inside the range the six structural tasks keep their documented order, and a runtime refusal consumes no dispatch run. `harness check` and `harness evidence` refuse the same way, while `emit` stays open because bootstrap runs it ([D004](../../evidence/WO-240/decisions.md#wo-240-d004--add-the-comparison-harness-check-was-said-to-make)). The harness entry now builds through `node scripts/build.mjs` from the running executable instead of `npm run build`.

**Children run on the selected runtime.** No production source spawns a bare `node`; the exposure was name lookup in the shell suites and npm children. `suiteEnvironment` now puts the running Node's directory first on every gate child's PATH, pinned by a fixture with a decoy `node` and `npm` ahead on the inherited PATH ([D005](../../evidence/WO-240/decisions.md#wo-240-d005--put-the-selected-runtime-first-on-every-gate-childs-path)). Bootstrap, sync, worktree finish and integrate, measure-gates and `harness evidence`'s own `npm test` still find `npm` by name outside the gate; the gate they reach judges its runtime at its host task.

**What running on Node 24 found.** The first complete run under 24.15.0 failed four of 43 suites: two on this order's own change (the export closure and the entry's build child) and two on real runtime differences. On Node 24 `fs.cpSync` applies the umask where Node 26 keeps each mode, a recursive `readdirSync` refuses a byte path, `JSON.stringify` overflows the stack near 6,100 nested arrays, and `node:test` publishes no test tracing channel and no `testId`. Each is repaired in the fixture that met it and recorded in CONTRIBUTING as a behavior code must not depend on ([D011](../../evidence/WO-240/decisions.md#wo-240-d011--what-the-first-node-24-run-found), [D016](../../evidence/WO-240/decisions.md#wo-240-d016--cores-document-gate-failed-on-node-24-where-the-complete-run-cannot-see-it)). The kernel history case, which the review selection never runs, was red on Node 24 for the one synthetic deep-nesting stream and now counts that stream as decoded only, below Node 26, for that error; `encodeLog` is unchanged. The gate heartbeat names a running case on Node 26 only ([D012](../../evidence/WO-240/decisions.md#wo-240-d012--the-heartbeat-names-running-cases-on-node-26-only), FUP-23eb1282f814be14).

**The recorded runs.** [node24-gate.json](../../evidence/WO-240/node24-gate.json) records the complete `npm test -- --review --again` under `v24.15.0` with one `node` on PATH: exit 0, 0 h 36 min, 112 fresh tasks and none reused, at the handoff code identity, with the document gate (27 suites) and the machinery gate (19 suites) run after it in the same environment. The Node 26.9.0 run at the same identity passed in 0 h 34 min with 112 fresh tasks. The runs pass `--again` because reuse compares code identity and never the runtime that ran a task; without it a second run at a passed identity would execute only the structural tasks and still report a pass ([D010](../../evidence/WO-240/decisions.md#wo-240-d010--a-recorded-run-forces-every-task-fresh-and-can-reach-one-node-only), boarded as FUP-3457a1c859fb51d8).

**Documentation.** The front page names both lines in its Node line; the founding lesson had already lost its reference to an earlier system through WO-192, so that edit is a recorded no-op ([D007](../../evidence/WO-240/decisions.md#wo-240-d007--the-founding-lesson-sentence-is-already-gone-so-step-5s-second-edit-is-a-noop)). The kit README's §First steps states the runtimes, what refuses another, the one range form the reader accepts, and the private-clone recipe from `gh repo create` to `node scripts/harness.mjs check`, with `cd <name>` added because the remote lines cannot run without it and the local-terms and `npm run meta` steps named as the ones the recipe does not replace; the recipe was rehearsed under 24.15.0 against an export of this tree, with only `gh repo create` stood in for ([D013](../../evidence/WO-240/decisions.md#wo-240-d013--the-recipe-is-written-as-rehearsed-on-node-24150)). CONTRIBUTING, the PLAYBOOK, product 07, the feature-configuration page and ADR-0002 say the same as built.

**Editions and the release.** `package-lock.json` and `packages/skeleton/package.json` are judged feedback sources, so the feedback edition is one live self-host episode rather than the carry the order expected ([D008](../../evidence/WO-240/decisions.md#wo-240-d008--run-the-owed-live-feedback-episode-against-the-orders-cost-line)); the stale `off-ramps.mjs` declaration carried in from WO-235 is removed in the same re-mint ([D009](../../evidence/WO-240/decisions.md#wo-240-d009--remove-the-stale-off-ramps-registration), FUP-4c704bb1ea210f14); the authority edition is re-minted deterministically and the other editions stand on their checks ([D015](../../evidence/WO-240/decisions.md#wo-240-d015--editions-and-the-release)). The target is `v0.105.0`, minor; no workspace source changed, so no component version moves, and no dependency is added. `.node-version` stays `26.9.0` and the kit exports none.

**Validation.** Three independent reviewers reported 29 distinct findings over five rounds, 28 fixed and one recorded ([reviews.md](../../evidence/WO-240/reviews.md)). [VER-001](../../verifications/WO-240/VER-001.md) passed at this identity on independent probes: thirteen named and 135 further version cases, malformed and foreign-directory ranges, real-host checks on both lines, a PATH decoy, the export's offline install under 24.15.0 and the lock comparison. The final review reproduced the runtime fixtures, the export and history cases under both lines, the generated-artifact, lineage, publication, artifact-edition, formatting and release-surface checks, `harness check` under real 24.15.0 and the refusal under real 22.2.0, and consumed the two complete rows ([FINAL-001](FINAL-001.md), [D022](../../evidence/WO-240/decisions.md#wo-240-d022--accept-the-unchanged-subject-on-its-standing-complete-rows)).

**Limits.** Only 24.15.0 ran on the 24 line; 24.16 to 24.22 are admitted by the range and untested. Gate rows record no runtime, so which Node ran a row rests on the evidence file and the captured logs. `gh repo create` and live worker episodes were not exercised under Node 24. An instance that kept an edited `package.json` with another form of range is refused by name after an update until the field reads as caret alternatives, which the kit README states with the remedy.
