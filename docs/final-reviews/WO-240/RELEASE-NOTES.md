## Release overview

The launchpad and every export now run on Node 24.15 or later in the 24 line and on Node 26, and say so: every package declares `^24.15.0 || ^26.0.0`, the gate refuses any other Node by name at its first task instead of failing somewhere inside a suite, and a complete gate has passed under Node 24.15.0 with the record to show it. An operator who clones the starter into a private repository on a Node 24 host follows one README passage from `gh repo create` to `node scripts/harness.mjs check` and meets no warning the kit did not predict. This matters to operators and forks whose hosts run the Node 24 long-term-support line, and to every instance, which gains a host check that names the runtime it refuses and the remedy.

## Read before upgrading

- Node 22, Node 25, Node 27 and every prerelease are refused at the gate's `host` task, by `node scripts/harness.mjs check` and by `harness evidence`, where before only `npm ci` warned and the suites ran. The refusal names the range and the version; `node scripts/bootstrap.mjs` is unaffected. On a refused runtime the `host` task runs first and nothing else runs.
- The host check reads only `^major.minor.patch` alternatives joined by `||`. An instance that kept its own edited `package.json` through an update is refused by name until its `engines.node` reads in that form; the kit README names the refusal and the remedy.
- `.node-version` stays `26.9.0` for development and the kit exports none; an instance that wants a version manager to select a runtime pins its own.
- Gate reuse compares code identity and never the Node that ran a task. A run meant to judge one Node line passes `--again`, or it may carry passes executed under the other line.
- Four Node 24 behaviors differ from Node 26 and code must not depend on them: `fs.cpSync` applies the umask where Node 26 keeps each mode, a recursive `readdirSync` refuses a byte path, `JSON.stringify` overflows the stack near 6,100 nested arrays, and `node:test` publishes no test tracing channel and no `testId`, so the gate heartbeat cannot name a running case on Node 24.
- The installed hooks and manifest change only by the selected evidence snapshot; `node scripts/harness.mjs check` reports the drift in an instance and `npm run sync` regenerates them. The stale `scripts/lib/off-ramps.mjs` declaration leaves the evidence-source inventories; no instance action follows.

## Substantive changes

**Runtime declaration.** The root `package.json`, the six workspace packages and the seven lockfile entries declare `^24.15.0 || ^26.0.0`; the export carries the same field in its generated manifests and lock entries, and the launchpad suite checks each one. `scripts/lib/node-engines.mjs` judges a version against that field with no dependency: caret alternatives only, prereleases outside, an unreadable file or unreadable range refused by name, a missing or null field read as no constraint, and the judgment always taken against the checkout whose scripts are running.

**Gate and harness.** `checkHost` compares `process.version` with the range and refuses outside it. On an outside runtime the runner puts `host` first in the structural phase, runs no other task and skips the stale-runtime build; a startup failure on a Node too old to run the runner prints the range above the raw error; a runtime refusal consumes no dispatch run. `harness check` and `harness evidence` refuse an outside Node as their first step; `emit`, `evidence --stop` and `evidence --wait` stay open on any Node. The harness entry builds through `node scripts/build.mjs` from the running executable rather than `npm run build`.

**Gate children.** Every gate child's PATH leads with the running Node's directory, so a suite, shell script, shebang or npm script that finds `node` or `npm` by name stays on the runtime the gate selected; a fixture plants a decoy `node` and `npm` ahead on the inherited PATH and checks a shell lookup, a shebang and npm's own lookup.

**Node 24 repairs.** The target-publish fixture restores each entry's mode after `cpSync`; the runner-fixtures spellings script judges each path spelling independently after Node 24 refuses a recursive byte-path listing; the case reporter falls back to a case's source position where Node 24 carries no `testId`; the heartbeat fixture asserts case naming on Node 26 and the stated fallback elsewhere; the kernel history case counts the one synthetic deep-nesting stream as decoded only, below Node 26, for the stack overflow, and keeps the byte round-trip for every other stream.

**Documentation.** The front page names both lines. The kit README's §First steps states the runtimes, what refuses another runtime, the accepted range form and the private-clone recipe in order from `gh repo create` through the `cd` into the clone, the `upstream` rename, the private origin, the first push, bootstrap and `node scripts/harness.mjs check`, naming the local-terms and `npm run meta` steps it does not replace. CONTRIBUTING, the PLAYBOOK, product 07 §Execution, the feature-configuration page and ADR-0002 state the range, the refusal, the structural order on an outside runtime and the four runtime differences.

**Evidence editions.** The feedback edition is a live self-host episode at this order, because the lockfile and the skeleton manifest are judged sources; the authority edition is re-minted deterministically; the artifact-identity and verification editions stand on their checks.
