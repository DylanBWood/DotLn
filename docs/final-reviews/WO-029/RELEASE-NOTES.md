## Release overview

DotLn `v0.9.0` is the minor release above the published `v0.8.0`. The author's personal runtime now binds each equipped compilation to the decisions that consume it. A successful compile returns a separate identity record beside the unchanged compiled program: the compiler contract and package versions, the existing whole-program semantic hash, the exact compilation environment and authority expiry that reproduce that hash, and one domain-separated definition digest for every active mechanic, linked support, and ambient effect the manifest says participated. The host records that identity at equip time, recomputes it before every later program-consuming decision, and writes the pinned hash and both compiler-version axes into each decision trace. When the recompilation disagrees with the pin, or compilation itself fails, the runtime records a typed, inert refusal instead of scheduling, emitting work, or widening authority, and it never throws out of replay. Historical logs keep their old replay behavior behind a logged enforcement boundary, and the L0 receipt and governed-raw projections show every equip comparison and refusal through canonical event links. Audience: the operator reading an audit receipt, and the first out-of-process worker order (WO-009), which can now consume a pinned whole-program identity instead of an unverified graph. The semantic-hash algorithm and preimage are unchanged; the kernel is byte-identical to `v0.8.0`; the compiler advances to component `0.3.0` and the walking skeleton to `0.8.0`.

## Read before upgrading

- **Every new log begins with `ArtifactIdentityEnforcementStarted`** carrying `{ "payloadVersion": 1 }`. The host driver appends it exactly once before accepting the first new input; a caller-supplied boundary is rejected, and a replayed duplicate leaves state unchanged.
- **The reactor starts with no authority.** `initialState()` now has `authority: null`, no pin, and no equip reference. Any host that relied on the module's default compiled authority before an equip must equip first; a program-consuming event before a valid equip records `ArtifactIdentityUnavailable`.
- **`LoadoutEquipped` has a new payload shape.** The host factory `LiveReactorDriver.equip(graph, environment, at)` mints `{ "payloadVersion": 2, "graph": ..., "artifactIdentity": ... }` under event-envelope schema 1 and is the only way to equip through the driver; `feed` throws on a legacy equip draft. Absence of `payloadVersion` is the only legacy discriminator, and any other value, an extra key, or a malformed identity refuses as `ArtifactIdentityInvalid`.
- **Extending a historical log requires the boundary and a v2 re-equip.** A pre-`v0.9.0` log still replays with its identity labeled unavailable and its old decisions intact. After the boundary is appended, a legacy-derived state refuses forward input and a legacy-shaped equip until an explicit v2 re-equip succeeds. No pin is fabricated for old history.
- **Refusals are events, not exceptions.** `ArtifactIdentityUnavailable`, `ArtifactIdentityInvalid`, `ArtifactIdentityDrift`, and `ArtifactCompilationRefused` remove usable authority, pending command, program, and active schedules until a valid v2 re-equip; `UnknownScheduleRefused` leaves valid authority intact. Each carries a version-1 payload with the reason, source and equip event references, pinned and observed identities when available, drift axes, and typed diagnostics. Replay of a refused log yields the same decisions and may truthfully have no emitted WorkOrder.
- **Recovery is checked before dispatch.** A restored outbox now records `CommandRedispatchRequested`, compared against the pin, before any adapter runs; a legacy or drifted recovery reaches no adapter, and a completed restored outbox is not dispatched again.
- **The compiler's success result gains a required `artifactIdentity` field** on `compileLoadout` and `compileEditableView`; failed compiles carry no identity. Code that constructs `CompileResult` literals must add the field. `fnv1a64`, `componentDefinitionPreimage`, `deriveArtifactIdentity`, and the domain, scheme, and package-version constants are newly exported.
- **The canonical scenario timeline changed.** The default CLI output now lists 28 events, including the boundary and eleven decision receipts, and is pinned in `fixtures/wo029-cli.txt`; the WO-020 CLI fixture and the WO-003 trace oracle remain unchanged historical artifacts, and the scenario test asserts the new trace fields as an explicit delta against that oracle.
- **Audit projections gain fields.** L0 and governed raw carry an `artifactIdentity` section; the denied authority record can now be labeled `explicit-event-link` when the refusal names its attempt by causation, with the adjacency label retained for unlinked historical input; the fixture omission text now says cryptographic integrity and authenticity specifically.
- **Whole-program identity is path-dependent by design.** Repository path, base commit, and authority expiry participate in the compiled program, so relocating an otherwise identical graph changes its semantic hash and requires an explicit re-equip; definition hashes are path-independent.
- **Prettier now ignores three generated evidence files** under `docs/evidence/WO-029/` whose exact bytes are owned by `npm run evidence:artifact -- --check`, which `npm test` runs after the package suites; `--write` regenerates them only after a reviewed source change.

## Substantive changes

- **Compiler (`@dotln/compiler` 0.3.0).** `deriveArtifactIdentity` builds `ArtifactIdentityV1` from the normalized graph, the compiled program, the environment, and the already-computed semantic hash: schema version 1, `compilerContractVersion` from the program's `compilerVersion`, `compilerPackageVersion` from a pure source constant tested against `package.json`, the canonicalized compilation environment, the authority expiry, and one `ComponentDefinitionIdentityV1` per manifest entry with scheme `dotln-component-definition-fnv1a64-v1` and a digest over the canonical JSON of `{ domain: "dotln:component-definition:v1", componentKind, definition }`. A manifest entry without a matching normalized definition throws at derivation, which only runs after a successful compile. Nothing enters the compiled program or its semantic-hash preimage.
- **Runtime identity module (`packages/skeleton/src/artifact-identity.ts`).** Exact-shape validators for the compilation environment, the identity, and the refusal payload; `compileArtifact`, the single runtime compile boundary that turns malformed recorded input into diagnostics instead of exceptions; `artifactIdentityDrift` over six axes; the v2 payload factory that snapshots the caller's graph; the four trace inputs; and the refusal type list.
- **Reactor (`packages/skeleton/src/reactor.ts`).** The equip decision validates the payload shape, recompiles with the pin's declared environment, refuses drift or diagnostics, and otherwise stores graph, pin, environment, equip event, and authority together, clearing stale work, pending command, program, and schedules on a v2 equip. `withEquippedArtifact` wraps presence, pulses, WorkOrder emission, command results, deletion attempts, refusals, termination, verification, and recovery requests; beacon-sweep results keep their own host-supplied authority and do not consume the loadout. The unknown-schedule branch records `UnknownScheduleRefused` after cutover and keeps the in-memory observation only for pre-boundary, unpinned history. The enforcement boundary is accepted once, drops unpinned authority, and is idempotent; replayed refusal events reproduce the blocked state.
- **Host driver and scenario (`packages/skeleton/src/scenario.ts`).** `LiveReactorDriver` is exported; it appends the boundary before the first input, rejects legacy equip drafts and caller-supplied boundaries, records one `DecisionRecorded` per consuming or refusing decision, persists refusal continuations, and offers `equip` and `ensureIdentityEnforcement`. The canonical scenario equips through the factory, and crash recovery records and checks `CommandRedispatchRequested` before dispatching, returning early with `workOrder: null` when recovery is refused or nothing is pending.
- **Audit (`packages/skeleton/src/audit.ts`, `artifact-audit.ts`).** `projectArtifactIdentities` derives `matched`, `unverified`, `unavailable`, and `refused` rows with canonical event links from equips, scoped decision records, and refusal events, rejecting malformed refusals and unresolved scoped references; the L0 receipt and governed raw include it with the `deterministic-content-equality-only` assurance label and four standing limitations. The authority-trace grammar admits exactly the four-input pin suffix, and the denied record prefers the explicit causation link to the attempt.
- **Evidence, fixtures, and tests.** Compiler fixtures for the Entropy Reducer graph and both exact identities; a compiler suite covering exact identities, manifest membership, the independent oracle, ordering inertness, attributable edits, relocation, the pinned Unicode vector, unequipped definitions, failed compiles, and the version constant; a skeleton suite covering v2 equip and receipts, stale pins, every drift axis through every consumer, diagnostics and malformed payloads, the frozen oracle with the logged boundary, factory shape, recovery, unknown schedules, environment inputs and the rewritten-pair limit, and both audit layers; the preserved legacy log and the new CLI fixture; the executable evidence helper that regenerates or byte-checks the semantic-hash inventory, canonical log, audit projection, and fourteen synthetic negative transcripts; and `docs/evidence/WO-029/` with the base-commit baseline, release preflight, and full test output.
- **Documentation.** The domain model's `Artifact identity v1` section; the architecture's pinned-artifact-identity section promoted from candidate to shipped with its path-dependence and unknown-schedule limits; the interfaces' pinned preimage, domain, scheme, and fixed vector; the roadmap's dated activation completion; the audit document's association labels and `Deterministic artifact receipts`; the compatibility document's identity and payload axes; both package READMEs; the planning map; the publication index and both edition locks; the ledger's dated section extending two adopted decisions; and the README release block.
