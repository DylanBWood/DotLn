## Release overview

Application v0.101.0 lets a Claude Code executor edit the registered target worktree of the order it is executing, without `operator override:` and without loosening any other refusal. The kit's compiler admits a sixth outside-write grant kind, `target-worktree`; the contributor loadout declares it for the executor role alone under an operator-granted authority grant; and the generated permission hook resolves it at every judged outside write from the session's dispatched order, that order's canonical phase and the single registry row that binds the order to a target from this physical launchpad. `worktree start` prints the Claude Code launch line beside the Codex and Copilot ones, all three starting in the launchpad. Until this release every implementation and repair of a target order under Claude Code needed `operator override:`, which suspends all five refusals for the session, or a Codex session with its sandbox off.

Audience: operators running exported DotLn instances with registered target repositories, and contributors changing the compiler's grant contract, the permission hook's outside-write judgment, the contributor loadout or the worktree start helper.

## Read before upgrading

- **A sixth grant kind and a new authority grant.** The emitted manifest carries `contributor.target-worktree` (operator-granted, repo `project`, effect `outside.write:target-worktree`) and the executor's declaration of kind `target-worktree` with source `WO-236-D001`. An instance receives both through the kit update and its own `node scripts/harness.mjs emit`, and `node scripts/harness.mjs check` must be green afterwards. No path is written into the manifest: the root is resolved from the instance's own registry at each write.
- **Executor only, and only while the order is open.** The grant admits a write when the session's role is executor, the dispatched order (or the canonical selection when none is bound) has canonical phase `active` or `repairing`, the launchpad's `docs/control/local/target-worktrees.json` under its configured control root holds exactly one row for that order, that row's `launchpad` equals this physical root and its `target` is absolute; only the target's physically resolved root is granted. Any other case, including an unreadable registry or an unavailable lifecycle, withholds this grant alone and names the cause in the refusal; the writer, gate-input, planning-branch and subagent refusals and the five existing kinds are unchanged. The verifier, reviewer, release-close, planner and refuter roles receive nothing new.
- **Launch lines change.** `worktree start` prints a Codex workspace-write session, a Copilot default-mode session and a Claude Code session that each begin with `cd` into the launchpad; Codex adds the target with `--add-dir`, and the Claude Code line ends with `enter: resume: next` and names the target the executor's grant admits while the order is active or repairing. The Copilot `--allow-tool` forms and the publication-command sentence still appear only for a GitHub origin, and a local origin prints `Publication host rules: unavailable`. The `Next (run manually)` block now starts Codex from the launchpad with `--add-dir` and the target path instead of inside the target; a session started inside the target still meets the separate target-worker bundle.
- **Refusal text.** Every refusal of an outside write by a role without the kind now ends with a `Granted root target-worktree grants nothing` clause naming the role, and an executor on a launchpad with no target registry sees the registry path named as the granted root with its cause. The refusal decisions themselves are unchanged; the wording is boarded for correction ([D030](../../evidence/WO-236/decisions.md#wo-236-d030)).
- **Hook latency for executors.** Every judged executor outside write, including writes the temp and scratch grants admit, spawns `scripts/resume.mjs status --json` once in each of the three judging hooks; on this checkout that is about 180 ms more per permission judgment than a verifier's write (medians of 303 against 98 ms). Verifier writes and in-project writes are unaffected. Boarded ([D029](../../evidence/WO-236/decisions.md#wo-236-d029)).
- **Known issues.** The resolver trusts the launchpad's own registry row rather than comparing it with main's registry and clone map as the publish admission does ([D028](../../evidence/WO-236/decisions.md#wo-236-d028)). Writer reservation stays per root, so a launchpad-rooted executor writing the target holds no writer in the target; `worktree start` now prints only launchpad-based routes. WO-192's planned target-rooted phase workers may later coexist with this grant, which the planning receipt records as a reopening condition. Codex tool calls stay unhooked, so a Codex executor keeps `--add-dir`; Copilot reuses the Claude registration and the same admission.
- **Versions.** Application v0.101.0 is a minor release over v0.100.0, assigned at activation under the order's classification. Compiler moves 0.31.0 to 0.32.0 for the additional closed grant kind; skeleton moves 0.70.0 to 0.71.0 for the executor admission and the console's exact pins follow; console 0.5.0, kernel 0.8.0, beacons 0.1.1 and browser-evidence 0.2.0 are unchanged, and no third-party dependency changes. The executor role text grows by 17 bytes to 30,874 in both installed roots, within its accepted ceiling of 34,953; the other five roles are unchanged.

## Substantive changes

**Compiler contract** (`packages/compiler/src/harness.ts`). `OutsideWriteGrant` admits `{ kind: "target-worktree" }` with no `root`; the closed-set validation accepts it and still refuses a `root` on every kind but `operator-root`; `outsideWriteEffect` renders `outside.write:target-worktree`; the generated grant line renders the kind name. The compiler case asserts the root refusal, the manifest row with its origin and authority, the executor's grant line and the refusal without a provenance-bearing grant.

**Hook resolution** (`packages/skeleton/src/harness-host.ts`). `registeredTargetWriteRoot` reads the canonical status for the dispatched order, requires phase `active` or `repairing`, reads the launchpad's registry under its configured control root as a regular contained file, requires one row for the order bound to this physical launchpad with an absolute target, and returns the target's prospective realpath; every failure returns a cause and withholds this kind alone. `outsideWriteResponse` resolves the kind in its grant switch, refuses a destination outside the target with a named cause, and names the withheld target-worktree root in a refusal when no physical root explains it. `RegisteredTargetEntry` gains the `launchpad` field the registry already records.

**Loadout** (`packages/skeleton/src/loadouts/contributor.ts`). `contributor.target-worktree` joins `contributorOutsideAuthority` with the operator's authorization and the capture digest as its reason; `contributor.executor` alone declares the kind with source `WO-236-D001`.

**Launch lines** (`scripts/worktree.mjs`). `hostLaunchLines` prints the three host sessions from the registry's `launchpad` for every origin, confines the Copilot `--allow-tool` forms, the publication-command sentence and the literal host-rule write to a GitHub origin, and prints `Publication host rules: unavailable` otherwise; the target start's `Next (run manually)` block starts in the launchpad with `--add-dir`. [D003](../../evidence/WO-236/decisions.md#wo-236-d003--host-sessions-start-in-the-launchpad) records the launchpad as the Codex directory with WO-221's host notes as evidence.

**Cases and controls.** `scripts/test-harness.mjs` drives the emitted permission hook through the executor's Edit, Write, literal redirect and Copilot native write into the target, a symlink escape, the parent, a sibling, a clone path and a `-beside` path, five other roles, zero and two rows, another launchpad, a relative target, an unreadable registry, six other phases, a session bound to another order, an unbound session and a status with no order, and an in-project write with a broken registry; `packages/skeleton/test/source-change-host.test.ts` admits the registered target and refuses the sibling at the hook level; `scripts/test-target-worktree-start.mjs` and `scripts/test-target-worktree-release.mjs` assert the printed lines; `scripts/test-authority-grants.mjs` and `packages/skeleton/test/writer.test.ts` carry the new effect in their exact projections; `scripts/test-gate-followups.mjs` compares the oracle's nominal and accepted ceilings through `budgetVerdict`. [controls.json](../../evidence/WO-236/controls.json) records the base refusing and the change admitting the same three requests.

**Role oracle** (`packages/skeleton/fixtures/wo236-role-baseline.json`). Pins the twelve re-emitted roots with `wo233-role-baseline.json` as the historical parent and `wo185-role-baseline.json` upstream, and records each role's startup cost with its nominal and accepted ceiling ([D007](../../evidence/WO-236/decisions.md#wo-236-d007)).
