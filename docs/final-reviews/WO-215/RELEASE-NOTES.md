## Release overview

Application v0.81.0 makes each core release reach DotLn-Enterprise-Starter with no hand-run step. After `release close WO-NNN --publish` has published the tag and its Release, the helper refreshes every export sibling the launchpad declares: it runs the export update for the released commit into a disposable worktree of the starter's recorded checkout (or, while the starter holds no `KIT-MANIFEST.json`, the first export of that commit), verifies the result the way an export verifies itself, commits it once, pushes that commit as a fast-forward of the starter's `main` through the hookless bare lane bound to core's origin owner and the sibling's name, fast-forwards the checkout, and holds WO-078's receipt in main's ignored pending lane for the next `worktree start` to carry into a reviewed change. It serves the operator, who no longer runs `launchpad export --update` by hand after a release, and the maintainer of an instance, whose upstream now moves with every core release.

The visible changes:
- `resume: release close` with `--publish` gains one external effect, one verified fast-forward commit to the `main` of each declared export sibling with a recorded checkout, and its close record gains a `starterRefresh` row and a summary line per sibling; a refused refresh is a close blocker with the same retry command that keeps the dispatch's writer, and the publication outcome, tag and Release are unchanged by any refresh outcome.
- `worktree clone DotLn-Enterprise-Starter /path/to/starter-checkout` admits a declared export sibling's id beside a registered repository's and records the checkout in the ignored clone map; a consumer sibling and an undeclared id refuse as before.
- `worktree start` carries each pending sibling receipt into the new worktree's evidence root, regenerates the registry there, empties the lane and prints the carried names; a malformed pending receipt refuses the start before any worktree or branch exists, and a registry failure keeps the worktree and prints a bound retry.
- `release close --publish --dry-run` previews the refresh: it judges the head main would fast-forward to, runs the checkout, branch, cleanliness, binding, fetch, ancestry and manifest checks, and prints `preview`, `current`, `skipped` or `refused` without changing a checkout file or pushing.
- Both forms of the release-close role text name the refresh as the helper's one further external effect, forbid every other push, force-push and merge, and make a refusal a reported blocker that never cleans, resets or commits in the starter checkout.

## Read before upgrading

- **The first live refresh is this order's own release close, and it is the starter's first export.** The public starter holds one empty-tree initial commit and no manifest. Before `resume: release close`, record the starter checkout from main with `worktree clone DotLn-Enterprise-Starter /path/to/starter-checkout`; the operator names the path or asks a role to create the clone, and the path never enters a committed record ([D002](../../evidence/WO-215/decisions.md#wo-215-d002--publish-only-the-verified-starter-commit-through-the-declared-binding)). A publishing dry run previews the checks before main's fast-forward.
- **A refused refresh holds the close open.** The row is `refused`, the exit is nonzero, a `starter-refresh` blocker carries the same retry command and the dispatch's writer stays reserved until a retry succeeds, including for a starter-side cause unrelated to the released order (planning receipt 045, criterion 5). The second verification found one cause with no completable route: a retained cleanup record whose original checkout has been moved or deleted refuses every preview and retry until the ignored record and its scratch directory are removed by hand; it is boarded with its repair rule as FUP-eee6c2fa1ef76215 ([D018](../../evidence/WO-215/decisions.md#wo-215-d018--verification-pass-ver-001s-findings-are-repaired-and-two-follow-ups-are-boarded)).
- **`harness emit` now refuses an operating contract whose only text is the generated block.** An instance must keep its hand-written clean-room floor outside the markers, as `build:none` already required; ordinary emit accepted the block-only contract before this release ([D006](../../evidence/WO-215/decisions.md#wo-215-d006--repair-the-shared-floor-check-discovered-by-the-refresh-refusal-fixture)).
- **The refresh commit follows the host.** It runs with hooks off under the host's configured Git identity and signing policy and a fixed message with no attribution trailer; a signing failure is a refused, retryable row ([D003](../../evidence/WO-215/decisions.md#wo-215-d003--keep-verification-and-git-transport-tied-to-the-released-sources)). The push goes only to `refs/heads/main` of the bound URL, with no tags and no force; a branch-protected `main` would refuse at the remote and record a refused row.
- **The starter's seeds are never refreshed and instance actions are not applied.** The update writes manifest-listed kit files only; `README.md`, `.gitignore`, the `CLAUDE.md` floor and the seeded root READMEs keep their bytes after the first export, and declared actions are listed in the row as preserved.
- **The receipt rides in whichever order starts next.** Until that `worktree start`, a refresh's receipt exists only in main's ignored pending lane; a carrier order that is withdrawn or discarded unmerged loses it until a later `current` rerun of release close writes another (planning receipt 045, criterion 7). A `current` row writes a pending receipt only when no committed or pending receipt records the starter's manifest hash.
- **A dry run fetches.** The preview's fetch updates the checkout's `refs/remotes/origin/main` and imports objects through the host-owned lane; it writes no work-tree file.
- **A fixture leaves residue on a mid-run failure.** The starter refresh fixture keeps the module's scratch directory in the system temporary directory when the test fails between its faulted update and its recovery step; boarded as FUP-d8297b92b32c8304 ([D018](../../evidence/WO-215/decisions.md#wo-215-d018--verification-pass-ver-001s-findings-are-repaired-and-two-follow-ups-are-boarded)).
- **Twelve follow-ups boarded by the final review** ([D020](../../evidence/WO-215/decisions.md#wo-215-d020--final-review-pass-final-001-at-the-integrated-subject-two-register-rows-settled-the-orders-follow-ups-left-for-planning)), none blocking. The ones an operator meets first: a kit file whose only change is its mode is planned as unchanged yet rewritten with the new mode, so every later update refuses at the staged-set check until its bytes change; the retained cleanup record is bound to the retrying process's temporary base, so retry a failed cleanup under the same `TMPDIR`; a target start retried after another start has consumed its captured receipt refuses with no route yet. The rest are the role's done condition and the blocker label, refusal placeholders that mislabel core main and the scratch directory, a refusal after a landed push summarized without its commits, the runner's missing declaration of the new role-oracle fixture, a silent self-start retry, an empty pending directory refusing starts after a declaration change, a duplicate pending receipt after a rerun that follows a carry, and product 04's stale authority sentence.
- **Versions.** Application v0.81.0 is a minor release over v0.80.0, assigned at activation under the order's classification. Skeleton moves from 0.58.1 to 0.59.0 for the release-close role text and the regenerated bundle; the console's skeleton pin and the lockfile follow. No dependency is added.

## Substantive changes

**The refresh module** (`scripts/lib/starter-refresh.mjs`). `refreshStarters` returns one row per declared export sibling: the checks in order (main's HEAD at the published tag, the recorded checkout a physical Git top level other than main, on `main` and clean, the push URL bound to core's origin host and owner and the sibling's id, a hookless fetch into a host-owned bare lane whose objects are imported offline, the checkout equal to or behind `origin/main`, the remote holding `main`, the manifest's core commit an ancestor of the released commit); a `current` or `skipped` decision from `origin/main:KIT-MANIFEST.json`; a detached disposable worktree under the system temporary directory owned by an ignored cleanup record; the first export through `exportKit` copied over the initial commit with kept and replaced paths listed, or the update through `planKitUpdate` and `applyKitUpdate` with the receipt held back and any refused row refusing; the export's own verification plus the starter's `launchpad verify`; the staged-set check and a raw blob-and-mode comparison with the verified files; a fixed-message commit with hooks off; the push through `pushObservedCommit` to `refs/heads/main`; the checkout's fast-forward; the pending receipt. A refusal names its reason with the checkout and scratch paths redacted; cleanup refusals also redact the retained record's paths and copy no malformed ignored input.

**Release close** (`scripts/release.mjs`). `close` calls the refresh after publication and cleanup on the published path and on the equal-version path with `--publish`, previews it on both dry-run paths with `--publish`, and calls nothing for target, lower-version and non-publishing closes; the module is imported only when the declaration names an export sibling. `main`'s record gains `starterRefresh`, a refused row adds a `starter-refresh` blocker with `releaseCloseCommand` and sets a nonzero exit, and `releaseCloseSummary` prints one line per row.

**Receipts and the carry** (`scripts/lib/siblings.mjs`, `scripts/siblings.mjs`, `scripts/worktree.mjs`). `writeReceipt` takes a pending lane under the ignored control-local root, refusing an unignored or tracked path; `readPendingReceipts` decodes the lane with the same validator as the committed receipts; `receiptRecorded` checks both lanes by manifest hash; `capturePendingReceipts` freezes paths and bytes; `carryPendingReceipts` copies the cohort, regenerates the registry, then consumes sources whose bytes still match. `worktree start` reads the lane before creating anything, captures it after the fast-forward, carries on both routes through `completeSelfStart`, and prints a bound retry when the carry or activation fails. `manifestBuildHash` moves from the launchpad into the siblings library.

**Clone admission and the push helpers** (`scripts/lib/target-worktrees.mjs`, `scripts/lib/github-repository.mjs`, `scripts/lib/target-publish.mjs`, `scripts/launchpad.mjs`). `recordRepositoryClone` admits a declared export sibling's id; `recordedRepositoryClone` reads the map, whose parser now reports invalid JSON without echoing it. `pushUrl` and `pushObservedCommit` move unchanged into the GitHub repository module and are re-exported, so early refusals run without the launchpad's sources. The export's self-verification is factored into `verifyExportTree`, which `exportKit` calls as before and the refresh calls with the operating contract compared by its marked block; `exportKit` returns its bundle.

**The role text and the bundle** (`packages/skeleton/src/loadouts/contributor.ts`, the generated skills, the harness manifest, `packages/skeleton/fixtures/wo215-role-baseline.json`). Both release-close forms name the refresh, the publication limits and the refusal rule; the 34 surfaces are regenerated; the process-debt role oracle selects a new snapshot that links the previous one by hash.

**The floor check** (`scripts/lib/harness.mjs`). `composeHarnessInstruction` refuses a contract with no hand-written text outside the generated block before any write, matching `build:none`.

**Fixtures.** The launchpad suite gains the starter refresh test over local bare remotes behind rewritten GitHub URLs (first export, the initial-commit refusals and collision, the preview with core behind, the update with an injected cleanup fault and its recovery, the privacy cases, the remapped checkout, the partial-journal reconstruction, current, behind, dirty, ahead, diverged, misbound, missing, non-root, wrong branch, empty remote, main past the tag, a later manifest, no declaration, the current preview and the failed verification) and the staged-tree clean-filter test; the release suite gains `starter_refresh` (the preview with main behind, the missing-checkout and misbound blockers, the current retry, the non-publishing previews and the lower-version close) and the captured-beacon cancellation cleanup; the worktree, target-worktree and siblings suites gain the pending-receipt, carry, clone-admission and self-start retry cases; the harness suite covers ordinary emit on a block-only contract; the fixture-temp-root driver covers five signal scenarios.

**Documents.** Product 07's `resume: release close` row and §Workflow closeout and releases (the Starter refresh paragraph and the authority sentence), product 03 §Platform and instance boundary, product 12 §One workstream across repositories, the playbook's release task and clone-map paragraphs, the harness security document's release-close paragraph, the documentation map's evidence line and the registry preamble change in place.
