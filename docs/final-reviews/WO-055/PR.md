# WO-055

Until now a negative verification ended at a finding. WO-052 could change source and WO-054 could judge a real worktree, but the step between them, turning a finding into the next bounded attempt, was an operator handoff. This work order adds that step. `deriveRepairOrder` turns a blocking finding into a repair WorkOrder whose surfaces are the files the finding's host witnesses name, whose tests are its exact reproduction commands, and whose contract, base, effective envelope and operation lists are the original order's, unchanged. `RepairHost` dispatches that order to a fresh WO-052 source-change worker branching from the failed commit, runs every derived reproduction against the committed repair, and re-verifies through WO-054 from the complete original contract. In the recorded proof a planted defect is found, repaired in one round touching only `fixture.txt`, and re-verified green; a double that repairs wrongly twice ends in a terminal `RepairExhausted` naming the last finding, with two writer launches, three verifier launches and no third dispatch.

**A read-only verifier cannot widen a writer's scope.** That was the planning refutation's hold on this order, and it is what the derivation refuses. Evidence ids resolve only against the failed subject's pinned host witnesses. A path outside the original declared surfaces, a reproduction that is not one of the original named test commands, shell composition in a command, a finding with no references, a foreign subject revision and a non-blocking finding each yield `NeedsHuman` naming the offending input; no order is derived, no write command is persisted and the stored envelope is byte-identical. The one exception is an exact scope grant with WO-042 provenance that matches a host registry record in full, names this repository, uses no wildcard and covers exactly the extra path or command. Its id is recorded on the derived order, and it still cannot add an effect or operation: the envelope stays the original's. The repair diff limit is enforced by the existing source-change host, which refuses any committed path outside the derived surfaces.

**A killed host resumes without a second repair.** The loop is a persisted executable program in the shared reactor: a `Sequence` of the repair `Invoke`, `Await(SourceChangeObserved)` and the verification `Invoke`, then `Guard` branches for success and the round limit, validated on replay. The parent acknowledges ownership before awaiting, child stores keep the native worker outbox and immutable commit receipt, and a snapshot-preparation receipt allows recovery before verifier dispatch. Two real SIGKILL cuts are tests; VER-001 added six more, one after each durable parent event, and every one resumed to `complete` with exactly one writer launch. The fresh worker receives the contract and the finding, never the first worker's facts, decisions or transcript.

**What this does not claim.** Every repair and verifier worker here is a synthetic double over real scratch Git repositories, with macOS-confined host tests and real SIGKILL; the live loop is WO-056. Scope grants rely on a trusted host registry, not cryptographic authentication, and the requested grants and the registry reach the host in the same options object: "separately admitted" means separate from verifier output. The `Await` carries a 180-second timeout that kernel `stepProgram` does not evaluate, so a stalled child relies on the WO-052 and WO-054 host deadlines, leases and locks. Repair surfaces include the criterion's cited test files, as the order specifies, so a repair writer may edit a named test that re-verification then runs; the command names and contract cannot change, and the verifier sees test bytes in its diff. `roundLimit` is a per-order field of the repair original with a default of two, not a field of the compiler `WorkOrder` type as the order's Design line words it; the compiler contract stays `0.14.0`. WO-054's trusted-host and snapshot-confinement limits apply unchanged.

**One change reaches earlier orders' writers.** The source-change writer prompt now lists the declared surfaces and says "Edit only the declared surfaces within the worktree mount" where it said "Edit only within the declared worktree mount". This matches what the host already enforced and no test pinned the old wording, but it applies to every WO-052 and WO-053 writer, not only repairs.
