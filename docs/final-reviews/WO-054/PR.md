# WO-054

Until now the verification loop judged a synthetic repository: the capsule carried fixture files, the host ran no target tests, and a behavior claim's evidence was whatever the verifier episode reported. This work order gives the verification host a `worktree-snapshot` profile over a real committed worktree. The host captures every committed file at the observed commit with its Git mode, seals that with the diff against the declared base, a closed WorkOrder contract and the exact named test commands, and runs each named test itself, before the verifier episode, in a fresh files-only copy under macOS confinement. The results reach the blinded verifier as `live` witnesses marked `origin: host`, which a worker result cannot supply. The proof fixture shows why that matters: the implementer's own superficial test exits 0, the host's contract test exits 1, the verifier double records a blocking finding with expected, observed, reproduction and evidence references, and the acceptance matrix keeps the row `failed` when a fixture implementer emits a success-shaped event.

What the capsule refuses: any field outside the closed set, with its schema path, at the snapshot, contract, test, file, evidence, witness, criterion and finding levels, so no part of the worker envelope, transcript or narrative has a slot. What the host refuses: a dirty or untracked target, symlinks, submodules, binary files, a target whose bytes or modes differ from its Git objects, an output directory overlapping the target, a named test that changes a sealed input, and any drift of the read-only snapshot, which is re-inventoried before and after every test, at dispatch, on cached recovery, after the worker completes and before admission. Missing confinement is unavailable evidence and never an unsandboxed fallback. Every WO-010 fixture passes unchanged; `verification-v1`, the accepted-result version and the event schema are unchanged, and the new names `snapshot` and `hostTest` are reserved.

**Operator scope expansion: Codex continues unfinished work after compaction.** The reported failure was an active work order, an automatic compaction, an answer to an old message, then idle until something else woke the session. The Codex contributor bundle now emits project-local `.codex/hooks.json`, a comment-only `.codex/config.toml` and one continuation hook. `PostCompact` records the turn, `SessionStart` with source `compact` restores the role, order, phase and outstanding completion event as context, and a synchronous `Stop` can request one continuation for that compacted turn, enforced by an exclusive receipt. It acts only for a root session whose saved record, canonical phase, outstanding event and own writer reservation all agree. It dispatches nothing, acquires or releases no writer, reads no transcript and parses no conversational text; `analysis:` and `operator override:` are checked first and again before blocking, and native interruption stays with Codex. Emission refuses to replace Codex configuration it does not own, and target-worker profiles never receive the capability.

**What this does not claim.** The confinement is the order's first-proof isolation and not a hostile-process security boundary; it blocks direct filesystem reads outside the admitted paths and network access, not every indirect route through process execution or system IPC, and descendant cleanup is not established. The snapshot seal and capsule hash are equality keys that do not authenticate a hostile writer. Named-test bytes come from the observed commit and are visible in the verifier's diff; they are not an independently authenticated oracle. Stderr beginning `sandbox-exec:` is treated as a launch failure, so target output can downgrade a failed test to unavailable, never to a pass. The profile is macOS-only, text-only, bounded to 100 files, 100,000 bytes per file and 100,000 diff characters, and refuses repair execution until WO-055; the live verifier episode is WO-056. For Codex, the native probes on CLI 0.155.0 ran the current generated bytes with synthetic status and ownership; desktop activation is not established, native hook trust is required, and the checked loader gives linked worktrees their hook definitions from the root checkout, so activation can only be observed after merge. Final review adds one named limit: no test or document establishes that the hook's `session_id` equals the id a production Codex role passes to `harness begin`; if they differ the adapter silently does nothing. If a Codex session still idles after compaction, compare those two values first.
