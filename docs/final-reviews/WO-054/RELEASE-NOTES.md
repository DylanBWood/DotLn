## Release overview

Independent verification can now judge a real committed worktree instead of a synthetic repository. The verification host gains a `worktree-snapshot` profile: it seals the target's committed files, the diff against the declared base, a closed WorkOrder contract and the exact named test commands, runs those tests itself in confined copies before the verifier starts, and hands the blinded verifier the results as host-run witnesses the implementer cannot author. In the recorded proof the implementer's own test passes, the host's contract test fails, the verifier records a blocking finding, and the acceptance matrix keeps the row failed when the implementer emits a success-shaped event.

The audience is anyone relying on a DotLn verification verdict over source a worker changed, and the operator running Codex as a contributor. This is the fixture-level proof with a double verifier on macOS; the live verifier episode is WO-056 and source-writing repair is WO-055.

## Read before upgrading

Application minor `v0.30.0` stages compiler `0.14.0` and skeleton `0.26.0`. Kernel and console versions are unchanged, no dependency was added, and `package-lock.json` moves only the workspace version strings. `verification-v1`, accepted-result version 1 and event schema 1 are unchanged. No migration is required.

One compatibility change for legacy verification subjects: `snapshot` on a subject and `hostTest` on an evidence item are now reserved names and are validated when present, including refusal of `null`. Compiler `0.13.2` dropped them silently. Unrelated extra fields on legacy subjects keep positive selection, and no WO-010 fixture uses either name. New-profile capsules pin the compiler version, so an older compiler cannot run one by dropping its metadata.

The new profile runs target-supplied test commands on the host. It runs only the exact commands the contract names, as whitespace-separated argument vectors with no shell, each in a fresh files-only copy under macOS `sandbox-exec` with a minimal environment, a 30-second deadline and 64 KiB output bounds. This is first-proof isolation and not a hostile-process security boundary: it denies direct filesystem reads outside the admitted paths and network access, it does not block every indirect route through process execution or system IPC, and descendant cleanup is not established. The snapshot seal and capsule hash are equality keys that do not authenticate a hostile writer. Without `sandbox-exec` the witness is unavailable; there is no unsandboxed fallback, so the profile cannot certify acceptance off macOS. Raw test output can contain physical paths, so apply your publication policy before sharing it, and test copies are kept for inspection with no automatic cleanup.

The Codex contributor bundle now writes three project-local files: `.codex/hooks.json`, a comment-only `.codex/config.toml` and `.codex/hooks/continuation.mjs`. Emission refuses, before any bundle write, to replace a file under `.codex/` that the installation manifest does not already own, and leaves unrelated Codex files alone. No user or account setting is changed. Operator action is required for the hooks to run: Codex's native project and hook trust must admit the generated definitions, which you can review with `/hooks`, and changed definitions can need renewed trust. In the checked Codex CLI 0.155.0 loader a linked worktree takes its hook definitions from the root checkout, so the root checkout must contain this release before its worktrees can activate them.

Two cold-start ceilings rise one 4 KB step each with dated acceptances naming the added shared rule: executor to 24,576 bytes and release-close to 16,384. The shared role text and `CLAUDE.md` gain one sentence describing the Codex compaction adapter and restating that other tool and completion judgments are advisory.

## Substantive changes

- Verification compiler: an optional `snapshot` on the subject carrying the profile, observed commit, snapshot hash, a closed contract of six WorkOrder fields and the named tests; each file carries its Git regular-file mode. Every level of a new-profile capsule refuses an unexpected field with its schema path, and capsule drift now reports the path that differs. Only live behavior criteria are supported, every contract criterion must be represented, and every named command must appear in the contract's required evidence.
- Host-run witnesses: evidence gains `hostTest` with kind `host-run-test`, `origin: host`, the snapshot hash, command, exit code, signal and bounded output. The compiler derives the outcome from the exit code and signal and refuses a witness whose stated outcome disagrees; snapshot evidence without a host-run test is refused. Exit zero is pass, nonzero is fail, and missing confinement, a process error or an interruption is unavailable, which cannot certify acceptance.
- Snapshot host: `prepareWorktreeVerification` accepts a canonical committed WO-052 target, the declared base, the observed commit, a public repository label, the contract, criteria, tests and a new host-owned output directory. It admits committed regular UTF-8 files only, up to 100 files of 100,000 bytes and 100,000 diff characters, checks each file's bytes and mode against its Git object, and refuses dirty or untracked source, symlinks, submodules, binary files and any overlap between the output directory and the target.
- Snapshot integrity: the read mount is sealed read-only and re-inventoried before and after every named test, at dispatch, on cached-result recovery, after the worker completes and before result admission. A named test that changes any sealed input, including its own source, is refused. The verification host selects the profile from the capsule; there is no second acceptance reducer, and the same matrix fold keeps a negative result against implementer success claims.
- Codex continuation after compaction, an operator scope expansion: `PostCompact` records the compacted turn, `SessionStart` with source `compact` restores the role, work order, phase and outstanding completion event as context, and a synchronous `Stop` can request one continuation for that turn, bounded by an exclusive receipt. It acts only when a root session's saved record, the canonical phase, the outstanding event and that session's own writer reservation all agree. It dispatches no lifecycle command, acquires or releases no writer, starts no worker, reads no transcript and interprets no conversational text. `analysis:` and `operator override:` are checked before any repository read and again before continuing; native interruption remains with Codex. Missing or malformed state leaves native stopping available.
- Harness profiles: the Codex contributor profile records the separately witnessed 0.155.0 continuation observation beside its unchanged 0.153.4 generic-hook observations, and target-worker profiles never inherit it. The generated Codex hook directory joins the generated-code format exemption, with a regression that runs the formatter over generated JavaScript.

Known limitations: those listed under Read before upgrading. The proof uses a double verifier and a scratch target. Stderr beginning `sandbox-exec:` is treated as a launch failure, so target output can downgrade a failed test to unavailable, never to a pass. Named-test bytes come from the observed commit and are judged through the verifier's diff. The profile refuses repair execution until WO-055.
