## Release overview

DotLn can now act on the feedback a pull request it opened receives. `npm run worktree -- resolve-pr --request REQUEST-FILE` takes each unresolved automated review comment and failing check in the latest recorded observation and works it to an end: a bounded repair by a fresh worker, verified against the original criteria, pushed to the pull request's branch and observed resolved; a rejection posted to the thread with its evidence; or a recorded stop that names the item for a human. The release is for anyone who publishes through DotLn and does not want to carry review comments back by hand. It is proven over fixtures with real local Git and a fake `gh`; running the loop against a live pull request belongs to a later order.

## Read before upgrading

A target publish request must now name its repository: add `repositoryId` as canonical `HOST/OWNER/REPO`. A request without it, or one whose origin URL names a different repository, is refused before any remote call. The focused test of a source-change episode now runs under macOS `sandbox-exec` with no network and writes confined to the worktree, and a Claude writer is admitted only that confined command, so a test that needs the network or writes outside its worktree now fails. On a host other than macOS the focused test reports `confinement-unavailable` and a source-change writer cannot run its named test. The loop's remote effects need operator grants: `repo.push` for the repaired head and the new `pr.thread.resolve` for a thread disposition. Known limits, recorded as follow-ups and not changed here: the loop can report `resolved` while one item needs a human, when a mapped check is still running after the push; an accepted comment that has no line makes the loop stop with an error and stay stuck on that item; a rejection reply can repeat if the process dies between the reply and its receipt; a comment the observer's screen refused stops the whole loop; and Claude's native allowlist rule for the confined command contains wildcards, so the host permission hook enforces the exact spelling.

## Substantive changes

The loop processes one item at a time as a persisted program in the episode store's `publication/` log: triage, repair, push, thread disposition and a fresh observation, each a recorded command and result, so an interrupted run resumes with the same request and does not push twice. Triage judgments are supplied in the request with evidence references. An accepted item enters the existing repair derivation as a host-recorded review item in place of a verifier's witness; the contract, surfaces, named tests and authority stay the original's, and each item gets one round. The push goes only to the branch the recorded pull request names, only for a head that descends from the recorded one and has a fully verified acceptance matrix. A thread is resolved, or answered with a structured rejection and then resolved, through `gh`. An item counts as resolved only when a later recorded observation at the repaired head shows the thread resolved or the mapped check passing. A human reviewer's comment is never dispatched or disposed; a comment outside the order's surfaces, a check the mapping does not name and a missing judgment end as needing a human; a refused comment stops the loop with a typed stop. `PullRequestReviewLoopStopped` records the outcome. Every Git read the publication host runs in a target's root now ignores the target's signature settings, so a planted signature program does not run during publication.

## Progressive polish

The observer records each inline comment's thread id, which the disposition uses. The `worktree` usage line names `resolve-pr`. Product 02 names the command, the stop event and the review item beside the publication and repair paragraphs, and product 06's pipeline sentence describes the post-PR loop. The skeleton README's feedback verifier budget cap now reads $5, the value the source already used. Test doubles for Git in the worktree and release fixtures accept the added configuration options.
