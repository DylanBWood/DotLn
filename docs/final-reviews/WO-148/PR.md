# WO-148

Watching a real order with the resident's mission check no longer means hand-writing a store. `node scripts/resident-bind.mjs WO-NNN --surface <path>... --transport <claude-cli-print|codex-cli-exec> --model <model> --effort <level>` reads the canonical control state for the order in its own worktree, locates that worktree through `git worktree list`, takes the merge base with the `main` the branch was created from (or the commit the operator supplies with `--base`), and writes `<control lane>/local/resident/WO-NNN-<n>/`: a `resident.json` holding the Contributor build's graph and environment, the mission-only presence policy and one `mission-check` actor whose `MissionSource` names that worktree, the order's authority file as its contract, its decisions file when one exists, the vision document and exactly the surfaces typed on the command line, beside a `binding.json` recording the order, phase, worktree, base, surfaces, contract hash and the control segment read. It prints the launch, presence, status and `export DOTLN_RESIDENT_STORE` lines for that store. `--check <store>` compares the binding with canonical state and the store's own declared source field by field, names every mismatch, exits non-zero and prints no launch line for a stale binding; a rebind writes the next store and leaves the old one byte-identical.

**Why now.** WO-099 delivered the mission check, but its only live observation needed a synthetic worktree and a purpose-built store, and nothing connected "I opened a worktree for WO-NNN" to "a resident is watching it". The operator recorded that empty boundary as a candidate on 2026-09-20; this order closes it and consumes the capability on itself: WO-148 was bound four times during its own execution, and the filed live row is a real Codex CLI launch over the fourth store with the operator away, counting 20 changed paths all inside the 15 declared surfaces and returning a verdict with a hold. The row proves aim, not the work, and says so.

**What it costs, measured.** Per bind, one ignored store directory holding a 1,494-byte binding record and a 290,006-byte `resident.json` (the compiled Contributor graph and the pinned capsule), which is larger than the order's "few hundred bytes" estimate and is recorded as such. Four such stores are retained in this worktree's ignored lane and will be preserved on finish; prune eligibility is an explicit non-goal. One suite is added to the runner (14 real-Git cases, about 4 s). No gate, hook, key, daemon, schema, runtime or dependency changes; no `packages/*/src` file moved.

**What a reviewer should know before merging.** The lane must be ignored: bind asks `git check-ignore` about the two files it is about to write and refuses by name when either is visible, so a launchpad with a configured control root needs its own `.gitignore` rule before the first bind. The stale-binding refusal lives only in the command: a resident already running, a shell that still exports an old store, or an outside scheduler keeps judging its declared subject, which is the recorded limit rather than a resident-host change. No `claude-cli-print` mission check can run today, because the shared result schema emits duplicate enum items and the Claude CLI refuses it; the defect is reproduced and boarded with a public follow-up, and the live row used the unaffected Codex transport. The first verification found three false guarantees (a check that accepted a store retargeted through unchecked source fields, a successful check of a moved store that printed commands for its old path, and a configured lane that could put physical paths on a Git-visible surface); all three were repaired at their boundaries with defect-restored controls and re-verified. Final review reproduced the ideation receipt's one constructible issue, a merge base moved by integrating `main`, observed the check refusing it, and added that case to the suite.

**The change itself.** `scripts/resident-bind.mjs` (the command), `scripts/test-resident-bind.mjs` (its real-Git suite) and `scripts/evidence-resident-binding.mjs` (the live-row collector, which runs the shipped `presence away` and `resident --once` on the real clock) are new; `scripts/test-runner.mjs` registers the suite. Product 03 §Operator-presence policy states how a store is bound and what stays declared; the skeleton README's resident runbook names the command as the ordinary path and keeps the hand-written shape as the reference; the candidate document records its disposition. Two adjacent one-phrase corrections land under the bound: the README release block and the software-engineer edition both still called the economy support default-off after WO-150 made it default. Everything else is the version triple, the evidence and verification records, the twenty decisions and the regenerated projections.

**Validation.** `npm test -- --review` passed **24 suites, 0 failed, 263.22 s, 68 fresh tasks, exit 0** at code identity `22f57294` on the reviewed, staged tree, outside the sandbox. The focused suite passes 14/14; `publication:check` reports 273/273 headings and both editions current; `release check-surfaces --local`, `plan check`, `format:check`, `meta --check` and `work-orders index --check` pass; `git diff --check` is clean in the working tree and the index; the manifest and lockfiles are untouched. `main` did not move while this order was in flight, so no integration was needed.
