## Release overview

For anyone who runs the kit as an instance, and above all for an instance on a team's machine that core has never seen, v1.0.0 carries in one update what a queue of fifteen orders was filed to deliver. A new instance starts on Claude Code alone and looks for no other host until its configuration elects one. A person on an unfamiliar machine runs one command before installing anything and reads what the kit assumes of that host. An update keeps the bytes an instance changed, and says so before the merge and again before the publish. The owner of an instance names its own workers and models, reads what an order cost in tokens by class and by day, keeps tools under a root the kit never touches, and decides for each registered repository whether an order's records are filed into it or stay in the instance. A target order closes when its reviewed change is in the base by a merge commit, a squash or a rebase.

Underneath, an ordinary word on the private list no longer stops a gate, a publish or an export, and an entry listed under `refuse:` still stops all three. Every format the kit's sources read has one reader, and the document check refuses a new reader written by hand. The version is the operator's naming; by its content this is a minor release, and the roadmap's Teammate-ready rung, which older records call v1.0.0, is v2.0.0.

## Read before upgrading

**Before you take the release, sort the private list.** From this release an entry with no marker is a context entry: it stops no gate, publish or export, and each stage reads the lines the terms task prints for it. Move every entry that must never appear under a `refuse:` line first. Reread any entry that holds a number sign after a space, which now opens a comment, or that opens with `context:`, which is now a marker. A context entry still holds a target's publication for the reviewer's `--confirm-terms`, and still refuses the planning publication into a target.

**Elect the hosts you use.** A host that only a discovery record showed is off. Set `features.host-codex` or `features.host-copilot` in `dotln.config.json` and run `node scripts/harness.mjs emit`, or the next emit removes that host's surfaces. A seeded first order that has not run keeps its old text: take its authority, capability checklist, deliverables and second and third criteria from `scripts/kit/first-order.template.md`.

**On the update branch, before you publish it.** Run `node scripts/harness.mjs emit`, `node scripts/lineage.mjs index` and `npm run sync`, and commit what they regenerate; this release changes rows of the features page, and a document gate run without the sync fails naming it. Where the roadmap carries the release-history block, `npm run release -- list --markdown --write` writes the record of release tags and renders the index, and running the index command before it leaves the roadmap's check failing until it has run; otherwise run `npm run work-orders -- index`. Commit `docs/control/release-history.json` and `docs/control/workstream-observations.json` with the pages; until one refresh has written them the index check fails naming the command. The generated pages carry no data comments any longer, so a tool that read them takes `npm run work-orders -- index --json`. Then run `npm run plan -- check`: a planning receipt filed before this release is refused where one of its orders holds a paragraph, after its criteria or its non-goals, that opens with bold words and is no label. No committed order of core's holds that shape and no route files such a receipt again, so an instance that meets it reverts the update's merge and records the receipt in `FOR-CORE.md`.

**How orders are read has changed.** An order's header fields are read from its leading header alone, the text before its Objective, so a Release classification, Target release notes, Front page or Workstream line written below the Objective is no longer read. The readers take CommonMark's reading of an order's text. Where a wrapped line of the acceptance criteria opens with a tag's name, such as a placeholder `<option>`, or with a number sign, or where a paragraph, a bold label or a heading stands between criteria, the list would read shorter than written, and every reader of it now refuses the order by line with the remedy. Elsewhere in an order nothing refuses: a wrapped line of the header, of a Preflight or Objective paragraph or of a criterion that opens with a placeholder spelled as an HTML element's name (`<title>`, `<dir>`), with a greater-than sign, or with a hyphen, a plus sign or an asterisk before a space, starts a block, and the fields or the text after it are not read as written. Write such a token in a code span or keep it off the start of a line. No order, decision, report or stored body in core's record holds such a line where a reader acts on it; an instance that finds one in its own records reports it in `FOR-CORE.md`. An order that shows its header's form in a fenced block inside a list item or a quotation is refused as a duplicate, a malformed Review ladder line refuses on an open order, and a pull-request body with a hand-numbered item wrapped after prose is refused.

**A resident is started with its launcher.** Start it with `node scripts/resident.mjs`, as `node scripts/resident-bind.mjs` prints. One started through the package's own entry holds a mission check with no judgment (`documents-unread`) and reports its work orders unavailable, naming the launcher in both, and a script that builds a resident host with the removed `workOrderIndexPath` option is refused by name and passes `workOrderCards`. A store pinned before this release on one of 59 older orders reports a changed contract clause until it is bound again. A Markdown discovery profile is refused by name.

**Files that arrive or leave.** New seeds and kit files: `.gitattributes` where the instance has none (a clone whose line endings Git had already converted runs `git add --renormalize .` once and commits the result), `FOR-CORE.md`, `docs/OPERATOR.md`, `THIRD_PARTY_NOTICES`, and the carried Markdown parser with its license and notices under `scripts/lib/vendor/`, about 650 KB in all. The seeded repository-profile and workstreams pages changed; an instance keeps its own and finds the new text in the kit guide and the two templates. The next emit removes the four presence hook files and the two per-model worker definitions an earlier kit wrote, and a target's bundle is one hook file smaller. `scripts/check-role-oracle.mjs`, the role-oracle task and the self-host modes of `scripts/console-fixtures.mjs` are gone.

**Configuration that is now judged.** `dotln.models.json` is read on every load of the configuration, and it and the `workers` section refuse an unknown key, a binding to an unlisted model, a name that would mean two things, an effort outside its provider's levels and a negative price, by file and key; ten words a worker definition reads as something else, such as `true`, `no` and `inherit`, are refused as a model's id. A document root may not lie under `extensions/`. `repositories.<id>.records` takes `target` or `instance`. A `spend.daily` of any shape but the two admitted fields refuses the budgets' load. A hook input whose `background_tasks` is no array is refused.

**Refusals added.** A worker's stop is refused once while a background task it started is live. A Claude Code completion that attests a version other than the one its hook observed is refused, naming the observed one. An update's publish refuses a merge that rewrote a file both the instance and the starter changed, naming each path, the command that restores it and `--take <path>`; it also refuses a revision no fetched ref names, a merge that joins more than two lines, a second starter revision on one branch, a clone too shallow to hold the merge base and histories that share no commit. An update's plan refuses a generated surface as locally modified where a carried compiled runtime file holds bytes no kit wrote. On macOS a gate shows the file-events daemon's size and refuses above 1 GiB; the remedy it names is `sudo killall fseventsd`, or a restart of the machine where there are no administrator rights.

**If you took v0.121.0 or v0.122.0 by merge.** Two files could have been merged over an instance's own bytes without notice. Compare the first order's text and `docs/control/budgets.json` with the commit before that update's merge.

**Interfaces a tool may rely on.** `npm run resume -- status --json` prints `schemaVersion` as its first key, and each element of its all-orders form carries it. `npm run meta -- --usage --json` carries one too. A withdrawal of an order that was never activated is that order's first control event, which a kit older than this release refuses to read. In a kit root no order's number switches the release-note contract on any longer; an instance that relied on an order numbered as one of core's to do so loses that at the upgrade, which planning holds as a follow-up.

**The library versions.** `@dotln/skeleton` is 0.91.0, `@dotln/console` 0.6.0 and `@dotln/compiler` 0.44.0; the resident's and the console's library contracts changed with them.

## Substantive changes

**The private list and the words screens.** The list has two classes, written as sections under `refuse:` and `context:`. The terms task prints a `FAIL` line and exits nonzero for a refuse entry alone, and prints a `CONTEXT` line by file and line for each context match, which the executor, the verifier, the reviewer and a planning pass each read and count before they hand off. Runs of letters are joined into a candidate only across the separators a writer or Markdown produces, so letters on either side of a brace or a pipe in minified code are no word. The kit ships `scripts/kit/terms.example.txt` with a sample and the lines the task prints for it. The verbatim screen compares words, taking a link target, a URL, a code span and a path as one word each.

**Reviews, repairs and the complete run.** An order's header sizes its first review round with `**Review ladder:**` (`full`, `combined` or `paired`), every brief states what blocks from round one, and the executor judges a finding by which writer produces its input before it changes code. A fix dispatch repairs what its failed report names and has that repair read once. A repair made after a failed run takes no review round, and the run after a failed run is started with `--keep-going`. The complete review run takes its four exclusive suites as one convoy and runs the hook suite in three shards: one comparison pair on one host went from 54 minutes to 42, which shows a direction and no exact figure. Lists of test titles, a per-case time bound and a fixture that followed the latest order are gone, each replaced by a check of the thing itself.

**One reader for each format.** Markdown is read through the pinned Prettier Markdown parser behind `scripts/lib/markdown-links.mjs`, carried in the scripts so the lifecycle still runs before any install; a work order has one reader; shell text and JavaScript source each have one build-free reader. A generated page is never read back: what the index observes outside the repository is kept in two committed records. `node scripts/docs-check.mjs` refuses a non-test source under `scripts/` or `packages/*/src/` that reads Markdown or JSON by pattern, naming the file, the line and the reader to call.

**Role text.** A shared rule is a record with the roles it binds, and a role's root holds the rules that name it. `npm run plan -- refute` prints the parent's refutation steps with its prompt, the review helper's mechanics have a section of their own in product 07, and `npm run meta` reports for each role its installed bytes and the bytes of the reads its root names. A role sentence is changed by editing it and regenerating.

**A new instance and an unfamiliar host.** The seeded first order and security page name Claude Code alone. `docs/OPERATOR.md`, generated from the kit guide's marked command blocks, holds the lines an operator types for the whole cycle, and `node scripts/launchpad.mjs commands` prints it before any install. `FOR-CORE.md` is the one file where an instance keeps what core should hear, which each final review and planning pass appends to. `node scripts/doctor.mjs` reports each assumption the kit makes of a host with its remedy, and prints no host name, user name, URL or absolute path. In a kit root the host check is sized to the tasks that root's gate carries, and an update's preview prints a line for each incoming floor the host does not meet.

**Updates.** A file both the instance and the starter changed keeps the instance's bytes through the merge; the preview lists those files first and the publish judges the update's own merge commit. A generated surface the instance's own emit wrote is planned as `re-emitted` where the instance's harness check passes. Every spelling of a kit worker launch counts against the cap.

**Workers, models and usage.** Models are rows of data and a worker is a name bound to a model for each provider; `npm run worker -- list` and `-- show <name>` say what a name runs and how this session launches it, and no role text, hook or definition holds a model. `npm run meta -- --usage` reports tokens in four classes that do not overlap, by order and by local calendar day, with an estimate in dollars where the instance declares prices.

**An instance's own tools.** `extensions/` is the instance's by guarantee: no kit path begins with it and no kit scanner or formatter enters it, save the screens for what must not leave a repository. `.claude/settings.instance.json` adds an owner's hooks and permission rules to the settings the kit emits, for the launchpad and a target worktree alike, and can remove or replace nothing the kit emits.

**Targets and teams.** A profile's directory holds area notes, each naming the paths it covers and the commit it was true at, and a target order's briefing prints them with the count of commits that touched those paths since. The close accepts a squash or a rebase by patch identity and takes `--merged-as <commit>` where the change landed under another patch. `contributions.authors` lists the people whose commits are the instance's own. The kit guide gains a section on working as a team on one instance.

**Planning.** A workstream document carries an initiative's layout, whose planned items are not orders, and a pass files the next wave. An order that was filed and never activated can be withdrawn, a register batch is judged on the state it produces, a receipt's known issue can be disposed, and `npm run plan -- check` prints a `preflight advisory` for each suite an open order's steps touch and its Preflight line leaves out.

**Pacing and bounds.** A dispatch bound counts worked time, so an order that sat overnight is not charged for it. `spend.daily` declares what a day may use, and a prompt shows the day's use against it and says when to finish the step in hand and stop. An executor keeps `docs/evidence/WO-NNN/standing.md` while it works, and `npm run resume -- checkpoint` records a recovery point without an event. `accept-overrun` takes `subagentCap`, so no session edits the budgets file for one order.

**Hooks.** A tool call starts only the hooks that judge that tool, the presence heartbeat rides inside hooks that already run, and the authorship snapshot rehashes a file only when its state changed: the fixed sequence of fifty calls started 400 hook processes before and 210 after.

## Evidence and compatibility

This release is built on `0097fcac608bcaa24c51c8b6d6020fc2382ea141` and is tagged v1.0.0 when the order's release close publishes it; the release manifest is written then. It runs on Node 24.15 or later in the 24 line and on Node 26, and on Git 2.31.0 or later. macOS is exercised; Linux and WSL2 are designed for and not exercised; native Windows is unsupported.

The order was verified seven times and reviewed twice. Five verifications and the first final review failed, on twenty-seven blocking findings in all, and each was repaired and run again; the [seventh verification](../../verifications/WO-276/VER-007.md) and the [second final review](FINAL-002.md) pass. Of 133 acceptance criteria, 130 are met and three are recorded as contradictory in their own wording, each confirmed by both reviews. The complete review run passes at the reviewed code: 48 suites and 125 tasks, none reused.

Known limitations. The readers moved onto the shared parser return less than the old line readers did where a hand-wrapped line opens a block, in about thirty readers and in no committed document; the [census](../../evidence/WO-276/final-review-002/block-openers-census.json) names each, and whether to harden them or move the fields the lifecycle acts on out of prose is [the operator's decision](../../evidence/WO-276/decisions.md#wo-276-d199--the-block-opener-class-where-a-wrapped-line-opens-a-block-the-moved-readers-return-less-than-the-bases-line-readers-read-in-about-thirty-readers-and-in-no-committed-document-and-the-choice-of-repair-is-the-operators). An update interrupted part way and tried again can run a compiled runtime file the incoming kit added before it compares it, and can refuse its surfaces for a runtime file the kit dropped; the close takes a squash reading before its rebase rule ([decision](../../evidence/WO-276/decisions.md#wo-276-d200--follow-ups-on-the-update-plan-and-the-close-a-runtime-file-the-incoming-kit-adds-is-loaded-before-it-is-compared-a-retry-refused-for-a-file-the-kit-dropped-and-a-squash-reading-that-answers-before-the-rebase-rule)). During a launcher-started resident's first card read a helper shows its work orders as unavailable ([decision](../../evidence/WO-276/decisions.md#wo-276-d201--follow-ups-on-the-resident-a-first-card-read-that-tells-the-operator-to-use-the-launcher-it-was-started-with-and-a-failed-card-read-run-again-at-every-tick)). A sentence copied whole into one inline code span passes the verbatim screen, since a code span is one word. One discovery timeout met in a complete run did not reproduce and is deferred. The first final review's sixty-two follow-ups, less those its repair took, stay with planning under their register entries.
