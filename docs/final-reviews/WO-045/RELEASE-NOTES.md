## Release overview

DotLn v0.20.0 makes the two boundaries every governed session and every worker cross first refuse malformed input positively. The kernel event-log codec validates each JSONL line against EventEnvelope schema 1 and answers a bad line with a typed code, a JSON path and the physical line number instead of casting it into an event that fails later inside a reactor or a fold. The harness hook host validates its stdin the same way and answers with the event's own protocol refusal instead of relying on a downstream throw, and the generated hooks hand their raw input to that decoder while keeping `analysis:` and `operator override:` reachable ahead of the runtime import. Every committed event stream decodes unchanged; nothing is migrated or rewritten. This is the first of the four codec boundaries the critical path holds mandatory before the unattended loop touches anything the operator keeps.

## Read before upgrading

Source release target v0.20.0 includes kernel 0.3.0, skeleton 0.17.0 and compiler 0.11.1. Console 0.1.6 and third-party dependencies are unchanged; the lockfile diff is the three workspace versions and the skeleton's two pins. No package distribution or hosted service is introduced.

The kernel's public `decodeLog` is stricter and that is the reason for its minor: a line that previously returned as an event now throws `Malformed JSONL at line N: detail (CODE at PATH)`, and `appendEvent` refuses to extend a log that no longer decodes. The new `tryDecodeLog` returns a `DecodeResult` carrying the event array for callers that want the result without the throw. Validation is closed: an unknown envelope key refuses, `schemaVersion` must be the number 1, `eventId` must equal `evt_N` for physical line N, identifiers must be strings, `occurredAt` must be a finite number, optional identifiers must be strings when present, and a non-finite number anywhere in the payload refuses with its bracketed path. Payload meaning stays with reactors; scalars, `null`, arrays and objects remain valid payloads; CRLF framing and the empty log are unchanged. All 66 committed EventEnvelope streams (3,968 events) round-trip byte-identically, so no historical log needs attention. A caller that appends a non-conforming draft is not stopped at append time; the next read refuses with the typed path, and WO-048 is nominated to validate the draft before writing.

The skeleton's `decodeHarnessInput(value, expectedEvent?)` requires a plain object with string `hook_event_name`, `cwd` and a non-empty `session_id`, an event among the four the host serves that matches the hook's configured event, string `tool_name`, `tool_use_id`, `transcript_path`, `harness_version` and `prompt` when present, plain-object `tool_input`, `tool_response` and `effort` when present, `effort.level` among `low`, `medium`, `high`, `xhigh` and `max`, and boolean `stop_hook_active`. Inherited and accessor properties refuse without being evaluated; undeclared native keys pass through. A `tool_response` that is an array or string refuses, which no native tool has produced and MCP responses have not yet exercised. The refusal shape follows the event: PreToolUse denies with `DOTLN_HARNESS_INPUT_REFUSED: CODE at PATH: message`, UserPromptSubmit accepts with the same diagnostic, PostToolUse and Stop report it as an advisory.

The generated hook entry changed: it reads stdin to text, parses tolerantly, runs the independent recovery prelude only for a plain object that has a string session or carries a recovery phrase on UserPromptSubmit, and otherwise imports the runtime and passes both the parsed value and the raw text to the host. Invalid JSON therefore reaches the typed refusal instead of the bootstrap fallback. The compiler contract and every hash preimage are unchanged; rebuild and regenerate the harness from reviewed source when updating an existing installation, which installs snapshot `902393d5d4254be5` beside the retained previous one.

Evidence editions may now carry a numbered revision for artifact-identity and verification, resolved to a numbered subdirectory of the kind's directory such as `artifact-identity/001`; original directories are never overwritten and the immutable writer still refuses replacement.

## Substantive changes

- Kernel: `packages/kernel/src/store.ts` replaces the framing-only parser with `tryDecodeLog`, a closed schema-1 validator with an iterative payload walk, and routes `decodeLog` and `appendEvent` through it; `types.ts` adds the generic `DecodeResult` type; the README map and the `ac7` surface list export both. `packages/kernel/test/store-decode.test.ts` runs the 22-line corpus at lines 1 and 2, the accepted payload forms, the framing diagnostics and the deep-payload case; `store-history.test.ts` decodes every committed `.jsonl` under `docs/`, `corpus/` and `packages/*/fixtures/` strictly unless `fixtures/jsonl-protocols.json` names it as another protocol.
- Skeleton: `packages/skeleton/src/harness-host.ts` adds `decodeHarnessInput` and gives `runHarnessHook` an `unknown` input plus optional raw text, answering parse and decode failures with the event's protocol refusal before any root, snapshot or writer work; `HARNESS_HOST_VERSION` is 0.17.0. `test/harness-input.test.ts` covers 28 malformed shapes, inherited and accessor fields, native metadata and all five effort levels, and proves the boundary is never called for malformed input.
- Compiler and generated hooks: `packages/compiler/src/harness.ts` emits the `rawInput` and `recoveryInput` entry lines; the nine hooks and the manifest are regenerated at compiler 0.11.1 and skeleton 0.17.0. `scripts/test-harness.mjs` adds the WO-045 case that pipes ten malformed payloads, two recovery prompts and a non-string prompt through the emitted PreToolUse and UserPromptSubmit processes; both fixture scripts accept the new trailing argument, and the WO-131 `{not-json` case now expects the typed refusal.
- Evidence editions: `packages/skeleton/src/evidence-editions.mjs` accepts numbered artifact-identity and verification revisions; `test/evidence-editions.test.ts` shows the original surviving beside the revision and the malformed revision strings refused.
- Versions: kernel 0.3.0, skeleton 0.17.0, compiler 0.11.1, `COMPILER_PACKAGE_VERSION`, the contributor profiles' runtime pin, the skeleton's dependency pins and the lockfile.
