## Source review

`store.ts` replaces `parseLog` with `tryDecodeLog`, which keeps the two framing checks and their messages (missing final newline, invalid JSON, expected a JSON object) and then validates each parsed object in a fixed order: unknown keys first, so a foreign key fails before a missing one is blamed; the seven required keys by own-property presence; `schemaVersion === 1`; string type for the four required identifiers and any present optional identifier; `eventId === "evt_<lineNumber>"`, which pins append order to physical position; `occurredAt` a finite number; then an iterative walk of the payload with an explicit stack that refuses non-finite numbers with a bracketed path and never recurses, so a 12,000-deep array validates without exhausting the call stack. Paths use dotted form for identifier-shaped keys and `["…"]` otherwise, so `$.payload["a.b"][0]` is unambiguous. The failure message keeps the historical `Malformed JSONL at line N:` prefix and appends `(CODE at PATH)`. `decodeLog` throws the message and returns the value; `appendEvent` counts through `decodeLog`, so a corrupted log refuses on append as well as on read. Nothing about `encodeLog`, the event type or the payload semantics changed, which is why every committed stream is byte-stable and the WO-003 oracle hash is untouched. `DecodeResult<T>` in `types.ts` is the discriminated union the order specified and is exported through the README map, which the `ac7` surface list now names.

`harness-host.ts` adds `decodeHarnessInput`, a wrapper that converts any thrown read into `UNREADABLE_INPUT` at `$`, over `decodeHarnessRecord`. The record check admits only plain objects whose prototype is `Object.prototype` or `null`; for each declared key it reads the own descriptor and refuses an accessor before ever invoking it, so the test's throwing getters are never called; it then requires the three required strings, checks every declared string field that is present, requires the event to be one of the four the host serves and equal to the configured event, refuses an empty session identifier, requires `tool_input`, `tool_response` and `effort` to be plain objects when present, checks `effort.level` as a data field among the five levels, and `stop_hook_active` as a boolean. Undeclared native keys pass through, which is what keeps this forward-compatible with new host metadata. `runHarnessHook` takes `decodedInput` as `unknown` plus an optional `inputText`; when text is supplied or nothing is, it parses the text itself and answers a parse failure with the event's own protocol refusal before any root, snapshot or writer work. The boundary is invoked only after a successful decode, which the skeleton test proves with a counting boundary.

The compiler entry (`harness.ts`) reads stdin to `rawInput`, parses tolerantly, and computes `recoveryInput`: a plain object whose `prompt` is absent or a string and which either has a string `session_id` or, for `UserPromptSubmit`, carries a recovery phrase. Only then does the independent recovery prelude run, with `session_id` coerced to string-or-undefined; otherwise the runtime is imported and `runHarnessHook` receives both the parsed value and the raw text. That is the smallest change that stops the prelude from handling or failing on malformed input ahead of the decoder while keeping `analysis:` and `operator override:` reachable without a usable session or a healthy runtime, which is what D002, the WO-131 cases and my piped probe show. The two test scripts widen one regex each to tolerate the new trailing argument, and the WO-131 case whose `{not-json` payload previously reached the bootstrap fallback now expects the typed `INVALID_JSON` refusal, which VER-001 O4 records as the intended consequence.

`evidence-editions.mjs` removes the rule that artifact-identity and verification editions may not carry a revision and resolves a numbered revision to `<kind>/<revision>`; the three-digit non-`000` pattern and the immutable writer are unchanged, and the new test shows the original directory surviving beside the revision and `000`, `1`, `0001`, `../001` and `001/next` refused. This is the D005 adjacent repair that let the integrated tree hold fresh compiler-dependent evidence without overwriting the bytes VER-001 judged; it is a shared check inside the order's own evidence surface and it is named here so the next edition's path shape is expected.
