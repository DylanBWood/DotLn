## Release overview

For anyone running an instance of the kit, this release turns the standing rule that no operator message is saved verbatim in a committed artifact into something the kit enforces: every role and every worker carries the rule, and the document gate compares what a branch adds against the ignored intake captures of the checkout it runs in, failing by file, line and capture digest without printing a word. The same gate screens a branch's added lines with the instance's private local-terms list, and the publish helpers screen a branch's committed change before the first push. A background worker's hand-back is journaled as the host's message, never the operator's. Discovery names a record it cannot parse and records each observation once. The launchpad publish form needs the passing final review in the committed control record. A record filed into a registered target ends with a footer naming a launchpad commit that holds every file its links reach. One verification judged the change and passed every criterion.

## Read before upgrading

After taking this release, re-emit with `node scripts/harness.mjs emit` and start a new session: the emitted host settings, the role text in both skill roots and the compiler version changed, and the host reads the emitted settings when a session starts. Render the features page with `npm run features -- render`, since the registry gains `verbatim-operator-words`.

`npm run test:docs` now fails a branch whose added lines carry twelve consecutive normalized words of a capture under that checkout's ignored intake root, naming the file, the line and the capture's digest. A message the operator asked to save is recorded as an `operatorQuote` carrying `captureSha256` and `requestedIn`, the digest of the capture holding that request; a record the branch adds that attributes words to the operator without a capture citation fails, where it advised before; a record written before the branch keeps its bytes and its note. A checkout with no capture prints `verbatim screen: no captures` and passes, and a directory or capture below the intake root that its owner closed is named in an advisory. An instance may elect `features.verbatim-operator-words` in `dotln.config.json` to turn the rule off; both checks then advise.

The document selection gains a `terms` task: with a private list registered at `docs/control/local/terms.txt`, a term in a line the branch adds fails by file, line and mode (`FAIL docs/notes.md:3: a local term in refuse mode` is the shape), never printing the term; without a list the task prints `local-terms list: unavailable` and an advisory and passes. `node scripts/refute-plan.mjs publish`, `node scripts/launchpad.mjs update --publish` and `node scripts/worktree.mjs publish WO-NNN --title --body-file` refuse a branch whose committed change carries a term before any push, and a malformed list refuses naming its line.

For a registered-target order, commit the instance records (the order's records and evidence) on the order branch before `npm run resume -- target-records`: the filing refuses while a source, or a file a source links, is uncommitted at the launchpad's HEAD, naming that step, and the footer it writes names that commit. Then commit the moved records' removal. The next-step texts and the reviewer role say so. The launchpad publish form of an order branch refuses, naming the phase, until the passing final review is in the committed control record: record the pass, commit the reviewed state, then publish.

A background worker's hand-back arriving through the prompt hook is journaled with source `host-agent-handback` and attribution `host`; `npm run plan -- check` refuses a standing rule that cites such a row, and `npm run plan -- failures` counts it under `hostHandbacks`, outside the interventions. `npm run discover -- harness claude-code` on a record without `versions` gives it the list, appends a version or a line only when it is new, prints `recorded` or `already recorded`, and names a record it cannot parse; `npm run resume -- status` and an attestation name a parse error apart from a missing observation.

## Substantive changes

The rule in every role and worker: `packages/compiler/src/harness.ts` defines `operatorWordsRule` and `workerNoPrintRules` once beside the worker definition, which carries both with a sentence that what a worker returns may be filed and so paraphrases the operator too; `packages/skeleton/src/loadouts/contributor.ts` adds both to the shared corrections of every role and to the router's own procedure, names awaiting-plan-approval in the router's stop list with the operator's next step, and has the reviewer's target clause commit the instance records before filing; the generated role roots, the three worker definitions and the hooks carry the result, and the role oracle `packages/skeleton/fixtures/wo259-role-baseline.json` pins it.

The document gate: `scripts/lib/branch-changes.mjs` reads a branch's change against its merge base with `main`, with untracked files whole, renames found, type changes included, a deletion's join recorded as a boundary and a header path holding a space read by its own name; `scripts/lib/verbatim-screen.mjs` compares the added lines with every text capture under the intake root through a hashed window matcher, excludes runs the base already held, honors a typed quotation's span for its own capture, and names what it could not read; `scripts/docs-check.mjs` fails a changed record's attributed speech without a capture citation, requires `requestedIn` on a quotation the branch adds, reads the election and prints the screen's status line; `scripts/lib/feature-registry.mjs` adds the row.

The terms screen and the publish helpers: `scripts/lib/terms.mjs` exports `localTermFindings`, the findings form `checkLocalTerms` wraps; `scripts/lib/branch-terms.mjs` screens a branch's changed text files and keeps the matches that touch an added line; `scripts/terms.mjs branch` is the document selection's `terms` task in `scripts/test-runner.mjs`; `scripts/lib/launchpad-publish.mjs` screens both doors and names a malformed list's line; `scripts/worktree.mjs` reads the committed control record's phase and screens the branch before any remote step; `scripts/lib/outward-lint.mjs` says what a configuration finding means.

The hand-back and discovery: `packages/skeleton/src/harness-host.ts` recognizes the envelope the host wraps a hand-back in and journals it under the host's source, and no longer adds the operator-question context to a hand-back or a task notification that ends in a question mark; `scripts/lib/planning-document.mjs` refuses such a row as a rule's provenance; `scripts/lib/plan-failures.mjs` counts it apart from the interventions; `scripts/resume.mjs` reads the discovery record once per command and names a parse error; `scripts/discover.mjs` deduplicates versions and lines and names a record it cannot parse.

Filed records: `scripts/lib/target-records.mjs` refuses a first filing whose sources or linked files are not committed at the launchpad's HEAD, reads Markdown links and the `href` and `src` attributes of raw HTML with their character references decoded, writes the footer naming the commit at which the links resolve, and resumes an interrupted filing with the footer version its saved operation records; `scripts/lib/markdown-links.mjs` exports the shared `decodeCharacterReferences`; `scripts/resume.mjs` puts the records commit before `target-records` in both next-step texts.
