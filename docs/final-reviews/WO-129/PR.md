# Suite successes are keyed by declared inputs and shared across worktrees, so lifecycle transitions stop re-running unchanged suites and every fresh task names what changed

Five of WO-125's ten fresh full gates followed a lifecycle transition with no source change and re-executed all 78 tasks (613 to 839 s each), because every suite's reuse key hashed the commit, every ref, the checkout path, the CPU count, the OS release and the whole Git configuration. Each suite's key is now exactly what that suite reads: its declared candidate paths, its declared Git state, the projected environment, the toolchain digests and the installed roots. Every inventoried suite declares its Git state: none by default; `index` reads `HEAD` and `refs/tags/*`, the current planning checks read `HEAD`, and `authority-evidence` reads `refs/tags/v0.16.0`. A checkpoint ref, a new branch, a commit of identical bytes or an appended control event changes no key except those of suites that declared that state, and an unknown suite name cannot grant itself reuse. On the operator's host the first full gate after `ImplementationReady` composed 32 fresh and 46 reused tasks in 390 s; a later document-only change composed at 376 s in a Claude Code session.

Every fresh task now says why. The runner prints one line per executed task naming the policy that forced execution and the input classes that differ from the suite's newest prior success (source, documents, git, environment, toolchain, runtime, declaration) with bounded path lists, for example `FRESH format (documents: docs/control/current.md, docs/control/orders/WO-129.jsonl, docs/evidence/WO-129/decisions.md, docs/final-reviews/WO-129/FINAL-001.md, docs/final-reviews/WO-129/PR.md (+4 more); environment)`, or `no prior success`; the gate row keeps the same reasons beside `executionMode`, `freshSuites` and `reusedSuites`. The physical checkout, CPU count and OS release are recorded as execution facts on the row, not hashed into any key.

Sealed successes live once per repository under `dotln/suite-success` in the common Git directory as version-3 records, so the main checkout and every linked worktree share them; version-2 records are ignored and never migrated. A fixture launches real npm gates in two worktrees at identical candidate and installed bytes and reuses the executed suite, and one differing byte invalidates it. The generated hooks refuse agent writes into the cache from any worktree, whether or not a gate is active. VER-001 found that npm's `npm_config_local_prefix` still carried the checkout path into every key through the canonical entry points; the repair gives it the worktree-relative identity `PATH` already had, while execution keeps the real value, and declares the historical tag `authority-evidence` reads. VER-002 confirmed both in both directions against the pre-repair module.

The operator's execution-time scope expansion replaces the exact CLI-version allowlists in the worker transports with minimums, Claude Code `2.1.270` and Codex CLI `0.154.0` with no upper bound, so a routine CLI upgrade no longer blocks the requested model; older or unparseable versions refuse with the required minimum, and the effort, model, restricted-launch and result contracts are unchanged.

Application target `v0.17.4` (patch) above the local `v0.17.3`; skeleton `0.15.4` with regenerated runtime pins and snapshot; compiler, kernel and console unchanged; no new dependency. Suite successes recorded before this change are version 2 and execute once more. Fresh WO-129 authority (001) and feedback (001) editions are selected in `docs/evidence/current.json`.

[VER-001](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-129/VER-001.md) failed on the npm prefix with one low finding beside it; the repair closed both, and [VER-002](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-129/VER-002.md) passed all eight criteria with one non-blocking finding: the repair's own passing gate on the Codex host persisted none of its suite successes, and the runner cannot tell. [FINAL-001](https://github.com/DylanBWood/DotLn/blob/main/docs/final-reviews/WO-129/FINAL-001.md) records the review: the fixtures reproduced, a two-worktree identity probe on the real host, a census of the shared cache against every gate in the series, the host-gate capture checked against the retained store and the control log, byte identity between the build and the pinned snapshot, a clean-room screen and the canonical evidence gate on the review tree. [D006](https://github.com/DylanBWood/DotLn/blob/main/docs/evidence/WO-129/decisions.md) defers the persistence finding to a follow-up with diagnosis first. Non-blocking: the reviewed environment projection still bounds reuse to one session on Claude Code hosts; the cache grows without pruning (284 records, 24.5 MB); the declaration version has no dedicated fixture.
