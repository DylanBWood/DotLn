## Release overview

Application v0.95.0 closes twenty follow-ups that earlier orders boarded on the resident, the vertical, the console, intake and triage, audit, the corpus lanes and the kernel's command admission, and that no later order took: 14 are settled with a fixture case and a paired control that fails with only that row's fix reverted, and 6 are declined to planning with their present harm and reversal condition. The visible payoff is that a malformed new command is refused before it is stored, a recovered source-change result is refused with the same typed reason as a fresh one, live status shows how a resident-owned continuation ended, the review loop stops at an explicit per-invocation bound, and a witnesses step can be stopped and resumed without leaking a browser.

Audience: operators who supervise a resident and read its live status, instances that run the vertical's review loop and browser witness, maintainers of the kernel's outbox and the source-change host, and maintainers of the WO-103, WO-105 and WO-107 corpus lanes.

## Read before upgrading

- **New commands are admitted structurally.** `persistCommand` and a new `CommandPersisted` append through `appendEvent` require a non-empty `commandId` and `workstreamId`, an optional `episodeId` and `resource` that are non-empty when present, an `Act` intent with a non-empty `effect`, and a JSON `payload`: plain objects and arrays of own enumerable data properties holding strings, booleans, `null`, finite numbers or further such values, with no cycle. A refusal throws `CommandAdmissionError`, whose trace's branch path is `persist`, `malformed` and the refused field's name. The append checks the draft and again the record it decoded, so a value that serializes differently cannot store an incomplete command. Historical decoding and `replayOutbox` keep the ID-only rule, so old logs replay unchanged; a caller that appended a command with only a payload now gets the refusal ([D016](../../evidence/WO-220/decisions.md#wo-220-d016)).
- **Recovered source-change results are refused with a type.** A rerun that re-observes an unreceipted committed result after an interruption or a crash records `SourceChangeRefused` with the refusing check's `host-admission-` reason (for example `host-admission-effect`) and closes the command, as a fresh return does; a pending terminal signal still takes precedence and leaves the command undecided. WO-204, which rewrites this host next, must keep the rule ([D007](../../evidence/WO-220/decisions.md#wo-220-d007)).
- **Live status changes shape inside the existing contract.** A finished resident continuation appends `intent-resolved`, `intent-refused` or `intent-needs-human` to the indexed work-order phase (for example `active; intent-resolved`), and an order missing from the index appears as `index-unknown; intent-…`. Authority expiring between steps yields one `intent-needs-human` hold and removes the actor, and the budget line reads "portfolio actors only; intent admissions excluded". The v1 schema already admits any phase string; a consumer that compares `phase` for equality sees the compound value ([D004](../../evidence/WO-220/decisions.md#wo-220-d004)).
- **The review loop has invocation bounds.** At most sixteen combined inline and body triages and sixteen outward actions run per invocation, and the loop stops with `needs-human` naming the next item before acting on it. The eight-body allowance now excludes an unchanged body rebound after the loop's own repair push, but that rebinding still counts as a triage. Supplied judgments count toward the triage bound as well as fresh episodes ([D010](../../evidence/WO-220/decisions.md#wo-220-d010)).
- **Stored judgments that fail today's validation are record refusals.** Intake counts one as a bounded host fault and holds after its attempts; triage ends the item in human attention. Neither launches a new episode for the same record or calls it an episode failure ([D014](../../evidence/WO-220/decisions.md#wo-220-d014)).
- **Retry clocks move.** Preparation backoff starts when the failure returns, so a long forge read or episode no longer spends the delay while it runs; the doubling, the five-minute cap and authority expiry are unchanged. A continuation's failure series resets only after a new step receipt, not on any normal return ([D015](../../evidence/WO-220/decisions.md#wo-220-d015), [D010](../../evidence/WO-220/decisions.md#wo-220-d010)).
- **The browser witness takes an abort signal.** `runScenario` accepts `signal`; on abort it kills the owned browser server, waits for it, saves the process record and rejects without writing a result. The witnesses step passes the run's signal and keeps each attempt's directory; a rerun recovers the latest attempt's process record and runs in a fresh numbered directory beside it (for example `browser-0-1` after `browser-0`). A directory that holds only pre-launch files and no process record recovers as empty ([D011](../../evidence/WO-220/decisions.md#wo-220-d011)).
- **The intent-only resident is quieter.** With a vertical scheduler and an unbound legacy portfolio actor, an idle tick records no `ActorUnavailable`; a missing runtime capability is still reported, and a portfolio-only resident still reports its unbound actor ([D020](../../evidence/WO-220/decisions.md#wo-220-d020)).
- **Retained qualification records.** The T1 schema now declares `minLength` 1, so new T1 answers with an empty receipt field are refused. Historical WO-138 records validate against their retained build's schema, recognized by comparing its source text with the current function's. A formatting-only edit to `taskSchema` would therefore refuse those records until the recognition binds by value (FUP-1330ac1551dff7d1, [D032](../../evidence/WO-220/decisions.md#wo-220-d032--ver-001-pass-board-the-retained-schema-recognitions-dependence-on-the-current-functions-source-text)).
- **Versions.** Application v0.95.0 is a minor release over v0.94.0: kernel 0.8.0, skeleton 0.68.0, browser-evidence 0.2.0 and console 0.4.8; compiler 0.31.0 and beacons 0.1.1 stay; no dependency is added.

## Substantive changes

**Kernel** (`packages/kernel/src/core.ts`, `packages/kernel/src/store.ts`). `assertCommand` and `CommandAdmissionError` are exported; `persistCommand` admits before inserting, `replayOutbox` uses the internal ID-only insert, and `appendEvent` admits a `CommandPersisted` draft and its decoded record. The README's export map names both symbols.

**Source-change host, repairs and resident** (`packages/skeleton/src/source-change-host.ts`, `repair-host.ts`, `resident-host.ts`, `resident-state.ts`, `runtime-status.ts`, `vertical-resident.ts`, `audit.ts`). `run` catches a recovery effect or observation failure after `recoverTermination`, delivers any pending signal first and closes through the check's `host-admission-` refusal; a refusal after the receipt is persisted still throws. `RepairHost.sourceHost` puts an item-namespaced child under the configured parent unless the child's persisted command already records the plain parent. The resident folds `lastNoOpKey` from the recorded reason, phase and replayed arm generation; the host skips the legacy portfolio actor for an intent-only idle tick after the capability check. `projectRuntimeStatus` adds the expiry hold and the outcome annotation. The vertical resident resets continuation backoff only on a new `VerticalStepCompleted` and spaces preparation retries from `now()` after the failure. Audit admits a state-only or environment-only partial suffix for `cannot evaluate revocation` refusals.

**Vertical runtime and review loop** (`scripts/lib/review-comment-loop.mjs`, `vertical-primitives.mjs`, `vertical-judgment.mjs`, `vertical-runtime.mjs`). `REVIEW_TRIAGE_LIMIT` and `REVIEW_OUTWARD_LIMIT` (16 each) with stops before an item opens and before a resumed triage, push or dispose; `ownPushBodyRekey`; `validateSnapshot` shared by fresh and cached resolution inputs; `JudgmentReplayError` for a stored result that fails current validation, mapped to a bounded intake refusal and a human-attention triage result; the browser attempt directory loop with `recoverFrom` and `signal`.

**Browser evidence and console** (`packages/browser-evidence/src/index.ts`, `processes.ts`, `types.ts`, `packages/console/src/runtime-status.ts`, `live.ts`). The abort handler and checkpoints in `runScenario`; pre-launch recovery in `recover`; the portfolio-only budget labels in both renderers.

**Qualification probe and corpus lanes** (`scripts/probes/local-model-role-qualification.mjs`, `corpus/harness/`). The T1 `minLength` declarations and the retained-schema recognition; the `deny-without-allow` factor level and regenerated WO-103 shards, manifest and precedence table; `compareBase`, `runtimeDrift` and `baseRead` in `wo105-common.mjs`, with the oracle hashes read at the base commit and the manifest's `afterBasePolicy`; the second WO-107 collector archived under `corpus/harness/wo107-second-protocol/`, admitted by `protocolLineage` and `validateProvenance`, and the comparison's single final newline.

**Tests.** New cases in `packages/kernel/test/kernel.test.ts`, the skeleton audit, resident, repair, runtime-status and source-change-host tests, the console runtime-status test, `scripts/test-harness-probe.mjs`, `scripts/test-vertical.mjs`, `scripts/test-vertical.recovery.mjs`, `scripts/test-vertical-judgment.mjs` and the WO-103, WO-105 and WO-107 lane tests; 26 paired controls are recorded with both arms.
