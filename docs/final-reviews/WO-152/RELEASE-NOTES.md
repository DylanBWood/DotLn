## Release overview

DotLn's mission check works on the Claude CLI again. A mission check asks a model whether the work in front of it is still the work its contract describes, and it hands the model a JSON Schema that names every clause, thesis and exclusion the model is allowed to cite. That schema listed every contract clause id twice, and the Claude CLI rejects a `--json-schema` whose enum repeats an item, so every mission check on the `claude-cli-print` transport ended in a transport failure after about 1.28 seconds — before any model was called. Only the Codex transport worked. This patch deduplicates the reference list at its source, preserving first-seen order, and the same path now returns a verdict. It matters to anything that runs a mission check on a transport the operator chooses at launch: the resident that WO-100 builds and the unattended hour that WO-111 builds both do.

## Read before upgrading

The emitted `missionCheckResultSchema` changes shape: the `contract-clause` reference enum now lists each clause id once instead of once per contract that supplies it. This is a narrowing of an input constraint, not a new one. `validateMissionCheckResult` is untouched and tests membership with `includes`, so every result a consumer could produce before this release is still accepted, including a finding that names a clause only the pin carries or only the observed contract carries. A contract edited mid-episode still contributes its new ids: the list is the union of the pinned, story and observed contracts, in that order. No verdict rule, resident host, event, hook or transport changes. The application moves to `v0.41.1` and `@dotln/skeleton` to `0.35.1`, with the console's exact pin and both lockfile locations following; compiler, kernel and console versions are unchanged and no external dependency is added. The current authority and feedback evidence editions move to WO-152 revision 001, and the console's self-hosted case is re-pinned to follow them; earlier editions keep their bytes.

## Substantive changes

**The reference list deduplicates at its source, not at the schema.** `missionReferenceIds` collected the pinned contract's clause ids, an optional story contract's and the observed contract's by concatenation. When the contract has not changed since the pin — the ordinary case — those lists are identical, so the emitted enum carried each id as many times as a contract supplied it. The three lists are now collected through a `Set` and spread back, which is first-insertion order. Deduplicating at the schema site was considered and declined: `missionReferenceIds` is read by the validator as well, and leaving its advertised output wrong would hand the next consumer the same defect.

**The regression walks the emitted schema generically.** Rather than naming the four enum sites, the new test collects every `enum` the schema carries by path and asserts the walk reached seven, so a walk that stops finding them cannot pass silently. It then asserts the literal expected id lists for the `contract-clause`, `thesis` and `exclusion` kinds over three subjects: an unchanged contract, a contract renumbered after the pin so the observed side drops one criterion id and adds another, and a subject carrying a story contract with a clause id of its own. Both validator directions are asserted in the same test.

**The evidence editions are re-minted and current.** Because `packages/skeleton/package.json` is a registered evidence source, the component bump carried the duty to mint new authority and feedback editions with one live self-host episode. Both exist as WO-152 revision 001, `docs/evidence/current.json` selects them, and both strict checkers pass — the feedback checker took its strict branch and validated the fresh live logs rather than retaining the previous audit. The change in each edition is identity only, and measured: `authority.json` is byte-identical to the edition it replaces and its bundle record differs in one comparison label; the new `feedback.json` differs in exactly one field, its subject hash.

## Progressive polish

The mission-check test fixture gains a `renumberContract()` helper, which edits the contract after the pin in a way that moves clause ids rather than one clause's text — the existing `editContract()` changes a criterion's wording but not its id, so it could not exercise the changed-contract case. The console self-host fixture's JSON, terminal and HTML expectations are re-recorded against the new feedback edition, which is why the labels in that board now read WO-152 rather than WO-149. Neither affects observable semantics, saved-data interpretation, compatibility, authority or any operator action.

Known limitations, each on the record. A worker refusal records only the code `invalid-result`: the interruption event carries no detail, the CLI prints only the code and raw transport output is discarded, so a refused live episode cannot be diagnosed from the store — the two refusals above cost USD 2.72 together with no diagnosable cause. That gap is deferred rather than fixed here, because its fix touches declared feedback evidence sources and would stale the editions this release just minted; it is recorded in [D009](../../evidence/WO-152/decisions.md#wo-152-d009) with public follow-up `FUP-ed431cc1c8ca9a52`. The live mission check's 46.8-second episode duration is a bound derived from store clock samples, not an exact measurement, and its effort is the launch selection rather than an effective readback, which the filed row states. The `evidence` enum is built by a function this order does not touch, so the walk establishes that it carries no duplicate for the judged subjects rather than that it never can; a generic schema check across every request kind is a declared non-goal and reopens if another kind's schema is refused. This order's two deferred adjacent-queue items still carry the literal target `planning` instead of their public follow-up identifiers, which the queue refuses to change outside the executor phase; the identifiers exist and the retarget is carried in [D011](../../evidence/WO-152/decisions.md#wo-152-d011).
