## Release overview

For anyone running a DotLn instance, this release closes eighteen edges the operator's fork met at its planning passes, entropy receipts, starter updates, change reviews and closes between 2026-11-03 and 2026-11-05: a planning or entropy pass never takes a newer starter release unless the operator asks in that session, a change review past its ceiling is split over more workers instead of refused or narrowed, the dispatch line is read whatever the host wrote before it, the front page is a reader entry point that may link a record, a closed order reads as closed, a receipt files on the first try with no private path, a moved record says where its links resolve, a fresh clone says what it lacks, a release says what to regenerate and when to start a new session, and the target publish helper has its allow rule. Two verifications judged the change: the first failed on the batch merger and the second passed after the repair.

## Read before upgrading

After taking this release, regenerate the pages whose renderers changed before the next document gate reads them: `npm run work-orders -- index` (the index card's criteria line) and `npm run meta` (the meter's comparison sentence and the features inventory). Re-emit with `node scripts/harness.mjs emit` and start a new session, since the emitted `.claude/settings.json` gains the allow rule `Bash(node scripts/worktree.mjs publish *)` and the host reads the emitted settings when a session starts.

A build overlay that names `tinkerer-economy` in `equip` or `unequip` now refuses the emit, the check, the feature table and the elections read; the choice was accepted with a migration advisory through v0.118.0. Elect `features.tinkerer-economy` in `dotln.config.json` and remove the overlay entry.

Under a journaled `planning:` or `ideation:` dispatch, or while an entropy review or refutation dispatch is pending, `node scripts/launchpad.mjs update --finish`, `update --publish` and core's `export --update` refuse unless `--operator-request`, with `--capture` naming an ignored intake file and `--capture-hash` naming its sha256 digest, names the operator's in-session words; the admission is journaled with the capture hash and a from-core update records it in the sibling receipt, whose decoder admits the optional `operatorRequest` field. Strike any instance rule that a pass takes the starter first; a session with no journaled dispatch updates as before.

In a repository with a process meter, a target order's records publication body must carry the record's criterion lines as its last block, written by hand, where it was refused for naming them before; `worktree publish` prints the lines it expects when they are missing, and a body naming lines the record does not hold is still refused.

A split change review is recorded part by part: `npm run worker -- record --batch N` keeps each batch's report under the lane and records the merged report when every batch is in, `--brief-sha256` with the dry run's digest binds a part to the brief its worker received, and a single report is refused for a split round. The dry run of a planning review prints the measured size, the 400,000-character ceiling and the batch plan with every batch's prompt and digest.

Plan receipts filed from this release carry `subject.separateTrack`, the open members of every `track: separate` workstream, which also appear in `subject.orders` after the sequenced orders; receipts filed before the key still validate under the rule they were filed under. A planning document's `Rules recorded` entry may name `order` to point the journal read at a closed order's retained lane.

Entropy receipts filed from this release render the frozen copy under the temporary-directory placeholder and screen the statement and every string of the worker's output for private absolute paths before filing: the launchpad, the system temporary directory and a home directory read as their placeholders, a path none covers refuses naming the text and the line with the original retained, and the same command refiles once the text is corrected. Receipts filed earlier re-render byte for byte.

The control fold now records the ordinal of the latest completed verification; status JSON is unchanged, and a historical comparison that serializes the fold's state checks that ordinal apart from its recorded snapshot. The feature registry lives in `scripts/lib/feature-registry.mjs`; a fixture or copied CLI that lists `scripts/lib/config.mjs` and `scripts/lib/features.mjs` by hand must copy the registry too, and an exported kit carries it through its emit closure.
