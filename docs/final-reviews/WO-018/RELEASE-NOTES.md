## Release overview

DotLn `v0.4.1` is a control-plane patch above the published `v0.4.0`. The four lifecycle scripts that drive work orders, worktrees, releases, and publication now share one helper library instead of carrying four drifting copies of the same Git runner, clean-tree gate, path-containment check, and ignored-material classifier. Canonical control state is machine-readable through `resume status --json`, and no lifecycle script parses the human Markdown projection any more. The release manifest's cadence-compatibility grammar is derived from the built kernel's type-exhaustive exports rather than from a regular-expression parser over TypeScript source. Closeout can no longer destroy ignored raw material that happens to live under a build-shaped directory name, and the operator's local harness settings are permitted in the main checkout without becoming disposable anywhere. The root test chain now runs the real-repository publication check and the identity corpus it previously only claimed to cover. Audience: the operator running the resume loop, any session dispatched by a `resume:` phrase, and consumers of the annotated-tag manifest. This release carries `@dotln/kernel` `0.2.1` for the additive `CADENCE_KINDS` export; `@dotln/skeleton` `0.4.0` and `@dotln/compiler` `0.1.0` sources are unchanged.

## Read before upgrading

- **The first post-merge release close uses a different command form.** Run the exact absolute command printed by `worktree publish` or projected by `resume release-close`: change directory into the main checkout and invoke the still-present subject worktree's `scripts/release.mjs close WO-NNN --publish`. The reviewed subject helpers then synchronize main, delegate cleanup to their sibling worktree helper, and remove their own source worktree. Only after that removal does the ordinary `npm run release -- close WO-NNN --publish` from updated main apply, for recoverable reruns. To make this possible, the cleanup gate in `worktree finish` moved from "the script must reside in the main checkout" to "the working directory must be the main checkout"; every other gate on the destructive path is unchanged.
- **Destructive cleanup reads committed control state.** `worktree finish` folds the subject worktree's `HEAD:docs/control/resume.jsonl` and requires phase `closed` for that exact work order. A working-tree-only or forged `docs/control/current.md` no longer influences the decision.
- **An unknown control-event type now refuses everywhere.** The fold throws `unknown control event type at line N` for any event whose `type` is outside the eight known types, consistent with the existing malformed-JSON refusal, so `status`, `next`, every transition, and release-time folding refuse instead of silently skipping the event. A log written by a newer schema must be migrated before this version reads it.
- **`resume status` accepts only `--json` as an argument** and refuses anything else with a usage error. Machine consumers must invoke `npm run resume --silent -- status --json`; without `--silent`, npm's script banner precedes the JSON on stdout. Both status forms are read-only and warn on stderr, without rewriting anything, when `current.md` disagrees with the fold.
- **The clean-tree gate is uniformly strict.** Every lifecycle mutation now checks `git status --porcelain --untracked-files=all`, so a checkout whose Git configuration hides untracked files (`status.showUntrackedFiles=no`) is reported dirty when one exists; previously `worktree start`, `publish`, and `finish` honored that configuration while release close did not.
- **Disposable ignored paths are anchored.** Only the root `node_modules/` and `dist/` directories, `packages/NAME/node_modules/` and `packages/NAME/dist/`, a `.DS_Store` basename, or a `.tsbuildinfo` suffix may leave with a removed worktree. Any other ignored path, including a `dist` or `node_modules` directory elsewhere and everything under `docs/intake/`, blocks removal and is preserved. A worktree that previously removed cleanly may now refuse until such material is backed up or moved.
- **The root `.claude/settings.local.json` is ignored and treated asymmetrically.** The exact root path is added to `.gitignore`; the main checkout's release-influence guard permits exactly that path; a copy inside a subject worktree is non-disposable and blocks `finish` while preserving the file, worktree, and branch. No other `.claude/` path is permitted, and no code reads or hashes the file.
- **`npm test` is stricter.** It now runs `check-publication.mjs` against the real repository and the WO-101 identity corpus test, so a stale publication lock or an identity-corpus regression fails the chain. The Program-lane corpus stays outside the chain and is marked frozen; promoting it requires a separately reviewed change.
- **Equal-tag release reruns rebuild evidence.** A rerun against an already-published equal version now runs `npm ci` and the evidence gate before re-deriving compatibility from the fresh kernel build, instead of trusting whatever ignored build output was present.
- **The discovery record's harness version is a list.** `effortReadbackProbe.harnesses.NAME.version` became `versions`, ordered oldest to newest with each entry classified; any listed observed version attests, a refusal names the versions on record, and a newly observed version is appended rather than replacing the previous one. The Claude Code `ultracode` session label is recorded beside that entry as an operator-attested note meaning dynamic workflows plus `xhigh` reasoning effort; the actor still supplies `--effort xhigh --source operator-attested` explicitly, and `resume` never converts the label on its own.

## Substantive changes

- **Shared helper library.** `scripts/lib/git.mjs` owns the single Git runner, failure formatter, NUL-terminated path-list reader, strict clean-tree gate, worktree parser, main-worktree resolver, and merged-branch removal; `scripts/lib/paths.mjs` owns contained-regular-file, JSON parsing and reading that names the file on failure, work-order authority-path validation, and the ignored-material classifier. `resume.mjs`, `worktree.mjs`, `release.mjs`, and `check-publication.mjs` import them, and no duplicate definition remains. The two clean-tree strictnesses reconciled to the stricter form, and the two ignored-path allowlists reconciled to one classifier that answers two deliberately different policy questions: what destructive cleanup may discard, and what may be present in the main checkout without contaminating release evidence.
- **Machine-readable control state.** `resume status --json` emits the same twelve fields as `docs/control/current.md` from the canonical fold of `docs/control/resume.jsonl`; `worktree finish` folds the committed log at the subject's `HEAD` through the exported projection, and `release close` spawns the JSON status, so neither contains a substring or regular-expression parse of the Markdown projection. `fold` refuses an unknown event type with its one-based ordinal.
- **Intake and local settings survive closeout.** The classifier never treats anything under `docs/intake/` as disposable and matches build outputs by anchored path rather than by any segment; the exact root harness-settings path is release-evidence-allowed but never disposable; the anchoring rule is pinned by destructive-cleanup fixtures, and the intake precedence by the release-evidence fixture and direct classifier probes.
- **Release manifest grammar from the built kernel.** `@dotln/kernel` `0.2.1` exports the compile-time-exhaustive `CADENCE_KINDS` tuple beside the existing evaluable-kind data. Release compatibility imports the built module in a child process and requires the complete tuple, the runtime `Cadence` constructors, and their `kind` discriminants to agree in both directions, requires the evaluable list to be a unique non-empty subset, and derives the deferred list by set difference; missing and inconsistent exports refuse with distinguishable messages before any tag object is created. The control-log schema range comes from the constant `resume.mjs` exports. The regex parsers over the cadence union in `types.ts`, the evaluator switch in `core.ts`, and the schema literal in `resume.mjs`, together with their fixtures, are deleted, which also retires the WO-015 review's concern about a `case` placed after `default:`; the event-envelope schema version is still read from `types.ts` by a pre-existing regex that lies outside this order's scope.
- **The test chain exercises what it claims.** `npm test` runs `check-publication.mjs` against the real repository before the build step and runs the WO-101 identity corpus after the package tests. `test-publication.sh` computes its expected lock with an independent `shasum -a 256` over bytes the fixture itself wrote instead of asking the checker for the answer, and the release suite's trace assertions carry non-empty guards so a missing trace cannot pass vacuously.
- **Harness-version attestation slot.** The version matcher accepts any observed version on the discovery record's list, refusals name the versions on record, and the unrecognized-label refusal points at the recorded `ultracode` note; the WO-019 rule that an unrecognized effort is stored as `unknown` plus its raw spelling stands.
- **Reviewed helpers govern the first close.** `worktree publish` and `resume release-close` always print the absolute subject-helper close command; the subject `release.mjs` delegates cleanup to its sibling `worktree.mjs`, so a lifecycle-policy change in the just-merged work order cannot be bypassed by stale pre-fast-forward helpers in main.
- **Product documentation from an operator ideation breakout (documentation only).** A candidate Additional Opinion support with a two-result Second Opinion preset is filed at status `vision` in the pattern library, with candidate subject, cohort, and adjudication terms in the domain model, fan-out, sealed reduction, and single-writer topology in the architecture, a prospective operator affordance in the interfaces, a verification-only pilot recommendation in the roadmap after WO-009 and WO-010, and evidence and minimization rules in the audit document. The ledger records the transformation and the work-order map preserves the unallocated candidate. Nothing in current resume control implements it.

- Known limitations: the new module-entry guard in `resume.mjs` compares a lexically resolved `argv[1]` with the realpath-resolved module URL, so a hand-typed absolute path that passes through a symlink makes the CLI a silent exit-zero no-op; no sanctioned invocation (`npm run resume`, `worktree.mjs`, `release.mjs`, or a relative path) is affected, and the one-line `realpathSync` repair is deferred to a follow-on order. The recorded `ultracode` note carries a `classification` value that the discovery record's own `labels` vocabulary does not yet declare; adding it to that list is the safe repair, because restamping the note would silence the refusal hint. The `docs/intake/**` precedence term is pinned on the release-evidence side and by direct classifier probes, but no destructive-cleanup fixture plants a `.DS_Store` or `.tsbuildinfo` file under intake. Linux portability of `stat -f`, a `recover` action, `dotln status`, and a `program` manifest field remain out of scope.
