## Release overview

DotLn v0.21.2 restructures the skeleton reactor's state without changing a single thing it produces. The reactor has always been one decider folding one state object, and three hosts read that object's fields directly; this release splits the state into four named typed slices — walking skeleton, worker episode, verification and feedback — with each event routed to exactly one fold, and gives hosts exported selectors instead of raw field access. For anyone running DotLn the visible payoff is nothing at all: every recorded log replays to identical Decisions, identical projections and identical rendered output. The payoff is for the next change. The 2026-09-06 phase-two plan declined this split and wrote down the condition that would reverse it — the next order adding a host branch does the split first — and this release is that condition being honoured on its own rather than buried inside the host order that needs it. A reserved, empty source-change slot means the upcoming source-change host adds a slice and a fold and touches nothing else.

## Read before upgrading

Nothing is required of you. Source release target v0.21.2 includes skeleton 0.18.2; kernel 0.4.0, compiler 0.11.1, console 0.1.6 and every third-party dependency are unchanged from v0.21.1, and the lockfile diff is the single skeleton workspace version. No event type or payload moves, no persisted contract, semantic hash or artifact identity changes, no state schema is written to disk — the reactor's state is a fold of the log and stays that way — and no recorded data is rewritten or migrated. Authorization and cadence are untouched. No package distribution or hosted service is introduced.

The public Decision shape is deliberately unchanged, and it is worth knowing why, because the internal version marker could mislead. `SkeletonState` carries `version: 1`, but that version describes only the internal composition. The flat `RuntimeState` remains the public compatibility boundary, chosen explicitly by the operator when the executor found that exposing a nested versioned state would alter serialized Decision bytes. Anything reading `Decision.state` sees exactly what it saw at v0.21.1.

One thing to know if you extend the reactor rather than run it. Slice ownership is a function of the active workstream mode *and* the event type, not of the event type alone: `CommandPersisted` and `CommandResult` are each folded by three different slices depending on which mode is active, and this is enforced per mode rather than globally. A new fold must declare its event types in the slice registry, and a registry entry with no fold branch — or a fold branch with no registry entry — fails the build in both directions. The reserved `sourceChange` slot is typed as permitting no fields and is excluded from the folded union, so it cannot be reached by the decider until someone adds it deliberately.

## Substantive changes

**One decider, four typed folds.** `seiriReactor` composes an internal `SkeletonState` per event, selects one slice by active mode, runs that slice's fold, and writes only that slice back into the public state. The walking-skeleton slice keeps the episode state the frozen scenario exercises; the worker-episode slice owns lease identity and expiry, lifted out of the walking switch; verification and feedback own their existing workstream states, which are now passed to their folds as typed values rather than re-derived from the runtime object on every call. The one-decider ownership guard is unchanged and still passes: no kernel decider — `evaluateCadence`, `authorize`, `decideProgram`, `guardQueuedPulse` — exists outside the reactor.

**Selector-only host reads.** `scenario.ts`, `worker-host.ts`, `verification-host.ts`, `worker-demo.ts`, `beacon-observe.ts` and `feedback-selfhost.ts` now reach state through exported selectors, and a test greps all six to keep it that way. Kernel predicates receive the complete previous context, including the worker lease fields that a slice-local view would have dropped — the compatibility hazard most likely to pass a type check and fail at runtime — and a test wraps every registered predicate to assert it on a real replay.

**A reserved slot for the next host branch.** `SourceChangeSlice` is an empty typed slot with no fold, so the upcoming source-change host adds its slice and its fold without editing an existing one. The reservation is excluded from walking-skeleton ownership by name rather than by convention, which matters because the walking slice is constructed by rest-destructuring and would otherwise have absorbed the new field silently. `initialState()` omits the key entirely, so current serialized Decisions carry no new field.

**A frozen identity harness.** A committed manifest pins nineteen fixed input logs by digest and pins the complete canonical output of replaying each one — entire Decisions including state, full semantic projections, and the status, rendered text and outbox at every event prefix, with no normalisation. It runs inside the product gate, so a future change that moves any of those bytes fails the build rather than a review.

## Progressive polish

Documentation and generated-surface refreshes accompany the release: the architecture document gains a short paragraph on slice composition beside the layer diagram, the phase-two plan's code table gains a dated note recording that its reversal condition was honoured here and that the package split it proposed stays declined, the skeleton README gains a "Reactor state slices" section covering the compatibility boundary and the pending replay projector, the roadmap records the v0.21.2 activation, and both publication tables of contents gain a line with refreshed source locks. The decisions index and follow-up projections carry this order's three decision records. The regenerated harness bundle differs from v0.21.1 only in runtime pins — the `skeletonVersion` literal, the runtime snapshot identifier and each hook's content hash — with no change to any hook's behaviour, the hand-written Clean Room floor or the skills.

## Evidence and compatibility

Source tag v0.21.2, published from `main` after merging the reviewed `wo-050` branch above v0.21.1 (`7fd94ae`). Supported versions: skeleton 0.18.2, kernel 0.4.0, compiler 0.11.1, console 0.1.6; all packages remain private and unpublished, and `npm publish` is refused by every manifest. `main` did not move during any phase of this order, so the branch was verified and reviewed at the same base, with no integration, no retiming and no carried-forward claim.

Compatibility is established by replay rather than asserted. Nineteen fixed input logs — the frozen 13-step scenario, its crash-recovery variant, the WO-029 legacy scenario, both worker transports, three worker failure-injection rows with their interrupted and recovered prefixes, a verification workstream, a feedback correction, and the committed WO-010, WO-011 and WO-048 evidence editions — replay to byte-identical complete Decisions and semantic projections before and after the split. The comparison is two-sided and was checked from both ends: the same frozen digests reproduce from a fresh build of the pre-refactor source and from the delivered source. The existing suites are unchanged and pass as they stood, including the frozen decision-trace oracle, the one-decider ownership guard, the negative fixture, tamper sensitivity and crash recovery.

Verification: [VER-001](../../verifications/WO-050/VER-001.md) passed all six acceptance criteria with no finding, re-deriving the slice-ownership bijection by hand and confirming the non-goals intact — no new event type or host, no package split, the replay projector not implemented here, and `authorize` and cadence unchanged. Final review: [FINAL-001](FINAL-001.md) confirmed the base, settled the identity question empirically against a rebuilt pre-refactor tree, re-derived the routing and write-back invariants from source, corrected trailing whitespace in a committed evidence transcript, and recorded the reviewer product gate: `npm test -- --review`, 27 suites, 0 failed, 715.89 s, 70 fresh tasks.

Known limitations, all recorded rather than repaired. WO-009's raw worker logs were never retained, so the worker cases replay synthetic subprocess fixtures captured once on the pre-refactor source; they are fixture transports, not live worker observations. Four of the nineteen cases are historical compiled-artifact logs that already refused before this order under pre-existing version-boundary drift, so for those the identity claim covers only the refusal location and message, and two of them share an output digest from different inputs; replay of obsolete compiled artifacts is scoped to a separate future decision. The selector proof is a grep, which establishes the absence of four literal spellings rather than the general property, and the ownership registry test reads the reactor as source text between marker strings — fail-safe, but still text scraping. The replay environment projector remains unlanded, so the reserved `rngState` and `policy` stay at the public top level. Deeper technical notes are in [FINAL-001](FINAL-001.md), [VER-001](../../verifications/WO-050/VER-001.md), the [implementation receipt](../../evidence/WO-050/implementation.md) and the [decision record](../../evidence/WO-050/decisions.md).
