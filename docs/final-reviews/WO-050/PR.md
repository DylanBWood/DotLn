# WO-050 — Fold the reactor's state into typed slices so the next host branch adds one instead of widening a shared bag

The skeleton has one reactor and, until now, one undifferentiated state object that three hosts read directly. The 2026-09-06 phase-two plan looked at that and deliberately declined to split it, recording the exact condition that would reverse the decision: the next order that adds a host branch carries the split first. WO-052 is that order, and adding a fourth host to the current shape would have meant a fourth consumer of the same untyped bag and a wider blob for WO-047's projector to read. This change does the split on its own, ahead of the host that needs it. `seiriReactor` now composes an internal `SkeletonState` version 1 from four typed slices — walking skeleton, worker episode, verification and feedback — selects exactly one fold per event from the active workstream mode, and writes only that slice back. Hosts read through exported selectors rather than reaching into raw fields. The visible payoff is in the next diff rather than this one: WO-052 adds a slice and a fold, and the type system stops it joining an existing slice by accident.

Nothing observable changed, and that is the load-bearing claim. The operator chose the compatibility boundary explicitly when the executor found the conflict: a nested, versioned public state would have changed serialized Decision bytes, so the flat `RuntimeState` stays public and the `version: 1` marker describes only the internal composition. Pure adapters compose and flatten it; no state is persisted, no event type or payload moves, no hash preimage changes, and `authorize` and cadence are untouched. Kernel predicates still receive the complete previous context including the worker lease fields, which is the compatibility hazard a naive split introduces silently — a wrapped-predicate test asserts it on a real replay rather than trusting the types.

What proves it: nineteen fixed-input cases replay to frozen digests covering entire Decisions **including state**, full semantic projections, and per-prefix status, rendered text and outbox, with no normalisation anywhere. The inputs are drift-guarded three ways — capture refuses to overwrite, the case list is asserted against the manifest, and each input's digest is checked before replay — and the comparison is genuinely two-sided, which the final review settled by rebuilding the pre-refactor source in an isolated tree and running the same committed check against it: the identical nineteen digests reproduce from the old reactor and from the new one. Alongside that, a registry test cross-checks declared slice ownership against the `case` labels scraped from the actual fold bodies in both directions, so a fold branch without a declaration and a declaration without a branch both fail; the frozen 13-step oracle and the one-decider ownership guard pass unchanged; and a grep test proves six host modules read state only through selectors.

The reserved source-change slot is the actual deliverable for WO-052 and it is a type-level guarantee, not a convention. `SourceChangeSlice` is `Readonly<Record<string, never>>`, its registry entry is empty, and `FoldedSlice` excludes it so the decider switch cannot reach it and needs no `default` arm. It is worth knowing that this was nearly wrong: the walking slice is an `Omit` with a rest-destructured constructor, which absorbs unknown keys by construction, so a future `sourceChange` field would have silently become walking state. The executor's own read-only audit caught it, stopped the gate through the canonical command after 94.3 seconds with no check recorded, and reserved the key explicitly — named in the `Omit`, destructured out, excluded from the folded union — with `initialState()` still omitting it so current serialized Decisions are unchanged. Both halves are asserted.

The application target is v0.21.2 with skeleton 0.18.2. Kernel, compiler and console are unmoved, there is no new dependency, and the lockfile diff is the single skeleton workspace version. `main` did not move during any phase of this order, so there is no integration, no retiming and no re-established claim; the branch was verified and reviewed at the same base. VER-001 passed all six criteria with no finding, and `npm test -- --review` then passed at 27 suites, 0 failed, 715.89 s.

Read before merging, mostly about what the evidence does and does not cover. The order names WO-009's recorded worker traces, and those raw logs were never retained — only summaries — so the executor captured synthetic subprocess fixtures once on the pre-refactor source and replayed those exact bytes on both implementations. They are fixture transports, not new live worker observations, and D002 says so. Four of the nineteen cases are historical compiled-artifact logs that already refused before this order because of pre-existing version-boundary drift; for those the identity claim reduces to refusing at the same event with the same message, and two of them share an output digest from different inputs. The substance rests on the other fifteen. Replay of obsolete compiled artifacts is scoped to a separate future decision rather than quietly repaired here. Two further limits are recorded rather than closed: the selector proof is a grep, so it establishes the absence of four literal spellings rather than the property in general, and the ownership registry test reads the reactor as source text between marker strings, which fails loudly rather than silently if a marker is renamed but is still text scraping. Finally, WO-047 has not landed, so the conditional branch in the order resolves to its second arm — the reserved `rngState` and `policy` stay at the public top level and the projector is recorded as pending.

Two disclosures. The final review broke its own first gate: it read six blank lines removed from `scenario.ts` as editing churn and restored them, which pushed the file past the WO-016 host-size ceiling of 748 lines and failed the one-decider ownership assertion. The executor had removed those lines to pay for the selector calls. The edit was reverted, the staged tree is byte-identical to the verified subject, and the gate was re-run; the failing row is in the log at a different code identity. And the hooks that gated both the verification and the review load the compiled reactor this order rewrites, so the instrument is not independent of what it measured — both refusals it produced behaved as specified and neither altered the subject.
