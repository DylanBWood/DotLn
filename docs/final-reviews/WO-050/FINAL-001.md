## Source review

The shape is right and the discipline is visible. `SkeletonState` is composed, never persisted: `skeletonStateFromRuntime` is a pure adapter run per event, and the only version marker lives on the composed value, which is exactly what keeps `version: 1` from reaching a serialized Decision. `runtimeDecision` is the whole compatibility story in four lines — take a `SliceDecision<S>`, apply the slice's own write function, return a `Decision<RuntimeState>` — and every fold returns through it, so there is one place where a slice becomes public state rather than one per branch. The selectors are thin and total, and `selectPredicateState(walking, worker)` is the one that earns its existence: kernel predicates keep the complete previous context including the worker lease fields, which is the compatibility hazard a naive split would have introduced silently, and the test pins it by wrapping every registered predicate and asserting `"workerEpisodeId" in context.state` on a real fixture replay.

The `sourceChange` reservation is the part a reader should not skim, because it is the order's actual deliverable for WO-052 and it was nearly wrong. `WalkingSkeletonSlice` is an `Omit` with a rest-destructured constructor, which absorbs unknown keys by construction; the executor's final read-only audit caught that a future `RuntimeState.sourceChange` would therefore land in walking state, stopped the gate through the canonical command after 94.3 seconds with no check recorded, and reserved the key explicitly — named in the `Omit`, destructured out in `walkingStateFromRuntime`, typed `Readonly<Record<string, never>>`, and excluded from `FoldedSlice` by `Exclude<…, "sourceChange">` so the decider switch cannot reach it and needs no `default`. `initialState()` still omits the key, so current serialized Decisions are unchanged, and the test asserts both halves: absence from `initialState()`, and absence from `reserved.walking` when a `sourceChange` value is supplied. That is a real seam rather than a comment promising one.

Two things are weaker than the rest and neither is a defect. The host-selector proof is a grep, which establishes the absence of four literal spellings rather than the property in general — `const { rngState } = driver.state` would pass it — and the order specifies grep as the method, so the bar as written is met. And the enumeration test's extraction is source-text scraping bounded by `indexOf` markers; renaming a marker collapses the window and fails the `deepEqual` loudly rather than silently, so it is fail-safe, but it is still a test that reads its subject as text.
