# :arrow_down: The kit runs on Git 2.31.0 instead of refusing it, and core's gate stops the next newer Git form

Since v0.121.0 the kit has declared a Git floor of 2.40.0, so `node scripts/harness.mjs check`, `harness evidence` and every `npm test` selection refused a host on Git 2.31.0 before running anything. A host the operator needs runs that Git. Lowering the declared floor alone would not have been enough: six Git forms the kit called are newer than 2.31.0, and there five fail at their call sites while the sixth, `GIT_CONFIG_GLOBAL`, is ignored, so a fixture's Git reads the developer's own configuration. This change replaces each form in place with one Git 2.31.0 has, lowers `engines.git` to `>=2.31.0`, and adds a core-only structural check that fails when a file under `scripts/` or `packages/` names a Git form nobody has recorded as confirmed against that floor ([the order](../../work-orders/WO-260-the-kit-runs-on-git-2-31.md), [D001](../../evidence/WO-260/decisions.md#wo-260-d001--the-outcome-is-the-operators-test-cycles-on-a-git-2310-host)).

No call site branches on the Git version. The code this repository's gates run on Git 2.55.0 is the code a Git 2.31.0 host runs, which is the point: the six forms arrived in six weeks unnoticed because every gate here ran a newer Git.

## What changed at the call sites

- The code identity at a committed revision reads that revision's attributes through a temporary index (`read-tree`, then `check-attr --cached`) where it used `check-attr --source` (Git 2.40). A release close's classification no longer stops on an older Git, the identity is the same for five revisions compared on a Git that has both forms, and the reading is faster: a median of 157 ms against 360 ms on this repository ([D005](../../evidence/WO-260/decisions.md#wo-260-d005--the-classification-at-a-revision-reads-a-temporary-index)).
- One reader, `gitTreeEntry` in `scripts/lib/git.mjs`, returns a tree entry's mode, type and object from `ls-tree -z`'s default output. An order's publish reads its own body through it, and a target order's record and planning reads use it, each keeping the refusal it printed; they used `ls-tree --format` (Git 2.36) ([D004](../../evidence/WO-260/decisions.md#wo-260-d004--one-tree-entry-reader-for-the-four-ls-tree---format-callers)).
- The outside-write grant for the main checkout's intake reads `worktree list --porcelain` without `-z` (Git 2.36) and leaves the grant unresolved when the first line is not a whole plain path ([D006](../../evidence/WO-260/decisions.md#wo-260-d006--the-main-checkout-is-read-without--z-and-only-a-whole-first-line-counts)).
- The stash prune and its drop read the reference backend from the repository's `extensions.refStorage`. An older `rev-parse` prints `--show-ref-format` back and exits 0, which read as an unsupported backend ([D007](../../evidence/WO-260/decisions.md#wo-260-d007--the-reference-backend-is-read-from-extensionsrefstorage)).
- The source-change admission runs `fsck` with `--no-references` and, when Git exits 129 on that option, once without it ([D008](../../evidence/WO-260/decisions.md#wo-260-d008--fsck-runs-once-without---no-references-on-a-git-that-lacks-it-and-the-edit-owes-a-live-feedback-episode)).
- A fixture's Git is isolated by a home inside the fixture, with `GIT_CONFIG_GLOBAL` (Git 2.32) kept beside it for a Git that reads it. The authority probe, its payload and the fixtures of eight test files take that environment from one helper, `isolatedGitEnvironment`; the probe's launched harness keeps the developer's home for its sign-in while its Git children run through a wrapper that reads only the fixture's configuration ([D009](../../evidence/WO-260/decisions.md#wo-260-d009--a-fixtures-git-is-isolated-by-a-home-inside-the-fixture), [D018](../../evidence/WO-260/decisions.md#wo-260-d018--correction-the-launched-harnesss-git-children-are-isolated-on-every-git)).
- The new reading found two more newer forms. A test's `symbolic-ref --no-recurse` (Git 2.39) now reads the loose ref, and four recovery messages that told the operator to run `git stash show --include-untracked` (Git 2.32) now name `git stash show --patch` and, for the stash's untracked files, `git show --patch` on its third parent ([D012](../../evidence/WO-260/decisions.md#wo-260-d012--two-more-forms-newer-than-the-floor-found-by-the-reading), [D017](../../evidence/WO-260/decisions.md#wo-260-d017--round-1s-eleven-findings-judged-before-they-were-fixed)).

## The floor and the check that keeps it

`package.json` declares `engines.git` `>=2.31.0`. The floor stays a named refusal: a Git below it is refused with the floor and the version read, because the two forms the floor rests on (`rev-parse --path-format` and configuration pairs in the environment) fail below it with words that name neither ([D010](../../evidence/WO-260/decisions.md#wo-260-d010--the-git-floor-is-git-2310-and-wo-258-d009-is-superseded)). The kit guide's first steps state the floor, what it rests on, and that an instance on an older Git lowers the line in its own `package.json` and reports what failed.

`scripts/lib/git-surface.json` records 474 Git forms the files under `scripts/` and `packages/` name (subcommands, subcommand and option pairs, global options and `GIT_*` names) with the floor they were confirmed against, and 14 newer or invented forms admitted only in the files that need them, each with its reason. `node scripts/structural-checks.mjs git-surface` runs in core's structural phase, between `generated` and `host`, and fails naming each unrecorded form with its file and line, and a record whose floor differs from `engines.git`. It takes a little over a second. An exported kit does not carry the task ([D011](../../evidence/WO-260/decisions.md#wo-260-d011--the-recorded-git-surface-and-its-core-only-check)).

A below-floor Git stands in for the real one in the tests: `scripts/fixtures/git-below-floor/git` reports `git version 2.31.0`, refuses or echoes the six forms as Git 2.31.0 does, and drops the two configuration variables that Git does not read. The fourteen cases of `scripts/test-git-floor.mjs` run each changed call site under it in the `runner-fixtures` suite, and each call-site case fails with its fix reverted ([D003](../../evidence/WO-260/decisions.md#wo-260-d003--the-below-floor-shim-and-its-cases-and-what-they-prove)).

## Limits a reviewer should know

- No real Git 2.31.0 ran. This host holds none, and it denied the build from Git's source ([D013](../../evidence/WO-260/decisions.md#wo-260-d013--no-real-git-2310-ran-here-criterion-5s-fallback-applies)). The below-floor Git models six forms; any other way Git 2.31.0 differs first shows on a host that runs it, and a failure reported from there is a defect of this order's objective for the next order.
- The check reads source statically. Arguments built at run time, and the shell shapes the header of `scripts/lib/git-surface.mjs` lists, are outside it, and a parser question is boarded rather than answered with a hand-written one ([D027](../../evidence/WO-260/decisions.md#wo-260-d027--a-hash-starts-a-shell-comment-only-where-it-begins-a-word-the-reading-stays-regular-expressions-with-its-other-limits-stated)). A `GIT_*` name written as a shorthand property is not named ([D037](../../evidence/WO-260/decisions.md#wo-260-d037--ver-003-passes-a-shorthand-environment-name-property-is-boarded-as-a-follow-up)).
- The check lists `scripts/` and `packages/`. The kit also carries six script files under `corpus/`; their Git forms are at or below the floor today, and one of them, `apply --unidiff-zero`, is not in the record ([D039](../../evidence/WO-260/decisions.md#wo-260-d039--the-surface-check-does-not-read-the-kits-corpus-scripts-boarded)).
- The `fsck` fallback's comment says a Git without `--no-references` checks no references. That holds at the floor, and not for Git 2.48 and 2.49, where the fallback also checks the shared references and can refuse on them; `main` refused every candidate there ([D040](../../evidence/WO-260/decisions.md#wo-260-d040--the-fsck-fallbacks-premise-is-wider-than-gits-record-boarded)).

Release: patch, v0.122.1 ([D014](../../evidence/WO-260/decisions.md#wo-260-d014)). `@dotln/skeleton` goes from 0.89.0 to 0.90.0 with the console's pin and the lockfile's entries, the installed harness is re-emitted, and the feedback edition is re-minted from one live self-host episode because the admission's source is a judged feedback source ([D015](../../evidence/WO-260/decisions.md#wo-260-d015--the-feedback-edition-is-re-minted-from-one-live-self-host-episode)). No dependency is added and an instance has no action beyond its ordinary update.
