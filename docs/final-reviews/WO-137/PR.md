# WO-137

Every plan for local models in this repository has waited since 2026-09-03 on one row: the only permitted launch of the local runner crashed it, so load and generation stood at `n=0`. This work order replaces that row with a measurement. On this machine the installed LM Studio build (`0.4.24+1`, CLI `ff50809`, llama.cpp `2.38.0`) started from its CLI, loaded an already-present Qwen3.6 27B Q4_K_M artifact and served a noninteractive client: three byte-identical answers at temperature 0 with a fixed seed, a schema-validated structured answer, one tool-call round trip, a cancellation that left the runner idle 164 ms after the abort, a 100 ms client timeout and a clean recovery. The outcome is `inconclusive`, and that is the honest class, not a failure: successful inference is not the whole readiness contract.

What it changes for a reader: WO-110 can now be written against real request and response shapes while recording readiness as `unavailable` on the route its own text admits, and WO-138 stays gated on a `ready` row that does not exist yet. Nothing about how this repository runs changes. No package source, component version, dependency, setting or hook moves; no model was downloaded and no runner setting was edited; the runner was left unloaded and stopped.

**Why it stays `inconclusive`.** Three blockers are named in the packet. Nothing confined the runner's outbound traffic, so WO-027's deferral condition, which asks for attributable egress behavior, is not discharged; loopback binding controls incoming connections only, and a during-generation snapshot of six loopback sockets is a snapshot, not prevention. The runtime's applied prompt template and its other sampling defaults were not read back. Cancelled and timed-out requests return no usage or rate from the HTTP API, the model log or the server log, and the packet declines to substitute stream chunk counts for tokens.

**The load run the operator added.** During execution the operator expanded the order with `scope expand:` to run a gentle load test, bound in the planning log under D002: at most two minutes of traffic, ten serial requests, 128 output tokens each, five-second rests, context 4096, parallelism one, with automatic stops on thermal state, memory pressure, 128 MiB of swap growth, lost monitoring, a visible product gate or a failed request. Nine requests completed at 7.3–8.1 s and 17.8–18.7 tokens/s, the tenth was cut by the traffic limit, a staged health check after request two preceded continuation, and all 130 health samples read nominal thermal state, normal memory pressure and unchanged swap. It is a short bounded observation of whole-host signals, not capacity, sustained load or hardware safety.

**What the diff contains.** Two experimental clients under `scripts/probes/` with fourteen deterministic tests against loopback doubles, registered as one suite inside `npm test`; the rendered packet and its JSON under `docs/discovery/`; and the write-backs to product 06, the environment record, the ledger and the decisions index. Live inference needs a literal `--live` flag and the script as the process entry, refuses to start while a product gate process is visible on the host, and is unreachable from any test. Failures are kept: the rejected `@q4_k_m` variant key, the unsupported `runtime ls --json`, and a first diagnostic whose whole token cap went to reasoning until `reasoning_effort: none` was set.

**Validation.** `npm test -- --review` passed 22 suites with 0 failures in 388.83 s, exit 0, for tree `889b2223` at code identity `eb90a8a9`, recorded `2026-09-19T00:22:44.236Z`; the `local-runner-double` suite carrying this order's tests passed in 0.97 s, and `runner-fixtures` was selected and passed because the runner's own source changed. The two probe test files also pass 14 of 14 when run directly. `git diff --check` and `git diff --cached --check` are clean, `plan check`, `publication:check` and `harness check` pass, and against the integrated base this branch changes no file under `packages/`, `package.json`, `package-lock.json`, `.claude/` or `.agents/`. VER-001 passed every applicable criterion and proved on a double that the current clients send byte-identical requests for all ten recorded shapes; the [final review](FINAL-001.md) re-derived the protocol and load results from the packet's rows and found no error in the verification.

**Limits a reviewer should know.** The live smoke rows predate the audit corrections to the client and the packet records no client content hash; the request shapes are proven identical. Two narrow client defects are reproduced and recorded, and neither touches a recorded row: the smoke client's live path uses a blocking state observer, so a deadline elapsing during that observation would be labelled a cancellation, and the load client without an idle observer can report its own two-minute limit as a request failure. Both stop conservatively, and both belong to the separate order product 07 requires before these clients are promoted. Raw logs were not retained, and operator time was not measured.

**Integration.** `main` advanced six commits during verification and published `v0.31.0` above the `v0.30.1` this order had staged, so the branch is merged onto `4d6dc769` and retimed to `v0.31.1` under its existing patch classification, with the original activation record preserved beside the dated retiming note (D004). Six files conflicted, none of them source; the roadmap conflict is a union of two dated paragraphs and the follow-up register was unioned by entry id. The full account is in the [final review](FINAL-001.md); the evidence is in [decisions](../../evidence/WO-137/decisions.md), the [packet](../../discovery/local-runner-2026-09-18.md) and its [JSON](../../discovery/local-runner-2026-09-18.json).
