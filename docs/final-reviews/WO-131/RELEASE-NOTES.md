## Release overview

Repository verification carries reusable suite successes between role sessions. The independent verifier's sandboxed later-phase gate took 62.377 seconds instead of the pre-repair 807.236 seconds, saving 744.859 seconds (92.27 percent). A passing final gate also ends report authoring: final timings and usage stay in local receipts and the response, preventing repeated gates caused solely by updating a report with its own validation cost.

## Read before upgrading

Source release target v0.17.6 includes compiler 0.9.2 and skeleton 0.15.11. Kernel and console versions, domain-event schemas and dependencies are unchanged. Suite-success records advance to version 4 and the replica mechanism to version 3. Older cache records are pruned as suites save new successes and are not migrated into current proofs.

Narrowed suites receive their declared environment plus runner-owned execution values. Harness identities and transport commands are absent from those declarations; fixtures supply identities they need. Canonical PATH handling removes dangling and duplicate physical directory spellings. Changed declared inputs still invalidate reuse.

Kernel read denial is applied and recorded where the host supports it. A host without it still executes replicas and reuses matching successes. A suite with a hard-coded absolute candidate path can read it without the denial; this accepted residual is not complete filesystem isolation.

Prompt submission stays available when setup or lifecycle dispatch fails. `analysis:` and `operator override:` suspend DotLn hook enforcement for the session until explicit exit, preserving work and evidence; host permissions still apply. Raw checkouts can run `node scripts/bootstrap.mjs` without built dependencies. Release close starts in main using the printed surviving main-helper handoff.

## Substantive changes

- Remaining reusable suites declare paths, Git shape and environment and execute in replicas. Every retained task names its live/current-tree reason. Console fixtures and the host check run separately without dropping coverage. Weighted scheduling limits expensive fixture overlap; bounded Git object reads reduce repeated planning work.
- Denial availability and application accompany gate and source records without splitting keys. Fresh explanations name changed variables without retaining their values. Each suite keeps its newest 24 success records; gate history retains executable observations.
- Prompt failures become advisory while automatic lifecycle mutation retains gate and exclusive-writer checks. Session-local recovery precedes repository/runtime reads. Same-host subagent effects remain guarded; remote spawns and unclassified effects produce explicit refusals.
- Report and meter snapshots have a pre-gate cutoff. After a pass, roles read current outputs, record completion, refresh the index once and hand off. Completion collects usage in ignored evidence. Substantive source or report corrections still require current checks; no Markdown or evidence path is exempt from exact-tree validation.
