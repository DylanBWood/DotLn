## Release overview

This release closes twenty-four small machinery defects that earlier orders found, reproduced and boarded, in one pass, so that no later order opens them one at a time. What a maintainer sees: release close removes a scratch repository instead of stopping at it and records each removal with the repository's path, its head commit and whether a remote held it; the document gate gains four forward-only refusals, for a report-local label or a leading order identifier in a code comment, for an absolute home or private temporary path in a tracked document, for an operator quotation typed without a capture digest, and for a relative link in a pull-request body or Release text; the harness host answers a failed Bash command at the failure itself and tells a host task notification from an operator message; and the executor's rituals shrink, the pre-registered experiment giving way to a comparison run only when the work shows a fork, and the eight-lens paragraph to one sentence naming the traps that change what the role will do. Items 2 and 6 were found already done by WO-195 and recorded not reproduced; item 22's role text landed in WO-196 and this order records its measure.

The audience is operators and maintainers of a DotLn launchpad who close releases, read pull-request bodies and Release pages, write code comments and decision records, and run the planning feed.

## Read before upgrading

- **Changed default: an undeclared nested repository is scratch and is removed at close.** A nested repository inside an order's worktree that lies outside the intake lane and that the tracked tree does not declare as a submodule is removed by `release close` with no flag, no declaration and no bundle; the close record keeps its path, its head commit and whether a remote-tracking ref of its own held that head. A keep declaration recorded by an earlier completion no longer preserves a repository; an operator word at close, `--material path=preserve` (scoped as `absolute-worktree::path` when the close must name the worktree), does. Intake-lane repositories, declared submodules and linked worktrees are never removed, and a word naming one refuses. The `worktree material` command, the local declaration file, keep rows and recovery bundles are gone. Reopen if a close record names a removed repository whose commits no remote or retained ref held and the operator asks to recover it.
- **Four document-gate refusals, forward only.** A new or changed comment line that carries a finding label, a bare decision number or a leading order identifier fails `npm run test:docs`; the 81 such lines in 27 edition-registered files pass by a fingerprint baseline in `docs/control/comment-baseline.json` that only shrinks, and a baselined line that is edited without being fixed fails. A tracked Markdown line that gains an absolute home path or a private temporary path fails; the 218 lines that hold one today pass by baseline in `docs/control/doc-baseline.json`. A decision whose typed `operatorQuote` lacks a capture digest fails at completion. A pull-request body or Release text whose relative link the publish step cannot rewrite is refused. Reopen if a later order resolves one of these failures by editing a baseline or suppressing the check instead of fixing the line.
- **One host event is registered.** The generated Claude Code settings register `PostToolUseFailure` with a new `failure-observer` hook, and the harness bundle is re-emitted (34 surfaces). Copilot CLI 1.0.89 loaded the shared file with the event named and fired the other hooks; the event is registered on that observation. A failed Bash command whose error text carries a shell diagnostic gets the class guidance at the failure and one counted row; the transcript route answers it no second time.
- **Role text changed in every generated root.** The executor root says remove scratch repositories, never declare them; it carries the comment rule and the fork-triggered experiment sentence and holds no instruction to name an experiment before implementation; every root carries the one goal-alignment sentence and none asks for all eight lenses. The executor root is 21,009 bytes against 21,255 at base; no ceiling moved.
- **Pull-request bodies and Release pages change shape.** The meter table leaves an unavailable observation blank, drops a dispatch row with nothing observed and says in one line how many were omitted; every link is written absolute to the repository at the reviewed revision or as plain text; the Release text names the order's title once under the overview and its section headings carry the order identifier alone.
- **`plan refute --transport codex-cli-exec`** defaults to `gpt-6.1-sol` at `max`, the per-transport table the Entropy Reducer pins; the six scripts that regenerate dated records keep their recorded models and say so in one comment line each.
- **The lifecycle whitespace check reads untracked files too**, through a temporary index copy; byte-exact captures under `docs/evidence/**/*.txt`, `*.tap`, `*.log` and `corpus/manifests/runs/*.log` are exempt by the `-whitespace` attribute.
- **Component versions.** Compiler 0.25.5 to 0.26.0, skeleton 0.55.1 to 0.56.0 and console 0.4.0 to 0.4.1, with their workspace pins; kernel and beacons unchanged; no dependency is added. Application v0.71.0, a minor release over v0.70.0, retimed from v0.70.0 at integration because WO-074 published that version first.

## Substantive changes

**Release close and scratch repositories (items 1, 3, 4, 5).** `inventoryMaterial` reads Git's ignored and untracked directory units, so a repository no ignore rule covers, such as one cloned after review, is scratch like an ignored one, while a re-included intake unit stays protected either way. `describeIgnoredMaterial` classifies a nested repository as intake, declared submodule (a gitlink entry or a `.gitmodules` path), linked worktree, or scratch. `removeScratchRepositories` checks every directory for writability before any byte leaves, restores owned write bits, removes each repository after the preservation check verifies and just before the worktree goes, and prints each record as it lands so a later failure loses none. Git calls inside a nested repository run with `core.hooksPath=/dev/null` and `core.fsmonitor=false` and the repository pinned by `--git-dir` and `--work-tree`, so a scratch repository's own hooks never execute during a close. A published tag's outcome is set before the forge preflight that can refuse; `already-published` is recorded whatever refuses after a published tag, and a Release an earlier attempt completed is carried and marked. A worktree whose index holds a submodule is refused before any scratch repository leaves, because Git removes it only with `--force`, which would discard the submodule's unpushed commits. A material-caused finish or settle blocker carries the admitted material command naming every kept worktree's repositories, its whole reason and, for a dirty derived worktree, the operator's own remedy. The close record exists before its flags are parsed, so a malformed `--material x=keep` leaves a record with outcome `refused`. The prune removes a `.partial` proof beside a whole one.

**Harness host (items 7, 8, 9).** A prompt the host queued as a task notification is journaled with source `host-task-notification` and left out of the intervention count; a prompt with no transcript evidence is `unattributed`. The failed-command event is registered and answered at the call itself. `plan failures` counts a decision whose dispatch names an operator correction, read from the persisted ids in WO-172's direction-agreement record, never parsed out of dispatch prose.

**Document gate (items 10 to 13).** Each operator-word provenance record gets a key unique within its file (`provenance`, `provenance-2`, in document order); the 34 baselined keys are unchanged. A product 06 with its release-history block removed fails the check, and a local release tag whose annotation cannot be read is reported as a failure. The home-path screen covers tracked Markdown, and the entropy review writes its subject repository as `.`. The operator-word check also reads a decision's `evidence`, `rejected` reasons, `reason`, `misread`, `meant` and operator-named fields, covers verification reports, final reviews and planning documents, and refuses a typed `operatorQuote` without a capture digest; eight explicit quotations in the decisions of WO-102, WO-112, WO-140, WO-185, WO-186 and WO-187 are paraphrased by the route WO-178 used, with their inventory in `operator-word-repair.json`.

**Release preparation and integration (items 14 to 16).** `release prepare --integration` refuses once the integration decision stub exists or a saved release outcome waits for it; an evidence directory reached through a symlink is refused; a lone conflict marker line is a conflict while a setext underline is not; a directory where the decisions file should be yields the pending line. The integration fixture's working-tree overlay includes the console package and its fixture script, so a removed console export fails the suite through the real generator. `release list` prints a tag whose recorded changed-file list is not an array, with no attribution.

**Planning feed and lifecycle scripts (items 17 to 21).** A written path's leading parent components match as a tail; a completion with no `main` prints a feed command that works or says the feed is unavailable; an export to a reserved local-lane name and a failing revision lookup each refuse. The whitespace check reads untracked files. The plan refuter's launch defaults are the pinned table. `resident-bind --check` compares the binding's profile identifier with the registered profile's envelope identifier and names a mismatch without printing a launch line. A bare-hex `sha256` in `plan-failures.mjs` and a direct Git spawn in `product-read-guard.mjs` are replaced by the shared helpers, and the helper-reuse test fails on a new definer of either kind, over untracked scripts too.

**Role rituals (items 22, 23).** The experiment is no longer pre-registered and no longer one per order; the dispatch briefing prints no experiment line and prints an order's `**Experiment:**` header when one is declared; the decisions generator still accepts the existing experiment records. Comments explain code: the executor's role text carries the rule, and `scripts/comment-labels.mjs` enforces it in the document selection against a baseline of edition-registered lines; 272 lines in 99 files outside every edition were rewritten to say what the code does.

**Pull-request and Release text (item 24).** `renderMetaTable` omits unavailable cells and rows and counts them. `absoluteBodyLinks` rewrites every link the installed Markdown parser renders with a relative destination, from the stored body's own repository path, to the repository at the reviewed revision, or writes the link's text where the destination escapes the repository, is a bare fragment, is empty, or no GitHub target resolves; it reads a body as the lines the parser counts under every Markdown line ending and masks code and raw HTML at the parser's positions, so a link-shaped sequence inside code keeps its bytes. `githubBodyProfileFailures` refuses any rendered relative link that survives. The Release text is built the same way at the release commit. WO-199's body and Release text were regenerated into evidence as the fixture of record.
