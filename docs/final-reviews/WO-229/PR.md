# WO-229

A gate now says who it waited for and how long, and nothing it prints or records names a checkout's path. The fork's planning pass of 2026-10-21 met a document gate whose summary read 304.86 s and then 1,520.76 s while every printed task ran under 6 s, WAIT lines that named holders the gate could not schedule without saying whose they were, and a planning condition that read another checkout's complete run as the document gate's own cost. This order removes each. Every holder in a WAIT line is labelled `this checkout`, `another checkout` or `checkout unknown` by comparing real paths against the waiter's own worktree; the gate summary appends the lane wait as a union of the tasks' wait intervals split by relation, such as `6.7 s waiting for host lanes (6.7 s behind another checkout)`, and prints nothing when the wait rounds to zero; the recorded row carries the same figures as `hostLaneWait` with `wallMs`, `byRelation` and path-free `holders`; the critical path splits its wait into `laneWaitMs` and `gapMs` whose sum is the old `waitMs`; a reused task carries none of these fields; and the attribution survives the 32-entry diagnostic cap, because every change of the observed relation set is kept as a compact segment, so a wait of any length behind one unchanging checkout reads as that checkout rather than unknown.

The slow document condition of `npm run plan -- conditions --slow` reports a wall-clock median beside an execution-only median read from each sample's own recorded row, marks a sample that waited behind another checkout `contended`, judges the cost condition on the execution-only figure ([D001](../../evidence/WO-229/decisions.md#wo-229-d001--distinguish-execution-cost-and-experienced-delay)), keeps a failed or timed-out sample unavailable with its contention when the row exists, and carries a lane snapshot by relation in its host context in place of `other host activity unknown`. `node scripts/harness.mjs lanes` prints the recorded capacity and the live holders (relation, task, slots, age, nested, owner alive) through a read that creates no directory, compiles no helper, takes no lock and reclaims no record; an instance answers "is it me?" without reading JSON by hand. The six structural tasks and `kit-verify` were measured three times each in core and in a fixture export, and their host requests are sized from that measurement at the recorded capacity of eight: `format` 3, `configuration-root` 2, `registrations` 2, `generated` 2, `host` 2, `kit-verify` 2, and `declarations` 4 under the operator-authorized exception recorded in [D022](../../evidence/WO-229/decisions.md#wo-229-d022--authorize-declarations-at-its-measured-four-slot-need) ("fine make the change"), which the amended order carries. Every structural task still reserves all local lanes, so local exclusivity is unchanged; only the registry request is smaller. A sibling fixture holds a short document gate's total lane wait under a complete gate's longest single task while that gate keeps admitting peers, and its full-capacity control fails the same bound. Admission order is unchanged and no fair queue is added (WO-217-D040).
