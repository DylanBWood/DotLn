## Release overview

The compiler now defines what a tracked-work artifact looks like once it is inside DotLn. `SourceBundle` v1 carries an issue's sections, discussion, image references and revisions as data, with spans that point back to the artifact's own bytes, and it enters the runtime only through a decoder that refuses malformed input with a path and screens the rest against a declared set of secret shapes and link forms. This is the input contract of the `SourceAdapter` port and the first piece of gate G on the critical path: the story contract (WO-061), the first adapter (WO-062) and the pull-request comment surface (WO-065) build on it. The release is for people building or reviewing that intake path; nothing a running DotLn instance does today changes.

## Read before upgrading

`@dotln/compiler` moves from 0.19.4 to 0.20.0, a minor release for the new export; existing exports and behavior are unchanged, and the skeleton and console pins follow without moving their own versions. A decoded bundle is screened, not clean: the screen refuses eight declared shapes (a private-key block header, a Bearer credential and GitHub's six token prefixes) and two link forms whose host is not on the allowlist the caller supplies, and it passes every other string, including an unprefixed 40-hex token, a JWT without the Bearer word and a password inside an allowed URL's userinfo. An adapter or consumer must not treat acceptance as proof that no credential is present. `allowedHosts` must be an array of multi-label DNS names in any case; an empty array refuses every link, and an invalid entry throws as a caller error. Refusals never carry the matched text, only the field's path, byte offsets and span. The generated hooks and manifest pin a new runtime snapshot, and the console's self-host fixtures follow the feedback edition recorded under `docs/evidence/WO-060`.

## Substantive changes

`packages/compiler/src/source-bundle.ts` exports the `SourceBundle`, `SourceSection`, `SourceDiscussionEntry`, `SourceImage`, `SourceRevision` and `SourceSpan` types, `decodeSourceBundle`, `screenSourceBundle`, `sourceBundleHash`, `resolveSourceSpan`, and the declared data `SOURCE_SECRET_SHAPES` and `SOURCE_URL_FORMS`, each entry carrying its pattern, a description and the public reference it was taken from. A span is a half-open range of UTF-8 byte offsets on code point boundaries into one section's or entry's text; a section's or entry's own span covers its whole text; sections, entries and images share one id namespace; an author is one of `reporter`, `reviewer` or `automation`; an image is `sha256:` and 64 hex digits with an optional one-line alt text; discussion entries carry UTC timestamps that never go back in time. Decoding returns a result: `malformed` with the first failing path and a reason from a fixed vocabulary, `screened` with every finding in field order (paths index the value as supplied), or the accepted bundle, frozen and in canonical order (images by id and each revision's changed spans sorted; document, thread and history order kept), with an `fnv1a64:` hash over `{ domain: "dotln:source-bundle:v1", bundle }` as an equality receipt. The compiler index exports the module, and the evidence-source registry names it.

The console's manifest and three expected self-host outputs follow the compiler label and the carried feedback edition, the four-file pattern WO-162 recorded. ## Evidence and compatibility

Application `v0.53.0` is a minor over `v0.52.10`; `@dotln/compiler` 0.20.0 is a minor over 0.19.4. The `source-bundle-v1` contract is a new version axis, named by its hash domain; the compiled-program contract, kernel and event schema are unchanged, and no dependency is added. The authority, artifact-identity and verification editions are re-minted deterministically as WO-060 revision 001 and the feedback edition is carried from WO-162 with no live episode, because no judged behavior changed. Independent verification (VER-001) passed all six criteria on the staged subject, slicing every fixture span from its owner's bytes and comparing the GitHub shapes with the vendor's published formats. The executor's handoff recorded the review gate as failing on one skeleton test, the WO-143 acquisition matrix at its 240 s deadline, in two of three runs; the verifier's and the final review's full gates passed on the same code identity (36 suites, 0 failed, 315.38 s and 367.01 s), and the deadline under the shared gate is recorded for the planner. Known limitation: detection is bounded to the declared set; a URL userinfo password and an unprefixed JWT are named today as candidates for a later minor.
