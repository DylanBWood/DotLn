## Release overview

A release close is now one command that is correct the first time and says where its minutes went. The close prepares its runtime in a child process before it imports any built module, so the compiler that predicts a starter update is the compiler the export's fresh emit uses and the refusal that cost both closes of 2026-10-28 a retry cannot recur. The close prunes only the roots it owns instead of walking every retained temporary root on the host, its transcript and removal receipt carry counts and digests instead of path lists, and its record carries one timed row per step so the next planning pass reads a measurement instead of an inference. `worktree integrate` refuses while a live gate holds a lane for the worktree or main and returns before any stash when there is nothing to take in. This matters to operators who close orders and to forks that run the kit's close.

## Read before upgrading

- Run the printed `--publish` close command once. `--dry-run` remains available when a prerequisite such as egress or a foreign tag is in doubt, and it is no longer a standing first step; the release-close role, the post-merge handoff and the `resume release-close` briefing say so.
- The close no longer walks the system temporary directory. Expired roots outside a close's scope are removed only by an explicit `harness prune --apply`; `plan start` still prints the read-only global census, and `worktree start` prints no census. Where routine cleanup should live is boarded for planning (WO-239-D020, FUP-69af2e1da022aa7a).
- Retained-material advisories and worktree-removal receipts now carry counts by class and a digest. Pass `--list-material` to `release close`, `worktree finish` or settle to print the paths; the flag is outside the admitted helper forms, so host permissions decide it.
- A new removal receipt references a digest-bound sidecar in the same retained lane, named `removal-inventory-` followed by its SHA-256 digest, and is verified against it; keep the sidecar beside the receipt. Receipts written before this release keep their inline arrays and remain readable.
- The close record gains an additive `steps` field; readers that parse `release-close.json` may ignore it. `plan failures` gains a `timing` summary under its local release-close counts.
- `worktree integrate` refuses, naming the holder and the retry, while a live host lane names the worktree or main's checkout, and in repair and final review it fetches `origin/main` before deciding it has nothing to take in. An executor integrates only at the lifecycle points product 07 names.
- Skeleton `0.73.1` regenerates the installed roles, hooks, manifest and runtime pins; a fork re-emits its harness after taking the release. The fork's kit `release.mjs` receives this close with the release that carries it.

## Substantive changes

**Release close.** The `close` entry runs its source-only prerequisites (working directory, origin reachability, main synchronization, control state, release surfaces, tag conflicts, publish authentication) before anything else, prepares a stale or missing runtime in a child process (a source build in core, the carried-runtime preparation in a kit) and only then imports the writer release and the close; later steps assert that preparation held instead of rebuilding after imports have cached the old compiler. The prune at close runs under a close scope: the closing order's captured owned roots, main's retained lane and this checkout's registered temporary roots, each bound to its checkout by owner token and physical path. The record carries seven timed rows, with nested time excluded and the writer release's session cleanup charged to prune, and `plan failures` reports the median total and the slowest step over the latest eight timed attempts.

**Worktree removal and retained material.** The retained-material advisory and the removal receipt carry a count, counts by class and a digest of the sorted path list. The receipt's full inventory lives in a digest-bound sidecar published atomically, and verification refuses a missing, renamed, moved, altered or summary-mismatched sidecar while still reading historical inline receipts. `--list-material` prints the paths on `release close`, `worktree finish` and settle; the worktree-preservation preview is compact by default and names the flag.

**Integration.** `worktree integrate` refuses live lane holders in the worktree or main's checkout, letting the primary checkout stand for main while a planning pass has it off main; it resolves the phase's actual upstream (local main for active execution, fetched `origin/main` for repair and final review) before the no-op check and returns before any checkpoint, stash or merge scratch when that upstream is already an ancestor of `HEAD`.

**Roles and handoffs.** The release-close role runs the printed command once and treats `--dry-run` as optional for a prerequisite in doubt; the executor role integrates main only at the named lifecycle points and launches or restarts its three independent reviewers only after implementation or repair and its write-backs are complete, finishing all three before each complete run; the consistency reviewer's brief now traces every changed document, emitted output and helper to its consuming tests. The worktree-publish handoff and the release-close briefing print the one-invocation wording.

**Machinery coverage and oracles.** Shell suites' script paths are collected conservatively from the whole source, including comments and heredocs. The role-oracle walk follows every recorded parent link, checks every recorded digest and requires every role oracle to stay reachable, and a new test requires every oracle in the fixtures directory to be a declared input of the suite that walks it.
