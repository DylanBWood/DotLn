# WO-239 — Release close prepares before it loads and runs once (v0.103.1)

On 2026-10-28 two releases each needed three close invocations and 16 to 19 minutes: the close process imported the compiler before it rebuilt it, so the starter refresh compared a fresh emit against a stale prediction and refused, and a fresh-process retry then passed; the census walked 5,633 retained temporary roots on every invocation; and each transcript opened with an 800 KB path list. This pull request makes the close one `--publish` invocation that prepares its runtime in a child process before any built module loads, prunes only what the close owns, records one timed row per step, keeps path lists behind a flag, and makes `worktree integrate` refuse live lane holders and return before any stash when there is nothing to take in.

**The runtime is current before anything loads it.** `release close` now runs its source-only prerequisites first (working directory, origin reachability, main synchronization, the merged control state, release surfaces, tag conflicts and, for a publish, `gh` authentication), then prepares a stale or missing runtime in a child process (`node scripts/build.mjs` in core, the carried-runtime preparation in a kit), and only then imports the writer release and the close. Freshness is judged from source and the build receipt without importing built code; the three in-close rebuilds are assertions that name the entry. A static walk of the close's import graph reaches 70 modules and no `packages/*/dist` file. The paired control in [controls.json](../../evidence/WO-239/controls.json) refuses at the base with the recorded starter mismatch (exit 1) and passes at the head on the first invocation (exit 0), with a module-load trace showing the child build finishing before the parent's first built import.

**One invocation closes an order.** The release-close role, the post-merge handoff printed by `worktree publish` and the `resume release-close` briefing all say to run the printed `--publish` command once; `--dry-run` stays available when a prerequisite such as egress or a foreign tag is in doubt and is no longer presented as a standing first step. The executor role says to integrate main only at the lifecycle points product 07 names, never during a live gate or on its own initiative inside a handoff.

**The census at close is bounded.** The close prunes under `scope: "close"`: the closing order's captured owned roots, main's retained lane and this checkout's registered temporary roots, each bound to its checkout by owner token and physical path so a stale ledger cannot admit a foreign replacement and a checkout reached through a symlink still hands over its roots. A fixture with 1,000 foreign gate-fixture roots reads none of their owner files at close and all 1,000 under `harness prune`. The global walk stays at `harness prune` and the read-only census `plan start` prints; `worktree start` no longer prints a census. One premise of the order was false: the session-end prune never walked the system temporary directory, so today only an explicit `harness prune --apply` removes expired roots outside a close's scope. Where routine cleanup should live is a planning question boarded in [D020](../../evidence/WO-239/decisions.md#wo-239-d020--resolve-the-integrated-reviews-and-state-the-global-walk-as-built) (FUP-69af2e1da022aa7a).

**Counts on the records, paths on request.** The retained-material advisory carries a count, counts by class and a digest of the sorted path list; the worktree-removal receipt carries the same summaries and references a digest-bound sidecar in the same retained lane, named `removal-inventory-` followed by its SHA-256 digest and published atomically so an interrupted write cannot poison a content-addressed name. Readers verify the sidecar's name, digest and summaries before trusting it; historical inline receipts remain readable. `--list-material` on `release close`, `worktree finish` and settle prints the paths; it is a diagnostic outside the admitted helper forms, so host permissions decide it. A close over 2,000 ignored files writes a 198-byte advisory and a 995-byte receipt and no path list in its transcript.

**The close says where its minutes went.** The close record carries `steps` with one row each for prerequisites, runtime, worktree-removal, publication, starter-refresh, prune and record, each with `startedAt`, `finishedAt` and `durationMs`; durations exclude nested steps, repeated visits accumulate in one row, a skipped step keeps null timestamps and zero duration, and the writer release's session cleanup is charged to prune. `plan failures` reports the median total and the slowest step over the latest eight attempts that carry timings and leaves older records with their ordinary counts.

**Integration happens at named points.** `worktree integrate` refuses, naming the holder and the retry command, while a live host lane names the worktree or main's checkout; while a planning pass has the primary checkout off main, that primary checkout stands for main's. Repair and final review fetch `origin/main` and tags before judging whether there is anything to take in, so a stale local main cannot hide a newer upstream; active execution keeps using local main. When the upstream is already an ancestor of `HEAD`, the helper reports that it took in nothing before any checkpoint, stash or merge scratch. The paired control creates one real stash at the base (exit 1) and none at the head (exit 0) across the active, repairing and final-review phases, with the stash list and untracked bytes unchanged.

**Generated outputs and versions.** Skeleton `0.73.1`, the console's exact pin and the lockfile follow the two role sentences; the release is `v0.103.1`, a patch above main's `v0.103.0`; compiler `0.33.0` and console `0.5.0` are unchanged and no external dependency changes. Both installed role trees are regenerated and pinned by `wo239-integration-role-baseline.json`, which chains to main's `wo235-removal` oracle and this branch's `wo239` oracle; the oracle walk now follows every recorded parent link and requires every role oracle to stay reachable, and a test requires every oracle to be a declared input of the suite that walks it. The executor root grows from 34,975 to 36,500 bytes and the release-close root from 22,657 to 22,758, within the accepted ceilings of 40,194 and 26,410. The authority evidence edition is re-minted at revision 005.
