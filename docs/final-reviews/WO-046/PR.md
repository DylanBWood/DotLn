# WO-046 — Make the executable program grammar a type so an unrunnable continuation fails when it is read

The kernel's Program grammar has always been larger than the part the stepper can evaluate, and the gap was held by a constant and a corpus rather than by the type system: `stepProgram` accepted any kind and threw `Program <kind> evaluation is deferred` in the middle of an episode, and `deserializeContinuation` was `JSON.parse(value) as Program.T` — an unchecked cast over data the runtime had persisted and would later act on. `ExecutableProgramV1` closes that gap. It is a recursive union of Done, Emit, Invoke, Await, Guard and Sequence in which every child, every `Guard` arm and every `Invoke` result branch is itself executable; `stepProgram` and `decideProgram` accept only it and return residuals and waits in it; and `EVALUABLE_PROGRAM_KINDS` is pinned to its kinds in both directions, so adding a kind to the union without the constant, or the constant without the union, fails the build. `decodeContinuation(value: unknown)` replaces the cast and returns the kernel's shared `DecodeResult<ExecutableProgramV1>`: it takes serialized or already-parsed JSON, validates nodes, event drafts, Act commands, patterns, predicate references and complete Cadence timeout shapes, and refuses anything else with a code, a JSON path and a message — a deferred kind as `DEFERRED_PROGRAM_KIND` naming the kind at the offending node's own path, whether that node is the root, a `Sequence` element, an `Emit` or `Await` continuation, either `Guard` arm, or an `Invoke` branch under a key that needs quoting. The skeleton now reads both of its persisted continuations through it: `seiriReactor` decodes `state.program` before any branch runs, and `verificationStateFromRuntime` decodes the stored verification continuation, so a continuation the runtime cannot execute is refused when it is read instead of after a command has been dispatched.

`Program.T` is deliberately untouched as the authoring grammar — the deferred kinds stay constructible, which is what the entropy-reducer's operator-mediated `Program.All` plan still needs — and the five affected constructors gained overloads that return the narrowed type for executable children while preserving their original signature and their exact runtime output. `serializeContinuation` emits the same bytes it always did.

What is proven: every deferred kind refuses at every continuation edge, in both input forms, with the kind named and the path exact, reproduced independently by the verifier at 90 assertions and by the reviewer at 80 including a four-level nesting; all 3,321 committed corpus continuations decode with zero false refusals, and the WO-101 corpus harness now feeds its 38,920 bounded evaluations through the decoder rather than a `structuredClone`, reproducing the recorded steps; round-trip equality, byte-identical re-serialization and identical `stepProgram`/`decideProgram` output before and after decoding; a differential fuzz of 1,573 mutants against a validator transcribed from the type rather than the decoder, with no value accepted that the type rejects; hostile input — cycles, array holes, throwing getters that are never invoked, custom prototypes, symbol keys, non-finite numbers, invalid JSON, a 20,000-deep tree — held inside the result contract; and the kind-constant pin failing the compiler in every divergence direction tried — four by the verifier, three of them reproduced independently by the reviewer from a clean copy. Nothing observable moved: all 18 committed fixtures and the frozen WO-003 oracle are byte-identical to `main`, and the artifact-identity and verification evidence regenerates from the changed reactor byte-identical to the previous edition, so no semantic hash or artifact identity changed.

The application target is v0.21.0 with kernel 0.4.0 and skeleton 0.18.0; compiler 0.11.1 and console 0.1.6 are unchanged and there is no new dependency, the lockfile diff being the two workspace versions and the skeleton's kernel pin. The kernel takes a minor because both stepper entry points reject programs they previously accepted and `deserializeContinuation` has left the export surface; the skeleton takes one because its two persisted reads now refuse malformed input. VER-001 passed every criterion with no blocking finding and eight observations. The final review re-read the whole subject at source, re-derived the refusal, parity, divergence and byte-identity claims by its own routes, measured the fold-time decode cost the verifier had left unmeasured, refreshed the two publication locks this order staled, corrected a capability note that still said verification was pending and a skeleton README lead that still described the previous release, and ran `npm test -- --review` once: 24 suites, 0 failed, 227.20 s. See `docs/final-reviews/WO-046/FINAL-001.md`, `docs/verifications/WO-046/VER-001.md` and `docs/evidence/WO-046/decisions.md`.

Read before merging: the stepper's `default:` branch now throws `Invalid executable program` instead of naming the kind, and has no regression pin — it is unreachable for typed callers, but an untyped JavaScript caller that bypasses the decoder loses the diagnostic WO-101 pinned, and a one-line test is nominated for the next kernel order. Deferred *Cadence* kinds inside a persisted `Await` timeout still decode: the decoder validates all 14 cadence shapes but not their evaluability, and eight of them are deferred at `evaluateCadence`; nothing evaluates a persisted timeout today, because the Program stepper returns the wait without touching it and the skeleton's only two cadence call sites use a compiled schedule and a literal `After`, but a future consumer that does evaluate one meets the mid-episode failure this order removes for Programs. The decoder is stricter than structural assignability about unknown fields, so a producer that adds a field to a persisted continuation will fail at read; and for already-parsed input it returns the same object rather than a copy, exactly as the previous cast did. Fold-time decoding costs about 19 µs for a realistic verification continuation, roughly 37 µs per fold counting the episode path's second decode. The executor's attestation recorded model and effort `unknown` under Codex CLI 0.154.0; the contract logs and never refuses, and the verifier and reviewer read every output that completion advised on. Release close publishes v0.21.0, which is free locally and on origin.
