## Release overview

DotLn v0.21.0 makes the runtime's executable program grammar a type and refuses a persisted continuation the runtime cannot execute at the moment it is read. Until now the kernel's `Program` grammar described eleven node kinds while the stepper could evaluate six, and the difference was held by an exported constant and a corpus rather than by the type system: a stored program of a deferred kind was accepted, cast and only rejected once evaluation reached it, mid-episode. `ExecutableProgramV1` is now what `stepProgram` and `decideProgram` accept — Done, Emit, Invoke, Await, Guard and Sequence, recursively, at every child and every continuation edge — and `decodeContinuation` validates persisted data against it before the local runtime folds an event or reads a verification continuation. For an operator running the always-on loop the visible difference is where a bad continuation stops: at the read, named by kind and JSON path, instead of somewhere after a command has already gone out.

## Read before upgrading

Source release target v0.21.0 includes kernel 0.4.0 and skeleton 0.18.0. Compiler 0.11.1, console 0.1.6 and every third-party dependency are unchanged; the lockfile diff is the two workspace versions and the skeleton's kernel pin. No package distribution or hosted service is introduced.

`deserializeContinuation` is removed from the kernel's public surface and replaced by `decodeContinuation(value: unknown)`, which returns the kernel's `DecodeResult` carrying an `ExecutableProgramV1`. Callers that relied on the old unchecked cast must handle a result: `{ ok: true, value }` or `{ ok: false, code, path, message }`. The only in-repository consumers were kernel tests, the WO-101 corpus harness and the skeleton, all updated.

`stepProgram` and `decideProgram` narrowed their parameter type. Code that passed an arbitrary `Program.T` no longer type-checks; it must decode first or construct through the executable overloads. This is a compile-time change only — no saved data, event schema, hash preimage or serialized byte moves, and `serializeContinuation` emits exactly what it did before. The authoring grammar `Program.T` is unchanged, so every deferred kind remains constructible and existing authored plans that use them are unaffected.

Two limits are worth knowing before you rely on the new boundary. Deferred *Cadence* kinds inside a persisted `Await` timeout still decode: the decoder validates all fourteen cadence shapes but does not judge their evaluability, and eight of them remain deferred at `evaluateCadence`. Nothing evaluates a persisted timeout on any current path, because the Program stepper returns the wait without touching it, but a future consumer that evaluates one would meet the same mid-episode failure this release removes for Programs. And the decoder refuses unknown structural fields, which is stricter than the type's own assignability: a producer that adds a field to a persisted continuation will fail at read rather than silently carrying it. No committed continuation in the repository is affected by either — all 3,321 of them decode.

No operator action is required, no migration is needed, and no recorded data is rewritten.

## Substantive changes

**Kernel — the executable grammar is a type.** `ExecutableProgramV1` is a recursive union in which `Emit.next`, `Await.next`, both `Guard` arms, every value of `Invoke.continuationByResult` and every element of `Sequence.programs` are themselves executable. `ProgramStep.residual`, `ProgramDecision.continuation` and the `waits` list carry it, so a residual taken out of the stepper is executable by construction. `EVALUABLE_PROGRAM_KINDS` is no longer an independently maintained list: it is pinned to the union's kinds in both directions, and dropping a kind from either side or adding one to either side fails the build. The five constructors that can hold children — `Emit`, `Invoke`, `Await`, `Guard`, `Sequence` — gained overloads that return the narrowed type when given executable children, with unchanged runtime output and an unchanged signature for authoring use.

**Kernel — typed continuation decoding.** `decodeContinuation` accepts a JSON string or an already-parsed value and returns the same `DecodeResult` shape the event-log codec introduced in v0.20.0. It validates node kinds and their required and optional fields, event drafts, Act commands, event patterns, predicate references and complete Cadence timeout shapes; refuses a deferred Program kind with `DEFERRED_PROGRAM_KIND`, the kind in the message and the offending node's own path; and refuses malformed data with a specific code and path — including cycles, array holes, non-finite numbers, symbol keys, inherited or accessor properties (never invoking a getter), custom prototypes and invalid JSON. Validation is iterative rather than recursive, so a deeply nested tree cannot exhaust the stack.

**Skeleton — persisted continuations are decoded at the read.** `seiriReactor` decodes `state.program` before any branch runs, and `verificationStateFromRuntime` decodes the stored verification continuation, each refusing with a prefixed message — `runtime program: …` or `verification continuation: …` — that carries the decoder's code and path. A refusing fold leaves the state object untouched and happens before any command is dispatched or any result consumed.

**Corpus and tests.** The WO-101 program corpus now routes every evaluated input through the decoder instead of a structural clone, so its 38,920 bounded evaluations exercise decoded values and pin the recorded steps against them; the corpus also asserts that its manifest's root kinds cover the executable constant. The WO-101 deferral pins moved from stepper throws to decode refusals at two paths per kind. New kernel and skeleton suites pin the type-level equalities, the refusal paths and both fold boundaries.

## Progressive polish

Documentation and generated-surface refreshes accompany the release: product 02's Events and decisions section names the executable type and the decoder, the kernel README rewrites its Program and continuation rows, the skeleton README describes the new read boundary, the roadmap records the v0.21.0 activation, the capability table carries a dated reassessment of `program.evaluable-subset` that retains level 2 with an unchanged real-session target, and the two publication table-of-contents editions have their source locks refreshed against the edited product section. The regenerated harness bundle differs from v0.20.0 only in runtime content pins — the runtime snapshot identifier and the skeleton reactor's content hash — with no change to any hook's behaviour, the hand-written Clean Room floor or the skills.

## Evidence and compatibility

Source tag v0.21.0, published from `main` after merging the reviewed `wo-046` branch above v0.20.0 (`83e734f`). Supported versions: kernel 0.4.0, skeleton 0.18.0, compiler 0.11.1, console 0.1.6; all packages remain private and unpublished, and `npm publish` is refused by every manifest.

Compatibility is unchanged where it is observable. All 18 committed fixture files and the frozen WO-003 decision-trace oracle are byte-identical to the previous release; the demo scenario audit, the semantic-hash inventory, the negative transcripts and the four synthetic verification-evidence files regenerate from the new build byte-identical to their prior edition; no semantic hash or artifact identity moved. A fresh feedback-audit evidence edition accompanies the changed skeleton runtime and passes its offline check.

Verification: [VER-001](../../verifications/WO-046/VER-001.md) passed all six acceptance criteria with no blocking finding and eight recorded observations, reproducing every consequential claim independently — 90 deferred-refusal assertions, 132 executable parity checks, 3,321 committed corpus continuations decoded with no false refusal, a 1,573-mutant differential fuzz against a validator written from the type rather than the decoder, a 27-shape hostile probe and a four-way compile mutation of the kind pin. Final review: [FINAL-001](FINAL-001.md) re-derived the refusal, parity, divergence and byte-identity claims by its own routes, measured the fold-time decoding cost at about 19 µs for a realistic continuation, handled the publication-lock and documentation bookkeeping, and recorded the reviewer product gate: `npm test -- --review`, 24 suites, 0 failed, 227.20 s, 67 fresh tasks.

Known limitations: the stepper's remaining backstop throws `Invalid executable program` without naming the kind and carries no regression test, which matters only for an untyped caller that bypasses the decoder; deferred Cadence kinds inside a persisted `Await` timeout decode without a claim that they can be evaluated; the decoder returns the same object rather than a copy for already-parsed input, as the previous cast did; and the capability `program.evaluable-subset` stays at level 2, because this release supplies no real-session evidence of persisting an `Await` residual and resuming a fresh episode against it. Deeper technical notes are in [FINAL-001](FINAL-001.md), [VER-001](../../verifications/WO-046/VER-001.md) and the [decision record](../../evidence/WO-046/decisions.md).
