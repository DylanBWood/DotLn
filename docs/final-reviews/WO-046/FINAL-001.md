## Source review

`types.ts` keeps every `Program` interface exactly as it was and adds `ExecutableProgramV1` as a union that reuses them through `Omit` plus a narrowed child: `Emit.next`, `Await.next`, both `Guard` arms, every value of `Invoke.continuationByResult` and every element of `Sequence.programs` are `ExecutableProgramV1`. That is the whole type, and it is the reason the order could avoid generics: nothing about the authoring interfaces changed, so `Program.T` and every document that describes it are still true. Five constructors — `Emit`, `Invoke`, `Await`, `Sequence`, `Guard` — became overloaded functions whose first signature returns the narrowed member when handed executable children and whose second is the original. The implementation signature is the original in each case, so the runtime object is byte-for-byte what it was; only inference changed. `Done`, `Choose`, `All`, `Race`, `Repeat` and `Compensate` are untouched arrow functions, which is the right asymmetry: the deferred constructors must keep producing `Program.T` and nothing else.

`core.ts` narrows four parameter and field types and deletes one export. `ProgramStep.residual` and `ProgramDecision.continuation` are `ExecutableProgramV1`; `waits` is `Extract<ExecutableProgramV1, { kind: "Await" }>[]`; `stepProgram` and `decideProgram` take the executable type. `ProgramDecision` now declares `continuation` as required where `Decision` declares it optional — a legal narrowing, and the reason `reactor.ts` can treat a program decision's continuation as present. The kind constant is no longer a bare `satisfies`; `defineExecutableKinds` constrains its argument to `readonly ExecutableProgramV1["kind"][]` *and* requires `[ExecutableProgramV1["kind"]] extends [Kinds[number]]`, so a missing kind makes the parameter `never` and an extra kind fails assignability. That is the bidirectional pin, and my mutation experiment shows both halves firing. The `default:` branch of `stepProgram` now throws `Invalid executable program` instead of naming the kind, which is correct for a branch that is unreachable for typed callers but is the one place where the change costs a diagnostic; see O1 carried below. `serializeContinuation` is unchanged.

`continuation.ts` is a two-pass iterative decoder, and the order of the passes matters. `validateJson` walks the value first with an explicit stack and a live `active` set, refusing cycles, non-finite numbers, non-plain prototypes, array holes, out-of-range or non-index array keys, symbol keys, and any property that is not an enumerable data property — the last of which is what makes a throwing or observing getter refuse without ever being invoked, as the committed test asserts by leaving its `called` flag false. Only then does the shape pass run, driven by three small tables (`programShapes`, `cadenceShapes`, `shapes`) and a type language of about a dozen tokens, with `?` marking optional fields and `[]` marking arrays. Unknown fields are refused before missing ones are blamed, so an extra key is reported as itself rather than as some absent sibling. Paths are built by `fieldPath`, which uses dotted form for identifier-shaped keys and `JSON.stringify` bracket form otherwise — the reason `$.continuationByResult["odd.key"].kind` is unambiguous. The deferred set is an explicit five-element list checked only when the kind is absent from `programShapes`, so a deferred kind gets `DEFERRED_PROGRAM_KIND` and a genuinely unknown one gets `UNKNOWN_KIND`; both name the path. Control flow is a thrown `InvalidContinuation` carrying the result, caught at the top and returned, with a defensive fallback that converts any other throw into a `NON_JSON_VALUE` result — so the function's contract is total, which my hostile probe confirms across every shape I could construct. The recursion is a `pending` array rather than the call stack, which is why a 5,000-deep tree decodes in the committed test and a 20,000-deep one did for VER-001.

`reactor.ts` changes two reads and one fold. `persistedContinuation(value, location)` decodes and throws `"<location>: <decoder message>"`, giving `runtime program: Invalid continuation: …` and `verification continuation: Invalid continuation: …`; `programFromState` is now that call, and it replaces the previous `throw new Error("runtime state lacks continuation")` for a null program with the decoder's `EXPECTED_OBJECT at $` — a message change, not a behaviour change, and the guard at the call site keeps `null` from reaching it during a fold. `verificationStateFromRuntime` returns a spread with a decoded `continuation` instead of casting the stored object wholesale. `seiriReactor` gains one line, `if (state.program !== null) programFromState(state);`, before any branch — the "refuse when it is read" boundary the objective asks for, and the reason the new skeleton test can assert that a corrupt program refuses on an ordinary `Tick` before any result or dispatch. `requiredContinuation` still tests `decision.continuation === undefined` although its parameter type now makes that unreachable; harmless, and cheaper to leave than to argue about.

The tests match the claims. `wo046-continuation-decoder.test.ts` carries five compile-time `Equal<…>` assertions (kinds versus the constant, both stepper parameter types, `Program.T` not assignable to the executable type, and a `Sequence` of `All` not assignable) alongside the runtime cases; `wo101-deferral-pins.test.mjs` moves WO-101's pin from stepper throws to decode refusals at two paths per kind; `wo101-program-corpus.test.mjs` now round-trips every evaluated input through the decoder rather than `structuredClone`, so the 38,920-evaluation corpus runs on decoded values, and its new case ties the manifest's root-kind coverage to the constant; `wo046-continuations.test.ts` pins both skeleton boundaries, including that the refusing fold leaves the state object unchanged. The one weakening is the deferral pin's lost stepper assertion, which O1 records.
