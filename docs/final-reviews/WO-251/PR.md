# WO-251 — Desktop control is opt-in: the hook and the emitted host settings refuse the desktop-control tools unless `dotln.config.json` elects `features.desktop-control`, browser verification is the Playwright MCP's snapshot, screenshot and image read, and every role's text says so (v0.109.0)

Until now nothing in the kit said how a session verifies a web surface or forbade taking over the operator's desktop: the permission hook knew no MCP tool, so every desktop-control, Claude in Chrome and desktop-app browser tool reached a session as an unclassified advisory and host permissions alone decided, and a session in the operator's instance chose native desktop control without asking. The only rule anywhere was the Codex worker transport's disabled features, which covered workers and nothing else.

Now desktop control and the operator's own browser sessions are refused unless the instance elects `features.desktop-control` in `dotln.config.json`, and an election makes the tools admissible without authorizing their use: the operator's explicit request in the session is still required. Two layers enforce it where Claude Code lets the kit enforce it. The permission hook classifies eight host namespaces (`mcp__computer-use__`, `mcp__remote-devices__computer_`, `mcp__claude-in-chrome__`, `mcp__Claude_Browser__`, `mcp__remote-devices__Claude_Browser__` and the three `enable__` switches) and `Skill` with any of four selections as `desktop`, reads the election at judgment time and refuses with `DOTLN_DESKTOP_CONTROL_REFUSED`, a reason naming the key, the Playwright route and the request requirement, before any working-directory or session-state handling, so the refusal survives a moved cwd and an unavailable journal; when the election is on it admits the tool after the existing descendant and router guards with one advisory per session. `harness emit` reads the same election and writes sixteen `permissions.deny` entries into `.claude/settings.json`, the eight namespace globs and, for each skill, `Skill(name)` with `Skill(name *)`, so the host refuses before any hook runs and a hook failure cannot admit the tools; `harness check` reports a settings file that disagrees with the configuration. Both layers read one inventory in the compiler, so they cannot drift. A Playwright MCP tool is judged as before.

The `features` section accepts `true`, `false` or `{ "on": boolean, "note": "the operator's reason" }` per feature, refuses an unknown id by name and reads absence as off; `desktop-control` is its one id until WO-241's registry. Every generated role, Claude and Codex copies alike, carries one sentence: verify a web surface in a browser the session launches, through structured state, then the DOM and accessibility tree in the Playwright MCP snapshot, then network and event data, then a screenshot read as an image, or the project's own browser tests, and desktop control and the operator's own browser sessions are refused without the election and the operator's words. The kit template, the example configuration (`"features": { "desktop-control": false }`), the kit guide's §What runs here, and what does not, product 07 §Discipline and the feature inventory say the same. The generated refusals sentence is now rendered from seven refusal rows, so its count follows the list and no order edits a number: `CLAUDE.md` reads seven refusals naming WO-251.

What a reviewer should know: an instance that updates to this kit and re-emits gets the sixteen deny entries and the hook refusal by default; a session that used desktop control or the operator's browser before is refused until the instance elects the feature and re-emits, and must still ask. The hook and the host rules name a listed skill exactly, so an alias, display-name or plugin-form invocation of the same skill is outside both layers' names, while the desktop tools themselves stay refused under every probed name; verification boarded the repair ([D017](../../evidence/WO-251/decisions.md#wo-251-d017)). The shared sentence grows every installed role root by 909 bytes; the planner root now measures 25,222 against its unchanged 24,576-byte ceiling, boarded for optimization with equivalent usefulness ([D007](../../evidence/WO-251/decisions.md#wo-251-d007)). Codex tool calls are unhooked, so under Codex the rule is role text, and the worker transport's disabled features are unchanged. The kit template's provenance and navigation paragraphs were compressed to keep an exported instance's cold start no larger than core's ([D015](../../evidence/WO-251/decisions.md#wo-251-d015)). Integration took in WO-245, moved the order's kit-guide paragraphs into `docs/KIT.md` and retimed the release from `v0.108.0` to `v0.109.0` ([D018](../../evidence/WO-251/decisions.md#wo-251-d018)).
