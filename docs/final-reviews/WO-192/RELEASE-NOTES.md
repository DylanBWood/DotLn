## Release overview

One typed phrase, `drive: WO-NNN`, now carries a DotLn order from its current phase to a pull request ready to merge, and, typed again after the merge, through release close. A router reads canonical status only, starts a fresh pinned worker for each phase in the order's own worktree (the target worktree for a registered target), hands it nothing but its lifecycle phrase, and stops with one line for the operator's merge, a routed finding, an off-ramp, a refused dispatch, a repair bound or an exhausted budget. Each worker keeps its own writer, role, selected effort and sub-agent budget; a shared ceiling bounds the whole drive. On Claude Code the whole lifecycle ran live on a registered target order from one phrase; on Codex CLI 0.166.0 the drive reached the passing final review and its release close was declined for a reason the host did not report, which this release records rather than hides. This matters to operators who run orders through DotLn and to forks that take the kit.

## Substantive changes

**Router and driver.** `packages/skeleton/src/loadouts/contributor.ts` adds the `router` role with the `drive:` intent and its generated skill. `scripts/drive.mjs` and the `scripts/lib/drive-*.mjs` modules separate pure route selection (`drive-route.mjs`, shared with canonical status), the physical registry binding of an order's worktrees (`order-worktrees.mjs`), launch profiles and worker notes (`drive-prompts.mjs`, `drive-worker.mjs`), native stream reduction to metering and protocol facts (`drive-stream.mjs`, `drive-diagnostics.mjs`), process supervision with a short-lived supervisor per native worker (`drive-transport.mjs`, `drive-process.mjs`) and session ownership, re-entry, budgets and the kernel-backed host lock (`drive-session.mjs`). Phase workers run as separate native CLI sessions, Claude print sessions or Codex exec sessions, with preloaded role skills; the launch arguments of both hosts, every role and both worktree shapes are retained in `docs/evidence/WO-192/driver-launch-arguments.json`.

**Identity, reservation and release.** `packages/skeleton/src/harness-host.ts` keys a lifecycle worker's session by host session and agent, records its role and selected effort from hook input, names the holding agent in `harness writer --show`, and releases its reservation at `SubagentStop`. The router holds no writer: its spawn must carry exactly one lifecycle phrase given to the agent type that phrase names (`DOTLN_ROUTER_SPAWN_REFUSED`), it edits nothing and runs only the live gate's reads, its driver and its usage command (`DOTLN_ROUTER_WRITE_REFUSED`), and a host denial of the driver latches a router-only refusal until a new drive phrase (`DOTLN_ROUTER_LAUNCH_REFUSED`). A driven worker's helper is read-only in both worktrees, and a live launchpad gate protects its inputs from a target worktree's hooks as from its own.

**Budget per worker.** `packages/skeleton/src/subagent-budget.ts` counts a spawn against the agent whose tool call made it, applies `subagentCap` per spawner and `drivenSessionCeiling` to the drive's shared counter, keeps unresolved joins as reported minima, and reports both counts through `harness usage`. The generated roots' fan-out sentence states both bounds.

**Grants and routes.** The `order-worktree` grant resolves the recorded branch through Git's worktree registry and, for a registered target, the target and paired launchpad through the target registry, compared by physical identity so an alias keeps the grant and another order is refused; roots that cannot be resolved withhold this grant alone and name the cause. Canonical status gains `route`; `worktree integrate` run from a registered target root integrates the paired launchpad; a target order's final-review briefing names that command.

**Generated definitions and checks.** `packages/compiler/src/harness.ts` emits every agent definition from one worker specification, with description, pinned model and effort, preloaded skill and body, and `harness check` detects drift in any of them. `.gitattributes` marks `.claude/agents/**` as generated; the instance gate identity includes the four lifecycle definitions.

**Runner and front page.** `scripts/test-runner.mjs` runs the lifecycle fixtures as the `resume` product preflight and the legacy comparisons as `resume-docs` in the document gate, strips a driven worker's context from every suite environment, and registers `scripts/test-drive.mjs` in the harness suite. `scripts/docs-check.mjs` admits a front-page change bound by a validated execution amendment while keeping the control, shape and binding refusals.

**Documents.** Product 07 §Operator resume phrases records the phrase, its authority, the route, its stops, the hosts' launch policies and the Codex close limitation; product 05 names the router as the first host binding of the orchestration policies; `docs/AI-HARNESS-SECURITY.md` states the router-only refusals, the per-agent identity, what stays root-wide and the `order-worktree` grant; the PLAYBOOK states the independence reading; `docs/product/feature-configuration.md` and the kit README list the new budget keys and suite.
