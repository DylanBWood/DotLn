## Findings and readings

No acceptance defect. The readings below were checked at source and change nothing.

- **Accepted-input set, traced.** `readReceipts` now reads every committed receipt's bytes in one batched `readMany` before the loop and JSON-parses every workspace receipt before validating any. The set of accepted and refused inputs is unchanged: the same three filters select the committed paths, a symlinked committed receipt is refused with the same message, `read` still refuses a missing workspace file, and the five malformed shapes VER-002 tried keep their original diagnostic. What can change is which of two bad receipts is reported first; the function either returns all receipts or throws, so no consumer observes the ordering.
- **Prefetch is a hint, and its failure is total but harmless.** `prefetchCommittedSources` wraps the whole request list in one `try`, so the first receipt whose revision does not resolve abandons prefetch for every later receipt. That costs launches, never correctness: the canonical `validateReceipt` rebuilds the subject at that same revision and refuses the receipt anyway. No change.
- **Split-on-failure spends launches only on the failure path.** `readBlobBatch` retries any error by halving, so one bad object in a 32-object batch costs up to about 63 launches before the singleton throws, and the successful halves' bytes are discarded rather than cached on that path. The success path is one launch per 32 objects. No change.
- **The immutable shortcut is keyed by resolved commit, not by input.** `committedTree` reuses a tree only when the requested revision is a full 40- or 64-hex id already present as a key in the same root's tree cache, and keys are written only from `rev-parse --verify <rev>^{commit}` results. An annotated tag's own id is therefore never a key and is peeled afresh (the D007 regression), `HEAD`, branch and tag names always resolve, and a cross-root id misses. VER-003 counted 36 `rev-parse` launches in the check, so mutable lookups still pay.
- **Receipt 027's two known issues stand as reopening conditions, not findings.** Criterion 2 is host-bound; every measurement in the sequence, this review's included, is from the operator's host, and the receipt names another host or a longer sequence as the reopening observation. Criterion 3's regressions test mechanisms (stat counts, launch counts, call counts) rather than wall-clock; the receipt's observation is a plan task above 10 s while the regressions pass. Both are unchanged by this order and are cited here so the next reader finds them.
- **Independence across the sequence.** Implementation ran on Codex CLI 0.156.1 / `gpt-6-sol`; both repairs on Codex CLI / `gpt-6-astra`; VER-001 on Claude Code 2.1.282 / `claude-opus-5-5[1m]`, which found the timing miss; VER-002 and VER-003 on one reused fresh-context Codex agent (`gpt-6-astra`) under a Codex root that recorded the transitions.
