## Release overview

This release makes the planning check fast. `node scripts/refute-plan.mjs check` rebuilds the planning subject from the committed tree and the workspace, compares it with every recorded refutation receipt, and runs twice inside `npm run test:docs`, which every planning pass and every final review executes. It took 16 to 20 s, and the two document-gate tasks it drives cost about 25 s each, because the subject builder rebuilt the work-order path pattern for every committed path of every sequenced order and re-read the launchpad configuration each time: 3.9 million `statSync` calls per check. On the operator's host the check now finishes in about 1.6 s, `plan subject` in 0.10 s, and the two tasks in 1.90 s and 1.81 s, with output byte-identical to the previous release on the same tree. The intended audience is anyone who runs a planning pass, a refutation or a final review.

## Read before upgrading

No operator action is required, and no contract, schema, gate step or role text changes. The planning subject, the receipt hashes and the check's JSON output are byte-identical to `v0.46.1` on the same tree, so no receipt is re-filed and no refutation is re-run. The receipt reader's behavior at its boundaries is unchanged: mutable revisions (`HEAD`, branches, moved tags, annotated tags) still resolve afresh on every read, an edited committed receipt is still refused, a symlinked required source is still refused, and an object larger than Git's 16 MiB output buffer still fails the read that needs it. Two regressions found by independent verification during the order, an unused legacy symlink rejected by the new prefetch and an aggregate batch overflowing that buffer, were fixed before release and each has a fixture. The normalization cache holds at most 512 entries and 1 MiB of string storage in process memory. No dependency is added and no component version moves.

## Substantive changes

**One configuration resolution per subject.** The subject builder resolves the configured work-order root once per call and compiles one expression per sequence id outside the committed-path filter. The fixture that drives a two-order sequence through 256 unrelated committed paths made 543 `statSync` calls before and makes 10 now, with the same pinned subject hash. `loadConfig` keeps its per-call stat, so a configuration that appears or disappears mid-process is still noticed.

**Batched committed reads.** The receipt reader reads every committed receipt's bytes in one `git cat-file --batch` per 32 objects instead of one launch per file, and prefetches each receipt's subject sources into the existing bounded caches (64 trees, 2,048 blobs). Prefetch grants no validity: the canonical subject is still rebuilt and compared, and an unusable hint is skipped. A tree is reused without a Git launch only for a full id already resolved as a commit in the same root. A failed multi-object read splits until singletons, whose failures still reach the caller. Launches per check fell from 242 to 104 (36 `rev-parse`, 29 `ls-tree`, 25 `cat-file`, 14 other).

**Bounded normalization cache.** The NFKC and whitespace normalization that receipt comparisons apply to criterion text is memoized by exact input string. Results, including for missing values, are unchanged; the cache evicts oldest-used entries at 512 entries or 1 MiB of combined input and output storage and bypasses oversized inputs.

## Progressive polish

Product 07's cold-gate candidate records the whole measured series, from the 2026-09-22 finding through the hoist-only result, the first repair and the final figures, and names which numbers are which. Product 06 records the `v0.46.1` activation and the retiming to `v0.46.2` after the sibling's release. The order text carries the two operator scope expansions and their planning-log bindings. Seven regression cases join the existing plan-refutation machinery suite and add no gate step. Two limits are on the record: the 2 s bound is measured on one host, and the regressions bound stat calls, Git launches and normalization calls rather than wall-clock, so a later change that reintroduces the cost through another call class would pass them; the planning receipt names a plan task above 10 s as the reopening observation.
