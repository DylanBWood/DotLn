## Release overview

A planning pass now opens knowing which recorded numeric reopening thresholds have been crossed, instead of a review finding them by hand. `npm run plan -- conditions` measures a named table of thresholds from the decision records and the follow-up register, and `plan start` prints how many hold. The meter's reopen-candidate count is now computed or reported as unavailable; it no longer prints zero for a predicate it could not read. An entropy review or refutation worker also gets its own temporary directory beside its frozen copy, and the receipt accounts for what it wrote there. This release is for the operator and planners who decide when to reopen a choice, and for anyone who reads an entropy receipt.

## Read before upgrading

No migration is needed, and no gate, refusal of a handoff or control-event schema changes. One new refusal applies when decisions are read: a decision whose `reopenWhen` metric predicate names a metric the meter cannot resolve fails with the decision's id and the metric. Every existing record passes. `plan start` now runs the default listing before it creates the planning branch, which added about 22 to 24 s per entry on the operator's host. The meter now lists WO-150-D003 as a reopen candidate, because the executor's cold start of 26,903 bytes exceeds its 24,576-byte condition; the pass that reads it records `reopens` or a new decision. New entropy receipts carry one more confinement field and witness sentence; receipts filed earlier render as before. A review worker's instructions now admit two writable roots: its frozen copy and its episode temporary directory.

## Substantive changes

The planning listing is a closed table of ten probes plus the meter's decision predicates. It covers the plan check's wall time, release tags newer than the generated table, distinct evidence bytes per order and tracked evidence added this week, the console's source collection, a cold release list, `status --all --json` bytes, the work-order index, and, with `--slow`, the document gate and its docs-check task. Each row names its source decision or register row, its method, value and threshold, and whether it holds. An unmeasured row is `unknown` with its reason. A final line counts the recorded conditions it does not evaluate: on 2026-09-30, 1,177 decision conditions and 799 register rows. Timings are medians of three fresh processes, printed beside the host's load average. It exits 0 whatever holds; a table row whose source resolves to no decision and no register row is refused.

The meter resolves each role's cold start (`coldStartBytes.executor` and the like) and `sequenceBytes` from the same measurement as its budget line, and order metrics from the order rows. A predicate that holds stays a reopen candidate until a later decision records `reopens` for it. If any unreopened predicate cannot be observed, the health line says the count is unavailable.

Each launched review and refutation receives `TMPDIR` set to a `tmp` directory inside the episode's scratch parent, outside the frozen copy, and the instructions name it. The receipt records that directory's path count, bytes and hash, and the witness sentence states the count and bytes. Filing makes the episode's directories writable, without following links, before removing the scratch parent. A removal that still fails prints one line naming the leftover path after the receipt is filed, and the command exits 0.

## Progressive polish

The release list's implementation can now be called with a root and an in-memory cold cache, and `scripts/release.mjs` runs its command only when executed directly. A host Codex or Copilot session no longer contaminates the release-close fixture's children. The reviewer's guide, the follow-up register's introduction and product 07's planning procedure each gain one sentence or paragraph naming the new command or the temporary root.
