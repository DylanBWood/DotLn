# WO-175

Decision records and the follow-up register state when a choice should be reopened, often as a number: a gate slower than 8 s, more than 1 MB of evidence per order, a cold start above 24,576 bytes. Nothing evaluated those numbers. Two consecutive entropy reviews found thresholds already crossed by measuring them by hand. The meter's one machine-readable predicate could never hold, because it named a metric the evaluator did not read, so the health line printed "0 reopen candidates" while it held. A review worker's temporary files also went to the system temporary directory, which its receipt never sees. Putting that root inside the frozen copy made product fixtures fail as nested checkouts. This pull request lands WO-175: a planning pass now opens with the count of named thresholds that hold, the meter prints a count it computed or says it has none, and a review's temporary files stay inside its episode.

- **`npm run plan -- conditions` lists the named numeric conditions.** A closed table of ten probes covers the plan check, the release table, evidence growth per order and per week, the console's source collection, a cold release list, `status --all --json` bytes, the work-order index, the document gate and its docs-check task. The meter's decision predicates are listed too. Each row shows its source decision or register row, how it is measured, the value, the threshold and whether it holds; an unmeasured row is `unknown` with the reason, never false. A last line counts the recorded conditions it does not evaluate. The command refuses nothing and is part of no gate. Timings are the median of three fresh runs, and the host's load average is printed beside them. The default listing took about 23 s on the operator's host. The two document-gate rows run only with `--slow`, which took 133 to 149 s in total.
- **`plan start` prints how many hold.** A block of about 230 bytes beside the failures block gives the holding and unknown counts and the command. If the count cannot be computed, the block says so and the branch still opens.
- **The meter's count is computed or absent.** Reading a decision whose metric predicate names a metric the meter cannot resolve fails with the decision's id and the metric. Each role's `coldStartBytes` (for example `coldStartBytes.executor`) and `sequenceBytes` resolve from the budget measurement. WO-150-D003 is now listed: the executor's cold start is 26,903 bytes against 24,576. A later decision that records `reopens` for a predicate removes it from the list. When a predicate cannot be observed, the health line says the count is unavailable instead of printing a number.
- **A review's temporary files stay in its episode.** Each launched review and refutation gets `TMPDIR` in a directory beside its frozen copy, inside the episode's scratch parent, and its instructions name that directory as the only other writable place. The receipt's confinement record and witness sentence give the directory's path count and bytes; receipts filed earlier render byte for byte as before. Filing repairs read-only directories before removing the scratch parent. If removal still fails, one line after the filed receipt names the leftover path, and the command exits 0.
