## Release overview

Application v0.97.0 gives the Entropy Reducer two subjects beyond the launchpad: a registered target repository at a recorded commit, and a workstream's distinct repositories reviewed one at a time. Before this release `entropy review` froze the launchpad and nothing else, so an instance could review its control plane and not the repositories where its product code lives; the frozen subject, the pinned reviewer, the blinded refutation, the immutable receipts and the operator's disposition into the register stopped there. On 2026-10-20 the operator asked for a way to run the reducer against a workstream's repositories with that same discipline, exported in the kit. This release adds `--repository ID [COMMIT]` and `--workstream WS-NNN` to `review` and `subject`, freezes the registered clone through the same path as the launchpad, binds the named commit to the reviewed tree in the recorded clone, names the repository and commit in receipts and candidate headings, and dispatches a workstream as a resumable sequence, with the launchpad's own receipts, hashes and historical records unchanged.

Audience: operators of a launchpad, core or an exported instance who open `planning: entropy reducer` passes; planners who read the register's candidate rows and allocate them; and maintainers of the entropy command, its library and the kit it ships in.

## Read before upgrading

- **Two selectors on `review` and `subject`.** `npm run entropy -- review --repository ID [COMMIT]` reviews a registered target; `review --workstream WS-NNN` reviews the next member of a workstream; the bare form and `review COMMIT` keep reviewing the launchpad. `subject` takes the same selectors and a positional commit, and the usage block prints all three forms. A repository together with a workstream, a workstream with a commit, or a flag without a value is refused with the usage text before anything is cloned.
- **A target subject is a named commit.** With no commit, the subject is the clone's already fetched base-branch tip for the registered `baseBranch`; the command never fetches, and an explicit commit resolves in that clone. Because the subject is a commit, the launchpad's dirty tree is recorded in the receipt's confinement block (`launchpad.workingTreeDirtyAtDispatch`, `trackedStatusByteIdentical`) rather than refused, and the clone's own tracked status and refs are the witnessed status and refs on either side of both episodes ([D002](../../evidence/WO-224/decisions.md#wo-224-d002--resolve-the-registered-clone-and-a-committed-subject), [D003](../../evidence/WO-224/decisions.md#wo-224-d003--keep-source-and-launchpad-witnesses-distinct)).
- **Where the clone is found.** The id must be registered in the launchpad configuration; its ignored clone mapping is read from the running checkout, then the primary checkout on any branch, then the main-branch worktree. A missing mapping refuses before any clone with a message naming that order; a mapping that moves between dispatch and filing refuses the filing; and the clone path stays in ignored pending state, never in a receipt ([D004](../../evidence/WO-224/decisions.md#wo-224-d004--refute-the-same-repository-and-commit)).
- **The frozen copy has no route home.** The copy is cloned without hard links or checkout, its `origin` removed, detached at the commit under the launchpad's scratch lane, with the clone's installed dependencies copied when present; a push from the copy fails. Lens scopes come from the copy's tracked paths, condensed to top-level directories with documentation one level deeper and intake excluded, so a target's compiled program names none of the launchpad's paths ([D013](../../evidence/WO-224/decisions.md#wo-224-d013--repair-the-independent-review-findings)).
- **Receipts and candidates name the subject.** Target and workstream receipts stay numbered and filed in the launchpad; their rendered subject names the repository, the commit and the frozen path, and the refutation keeps the same repository and commit. An accepted finding's candidate heading and bold title name `REVIEW-NNN ID@COMMIT`, so `npm run plan -- followups --sync` mints a row naming the target and `--apply` allocates it to any launchpad order, a workstream member included. The subject hash appends the registration id for targets only, so every existing launchpad hash is unchanged, and the historical receipts whose subject was an absolute path remain launchpad subjects for rendering, refutation, consumption and candidate text ([D005](../../evidence/WO-224/decisions.md#wo-224-d005--name-candidates-and-select-consumption-by-subject), [D016](../../evidence/WO-224/decisions.md#wo-224-d016--preserve-historical-launchpad-subject-semantics)).
- **A workstream is a sequence.** `review --workstream WS-NNN` reads the one `WS-NNN-*.md` under the configured `workstreams` root, validates its block and every member's registration before any copy, and dispatches the next distinct repository in membership order; `self` is the launchpad at its recorded HEAD. Each dispatch returns for `entropy receipt`, each receipt carries the workstream id, sequence and member set, one review stays pending per launchpad as today, and membership cannot change until the recorded member set is filed. `subject --workstream WS-NNN` names the pending dispatch, the receipt to refute, the survivors and packets left to dispose, the next member, or `complete`; a finished set never restarts itself, and an explicit later review starts the next numbered sequence ([D006](../../evidence/WO-224/decisions.md#wo-224-d006--make-a-workstream-a-resumable-sequence)).
- **`subject` is selective.** The selected forms keep returning a partially disposed receipt until every survivor and proposal packet has a disposition, and report recorded work (a pending dispatch, a consumable pair, a full recorded commit) even when the clone mapping is absent; the default form keeps its prior behavior and excludes target receipts from the launchpad's consumption.
- **Known issues.** A registered clone that was never fetched, or whose remote is not named `origin`, refuses `subject --repository` and `review --repository` before any copy with Git's bare `fatal: Needed a single revision` rather than a message naming the repository and the remedy ([D017](../../evidence/WO-224/decisions.md#wo-224-d017--name-the-missing-fetched-base-when-a-target-subject-cannot-resolve)); a target that tracks a top-level file named `docs` cannot be dispatched, because the unchanged compiled validator refuses that scope at compile time ([D018](../../evidence/WO-224/decisions.md#wo-224-d018--target-lens-scopes-must-be-ones-the-compiled-validator-accepts)); the frozen copy holds a fetched base that no local branch of the clone reaches only because a local-path clone copies the whole object store, so a partial clone of a target is untested. Every worker episode in the fixtures ran on the `fake` transport; the first live target review is the operator's dispatch, at about USD 5 to 9.50 and roughly 1,000 s per member repository, and nothing runs a review on a cadence.
- **Versions.** Application v0.97.0 is a minor release over v0.96.1, assigned at activation under the order's classification. No component version changes: compiler 0.31.0, skeleton 0.68.0, console 0.5.0, kernel 0.8.0, beacons 0.1.1 and browser-evidence 0.2.0 stay, the lockfile is unchanged and no dependency is added. No role text changed, and no evidence edition is re-minted.

## Substantive changes

**The command** (`scripts/entropy.mjs`). The usage block names the three forms of `review` and `subject`. A shared selector parser splits flags from the one admitted positional commit, refuses a repository with a workstream and a workstream with a commit, and passes the selection to `beginEntropyReview` and `entropySubject`.

**The library** (`scripts/lib/entropy-review.mjs`). `freezeSubject` takes the repository to clone, the launchpad passing itself and the target form the recorded clone. `subjectSource` checks the registration, reads the clone mapping in the running, primary and main-checkout order, requires a physical Git top level and returns the clone with its default revision; `resolveSubject` resolves the revision there with `--end-of-options`. `subjectRecord` carries the registration id and hashes it for targets only. `beginEntropyReview` and `beginEntropyRefutation` freeze the selected source, pass target-fit lens briefs from the frozen copy's census through the loadout's existing option, record the clone path and the launchpad's status in ignored pending state, and carry the workstream record; `fileEntropyReview` and `fileEntropyRefutation` re-resolve the mapping, refuse a moved one, bind the named commit to the reviewed tree in the clone, witness the clone's refs and tracked status and add the separate launchpad witness. Receipts are classified as target receipts by that witness. `candidateHeading` and `appendCandidate` name the review and the subject for target and workstream receipts. `workstreamRepositories` reads the one workstream document under the configured root, validates the block and every registration, and deduplicates members in order; `workstreamSequence` reads the filed receipts to find the next member, refuses a membership change mid-sequence and numbers a restart. `unconsumedReview` and `entropySubject` take the selection, report pending work before resolving any clone, select a full recorded commit from the receipts directly, keep a partially disposed selected receipt consumable, and name the next action and command.

**Tests.** `scripts/test-entropy-review.mjs` gains a registered fixture target with a local bare origin and a fixture workstream, and seven cases: the registered subject through review and refutation with both witnesses and the push attempts; target lenses after many documentation files; target filing that binds the original clone and tree while concurrent drift is recorded; a workstream of duplicate and distinct members under a configured root, with partial dispositions and an allocation to a member order; `self` after a target receipt and the invalid selectors that allocate no copy; clone lookup across the running, primary and main maps with the missing-mapping refusal; and a synthetic historical absolute-path receipt kept as a launchpad subject. The exported-instance case in `scripts/test-launchpad-planning.mjs` registers a target in the kit, selects it, runs a fake review, files the receipt and checks the chain through the exported runtime.
