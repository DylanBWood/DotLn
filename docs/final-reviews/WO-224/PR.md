# WO-224

The Entropy Reducer now reviews a registered target repository, or each repository of a workstream, with the discipline the launchpad review already had. `npm run entropy -- review --repository ID [COMMIT]` freezes the registered clone at the named commit, or at the clone's already fetched base-branch tip when none is named, through the same freeze path as the launchpad: a copy with no remote under the launchpad's scratch lane, detached at the commit, with the dependency copy when the clone has one. The pinned reviewer runs the compiled program over that copy with lens briefs drawn from the copy's own tracked paths rather than the launchpad's layout; the host revalidates the return; the receipt is numbered, filed and bound in the launchpad as today, its subject naming the repository, the commit and the frozen path, with the registration id in the subject record and its hash. `refute` re-freezes the same repository at the same commit; both filings bind the commit to the reviewed tree in the recorded clone, witness the clone's refs and tracked status on either side, and record the launchpad's own tracked status rather than refusing it. `dispose … accept` writes the candidate under a heading, and a bold title, naming the review and `ID@COMMIT`, so the register's row names the target and a planning pass can allocate it to any launchpad order, a workstream member included. `review --workstream WS-NNN` reads the workstream document's membership block under the configured `workstreams` root, validates every member's registration before any copy is made, and dispatches the distinct repositories one at a time, each receipt filed by `entropy receipt` with the workstream id, sequence and member set; `subject --workstream WS-NNN` names the next member, the pending dispatch, the receipt to refute or consume, or `complete`. The exported kit carries both forms, and the launchpad's own receipts, hashes and historical records are unchanged.

Why it matters: until now an instance could review its launchpad and not the repositories where its product code lives, so the frozen subject, the pinned reviewer, the blinded refutation, the immutable receipts and the operator's disposition into the register stopped at the control plane. The operator asked on 2026-10-20 for a way to run the reducer against a workstream's repositories with that same discipline, exported in the kit, and no order or register row planned it; this order is that capability ([the order](../../work-orders/WO-224-entropy-reducer-on-a-registered-target.md), [D002](../../evidence/WO-224/decisions.md#wo-224-d002--resolve-the-registered-clone-and-a-committed-subject), [D006](../../evidence/WO-224/decisions.md#wo-224-d006--make-a-workstream-a-resumable-sequence)).

What a reviewer should weigh. A target subject is always a named commit, so the explicit-commit route is its route: the launchpad's dirty tree is recorded, never refused, and the clone's own drift is the witnessed drift ([D003](../../evidence/WO-224/decisions.md#wo-224-d003--keep-source-and-launchpad-witnesses-distinct)). The default subject is the clone's fetched base-branch tip and the command never fetches; the clone is found in the running checkout's ignored map, then the primary checkout's, then the main-branch worktree's, and a mapping that moves between dispatch and filing refuses the filing ([D002](../../evidence/WO-224/decisions.md#wo-224-d002--resolve-the-registered-clone-and-a-committed-subject), [D004](../../evidence/WO-224/decisions.md#wo-224-d004--refute-the-same-repository-and-commit)). The subject hash appends the registration id for targets only, so every existing launchpad hash is unchanged, and a receipt counts as a target receipt by its separate launchpad witness rather than by a repository value other than `.`; that rule keeps the historical receipts whose subject was an absolute path as launchpad subjects for rendering, refutation, consumption and candidate text, a defect the document gate found and the executor fixed with a synthetic regression ([D016](../../evidence/WO-224/decisions.md#wo-224-d016--preserve-historical-launchpad-subject-semantics)). Lens scopes come from the frozen copy's census condensed to top-level directories, documentation one level deeper, intake excluded and nothing truncated ([D013](../../evidence/WO-224/decisions.md#wo-224-d013--repair-the-independent-review-findings)). A workstream is a resumable sequence of dispatches: one pending review per launchpad as today, membership frozen until the sequence completes, `self` for the launchpad at a named HEAD, and an explicit later review starting the next sequence ([D006](../../evidence/WO-224/decisions.md#wo-224-d006--make-a-workstream-a-resumable-sequence)). Two low-severity follow-ups from verification stay boarded with repair rules: a registered clone that was never fetched refuses with Git's bare message rather than one naming the repository and the remedy ([D017](../../evidence/WO-224/decisions.md#wo-224-d017--name-the-missing-fetched-base-when-a-target-subject-cannot-resolve)), and a target that tracks a top-level file named `docs` cannot be dispatched because the unchanged compiled validator refuses that scope ([D018](../../evidence/WO-224/decisions.md#wo-224-d018--target-lens-scopes-must-be-ones-the-compiled-validator-accepts)). The protocol and the loadout are unchanged, so no evidence edition is re-minted and no live feedback episode is owed ([D009](../../evidence/WO-224/decisions.md#wo-224-d009--preserve-compiled-source-and-evidence-editions)).

Validation: the executor's complete review passed 37 suites and 103 fresh tasks at code identity `d79b29bb685f09198299c42bab18ca42aaf718ed78956ce1b27e13bc1dcedbee` after two failed complete attempts and one document-gate failure, each repaired on the record ([handoff](../../evidence/WO-224/handoff.md), [D014](../../evidence/WO-224/decisions.md#wo-224-d014--resolve-lens-boundary-paths-through-the-configuration-owner), [D015](../../evidence/WO-224/decisions.md#wo-224-d015--repair-fixture-inputs-and-rerun-the-complete-gate), [D016](../../evidence/WO-224/decisions.md#wo-224-d016--preserve-historical-launchpad-subject-semantics)); two independent Codex workers found four defects in the frozen diff, each fixed with a regression ([self-review](../../evidence/WO-224/self-review.md)). [VER-001](../../verifications/WO-224/VER-001.md) passed all seven criteria and ran eight probes of its own, among them the compiled program's text rather than its lens inputs, a fetched base ahead of the local branch, an origin that moves between review and refutation, the committed receipt chain and workstream block read-only, an unfetched clone and a target tracking a top-level `docs` file; the last two became the boarded follow-ups. [FINAL-001](FINAL-001.md) integrated `main` and took in nothing, read the whole diff, reran the 33 entropy fixtures and the receipt-chain check at the integrated tree with the affected checks, probed the freeze mechanism, and passed with no finding of its own.

Limits a reviewer should weigh: every worker episode ran on the `fake` transport, so this proves selection, confinement, binding, disposition and kit carriage and not the quality of a live target review, whose first run is the operator's `planning: entropy reducer` dispatch at about USD 5 to 9.50 and roughly 1,000 s per member repository; a remote not named `origin`, or a clone never fetched, refuses with Git's bare message; a target tracking a top-level `docs` file cannot be dispatched; the frozen copy holds a fetched base that no local branch of the clone reaches only because a local-path clone copies the whole object store, so a partial clone of a target is untested; and nothing here runs a review on a cadence.
