# Reviewed suites run inside a replica of their declared inputs, so no undeclared file can change a run

Six suite scopes and the release cases have reused executed successes since WO-126 on the strength of a human read inventory: nothing stopped a scoped suite from reading a file outside its scope, and a suite that checks whether an optional file exists before reading it could not be validated by any finite set of probes — the planning pass held that criterion twice, at receipts 009 and 010. Validation is now replaced by construction. Each fresh narrowed execution runs in a replica containing exactly its declared candidate paths, with `node_modules`, each `packages/*/dist` and `.runtime/harness` linked to one verified read-only copy per gate, under a nonce-named parent the suite cannot list, in scratch outside the checkout. The suite's working directory, arguments and projected environment carry no path into the candidate tree, or the run is not narrowed. Whatever guard precedes the read — an existence check, a regular-file check, a declared flag that selects it — the undeclared file is simply not there.

The fixtures drive all four read forms against four candidate-tree states of the same undeclared file (absent, present, present as a directory, changed). The three guarded forms produce the same outcome and one identical key in all twelve runs; flipping the declared flag changes the key while the fresh replica still reports the file absent; the unconditional read passes in the candidate tree and then fails the gate with `Replica suite kernel failed; first unreadable path: … undeclared.txt. No candidate-tree fallback.` There is no retry path: a replica failure is a declaration defect or a real defect, and the gate says which it could tell. A declared symlink whose target leaves the replica, an argument or an environment value carrying the checkout path, and an incomplete toolchain observation each refuse narrowing before any cache lookup.

Because a narrowed suite's key is now its declaration rather than the whole tree, the package suites stop re-executing for source they never read. On the operator's host a fresh full gate passed all 37 aggregate suites and 78 tasks in 798 s, 47 of them in replicas, using one verified copy of 50,685,411 bytes in 1,099 files built in 240 ms with 22.7 s of per-replica setup; adding a single comment-only file under `scripts/` then composed `npm test` in 52 s with `kernel`, `compiler` and `skeleton` reused at unchanged keys, retaining 200 s of package execution, and removing only that file restored the exact tree hash. Full and fast gates have different inventories, so those durations are not a speedup ratio. A refused narrowing is neither silent nor unkeyed: it runs in the candidate tree under the whole-tree contract these scopes had before, names the refusal on the task row and in the fresh explanation, and can never share a key with a replica run.

VER-001 failed the order in a Claude Code session whose shell exports a harness-injected Git configuration family for its own checkouts. The replica projection refused to narrow on it, and a refusal left every declared suite with no key at all, so fourteen fixture cases collapsed and the canonical gate the next role must run was red. That family is now treated as invocation metadata and dropped from execution and key alike, as rotating proxy variables already were; replica children carry `GIT_CEILING_DIRECTORIES` at their unlistable parent; and every fixture asserts replica creation, naming the refusal, before using one. VER-002 and VER-003 then failed the operator-directed dispatch expansion twice, and both repairs are in this branch.

The operator's `resume:` phrase now records its own dispatch. In Claude Code the generated session hook runs the matching lifecycle command when the canonical status lists it, delivers that command's briefing before any procedure loads, and prints a one-line terminal receipt naming the recorded command, work order, role and equipped supports; a phrase whose dispatch is already recorded receives the same briefing from the new read-only `npm run resume -- briefing` projection, so a session that resumes a recorded repair, verification or review starts where the recording session did; an illegal phrase is refused with the lifecycle's legal actions. The dispatch is admitted exactly as the ordinary `npm run resume -- <action>` command it replaces — the same active-gate refusal and the same compiled writer-isolation unit judge it first, so a live gate or another session's live reservation refuses it before any event, checkpoint or projection changes, and `next` stays the metadata command it is on the tool path.

The format gate now covers code only: `*.md`, `*.json` and `*.jsonl` are no longer formatter input, and authored prose, data records and event logs keep the bytes their authors and generators wrote. Prettier still checks 122 `.mjs` and 120 `.ts` files. No generator, check or fixture reads `.prettierignore`.

Application target `v0.17.5` (patch) above local `v0.17.4`; skeleton `0.15.4` through `0.15.8`; compiler `0.9.1`, kernel and console unchanged; no new dependency. The suite declaration version and the replica mechanism version both advance to 2, so every inventoried suite executes once more after this lands; the success record format, the exact-tree aggregate and the lifecycle evidence contract are unchanged.

Four independent verifications: [VER-001](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-001.md) failed on the injected Git configuration, [VER-002](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-002.md) on the new dispatch bypassing writer ownership and the active-gate guard, [VER-003](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-003.md) on a resumed session losing its briefing, and [VER-004](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-004.md) passed all seven criteria. [FINAL-001](https://github.com/DylanBWood/DotLn/blob/main/docs/final-reviews/WO-130/FINAL-001.md) records the review: all 26 suite-evidence cases and the three dispatch and composition fixtures reproduced in the same Claude Code environment VER-001 failed in, with nothing removed from it; three direct key probes against the real repository showing the six scopes narrowing with no environment leak, a `scripts/` change leaving the package suites reused while a declared change re-executes them, and zero of nine successes reusable across roles; and an audit of the retained host measurement. [Decisions D001–D015](https://github.com/DylanBWood/DotLn/blob/main/docs/evidence/WO-130/decisions.md) carry the sources, rejected alternatives and reopening conditions. Known limits: a declared suite that hard-codes an absolute checkout path in its own source can still read it — receipt 011's hold, kept as a known issue by operator direction 2026-09-12 with review of narrowed suites as its control until WO-131's kernel denial where a host permits it; per-session environment values still prevent one role from reusing another's successes, so every independent role pays a full fresh gate; the three fixture scopes declare `packages/` and `scripts/`, so they gain little reuse; and the dispatch receipt names no supports for the verifier and reviewer roles, whose briefings do not enumerate them.
