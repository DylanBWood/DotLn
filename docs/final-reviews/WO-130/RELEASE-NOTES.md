## Release overview

A suite that declares its inputs now runs inside a replica containing exactly those inputs, so a file it never declared cannot change what it does — not when it reads that file unconditionally, and not when it checks first whether the file exists, whether it is a regular file, or whether a declared flag selects the read. In every one of those runs the file is not there. The same declaration is the suite's reuse key, so the package suites stop re-executing for source they never read: on the operator's host, adding one comment-only file under `scripts/` left `kernel`, `compiler` and `skeleton` reused at unchanged keys and retained 200 seconds of package execution. This release is for anyone who runs the repository's gate or reads its evidence, and for anyone who has wondered whether a scoped suite's reuse was sound rather than merely reviewed.

## Read before upgrading

Every inventoried suite executes once more after this release. The suite declaration version advances to 2 and the replica mechanism version to 2, both of which participate in every key, so no success recorded before this change can match. The success record format stays at version 3, the exact-tree aggregate is unchanged, and nothing is migrated or discarded.

A harness session's injected Git configuration — `GIT_CONFIG_COUNT`, `GIT_CONFIG_KEY_*`, `GIT_CONFIG_VALUE_*` and `GIT_CONFIG_PARAMETERS` — is now treated as invocation metadata and is absent from every suite's execution and from every key, exactly as rotating proxy variables already were. If a gate child on some host genuinely needs such a value — a `safe.directory` entry for a checkout owned by another user, for example — it will no longer receive it. On this host both checkouts are owned by the same user, so the dropped entries are inert. Replica children also carry `GIT_CONFIG_NOSYSTEM` and a `GIT_CEILING_DIRECTORIES` entry at the replica's unlistable parent.

The operator's `resume:` phrase now records its own dispatch in Claude Code. The generated session hook runs the matching lifecycle command when the canonical status lists it among the legal next actions, delivers that command's briefing before any procedure loads, and prints a one-line terminal receipt naming the recorded command, work order, role and equipped supports. A phrase whose dispatch is already recorded receives the same briefing through the new read-only `npm run resume -- briefing` command and changes no lifecycle byte; a phrase that is not legal in the current phase is refused with the lifecycle's legal actions. The dispatch is admitted exactly as the ordinary command it replaces, so a live evidence gate or another session's live reservation refuses it before anything changes, and an admitted dispatch holds the writer reservation the session's first write would take. Codex sessions still run these commands themselves, including the read-only briefing when they resume.

The format gate covers code only. `*.md`, `*.json` and `*.jsonl` are no longer formatter input, so authored prose, data records, event logs and generated JSON keep the bytes their authors and generators wrote. Prettier still checks the repository's 122 `.mjs` and 120 `.ts` files, and no generator, check or fixture reads `.prettierignore`.

`.runtime/harness` joins `node_modules` and each `packages/*/dist` as an installed input: it is copied into the per-gate replica mount, keyed as an execution input, and protected from agent writes while a gate runs. The scheduler's peer file and deadline log move from `docs/control/local/harness/deadlines/` into per-gate scratch outside the checkout and are removed with it, so a deadline hit survives as the parsed rows retained in the gate record rather than as a local transcript. Gate rows gain `replicaSetup` on the aggregate and `executionRoot` plus `narrowingRefusal` on task rows; existing readers are unaffected.

Application target `v0.17.5` (patch) above local `v0.17.4`; skeleton `0.15.4` through `0.15.8`; compiler `0.9.1`, kernel and console unchanged; no new dependency.

## Substantive changes

**Replica execution for the reviewed scopes.** `kernel`, `compiler`, `skeleton`, `worktree`, `plan-refutation:fixtures`, `process-debt`, release-template preparation and all 40 release cases execute in replicas. Each fresh narrowed run copies its declared candidate files with their modes into a nonce-named directory whose parent the suite cannot list, recreates a declared symlink only when its target stays inside the replica, and links the installed roots to one read-only copy per gate whose every file is verified against the observation before the copy is sealed. A declaration chooses `git: none` or a deterministic `replica-repo` initialized from the declared files alone under a fixed identity and timestamp; candidate history and local Git metadata never appear. The suite's working directory, arguments and projected environment carry no path into the checkout, `PATH` entries inside the checkout are rebound to their replica counterparts, npm's cwd-derived local prefix follows the replica, and each suite gets its own temporary root.

**Declarations as the suite's world, and as its key.** A narrowed suite's key is its declaration, the declared paths' bytes, types and listings, the installed roots, the toolchain, the host configuration its own `git` and `npm` children still read, the command and the replica mechanism version. A change under `scripts/` that no package declaration names leaves those three suites reused; a change to a declared path, its mode, its name, or to the suite's command re-executes them, and the fresh explanation names the changed paths.

**Refusals are named and keyed, never silent.** An escaping declared symlink, an argument or projected environment value carrying the checkout path, an unsupported installed link, an unmodelled startup adapter and an incomplete toolchain observation each refuse narrowing before any cache lookup. A refused task then runs in the candidate tree under the whole-tree contract these scopes had before this change, with the refusal named on its recorded row and in its fresh explanation, and its key can never coincide with a replica key because the declaration digest names the execution root.

**A replica failure fails the gate.** A narrowed suite that fails in its replica fails the gate with the suite named and the first missing-path diagnostic its own output reported, and there is no retry in the candidate tree — a suite that passes there still fails here. Per-suite cleanup tolerates only an already-absent owned entry; any other cleanup fault becomes failed evidence for that suite without tearing down its active peers, and the gate finishes its owned cleanup before publishing success or caching any result.

**Dispatch recording, admission and resumed briefings.** Described under "Read before upgrading"; the mechanism is a phrase table in the generated session hook, the equivalent Bash invocation it models, the same compiled writer-isolation unit the writer hook carries — bound to the emitted bundle through the manifest's recorded policy hash, so a drifted inventory cannot admit — and the shared lifecycle briefing builders behind both the recorded and resumed paths.

## Progressive polish

Skeleton and host-version bumps across four repairs; the regenerated hook bundle, manifest and pinned runtime snapshot with four immutable authority editions; the README release claim, the publication source lock, the decisions index rows D001 to D015, the follow-up register and the work-order index; the beacon destination test given its own synthetic repository instead of relying on an ambient ignored intake directory; the gate-deadline load-policy fixture moved onto a whole-tree scope with a non-null baseline assertion; and the harness runtime snapshot copied by value so an installed root that is a replica mount cannot become an external link.

## Evidence and compatibility

Four independent verifications preceded this release: [VER-001](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-001.md) failed criterion 7 because the injected Git configuration refused narrowing and left every declared suite unkeyed, with one non-blocking finding and seven observations; [VER-002](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-002.md) failed because the new prompt dispatch bypassed writer ownership and the active-gate guard; [VER-003](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-003.md) failed because a session resuming a recorded repair received neither its support list nor its opening-intent instruction; [VER-004](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-130/VER-004.md) passed all seven criteria. [FINAL-001](https://github.com/DylanBWood/DotLn/blob/main/docs/final-reviews/WO-130/FINAL-001.md) records the review and its independent checks, and [decisions D001 to D015](https://github.com/DylanBWood/DotLn/blob/main/docs/evidence/WO-130/decisions.md) record every source, rejected alternative and reopening condition, including four same-day corrections. The [execution evidence](https://github.com/DylanBWood/DotLn/blob/main/docs/evidence/WO-130/README.md), [host measurement rows](https://github.com/DylanBWood/DotLn/blob/main/docs/evidence/WO-130/replica-measurements.json) and [fixture transcript](https://github.com/DylanBWood/DotLn/blob/main/docs/evidence/WO-130/fixture-transcript.txt) carry the numbers.

Known limitations. A declared suite that hard-codes an absolute checkout path in its own source can still read it: the replica confines every access made through the working directory, relative paths and the projected environment, but not a path the runner never supplied. That is planning receipt 011's hold, kept as a known issue by operator direction on 2026-09-12, with review of the narrowed suites as its control until WO-131 adds a kernel denial where a host permits one; it reopens if a narrowed suite is observed reading the checkout that way, or if a fresh run contradicts a reused success at the same key. Per-session environment values still prevent one role from reusing another's successes, so each independent role pays a full fresh gate; per-suite environment declarations are proposed as the next step. The three fixture scopes declare `packages/`, `scripts/` and the root configuration files, so they gain little reuse from this change. The shared success cache still has no pruning. The dispatch receipt names no equipped supports for the verifier and reviewer roles, whose briefings do not enumerate them. Declared directory modes are keyed but replicas build directories with the process umask, which can force an unnecessary re-execution and never an unsound reuse. The supported Node line, package privacy and every publication control are unchanged.
