# WO-202

An instance exported by `launchpad export` can now run the planning commands core runs, on its own records. Until this change an instance depended on core for its planning: in a fresh export, ten of the 29 commands a planning pass and a release close use failed on inputs only core has (its follow-up register, document ceilings, publication editions, reader scores, vision, roles, capability table and critical path), and no planning pass, refutation, entropy review or document gate had ever run inside an export. Now the export seeds five instance-owned files once, the scripts name an absent core input instead of failing on it, and inside a fixture export all 31 commands of the list exit 0: `plan start` creates a planning branch, `plan refute` prints a prompt built from the instance's own sequence and pre-drafted order, `plan receipt` files a result and `plan check` passes, `entropy -- subject` names no review and a `fake`-transport review files its receipt under the instance's roots, and the reads a release close performs run or report unavailable by name.

**What the export now seeds.** Beside the sequence seed, `prepareKit` writes `docs/planning/followups.json` (an empty schema-1 register), `docs/control/doc-ceilings.json` (no documents), `docs/control/doc-baseline.json` (an empty editorial baseline), `docs/control/budgets.json` (the kit defaults from the new template `scripts/kit/budgets.template.json`, no acceptances) and `docs/lineage/idea-ledger.md` (the header and status vocabulary). Each is written once, never manifest-listed, and left alone by an update: the WO-078 update case overwrites all five with sentinels and asserts the bytes survive, and the WO-074 case asserts none is a manifest path. Core's register, ceilings, ledger, editions and score history are not copied ([D003](../../evidence/WO-202/decisions.md#wo-202-d003)).

**What names an absent input.** In a committed kit the planning subject reads the vision, the roles table, the capability table and the critical path only when present, lists the absent ones under `standard.unavailable`, and hashes that absence into the subject; core's own subject keeps its shape and its historical receipt hashes ([D002](../../evidence/WO-202/decisions.md#wo-202-d002)). `plan conditions` in a kit skips the condition table's core-source validation and reports a row whose sources are absent as unknown, naming them; its `collect-sources` row names the uncarried console package. `publication:check` with neither edition file prints `publication: no editions declared` and exits 0, while one missing edition still fails. `reader -- check` with no profiles, examples or score rows passes naming the three; a recorded score whose tag object is absent fails with its release, the object id and the restoring `git fetch --tags origin` instead of a raw Git error, and recovers after the fetch; a malformed score entry gets a contextual error and appends nothing ([D004](../../evidence/WO-202/decisions.md#wo-202-d004)). In a kit, `docs-check` judges instance-authored product documents and links and leaves manifest-listed carried guides with their upstream history; `lineage index` admits a header-only ledger and links only the lineage sources present; the work-order index links the seeded sequence when no planning map exists; `release check-surfaces --local` in a kit with no order prints that release surfaces are unavailable; and `resume status` no longer warns that an absent projection disagrees with an empty fold. Six suites leave the kit's core-only table (`publication`, `docs-check`, `lineage`, `plan`, `plan-refutation-current`, `reader-profiles`), so the kit's `npm run test:docs` now runs 17 suites.

**The fixture and the client README.** `scripts/test-launchpad-planning.mjs` exports a kit, commits it, installs offline and runs the whole list with `spawnSync`, recording each command's exit code, duration, output head and the input paths its output names; it ran first as the probe at the base ([`commands.json`](../../evidence/WO-202/commands.json), 29 rows, 12 nonzero) and now asserts the final table ([`commands-final.json`](../../evidence/WO-202/commands-final.json), 31 rows, all 0), plus negatives for a malformed declared vision, a symlinked one, a broken instance link and a partial edition declaration. The README's new §Planning in this instance names the commands a planning pass runs here in order, the seeds they read, the rows that report unavailable, and that the installed planner skill dispatches the refutation worker; its `test:docs` list is asserted against the kit's observed selection. The final review replaced the two older sentences that still called instance planning pending ([D015](../../evidence/WO-202/decisions.md#wo-202-d015--final-review-fix-ver-001s-f1-in-the-client-readme-inside-the-declared-surface)); the remaining limits are named as limits.
