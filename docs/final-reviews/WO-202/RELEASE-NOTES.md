## Release overview

Application v0.78.0 lets an exported instance run its own planning pass. Until now an instance depended on core for its planning: in a fresh export, ten of the commands a planning pass and a release close use failed on inputs only core has, and no planning pass, refutation, entropy review or document gate had ever run inside an export. In this release the export seeds five instance-owned records once, the planning scripts name an absent core input instead of failing on it, and inside a fixture export every command of the list exits 0 or prints its unavailable row by name. It serves the operator of an exported instance, who now opens the instance's first planning pass on its own records, and the contributors who add a planning input to core, who now decide whether an instance seeds it or reports it absent.

The visible changes:
- `launchpad export` writes `docs/planning/followups.json`, `docs/control/doc-ceilings.json`, `docs/control/doc-baseline.json`, `docs/control/budgets.json` and `docs/lineage/idea-ledger.md` beside the sequence seed, once, outside the manifest, and an update leaves their bytes alone.
- In a committed kit, `plan start`, `plan refute`, `plan receipt`, `plan check`, `meta -- --plan-cost` and `plan conditions` run with the instance's vision, roles, capability table, critical path and core condition sources named as unavailable where absent; the prompt is built from the instance's own sequence and orders.
- `publication:check` with no edition files passes stating none is declared; `reader -- check` with no profiles, examples or score rows passes naming them, and a recorded score whose tag object is absent names its release, the object and the restoring fetch instead of a raw Git error.
- In a kit, `docs-check`, `lineage index`, the work-order index, `release check-surfaces --local` and `resume status` run on the instance's own records; six suites leave the kit's core-only table and the kit's `npm run test:docs` runs 17 suites.
- The client README's new §Planning in this instance names the commands a planning pass runs, the seeds they read, the rows that report unavailable and how the refutation worker is dispatched; the older sentences that called instance planning pending are gone.

## Read before upgrading

- **No operator action and no component change.** No package version, dependency or lockfile moves. Core's own planning subject keeps its shape and its historical receipt hashes; core's checks keep validating the inputs it declares.
- **Existing exports take the seeds through `launchpad export --update`.** The update writes a seed the instance does not yet have and leaves one it has alone; a fresh instance runs `npm run meta` and `node scripts/lineage.mjs index` after activation so its indexes exist before its first gate, as the README's first steps say.
- **The publication early exit applies in any checkout.** A core clone with both edition files deleted now exits 0 with `publication: no editions declared` where it exited 1 with an uncaught error, and a kit holding only the audience index passes unchecked; one missing edition still fails. The repair rule, pass only when no publication declaration exists, is boarded ([D011](../../evidence/WO-202/decisions.md#wo-202-d011--verification-board-publicationchecks-absence-rule-which-does-not-distinguish-an-undeclared-instance-from-a-core-checkout-missing-its-editions), FUP-acdc329e47638889).
- **The release-surface read holds only in a fresh instance.** Once an order carries a version, `release check-surfaces --local` in an export fails on `docs/LEGAL.md` pins, which the kit neither seeds nor reports unavailable. The first real instance release close (WO-083) depends on the repair ([D010](../../evidence/WO-202/decisions.md#wo-202-d010--verification-board-the-release-surface-read-which-fails-on-docslegalmd-once-an-instance-order-exists), FUP-a065bc5b99e40660).
- **An instance's refutation still reads core's goal standard.** The subject reports the instance's critical path unavailable yet takes its goal standard from the carried product 07 §Goal-aligned decisions, which states core's purpose and targets ([D012](../../evidence/WO-202/decisions.md#wo-202-d012--verification-board-the-instance-refutations-goal-standard-which-carries-cores-purpose-and-critical-path-targets), FUP-3cceac0fff2dba94).
- **A missing score row passes in core, before and after this release.** Planning receipt 044's criterion 4 condition occurred through that branch with `main`'s scripts as well; the next planning pass decides whether the reader check should know which releases must carry rows ([D013](../../evidence/WO-202/decisions.md#wo-202-d013--verification-planning-receipt-044s-criterion4-reopening-condition-for-wo-202-has-occurred-through-its-score-row-branch-independently-of-this-order), FUP-9bf47c37df1cc049).
- **Live transports and a publishing release close are not exercised.** The fixture runs the entropy review with `--transport fake` only and records the reads a release close performs; the operator's first instance pass records what the fixture cannot.
- **The `launchpad` gate task stays large.** It read 323.6 s fresh in the executor's second full review, above twice its pre-WO-201 reading; the watch rows FUP-b531e850b70f6d4e and FUP-e96221b106cd136a stay open for planning. The new `launchpad-planning` task is a separate row at about 33 to 43 s.
- **A `skeleton` readiness case is intermittent under load.** The built-CLI supervisor signal case failed in two of three fresh full reviews of this subject and passed in isolation each time; no runtime source changed in this release and no timer or assertion was relaxed. Its cause is unknown and its register row is open for planning ([D008](../../evidence/WO-202/decisions.md#wo-202-d008), [D017](../../evidence/WO-202/decisions.md#wo-202-d017--final-review-d008s-readiness-failure-recurred-in-the-fresh-review-gate-rerun-composed-d008-reopened), FUP-3b39865f91df30a7).
- **Versions.** Application v0.78.0 is a minor release over v0.77.0, assigned at activation under the order's classification. No component version changes and no dependency is added.

## Substantive changes

**Seeds and the template** (`scripts/launchpad.mjs`, `scripts/kit/budgets.template.json`). `prepareKit` adds five `addSeed` calls beside the sequence seed: an empty schema-1 register, a ceilings file with no documents, an empty editorial baseline, the budgets from the new manifest-listed template (kit defaults, no acceptances, `unsetPolicy` stated) and a ledger header carrying the status vocabulary. The WO-074 case lists the five among the expected seeds and the update case asserts their bytes survive an update.

**The planning subject and conditions** (`scripts/lib/plan-subject.mjs`, `scripts/lib/planning-conditions.mjs`, `scripts/meta.mjs`). When `KIT-MANIFEST.json` is committed, the three standard paths (vision, roles, capability table) and the critical path are read only when present; absent ones enter `standard.unavailable` and the subject's hashed parts as `unavailable` entries, so a declared file that is malformed or a symlink still refuses. In a kit the condition table's core-source validation is skipped and a row whose sources are absent is unknown, naming them. `meta -- --plan-cost` prints each unavailable input.

**Publication, reader and document checks** (`scripts/check-publication.mjs`, `scripts/lib/reader-profiles.mjs`, `scripts/reader.mjs`, `scripts/docs-check.mjs`, `scripts/lineage.mjs`, `scripts/work-orders.mjs`). The publication check exits 0 naming no editions when neither edition file exists. `readPublication` tests the recorded object with `cat-file -t` first and refuses an absent object with the release, the object id and `git fetch --tags origin`, and a present non-tag object with its own error; `recordScores` checks each release row and each answer as an object before use. `reader check` with no profiles, examples or scores passes naming them. In a kit, `checkDocs` excludes manifest-listed files from the ceilings and the link failures and the seeded product README from the ceilings. `inspectLedger` admits a header-only ledger and `renderIndex` links only the lineage sources present. The work-order index links the seeded sequence when no planning map exists.

**Release and control reads** (`scripts/release.mjs`, `scripts/resume.mjs`). `check-surfaces --local` in a kit with no order prints that release surfaces are unavailable in a fresh instance. `warnIfProjectionDisagrees` treats a missing projection over an empty order map as agreement.

**The runner and the fixtures** (`scripts/test-runner.mjs`, `scripts/test-launchpad-planning.mjs`, `scripts/test-launchpad.mjs`, `scripts/test-reader.mjs`, `scripts/test-runner.test.mjs`). A `launchpad-planning` row, core-only in a kit, with 25 declared machinery sources; six `kit` declarations removed. The new suite exports a kit into a bounded temporary directory, installs offline and runs the 31 commands, printing its rows and asserting the branch, the prompt, the receipts, the conditions row and the negatives. The launchpad fixture's seed list and update case cover the five seeds, its WO-201 case generates the lineage index, and the unavailable-selection cases name `release-surfaces` in place of `publication`. Three reader cases cover no records, the absent tag with its recovery, and malformed entries.

**Documents.** The client README gains §Planning in this instance and loses its two pending-planning sentences; product 07 §Operator-opened planning pass and product 12 §One workstream across repositories cite the fixture evidence in place.

- An instance's refutation goal standard carries core's purpose and critical-path targets.
- A launchpad separate from its scripts checkout and relocated document roots are not qualified (FUP-cb5c3b3e7d0b0c0d).
- No live refutation or entropy transport and no publishing release close ran in the fixture.
- One `skeleton` readiness case fails intermittently under load; its cause is unknown.
