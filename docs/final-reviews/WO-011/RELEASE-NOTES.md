## Release overview

DotLn `v0.13.0` is the minor release above the published `v0.12.0`. It compiles ten recurring operator corrections, taken from this repository's own lineage rather than any external rule stack, into executable feedback checks, and it takes the first bounded self-hosted step. Each unit is a complete FeedbackUnit with incident provenance, undesired and desired observable behavior, scope, trigger, mechanism with its rationale, enforcement, required evidence, regression fixtures, conflicts, supersession, retirement and next-maturity conditions, lowered to the cheapest sufficient rung of the mechanism hierarchy: scripts for attribution and suppression diffs, pre-effect guards for decision lineage, writer isolation and cleanup scope, a pure reactor branch for semantic correction, an evaluator for evidence judgments, and workflow gates for application evidence, output reads and complete scope. No unit lowers to prose. Every fixture fails by assertion when only its mechanism is removed, the matched instruction projection saves 2,393 bytes against the WO-004 startup-context baseline, and `dotln feedback-audit` runs one read-only work order on this repository through the kernel's decider, authority and durable outbox, executes the twenty fixture subprocesses, and hands the pinned source and evidence to a separate blinded verifier episode over the WO-009 transports. The retained live run used Claude Code and completed on its second attempt after a refused first return. Audience: operators who want corrections to bind as mechanisms rather than as prompt text, and engineers extending the feedback contract. Everything enforced here applies at equipped host boundaries; ordinary `resume` sessions still follow the execution guide.

## Read before upgrading

- **`@dotln/skeleton` gains one external runtime dependency.** The already pinned TypeScript `5.4.5` package moves from development-only to a skeleton runtime dependency, loaded on demand only for the source-comment suppression check and refused on version drift. `@dotln/kernel` and `@dotln/compiler` keep zero runtime dependencies. ADR-0002's Amendments and `docs/LEGAL.md` record the change.
- **The shared reactor gains a feedback branch that takes precedence.** A `RuntimeState` whose optional `feedback` field is set, or a `FeedbackAuditOpened` event, is folded by the feedback branch of `seiriReactor` before the verification branch, so a store carries one workstream kind; the self-hosted path uses separate audit and verifier stores. Existing runtimes leave the field unset and are unchanged.
- **Verifier transport requests accept an optional `feedback` profile.** When present, the request carries the policy hash in the existing cache identity, the Claude launch emits command-scoped attribution settings (`commit` and `pr` empty, `sessionUrl` false), and the attempt records fixed feedback-verifier limits of a ten-minute process deadline and a `3.00` USD budget cap. Requests without the profile keep the WO-009 limits. The Claude transport accepts the observed versions `2.1.261` and `2.1.263` and still refuses unknown ones.
- **New CLI command and a new evidence gate.** `dotln feedback-audit --store DIR` runs the self-hosted audit with the deterministic transport by default; `--transport claude-cli-print|codex-cli-exec --model M --effort E` runs it live under the existing `DOTLN_LIVE_WORKERS=1` opt-in. `npm test` now ends with `scripts/feedback-evidence.mjs --check`, which reruns all twenty present/removal fixture subprocesses, recomputes the instruction accounting, and validates the retained live audit and verification streams against the current pinned source and report. Changing any of the seventeen pinned files or the catalog therefore requires a new live recording, not only regenerated fixtures.
- **Store paths must be canonical.** The host refuses the feedback verifier mount when its resolved path differs from the path given; on macOS a store under `/tmp` is refused after the audit has already run and the CLI prints its deliberately generic refusal. Use the gitignored `.runtime/` root or `/private/tmp/...`, as the runbook now states.
- **Component versions and evidence editions.** `@dotln/compiler` is `0.6.0` and `@dotln/skeleton` is `0.12.0`; `@dotln/kernel` stays `0.2.1`, the event-envelope schema stays `1` and the compiled-loadout contract stays `1`. `feedback-v1` is a separate optional contract and every existing semantic hash is unchanged, while `artifactIdentity.compilerPackageVersion` now reads `0.6.0`. The artifact-identity and synthetic verification evidence helpers write and check their current editions under `docs/evidence/WO-011/`; the WO-010 and earlier receipts are retained as historical bytes.

## Substantive changes

- **Compiler: feedback units (`@dotln/compiler` 0.6.0).** `FeedbackUnit`, `CompiledFeedback`, `FeedbackRequest`, `FeedbackVerdict`, `CorrectionState` and `FeedbackObservation` are pinned types over a closed ten-handler vocabulary with declared rungs. `compileFeedbackUnits` validates and positively copies at most ten units; it refuses an unsupported or mismatched handler, a non-public source treatment, a source reference outside the repository or under `docs/intake/`, duplicate unit ids or handlers, and a conflicting or superseded unit that is still equipped; it sorts and normalizes every list and pins a `policyHash` over the compiled data and the compiler package version, and `assertCompiledFeedback` recompiles and refuses drift. `evaluateFeedback` judges host-supplied facts for the nine boundary kinds and returns per-unit violations with their enforcement, so an unequipped rule is inactive and an advisory finding never becomes a hard denial. `hasAiAttribution` is the exact co-author trailer and generated-with footer predicate. `applyFeedbackCorrection` is a monotone meet over the four typed semantic corrections: it can only remove wildcard and destructive effects, forbid scope expansion, preserve evidence and require diagnosis, and it is idempotent by event id. `feedbackMaturity` folds labeled fixture and live observations separately and refuses invented or duplicate ones. `compileFeedbackAudit` produces the bounded read-only `WO-011-feedback-audit` WorkOrder that denies `repo.write`, `repo.delete` and `publish`.
- **Skeleton: the personal catalog and the boundary adapter.** `personalFeedbackUnits` declares exactly the roadmap's ten units, each hard, with public lineage references and a stated reason the rung below is insufficient. `feedbackBoundary` evaluates host facts and throws `FeedbackRefused` before the effect runs; `feedbackReadOutput` binds a read to the current bytes and a receipt; `feedbackWriterFacts` resolves the physical working directory, Git root and branch; `feedbackSourceComments` parses a file with the pinned TypeScript parser and returns only actual comment ranges, so directives inside regular expressions, template literals and JSX text cannot impersonate suppressions and a quoted regular expression can no longer hide a later one. `scripts/feedback-commit-msg.mjs` is the commit-message hook adapter; it fails closed on any error, including a missing build, and is installed only where a host selects it.
- **Skeleton: the feedback branch of the shared reactor.** `FeedbackAuditOpened` recompiles the work order and refuses drift; `FeedbackAuditRequested` authorizes the `feedback.audit` intent through the kernel and dispatches it through `Program.Invoke` and the durable `CommandPersisted` outbox; `FeedbackAuditExecutionRequested` re-authorizes the persisted command at its own time, so an expired grant refuses; `CommandResult` is admitted only for the pending command with the pinned subject and policy hash. An operator-authored semantic correction narrows the policy and emits `FeedbackDiagnosisRequested`; a worker-authored one, or an ordinary message whatever its wording, leaves the policy unchanged, and a pending diagnosis blocks further dispatch and execution. Live and replayed decisions are compared for equality.
- **Skeleton: audit host and bounded self-hosting.** `readFeedbackSource` pins seventeen implementation and fixture files by content hash and requires the Git root. `runFeedbackRegressions` executes each unit's fixture in its own subprocess with the mechanism present and then removed, requires the removal run to exit 1 with exactly one assertion failure naming that test, refuses if the source changed during the audit, and computes the WO-004-method instruction accounting behind a positive-reduction gate. `runFeedbackSelfhost` drives the audit through the kernel in a locked store, recovers a saved result without re-executing the subprocesses, then opens a WO-010 verification workstream over the pinned source plus report with two criteria, an honestly unavailable base-revision witness, zero repairs and a denied-effects envelope, dispatches one blinded verifier into an empty Git mount with model tools disabled, and refuses source, work-order or verifier-selection drift on recovery. `dotln feedback-audit` exposes the whole path.
- **Tests.** Five compiler tests cover complete-shape validation and every refusal, unequipped and advisory profiles, the attribution predicate, the pure and idempotent correction under a throwing clock and random source, and maturity accounting. Ten skeleton regression fixtures, one per unit, each fail by assertion under the test-only removal variable; they use a real temporary Git repository with a real `commit-msg` hook, real Git roots and a real branch rename, a real subprocess exit code, and real file bytes where those facts matter, and the suppression fixture includes regex, template, JSX and trailing-directive cases. Three host tests cover the transport's observed versions, the end-to-end self-hosted audit with interruption recovery, equipped settings and limits, an empty verifier mount and idempotent completion, and the reactor's dispatch, expiry refusal and durable diagnosis request under replay.
- **Documentation and evidence.** The domain model gains the Feedback compiler v1 contract and states that the decision-lineage guard is implemented for equipped boundaries; the architecture records optional sibling-repository and documentation-adapter intentions and a corpus policy; the roadmap assigns `v0.13.0` and records the receipt; the execution guide names the absorbed duties, the disposable-backup rule and the corpus constraint; IR compatibility adds the `feedback-v1` axis; ADR-0002's Amendments and the legal inventory record the runtime parser; the planning map, the publication index and both edition locks, the root README release block, both package READMEs, the discovery record, the work order's activation header and ideation receipt, and the ledger are updated. Executor evidence under `docs/evidence/WO-011/` carries the twenty captured fixture runs with the instruction accounting, the retained live audit and verification streams, and the current artifact-identity and verification editions.
