# WO-072

`worktree start WO-NNN` for an order that declares a registered repository now creates two worktrees: the target repository's code worktree at the order's declared base commit under the configured parent, carrying WO-049's target-worker bundle as ignored files and no role skill, and the launchpad's usual order worktree for records. `resume` commands run from the target worktree select the order through the launchpad, and `release close` ends a target order without a tag. Before this change, `worktree start` built only sibling worktrees of this repository from `origin/main`, target worktrees existed only inside the source-change host for a worker episode, and `release close` had no path for a registered target. This is the control-plane lifecycle the three-repository route and WO-082 depend on.

**Start.** `worktree clone`, given the repository id and the clone's absolute path, records the physical local clone of a registered id in an ignored map in the main launchpad; `worktreeParent` resolves relative to that launchpad. Start refuses before `git worktree add`, naming the id and the reason, when the id has no clone recorded, the clone is not a Git top level, or the parent or clone is spelled other than the filesystem's identity for it, and when the planned target and launchpad worktree paths overlap or differ only by letter case. Each refusal leaves no worktree, branch or registry entry. An umbrella order refuses before any worktree exists, which closes the worktree half of FUP-bd3e66761dc301ed. An ignored pending-start receipt binds the pair, its bases and the order's bytes before either worktree is created, so a bootstrap or emit failure is retried with the same command: the retry preserves target commits, activates the order once and registers both launchpads before clearing the receipt. The handoff echoes the repository's authority profile and the launchpad command to run from the target.

**Selection.** From the target worktree, `status`, `next`, `verify` and `final-review` select the order through the order launchpad's own scripts or through `DOTLN_LAUNCHPAD` naming it. An ignored registry keyed by the target's physical path binds it to the order, and the target branch must still be the order's `wo-NNN`. Launchpad identity is compared physically, so a symlink, another letter case, a trailing slash or a volume alias keeps selecting the same order; VER-001 found the lexical comparison that lost self selection, and the repair closed it. Reports land only in the launchpad's configured roots. A directory the registry does not list selects no order and says so; `status --json` then exits 1 with the sentence on stderr and nothing on stdout. The working directory never selects a launchpad.

**Close.** `release close WO-NNN --publish` for a target order records the `no-release` disposition and creates no tag in either repository. It requires the merged control state to be closed and the target branch to be an ancestor of the declared base branch, proves the target writer released, the worktree clean and the bundle owned, then removes the bundle, the target worktree and the merged branch, and finishes the launchpad worktree as today. A dry run reports `would-remove`. A repeated close after removal succeeds from the retained record. Unmerged work, tracked dirt and ignored material outside the bundle each refuse and retain the source.

**Read before merging.** The clone map, the target registry and the pending-start receipt are ignored local state under the main launchpad's control-local directory, with a registry copy in the order launchpad; no local path enters a control event, the index or a target commit. A launchpad with repository declarations or a target registry no longer selects its branch order from an unrelated directory; that is the designed outcome, and a launchpad with neither keeps its earlier resolver. Selection and creation call `/bin/pwd -P`, and the execution evidence is from one case-insensitive macOS volume; no Linux or case-sensitive run is claimed. Two follow-ups are boarded in the declared surfaces: run from the target with `main`'s own scripts and no override, the no-selection sentence calls a listed target unregistered and names no launchpad (D008, FUP-f82660a8edb23a4d); and a target close that meets ignored material outside the bundle refuses with every ignored file listed and no remedy, while plain `git worktree remove` would remove the worktree (D010, FUP-00b15d92d53011b2). The start handoff ends with `codex` and `enter: resume: next` in a target that carries no role skill; how that phrase behaves there was not run. Per-repository release policy stays open, as the order's declined alternatives record.

**Validation.** VER-001 failed: a launchpad spelled through a symlink or in another letter case selected no order, where the base selected it, and `status --json` printed plain text with exit 0. The repair compared physical identities and made the JSON form refuse, and VER-002 passed it. FINAL-001 passed with the one follow-up above.
