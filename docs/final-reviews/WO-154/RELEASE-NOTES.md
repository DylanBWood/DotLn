## Release overview

This release changes what a feedback evidence edition is made of and when it goes stale. Until now every feedback self-host edition copied the full text of every file the live verifier judged twice into the tracked tree, about 2.1 MB per edition on the current subject and 105 MB across the repository, and any change to a registered source, including a routine component version bump beside an unrelated edit, could owe a paid live self-host episode of two to five minutes. A schema 2 edition now records those files by path, Git blob identity and length, rebuilds their bodies from the working tree or the object store when a check or a reader needs them, and keeps a behavioral identity over the judged files with release labels normalized beside a pins record of the labels themselves. Staleness and the live episode follow the judged behavior and the regenerated report: a version bump keeps the recorded audit, a compiler release carries it into a new edition with one deterministic command, and a judged change still cannot inherit an older audit. The two new editions are 178 KB and 189 KB against 2.2 MB by value. For an operator this means smaller clones, fetches and integrations, and fewer paid episodes for changes that judged nothing new.

## Read before upgrading

A feedback edition recorded from now on is not self-contained: its verifier stream carries references, and `feedback-evidence --check`, the console and the stored-stream replay rebuild the bodies from Git, so a checkout without the referenced objects (a shallow or blob-filtered clone) reports the edition stale by path; the repository with its objects is the evidence store, which the order's operator-review assumption accepts. Existing editions keep their bytes and their exact check path. The compiler's `assertCompiledFeedback` and `assertVerificationTask` now admit a program or capsule recorded under an earlier compiler release when everything else is this compiler's lowering, and the verification reactor adopts a persisted command whose capsule differs from the dispatched one only in that label; this is the compatibility decision WO-050 D002 and WO-133 D004 had reserved, and it means the four historical streams the WO-050 byte oracle froze as refusals now replay to completion (the oracle keeps its bytes behind a hash-chained successor manifest, and the WO-011 self-host verifier's replay is asserted in the skeleton suite instead of the oracle). After a compiler release is built, `feedback-evidence --check` refuses with a named remedy, `--carry` naming the edition directory with `--edition WO-NNN --revision NNN`, which mints an edition with no live episode and must be followed by a console re-pin; a skeleton or console label bump needs no action. `@dotln/compiler` moves to 0.18.0, `@dotln/skeleton` to 0.39.0 and `@dotln/console` to 0.1.11; no dependency is added. The planning refutation receipts are unchanged; storing their subject by identity is split to its own patch order.

## Substantive changes

**Editions by reference.** `feedback-evidence --record-selfhost` projects every `{path, contents}` files entry of the verifier stream (the opening's subject and baseline and the persisted capsule) to `{path, blobHash, bytes}`, the two synthesized package projections naming the repository blob they derive from, and writes only after the references rebuild the store's stream byte for byte. `--check` resolves from a hash-matching working-tree file, the edition's own pins snapshot and report, or one `git cat-file --batch` for the rest, verifies the rebuilt subject against the recorded revision hash, and names each unresolvable reference by path. A content-addressed `pins/` snapshot beside the edition keeps the raw bytes of every label-bearing judged file so a version bump before the first commit cannot strand a reference.

**Behavior key and carry.** The edition record (schema 2) carries a behavioral identity over the 51 judged files with component release labels normalized, a pins record, and a live-audit reference. A pins-only change is retained with no action; `--carry` writes a deterministic edition naming the live audit it carries; a judged-file change, a changed regenerated report, or a recorded program that differs from the current lowering in anything but its release label is refused, with a forged identity refused twice more by the live audit's own per-file comparison.

**Recorded compiler releases replay.** A recorded program or capsule keeps the compiler release it names, the compiler lowers at that release for comparison and refuses every other difference, and the verification slice rebuilds its continuation from an adopted persisted capsule. `feedback-evidence --check` names the deterministic carry when a compiler release moved the policy hash the console binds.

**Readers.** One reader, `feedbackEditionLog`, rebuilds a committed self-host stream for the console's self-host stores, the console fixture loader and the WO-047 stored-stream replay; `console-fixtures --record-current-selfhost` pins a carried edition's live-audit paths.
