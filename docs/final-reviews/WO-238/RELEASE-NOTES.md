## Release overview

Every committed document in a DotLn instance is now standing, record or generated, by a kind derived from its path, and a standing document has a reader: the document check refuses a reader entry point that names a record, reports a standing document no entry point, link or program reaches, and judges no document's bytes. A planning pass reads a census of which documents sessions read over the last five releases and red-tags what nobody reaches and nobody read; the next pass removes or folds each with a disposition. For an operator this release answers "is this document used?" with the journals the hooks already write instead of a byte count, and it moves the history out of the pages a session reads at start.

## Read before upgrading

`docs/control/doc-ceilings.json` is no longer read or seeded; an instance that holds one may delete it, and the document check no longer prints a byte table or a ceiling advisory. `npm run test:docs` now fails when a reader entry point (the root instruction file's Start here, a skill's `Read:` line, the execution guide's cold-start order or the kit guide's First steps) names a record such as a verification or a decisions file, when a file is created at a path `docs/control/document-moves.json` lists as moved, or when a planning pass document's red-tag block leaves a tag undisposed past one pass; it reports, without failing, each standing document no reader reaches. An instance that wants other entry points or a kind its path does not say adds `docs/control/documents.json`. `npm run plan -- start` now writes the pass document under `docs/planning/passes/` and gives it a `Red tags` section with a marker block; the `Write-backs and ceilings` heading is `Write-backs`. The kit's dated planning documents moved under `docs/planning/passes/`; links written before the move resolve through the move map in the kit's checks, and a Markdown renderer follows them only to their old paths. Release close now refuses to publish while a proposal packet routed to the closing order names a release other than the one being published, printing the route command that completes it. The repository-profile template's `Checked:` field is `Current at:`; the workstream template gains a `Rules` section. The kit carries `docs/product/operator-reference.md` beside the execution guide.

## Substantive changes

Documents and their readers: `scripts/lib/document-kinds.mjs` derives each document's kind and each standing document's reader binding; `scripts/lib/document-census.mjs` counts the sessions that read each document from the Claude and Copilot journals, labels Codex unobserved and writes `docs/control/local/document-census.json`; `npm run plan -- documents` pages the records named, the red tags, the unbound and unread documents at 8 KB with a revision-bound `next`; `scripts/docs-check.mjs` carries the three new refusals and the unbound report and loses the ceiling check; a moved document keeps its bytes and one map, `docs/control/document-moves.json`, gives every reader the same meaning for an old path, with a moved path never reused.

Planning: 51 dated pass documents, the retired map copy and the release-history notes live under `docs/planning/passes/`; `docs/planning/README.md` names what a pass reads and leaves; the planning map's standing sections stand above a record divider with the dated candidate sections below it, their anchors unchanged; `plan start` writes the pass's red-tag block; the follow-up register keys a moved document's candidates by the path they were written at.

The execution guide: every top-level section stays as the roles' source; the operator's procedures are in `docs/product/operator-reference.md`; five dated accounts are in `docs/planning/passes/execution-guide-record.md`; item 7 of the planning pass and the freshness section state the kinds, the entry points, the census, the red tags and the move rule as built; the screens before filing are a list of rules each linking its pass.

Proposals and releases: a filed packet carries `deliveredBy` (`workOrderId`, `release`, `recordedAt`), written by `npm run entropy -- dispose ... route --order WO-NNN`, completed by the order's release preparation, and judged by release close before anything publishes; the twelve packets filed before the field are backfilled from the release tags; the entropy chain's hash still judges the filed bytes.

The Entropy Reducer: a fifth lens, `documents-and-readers`, asks which standing document carries a dated history, which document has no reader and which record a session reads at start; the checklist holds five lenses.

The kit and the roles: every role root states the three kinds, the entry-point rule, the census and the final reviewer's judgment of a changed standing document; the shared instruction's residue is one line per profile; the repository-profile and workstream templates state their kinds; the instance's root instruction file names the three kinds; the index card drops its Cost paragraph while the order keeps the field; a document row at completion also stands for the tree without the order's own evidence directory, and a repeated document-gate run within one handoff is reported as a failure.
