# WO-201

An instance exported by `launchpad export` can now run core's gates on the runtime it carries. The kit holds no package TypeScript, so until this change `npm test`, `npm run test:docs` and `npm test -- --review` failed at the build inside every export, the client README recorded that as a limit of the kit (WO-074 D007), and no order in an instance could pass verification or final review on the instance's own gate. Now the runner recognizes a kit root, verifies the carried compiled files against the kit manifest instead of compiling, runs every suite whose inputs the kit carries, and prints by name each suite the kit cannot run with the reason. In a fresh source-free export the three selections exit 0 in about 40, 12 and 10 seconds.

**How kit mode works.** Kit mode is detected, never configured: `KIT-MANIFEST.json` at the root and no package source. In that mode the runner replaces the `build` row with `kit-verify`, which runs `node scripts/launchpad.mjs verify`: it hashes every manifest-listed file, refuses by path on the first mismatch under a runtime package's `dist/` directory before any other task runs, and reports every other differing kit file in one advisory line (`kit files differ from the manifest`, with the count) without refusing, because an instance that edited a script has chosen the true-fork path and still gets its gates. `verify` is also a command form on its own. A suite row that reads something the kit does not carry declares it, `kit` as `core-only:` followed by the reason, and the runner validates the form; in a kit such rows are not selected, every selection and `--list` prints a `not carried` line with each one's name and reason, and `--only` naming a declared row refuses with the name and reason before any task or gate result is recorded. Core's own gate is unchanged: at a core root `--list` still selects `build` and prints no `kit:` line, and the refusal sits inside the kit branch only.

**What the kit now carries.** The compiled tests under each runtime package's `dist/test/` directory travel beside the runtime, byte-identical to a rebuild at the commit and manifest-listed, together with the three fixture trees they read, the formatter configuration, the identity-corpus test with its manifest and two synthetic vector files, and the three mutation self-test modules. One fixture is excluded by name: `scripts/fixtures/wo138-local-role-qualification.json` is derived from a core verification report, so it does not travel and its suite is declared core-only ([D004](../../evidence/WO-201/decisions.md#wo-201-d004--keep-the-role-qualification-oracle-with-its-core-report)). The kit grows from 605 files and 9,793,574 bytes to 863 files and 15,971,669 bytes ([D016](../../evidence/WO-201/decisions.md#wo-201-d016--refresh-export-measurements-without-dropping-coverage)). The compiled tests travel under the same Apache-2.0 terms as the runtime; `docs/LEGAL.md` says so in place.

The fixture asserts the README's lists and table against the kit's gate rows and the runner's declarations, so a changed selection fails the launchpad task until the README follows.
