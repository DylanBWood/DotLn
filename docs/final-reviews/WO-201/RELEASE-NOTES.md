## Release overview

Application v0.77.0 lets an exported kit run core's gates on the runtime it carries. A launchpad instance holds no package TypeScript, so until now `npm test`, `npm run test:docs` and `npm test -- --review` failed at the build inside every export, the client README recorded that as a limit, and no order in an instance could pass verification or final review on its own gate. In this release the runner recognizes a kit root, verifies every carried compiled file against the kit manifest instead of compiling, runs the suites whose inputs the kit carries, and prints by name each suite the kit cannot run with the reason. It serves the operator of an exported instance, who now runs the three gates there, and the contributors who add a suite row to core, who now say whether it runs in a kit.

The visible changes:
- In a kit, each of the three selections starts with `kit-verify`, which hashes every manifest-listed file and refuses a changed, missing or nonregular compiled file by path before any other task; other kit-file edits give one advisory line and the gates run on the instance's bytes.
- `node scripts/launchpad.mjs verify`, with an optional directory argument, runs the same check on its own.
- Suite rows that read core's history, documents or package source declare `kit` as `core-only:` followed by the reason; every selection and `--list` prints each as not carried with its reason, and `--only` on such a row refuses with the name and reason and records nothing.
- The kit carries the compiled tests under each runtime package's `dist/test/` directory, the fixture trees they read, the formatter configuration and the portable corpus files, all manifest-listed and byte-identical to a rebuild.
- The client README states which suites run in a fork and which stay core's with the reason, where an instance's orders and reports live, that its first planning pass is its own, and what editing a kit file means.

## Read before upgrading

- **No operator action and no component change.** No package version, dependency or lockfile moves. Core's own gate is unchanged: at a core root `--list` still selects `build` and prints no `kit:` line.
- **Existing exports take the change through `launchpad export --update`.** The update carries the new runner, the compiled tests and the fixture trees into an existing instance as manifest-listed files; a kit file the instance edited is refused and keeps its prior hash, as before. An instance runs `npm run meta` once after activation so its own decision index exists before its first gate; the README's first steps say so.
- **45 of 72 suite rows stay core's.** The whole package rows (`kernel`, `compiler`, `skeleton` and their document rows), the publication and release rows, the rows that read core's control records, editions, ledger or evidence, and the console and browser-evidence packages are declared with their reason and listed in the README's table. An instance runs the compiled tests only where a script suite drives them, and planning inside a fresh instance remains the separate WO-202.
- **A declaration is bound by a rule, not by the gate.** A row is declared core-only only when a clean export execution fails for want of its named input ([D014](../../evidence/WO-201/decisions.md#wo-201-d014--correct-the-exclusion-using-clean-execution-evidence)); VER-001 found one declaration that broke that rule and the repair removed it. The fixture independently requires only two portable rows (`publication-fixtures`, `beacon-portability`) beyond the equality of printed and declared sets, so a future false declaration is caught by that rule and by verification, not by the gate; this is planning receipt 044's criterion-2 condition and stays with planning.
- **`verify` trusts the manifest.** A manifest whose hash is rewritten to match an edited compiled file passes, and an unlisted file added under `dist/src` passes and is loaded by no carried selection. Run it from the kit root; from a subdirectory the default root is the working directory.
- **The `launchpad` gate task grew.** It read 328,008 ms in the passing review gate against a pre-order reading of 123,776 ms, with the three-selection export case at 191,260 ms under three concurrent peers. All three selections are retained as the order required, the contributors are recorded ([D011](../../evidence/WO-201/decisions.md#wo-201-d011--retain-the-three-selections-and-record-the-full-tasks-cost), [D017](../../evidence/WO-201/decisions.md#wo-201-d017--record-the-repaired-subject-and-complete-review-evidence)), and the two register rows that watch it, FUP-b531e850b70f6d4e and FUP-e96221b106cd136a, are returned to open for a planning bound.
- **One fixture no longer travels.** `scripts/fixtures/wo138-local-role-qualification.json` is derived from a core verification report and is excluded from the kit; its suite, `local-runner-double`, is declared core-only ([D004](../../evidence/WO-201/decisions.md#wo-201-d004--keep-the-role-qualification-oracle-with-its-core-report)).
- **Versions.** Application v0.77.0 is a minor release over v0.76.1, assigned at activation under the order's classification. No component version changes and no dependency is added.

## Substantive changes

**Kit mode in the runner** (`scripts/test-runner.mjs`). `isKitRoot` detects a kit root: `KIT-MANIFEST.json` present and no package source. `buildSuite` supplies `kit-verify` (running `scripts/launchpad.mjs verify`) in place of `build` for a kit, derived from the gate's repository argument so an imported gate selects the row for the repository it judges. `scheduleSuites` runs `kit-verify` first and alone, then the format preflight, and refuses every later task on drift; core keeps its format-before-build order. `runGateChecks` prints the not-carried line for each declared row, throws an error naming the suite and its declaration (`is not carried in this kit`) for an explicit `--only` on one, drops declared rows from the selection, and places `kit-verify` first; the review composition never reuses `kit-verify`; a successful `kit-verify` forwards its `kit:` diagnostics into the gate output. `validateSuites` refuses a declaration that does not start with `core-only:` and a reason. Forty-five rows carry declarations; `publication-fixtures` and every other row that builds its own fixture records does not.

**The `verify` form and the kit's file set** (`scripts/launchpad.mjs`). `verifyKit(root)` reads the prior manifest, hashes each listed file, throws `kit runtime differs from the manifest:` with the path on the first mismatch under a runtime package's `dist/` directory, counts other mismatches (an unreadable or nonregular listed file counts as differing) into one advisory line, and prints the count of verified files with the manifest's commit; the CLI gains `launchpad verify` with an optional directory argument. `RUNTIME_TEST_OUTPUT` adds `dist/test` to the runtime walk and to the update's kit-path rule; `TEST_FIXTURE_TREES` adds the three fixture trees and `TEST_SUPPORT_FILES` the eleven support files to `KIT_FILES`; `KIT_FILES.excluded` names the one fixture that stays home, filtered out of the scripts tree at export. `UPSTREAM.md` describes the runtime and tests group, the fixture group and the exclusion.

**The client README** (`scripts/kit/README.client.md`). §What runs here, and what does not is rewritten from the fixture's observed lists: the three selections' suites, the review selection's reuse rule, the `--only` refusal, the 45-row table of core-only rows with the input each lacks, and the remaining limits (build, console fixtures, browser evidence, planning pending WO-202). §Kit files and instance files lists the carried fixture and corpus files and the excluded fixture, and carries the "Your orders live here" paragraph. §Taking upstream updates carries the true-fork paragraph, narrowed where the subject contradicts the draft ([D005](../../evidence/WO-201/decisions.md#wo-201-d005--preserve-the-readmes-intent-without-claiming-pending-behavior)). The first steps add `npm run meta` after activation.

**Fixtures** (`scripts/test-launchpad.mjs`, `scripts/test-runner.test.mjs`, `scripts/lib/document-gate-stubs.mjs`). The export fixture's verbatim comparison is driven by `KIT_FILES` and asserts the exclusion; the WO-075 rebuild case covers `dist/test`; a criterion 4 case runs `verify` fresh, with an explicit directory, under a launchpad override, after a one-byte `dist/src` and `dist/test` change (refuses by path) and after a script edit (one advisory line); the three-selection case exports once, installs offline, activates the seeded order, runs `meta`, then runs the three selections under the bounded wrapper and asserts exit 0, `kit-verify` first, no build task, printed exclusions equal to the declarations, the carried union equal to the undeclared rows, the README's lists and table, two unavailable `--only` requests refusing with an unchanged gate index, the advisory through a gate, a `dist/test` refusal by path with `kit-verify` the only executed case, and records the durations and byte figures in a diagnostic. The runner fixture gains a kit listing case, an `--only` refusal case and a schedule case; `launchpad.mjs` joins the document-gate stub registry.

**Documents.** Product 03 §Platform and instance boundary replaces the sentence that running the suites still needs the omitted source with what runs in a kit and the `--only` refusal. `docs/LEGAL.md` §Current state carries the compiled tests under the runtime's terms. The capability table gains a dated `launchpad.starter` reassessment from the recorded export gate rows.
