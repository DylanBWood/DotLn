## Release overview

For anyone running DotLn's review ladder, the reviews now find what the complete run finds: a recheck reads the whole change again instead of the repair alone, a consistency review is recorded only with the table of consumers it traced and the commands it ran, each planning pass keeps its own review lane, the criteria adversary of a planning pass reads the operator's dispatch and answers it item by item, a registered target's order is reviewed through the same helper, and every worker launch names one of the operator's four model options with the harness defaults. Three verifications judged the change; the first two failed on the lane name and on the recorder's reading of JSON examples, and the third passed after the recorder learned to ask the caller which it meant.

## Read before upgrading

`npm run worker -- record` now declares the intent of mixed text with `--format prose|json`: whole JSON, a whole fenced result and plain prose record as before, but a report that mixes prose with a result-shaped JSON object is refused until the flag names its intent, `prose` keeping every example and adopting no findings and `json` binding exactly one result with its findings and report table; under `json`, a brace in the surrounding prose that opens no JSON object also refuses the record, and the remedy is to put the result alone in the input file.

`record` also takes `--host`, `--model` and `--effort` for what ran and `--tree` for the tree the worker reviewed; a report whose opening `Reviewed tree:` line names another tree than the working tree is refused until `--tree` names it.

A consistency review is recorded only with its `Traced consumers` table carrying a generated pages row and a fixture manifests row, and a capture review only with its `## Items` table; a table quoted in code, HTML or a blockquote does not satisfy either rule.

A planning subject's review lane under `docs/control/local/reviews/` is now `planning-` followed by the branch's name after `planning/`, URL-escaped, instead of `planning-` followed by the date; this is ignored local state, and earlier lanes are neither read nor moved.

Codex installations now emit the custom agent `.codex/agents/dotln-worker-astra.toml` beside the hook and configuration the profile already owns; an unowned file there is never replaced. `npm run plan -- refute` takes `--model opus|fable|sol|astra` on its direct and transport forms; an `--effort` outside the named option is refused, and the fake transport takes neither flag.

## Substantive changes

Review helper: round 2 confirms the earlier findings and then reviews the whole current change against the base, naming the earlier round's tree; `--since` with a tree starts a fresh round-1 ladder under a `since-` directory named by that tree, and a fresh round 1 over the tree its lane last reviewed is named a re-roll in an advisory; `--capture` with the capture file appends a planning subject's dispatch capture to the criteria brief, the report answers each item in an `## Items` table, the record keeps only the capture's digest and byte count, and quoted passages are omitted from every string the record keeps; `--target` with the repository id and `--order` with the order bind a registered target's order to its activation base and worktree, read with the host's safe Git options, counted once and reported in the launchpad's lane; `--dry-run` prints the brief as well as the argv.

Recorder: `--format prose|json`, the actor and tree flags, required report tables read as actual sections through the shared Markdown parser, and each record naming its base, its ladder, the reports it answered with their digests and the `inputFormat` it was given.

Worker options: one table of the four options in the contributor loadout drives the generated worker definitions, the helper's and the refuter's `--model` lookup and the refutation receipt's worker types; the dispatch words `fable` and `astra` closing a `planning:` or `resume:` line select the host's non-default for the session's launches, journaled by Claude's prompt hook and the generated Codex prompt hook as a `WorkerOptionsSelected` row, the Codex hook making the checkout's journal lane for a first dispatch line; a line naming neither returns to the defaults.

Generated roles and guidance: the executor root states the whole-change recheck, the required table and the record command's flags; the planner root names the capture review's command with its host; product 07 §Verification review and attack, §Paired passes and the synthesis pass and §Model-specific notes, the kit guide, the security note and the skeleton README describe the lane, the ladder, the tables, the capture flag, the target form, the recorder's formats and the four options as built.
