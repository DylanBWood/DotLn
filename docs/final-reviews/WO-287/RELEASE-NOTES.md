## Release overview

In an exported instance, the kit no longer stops work for a reason that has nothing to do with its owner's work. Every stop the kit ships, whether a hook that denies a tool call, a gate task that fails for a reason other than the code under test, or a bound, now has an id, a class and a level that one line of `dotln.config.json` sets. A stop that guards the kit's own records, a property of the machine or a budget advises in an instance and the work goes on, in a registered sibling repository's worktree as in the launchpad. A stop that guards the owner's work still refuses. The working rules the kit's author puts into every session are a layer an instance removes with one line, a routed run that stops says why, and core, which builds the kit, refuses on every stop as before.

## Read before upgrading

**Stops have levels, and an instance starts lower.** `npm run features -- list` prints every stop under Stops: its id, class, what it protects, where it is enforced, its level in this root, who set it and the one line that changes it. That line is `"stops": { "<id>": "refuse" }`, `"advise"` or `"off"` in `dotln.config.json`, followed by `node scripts/harness.mjs emit` ([Stops](../../KIT.md#stops)).

**What now advises in an instance.** Stops of the classes `record`, `host` and `bound`: a write outside `docs/` on a `planning/` branch, a write while a gate runs in the worktree, a launch past the dispatch bound or the worker cap, a router's or a driven helper's write, the gate's own format, index, generated-page and document-form checks, its kit verification, a link in a document that resolves nowhere, and the others the page lists with those classes. An advised call goes on with one line naming the stop and what it protects. An advised gate task is recorded as advised with its output, fails nothing and is never reused as a pass.

**What still refuses in every root.** Stops of the class `work`: another session's writer reservation, a write outside the project, the `gh` repository check, `ssh`, package publishing, credentials access, the owner's settings, disabling the sandbox, an unapproved remote, a target worktree's bundle and its publication, attribution, and a private path in a document. An entry of the private terms list's `refuse` class fails at any level, and so does a check ended for time, whether the gate's limit ended the task or a limit of the task's own ended a step inside it. Desktop control keeps its own election and has no level.

**To keep what an earlier kit did, set the stop to `refuse`.** The features page prints the line for each.

**Emit again, in the launchpad and in each registered target worktree.** After taking the release, run `node scripts/harness.mjs emit` and start a new session, since the emitted hooks and role text change. A target worktree's guards carry the levels of their own last emit, so run `node scripts/harness.mjs emit --target <worktree>` for each one. A worktree installed by an earlier kit recorded no levels: it refuses as before and is not named as behind until that emit ([What a hook does in this instance](../../KIT.md#what-a-hook-does-in-this-instance)).

**In a target worktree, a command the guard cannot read now goes on.** An earlier kit refused a shell line the guard's classifier could not read. In an instance it now advises, as the launchpad's own hook does. One consequence: a commit whose message the guard cannot read (a message built by a substitution such as a here-document, a message file outside the worktree, or no message on the line) is no longer refused there, and its message is not judged for AI attribution. Set `target-classification` to `refuse` to keep the refusal.

**Lowering `ssh` does not lower credentials access.** A line of `ssh`, `scp` or `sftp` that names a credential file is still refused, wherever the name stands in the line or in what feeds it. A key or a configuration given to the transport by a lone `-i`, `-F` or `-o` setting among the options the line opens with is passed over; any other spelling of it is refused. The screen is of names: a directory or pattern that holds such a file, a name the shell expands and a file's contents are not seen.

**The author's rules are a layer, and nothing changes until you choose.** The same page lists under Rules every feedback unit and shared role rule with its layer and the overlay line that changes it. An instance that names no unit or rule in its build overlay emits the rules it emitted before. `"unequip": ["author"]` in the overlay leaves the author's layer out, and a single id in `equip` or `unequip` keeps or removes one rule. A unit left out takes its hook with it, and its stop then reads `off` ([What is the kit's and what is the author's](../../KIT.md#what-is-the-kits-and-what-is-the-authors)).

**The paraphrase rule's stop.** `verbatim-operator-words` has a level. In an instance it advises with one line for each file, and at `off` the screen is not run. The election `features.verbatim-operator-words` still sets it where you write no `stops` line for it ([The operator's words are paraphrased](../../KIT.md#the-operators-words-are-paraphrased)).

**A routed run.** A driven Claude phase starts with the host's wait for background work uncapped, unless the drive's own environment sets `CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS`. A host's denial of a helper agent's call is recorded and no longer ends the phase; the phase worker's own denied call still does. `node scripts/drive.mjs why WO-NNN` prints why a drive stopped, and the router gives the operator those lines. A Claude release-close phase starts with a narrow rule for the close's one helper command, for the order being closed ([When a routed run stops](../../KIT.md#when-a-routed-run-stops)).

**The Codex workers' models.** A Codex launch of the `default` and `verifier` workers now asks for `gpt-6.2-sol`, and one of `astra` or `advanced` for `gpt-6.2-astra`. Each model's own effort stays `max`, and `verifier` binds `sol` at `xhigh`, as before. An instance that names no model of its own in `dotln.models.json` runs them after the update; one that keeps an earlier model writes a row with the kit model's name there.

**The features page reads the compiled runtime.** Its rules and stops come from the compiled loadout. In a source checkout, run `npm run build` before `npm run features -- list` or `npm run meta`; `npm run features -- list --json`, which prints the elections alone, needs no build. An exported kit carries the compiled runtime, and where the loadout is missing the page says to run `node scripts/launchpad.mjs verify`.

## Substantive changes

**The table of stops.** One build-free module, `packages/skeleton/src/stops.mjs`, holds 91 rows: 65 stops with a level, four that keep a switch of their own, two set in a file of their own and 20 refusals of lifecycle commands, which have no level and are listed with their way forward. A `stops` section of `dotln.config.json` sets a level. A line that names no stop or no level is named in one advisory and ignored, and so is an unknown `features` key in an instance.

**Hooks.** Each hook answers a stop at its root's level: a denial at `refuse` that names the stop and the line that lowers it, the call allowed with the stop's line at `advise`, nothing at `off`. An advisory is shown once a session and every one is journaled. A stop that advises does not end the hook's judgment, so a lowered stop never hides one that still refuses. No refusal names `operator override:` as its route, and both recovery controls now reach a target worktree's guards.

**Target worktrees.** A target worktree's guards answer at the launchpad's levels, which their bundle takes at its emit. A guard that cannot reach the launchpad's runtime allows the call and says that nothing there is being judged; `target-runtime` at `refuse` denies instead. The host deny rules for `ssh` and a package publish are left out of the emitted settings where the owner lowers those stops.

**The gate.** A failed task whose stop advises is reported as `ADVISED` with what it said, the tasks after it run and the selection can pass; its row names the advised tasks. The document check and the host check judge each failure by its own stop. A check that could not run or was ended for time fails at any level: a generated check, the license check's dry run, the index check's read of the suites and the host check's read of Git's version among them. A selection that passed with advised or off tasks stands for the completion that consumes it, an instance's kit verification among those tasks, and a later selection still runs those tasks again.

**Bounds inside commands.** The dispatch bound, the worker cap and a drive's budget are one row each however many places enforce them: the hook, the bounded probe wrapper, a re-dispatch, the review helper's launch, and the driver before a phase and as a Codex worker reports its helpers.

**The features page.** `npm run features -- list` prints the feature elections, then one row for each rule and one for each stop; `rules` and `stops` print those tables alone, with `--json` for their rows. No "Not electable" list is printed.

**The author's layer.** Each of the ten feedback units and the 33 shared role rules carries a layer: 18 rules are the platform's and 15 rules and all ten units are the author's. The emit leaves an unequipped unit's line, hook and Origin id, and an unequipped rule's sentence, out of the launchpad's bundle and a target worktree's. `harness check` judges the installed bundle against what the overlay emits, the kit's verification counts a removed unit's hook files as left out, and an update neither writes nor lists them. A fresh export's `CLAUDE.md` says that its Clean Room and Secrets sections are the owner's own text.

**A drive.** The drive's record keeps, of a denied call, the tool from a fixed list, who called, what decided and when. Of a refused dispatch it keeps why in the kit's own fixed words. A command's shape keeps a word only in the place its grammar gives it; a line whose command boundaries are uncertain has no shape, and an older record's shapes are shown as placeholders. The router's role has it run the account's command after a stop and answer from it.

## Progressive polish

The kit guide's sections on stops, hooks, the gate, the build overlay and a routed run were rewritten around the table, and the execution guide's passages on refusals and standing gate rows follow them. The shared test fixture turns Git's background maintenance off in every repository it makes, after a teardown raced it. The decisions of the order, with every reader's and every critic's points judged, are in [its record](../../evidence/WO-287/decisions.md).

## Evidence and compatibility

The order's 27 criteria were judged by three verifications and one final review: [VER-001](../../verifications/WO-287/VER-001.md) and [VER-002](../../verifications/WO-287/VER-002.md) failed and were repaired, [VER-003](../../verifications/WO-287/VER-003.md) passed, and [the final review](FINAL-001.md) repaired eight further defects and passed. Criterion 4 is recorded defective: one clause asks that the existing cases for the nine refusals pass unchanged, and criterion 10 removes the recovery-override sentence one of them pins. The final review's complete run passed at code identity `47aac45382e0f4e282ac4e9756d11d5e46b2ca2c330b68918874ba1f625de666`: 47 suites and 124 tasks, all fresh. The plain selection and the document gate passed after it.

Node and Git requirements are unchanged. `@dotln/compiler` moves from 0.44.0 to 0.45.0 and `@dotln/skeleton` from 0.93.0 to 0.94.0; neither is published. The drive's records written by an earlier kit stay readable, with their command shapes shown as placeholders. A root that sets no `stops` line answers as this release's defaults say: core as before, and an instance at the levels above.
