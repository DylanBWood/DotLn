## Release overview

DotLn's local actor kind has its first measured role. A pilot ran three read-only inspection tasks, each with a deterministic oracle, against the pinned local Qwen3.6 27B artifact and against one remote inspection transport under the same input, prompt, schema and probe build, five repeats each, and asked whether the local model meets the reliability each role needs. The answer is `inconclusive`, on purpose: one task qualifies and two do not. Ranking the discovery producer's six candidates for a seeded repository against the operator's held-out order, the local model returned five schema-valid rankings whose Spearman correlation with the operator is 0.828571, the same median the remote model produced, with a median latency of 12.1 s and no operator intervention. Summarizing a verification receipt into a fixed-schema abstract it got one field in ten right, and classifying hook-journal rows into a closed set it got ten rows in twelve, both below their pre-registered 0.9 floors and both well behind the remote model's 1.0. This release is for the operator and for whoever plans the next local-model order: it says exactly which role the catalog may now hand to the local kind, on what evidence, and what the next qualification must show.

## Read before upgrading

Nothing about how DotLn runs changes, and no operator action is required. No package source, component version, dependency, harness setting, hook, event schema or authority rule moves; the branch changes nothing under `packages/`, `package.json` or `package-lock.json`. Three limits bound what the catalog row means. The qualified role is fixed and narrow: ranking committed public discovery candidates under a read-only contract with host-validated coverage; it is not a capability level and it does not qualify writing, implementation, independent verification or any role that reads private material. No no-egress claim is made; the runner ran with networking permitted, as WO-137 recorded, and every input was committed public material or a seeded scratch repository, so the proof that nothing leaves the machine remains a separate, still-open experiment. Five repeats of one fixed cell estimate that cell, not a population reliability rate, and the latency and throughput figures are one host, one session.

## Substantive changes

**The qualification and its write-backs.** Product 03's runtime catalog carries a dated row: for committed public inputs only, the local kind may rank T2's six discovery candidates under its fixed contract; T1 and T3 remain unqualified; the row changes no availability, no boundary and no capability level, and names its reopening conditions. Product 06's local-model candidate carries the dated `inconclusive` disposition with the two next qualifications: T1 needs a fresh fixed-schema accuracy qualification, and T3's single label-definition cell, which reached 1.0 where its baseline reached 0.833333, is a candidate for a separately registered repeated qualification.

**The evidence.** `docs/evidence/WO-138/` holds the [decision packet](../../evidence/WO-138/decision-packet.md), 38 episode records (30 baselines, five one-factor cells, three unexpected-input cells), the pinned task inputs both transports consumed, `results.json`, both run manifests, the operator's held-out ranking with its self-reported 60 seconds, and an independent audit script that recomputes every distribution from the records. Every record names the same probe build hash, the pinned artifact's SHA-256 from the runner's own inventory, and the hashes of its input, prompt and schema. Eight earlier attempt sets are retained unscored and explain their own exclusion: setup and preflight failures, a gate-race matrix, a build that predated formatting, the matrix VER-001 rejected, and the first repair matrix whose two arms had drifted apart on one input digest.

**The instrument.** `scripts/probes/local-model-role-qualification.mjs` prepares the operator ranking request, runs one transport's cells, and evaluates a directory of records against the pre-registered floors; it performs no inference on import, refuses to start while a product gate process is visible, aborts and discards any episode during which a gate starts, pins the generated inputs once so both arms bind to the same bytes, validates every returned object in host code, retains a model's invalid output as a typed failure rather than discarding it, and redacts credentials from remote diagnostics. Thirteen deterministic tests over loopback doubles and the committed records run inside `npm test` under the `local-runner-double` suite; live runs happen only by explicit command.

**What the repair fixed.** The first verification found that the remote transport had rejected every T2 request before inference because the emitted schema used a keyword it does not permit, and that the collector had discarded the diagnostic, so a comparator floor was recorded as met without being measured. The repair removed the keyword while keeping the host's own duplicate rejection, made remote error events survive into the record, made an unmeasured comparator an explicit `null` that cannot qualify a task, declared the host's existing 40-character field bound in the T1 schema, and recollected the whole matrix under one build, twice, when the executor's own strengthened provenance check caught the input drift. No prompt, oracle, ranking, floor or cell count was tuned after trial evidence.

**An adjacent planning repair.** The planning-continuation check now admits the equivalent article and sentence spellings of the evidence-only release header that release preparation writes, while still refusing a changed axis, description or article; six fixture combinations cover it. This resolves a disagreement between two existing readers of the same line and grants no scope.

Known limitations, each labelled in the packet. The local T1 envelopes are schema-valid but their content is degenerate, a truncated prose fragment and bare commas, so the validity rate should not be read as contract understanding. The T1 schema does not declare the host's minimum field length, and one retained unexpected-input cell was rejected on that gap after the model had blocked correctly; the correction is named for the next T1 recollection because it would change the build hash this closed matrix is bound to. The remote comparator is one model over one transport; the T2 oracle is one person's ordering of one six-candidate fixture; and energy, memory and USD cost were not measured. Nothing here is a statement about model quality in general or a capability level.
