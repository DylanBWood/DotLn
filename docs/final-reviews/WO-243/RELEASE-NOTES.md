## Release overview

The checks an order owes at its closeout now follow the repositories the order changed, and every reader says the same thing. A target-only order runs its registered target gate and the launchpad document gate; an order that changed launchpad machinery, or resolved a machinery conflict at integration, still runs the launchpad's complete run; an integration that only adopted main's already-gated kit changes adds no run of its own. The executor's and reviewer's briefings, the integrate helper's owed list and completion's recorded advisory all read one selection, and a selection that cannot classify the order keeps the complete run and says why. This is for instances that drive target repositories through the kit, where a target-only closeout was told to pay a launchpad run nothing consumed; a launchpad order's own closeout is unchanged.

## Read before upgrading

Nothing is required of an instance. The executor's closeout step now says to run the checks the closeout selection names, which `npm run resume -- briefing` and `worktree integrate` print, instead of starting one complete run unconditionally; the reviewer's steps and the target clause the execution roles share read the same selection. The integrate helper's single "Affected checks (not run)" list is replaced by two lines: "Affected by main's merge" names the launchpad machinery suites main's change touched and nothing to run, and "Owed by this order" names the order's checks; a reader who ran `npm run publication:check`, `harness check` or `release check-surfaces --local` from the old list finds them in the structural phase of the document gate every order owes. An order already active when the instance takes this release re-runs nothing: its next briefing or integration prints the selection from its current changes, and until then a target-only order runs its target gate and the document gate. A target order whose criterion names `npm test` in any form keeps the complete launchpad run by the criterion's own words. No command, phrase, event or refusal is added, and no gate row is reused across a changed identity.

## Substantive changes

Closeout selection: `closeoutScope(root, order)` in `scripts/lib/closeout-scope.mjs` reads the order's `Repository:` field and activation, the paths its branch changed since the activation base or the main commit its latest integration took in plus every conflict its integrations resolved, the registration's gate and the checks its criteria name, and returns the target gate selection, `document` or `complete` for the launchpad, and the reasons; gate-input records and minted editions, kit files, launchpad source and configuration and declared suite inputs are machinery, the order's own record lanes and document files under record roots are documents, anything else is unclassifiable and keeps the run. Readers: the executor, fix, verify (target orders only), briefing and final-review briefings end with the selection spelled for the session's worktree; `implementation-ready` and `repair-complete` record it as one advisory; `worktree integrate` prints the owed list after a completed generation and after "took in nothing". Integrate helper: `mergedMachinery(root, before, upstream)` replaces `integrationTestCommand`, comparing the old head with the main commit taken in through `changedMachinery`'s new optional `head`, whose default callers keep their merge-base-to-working-tree semantics; the receipt carries `priorAuthored` so an earlier integration's resolved conflicts stay the order's. Role text: the executor's run and handoff steps, the reviewer's run, report and integration sentences and the shared target clause name the selection; the installed skills, hooks and manifest, the role oracle and the authority edition are regenerated. Documents: product 07 §Preflight before the full gate and §Independent workflows and integration and the kit guide's §What runs here, and what does not state the selection, its readers, the adopted-paths rule and the unknown case.
