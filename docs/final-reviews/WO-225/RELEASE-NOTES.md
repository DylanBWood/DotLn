## Release overview

Application v0.92.0 gives an instance's browser shell the platform contracts it reads, and nothing in them names a machine. The fork's UI pass of 2026-10-21 met a board whose failure reasons named the home directory, an export whose `npm run console` failed on a missing `tsconfig.json`, a Work panel empty in an instance with eight closed orders, a contract pinned by reaching into core, and no route from a browser to the board or the status. This release codes every board failure reason, strips the directory from a refused Beacon row, carries the two schemas in the kit, makes `npm run build` a no-op in a kit, reads an instance's control segments with an optional legacy log, and serves the status file and a board snapshot read-only over the resident's loopback to a local origin behind the command route's checks.

Audience: operators of exported instances who run a browser shell beside the resident; the fork's console order, which drops its mocks against this release; and operators who read `board --json` in core.

## Read before upgrading

- **The board names no path.** Every unavailable source carries one of five codes: `not found`, `not readable`, `invalid format`, `timed out` or `command failed (exit N)`. Raw exception messages, child stderr and refused Beacon directories no longer enter the board; a refused worktree row's age cell is the reason alone, such as `directory cannot be read`. A child ended by a signal or by its output limit is labelled `invalid format` for now; the repair rule is boarded ([D022](../../evidence/WO-225/decisions.md#wo-225-d022)).
- **Two read routes on the resident's loopback.** `GET /runtime-status-v1` returns the status file and `GET /uifa-board-v1` returns the board snapshot `console/uifa-board-v1.json` in the resident's store, as JSON file bytes. Both require the socket on `127.0.0.1`, a Host equal to `127.0.0.1` with the bound port, a local Origin or none, and the bearer token; a refusal is the command route's 403, and a missing projection or a failed refresh is 503 in the console refusal shape. The reads run outside the command lane and append no receipt or event. A snapshot absent or at least 30 seconds old is refreshed by one `console board --json` child under a 60-second timeout and a 16 MiB output bound, shared by concurrent readers and written atomically with mode 0600; a failed refresh keeps the previous file. A fresh snapshot is served as is, within the owner-only store directory's trust boundary. The command route's Host check now requires the bound port rather than any `127.0.0.1` port; clients that build the URL from the descriptor already send it.
- **The kit builds nothing.** `npm run build` in a kit prints `carried runtime is the build; nothing to compile` and writes no file, so `npm run console`, `npm run dotln`, `npm run skeleton` and `npm run harness` run on the carried runtime; `node scripts/bootstrap.mjs` remains the restoration command. The kit manifest lists `packages/console/uifa-board-v1.schema.json` and `packages/console/runtime-status-v1.schema.json`, byte-identical to core, and both labels are unchanged.
- **Segmented control reads.** The console collector reads `resume.jsonl` only when it exists and the per-order segments from the roots `dotln.config.json` declares (`roots.docs`, `roots.control`, `roots.orders`, with the documented defaults); a root that escapes the launchpad, including through a parent symlink, reads `not readable`. With a legacy log present the status fold is still cross-checked against the records.
- **Client exports.** `readRuntimeStatus(connection)` and `readBoard(connection)` join `invokeConsoleCommand` and `readConsoleContract` in `@dotln/console/client` and import no Node API. At the package root the existing `readRuntimeStatus(directory)` still reads a local file, and the network reader is `readConsoleRuntimeStatus`.
- **Versions.** Application v0.92.0 is a minor release over v0.91.0. Console moves from 0.4.5 to 0.4.6 and skeleton from 0.65.0 to 0.66.0; compiler 0.30.0, kernel 0.6.0, beacons 0.1.1 and browser-evidence 0.1.0 stay; the lockfile moves only the two workspace versions and no dependency is added. UI state an operator makes in a shell stays in a store the host owns; no core store is added.

## Substantive changes

**The console** (`packages/console/src/values.ts`, `collect.ts`, `builds.ts`, `text-sources.ts`, `console-client.ts`, `index.ts`). `readFailureReason` maps an error to one of the five codes and `attempt`, the loadout factories and the store readers use it; `controlRoots` derives the control roots from the configuration, `contained` compares realpaths, and the control source lists the legacy log only when present; `parseConstellation` keeps a refused row's reason and drops its directory; `readProjection` backs `readRuntimeStatus` and `readBoard`, and the package root re-exports the network reader as `readConsoleRuntimeStatus`.

**The resident** (`packages/skeleton/src/resident-host.ts`, `console-loopback.ts`). `ResidentBoardSnapshot` owns the snapshot: one pending collection shared by concurrent reads, a detached `console board --json` child with the resident's Node, a 60-second timer and a 16 MiB bound, a shape check on the output, an atomic rename with mode 0600, and a kill on timeout or shutdown. The loopback takes a board reader, serves the two `GET` routes after the socket, Host, Origin and token checks and before the command lane, answers 503 when a projection is unavailable, and requires the bound port in the Host.

**The kit** (`scripts/launchpad.mjs`, `scripts/build.mjs`, `scripts/lib/launchpad-fixture.mjs`, `scripts/test-launchpad-planning.mjs`). `KIT_FILES.files` and the export README grouping name both schemas; the build's main block returns the no-op line before `atomicBuild` when `isKitRoot` holds; both export fixtures copy the schemas into their synthetic sources.

**Tests.** The console suite gains the no-path case over the failure fixture, the empty-source schema case, a shared schema checker, the three-layout segmented-instance case with the lying fold, the escaped-parent-symlink case, and the real-resident projection-read case with its refusals, no-event assertion and blocked-invoke read; the skeleton suite gains three snapshot and refusal cases at `packages/skeleton/test/console-loopback.test.ts`; the launchpad export suite gains the kit case and forces the WO-226 recovery control through `atomicBuild`; the update suite checks the carried schema hashes; the case census becomes 37.
