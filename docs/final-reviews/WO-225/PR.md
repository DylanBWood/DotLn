# WO-225

An instance's browser shell can now read the platform through contracts the kit carries, and nothing in them names a machine. The fork's UI pass of 2026-10-21 met five states in a row: a `board --json` whose failure reasons named the home directory (scrubbed by hand before a fixture could be committed), an export whose `npm run console` failed on a missing `tsconfig.json`, a board whose Work panel was empty in an instance with eight closed orders, a contract an instance pinned by reaching into core, and no platform route from a browser to the board or the status. This order removes each. Every failure reason in the board is one of five codes (`not found`, `not readable`, `invalid format`, `timed out`, `command failed (exit N)`), the refused Beacon row shows its reason without the directory, and a test asserts that no string in the JSON contains the fixture root, the Node binary or the home directory. The kit lists `packages/console/uifa-board-v1.schema.json` and `packages/console/runtime-status-v1.schema.json` in its manifest, and `npm run build` in a kit prints `carried runtime is the build; nothing to compile` and writes nothing, so `npm run console`, `npm run dotln`, `npm run skeleton` and `npm run harness` run in an export as they do in core. The collector reads `docs/control/resume.jsonl` only when it exists and the per-order segments from the configured control root, so the Work and Actors panels fill in an instance with segments only, and the WO-164 cross-check still refuses a fold that returns orders the records lack.

The resident's loopback serves `GET /runtime-status-v1` (the atomically written status file) and `GET /uifa-board-v1` (a board snapshot the resident writes beside it) to `127.0.0.1` behind the same socket, Host, Origin and bearer-token checks as the command route, outside the command lane and without receipts; a non-local Origin, a wrong Host or a missing token is refused with the command route's 403. The snapshot is refreshed when a read finds it absent or at least 30 seconds old, by one bounded child run of `console board --json` (60 seconds, 16 MiB) that concurrent readers share; a failed refresh keeps the previous file and the route answers 503 in the console refusal shape, never an empty success. The browser client gains `readRuntimeStatus` and `readBoard`; the package root keeps its file reader and names the network reader `readConsoleRuntimeStatus`. UI state stays the host's: reading never writes a control record, and no core store is added. The console README names component 0.4.6, application v0.92.0, the three names (UIFA v0 as the board exported as `uifa-board-v1`, console v1 and the UIFA v1 shell as the instance's Angular shell), both routes and both kit paths; product 04 names the two read routes beside the one command route and the snapshot's bounds.
