## Release overview

DotLn v0.18.0 stands the lifecycle machinery down. A work order's transitions record their reports the moment they exist and never run or require a test gate. One product gate, `npm test`, runs once per order at final review, keyed by the code it tests so that reports, control events, generated projections and release text never invalidate it, and that row is the evidence the pull request, the tag manifest and the release close consume. Release close is the post-merge publish of the tag and Release and runs no suite. Attested harness, version, model and effort are logged as given and never refuse. DotLn's hooks refuse a second writer in a worktree and a write during the live gate, and delegate every other judgment to the host's own permission prompt on both harnesses. The default gate holds the suites that protect product and lifecycle behavior, each naming what it protects, and finishes fresh in about four minutes against ten; the machinery's own suites run on demand. The planning refuter judges goal alignment, system traps, constraint removal and antifragility, and a constructible counterexample is a known issue, never a hold.

## Read before upgrading

Source release target v0.18.0 includes compiler 0.10.0, skeleton 0.16.0 and console 0.1.6. Kernel 0.2.1 and third-party dependencies are unchanged; the lockfile diff is first-party component versions only. No package distribution or hosted service is introduced.

Lifecycle admission: `implementation-ready`, `repair-complete`, `verification-result` and `final-review-result` run `git diff --check` inline, validate the report and its actor attestation, and append. Missing gate rows, session authorship, output-read receipts, usage counters, stale projections and pending planning handoffs are advisory lines. An illegal phase or a missing or mismatched report still refuses. A verification pass no longer proves a product gate ran; the reviewer's committed row is that proof, and release close refuses without it or when the merged code identity differs from it.

Attestation: `--harness`, `--harness-version`, `--model`, `--effort` and `--source` are required as observations and recorded as supplied, including `unknown`. `ultra` and `ultra code` normalize to `xhigh` with `mode: subagents` and their raw spelling. No effort-below-declared, readback, discovery-row or version-minimum refusal remains in the lifecycle, the worker transport or the plan-refuter transport; each warns instead, and Codex launches in subagents mode no longer disable multi-agent features. `Effort:` lines in work orders are recommendations and accept `any` or a level with or without `+`.

Hooks and writer isolation: the generated hooks refuse exactly two things, a second live writer in the same worktree and a write to gate inputs or the success record during a live product gate. Unclassified tools, opaque command shapes, outside-root reads, the adapter-unavailable fallback, the read-scope observer and the attribution pre-check return a `DotLn advisory:` line and a journal row and leave the decision to Claude's permission mode or Codex's approval. The host deny list for `ssh`, `scp`, `sftp` and `npm publish` stays in settings. A writer reservation applies on main as on any other branch, so a session on main can build, bootstrap, read history and run the release helper. During a live gate the guard refuses any shell command whose write set it cannot bound, including `for` loops, command substitutions and most pipelines; `ls`, `head`, `grep`, `cat` and descriptor-only redirects are admitted, and redirect operands that begin with a shell-special character such as `!` or `=` are opaque. Rebuild and regenerate the harness from reviewed source when updating an existing installation; the manifest residue both harnesses need is emitted into the shared instruction block.

Gate and reuse: suite-result reuse is removed by design. Replica execution, declared-input keys, the shared success cache under the Git common directory, the kernel-denial probe and per-task expansion leave the runner with their machinery-only tests. Every invocation is fresh, against the working tree, one task per suite except the release cases. Stage intended new source files before the reviewer's gate; untracked files are outside the code identity. `npm run test:machinery` runs the fifteen machinery suites on demand; `npm test -- --review` adds only those whose declared sources changed since the base.

Planning: new refutation receipts use `plan-goal-review-v1` with verdicts `aligned`, `aligned-with-findings` and `misaligned`. Only an observed failure or a vision contradiction holds; hypothetical concerns are known issues with reopening observations. `npm run plan -- dispose` binds a disposition to criterion text so a later receipt cannot re-raise it; the third-hold stop, the 120 s budget refusal and the structural cost hold are removed. Historical receipts retain their bytes and identities. `npm run meta` prints each closed order's Cost promise beside observed gate rows and marks a measured shortfall as a planning input; nothing refuses on it.

## Substantive changes

- Lifecycle evidence: `scripts/lib/lifecycle-evidence.mjs` runs the inline whitespace check, records it, advises on every other observation, and carries the reviewer's passing `npm test` row into the `FinalReviewCompleted` event. `gateCodeIdentity` hashes tracked, non-generated code by path, mode and bytes; `findGateCheck` matches `npm test` rows by that identity and every other check by exact tree.
- Runner: `scripts/test-runner.mjs` classifies each suite as product, machinery or document with a `protects:` line, restores exclusive scheduling for the harness and process-debt fixtures (the faster measured WO-128 D010 configuration), runs release cases across four lanes, and records one `npm test` row with both identities. `scripts/lib/suite-replica.mjs`, `suite-sandbox.mjs`, their tests and the declared-input, replica and cache parts of `suite-evidence.mjs` are deleted.
- Release and worktree: `release close WO-NNN --publish` proves egress, fast-forwards main, checks surfaces, builds missing dist, validates a manifest citing the reviewer row with the reviewed and merge trees, publishes the tag and Release, then runs worktree finish and derived-worktree settlement as best effort and reports blockers without failing the close; `--dry-run` previews the same steps and manifest. `worktree publish` validates the committed reviewer row against the branch's code identity and adds its record to the PR body.
- Attestation and transport: `scripts/resume.mjs` validates presence only and warns on unrecorded values; `packages/skeleton/src/worker-transport.ts` and the plan-refuter host log version and effort observations and launch; the `ultra` normalization lives in `worker-protocol.ts`.
- Hooks and writer isolation: `packages/compiler/src/feedback.ts` carries writer-isolation version 2 without the main-branch conjunct; `packages/skeleton/src/harness-host.ts` refuses only a foreign live writer and a live-gate input write and answers everything else with an advisory; `harness-command.ts` admits `ls`, `head` and `grep`, resolves descriptor-style and append redirects to their real destinations, and treats shell-special operands as opaque. `packages/compiler/src/harness.ts` emits the same role text and the two invariants to both harnesses.
- Refuter: `packages/skeleton/src/plan-refutation-protocol.ts` validates the goal-review result, derives holds only from supported findings of `misaligned` orders, and refuses a second judgment in a pass unless observed evidence changed; `scripts/lib/plan-receipts.mjs` binds dispositions and overrides to criterion text.
- Cost reconciliation: `scripts/lib/meta.mjs` extracts the complete wrapped Cost paragraph, parses an explicit fresh-gate ceiling, and prints `PLANNING INPUT` on a measured shortfall.
