# WO-132 — One product gate per work order, keyed by the code it tests

A work order's lifecycle no longer runs a test suite at every transition. Each completion command runs `git diff --check` inline, validates that the report and its actor attestation exist, and appends its event; a missing gate row, session authorship, output reads, usage counters, a stale projection or a pending planning handoff are advisory lines, and only an illegal phase or a missing report still refuses. The product gate is `npm test`, run once by the final reviewer after the last source edit, and its success row is keyed by a hash of tracked, non-generated code outside `docs/`, `.claude/`, `.agents/` and root Markdown, with the exact tree recorded beside it. Reports, control events, index regeneration, the PR body and the release notes never move that key. The pull request carries the row, the tag manifest cites it with both the reviewed tree and the merge tree, and release close consumes it: it proves egress first, fast-forwards main, runs the surface checks, builds missing dist, validates the manifest, publishes the annotated tag and the Release, and then attempts worktree cleanup as best effort. It runs no suite, no `npm ci` and no CLI smoke row, and it refuses when the merge tree's code identity differs from the reviewed row.

The runner loses the replica execution, declared-input keys, shared success cache, kernel-denial probe and per-task expansion that the per-transition gate had justified; those modules and their machinery-only tests are deleted. The default gate holds the nineteen product and lifecycle suites, each declaring in one line what operator-visible behavior it protects (`npm test -- --list`), with the release cases as the only expansion. The fifteen machinery suites run on demand under `npm run test:machinery` and enter the reviewer's `npm test -- --review` only when a file under their own declared sources changed since the base; document-sensitive live checks stay in `test:docs`. Fresh on the operator's host the product gate runs in about 250 s with 62 tasks against the recorded 605 s and 82 tasks at v0.17.7 (three executor runs of 254.9, 250.5 and 246.2 s; three independent verifier runs of 240.4, 243.2 and 243.6 s).

Attested harness, version, model and effort are recorded as supplied and never refuse: the effort-below-declared, readback, discovery-row and version-minimum refusals leave `resume.mjs`, the worker transport and the plan-refuter transport, which warn instead; `ultra` and `ultra code` record `xhigh` with `mode: subagents` and their raw spelling; `Effort:` lines are recommendations. Writer isolation is one registered writer per worktree on any branch, so a session on main can build, bootstrap, read history and run the release helper under its reservation. DotLn's generated hooks now refuse exactly two things, a second live writer in the same worktree and a write to gate inputs or the success record during a live product gate; unclassified tools, opaque command shapes, outside-root reads, the adapter-unavailable fallback, the read-scope observer and the attribution pre-check return an advisory and a journal row and leave the decision to the host's own permission prompt. Both harnesses receive byte-identical role text carrying the two invariants. The planning refuter becomes a goal review: four questions per order, verdicts `aligned`, `aligned-with-findings` or `misaligned`, a hold only on an observed failure or a vision contradiction, constructible counterexamples recorded as known issues with reopening observations, dispositions bound to criterion text, and no third-hold stop, budget refusal or structural cost hold. `npm run meta` prints each closed order's promised removal beside its observed gate rows and marks a measured shortfall as a planning input.

Verification ran five times. VER-001 found the cost reconciliation truncating every wrapped Cost paragraph and the live-gate guard refusing ordinary `ls`, `head` and `grep` reads; VER-002, VER-003 and VER-004 each found one more shell redirect spelling (`>&word`, zsh's `>>&` with numeric or dash operands, and the `!` clobber-override forms) that the guard's destination adapter misread and therefore admitted into the built `dist` during a live gate; each was repaired with a parser regression and a generated-hook fixture against the real protected destinations, and the adapter now treats any operand that does not begin with a plain path character as opaque. VER-005 passed every criterion at the final source. The final review read the whole subject, ran the generated-surface, publication, authority, format and meta checks, and ran the single reviewer gate `npm test -- --review`; its row is recorded in the final-review event and reproduced below. See `docs/final-reviews/WO-132/FINAL-001.md`, `docs/verifications/WO-132/` and `docs/evidence/WO-132/decisions.md`.

Read before merging: the live-gate guard refuses any shell command whose write set it cannot bound while a gate is running in the worktree, including `for` loops, command substitutions and most pipelines, so use the host's read tools for those reads or wait for the gate; `ls`, `head`, `grep`, `cat` and descriptor-only redirects are admitted. Reuse of suite results is gone by design: the gate runs fresh, once. The next real order's one-gate control segment is a future observation named in the order's execution record. Compiler moves to 0.10.0, skeleton to 0.16.0 and console to 0.1.6 for application v0.18.0; kernel 0.2.1 and third-party dependencies are unchanged, and no user setting is in the tree.
