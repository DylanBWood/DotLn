## What this merges

WO-019, the `v0.3.4` patch work order: effort becomes a declared, attested, checked, and projected control-plane fact. Every newly activated work order declares a minimum effort per role beside its model line, every completion event carries the actor that produced it with an epistemic source label, the transition refuses a below-declared or unevidenced claim and a report whose machine header disagrees with its completion flags, and the control projection shows the latest attestation and within-order drift.

- **The defect:** effort lived in exactly one place, a prose table in the playbook, and that place was false for WO-001 through WO-003, where the executor ran at `low` while the table read `xhigh`. No document, script, or verification could detect the drift, and no executor's model, effort, or harness appeared in any committed artifact.
- **Declared per role.** The leading metadata header of a work order carries exactly one `**Model:**` field followed by exactly one `**Effort:**` field naming `executor`, `verifier`, and `reviewer` as `any` or a ladder minimum on `low < medium < high < xhigh < max`. Activation refuses a missing, duplicate, misplaced, reordered, or malformed declaration and names the line; `resume -- next` repeats both fields in the dispatch briefing.
- **Attested per completion.** `implementation-ready`, `verification-result`, `repair-complete`, and `final-review-result` require `--harness`, `--harness-version`, `--model`, `--effort`, and `--source`; the event records recognized values byte for byte and an unrecognized label as `unknown` plus the verbatim `raw` label. Values are single-line data, so a control character or line separator refuses before it can forge the projection.
- **Checked, not trusted.** The ladder check refuses an attestation below the role's declared minimum with a message naming both values and the amendment path; `unknown` satisfies only `any`; a recognized value is accepted only when discovery records it for the exact harness and version; `harness-readback` is accepted only where an observed effective readback is recorded, which today is nowhere; and there is no override flag.
- **Agreement by construction.** A verification or final-review report carries exactly one column-one `**Actor attestation:**` header with the normalized actor JSON, and the completion command compares it with its flags before appending, so the immutable report and its event confirm each other without the report inspecting a future event.
- **Projected.** `docs/control/current.md` gains `Latest attestation` and `Effort drift`; drift is the ordered set of distinct effort pairs within the active order, with an unrecognized value rendered as `unknown (raw: label)`. `status` stays read-only.
- **Forward-only.** New activations carry `effortDeclarationValidated: true`; a pre-WO-019 active order without the marker can finish under a visibly synthesized `any` declaration when its authority lacks an Effort field, while WO-019 itself and every marked activation are strict. History is not backfilled, and the dated migration note sits where readers meet it.
- **Discovery probe.** A bounded readback probe records, per harness and version, that Claude Code 2.1.259 documents a five-value `--effort` selector but no effective readback, and that Codex CLI 0.152.1 has an observed persisted selector but no dedicated session selector and no readback. Only the effort level was printed.
- **Docs and write-backs:** execution guide, playbook, domain model, verification and final-review READMEs, work-order map, ledger, the three not-yet-activated drafts WO-016, WO-017, and WO-018, and the downtime-series preflight. The work order's heading carries `v0.3.4` and its release block matches; the activation helper had left the planner's placeholder, and the executor forward-corrected it with disclosure, as WO-025 did.
- **Ideation breakouts, no code effect.** Two operator-opened breakouts are synthesized into the ledger and product docs as labeled candidates and future experiments; they change no code contract, acceptance criterion, schema, version, dependency, or authority.
