## Release overview

Effort is now a checked control-plane fact instead of a prose table that was silently wrong for three work orders. Every newly activated work order declares a minimum effort per role beside its model line; every completion event in the append-only control log carries the actor that produced it, with harness and version, model, effort, and an epistemic source label; the transition refuses a claim below the declared minimum, a recognized ladder value without discovery evidence for that exact harness version, a readback claim no installed harness can make, and a report whose machine header disagrees with the flags that complete it; and the control projection shows the latest attestation and any within-order drift. Audience: operators dispatching and closing work orders, executors and verifiers recording completions, and anyone reading the control projection to learn which configuration produced a piece of evidence. This is a source-only patch above `v0.3.3` with no change to exported runtime capability.

## Read before upgrading

- **Activation requires a declaration.** `resume -- activate`, and therefore `worktree start`, refuses a work order whose leading metadata header does not contain exactly one `**Model:**` field followed by exactly one well-formed `**Effort:**` field naming `executor`, `verifier`, and `reviewer` as `any` or as a ladder minimum written with a trailing plus sign, such as `xhigh+`, on `low`, `medium`, `high`, `xhigh`, `max`. The Effort field must follow the complete Model field apart from blank lines, both must sit above the first `**Objective:**` field or level-two heading, and a duplicate label anywhere in the file, including a fenced example, refuses. Existing drafts do not inherit a default; the planner adds the line before activation, and the WO-016, WO-017, and WO-018 drafts already carry one.
- **Completion commands take actor flags.** `implementation-ready`, `verification-result`, `repair-complete`, and `final-review-result` refuse without all of `--harness`, `--harness-version`, `--model`, `--effort`, and `--source`, print the usage line, and append nothing. Values are single-line data; a control character or Unicode line separator refuses. Use `not-applicable` for a structurally absent field and `unknown` for a value that exists but cannot be known.
- **A recognized effort needs evidence.** A ladder value is accepted only when `docs/discovery/environment.json` records that value for the exact harness and version through a selector or an observed readback; otherwise attest `unknown`. An unrecognized label is stored as `unknown` with the verbatim `raw` label and compares as `unknown`. `unknown` satisfies only a role declared `any`.
- **Readback is not available yet.** `--source harness-readback` is refused for both installed harnesses, Claude Code 2.1.259 and Codex CLI 0.152.1, because neither exposes an observed effective-effort readback; use `self-reported` or `operator-attested`. A self-report records a labeled claim about a selection, not an observed effective setting.
- **Reports carry one machine header.** Verification and final-review reports must contain exactly one line that begins at column one with `**Actor attestation:**` followed by the normalized actor JSON, and the completion command refuses when that header is absent, malformed, or different from its flags. Any header quoted from another report must be indented, blockquoted, or placed in a table cell.
- **No override flag.** A below-declaration attestation can proceed only after a dated operator amendment to the work order's Effort field, followed by rerunning the transition.
- **Forward-only migration.** Historical headers, events, and reports are not backfilled or invalidated. New activation events carry `effortDeclarationValidated: true`; a pre-WO-019 active order without that marker may finish under a visibly synthesized `any` declaration when its authority lacks an Effort field, while WO-019 itself and every new activation are strict.

## Substantive changes

- **Control plane.** `scripts/resume.mjs` parses the declaration at activation with the header-region, adjacency, and uniqueness rules and marks the activation event; parses the five actor flags with the single-line guard; gates recognized effort values on discovery evidence for the exact harness version; applies the ladder check for the role each completion action implies; scopes `harness-readback` to an observed readback for that version; compares the report's machine header with the completion flags before `verification-result` and `final-review-result` append; repeats both declaration fields in the `next` briefing; and projects `Latest attestation` and `Effort drift` in `docs/control/current.md`, where drift is the ordered set of distinct effort pairs and an unrecognized value renders as `unknown (raw: label)`. Control-log schema stays at version 1 and the fold of existing events is unchanged.
- **Discovery.** A bounded readback probe per harness and version is recorded in `docs/discovery/environment.md` and `environment.json` with the labels observed, documented locally, not found, and blocked. Only the effort level was printed; no settings path, scope, or surrounding content entered the repository.
- **Process documentation.** The execution guide's model-specific notes describe the mechanism and carry the dated migration note; the playbook's actor table points at the declared lines and demotes the earlier drift paragraph to history; the domain model pins the control-log `actor` record and marks it a candidate for runtime episode events; the verification and final-review READMEs state the header-agreement duty and how quoted headers must be laid out; the work-order map shows declared effort; the ledger records adoption beneath the 2026-08-31 effort-truth entry without rewriting it; and the downtime-series preflight names the planner's Effort duty.
- **Ideation write-backs with no code effect.** Two operator-opened breakouts during execution and repair are synthesized as explicitly labeled candidates and future experiments: recap-primed resident memory, work-order-scale effort experiments, local-inference calibration with a hybrid local-first route, compiled senses, phase-selective intervention restraint, external-target privacy, a Snooping Footprint Reducer, model-input exposure plans, a public Git with a local private evidence lane, influence response policies, and a nominated fictional source. Nothing in them is implemented, and none changes a kernel schema, roadmap rung, acceptance criterion, or authority.

## Evidence and compatibility

- **Verification trail.** `docs/verifications/WO-019/VER-001.md` failed the order on acceptance criterion 7 alone, after confirming criteria 1 through 6, 8, and 9 first-hand and finding no production-code defect; the repair was confined to `scripts/test-resume.sh`. `docs/verifications/WO-019/VER-002.md` passed it with `scripts/resume.mjs` byte-identical to the VER-001 subject, all six surviving mutants killed, and 68 single mutants plus 4 multi-guard combinations swept. `docs/final-reviews/WO-019/FINAL-001.md` passed it after re-establishing the evidence first-hand, comparing every report header with its control event by object comparison, and driving the shipped mechanism through an independent 25-command fixture probe.
- **The order's own transitions** were recorded through the mechanism it ships: executor readiness and repair as Codex CLI 0.152.1, GPT-5.6 Sol, `xhigh`, self-reported; both verifications as Claude Code 2.1.259, `claude-opus-5[1m]`, `max`, self-reported; the final review as Claude Code 2.1.259, `claude-fable-5-1`, `max`, self-reported. The projection's drift line reads `xhigh -> max`.
- **Compatibility.** Control-log schema 1 and the tag-manifest schema are unchanged; `packages/` is untouched, so kernel and skeleton versions stay at `0.1.0` and `0.3.0`; no dependency was added; `npm test` reports 78 of 78 node tests and every shell suite green; `git diff --check` is clean.
- **Known limitations.** A `self-reported` value is a labeled claim that the mechanism compares but cannot observe. The recorded Codex persisted selector value is what makes a Codex recognized-effort claim acceptable and goes stale when that setting or the harness version changes. The WO-019 activation event predates the parser and carries no validation marker, which is the designed strict boundary rather than a legacy fallback. The script names `WO-019` literally as that boundary. The `parseActor` structural guards are individually redundant, so a refactor could drop two at once without turning the suite red; the declaration grammar is exercised at two of its six levels; the final-review report containment refusal and the column-one header boundary have no test. `worktree start` creates the worktree before activation can refuse a missing declaration.
