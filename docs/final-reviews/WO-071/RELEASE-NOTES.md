## Release overview

A DotLn work order can now say which repository it changes. One leading line — `**Repository:**` followed by a repository id, an `@`, and a base commit — names a repository registered in the launchpad's configuration and the immutable commit the work starts from. The registration is public and lives in the committed configuration: an id, a base branch, a relative worktree parent, an opaque class for a later release to give meaning, and a complete authority profile in the domain model's `AuthorityEnvelope` shape. That profile reaches the compiled WorkOrder through the existing monotone authority floor, so it narrows what the work order may do freely, and widens it only through one deterministic grant that the registration itself produces and that carries `registered-repository` provenance and the repository's id. Before this release nothing in a work order said which repository it changed, and the founding "never push or open a pull request" rule was overridden per repository by hand. This release is for anyone preparing cross-repository work: it gives the target lifecycle a repository, a revision and an authority interface to consume, and it refuses the cases where any of the three is wrong.

## Read before upgrading

**Nothing changes for a work order without the field.** Absence means `self`, and it emits no new keys in the activation event, the current-state document, the JSON status, the orders list or the generated index. Existing activations, fixtures and projections keep their previous bytes, and the fixtures assert that rather than assuming it.

**A base commit is a commit, not a branch.** The field takes a full 40- or 64-hex object id. A branch name, a short id and an uppercase id all refuse, because a movable ref would not bind what the activation is a record of.

**A profile's allow list is not a ceiling.** Only `deniedEffects` narrows the active base. Registering `allowedEffects: ["repo.read"]` does not restrict a work order to reading; it declares an allowance, which is either already admitted by the base or carried by an explicit grant. To forbid something, deny it. This is the correct behaviour under the monotone floor and it is not what a reading of "the profile bounds the target" would suggest.

**Widening is exact or it is refused.** An allowance outside the active base must arrive as the one grant the registration produces, compared by canonical serialization. A grant with an extra effect, a wildcard allowance outside the base, a resource limit above the base or absent from it, and an existing grant that would override a profile denial each refuse rather than resolving in favour of more authority.

**No physical path is registered or recorded.** The configured worktree parent is relative, and it appears in no lifecycle event and no projection. Creating anything in a target repository is not part of this release.

**A malformed registration refuses as a stack trace.** It names the configuration path and the exact field, so the refusal is complete, but it surfaces as an uncaught throw during module initialisation rather than the clean `error:` line that the unknown-id and missing-base refusals print. The cause is inherited from the previous release's configuration loader and is unchanged here.

## Substantive changes

**The field and its parser.** A shared leading-metadata parser, used by both the lifecycle and the index generator, accepts exactly one `**Repository:**` line in the leading block. Two lines refuse as a duplicate; a line below the leading metadata is not parsed at all; a malformed id or base names the work-order path and the expected form. The index renders the pair on the order's row, and the index generator refuses when a committed order's declaration no longer matches its recorded activation — in either direction, a changed base or a removed field.

**A positively decoded registration.** The configuration's `repositories` section is no longer opaque. Each key is validated as a public id, `self` is rejected as implicit, and each value must carry `baseBranch`, a relative normalized POSIX `worktreeParent`, an opaque `repositoryClass` and a complete `authorityProfile`. Unknown keys at either level refuse by name. Effect patterns must be exact ids or terminal-prefix globs; a bare `*` is refused, so a total deny-all cannot currently be expressed. Resource limits must be non-negative safe integers, expiry must be a non-negative safe integer, and revocation conditions must be well-formed predicate references. Every refusal names the configuration path.

**Activation that records identity and nothing else.** Activation resolves the declared id against the launchpad configuration — by own key, so an id that happens to name a JavaScript object member is unknown like any other — and appends `repositoryId` and `baseCommit` to the `WorkOrderActivated` event. The control fold validates that pair on every read, rejecting `self`, a malformed id, a malformed base or one field without the other. Unknown id, missing base and malformed profile all refuse before the event directory is created.

**A registered profile compiled through the floor.** Profile denials are removed from the active envelope's `allowedEffects` and the WorkOrder's `allowedOperations` and added to both denial lists. Resource limits may only shrink; expiry takes the minimum; required evidence, revocation event types and revocation conditions union. An allowance the base already admits produces no grant. Each exact allowance outside the base is carried by one grant whose id is built from the repository id, with `grantedBy: "registered-repository"` and the repository id as its `repo`, and the compile refuses unless the caller supplies that grant byte for byte.

Known limitations, each owned. The profile compile has no production caller: it is reached only from its test, and the first consumer is the target-worktree lifecycle that follows — the same boundary the previous authority release recorded for its own adapter. Criterion 2 is therefore established against the compiler's synthetic authority fixture rather than a shipped loadout's real envelope; the semantics are proved, the behaviour against a real loadout is untested. The registration schema refuses a bare `*` effect pattern although the domain model admits it, so a deny-all profile cannot be expressed; the direction is fail-closed. A profile requires exactly one active mechanic in the graph and raises an invalid-graph error otherwise, which today's loadouts cannot reach. The malformed-profile refusal presents as a module-load stack trace, inherited unchanged from the configuration-root release. `worktreeParent` accepts `..` segments by design, because a target's worktree parent is a sibling of this checkout; only unnormalised paths refuse, and resolving one to a real directory belongs to the next release. Final review made two changes to the subject and re-ran the full gate afterwards: a two-line own-key guard so a repository id naming an object member refuses by name instead of raising a type error, with a regression assertion; and three reindented continuation lines in one publication table of contents. The order's cost declaration remains a legacy unavailable line: no measurement of added or removed wall-clock, context, commands, tokens or steps is claimed for this change.
