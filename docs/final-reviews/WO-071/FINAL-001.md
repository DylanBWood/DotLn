## The defect I met, and fixed

`compileRegisteredRepositoryLoadout` resolved its registration with `loadConfig(root).repositories[repositoryId]` and tested the result for truthiness. `repositories` is an ordinary object literal, so an id naming an `Object.prototype` member resolved to the inherited function, passed the truthiness test, and reached `repository.authorityProfile` as `undefined`. Observed at the reviewed tree before the fix, against a launchpad with an empty `repositories` map and a one-mechanic graph:

```
ghost          -> Error: unknown registered repository id "ghost"
toString       -> TypeError: Cannot read properties of undefined (reading 'allowedEffects')
constructor    -> TypeError: Cannot read properties of undefined (reading 'allowedEffects')
hasOwnProperty -> TypeError: Cannot read properties of undefined (reading 'allowedEffects')
```

All three prototype-member ids above satisfy the order's own id grammar `[A-Za-z0-9][A-Za-z0-9._-]{0,63}`. The behaviour is fail-closed — no authority is admitted — but the refusal is an unnamed stack trace where the contract promises `unknown registered repository id`, and the sibling resolution in `scripts/resume.mjs` already guarded with `Object.hasOwn`. I took it as a bounded reviewer cleanup on the WO-069 D017 precedent: it is a two-line change inside this order's own new function, it makes the compile path agree with the activation path it was written beside, and WO-072 is the first production caller of exactly this function, so the alternative is handing WO-072 a stack trace to diagnose. A regression assertion for `toString` now sits beside the existing `absent` case in the WO-071 authority-grant test, and the whole gate ran after the edit. Recorded as [WO-071-D005](../../evidence/WO-071/decisions.md#wo-071-d005) with its rejected alternatives: leaving it as an observation, giving the loader a null-prototype map, and denylisting member names in the id grammar.

I also reindented three continuation lines in `docs/publication/everyday-ai-user-toc.md` that the write-back had left at four spaces among six-space neighbours. Markdown is `.prettierignore`d, so no gate would have caught it; the render is unchanged and the diff is now exactly the added claim.
