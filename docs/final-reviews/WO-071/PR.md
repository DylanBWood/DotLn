# WO-071

A work order can now declare `**Repository:**` with a repository id, an `@`, and a base commit in its leading metadata, and DotLn resolves that id against a public registration in the launchpad configuration: a base branch, a relative worktree parent, an opaque class, and a complete `AuthorityEnvelope`. Activation records the repository id and the immutable base commit and nothing else — no configured path, no physical path, in the event or in any projection. The registered profile reaches the compiled WorkOrder through WO-042's monotone floor, so it can narrow the active base freely and can widen it only through one deterministic `registered-repository` grant that the committed registration itself produces. Until now the founding "never push or open a pull request" rule was overridden per repository by hand, and nothing in a work order said which repository it changed.

**The field, and what it deliberately does not carry.** One leading line, parsed beside the existing header fields, with the base as a full 40- or 64-hex object id — a branch name is refused, because a movable ref would not bind the activation subject. Absence means `self` and emits no new keys at all: `renderOrder` wraps the line in a conditional that yields the empty string and both JSON projections spread a conditional object, so every existing activation, fixture and projection keeps its previous bytes. The fixture proves the omission rather than assuming it, asserting that a registration whose worktree parent is `../target-worktrees` produces an event and a current-state document in which that string does not appear. Duplicate lines, a line after the leading metadata, a short or uppercase object id, an unknown id and a malformed profile each refuse, naming the work-order or configuration path, before any lifecycle event is appended.

**Authority narrows by default and widens only on the record.** Profile denials are removed from the active `allowedEffects` and `allowedOperations` and added to both denial lists; resource limits may only shrink and a resource the base does not carry refuses; `expiresAt` takes the minimum; required evidence, revocation event types and revocation conditions union. An allowance the base already admits produces no grant at all. An exact allowance outside the base is carried by one grant with `grantedBy: "registered-repository"` and the repository id as its `repo`, compared by canonical serialization so a tampered or extra-effect grant refuses rather than passing as "a grant was supplied". A wildcard allowance outside the base refuses as unrepresentable instead of quietly broadening the definition, and an existing graph grant that would override a profile denial refuses instead of weakening the registration. One thing to read before building on this: a profile's `allowedEffects` does not act as a ceiling — only `deniedEffects` narrows — which is the decided semantics and the correct reading of the monotone floor, but not what WO-033 phase 2's prose suggests.

**What a reviewer should know before merging.** The profile compile has no production caller yet — `compileRegisteredRepositoryLoadout` is reached only from its test, and WO-072 owns the first consumer, which is the boundary WO-042's review recorded for the same reason. Criterion 2 is therefore proved against the compiler's synthetic authority fixture, not against a shipped loadout's real envelope. A malformed profile refuses as an uncaught module-load throw rather than a clean `error:` line: it names the configuration path and the exact field, so the contract holds, but the presentation is inherited from `loadConfig` running during `resume.mjs` initialisation in WO-069 and is unchanged here. The registration schema refuses a bare `*` effect pattern, so a total deny-all cannot be expressed even though the domain model admits the pattern — fail-closed, and worth WO-073's attention. `worktreeParent` accepts `..` segments by design, because a target's worktree parent is a sibling of this checkout; only unnormalised paths refuse. Final review changed two things in the subject: a two-line `Object.hasOwn` guard in `compileRegisteredRepositoryLoadout`, because a repository id naming an `Object.prototype` member — `toString`, `constructor`, `hasOwnProperty`, all legal under the order's id grammar — resolved to the inherited function and died on a `TypeError` instead of refusing by name, with a regression assertion added and the whole gate run afterwards ([D005](../../evidence/WO-071/decisions.md#wo-071-d005)); and three continuation lines in one publication table of contents reindented to match their neighbours.
