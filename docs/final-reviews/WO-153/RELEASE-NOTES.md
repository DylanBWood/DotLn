## Release overview

A Codex-launched lifecycle dispatch can no longer lose its report path because its harness session failed to begin. When `next`, `fix`, `verify`, `final-review` or `release-close` runs from a Codex thread and the session entry throws for any reason other than the already-began case, the dispatch now writes one stderr advisory naming the host's error and ending `process cost remains unknown; cause no-session`, then prints its briefing and exits 0. Before this release the same failure exited 1 after `verify`, `fix` or `final-review` had already recorded its transition, so the briefing carrying the allocated report path would not appear, the role text forbids repeating the dispatch, and the operator would have had to recover the path by hand (WO-149 D009). The path was reproduced by probe and never observed in a live dispatch. This is for whoever drives lifecycle work from Codex: a measurement problem is now reported as one, and the work continues.

## Read before upgrading

No event, envelope, schema, counter format, role text, hook behavior or dependency changes, and no existing record is rewritten. Two behaviors change. First, a Codex dispatch whose session entry fails now exits 0 with the advisory on stderr instead of exiting 1; anything that relied on that exit code to notice a broken session store should read stderr for `DotLn advisory: Codex session entry failed (`. Second, `beginHarnessSession` now removes the session record it has just written when appending the entry observation fails, and rethrows the original error; a later `harness usage` reports `no-session` and both the next dispatch and `node scripts/harness.mjs begin` can retry, where before the half-made record made a retry refuse or stay silent. Skeleton moves to `0.38.1` and the console's exact pin follows it. The authority and feedback evidence editions are re-minted as WO-153 revision 001 and selected in `docs/evidence/current.json`; artifact identity and verification stay at WO-157 revision 001.

## Substantive changes

**Session entry is advisory at dispatch.** In `scripts/resume.mjs` the Codex branch wraps its begin step, the import of the built harness host and the `beginHarnessSessionOnce` call, in one catch. The already-began refusal is still absorbed silently by the adapter, a successful begin and a threadless dispatch are unchanged, and the unbuilt-runtime advisory keeps its own wording. Every other error is named in the advisory with its own message, so an invalid role, a missing identity or an unwritable store stays visible rather than becoming an unnamed unknown. Nothing is retried.

**A failed begin leaves no half-made session.** Verification showed that the host wrote the session record before appending its entry observation, so an append failure left a record behind: the advisory said `no-session` while a later usage readback measured from the record, and a repeat dispatch treated the session as begun. The host now withdraws that record before rethrowing, which makes the advisory's cause true for every caller.

## Progressive polish

The 31 generated harness surfaces were regenerated for the new pinned runtime snapshot; they differ from the previous surfaces only in the snapshot path and the `harness-host.js` hash, and hook behavior is unchanged. The WO-153 fixture in the existing `process-debt` machinery suite adds no product-gate suite or fresh task. The work-order index, control projection, decisions index, follow-up register and the everyday edition's source lock reflect the completed order. None of this changes observable semantics, saved-data interpretation, compatibility, authority or any operator action.
