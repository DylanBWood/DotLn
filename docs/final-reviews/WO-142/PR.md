# WO-142

Reviews since WO-003 logged defects and nominations that no order owned, and the feed meant to surface them had stopped working: every decision record was harvested as a pending follow-up, so it grew from 359 to 399 entries in two days and three planning passes selected nothing from it. This order fixes the collector, so a decision enters the feed only when its JSON names a `followup` or records an observed reopening; gives executor, verifier and reviewer one rule, that a defect met and not fixed is boarded as a decision with a named follow-up and never left as a sentence in a report; and then clears the backlog. Of the 51 row groups in the [row dispositions](../../evidence/WO-142/rows.md), all are fixed with a named check except A7, which did not reproduce before any edit, and the non-starred half of B12, returned with a follow-up because its correct fix changes the replay fold ([D002](../../evidence/WO-142/decisions.md#wo-142-d002--preserve-replay-behavior-when-returning-resident-noop-identity)). No starred row is returned.

**What changes in daily use.** An order carried by a refutation receipt stays carried when activation stamps a version into its title, so that no longer forces a paid re-judgment. Every `resume` transition refreshes the work-order index, which ends the first `npm run test:docs` failing after each `verify` or `final review`. A Claude Code session is told the truth about its background tasks: dispatches are journaled, `completed`, `failed`, `stopped` and `killed` are all terminal, and the first terminal state and time stand. During a live gate the guard admits `tail`, `wc`, `ps`, `sed -n` with a line range and bounded `git --no-pager status`, `log` and `diff`, and still admits everything it admitted before. `node scripts/harness.mjs prune` lists local residue and deletes only with `--apply`.

**Node 26 and TypeScript 7, at the operator's request ([D010](../../evidence/WO-142/decisions.md#wo-142-d010--integrate-main-and-upgrade-node-and-typescript)).** Every manifest declares `engines.node` as `>=26.0.0 <27` and `.node-version` pins 26.9.0, so Node 22 is no longer supported: switch Node, then `npm ci`. TypeScript is pinned at 7.0.2; the lockfile adds only the compiler's platform packages and `@types/node` 26.6.2. WO-084 was integrated by fast-forward to `c5b2b0e7`; its ledger, Resolutions page, lineage index and script are byte-identical to `main`, and a fetch during final review found nothing newer.

**Seven inputs now refuse**, which is why this is a minor release, `v0.32.0` above `v0.31.2`: a claim-free bare `*` pattern, a lens scope with glob characters or padding, an unknown skeleton CLI argument, an appended event whose envelope does not decode, an `Assisted-by:` trailer, surplus words after a `worktree publish` title, and a generated heading shape in release notes. Components: kernel 0.6.0, compiler 0.15.0, skeleton 0.28.0, console 0.1.7. The [release notes](RELEASE-NOTES.md) carry the full read-before-upgrading list.

**Validation.** The final-review gate `npm test -- --review` passed 35 suites with 0 failures in 307.84 s under Node 26.9.0, at code identity `b9bd4886`. Verification took four rounds and the failures are the useful part: [VER-001](../../verifications/WO-142/VER-001.md) found four rows that passed their fixtures and failed in real use, [VER-002](../../verifications/WO-142/VER-002.md) an unrecognized `killed` status and a read class only partly restored, [VER-003](../../verifications/WO-142/VER-003.md) a finished task demoted by a later observation, and [VER-004](../../verifications/WO-142/VER-004.md) passed with live observation, thirteen targeted mutations and a replay of 185 transcripts in which no finished task is misstated, against 41 before. [FINAL-001](FINAL-001.md) staged three new source files before its gate, because the gate's code identity lists tracked files only and would have omitted them at release close.

**Before running prune on `main`.** The operator's apply on this worktree is recorded in [D021](../../evidence/WO-142/decisions.md#wo-142-d021--record-the-operators-prune-apply-and-the-integrated-tree-observations); it also removed the 97.8 MB dead cache for `main`, because that cache lives in the shared Git directory. A read-only plan lists 58 candidates and 96.5 MB on `main`. An apply there is projected at about twenty minutes, because it re-checks publication for every retained lane before each deletion; it is fail-safe and can be rerun. All 18 markers on `main` are in the older format and will be kept, as will two lanes that hold nested repositories ([D022](../../evidence/WO-142/decisions.md#wo-142-d022--board-up-two-prune-limits-met-at-final-review)).

**Left open, each owned.** Twelve of this order's 23 decisions board a follow-up with a reopening condition; the feed on this tree reads 430 total, 93 pending, 12 untriaged, beside 364 untriaged before the planning pass settled it. The ones a reviewer may care about: the guard still over-refuses a quoted word containing `*`, `?` or `[` and any `<` redirect (D018), an admitted `git diff` can refresh the index (D012), the product gate leaves target receipts in a checkout that pin its snapshots (D022), and neither worker CLI has yet accepted the refuter's new result schema live (D023). Nothing in `packages/skeleton/src/reactor.ts`, the ledger or any immutable report changed.
