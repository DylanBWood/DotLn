## Release overview

DotLn `v0.6.0` is the minor release above the published `v0.5.2`. Every evidenced episode in the walking skeleton can now be read from one metadata sweep: an optional Beacon file whose exact byte size is a published codeword for the episode's latest consequential action class, outcome, capped refusal count, provenance, and codebook version; whose modification time is the virtual time of the event that state was derived from; and whose content is the matching L0 receipt inside a rebuildable projection record. A reader learns the state of a directory of episodes with `stat` alone and never has to open a file. The fake executor separately writes an explicitly self-reported claim before its result exists, and the constellation listing shows that claim beside the host's evidenced projection with both provenances decoded, so a worker's own story never overwrites the host's evidence. Audience: the operator and any agent that needs a cheap, exact, non-invasive reading of episode state before paying for receipts; WO-021 is the nominated control-plane consumer. Without `--beacons`, the skeleton's output is byte-identical to `v0.5.2` apart from its package-version banner. The order's operator-authorized ideation breakouts ride along as documentation and planning only: executor-owned documentation freshness, the Protíno path correction, a readable proposed work sequence in the generated index, a proposed beacon usefulness checkpoint, an automation direction, and candidate resource-pressure, budget-window, concurrent-workflow, tenant-track, constraint-admission, and Actor UI (UIFA) material. Component versions: `@dotln/skeleton` advances from `0.5.0` to `0.6.0`; `@dotln/kernel` `0.2.1` and `@dotln/compiler` `0.2.0` are unchanged with no `src/` change and no dependency added.

## Read before upgrading

- **Beacons are opt-in and disclose state through metadata by design.** Nothing is written unless `--beacons` followed by a directory path is passed exactly once. When it is, byte size reveals every codebook field, and file existence and mtime reveal activity and recency to any observer who can reach the path, even when content reads are denied. Content permissions are not metadata secrecy; choose and protect the directory before exposing its path. The provenance field labels the emitting channel and does not authenticate the writer; no padding, check residue, or opaque address provides secrecy or authenticity.
- **The beacon directory must be explicit and, inside the repository, gitignored.** A destination inside the repository refuses unless `git check-ignore` accepts it (`/.beacons/` is now ignored); any path under `docs/intake`, including through a symlink alias, refuses; a non-directory destination refuses; a directory outside the repository is accepted. Writers replace only their own stable addresses and never purge other files in a reused directory.
- **Default output changes only its banner.** `npm run skeleton` with no flags prints `@dotln/skeleton v0.6.0` on its first line; every other byte equals the `v0.5.2` output, and no file is created.
- **The codebook is versioned data, not prose.** The normative v1 JSON block in the domain model is equality-tested against the shipped `BEACON_CODEBOOK`. Sizes off the lattice decode to `malformed`; framed sizes carrying a future version decode to `unknown-codebook` with the version only; no size ever decodes to a guessed state. A future codebook is a new version, never a reinterpretation of v1 sizes.
- **Beacon content is the L0 receipt, with its scope, actor, action, outcome, time, and evidence link.** Anyone who can read the file reads that receipt. A self-reported claim file holds a labeled claim record and is never an L0 receipt.
- **Dates in the demo constellation are 1970-relative** because the demo's events and the fake claim use virtual milliseconds; the mtime is derivation time, not wall-clock write time.
- **The historical Protíno path is now a pointer file.** `docs/product/11-proteino.md` keeps its sixteen heading anchors and links each to `docs/product/11-protino.md`, where the current document lives; the display name is `protíno` and ASCII `protino` is accepted. Older citations still resolve; new links should use the new path.
- **The generated work-order index changed shape.** `docs/work-orders/README.md` now opens with the operator's proposed sequence from the marked block in `docs/planning/work-order-map.md`, with check marks derived from passing final review in the control log, and lists complete per-order evidence below instead of wide tables. A missing or malformed sequence block, a duplicate ID, or an ID without an authority makes `npm run work-orders -- index` refuse; the reference-link address of every work-order file is unchanged.
- **Documentation freshness is the executor's duty.** The execution guide, publication compiler, and playbook now state that the change which makes a fact different owns the same-pass documentation update, the verifier checks it, and final review closes the consistency pass; a dedicated publication order is for edition assembly or broad editorial repair, not a queue for stale facts.

## Substantive changes

- **Skeleton: pure Beacon codebook (`packages/skeleton/src/beacon.ts`).** `BEACON_CODEBOOK` v1 (base 8192, stride 64, check `(code * 17 + 11) % 64`, version radix 4, outcome radix 3, refusal radix 4, two provenances, and the seven consequential action classes in most-significant-first order so a size-sorted listing groups lifecycle classes); `encodeBeaconState` and `decodeBeaconSize` over 104 assigned states, the largest 51,064 bytes; `deriveBeaconProjections`, which folds the existing audit/L0 projection in append order into one `BeaconProjectionRecord` per `(workstreamId, episodeId)` with the cumulative `authority-decision/denied` count capped at three; and one `encodeBeacon` that derives content (UTF-8 JSON padded only with trailing newlines), codeword size, and mtime from a projection record or a `BeaconClaimRecord`, refusing oversized records and unrepresentable times before any write. The module does no I/O.
- **Skeleton: filesystem edge (`packages/skeleton/src/beacon-fs.ts`).** `validateBeaconDirectory` enforces the explicit-directory, gitignored-inside-the-repository, never-under-`docs/intake`, and canonical-path rules; `beaconAddress` is a SHA-256 of producer and scope only, so no status, version, or codebook state is spelled in a filename; `createBeaconWriter` stages each complete file in a private sibling temporary directory, sets and re-verifies the exact size and nanosecond mtime (with a measured half-microsecond centering for Node's seconds-to-time conversion), and atomically renames it into place; `sweepBeacons` enumerates a directory and reads metadata with non-following `lstat` only, never content, labeling links and other non-regular entries `malformed`; `renderConstellation` prints size, mtime, decoded state, refusals (`3+` at the cap), provenance, codebook version, and address in size-then-address order.
- **Skeleton: scenario and CLI.** `runScenario` accepts `onEvents` and `onExecutorClaim` observation edges; the live driver projects after every appended event and after recovery; the fake executor emits its `verification/passed` claim before `CommandResult` exists and never again on a deduplicated re-dispatch; the scenario result with and without the edges is deep-equal, so no log, decision, or adapter effect changes. `--beacons` followed by a directory path composes with `--audit` and `--compiled-diff`, refuses a missing or duplicated argument before writing, and prints the constellation decoded from `stat` alone; the demo's two rows are the executor's `verification/passed` claim at 37,216 bytes and the host's terminal `external-effect/observed` state (the existing `schedule.cancel` receipt, one refusal) at 49,764 bytes.
- **Tests.** Fourteen new tests: exhaustive round-trip of every v1 state and every integer from 0 through 102,128 against an inline framing oracle; decoder refusal of unsafe, fractional, negative, and out-of-range inputs and a future-version frame at 10^30 scale; live-versus-replay identity by `readFileSync`, `cmp(1)`, `st_size`, and `mtimeNs` with the audit inputs proven unchanged; fold scoping, refusal capping, and append-order precedence under clock regression; UTF-8, padding, overflow, and mtime refusals; a mode-000 file and garbage content at preserved size both decoding identically; the premature claim beside unchanged host bytes and mtime before either result or verification; 128 synchronized atomic replacements observed by a worker thread with no off-lattice size or partial name; destination, alias, non-regular-file, changed-directory, and record refusals; future-codebook, malformed, and non-regular labeling; and the CLI's byte-identity to the committed `v0.5.2` base fixture apart from the banner.
- **Discovery.** `docs/discovery/beacon-probe-2026-09-04.md` and its JSON transcript record a fresh, bounded observation of every requested channel with Principle 15 labels (`st_size`, `utimes` mtime, `rename`, sparse `truncate`, file and directory permissions, name limits and case folding, symlink target limits, xattr, and Node's timestamp conversion), an honest `observed-not-exposed` for filesystem identity, and the reason size was chosen for v1 over symlink targets, names, and xattrs; `scripts/probe-beacon.py` reproduces it.
- **Product documentation for Beacons.** Architecture adds the Beacon as the cheapest rendering of the shared world; the domain model adds the `Beacon`, `BeaconCodebook`, and `BeaconObserved` rows and the normative v1 codebook block with its framing arithmetic and record shapes; interfaces add the constellation row to the sparse twin and the blur/near-transparent staleness grammar with thresholds deferred to WO-021; audit adds the `M0 beacon` rung below `L0 receipt` with its audience, access rule, omissions, retention, and metadata leak; the capability table adds `projection.beacon` at level 1 with its blocking gate; the root and skeleton READMEs document the invocation, the two demo rows, and the disclosure; the ledger records the adopted, transformed, and preserved Beacon entries.
- **Planning tooling: readable work-order index.** `scripts/work-orders.mjs` parses the single marked sequence block in the planning map, renders the proposed order with control-derived progress and short labels first and complete per-order details below, and refuses missing, duplicated, malformed, or unknown entries and an escaped planning path without mutating the index, control log, or refs; `scripts/test-work-orders.mjs` covers the layout, complete detail retention, explicit ordering, close and failure marks, changed-recommendation detection, invalid input, and the earlier release-evidence cases.
- **Documentation ownership and the Protíno path.** The execution guide, publication compiler, and playbook gain the freshness-and-ownership rule; current Protíno content moves to `docs/product/11-protino.md` with the old path reduced to compatibility pointers and mutable inbound links updated; the publication index and both audience outlines follow.
- **Ideation breakouts (documentation and planning only).** Ledger entries and product/planning write-backs for the automation direction (architecture and execution discipline), the resource-pressure environmental modifier (architecture candidate with domain-model and roadmap cross-references), budget-window work-order ladders with a Fable planning handoff (`docs/planning/budget-window-work-order-ladders.md`, roadmap, map, and the playbook's concurrency correction), concurrent workflows and delegated compatibility choices (IR compatibility and workstream application), tenant-scoped tracks and constraint-aware admission (roadmap, architecture, handoff), the proposed beacon usefulness checkpoint (`docs/planning/beacon-usefulness-checkpoint.md`, roadmap, map), and the Actor UI direction with the proposed UIFA name and its sound associations (vision, interfaces, audience outlines). Each is labeled candidate, preserved, or proposed; none adds a runtime, schema, acceptance gate, or authority.
