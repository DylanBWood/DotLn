## Release overview

This release gives core a record of its sibling repositories that no one maintains by hand. A generated page, `docs/siblings/README.md`, lists each declared sibling with its purpose, its upstream relation to core, the kit version, core commit, manifest hash and build hash it carries, its receipts, and the orders closed in core between consecutive receipts. Every `launchpad export` and `launchpad export --update` into a declared sibling writes the receipt the page is built from, inside the command's own manifest step, and regenerates the page. The release is for the operator who exports and updates the starter, and for the planning passes that name a sibling's version: the manual lookup of a sibling's manifest commit and build hash in its own checkout is removed, and the recorded version becomes a committed receipt instead of memory.

## Read before upgrading

- **New document root.** `siblings` (default `docs/siblings/`) joins the configuration loader's root list and product 07. An instance that relocates its roots may declare `roots.siblings`; receipts sit under the configured `evidence` root, so no new key is needed for them.
- **Receipts land in core's evidence tree.** An export or update whose destination resolves to a declared sibling writes one JSON receipt under `docs/evidence/siblings/` in the launchpad it exported from, in a directory named by the sibling and a file named by the receipt's date. The receipt belongs to the change in which the operator ran the command and is committed with it. An undeclared destination writes nothing, and the command says so.
- **A new document-gate row.** `siblings index --check` runs in `npm run test:docs`. It refuses a hand-edited entry, an entry whose manifest hash is not its latest receipt's, a receipt it cannot decode, and a captured tag observation that Git does not hold at the required relationship. A tag deleted from Git after generation refuses the row until `node scripts/siblings.mjs index` regenerates the pair.
- **Two generated files.** `docs/siblings/README.md` and `docs/siblings/tag-observations.json` are generated and are regenerated by `worktree integrate`; change an entry through the declaration or a receipt, never there.
- **Update journal.** `launchpad export --update` writes `KIT-MANIFEST.pending.json` beside the manifest before its first kit write and removes it after the last. A destination that holds one is an interrupted update, and the retry consumes it.
- **Versions.** Application v0.74.3 is a patch release over v0.74.2. No component version changes, and no dependency is added.

## Substantive changes

**Sibling declaration and registry.** `docs/siblings/siblings.json` declares each sibling once: a public repository name, its purpose, its relation (an export of core at a named commit, or a consumer of a named contract version) and a typed list of capability-row ids. The starter is declared as an export whose commit is not yet evidenced, and the Angular consumer as a consumer of `uifa-board-v1`. The generator reads the declaration, every receipt, and this repository's tags and committed control records at each receipt's commit. A commit this repository does not hold reads "not evidenced" rather than refusing, and every field no receipt supplies reads "not evidenced".

**Receipts inside export and update.** The destination is resolved before the build and before any write, so a malformed declaration refuses there. After the manifest is written, the receipt is written whole beside its final name and linked into place, so a second receipt of the same date refuses rather than overwrites. The command then regenerates the registry through the generator's own write path and prints the receipt path and whether the page changed. The receipt is the launchpad's evidence, never the export's content.

**The check's expected versions come from Git.** Generation captures the tag at each receipt commit and the nearest tag below it in `tag-observations.json`, so an unedited page stays current after a later tag is added, and the check reports the later tag as newer evidence. Before using a captured name, the check validates it against Git: an exact tag must appear in `git tag --points-at` the receipt commit, and a nearest tag in `git tag --merged` it, by literal name, so revision expressions, full refnames, prefixes and tags at other commits refuse. Two verifications found that an invented version written into every generated copy passed; the repairs closed the class.

**Update repairs.** A declared `rename-root` into a kit-owned prefix refuses before any write. A kit file whose bytes already equal the incoming kit's is converged, never refused, and the manifest records the incoming hash. An update interrupted after its kit writes is completed by the retry, at the same or a later commit, including after the second of two renames.

## Progressive polish

`describeTag` moves from the export command to `scripts/lib/git.mjs` and serves both the kit manifest and the registry. `docs/README.md` §Map names the siblings root and the receipts, and product 07's root list gains `siblings` in place. The new fixture suite `scripts/test-siblings.mjs` runs over a synthetic launchpad with its own Git history in about ten seconds without a build; the export receipt case lives in `scripts/test-launchpad.mjs` beside the other export cases, which saves a measured 4.2 s of setup per product gate (D006). Three nonblocking rows from the executor's worker reviews are boarded in D009.
