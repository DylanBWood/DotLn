# WO-078

Core now keeps a generated registry of its sibling repositories, and every kit export or update writes the receipt the registry is built from. Before this change, knowing what the starter carried meant opening its checkout to read the kit manifest's commit and build hash before every update, planning pass or receipt that named it, and the recorded version lived in memory between reads. Refutation receipt 009 held the order on that bookkeeping until the removal was named. The removal is that lookup, one checkout read per sibling per occasion, and nothing recurring is added: the declaration is written once per sibling, the receipt by the command the operator already runs, and the page by the document gate.

**Receipts.** `launchpad export` and `launchpad export --update` resolve the destination directory against `docs/siblings/siblings.json` before the build and before any write: the destination's own repository name from its origin remote when it has one, else its directory name, compared without case as repository names are. When it names a declared sibling, the command writes one JSON receipt under `docs/evidence/siblings/`, in a directory named by the sibling and a file named by the receipt's date, immediately after the kit manifest, holding exactly `sibling`, `coreCommit`, `manifestHash`, `buildHash` and `date`, then regenerates the registry page and prints the receipt path and whether the page changed. Any other destination writes nothing and the command says why, so fixture and scratch exports never reach core's evidence tree. A receipt failure names a complete export, never a partial one.

**Registry.** `node scripts/siblings.mjs index` renders `docs/siblings/README.md` from the once-per-sibling declaration, every receipt and this repository's Git: purpose and upstream relation; the kit version as the tag at the receipt's commit or the nearest below it; core commit, manifest hash, build hash and last receipt; the orders whose committed control segment reads closed at a receipt's commit and not at the previous receipt's; the declared capability-row ids; and a receipts table. Every field no receipt supplies reads "not evidenced", which is both entries' state today: the starter and the Angular consumer are declared, and no export has run. `index --check` runs as a document-gate row. It regenerates and refuses a hand-edited entry by its first differing line, an entry whose manifest hash is not its latest receipt's by naming the receipt, and a receipt it cannot decode by path, writing nothing. Captured tag observations beside the page keep an unedited page current after a later tag is added, and the check validates every captured name against Git (an exact tag must point at the receipt commit, a nearest tag must be at or below it), so an invented version in either generated file refuses.

**Update repairs.** WO-077's three boarded update defects are fixed in the same edit of `scripts/launchpad.mjs`: a declared `rename-root` into a kit-owned prefix refuses before any write; a kit file whose bytes already equal the incoming kit's is converged, not refused; and the update journals its planned manifest as `KIT-MANIFEST.pending.json` before its first kit write, so a retry after a run that failed after its kit writes completes at the same or a later commit, including after the second of two renames.

**Read before merging.** A new document root `siblings` (default `docs/siblings/`) joins the configuration loader and product 07's root list; receipts sit under the configured evidence root. The registry's two generated files are marked generated and are regenerated by `worktree integrate`. A tag deleted from Git after generation makes the `siblings` document row refuse until `node scripts/siblings.mjs index` regenerates the pair (VER-003 H13). Coordinated edits of both generated files that name only tags Git holds at or below the receipt commit still pass; they can be genuine older observations and are recorded as limits (VER-002 cases D and F, VER-003 L1 and L2). A fork's publish check still reads the operator identity from `scripts/lib/contributions.mjs`'s constant; WO-078 left that row with a recorded reason (D004), and it returns to the register. Three nonblocking rows from the executor's worker reviews are boarded in D009.
