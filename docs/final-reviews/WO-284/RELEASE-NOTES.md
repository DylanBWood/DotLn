## Release overview

An instance can pass its gate on a slower machine and can change any time limit that stops it. Every time limit of the gate is a row of one table, set with room for a machine several times slower than core's; an instance changes them in one file; a limit that is passed names itself; and an instance's gate checks the instance's own configuration in place of the kit's tests of its loader. In core, a tree that already holds a passing complete run is not run again without a stated reason. This matters first to an instance on an earlier kit whose every gate selection failed when one structural check ran past its fixed 30 seconds.

## Read before upgrading

**The limits file.** `docs/control/time-limits.json` holds every time limit of this instance's gate. An update brings the release's file where your instance has none or never changed its own, with the starter's other commits, and `npm run limits -- --write` creates it at any time: every key at the kit's figure. Where you have changed your file, the update keeps your bytes and `npm run limits -- --write` adds a later release's keys to it. Without the file the kit's figures apply and nothing fails. `npm run limits` lists every key with the figure that applies here and where it came from ([Time limits, and a slower machine](../../KIT.md#time-limits-and-a-slower-machine)).

**On a slow machine, set `scale`.** `"scale": 2` doubles every limit. Raise one key with its `set` where one step alone is slow, turn one limit off with `null`, or turn them all off with `"enforce": false`. The five pauses after a stop grow with `scale` and are never turned off or shortened.

**If you edited the runner by hand.** An instance that edited `scripts/test-runner.mjs` to raise a limit takes this release's copy of that file when the update's merge reaches it, and sets the key in the limits file instead. The update preview flags the path as locally modified ([Taking upstream updates](../../KIT.md#taking-upstream-updates)).

**The limits are longer, so a hung step waits longer before it is ended.** A structural check has 5 minutes where it had between 10 and 30 seconds, the generated checks 10 minutes where they had 2, and every other task 45 minutes where it had 15. Under `node scripts/harness.mjs bounded`, a test selection run by name now has the six-hour outer bound a complete selection had, with each task's own limit inside it. To tighten a limit, give its key a smaller `set`.

**After you change a figure, earlier passes no longer count.** A gate row records the limits it ran under. Once a figure changes (a key raised or lowered, `scale`, `null` or `enforce: false`), no earlier pass at that code identity is reused or stands for a claim: the next run runs every task under the figures in force, and the closeout lists the complete run again. An edit that changes no figure, such as a note of your own or a refreshed `kit`, changes nothing, with one exception: a target order that edits the file in any way owes the launchpad's complete run unless a row stands ([The checks an order owes at its closeout](../../KIT.md#the-checks-an-order-owes-at-its-closeout)).

**An instance's selections list `configuration`, not `configuration-root`.** The second structural check now loads this instance's own configuration and names what the loader refuses. The kit's tests of that loader are in no selection of an instance, `npm run test:machinery` among them; run them by name with `npm test -- --only configuration-root`.

**In core, `--again` and `--fresh` need a reason at an identity that already passed.** Where a passing complete row stands at the code identity, `npm test -- --review --again` prints that row, runs nothing and exits 0. A script that forces a complete selection there and expects a run must pass `--reason "<why>"`; the row keeps the text. An instance's selections reuse nothing and always run, so nothing changes for them.

**What raising a figure does not reach.** Three rows also bound a step inside a hook or a dispatch whose own bound is fixed: the read of a gate owner's start time, the read of the temporary directory and the wait for the host guard. A figure raised past that bound changes nothing there. The host guard is one process for every checkout on the machine and follows the limits file of the checkout that started it.

No refusal is added to an instance.

## Substantive changes

**Time limits.** One build-free table, `packages/skeleton/src/time-limits.mjs`, holds 38 keys: a figure, what it bounds and what passing it does. The runner's suite rows, the generated checks, `npm run sync`, the license check's dry runs, the evidence and bounded-probe wrappers, the work-order index check and the host's monitor, guard, helper compile and record lock read their figures there and keep none of their own. A step an instance's gate runs has at least ten times its slowest passing time in core's gate record of the thirty days before the order, a suite row at least five minutes, and a row only core's complete run uses at least three times. A value the file holds that cannot be used is named in one advisory for the whole command and the kit's figure applies; no command stops for it.

**A miss names itself.** A step ended for time says its key, the figure that applied, the limits file and `npm run limits`. A structural check ended that way is reported as `TIME`, not `FAIL`, and the tasks after it say that nothing was judged. The Git version read, the lane reader, a native helper's compile and core's build of a stale runtime say which limit ended them and no longer point at a missing tool.

**The listing and the writer.** `npm run limits` prints one line for every key. `npm run limits -- --write` writes the file with every key, writes back each entry as its owner wrote it, a field of the owner's own included, and refreshes each entry's record of the kit's figure. It refuses, and leaves untouched, a file that does not parse, that is no object or that has another `schemaVersion`. An entry left at `"kit"` follows the kit's figure through releases; an entry with a number keeps its number.

**The instance's gate.** An instance's structural phase is `format`, `configuration`, `registrations`, `declarations`, `generated` and `host`. Core keeps `configuration-root` in the second place and its Git surface check before `host`.

**Core checks the room.** The export fixture runs an exported instance's three selections with `scale` at one third and judges each task's own result against its reduced figure. A release whose instance gate needs more than a third of a figure on core's host fails core's gate before it ships.

**Reuse and the closeout.** Where a passing complete review row stands at the current code identity, under the limits in force, the briefing and `worktree integrate` say the complete run is satisfied, name the row's time and list `npm run test:docs` alone. A forced complete selection there is answered with the row, as above. A suite a selection reuses whole is named in the schedule line as reused at the code identity, never as changed or scheduled first. The reviewer's and the executor's role steps say that an edit to documents alone owes `npm run test:docs` and no complete run.

**Seeds and the starter.** A fresh export seeds the limits file. A starter refresh adds it where a starter lacks it, brings an unchanged one to the release's template and keeps one its owner changed, with the reason. The seeded first order keeps a private terms list that is present and creates one from the example only where none is.

## Progressive polish

The read census says that a file read through the shell is not counted, so its counts are a lower bound. The two structural phases are held in one module. The fixture manifests and the hand-written lists of build-free modules name the new table. Cases of the kit's own tests that run a selection twice at one identity state why, and the lane-size case follows the root's own gate share.

## Evidence and compatibility

This is the minor release `v1.3.0`, staged by WO-284 above `v1.2.0`. The skeleton component moves from 0.92.0 to 0.93.0, and the console's pin of it and the lockfile follow; no other component version changes. The Node range (`^24.15.0 || ^26.0.0`) and the Git floor (`>=2.31.0`) are unchanged. The release tag and the Release are made at the release close after the merge, and the tag's manifest binds the source identity; nothing is published by this review.

The complete review run, `npm test -- --review`, passed at the reviewed code identity with 47 suites and 124 tasks, all fresh, in 0 h 51 min, and `npm run test:docs` passed on the candidate tree. [The order's evidence](../../evidence/WO-284/evidence.md) holds the listing in core and in an instance fixture, a timed-out row's message, the exported instance's selections at a third of every figure, the closeout selection's two forms and the forced selection's answer. Known limits. The other 139 time limits the kit ships, in lifecycle commands, hooks, worker launches and host tooling, keep their figures; a later order moves them into the table. The scan that keeps time figures in the table does not follow an elapsed time held in a variable or a constant imported from another file ([D030](../../evidence/WO-284/decisions.md#wo-284-d030--retain-the-earlier-nonblocking-limits-with-a-named-follow-up)).
