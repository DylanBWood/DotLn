## Release overview

This release makes cold-start growth visible. Every DotLn role session loads the shared floor (`CLAUDE.md`) plus its role skill, and that size has an advisory ceiling per role. Since 2026-09-17 the ceilings have been raised eight times by acceptance records, and until now nothing showed how much a role had grown since its last raise or since the last release. `harness-context` and `npm run meta` now report, for every role and both installed skill roots, the bytes now, the ceiling, the bytes and delta since the previous release tag, and the bytes and delta at the commit that recorded the role's latest acceptance. On this release the verifier is 832 bytes above its last raise, the reviewer 1,772 and release close 1,576, and the executor is level with its raise. The intended audience is the operator deciding the next ceiling request and anyone reading the meter's drift signal.

## Read before upgrading

No operator action is required, and no ceiling, acceptance, rule or refusal changes. `node scripts/harness-context.mjs --check` now does what its usage line says: it evaluates budgets and prints advisory breaches on standard error, and it still never refuses. Without a flag the command prints only the measurement, and an unknown option exits 1 with the usage line. The measurement JSON moves from schema 2 to schema 3. The new fields (`previousCause`, `lastAcceptance`) are additive, and `comparisonEdition` is now the highest reachable release tag instead of the fixed `v0.16.0`. The proposed saving of 1,667 bytes per role session did not happen. Fresh Claude Explore and Copilot task workers were observed reading a role skill with no floor in their context, so the five-refusals paragraph stays in every generated skill and the generated bundle is byte-unchanged. `@dotln/skeleton` moves to 0.39.1 with no source change, and the console's exact pin follows. No dependency is added.

## Substantive changes

**Cold-start trend.** Each role row carries its installed bytes, ceiling, previous-edition bytes and delta, and a last-acceptance record: date, ceiling, the commit that introduced it, the bytes measured there, and the delta. The previous edition is the highest `vX.Y.Z` tag reachable from `HEAD`, so a sibling worktree's unmerged release is ignored. The acceptance baseline is the first commit on `HEAD`'s first-parent history whose budget file holds the role's latest global acceptance. Neither the ceiling nor any number in an acceptance's reason text is ever read as a measurement. Missing tags, shallow history or missing files report `null` with a named cause instead of a number.

**One measurement for the CLI and the meter.** `npm run meta` prints the same per-role rows under its drift-to-low-performance signal and carries them on that trap row in its JSON, and the regression asserts that the CLI output, the meter's cold-start record and its drift row are equal.

**Skill-loading observations.** The order's completeness check covers six loading paths: the Codex, Claude and Copilot roots and a fresh worker in each. It is recorded with a reopening condition: deduplication is reconsidered when fresh workers in every supported harness receive the complete floor before a role skill.

## Progressive polish

Historical snapshots are measured with one `git ls-tree -l` per snapshot instead of thirteen `git show` calls, with equal byte counts, and the budget history is read with one `git cat-file --batch`. Product 07 gains a paragraph describing the baselines and the `--check` behavior, and product 06 records the release assignment. The two publication source locks are refreshed for those product edits. One known label defect remains: the new drift rows print an unset ceiling as "ceiling unavailable". It is recorded as a low-priority follow-up (`FUP-e5a6ca7dbe6270ea`).
