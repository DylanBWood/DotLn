The meter compared every role with `v0.16.0`, and `harness-context --check` behaved exactly like the plain command. The paragraph is emitted from `HARNESS_BOUNDARIES` in `packages/compiler/src/harness.ts`, not from the contributor loadout the proposal named.

**How the baselines are chosen.** The previous edition is the highest `vX.Y.Z` tag reachable from `HEAD`, so a sibling worktree's unmerged tag is ignored. On an order branch the delta is that order's own growth; on `main` right after a release close it reads 0 until the next change. The acceptance baseline is the first commit on `HEAD`'s first-parent history whose `budgets.json` holds that role's latest global acceptance, chosen by date and then record order. Scoped acceptances are skipped, and neither the ceiling nor any number in the reason text is ever read as a measurement. Missing tags, shallow history and missing files produce `null` with a named cause. One `git ls-tree -l` per snapshot replaces thirteen `git show` calls and returned the same byte counts ([D002](docs/evidence/WO-155/decisions.md#wo-155-d002)). `--check` now evaluates budgets and prints advisory breaches, never refusing; the plain command prints only the measurement ([D004](docs/evidence/WO-155/decisions.md#wo-155-d004)).
