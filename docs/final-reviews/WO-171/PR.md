# WO-171

`harness prune --apply` re-planned the whole prune before every deletion, and every plan asked GitHub about every retained lane and integration stash with one `gh release view` and one `git ls-remote` each. At the 2026-09-27 listing (186 candidates, 64.2 s for one plan) the order estimated an apply at about three hours, an inference from that listing and the source. The last recorded apply, on 2026-09-24, ended with exit 143. Fourteen integration stashes of about 5.4 GB and seventy-two retained lanes stayed on disk. Those lanes also hold the only copy of 2,141 usage rows, which an apply that worked would have deleted.

This pull request lands WO-171. An apply now plans once, observes publication with one listing of Releases and one listing of remote tags, re-checks only the candidate it is about to remove, and resumes when run again after a stop. A retained lane holding a usage copy stays until the order's committed `meta.json` names that copy's SHA-256.

- **One plan per apply.** Each retention rule moved unchanged into a judgment for one candidate. The plan enumerates them. Before each deletion a fresh context re-reads registered worktrees, the writer and its events, live gates and the ref backend, and re-judges that candidate alone: its inventory, its guards and, for a stash, its identity by SHA. A difference is refused with `Prune subject changed` as before ([D002](../../evidence/WO-171/decisions.md#wo-171-d002--one-plan-and-a-pre-delete-check-that-re-judges-only-its-candidate)).
- **Publication is two listings per apply.** `gh release list --limit 10000` and `git ls-remote --refs --tags origin` are joined to the local release records. An order's release is its newest local release tag that is listed as non-draft and whose remote tag names the same object, which is the old per-release test. A failed listing keeps every lane and stash ([D003](../../evidence/WO-171/decisions.md#wo-171-d003--publication-is-one-release-listing-and-one-tag-listing-joined-per-order)).
- **A stopped apply resumes.** Byte proofs are written to a partial file and linked into place, so a proof that exists is always whole and a rerun continues from what remains ([D007](../../evidence/WO-171/decisions.md#wo-171-d007--what-a-stopped-apply-resumes-from-one-repair-and-what-stays-boarded)).
- **Usage copies keep their lane.** A lane holding `process/usage.jsonl`, or a copy that worktree preservation renamed `.from-WO-NNN[-n]` on the file or its directory, is listed as retained with `usage has no committed snapshot` or `usage copy is not in the committed snapshot`. It stays retained until HEAD's `docs/evidence/WO-NNN/meta.json` names every copy's SHA-256 ([D004](../../evidence/WO-171/decisions.md#wo-171-d004--a-lane-holding-a-usage-copy-waits-for-a-committed-snapshot-that-carries-it), [D013](../../evidence/WO-171/decisions.md#wo-171-d013--usage-retention-follows-preservations-collision-names)).
- **A bound resident store follows its lane** into the lane's byte proof, with no code change ([D005](../../evidence/WO-171/decisions.md#wo-171-d005--a-bound-resident-store-follows-its-lane-with-no-code-change)).

**What a reviewer should know.**

- **WO-170 as filed will not release these lanes.** It writes usage totals by role into each snapshot and no digest, so under this rule the 73 lanes (45.6 MB) kept for usage on the operator's checkout stay kept after WO-170 closes. The register row [`FUP-dc6c139003bd4b89`](../../evidence/WO-171/decisions.md#wo-171-d004--a-lane-holding-a-usage-copy-waits-for-a-committed-snapshot-that-carries-it) is open for the next planning pass to amend WO-170 before it activates. The rule does not touch the 15 published integration stashes (5.85 GB), which one apply removes.
- **Publication is read once per apply.** A Release withdrawn while an apply runs is not seen by that apply, where the old re-plan would have refused. The Release listing is capped at 10,000, and an order outside it stays retained.
- **One minor defect is boarded, not fixed** ([D014](../../evidence/WO-171/decisions.md#wo-171-d014--final-review-passes-and-boards-where-the-usage-rule-looks-for-a-digest)). The usage rule finds a digest anywhere in the snapshot's text rather than in a field that says the copy is carried. Nothing writes a digest into `meta.json` today, and the field is WO-170's to choose. A stop between a proof's link and the partial's removal also leaves a small `.partial` file beside the whole proof.
- **A stash drop stopped inside its locks still needs the operator.** The three stopped states are in `scripts/lib/stash-drop.mjs`, outside this order's files, and are boarded with their remedies ([D007](../../evidence/WO-171/decisions.md#wo-171-d007--what-a-stopped-apply-resumes-from-one-repair-and-what-stays-boarded)).

The executor fixed five with failing-first fixtures, including a first usage rule that would have released WO-043's lane and deleted 42 rows found nowhere else. [VER-001](../../verifications/WO-171/VER-001.md), run in Codex, failed criterion 5: a usage copy that worktree preservation renames on a collision was not recognized. The repair widened the match to preservation's names and added a fixture that gets them from the real reconciliation call. [VER-002](../../verifications/WO-171/VER-002.md) passed all nine criteria. [FINAL-001](FINAL-001.md) re-ran the review gate and ran a read-only listing of the operator's main checkout, which reproduced the executor's figures. It also disposed the twelve follow-up rows its own `--touching` run returned. Two read-only helpers re-ran the fixtures against the base module, probed the recheck, the publication join, the usage names and the proof partial in throwaway repositories, and found no blocking defect.

**Validation.** The reviewer's `npm test -- --review` on the staged subject passed **32 passed, 0 failed, 570.30 s, 76 fresh tasks, exit 0** at code identity `d654147c59affece465b8f1cf7f12d0993f391b9ccd1325f8962faabf629c1dc`, the identity VER-002 judged, and that row binds the released bytes. Against the base module, five of the nine WO-171 fixtures fail and the four that pin existing behaviour pass. The listing of the operator's main checkout took 68,229 ms before this change and 16,400 ms after (executor), and 17,996 ms in this review, with 126 candidates of 5,882,125,113 bytes and 114 retained. No apply was run against a real checkout. `npm run test:docs` passed after the review records were written. `harness check`, `publication:check`, `release check-surfaces --local`, `meta --check` and `plan check` pass. `git diff --check` is clean, no dependency is added and the diff adds no suppression.
