## Release overview

DotLn's blinded verifier — a model given a sealed worktree snapshot, a pinned diff, host-run test witnesses and no tools — had until now only ever been exercised by process doubles. This release is the first evidence of it working with real models, and the first thing that evidence found was a defect in DotLn itself. Four consecutive live attempts failed, none of them because the model was wrong: the host admits a finding only when its `observed` and `expected` equal an adverse witness's strings exactly and each reproduction step is a witness's step or an exact named command, and nothing ever told the verifier so. Only a double that copies the host's own strings could satisfy the rule. The contract is now stated to the verifier in its instructions and its result schema, the Codex verifier launches in the files-only read mount it was being refused by, and on the repaired runtime a Claude and a Codex verifier each caught a planted defect, had it repaired by a fresh worker and re-verified it against the original contract. This is for anyone running DotLn's verification and repair loop with a live model rather than a fixture.

## Read before upgrading

**No admission rule changed.** `parseEvidenceResult` and `deriveRepairOrder` keep their exact bytes; `repair.ts` is not modified. A finding still has to restate a host observation, and model prose still cannot stand in for one. What changed is that the verifier is now told the rule it is judged by.

**The schema constraint cannot refuse a finding that admission would accept.** A finding's `observed` and `expected` are restricted to the strings of the adverse (`fail`) witnesses, which is a superset of the single pair admission demands, and the restriction is omitted entirely when there is no adverse witness. It publishes nothing new either: those strings are already inside the capsule the verifier reads.

**Reproduction steps are constrained in one profile only.** The `worktree-snapshot` profile turns steps into commands the host actually runs, so there they must be a witness's step or one of the contract's exact named commands. The legacy `verification-snapshot-v1` profile's steps are free text exactly as before.

**One Codex launch vector gained one flag.** An evidence worker in the `worktree-snapshot` profile is launched with `--skip-git-repo-check`, because its read mount is a files-only copy carrying no Git metadata, which Codex CLI 0.155.1 refuses before any model call. Inspection, writer and `verification-snapshot-v1` vectors keep their exact arguments, and fixtures assert their absence of the flag.

**Your verifier will now write its diagnosis somewhere else.** Its own account of the cause belongs in `envelope.summary`, capped at 320 characters. Findings carry no durable analysis field, so a verifier's reasoning does not reach the repair worker; whether it should is an open planning question, not an oversight.

## Substantive changes

**The finding contract is stated to the verifier.** `evidenceResultSchema` derives the admissible values from the request's own adverse witnesses and encodes them as enums; `transportPrompt`'s verifier instructions state the same rules in prose and direct the model's diagnosis to the envelope summary. The derivation is a pure function of the capsule, so a request with no adverse witness yields free-text fields rather than an empty enum.

**The Codex evidence worker runs in the sealed snapshot.** `canonicalWorkerArgs` adds `--skip-git-repo-check` when, and only when, the request is an evidence request in the `worktree-snapshot` profile.

**Regressions hold both repairs, and are not vacuous.** One fixture ties the enums to the witnesses, checks the instruction text, admits a finding drawn from the stated values and derives a repair from it, then requires the exact shape a live verifier returned on 2026-09-20 — correct in substance, outside the stated values — to be refused by the unchanged admission rule, and a paraphrased step to yield `NeedsHuman`. Another pins the Codex vector to a single occurrence of the new flag and asserts the other three vectors do not carry it.

**The live evidence itself.** A planted-defect fixture builds a synthetic two-clause repository outside DotLn, commits `left + Math.abs(right)` through the real source-change host so the superficial test goes red to green, and runs the real verification, repair and re-verification hosts against it. Nine receipts are filed, six of them live: four failed attempts, and one passing episode per harness. The Claude episode's event log is published, and a suite replays it under injected implementer success events — including a forged pass — and requires the negative result to survive every one, with both controls live and a tampered log throwing.

Known limitations, each owned. The receipt contract detects inconsistency and careless relabelling; it is not authentication, because the log's launch fields are not hash-bound, so a deliberate forger with write access could fabricate a receipt, and filing stays the operator's act. Criterion 2's repair and re-verification facts are host observations with no published log behind them. A Codex run on a machine whose writer needs an absolute Node path withholds its log rather than publish a private path or edited bytes, so it evidences the finding and the repair but not the public replay; a path-free named command under the Codex writer profile would close that. The verifier's diagnosis has no durable field and the hosts retain no host-authored refusal detail; both are planner follow-ups. Nothing here evidences dependability: one synthetic two-clause repository, one passing episode per harness, and the trusted-host and snapshot-confinement limits of the earlier verification orders apply unchanged.
