## The scope expansion, and what it did not license

The operator's expansion authorizes two runtime surfaces and holds everything around them at exact bytes. I checked each boundary rather than accepting the claim:

- **The contract is stated, not changed.** `repair.ts` is not modified, and the admission rule `"finding observed versus expected"` is byte-identical. The claim that the host already enforced this predates the order — product 02 has required since WO-010 that the observed/expected pair match an adverse host witness — so the repair closes a gap between what the host demanded and what the verifier was told, which is the honest reading.
- **The schema cannot exclude an admissible finding.** `observed` and `expected` become an enum over the adverse witnesses' strings, a superset of the single pair admission requires; the enum is omitted entirely when no adverse witness exists, so it can never be empty. It leaks nothing, because those strings are already in the capsule the verifier reads.
- **The step constraint is scoped to one profile.** It keys on `subject.snapshot`, which is exactly `worktree-snapshot`; the legacy profile's steps stay free text, asserted directly.
- **One launch vector gained one flag.** `--skip-git-repo-check` is emitted only for an evidence request in `worktree-snapshot`, pinned to a single occurrence, and the inspection, writer and `verification-snapshot-v1` vectors are asserted free of it.
- **The regressions are not vacuous.** The finding-contract test admits a finding drawn from the stated values and derives a repair from it, then requires the exact shape a live verifier returned on 2026-09-20 to be refused by the unchanged admission rule and a paraphrased step to yield `NeedsHuman`. A test that only asserted the new enums would have passed against an empty schema; this one fails if either rule moves.
