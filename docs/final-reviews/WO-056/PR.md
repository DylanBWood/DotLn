# WO-056

DotLn's blinded verifier has always been exercised by process doubles. Run live for the first time, it failed four times in a row, and the cause was not the model: admission requires a finding's `observed` and `expected` to equal an adverse host witness's strings exactly, and each reproduction step to be a witness's step or an exact named command, but neither the verifier's output instructions nor its result schema ever said so. A real verifier returned a substantively correct blocking finding on the violated clause and the host refused it. Only a double that copies the host's own strings had ever satisfied the rule. The operator expanded this order to repair that and one other defect; on the repaired runtime a Claude verifier and a Codex verifier each caught, repaired and re-verified a planted defect end to end, and this branch files the receipts.

**The contract is now stated, not changed.** `evidenceResultSchema` limits a finding's `observed` and `expected` to the strings of the adverse (`fail`) host witnesses, and — in the `worktree-snapshot` profile only — its `reproductionSteps` to those witnesses' steps and the exact named commands. The output instructions say the same in prose and send the verifier's own diagnosis to the envelope summary, which is where the repair worker never sees it. `parseEvidenceResult` and `deriveRepairOrder` keep their bytes: `repair.ts` is untouched, and the admission rule reads exactly as it did. The constraint cannot exclude an admissible finding, because the enum is a superset of the single pair admission already demands, and it leaks nothing, because those strings are already in the capsule the verifier reads. With no adverse witness the fields stay free text rather than becoming an empty enum, and the legacy `verification-snapshot-v1` profile's steps are never constrained.

**The Codex verifier now launches in its own read mount.** That mount is a files-only copy without Git metadata, which Codex CLI 0.155.1 refuses before any model call, so the evidence-worker vector gains `--skip-git-repo-check` for the `worktree-snapshot` profile alone. Inspection, writer and `verification-snapshot-v1` launches are asserted free of it, and a fixture pins the flag to exactly one occurrence in the one vector that carries it.

**What the live episodes observed.** At the planted commit the superficial test passed (exit 0) and the contract test failed (exit 1). `claude-live-3`'s verifier returned one blocking finding on `AC-signed` restating that witness, blaming `sum.mjs`; the derived repair order allowed only `sum.mjs`, the repair commit touched only `sum.mjs`, and a separate verifier episode passed every original criterion against the unchanged contract hash. Its event log is published and replays negative under eight injected implementer events — a forged success envelope among them — with both controls live; the verification re-executed that replay and matched the receipt's recorded result byte for byte, and the regression that holds it re-executes it again on every gate run. `codex-live-3` carries the same finding and repair shape; it withholds its log, because this machine's Codex writer needs an absolute Node path that would be published inside the hashed capsule, so it evidences the finding and the repair but not the public replay.

**Validation.** `npm test -- --review` passed **27 suites, 0 failures, 256.20 s, 71 fresh tasks, exit 0**, recorded 2026-09-20T06:08:26.620Z at code identity `324116cb`, after the new regression fixture was staged. `harness check` matches 31 generated surfaces; `git diff --check` is clean in the worktree and the index; `publication:check`, `plan -- check` (11 passes, with WO-056 bound to its authorizing decision) and `release -- check-surfaces --local` all exit 0. All four evidence editions verify against the changed source. [VER-001](../../verifications/WO-056/VER-001.md) passed all six criteria independently, under a different model from the executor's, and reproduced the replay rather than reading it. This is a patch, `v0.33.2` above `v0.33.1`, with skeleton `0.29.2` and the console pin; no dependency is added.

**What a reviewer should know before merging.** The receipt contract is a consistency contract, not authentication: the log's launch fields are not hash-bound, so a deliberate forger with write access could still fabricate a receipt, and filing remains the operator's act. Criterion 2's repair and re-verification facts are host observations with no published log behind them. This is one synthetic two-clause repository with one passing episode per harness, so the capability table moves `runtime.independent-verification` to **level 1 — demonstrable, live-evidenced** and names the remaining gate honestly, including that it is executor evidence awaiting independent verification. Four earlier attempts are filed as failures and claim no passes.

**Left open, owned.** The verifier's diagnosis still has no durable field beyond a 320-character summary, and the hosts retain no host-authored detail from a refusal; both are planner follow-ups recorded in [D007](../../evidence/WO-056/decisions.md#wo-056-d007) and [D008](../../evidence/WO-056/decisions.md#wo-056-d008). A Codex receipt on a machine with a private Node path cannot publish a replayable log until a source-change worker can run a path-free named command ([D002](../../evidence/WO-056/decisions.md#wo-056-d002)). Final review corrected two sentences in product 03 that would have read as a still-pending WO-056 proof after merge, recorded in [D012](../../evidence/WO-056/decisions.md#wo-056-d012); 02 and the skeleton README keep their predecessor sentences, because in both the superseding paragraph sits directly below.
