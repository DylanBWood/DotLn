# WO-114

Until now, nothing showed the operator what the always-on resident was doing. The actor board projects control state at rest, but not a running actor, a presence phase or a cadence. This pull request lands WO-114. After every recorded event, the resident rewrites `runtime-status-v1.json` in its store directory by atomic replacement. The file lists configured actors, live episodes with order, transport, phase and elapsed recorded time, presence and armed cadences, coded holds, portfolio budget, and every Active or Open order's phase, dependency state and verdict from the generated work-order index. `npm run console -- status --store .runtime/launchpad` renders it, `--json` emits it for another local host, and `--watch` follows its replacements. The file is a disposable projection: it grants no action, a restart rebuilds it from the event log, and it carries no physical path, session id or host name. WO-115's loopback surface and the operator's Angular consumer read the same versioned model.

**What changed.** Skeleton defines the `RuntimeStatusV1` type, its decoder and the pure allowlisted projector. Console publishes the JSON Schema as a file and re-exports the type and decoder. `ResidentStore` publishes after each durable append, and once at the end of a transaction that appended nothing, using temporary-file write plus rename without fsync. The event log keeps its fsync. Publication failures are contained, so the resident's operation completes and a later event, tick or restart rebuilds the file. On first start, the lifetime owner binds the selected index in private store metadata (mode 0600). Every other writer reads that binding: presence and handoff helpers, and the harness heartbeat running from its installed snapshot. So every publication projects one index. `dotln resident` selects the launchpad's configured index through the existing resolver, including `DOTLN_LAUNCHPAD`. `PresenceMachine.nextCadenceAt()` exposes the due time the policy interpreter already computes, without advancing the machine. The console watcher subscribes before reading, deduplicates identical views, reports a generic unavailable line for missing or invalid files, and neutralizes terminal, bidi and line-separator controls. Skeleton moves to `0.40.0` and console to `0.2.0`. Compiler and kernel are unchanged, and no dependency is added.

**What a reviewer should know.** [VER-001](docs/verifications/WO-114/VER-001.md) failed the first subject on three major defects. Per-event file and directory fsync (777 publications at 9-14 ms each) pushed the unchanged WO-143 restart test past its 60 s timeout in one of two gates. Helpers and the snapshot heartbeat projected a different index than the host. A projection failure could abort a dispatch that was already durable. [The repair](docs/evidence/WO-114/repair.md) fixed those and three minor defects ([D010](docs/evidence/WO-114/decisions.md#wo-114-d010--repair-publication-and-consumer-boundaries), [D011](docs/evidence/WO-114/decisions.md#wo-114-d011--correct-contract-and-evidence-claims)). [VER-002](docs/verifications/WO-114/VER-002.md) reproduced each fix with its own probes: injected `ENOSPC`, `EMFILE` and read-only faults, the real generated hook as a child process, and 12 publications equal to replay. It found two minor edge-input defects, boarded up in [D013](docs/evidence/WO-114/decisions.md#wo-114-d013--ver-002-pass-two-minor-index-source-hardening-defects-boarded-up) with the follow-up "Resident index-source hardening". First, `dotln resident` now refuses, with a message that names no cause, when `DOTLN_LAUNCHPAD` names a missing directory or `dotln.config.json` is malformed. Second, a FIFO or other blocking special file at the bound index path hangs the first transaction. Without `DOTLN_LAUNCHPAD` the resolver falls back to the tool root and cannot refuse. Library hosts pass `workOrderIndexPath` on first start; without a binding, orders read `unavailable`.

The writer-parity fixture checks start, helper, snapshot-heartbeat and clock publications against replay, and the failure fixture shows start, presence and dispatch completing with the status path obstructed. The five actor-board fixture cases remain byte-identical. An end-to-end probe of the shipped CLI in this review rendered 54 orders from this launchpad's index, with no path, host, user or UUID in the file or the render. `git diff --check`, `publication:check`, `harness check` (31 surfaces), `release check-surfaces --local` (44 PASS, 0 FAIL), `plan check` and Prettier pass. Fs-watch behavior and timing were observed on darwin only, and every fault was injected. Implementation ran on Codex CLI 0.156.1 with `gpt-6-sol`, and the repair with `gpt-6-astra`. Both verifications and this review ran on Claude Code 2.1.282 with `claude-opus-5-5[1m]`, all at `xhigh`.
