## Release overview

This release gives the always-on resident a live status view. After every recorded event, the resident rewrites `runtime-status-v1.json` in its store directory by atomic replacement. The file lists configured actors with their availability and last episode, live episodes with order, transport, phase, elapsed recorded time and declared launch claims, presence signal and armed cadence times, coded holds, portfolio budget consumed and remaining, and every Active or Open work order's phase, dependency state and latest verdict from the generated index. `npm run console -- status --store .runtime/launchpad` renders the file as text, `--json` emits one snapshot for another local host, and `--watch` follows each replacement. It is intended for operators who run the resident, and for authors of the next UI hosts (the WO-115 loopback surface and the operator's Angular consumer), which read the same versioned model.

## Read before upgrading

No operator action is required for an ordinary launch. Two new files appear in each resident store directory: `runtime-status-v1.json`, the view, and `.runtime-status-source.json`, a private (0600) binding that records the absolute path of the selected work-order index. Stores already live in an ignored lane because they carry physical paths. `dotln resident` now resolves the launchpad through the same resolver the other commands use, so the view's order list comes from the launchpad's configured index, including under `DOTLN_LAUNCHPAD`. As a consequence, `dotln resident` now refuses with its generic worker-host message when `DOTLN_LAUNCHPAD` names a missing directory or `dotln.config.json` is malformed. Without `DOTLN_LAUNCHPAD` it uses the tool checkout as before and cannot refuse this way. A library caller of `ResidentHost` passes `workOrderIndexPath` on first start; a store that was never bound reports orders `unavailable`. Status writes use atomic replacement without fsync, while the event log keeps its fsync. The actor board, its command and its recorded fixtures are unchanged. No dependency is added. Skeleton moves to `0.40.0` and console to `0.2.0`; compiler `0.18.0` and kernel `0.6.0` are unchanged.

## Substantive changes

**A versioned, allowlisted view model.** `runtime-status-v1` is defined once in skeleton as a TypeScript type and a strict decoder. Console publishes the matching JSON Schema as `packages/console/runtime-status-v1.schema.json` and re-exports the type and decoder. A differential test holds the schema and decoder to the same `WO-NNN` rule. The projector copies no raw event payload or actor specification. It selects facts, reduces holds to coded reasons, admits launch claims only through a restricted pattern that refuses UUID shapes, and reads orders only from the generated index, where derived orders keep their ordinary `WO-NNN` identity. An unreadable, missing or malformed index makes the order section `unavailable` rather than creating a second order truth.

**Publication on every event, from every writer.** The resident store publishes after each durable append and once at the end of a transaction that appended nothing, so a restart rebuilds the same bytes from the log and the bound index. Every writer of a store reads the lifetime owner's index binding: the host, presence and handoff helpers, mission-hold clearing, and the harness heartbeat running from its installed snapshot. Each publication therefore agrees with a replay of its own log prefix. Publication failures are contained after the durable append: the operation completes, the previous file stays, and a later event, tick or restart rebuilds it.

**A console text host that survives change.** `console status` reads and decodes the file and renders six sections: Actors, Live episodes, Presence, Holds, Budget and Open work orders. It neutralizes terminal, bidi and line-separator controls. `--watch` subscribes before its first read, renders each changed valid view once, prints a generic unavailable line for a missing, malformed or foreign-version file, and resumes on the next valid replacement without printing a path.

**A read-only cadence projection.** `PresenceMachine.nextCadenceAt()` returns the due time the policy interpreter already computes, without advancing the machine. The dispatch path uses the same method, so status and dispatch cannot disagree about the next fire time.
