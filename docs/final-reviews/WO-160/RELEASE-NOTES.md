## Release overview

This release turns nine rescues that DotLn's own machinery kept asking of a human into commands with fixtures. During the WO-111 cycle the planning gate passed an orphaned amendment row by failing to match it, `entropy subject` pointed at a review nobody could consume and printed `undefined` paths, `release prepare` said "no files changed" while rewriting the PR meter, an evidence-only order had to edit a kernel test fixture, reviewers typed `core.hooksPath=/dev/null` commits by hand, a red document gate was judged "inherited" by eye seven times, eighteen integration stashes sat on the shared stack with nothing to prune them, every completion warned that the file the session had just written was unread, and an executor reached verification with the document suites red. Each of those now has a command that does the right thing and a fixture that would fail if it stopped. The intended audience is anyone running orders through DotLn's lifecycle, and the next order that meets one of these seams.

## Read before upgrading

No operator action is required, and no real stash was removed by this release. `harness prune` gains its first destructive capability under `--apply`: it removes integration stashes named `WO-NNN integrate YYYY-MM-DD` whose order has a published release, and only those, after writing a byte inventory and a ref, reflog and packed-refs recovery snapshot under `docs/control/local/retained/integration-stashes/`; the preview without `--apply` is read-only; the update is recoverable, not crash-atomic, so an interruption can leave a lock or a mismatched file that the snapshot repairs; a foreign lock, a reftable backend, an ambiguous identity, an order that still has a worktree or a pending integration all retain the stash with a reason. `worktree integrate` now refuses outside `repairing` and `final-review` (it used to admit any unpublished order), commits its preservation checkpoint and any divergent merge itself with hooks disabled, and records `phase`, `preservationCommit`, `mergeCommit` and `stashesBefore` in its receipt; a reviewer no longer makes that commit by hand. The planning control log gains the event type `PlanExecutionAmendmentWithdrawn` (schemaVersion 4) and `plan check` now fails, naming the order and row, on an amendment row that matches no judged or current source and has not been withdrawn; the remedy is `plan amend-order WO-NNN --withdraw N "reason"` or restoring the approved bytes. A non-envelope JSONL stream under `docs/evidence/WO-NNN/` must be declared in that order's `jsonl.json`; the kernel fixture no longer classifies evidence paths, and the kernel census now includes untracked files. `npm run test:docs` records a gate row; executor completion prints an advisory, never a refusal, when the current tree has no passing one. The observer credits a read for a path the session's own tool named and changed, so the "outputs not read at current bytes" advisory no longer fires on a file the session just wrote; an opaque shell write still needs `read-output` and `delivered`, and a foreign overwrite of the same named path inside the same tool window is not distinguished. `release prepare` prints `Files changed:` with each path, or `no files changed.` when nothing was written; the retimed message no longer lists surfaces. `@dotln/skeleton` moves to `0.43.1`.

## Substantive changes

**Planning log.** `plan amend-order WO-NNN --withdraw N "reason"` appends a `PlanExecutionAmendmentWithdrawn` event bound to the withdrawn row's amendment, receipt, source-order and order hashes; the reader refuses a withdrawal whose binding differs from its row; a withdrawn row is inert to the continuation gate, a superseded row stays in history, and only the latest surviving amendment satisfies a repeated authorization. The gate reports an unmatched, un-withdrawn row by work order and physical ordinal instead of treating the order as unchanged, admits a legacy-normalized activation row followed by a strict execution appendix, and row 22 of this repository's log is withdrawn under WO-111 D019.

**Entropy Reducer.** `entropy subject` considers only reviews with an `EntropyReviewFiled` event and reports `latestFiledReview`; the pre-mechanism `REVIEW-001` and `REFUTATION-001` keep their bytes and `entropy check` still lists them.

**Release preparation.** `applyReleasePreparation` returns the paths it wrote, the PR meter is written only when its bytes differ, and the command prints every file it changed.

**Evidence census.** `scripts/lib/evidence-jsonl.mjs` reads `docs/evidence/WO-NNN/jsonl.json`, refuses targets outside the order's directory and empty reasons, and serves both `check-registrations` and the kernel `store-history` census; WO-111's two sanitized projections are declared there.

**Integration.** The helper is admitted in `repairing` and `final-review` and records the phase; its preservation checkpoint and any resolved divergent merge are committed with `core.hooksPath=/dev/null` and `commit.gpgsign=false` and recorded as `preservationCommit` and `mergeCommit`; `--continue` on a clean tree adopts only an unseen stash carrying this integration's name and base commit and refuses an ambiguous match; product 07 §Independent workflows says so.

**Document gate.** `npm run test:docs -- --against REV` (default the merge base with `main`) reruns each failing check in a shared, hookless, detached clone of the base with the base's own workspace packages and build, prints `introduced`, `inherited` or `unknown` per failure with the base revision, records the comparison on the gate row, and never turns a red check green.

**Stash pruning.** `harness prune` inventories every blob of a published-order integration stash (worktree, index and untracked trees) with byte totals, retains unpublished, unnamed, worktree-owned, pending, gate-live or unsupported stashes with a reason, and under `--apply` drops the exact entry by object identity under Git's `refs/stash`, reflog and `packed-refs` locks, rewriting the reflog as `git stash drop` does, keeping the packed row while entries remain and removing it only with the last entry, so a concurrent `git pack-refs --prune` cannot leave `refs/stash` unresolvable.

**Observer and completion.** `observeAuthorship` records a `host:observed-output-write` read at the observed bytes only for a changed path the tool named as a destination and whose tool reported no failure; explicit observation records the receipts it added. `requireLifecycleEvidence` reads the latest `npm run test:docs` row for the current tree at `implementation-ready` and `repair-complete` and advises when it is missing, red, partial, unexecuted or unreadable.

## Progressive polish

`createCheckpoint` takes a `hookless` option; suite rows carry a `failureKind` (`setup`, `launch`, `timeout`, `stopped`) so a base comparison can tell an ordinary failure from an aborted one; the runner registers the new modules as sources of their suites; the WO-039 read-your-own-output assertion is flipped to the new rule and the WO-132 range fixture adds a foreign-edit case; README's build-itself paragraph names the new commands; the harness bundle was re-emitted for the changed observer and the integrated skeleton, differing from the previous snapshot in its id and one runtime hash; the roadmap records the `v0.50.0` activation, the `v0.51.0` retime and the final-review integration. The authority edition was re-minted as `WO-160/002` on the integrated source; artifact identity, verification and feedback stay at `WO-161/001`.

Known limitations, each on the record. The stash drop is recoverable, not crash-atomic, and its error-path rollback is not fault-injected (O20, O29). The own-write credit cannot distinguish a foreign overwrite of the same named path inside the same tool window (D014). An `inherited` label establishes recurrence at the base, not causation; a missing base or a failed base setup yields `unknown`. The race regression widens Git's natural window with 30,000 loose tags and does not measure its real-world frequency. Only the latest amendment per receipt and order is matched, so a superseded, un-withdrawn row is neither reported nor withdrawn (O3). Twenty-seven non-blocking observations are boarded on the adjacent queue under `FUP-dd20beb6b16ea86c`; the two close-stage follow-ups `FUP-fd5f7c2b91095343` and `FUP-dcadda81305b4fb7` are retargeted at release close.
