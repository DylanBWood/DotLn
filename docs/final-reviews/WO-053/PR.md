# WO-053

Until now no session, actor or pattern had changed a file in a repository the operator did not edit by hand: every real worker was read-only and every source-change proof ran on process doubles. This work order runs the primitive for real. In a synthetic Git repository outside DotLn, a Claude worker and a Codex worker each fixed one wrong function, ran the host's focused test from red to green, read the diff and committed exactly one file, while the host proved the DotLn checkout, the target's main checkout and a sibling sentinel directory were byte-identical before and after. A third episode killed the Codex host after its worker had committed and exited, and the host recovered that commit by identity without dispatching a second worker.

What it changes for a reader: the roadmap's source-to-deliverable rung, the root README and the capability table now point at live receipts instead of a pending proof, and the second replan checkpoint has its WO-053 disposition. The `worker.source-change` capability stays at level 1, demonstrable; the receipts establish one bounded task on each harness, not dependable general operation, not universal filesystem confinement and not fencing of a still-running orphan.

**What the receipts show.** Each successful receipt records the host's test exit `1 → 0` with no signal, a changed-path list of exactly `sum.mjs`, one commit above the base whose sha agrees across the host observation, an independent Git read and the returned envelope, and unchanged protected snapshots. The parent that received the worker's result grew by exactly the serialized envelope: 532 bytes for Claude, 490 for Codex, 523 for the recovery episode, each measured as a file size and re-derived at review from the envelope bytes. The recovery receipt shows `SIGKILL` before any durable source-change result, one `WorkerAttemptStarted`, one commit, and a clean second host run after the real lease expired. Every fact is labelled `observed`, `launch-claim` or `unknown`; harness version, model and effort stay launch claims with unknown effective readback, and the complete executor conversation's growth is recorded as unknown rather than inferred from the envelope channel. Six failed attempts are retained under their own names with the loadout edition each ran against, and no earlier receipt was rewritten.

**What was repaired, and why it stays bounded.** The live episodes found two blockers the doubles had not: Claude returned display prose where the transport required JSON, and once native schema output was requested, the target guard refused Claude's data-only `StructuredOutput` submission as an unknown tool; Codex returned a blocked envelope because the prompt authorized only the three effectful commands while the harness needed to read, and then could not resolve a bare `node`. The operator's 2026-09-17 override kept the repairs in this order. Claude's writer launch now uses aggregate JSON with `--json-schema` and the decoder requires `structured_output`; the guard classifies `StructuredOutput` as `read` while unknown tools still refuse and the three effectful Bash routes are unchanged; the writer prompt gains explicit bounded inspection instructions, which are prompt text enforced by the existing Codex workspace-write profile and the host's checks; the fixture names its exact test executable. The transport now rejects a terminal without a structured result, so a commit alone can never pass an episode.

**What the diff contains.** The evidence fixture and receipt validator under `docs/evidence/WO-053/`, nine receipts, three loadout editions and the decisions record; a regression test that loads every receipt and rejects forged passes, mismatched commit or branch identity, invalid test outcomes, extra fields and private paths; the three bounded runtime changes in `packages/skeleton/src/` with their tests and an extended process double; skeleton `0.25.2` with its regenerated bundle pins and fresh WO-053 authority and feedback evidence editions; and the write-backs to the roadmap, README, capability table, planning checkpoint, decisions index and follow-up register. No dependency changes; `package-lock.json` moves only the workspace's own skeleton version.

**Validation.** `npm test -- --review` passed 26 suites with 0 failures in 812.79 s, exit 0, 70 fresh tasks, for tree `7e4a0f17` at code identity `8df3152f`, recorded `2026-09-18T00:39:01.270Z`; the `skeleton` suite carrying this order's tests passed in 235.97 s. The publication lock, Prettier, harness-bundle, console-fixture, authority-evidence and feedback-evidence checks all exit 0 on the same tree. `git diff --check` and `git diff --cached --check` are clean. VER-001 passed all six criteria independently; the [final review](FINAL-001.md) re-derived the handoff byte counts, the loadout-hash split, the recovery invariants and the privacy screen from the receipt bytes, and confirmed the regenerated hook diff is pin-only.

**Integration.** `main` did not move during verification: `HEAD`, local `main`, `origin/main` and the merge base are the same commit, which also carries the published `v0.29.2` tag. The application target was retimed to `v0.29.3` at implementation under the order's patch classification with a dated roadmap note; `npm run release -- prepare` against origin's tag observation reports `WO-053 target v0.29.3 remains current; no files changed`.
