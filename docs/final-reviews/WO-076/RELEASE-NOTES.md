## Release overview

Application v0.76.0 lets an instance own its build. A fork of the kit no longer edits kit files to change what `harness emit` installs: it writes one JSON overlay, names it in `dotln.config.json` under `build.overlay` (by the kit's convention `build/overlay.json`), and the emit composes it over the kit's Contributor starter build. The overlay can replace the identity, equip or unequip the existing support switches, narrow the authority envelope, add grants that carry `operator` or `host-policy` provenance, or declare `build: none` so that only the hand-written `CLAUDE.md` floor remains. `harness check` verifies the composed result and the overlay bytes. The release serves operators of exported instances (WO-075's kit) and the orders that build on it: `harness update` (WO-077) can update kit files a fork never edits, and the three-repository route's WO-118 depends on the overlay.

The visible changes:
- `node scripts/harness.mjs emit` and `check` read the configuration's `build.overlay` and refuse before any write, naming the path and the key or condition, when the file is missing, unreadable, outside the launchpad, not JSON, or holds an unknown key or a wrong type.
- Widening beyond the kit's envelope without a grant refuses with `AUTHORITY WIDENING`; with a grant the emit proceeds and each profile's manifest records the grant's provenance.
- `.claude/harness-manifest.json` gains `overlay: { path, sha256 }` of the bytes read; with no overlay the manifest has no such key and the emitted content is unchanged.
- The kit's client README opens with the overlay: the Contributor build is starter content, not kit law, and the overlay owns the fork's build.

## Read before upgrading

- **No action without an overlay.** A checkout that declares no `build.overlay` emits the same content as before. The compiler release re-pins the runtime snapshot, so the manifest and fifteen hook files change hashes and version strings while the semantic hash and the installed path list do not ([D004](../../evidence/WO-076/decisions.md#wo-076-d004)). Run `node scripts/harness.mjs emit` after updating, as the bootstrap does.
- **Schema.** Overlay version 1 has the keys `version` (required, `1`), `build` (`"contributor"` or `"none"`), `identity`, `unequip`, `equip`, `narrow` and `grants`; `build: none` accepts no other key, and an unknown key refuses. The schema has its own axis in product 10 §Separate version axes, independent of the file's SHA-256 and the build's semantic hash. The configuration schema stays at version 1.
- **Narrowing is pre-grant.** `narrow` applies to the kit's base before the compiler applies grants, and the kit's own temporary-write grant still applies. A denial of `outside.write:system-temp`, `outside.write:session-scratch` or `outside.write:host-scratchpad` is accepted and silently not applied, and `narrow.allowedEffects` cannot remove a kit-granted effect ([D008](../../evidence/WO-076/decisions.md#wo-076-d008), FUP-d5d0ef5cf034102e). Grants cannot raise resource ceilings, extend expiry or bypass the floor; a granted effect removes its exact denial, and a wildcard denial that covers a granted effect refuses.
- **`build: none` keeps a stale floor and misleads the runtime reader.** On the real core floor the remaining `CLAUDE.md` still points at the five role skills the emit removed and does not say that no compiled refusal, hook or verification governs the instance ([D007](../../evidence/WO-076/decisions.md#wo-076-d007), FUP-d72bf62d3c82ca3f). The manifest's empty profile list reads as `runtime-unavailable` to the control plane's runtime reader: every `resume` and `plan` command prints an advisory to run the bootstrap, and `worktree finish`, `worktree settle` and release preparation refuse after a rebuild ([D011](../../evidence/WO-076/decisions.md#wo-076-d011), FUP-9d397b57910ae6ed). Emit and check themselves pass.
- **Identity text reaches `CLAUDE.md` unescaped.** An identity string holding a harness block marker is accepted, and the emitted file then fails `check`, as does every later emit, until the file is repaired by hand ([D009](../../evidence/WO-076/decisions.md#wo-076-d009), FUP-620f25409f65f4aa).
- **Profile emits remove more.** `emit --profile` now removes every previously installed file the selected profile does not own, including another profile's settings file; a full emit restores them.
- **Component versions.** Application v0.76.0 is a minor release over v0.75.0. Compiler 0.27.0 replaces 0.26.0 and skeleton 0.58.0 replaces 0.57.2; the console's exact pins and the lockfile follow. Kernel, console, beacons and browser-evidence versions are unchanged. No dependency is added.

## Substantive changes

**Overlay decoding and reading** (`scripts/lib/harness.mjs`). `decodeBuildOverlay` validates the closed version-1 schema: the key list, `version` equal to 1, `build` in its two values and alone with `version` when `none`, `equip` and `unequip` as distinct arrays of the ten known support switch ids with no id in both, a complete `identity`, the seven `narrow` fields with their types and effect patterns, and `grants` with `grantedBy` limited to `operator` and `host-policy`, `repo` equal to `project`, exact effects and unique ids. Every refusal reads `invalid build overlay in` the configured path with the key or condition. `readBuildOverlay` resolves `build.overlay` through the contained-regular-file rule and returns the path and the bytes; the installation decodes and hashes those same bytes, so the decoded value and the recorded digest come from one read.

**Composition** (`packages/skeleton/src/loadouts/contributor.ts`). `contributorProgram` and `contributorConfiguredProgram` take an optional overlay. `overlayContributor` narrows the saved Contributor graph before compilation: it checks allowed effects, resource limits and expiry against the kit's immutable envelope and throws `AUTHORITY WIDENING` on any excess; it appends denied effects, required evidence, revocation event types and revocation conditions; it narrows the inherited presence phases and removes granted effects from the inspection restriction notes; and it replaces the identity, adding an `instance.identity` prompt fragment so the replacement's text reaches the bundle. The exported `contributorSupportIds` names the ten switches that `equip` and `unequip` may use. The static permission matchers are filtered against the compiled envelope only when an overlay is present, which keeps the no-overlay bytes unchanged.

**Emit and check** (`scripts/lib/harness.mjs`, `scripts/harness.mjs`). `harnessInstallation` maps `unequip` and `equip` to the switches, passes the rest to the composition, records `overlay: { path, sha256 }` only when an overlay exists and, under `build: none`, returns no generated files and a manifest with no profiles. `emitHarness` then writes the floor alone, refusing a `CLAUDE.md` that holds only the generated block, removes every previously installed owned file and skips the runtime snapshot. `checkHarness` requires the floor alone under `build: none` and otherwise compares as before. The CLI decodes the overlay before creating the output directory, so a refusal creates nothing.

**Compiler** (`packages/compiler/src/harness.ts`, 0.27.0). The permission-guard facet no longer requires at least one static deny matcher; each matcher present must still name a denied build effect in the observed Bash shape. The generic envelope hook therefore remains when every static deny has an explicit grant.

**Fixtures** (`scripts/test-harness.mjs`, `scripts/test-worktree-integration.mjs`). Six WO-076 cases: no overlay reproduces the bytes and a narrowing changes only the declared fields across every merged and per-profile file and the whole manifest; identity replacement with two unequips and one equip reaches the bundle; `build: none` removes the owned surfaces, keeps the floor and checks without a runtime snapshot; ungranted widening refuses while grants record provenance and keep the envelope hook; unreadable, non-JSON, unknown-key and wrong-type overlays refuse by path before any write; and the closed schema's nested refusals. The worktree-integration fixture copies the compiler and skeleton sources beside the scripts it rebuilds, so one source revision travels together ([D006](../../evidence/WO-076/decisions.md#wo-076-d006)).

**Documents.** The kit's client README opens with the overlay's ownership, an example and the schema. ADR-0006 §Amendments records the composition as the implementation of Decisions 1 and 7. Product 10 §Separate version axes lists the overlay schema axis. [D001](../../evidence/WO-076/decisions.md#wo-076-d001) records that WO-069-D001 does not reopen: the configuration's existing `build.overlay` string is sufficient, and registration and classes keep their single home in the configuration.

## Evidence and compatibility

Application `v0.76.0` is a minor release over `v0.75.0`, built from WO-076 on `main` at `ffff74e1`, also the order's base; `main` did not move during the order, so integration merged nothing ([D010](../../evidence/WO-076/decisions.md#wo-076-d010)). Compiler 0.27.0 replaces 0.26.0, skeleton 0.58.0 replaces 0.57.2, and no other component or dependency changes. The overlay schema is version 1, and a checkout without an overlay keeps its content.

The verification sequence:
- [VER-001](../../verifications/WO-076/VER-001.md) passed all six criteria at code identity `d43b5afa…`. Beyond the six fixtures it attacked the real corpus with fifteen refusal variants, four ungranted widening routes, operator and host-policy grants, three refused grant shapes, stale and forged overlays and each profile subset, and boarded three follow-ups (D007 to D009).
- [FINAL-001](FINAL-001.md) passed at the integrated tree, re-ran the six fixtures under the bounded runner (6 of 6 in 4.5 s), reproduced the `build: none` runtime-reader finding on a scratch copy of the subject and boarded it (D011).

The executor's `npm test -- --review` at code identity `d43b5afa…` passed 41 suites with 93 fresh tasks in 1,535.0 s, after a fixture repair that copied the compiler and skeleton sources into the integration fixture. The final review's gate at the same identity reused those tasks, ran `format` fresh and passed 41 of 41 in 8.39 s, and `npm run test:docs` passed 35 of 35 in 134.0 s at the report.

Known limitations:
- Narrowing a kit-granted effect is accepted and not applied, with no diagnostic (D008).
- `build: none` leaves the five role directives and no disclosure in the floor (D007), and its manifest reads as `runtime-unavailable` to the control plane's runtime reader, which advises a bootstrap on every command and refuses `worktree finish`, `worktree settle` and release preparation (D011).
- Identity text holding a harness block marker breaks `CLAUDE.md`'s check until hand repair (D009).
- The carried relocation of the Start-here directives into the compiled bundle stays on FUP-44639ec9a751d8d1 ([D003](../../evidence/WO-076/decisions.md#wo-076-d003)).
- `equip` and `unequip` name only the ten existing support switches; the tree has no data-defined unit catalog, and D001 reopens when an instance needs a unit beyond them.
- Execution evidence is from one macOS host, and no exported instance has yet selected an overlay.
