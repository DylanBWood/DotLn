# WO-235 — Derive useful artifacts from their contracts and add a document quality pass (v0.103.0)

Documents written under DotLn now start from their contract and their reader rather than from the previous instance of their kind, and usefulness is judged by what that reader can understand, answer, decide, do, verify or recover, never by byte count. This pull request lands four pieces of machinery for that rule, withdraws the operator-message design the order first carried, and leaves `main`'s prompt router, journal, completions, planning receipt and Stop untouched.

**Writing guidance names the contract first.** `npm run reader -- profile <surface>`, the publish helper and release preparation now open with a `Contract:` line naming the product sections that state the surface's rules and the functions that judge or render a draft (for a PR body: `pullRequestBodyShapeFailures`, `githubBodyProfileFailures` and `hasAiAttribution`), then the document kind and reader, then the profile, then a usefulness sentence. The "Nearest example" line is gone, no example is selected by distance or length, and a malformed optional example appends its diagnostic instead of erasing the guidance; the explicit `profile` and `preview` commands stay strict. `test-reader.mjs` resolves every named section and function and varies example lengths without changing the guidance.

**`plan start <slug>` writes the planning document.** It creates `docs/planning/<slug>-<date>.md` with the nine section headings product 07 lists (dispatch and capture, readings, orders filed and amended, register, NoOps, sequence, write-backs and ceilings, process cost, validation), prepares the file with an exclusive open before `git switch -c`, removes only its own file when branch creation fails while `main` stays selected, and refuses a pre-existing document by name. The headings live in `scripts/lib/planning-document.mjs` beside that product paragraph.

**Document evidence binds the exact candidate tree.** A completion consumes an `npm run test:docs` row only when the row's tree hash equals the candidate's, reports, decisions and generated indexes included, so a later record edit cannot inherit an earlier pass. This is `main`'s rule restated after the order's interim projection was removed; `gate-evidence.mjs` is byte-identical to base, and `test-runner.test.mjs` pins that a changed report, decision, generated index, relocated record or newly introduced record refuses the old row while an ignored local file does not. The role text and product 07 say so in the same words.

**`quality pass: <target>` is a session command.** Every generated role carries one shared sentence from `packages/skeleton/src/document-quality.ts`: accept a file, a file list, a folder, a described set or a passage; resolve and announce the edit scope; ask only about material target or reader ambiguity; improve usefulness, currency, coherence and organization while preserving useful information, settled structure and sound passages; correct generated documents through their sources; run the existing checks; report what changed or needed no change; then continue the original task. In Claude Code the prompt hook also adds that sentence to the assistant's `additionalContext` when the prompt's own first content line opens with the command, the line every dispatch prefix is read from; it reads no earlier prompt or transcript, so a task notification or another agent's report, which opens with its envelope, never receives it, and an active `analysis:` control takes precedence. The command appends no lifecycle event, opens no gate and moves none of the six hook refusals; `docs-check` admits the prefix in decision dispatches and the meter counts it as a direction. `test-harness.mjs` covers the five target forms, blank-line and fenced leads, prose, quoted and envelope mentions, envelopes carrying the command after a delivered operator command (idle and mid-turn), queued words that open with the command, control precedence and an unchanged control log.

**Two adjacent repairs ride along.** The hedged-quantity scanner no longer reads a dotted version such as 2.1.312 as a quantity while a decimal such as 2.5 minutes is still reported ([D060](../../evidence/WO-235/decisions.md#wo-235-d060)). Three fixtures were stabilized: the exported-instance recovery case resolves the README conflict its stash application can meet, the target-worktree close fixture's fake Git exits naturally so piped output drains before its size is judged, and the target-briefing comparator normalizes volatile write counters.

The removal restored `main`'s router, journal sources, intervention count and Stop, and D063 returns the router's known Claude Code 2.1.312 attribution gap and six related follow-ups to planning under FUP-8331693069c2747d.
