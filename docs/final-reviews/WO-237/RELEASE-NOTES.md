## Release overview

A closed order no longer loses what its sessions recorded. Release close moves the worktree's session journals, session states, gate index and suite records into main's retained lane for the order, where they live for a window the operator owns (thirty days by default) before the prune removes them; planning's failure counts and the usage readback read them by order; and a temporary root created before a reboot is judged by its token and inode instead of being refused for a device number the reboot changed. This matters to operators who close orders and read `plan failures`, to maintainers who need a closed order's hook judgments, denials and operator messages after its worktree is gone, and to anyone whose host reboots between an order's work and its close. The worktree itself is still removed at close: it is gigabytes of regenerable captures, build output and packages, while the record kept is kilobytes to megabytes of journal.

## Read before upgrading

- The `retention` object in `docs/control/budgets.json` gains `closed-journal`, seeded at 720 hours; the kit template carries the seed, an instance whose budgets file lacks the key reads the default, `null` keeps every lane indefinitely and `0` removes lanes at the next prune. A runtime older than its budgets file ignores a retention key it does not define, while the gate's budget validation still refuses an unknown key.
- Release close now moves `*.jsonl` logs, session `*.json` states and their sidecars, `checks.json`, `suite-success/` and `deadlines/` from the closing worktree's `docs/control/local/harness/` into `docs/control/local/retained/WO-NNN/harness/` under main before the worktree is removed. The lane is ignored local material that holds host paths, session ids and operator-message digests; it is never committed. Gate captures, targets, excludes, the writer and the started markers stay with the worktree. A failed move is the close's cleanup blocker: the worktree stays, the cleanup row and `release-close.json` record `journals.outcome: failed` with the error and the retry command, and the published release stands; a rename across volumes copies and then removes; a retried close merges into the existing lane.
- `plan start` now applies the owned-resource prune across the host, every registered temporary root and the system temporary bases, where it previously printed a read-only census: expired temporary roots outside every close's scope leave at the next planning pass. While a gate holds the host lanes it prints the census and defers; an apply that stops partway names what it removed. `harness prune --apply` remains the on-demand route and kit update preview keeps its read-only census.
- A temporary root's owner record is judged by its token and inode. A device number that differs while the inode and the marker's token match, and the owner's ledger registers that token at that path, is re-stamped and ledgered as `device-renumbered` with both numbers. A removal first moves the root aside, to a sibling directory named `dotln-removing-` followed by the root's token, and deletes only a moved directory that still carries the record's inode and token; a removal that stops leaves that directory, which the next prune lists and finishes, so a `dotln-removing-*` directory is the kit's own bookkeeping and not residue to delete by hand. A renumbered root whose owner checkout no longer exists is still refused, as before this release (see the known limitations).
- `plan failures` output and export carry a new `retainedJournals` field after `localHostDenials`; a closed order's denials, interventions and stops include its lane's rows while the lane lasts, so one order's counts change when its lane is pruned. The start block's 1 KB bound is measured on compact JSON and an overrun prints one line naming the command; `boundAcceptances` renders a null ceiling as `unlimited`.
- `harness usage` for a session whose state is only in a retained lane answers from the lane: `source` reads `retained-lane:` followed by the lane's path, `counterSource` keeps the counters' provenance, `retained` names the order, lane, role and start, standing reads `closed`, and no usage row is appended. A session whose state two lanes hold is refused as ambiguous.
- Component versions: `@dotln/skeleton` 0.76.0; the console depends on it at that version and keeps its own 0.5.0; the compiler stays at 0.35.0. The generated hooks and manifest change by the runtime snapshot path alone; `node scripts/harness.mjs check` reports the drift in an instance and `npm run sync` regenerates them.

## Substantive changes

**The journals outlive the worktree.** `worktree finish` and `settle` move a closing worktree's session journals and other logs, session states and sidecars, gate index, suite-success and deadline records into main's retained lane for the order, under the writer lock, after every other removal check and immediately before the removal proof and `git worktree remove`; a file the repository tracks stays where it is. The lane records in `sources.jsonl` the worktree each move came from. An existing lane is merged, never replaced: a log appends, with each append recorded in `merges.jsonl` before it is published so a retried close counts no row twice and drops none; the gate index takes the union of its rows; an identical file is dropped; a differing state keeps its earlier bytes beside the newer one under a content-addressed name. Every destination, its ancestors and the lane's own records must be free of links before anything is written. The cleanup row and `release-close.json` record `journals: { lane, files, bytes, outcome }`.

**The lane is an owned root the prune judges.** The lane is created through the owned-root helper with class `closed-journal`, so the close-scope and all-scope prunes both find it, judge it by its class window, keep it under `null`, remove it at `0`, and name the class in the report and census. An order's retained lane waits while a journal lane inside it remains. A `closed-journal` root holds only the entries a close moves into it; any other entry retains the root.

**Two readers, no new reader.** `plan failures` reads every lane beside the checkout's own journals, attributes a lane's rows to its order, counts an unlistable lane as unreadable while the rest still count, and reports `retainedJournals` in the page, the export and the start block; a page names the sixteen most recently created lanes and counts the rest. `harness usage` finds a closed session's state in exactly one lane, measures its counters from the host transcript through the worktree paths the lane recorded, keeps credit-only observations, and refuses a session two lanes hold.

**A root is its token and its inode.** The owner record's device number is recorded for diagnosis and re-stamped when it differs, under the proof of the marker's token and the owner's ledger; a different inode, a token the ledger does not register at that path, or a record naming a repository that holds no such registration is refused and nothing is deleted. The transition is ledgered before the marker changes and once per renumbering. The legacy-backfill check and the starter-refresh scratch check follow the same rule.

**A removal deletes only what it verified.** One rename moves whatever holds the root's path aside under a name its token derives; the moved directory is deleted only when it carries the record's inode and its marker the record's token, and a replacement goes back to its path. Nothing inside a root is touched before it is verified, owned roots nested in it go with it, the owner record is deleted last, and a parent that refuses the rename refuses before anything inside is deleted. A root left aside by a stopped removal is listed through its ledger and finished by the next prune; a nested root left in a parent's aside is bound through the parent's registration.

**Routine cleanup has a home.** `plan start` applies the prune under the host lane lock and prints the apply's report, the deferred census while a gate holds the lanes, or a stopped apply's progress before the census of what remains; a root removed before its bookkeeping failed is still reported as removed, and a stale Codex home listing that cannot inspect an entry is reported as unavailable instead of replacing the prune's result. The three suites that run `plan start` in fixtures scope their prune to the fixture repository.

**Planning's start block and feed.** The start block's bound is measured compact, clipping only its two reason strings and, if the block still overruns, keeping the command, window and item count with one overrun line; the feed renders an unlimited acceptance ceiling as `unlimited`.

**Documentation.** Product 07 states the lane, the class and the seed, what moves and what stays, the ignored-local boundary, the identity rule and the removal's shape, and that `plan start` applies the prune; the kit README states the same for an instance, including the `closed-journal` seed in its read-before-upgrading list.
