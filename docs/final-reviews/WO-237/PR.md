# WO-237 — A closed order keeps its journals, and a temporary root survives a reboot (v0.107.0)

Until now release close removed an order's worktree with every session journal, session state and gate index inside it, so a closed order's hook judgments, host denials, dispatch rows and operator messages were gone the moment it closed: `plan failures` counted denials and interventions from the current checkout's journals only, the fork's executor could not read earlier orders' journals on 2026-10-28, and the first close after a reboot refused six of the kit's own regenerable build directories because their owner records carried the volume's old device number. This pull request keeps the small record and lets the large residue go. Before the worktree is removed, the close moves its session journals and other logs, its session states with their sidecars, the gate index and the suite-success and deadline records into main's ignored retained lane `docs/control/local/retained/<WO>/harness/`, an owned root of the new `closed-journal` class that the prune judges by a window the operator owns in the budgets file (seed 720 hours; `null` keeps; `0` removes at the next prune), while gate captures, targets, excludes, the writer and the started markers fall with the worktree or their own classes ([D001](../../evidence/WO-237/decisions.md#wo-237-d001--a-closed-orders-journals-move-into-its-retained-lane), [D002](../../evidence/WO-237/decisions.md#wo-237-d002--the-closed-journal-class-its-seed-and-readers-of-a-newer-budgets-file), [D003](../../evidence/WO-237/decisions.md#wo-237-d003--the-prune-judges-a-journal-lane-by-its-class-and-the-orders-lane-waits-for-it)).

Two readers follow the journals. `plan failures` reads every lane beside the checkout's own journals, counts a lane's rows for the lane's order whatever order a row names, and reports `retainedJournals` with the lanes read, their window and the oldest lane's start, so a reader can tell coverage from behavior; `harness usage <session>` answers for a closed session from its lane, naming the lane as `source`, keeping the counters' own provenance as `counterSource`, reporting standing `closed` and appending no usage row ([D006](../../evidence/WO-237/decisions.md#wo-237-d006--plan-failures-reads-the-lanes-the-start-blocks-bound-is-compact-and-unlimited-reads-as-unlimited), [D007](../../evidence/WO-237/decisions.md#wo-237-d007--harness-usage-reads-a-closed-session-from-its-lane)). Two carry-ins close in the same file: the start block's 1 KB bound is measured on compact JSON and an overrun prints one line naming the command instead of refusing the planning branch, and an acceptance recorded with `--ceiling unlimited` reads `unlimited` in the feed. The routine removal of expired temporary roots outside every close's scope also has a home: `plan start` applies the prune it already ran as a census, prints the read-only census and defers while a gate holds the host lanes, and names what it removed when an apply stops partway ([D005](../../evidence/WO-237/decisions.md#wo-237-d005--plan-start-is-where-expired-roots-outside-every-close-leave)).

A temporary root is its token and its inode. A record whose device number differs from the directory's current one, with the inode and the marker's token unchanged and the owner's ledger registering that token at that path, is re-stamped with the current number, ledgered as `device-renumbered` with both numbers, and judged by its class and window; a different inode, a token the ledger does not register there, or a record naming a repository that holds no such registration is still refused and nothing is deleted. The removal changed shape under the independent reviews: it moves the root aside to `dotln-removing-<token>` beside its path by one rename, deletes only a moved directory that still carries the record's inode and token, puts a replacement back, deletes the owner record last, and a root that a stopped removal left aside is listed and finished by the next prune ([D004](../../evidence/WO-237/decisions.md#wo-237-d004--a-root-is-its-token-and-its-inode)).

A failed move is the close's existing cleanup blocker: the worktree stays, the cleanup row and `release-close.json` record `journals.outcome: failed` with the error and the retry command, and the published release is untouched; a rename across volumes copies and then removes; a retried close merges into the existing lane, each append recorded in the lane's `merges.jsonl` so a retry counts no row twice and drops none, with the gate index taking the union of its rows and a differing state keeping its earlier bytes beside the newer one.

Validation: the complete `npm test -- --review` run at code identity `5a4b8345…` passed on 2026-11-01 (45 suites, 115 fresh tasks, 0 h 36 min, exit 0); six paired [controls](../../evidence/WO-237/controls.json) show each mechanism absent with its reversion and present here; [VER-001](../../verifications/WO-237/VER-001.md) passed on an independent nine-variation matrix, an exact-baseline archive and focused reproductions, and boarded four interrupted-removal bookkeeping cases ([D013](../../evidence/WO-237/decisions.md#wo-237-d013--verification-keeps-the-four-recovery-findings-as-follow-ups)); [FINAL-001](FINAL-001.md) accepted the unchanged subject at that identity after rerunning those probes, the focused cases and both release close cases, and boarded one finding of its own ([D015](../../evidence/WO-237/decisions.md#wo-237-d015--final-review-passes-at-the-handoff-identity-integration-takes-in-nothing-and-a-renumbered-root-whose-checkout-is-gone-stays-refused)).

What a reviewer should know: the lane is ignored local material and is never committed, because journals hold host paths, session ids and operator-message digests; a target worktree keeps no journals and a target close moves nothing, a known issue whose reopening condition the fork has already met ([D009](../../evidence/WO-237/decisions.md#wo-237-d009--the-forks-messages-of-2026-11-01-and-cores-last-close-message)); `plan start` now removes expired temporary roots across the host where it previously printed a census; a renumbered root whose owner checkout has already been removed is still refused, as it was at `main` (F1, D015); four recovery edge cases after two interrupted removals in a row are recorded, not fixed (D013); the three independent reviewers ran as read-only Codex sessions on the operator's direction, their fixes after the fourth recheck went unrechecked, and the order took five complete runs, the fourth stopped under the operator's override ([D011](../../evidence/WO-237/decisions.md#wo-237-d011--the-independent-reviews-ran-on-codex-and-what-they-changed), [D012](../../evidence/WO-237/decisions.md#wo-237-d012--the-operators-override-stopped-the-fourth-complete-run)); the original three review reports were not found at verification and the consolidated [reviews](../../evidence/WO-237/reviews.md) record stands in ([D014](../../evidence/WO-237/decisions.md#wo-237-d014--verification-capture-limits-and-missing-original-review-files)). The skeleton moves to 0.76.0 with the console's dependency following; no dependency is added.
