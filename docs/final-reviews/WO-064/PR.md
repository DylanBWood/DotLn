# WO-064

A source change DotLn governed on another repository can now become a pull request on that repository. `worktree publish WO-NNN --target <request.json>` reads the finished source-change episode, pushes exactly the commit the host observed and opens one pull request through the existing `gh` helper, then records `PullRequestOpened { repositoryId, number, headSha }` in the episode store's own `publication/` log. It is the first remote effect DotLn runs under compiled authority: each of `repo.push` and `pr.open` must be allowed by the envelope and the WorkOrder, pass the kernel guard, and be named by an admitted grant whose `grantedBy` is `operator`; a `host-policy` grant or no grant refuses. The self-publication path is unchanged apart from its `gh` preflight moving into `github-repository.mjs` so both paths share it.

**The pull request says only what the artifacts say.** The title is the host-authored commit subject, which must equal the observed commit's. The body is generated by a pure function over the WorkOrder's objective, non-goals and acceptance criteria, the host's before and after test outcomes, and the diff summary; contract text is escaped so Markdown, mentions and `#` references render literally, and no worker prose, test command or local path reaches it. Without a verification store every criterion reads `not independently verified`. The branch, every pushed commit message, the title and the body pass the WO-063 outward lint before anything leaves the machine, and an absent local-terms list refuses rather than passes.

**Publication is bound to the change it publishes.** The host recompiles the loadout with the host grant registry for authority, and without its publication grants for identity: that writer form must equal the persisted command's artifact identity, WorkOrder and envelope, so an edited contract cannot be published as the one that produced the change. The target branch must still name the observed commit and the binary diff digest must match the receipt. Every refusal precedes the first `gh` call and the push, which fixtures assert as an empty `gh` log, no remote branch and no publication log; a rerun for the same head pushes nothing.

**One verification failed, and the repair holds.** [VER-001](docs/verifications/WO-064/VER-001.md) showed that an acceptance matrix selected by revision alone could put an unrelated `verified` criterion into the pull request. [D009](docs/evidence/WO-064/decisions.md#wo-064-d009--repair-a-supplied-acceptance-matrix-must-carry-exactly-the-workorders-criteria-or-publish-refuses) binds a supplied matrix to the WorkOrder by exact criterion text, the compiler's own coverage rule, at both the generator and the host, and renders it in contract order; a same-head mismatch refuses before any remote call. [VER-002](docs/verifications/WO-064/VER-002.md) reproduced the refusal and passed.

**What a reviewer should know.** The push runs in the target repository, so Git runs that repository's own `pre-push` hook with the operator's Git and `gh` credentials. The product already records that neither writer sandbox confines a write outside the worktree, and the writer commits into the target's shared Git directory, but no probe has shown a sandboxed writer placing a hook there; final review boards this up with a probe-and-fixture follow-up rather than silently disabling targets' legitimate hooks ([D010](docs/evidence/WO-064/decisions.md#wo-064-d010--board-up-the-publish-push-runs-the-target-repositorys-git-hooks-with-the-operators-credentials), `FUP-df9179fc4e1447a6`). Until then, inspect a target's hooks before publishing a model-written change. The skeleton still refuses an artifact identity compiled with a grant registry, which is why the writer runs a grant-free compilation ([D006](docs/evidence/WO-064/decisions.md#wo-064-d006--board-up-a-grant-bearing-artifact-identity-is-refused-by-the-skeleton), `FUP-a829a8799711b2ea`). The live smoke's writer was the deterministic double, not a model, and it supplied its scratch grant as explicit host input to the same function the CLI calls. A crash between pull-request creation and the event append needs manual inspection. The adjacent-queue item for D006 still targets prose rather than its public identifier because the queue refuses changes in review ([D011](docs/evidence/WO-064/decisions.md#wo-064-d011--the-deferred-adjacent-item-still-targets-prose-instead-of-its-public-follow-up)). One commit in this PR is not WO-064's own work. The reviewer's first gate failed in the `configuration-root` machinery suite, which runs here only because this order edits `scripts/worktree.mjs`. Both failing cases fail on `main` without WO-064: a comment in `entropy-review.mjs` spelled the planning root as a path literal the root guard counts, and a fixture hard-coded a 2026-09-21 planning-pass heading that `planningPassScope` stops admitting once the fixture commit is dated later. At the operator's direction the reviewer rewords the comment and pins the fixture commit's date. No verifier judged those two edits; the suite is their check ([D012](docs/evidence/WO-064/decisions.md#wo-064-d012--repair-two-defects-already-on-main-that-the-review-gate-selected-at-the-operators-direction)).

**Validation.** `npm test -- --review` passed **29 suites, 0 failed, 341.15 s, 73 fresh tasks, exit 0** at tree `09660a9d`, code identity `ce87ae9a`, with the sandbox not in force; that row binds the released bytes. The reviewer's first gate at this subject failed 27 of 28 in `configuration-root` before D012's fixes, and the executor's and verifiers' plain `npm test` rows (26 suites each) were computed at earlier code identities, so none of them binds it. The live smoke against an empty scratch GitHub repository pushed the observed commit and opened one pull request whose head, title and body read back equal to the pushed commit, the host commit subject and the pinned generated body, recorded as shapes in [smoke.json](docs/evidence/WO-064/smoke.json). `git diff --check` is clean, `package.json` and the lockfile are unchanged, and `plan check` and `publication:check` pass. Verification was independent of implementation in harness and model: implementation and repair ran on Claude Code 2.1.280 / `claude-opus-5-5[1m]`, and both verifications on Codex CLI 0.155.1 / `gpt-6-sol` with session readback. Review ran on Claude Code 2.1.280 / `claude-opus-5-5[1m]` at `xhigh`, the same harness and model as implementation.

This prepares application `v0.43.0` as a minor release; compiler, kernel, skeleton and console versions are unchanged and no dependency is added. `main` did not move during review, so nothing was integrated. Full evidence: the [implementation receipt](docs/evidence/WO-064/implementation.md), [decisions D001–D012](docs/evidence/WO-064/decisions.md), [VER-001](docs/verifications/WO-064/VER-001.md), [VER-002](docs/verifications/WO-064/VER-002.md) and [FINAL-001](docs/final-reviews/WO-064/FINAL-001.md).
