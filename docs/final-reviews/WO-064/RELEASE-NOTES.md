## Release overview

DotLn can now publish a source change it governed on another repository as a pull request on that repository. Until this release a worker's change on a target repository stopped at a local branch: `worktree publish` opened pull requests only on DotLn's own repository, and no remote effect had ever run under a compiled grant. `worktree publish WO-NNN --target <request.json>` pushes exactly the commit the source-change host observed and opens one pull request, but only when the order's loadout carries an `operator`-provenance grant for both `repo.push` and `pr.open`, the finished episode still matches the loadout that produced it, and every outward artifact passes the outward-artifact lint. The title and body are generated from the contract, the acceptance status, the host's own test observations and the diff; nothing the worker wrote as prose reaches the pull request. This is the publication step of the source-to-deliverable loop, and the step pull-request observation (WO-065) builds on.

## Read before upgrading

The self-publication path is unchanged: `worktree publish WO-NNN` with `--title` and `--body-file` behaves as before, and its `gh` preflight moved into `scripts/github-repository.mjs` without a behavior change so both paths share it. The target path is new and opt-in. It needs a host-owned request file naming the loadout, its compilation environment, the episode store, the pull-request base branch and an optional verification store, and it needs the operator's grant in the committed registry `packages/skeleton/loadouts/grants.json`; a `host-policy` grant in the local registry is refused. An absent local-terms list refuses publication rather than passing it. The push runs in the target repository and Git runs that repository's own `pre-push` hook with the operator's credentials; until a probe shows a sandboxed writer cannot place one, inspect the target's hooks before publishing a model-written change ([D010](../../evidence/WO-064/decisions.md#wo-064-d010--board-up-the-publish-push-runs-the-target-repositorys-git-hooks-with-the-operators-credentials)). The application moves to `v0.43.0`; compiler, kernel, skeleton and console versions are unchanged and no dependency is added.

## Substantive changes

**Publication is bound to the episode that produced the change.** The host recompiles the order's loadout twice from the one source: once with the host grant registry, which supplies the publishing authority, and once without its publication grants, the form the writer ran. The writer form must equal the persisted command's artifact identity, WorkOrder and envelope, so a contract edited after the change cannot be published as the contract that produced it, while adding the publication grant after reviewing the change is allowed. Repository, base and branch come from the store's own events and the immutable receipt; the target branch must still name the observed commit, and the recomputed binary diff digest must match the receipt.

**Authority comes only from an operator grant.** Each of `repo.push` and `pr.open` must be allowed by the effective envelope and the WorkOrder, pass the kernel guard with the episode's persisted authority evidence and its events as revocation input, and be named in both effects and operations by an admitted grant whose `grantedBy` is `operator`. The writer itself never holds either effect.

**Every artifact passes the outward lint before the first remote call.** The branch name, every pushed commit message, the title and the generated body go through the WO-063 lint; a finding names its rule, and an unavailable local-terms list refuses. The body is also checked for the GitHub prose profile and AI attribution. Only then does the host push the observed commit with no tags and no upstream configuration, open the pull request through the existing `gh` helper, and record `PullRequestOpened { repositoryId, number, headSha }` in the episode store's separate `publication/` log. A rerun for the same head reports the recorded pull request and pushes nothing.

**The body is generated from artifacts, never from narrative.** `generateTargetPullRequest` takes the host commit message, the WorkOrder contract, the host's before and after test outcomes, the diff summary and an optional acceptance matrix, and has no free-text input. Contract text is collapsed to one line and escaped so Markdown, mentions and `#` references render literally. Without a verification store every criterion reads `not independently verified`. A supplied store must hold exactly one acceptance matrix for the published head whose criteria are exactly the WorkOrder's; the first verification found that a matching revision alone let an unrelated `verified` criterion into the table, and publication now refuses that before any remote call and renders a matching matrix in the contract's order.

## Progressive polish

The worktree integration fixture now overlays the root-level modules `worktree.mjs` imports statically, so a working-tree entry point and its peers never split across committed copies; the fixture failed once on exactly that split when `ensureGh` moved. The CLI usage line names the new target form. Two defects already on `main` in the configuration-root machinery suite are repaired: a documentation comment in the Entropy Reducer module no longer spells the planning root as a path literal the root guard counts, and the planning-scope fixture pins its commit date to the day its ledger heading names, so it no longer fails on every day after 2026-09-21. Neither changes runtime behavior ([D012](../../evidence/WO-064/decisions.md#wo-064-d012--repair-two-defects-already-on-main-that-the-review-gate-selected-at-the-operators-direction)).

## Evidence and compatibility

This prepares application `v0.43.0` as a minor release over `v0.42.0`, the classification the order declared. The reviewer's product gate is the record that binds the released bytes: `npm test -- --review`, **29 suites, 0 failed, 341.15 s, 73 fresh tasks, exit 0**, tree `09660a9dbb8afe6a99ca20a8f74a523c0f220ed7`, code identity `ce87ae9adcc91b259e86d83d982cb510ba96d6e2e1175fbd797b1d221ea6d865`, recorded 2026-09-22T19:33:27.480Z with the sandbox not in force. The reviewer's first gate at this subject failed in the `configuration-root` machinery suite on two defects already on `main`, repaired here at the operator's direction. The target-publish suite runs five cases over real source-change episodes, a bare origin behind a GitHub URL and a `gh` stub: no grant, a `host-policy` grant, an edited contract, a moved branch, a local-term finding, an absent local-terms list, a matrix for another revision and a same-head matrix for other criteria each refuse with no `gh` call, no remote branch and no publication log; the granted run pushes only the observed commit, opens one pull request whose body is byte-equal to the pinned fixture and records one event. An operator-run live smoke against an empty scratch GitHub repository pushed the observed commit and opened one pull request whose head, title and body read back equal to the pushed commit, the host commit subject and the pinned body, with one event recorded; its writer was the deterministic double rather than a model, and the scratch repository's identity is recorded only as a shape. The sequence had two verifications: [VER-001](../../verifications/WO-064/VER-001.md) failed the acceptance-matrix binding and [VER-002](../../verifications/WO-064/VER-002.md) passed the repair.

Known limitations, each on the record. Git runs the target's own push hooks with the operator's credentials, and whether a sandboxed writer can place one is not established ([D010](../../evidence/WO-064/decisions.md#wo-064-d010--board-up-the-publish-push-runs-the-target-repositorys-git-hooks-with-the-operators-credentials), follow-up `FUP-df9179fc4e1447a6`). The skeleton refuses any artifact identity compiled with a grant registry, so the writer runs a grant-free compilation and a writer loadout that needs any other grant cannot yet be published ([D006](../../evidence/WO-064/decisions.md#wo-064-d006--board-up-a-grant-bearing-artifact-identity-is-refused-by-the-skeleton), `FUP-a829a8799711b2ea`). Only a plain source-change episode is published; a repair continuation is refused. A crash after the pull request is created and before the event is recorded needs manual inspection. The acceptance binding is exact criterion text, the compiler's own rule, not a cryptographic identity of the WorkOrder. Pull-request observation, merging and releasing on the target stay out of scope.
