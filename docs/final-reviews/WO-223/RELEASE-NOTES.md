## Release overview

Application v0.88.0 lets an exported instance that has moved an order's records into its registered target take a starter release and run its gates, its launchpad publish and its target publish without a step the kit did not name. The operator's own instance held starter v0.87.0 as a draft update pull request because the kit's document gate failed on its moved decisions records. This release repairs that gate, lets the moved-record readers find the clone mapping from a secondary worktree while the primary checkout holds a planning branch, names the sign-off declaration before a launchpad branch's first commit, prints the expected release-close helper spelling and the class of a mismatch, corrects the kit README's target publish spelling to the form the hook admits, and prints a commit subject's length beside the 72-character limit when the lint refuses it.

Audience: operators of exported instances taking this starter release, above all an instance with moved target records; operators of this repository who run release close; and the planner who reads the three boarded follow-ups.

## Read before upgrading

- **The document gate reads a moved decisions record through its binding.** `checkDocs` takes a moved row's text from the source `readDecisions` already read and verified through the immutable repository, commit, path and hash binding, so `docs-check` and the checks after it (`entropy`, `reader-profiles`, `plan` and `plan-refutation-current`) run over moved records as over local ones. A local row is read as before, and a retained local copy is still compared with one immutable read. An unreadable moved record now fails naming its binding, the repository id, commit and path ([D003](../../evidence/WO-223/decisions.md#wo-223-d003)).
- **The moved-record readers look in three places and refuse naming all three.** `readTargetRecord` reads the ignored clone mapping from the running checkout, then the primary checkout (the worktree whose Git directory is the common Git directory, whatever branch it holds), then a worktree on `main`. The former fallback to the order's target-registry entry is removed: with no mapping in those three places the reader refuses and names them and the arrangement, where v0.87.0 read through the registry entry. Keep the ignored clone mapping in one of those checkouts, which is where `worktree clone` writes it ([D004](../../evidence/WO-223/decisions.md#wo-223-d004)). The target publish and the pre-review commit lint still resolve the main-branch worktree, so a final review or target publish from a launchpad whose primary checkout is on a planning branch is unchanged by this release; planning receipt 051 carries that limit with its reopening condition.
- **The sign-off rule is named before the first commit.** `worktree start` of a launchpad order prints one advisory when the instance's `dotln.config.json` declares no `contributions.operatorAuthor`: every commit on the branch needs a `Signed-off-by` trailer matching its author, or the instance declares the identity through a reviewed change. The publish-time `FAIL contribution-signoff` line names the same two routes. The rule itself decides the same commits as before ([D006](../../evidence/WO-223/decisions.md#wo-223-d006)). The FAIL line offers the declaration route even when an operator identity is already declared, and a target order's start prints no advisory although its records publish meets the same rule; both are boarded ([D018](../../evidence/WO-223/decisions.md#wo-223-d018), [D020](../../evidence/WO-223/decisions.md#wo-223-d020)).
- **The release-close advisory says what it expected.** For a dispatched order whose helper suffix differs from the byte-exact form, the generated hook's advisory now prints the expected `--publish` and `--dry-run` spellings and the mismatch class: a shell operator or redirect, non-canonical material flag quoting or value, or extra words or whitespace after the helper. The four admitted forms are unchanged and each is asserted by a case; the helper is still withheld and host permissions still decide ([D007](../../evidence/WO-223/decisions.md#wo-223-d007), [D014](../../evidence/WO-223/decisions.md#wo-223-d014)). A suffix that mixes a canonical material word with another mismatch is named by the material class, and the displayed text ends with the host-permissions phrase twice, as at v0.87.0; both are boarded ([D017](../../evidence/WO-223/decisions.md#wo-223-d017)).
- **The kit README's target publish form is the node spelling.** The session form is `node scripts/worktree.mjs publish WO-NNN --target-worktree` with its `--branch`, `--title` and `--body-file` values, run from the launchpad root; the `npm run worktree -- publish` form is named as withheld. The update route states the readers' lookup order ([D005](../../evidence/WO-223/decisions.md#wo-223-d005)).
- **Commit-lint refusals print the length and the limit.** The pre-review refusal before `final-review-result pass` and the publish-time refusal print the subject length and the limit, as `subject.length: 90 of 72 characters` for a 90-character subject, counting code points as the lint does, with the limit read from the one constant in `scripts/lib/outward-lint.mjs` ([D008](../../evidence/WO-223/decisions.md#wo-223-d008)).
- **Versions.** Application v0.88.0 is a minor release over v0.87.0, assigned at activation under the order's classification ([D001](../../evidence/WO-223/decisions.md#wo-223-d001), [D011](../../evidence/WO-223/decisions.md#wo-223-d011)). Skeleton moves from 0.63.0 to 0.63.1 for the advisory text; the console pin and the lockfile follow; no other component changes and no dependency is added.

## Substantive changes

**The document gate and the moved-record readers** (`scripts/docs-check.mjs`, `scripts/lib/meta.mjs`, `scripts/lib/target-record-reader.mjs`, `scripts/lib/git.mjs`). The decisions loop of `operatorWordFindings` reads a moved row from `row.recordSource` and a local row through `readListed`; `readDecisions` wraps a failed immutable read with the record's binding. `primaryWorktree` resolves the worktree whose real Git directory equals the common Git directory, skipping bare and prunable entries; `readTargetRecord` consults the running checkout, that primary checkout and the main-branch worktree in order and refuses naming all three.

**Launchpad start and the sign-off rule** (`scripts/worktree.mjs`, `scripts/lib/contributions.mjs`). After a launchpad order's worktree is created, `start` loads the new checkout's configuration and prints one advisory when `contributions.operatorAuthor` is absent; the FAIL line of `contributionSignoffRules` names the declaration route beside the trailer route.

**The release-close admission's advisory** (`packages/skeleton/src/harness-host.ts`). `releaseCloseAdmission` keeps its admission grammar and, on the withheld branch, strips quoted and backslash-escaped text before classifying the suffix, then prints the expected spellings for the dispatched order and the class. The harness bundle and manifest are regenerated from it.

**The commit lint's refusals** (`scripts/lib/outward-lint.mjs`, `scripts/lib/target-commit-lint.mjs`, `scripts/lib/target-publish.mjs`). `outwardFindingText` formats a `subject.length` finding as `subject.length: 73 of 72 characters` from the first line's code points and `subjectLengthLimit`; `lintReviewedTargetCommits` and `lintArtifacts` print it.

**Write-backs** (`docs/product/07-execution-guide.md`, `scripts/kit/README.client.md`). Product 07 states the readers' lookup order in §Where the control plane finds its documents and the advisory's spellings and classes in §Workflow closeout and releases; the kit README names the node session form, the withheld npm form and the worktree arrangement the readers need.

**Tests.** The moved-records case runs `checkDocs` over the fixture launchpad and compares the carried text with a fresh immutable read; a new case arranges the fixture launchpad with its primary checkout on a planning branch, reads from the secondary, runs the meta writer and its check there, and asserts running-over-primary and primary-over-main precedence, the `main` fallback and the three-place refusal; the exported-instance case asserts exactly one start advisory and runs the instance's own document gate over a moved record; the WO-178 hook case asserts the advisory text for redirected, piped, extra-flag, double-quoted, unquoted and escaped-character suffixes beside the four admitted forms; the outward-lint, target-publish and target-worktree suites assert the subject-length text at both refusals; the license-surfaces case asserts the FAIL line; the worktree script fails if a declared exemption still prints the advisory; the runner's target-worktree inventory counts the two new cases.
