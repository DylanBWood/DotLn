## Release overview

A source-change episode now has a host. One compiled WorkOrder becomes one governed branch worktree in a target repository, with the bundle emitted into it, the order's focused test recorded before and after, the `source-change-v1` writer dispatched, and the resulting commit identity persisted as an immutable effect receipt. That receipt is the release's payoff: a host killed mid-episode recovers by reading Git instead of dispatching a second writer, so a crash cannot produce two commits. This is the last piece before the first real external source change (WO-053); the inspection host, its workers and every historical replay are untouched.

## Read before upgrading

No migration is required and no stored data changes meaning. Three event types are added under schema 1 — `SourceChangeRequested`, `SourceChangeObserved` and `SourceChangeRefused` — folded by the slice WO-050 reserved; the event schema version, the command hash preimage and every existing Decision trace are unchanged, and the 19 recorded transcripts replay byte-identically. Authority: the emitted target permission guard now admits three exact host-selected commands — the order's focused test, `git add -A` and a `git commit -F` of the host-written message file — but only while a launchpad-side grant has a live owner, an unexpired deadline capped at the transport's invocation deadline, and a matching branch, base and message digest; the grant lives where the target worker cannot write it, an invalid or expired grant fails closed, and the route adds a second authorization for the narrower `shell.run` or `git.local` effect rather than replacing the existing screen, so it cannot widen target authority. This is trusted-host governance, not OS isolation of an arbitrary test script, and an expired lease is not proof that an orphaned writer process stopped. No live writer was launched in this release. One red gate is recorded with it, and it is not this release's. The machinery suite `process-debt` fails three subtests that assert the pre-presence harness hook wiring; that failure is inherited from the previous release and reproduces without this release's changes, with its reproduction in the final review. The release's own capability write-back also met the planning-continuation gate, which refuses an id absent from the judged subject; that was cleared during final review by a narrow admission pass, an independent refutation and receipt 016, so the document gate is green, and a filed work order removes the recurrence. `@dotln/skeleton` moves to 0.24.0; kernel and compiler versions are unchanged, and no dependency is added or removed.

## Substantive changes

Source-change host: `SourceChangeHost` accepts a compiled WorkOrder, its artifact identity, a supplied authority envelope and separately established authority evidence — required evidence is never treated as observed evidence — then creates the branch worktree from the declared base, emits the matching target bundle, records the focused test as `testBefore`, dispatches, and derives the outcome from Git. It checks every changed path against the declared surfaces, plus branch identity, base ancestry, a clean committed tree and the bundle's own bytes, and rechecks authority before dispatch, after completion and around the after-test.

Effect receipt and recovery: the worker store gains an immutable `.source-change.json` receipt binding the canonical request key to the commit, branch, base-relative binary diff digest and both test observations, written through the existing durable staging path and positively decoded before any lock reclaim. Recovery reads Git first: a clean descendant commit on the declared branch is observed and saved without a second dispatch, a baseline branch permits exactly one recovery dispatch, and a further interruption refuses with `recovery-dispatch-exhausted`. A recovered Git effect never fabricates a worker result, and a failing after-test stays an observation rather than becoming a verification pass.

Reactor: a pure `source-change-state` module supplies the fold for the `sourceChange` slot WO-050 reserved, with positively decoded payloads, deduplicated terminal events and refusal of cross-order, cross-branch or conflicting results. The reactor diff adds exactly one fold case and touches no other slice.

Refusal and preservation: a worker that returns edits without a commit yields `SourceChangeRefused` with its reason and keeps the edits; dirty committed trees, foreign branches, out-of-surface commits, changed requests and malformed receipts all refuse without discarding work. Only an explicit `finish()` removes a worktree, after checking the persisted receipt and refusing unowned residue; nothing pushes, rebases, force-removes or resets.

Documentation: 02 §Actors and episodes carries the three payload shapes, the receipt rule and the schema note; 03 §Session lifecycle & resilience carries recovery by commit identity, the route's fences and the explicit-finish contract; the skeleton README gains a runbook and its pointer; the capability table gains a dated, fixture-evidenced `worker.source-change` row.
