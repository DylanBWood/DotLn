# :sparkles: A killed source-change episode recovers from its commit instead of dispatching a second writer

DotLn can now run one compiled WorkOrder as a source-change episode in another repository: it creates the declared branch worktree from the declared base, emits the governed target bundle into it, runs the order's focused test and keeps that observation before anything is dispatched, launches the `source-change-v1` writer from WO-051, and then reads Git rather than the worker's prose to decide what happened. The commit identity is persisted as an immutable effect receipt, which is the point of the order: a host that is killed after the writer commits recovers by reading the branch and records the observation without a second dispatch, and a host killed before the commit re-dispatches exactly once. Three real `SIGKILL` windows are fixtures, each killing a separate process so that every recovery input has to survive on disk.

The host never claims more than it observed. A worker that returns edits but no commit produces `SourceChangeRefused` with its reason and the edits are preserved; a failing after-test is recorded faithfully as an observation, never as a verification pass; a recovered Git effect never fabricates a worker result. Every changed path is checked against the order's declared surfaces, along with branch identity, base ancestry, a clean committed tree and the bundle's own bytes, and the worktree is removed only by an explicit `finish()` that refuses unowned residue. Nothing pushes, rebases, force-removes or resets.

The one authority change is narrow and checked in both directions. The emitted target permission guard now admits three exact host-selected commands — the order's focused test, `git add -A`, and a `git commit -F` of the host-written message file — while a launchpad-side grant has a live owner, an unexpired deadline that is capped at the transport's own invocation deadline, and a matching branch, base and message digest. The grant lives where the worker cannot write it, an invalid or expired grant throws and fails closed, and the route adds a second authorization for the narrower `shell.run` or `git.local` effect rather than replacing the existing one: a fixture narrows the target envelope to deny `git.local` and watches the test command still pass while `git add -A` refuses, proving the route cannot widen target authority. `git push`, an appended `&& git push`, a near-miss message path, a wrong cwd, an expired grant, a dead owner and a revoked grant are all refused by fixtures.

Every writer here is a process double against a real scratch Git repository; no live writer was launched at any phase, and the live episode remains WO-053. Store leases and exact command routes are trusted-host governance, not OS isolation of an arbitrary test script and not proof that an orphaned writer process has stopped.

**Merging needs one thing first.** The order's write-back duty adds a new capability id, `worker.source-change`, and the planning-continuation gate rejects a new id by design, so `npm run test:docs` is red on this branch (`plan`, `plan-refutation-current`). A planning dispatch that admits the id into the judged subject clears it; merging before that turns the document gate red on `main`. No repair can discharge it — deleting the row violates criterion 5 and authoring a planning receipt is the planner's dispatch — and this is the second occurrence, after WO-068's identical condition on `runtime.resident`, whose nomination to the planner is still open.

Validation, stated in full because two gates are red: the product gate `npm test` passed 19 suites, 0 failures, 63 fresh tasks in 302.64 s outside the sandbox, and `git diff --check` is clean. The reviewer's wider `npm test -- --review` selection did **not** pass — 27 of 28 suites, with `process-debt` failing on three subtests that assert the harness hook wiring as it was before WO-121 added the four presence hooks. All three reproduce byte-for-byte on a clean `main` tree built from `git archive main`, with none of this order's bytes present, so the defect is inherited rather than introduced; it surfaced now only because that suite declares `packages/skeleton/src/harness-host.ts` and this is the first order since `417c094` to change it. It is not repaired here: a reviewer does not write a behavioural fix and certify it, and the correct assertions are a presence-contract choice this order does not own. [FINAL-001](https://github.com/DylanBWood/DotLn/blob/wo-052/docs/final-reviews/WO-052/FINAL-001.md), [VER-001](https://github.com/DylanBWood/DotLn/blob/wo-052/docs/verifications/WO-052/VER-001.md) and [WO-052-D004](https://github.com/DylanBWood/DotLn/blob/wo-052/docs/evidence/WO-052/decisions.md#wo-052-d004) carry the evidence, the reproduction and the reopening condition. Only `@dotln/skeleton` moves, 0.23.0 to 0.24.0, with no dependency change. Release target: v0.28.0 under the order's minor classification.
