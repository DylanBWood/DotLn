## What this merges

WO-025, the `v0.3.3` patch work order: every public statement of "which release is this" is now derived from, or checked against, release truth at the two moments that matter, before the reviewed branch is pushed and before the tag is cut. The root README states the release of the source it is in, a component's version can no longer stay frozen while its source moves, the skeleton banner reads its own manifest, and reviewed PR and release-note prose is authored for the reader's renderer instead of an 80-column terminal.

- **The defect:** `v0.3.0` was tagged from a commit whose README still described `v0.2.3` as the published boundary, because the front page is only ever edited inside work-order branches before the release exists and release close pushes a tag, never a commit. The skeleton gained a module in `v0.3.0` while its package version and its hardcoded banner stayed at `0.2.0`.
- **One block, one claim.** `README.md` §What runs today carries one delimited release block stating "This source is DotLn `v0.3.3`" with the version-bound "what runs today" sentences and pointers to the GitHub Releases page and `npm run release -- notes`. No sentence outside the block asserts a current boundary; historical mentions stay time-indexed.
- **Expected version is release truth, not the latest tag.** The block must name the work order's H1 target when that target is strictly above the latest published annotated tag, otherwise the latest tag. A no-release work order therefore leaves the block alone, and a refused close carries the same version into its patch order.
- **Component versions move with their source.** For each package under `packages/`, a `src/` diff against the previous release's commit requires a `package.json` version that differs from that release's manifest entry; a change confined to tests or the package README needs no bump, and a new component receives a first-version baseline. `@dotln/skeleton` is corrected forward to `0.3.0` with a dated note; `@dotln/kernel` stays `0.1.0` with byte-identical source. The CLI banner derives from `package.json` at runtime and a node test binds it.
- **Two gates, one check.** `npm run release -- check-surfaces` is a read-only preview that prints one PASS or FAIL line per rule with observed and expected values. `worktree publish` and `release close` run its committed mode, folding control state from `HEAD:docs/control/resume.jsonl` and reading version-bearing bytes from `HEAD`, so hidden working-tree or index edits and a stale generated projection cannot substitute for what will be pushed or tagged. Publish runs it before the `gh` preflight and the push; close runs it after synchronization and before `npm ci`, prints the checker's report verbatim on refusal, and withholds the worktree-finish output. The publish-time closed-phase gate moved into this check, so its refusal wording changed.
- **Renderer-wrapped handoff prose, forward only (operator-authorized expansion).** `.prettierrc.json` moves Markdown from `proseWrap: "always"` to `"preserve"`; `printWidth: 80` remains a code preference. A dependency-free profile in `scripts/github-body.mjs` refuses accidental soft wraps in prose and list-item paragraphs while preserving headings, blank boundaries, distinct bullets, fenced and indented code, tables, block quotes, and explicit hard breaks. Both publishers check the current committed `PR.md` and `RELEASE-NOTES.md` before any remote mutation and transport the bytes unchanged. Every historical review artifact is byte-identical to `origin/main`, and historical-tag re-derivation still accepts the hard-wrapped notes. This package is the first forward example.
- **Ideation breakout, no code effect.** An operator-opened breakout on time fidelity, counterfactual closure, and bounded future reachability is synthesized into `11-proteino.md` as a vision-status candidate, a roadmap catalog pointer, and a ledger entry; it changes no clock, schema, simulator, or roadmap rung.
- **Docs and write-backs:** execution guide, playbook, release records README, final-review README, roadmap release boundary and Post-1.0 horizons, IR compatibility, publication compiler, ADR-0002 amendments, work-order map, ledger, and refreshed publication locks with the staleness recapture. The work order's heading carries `v0.3.3`, an activation-preflight gap the executor forward-corrected and disclosed in place.
