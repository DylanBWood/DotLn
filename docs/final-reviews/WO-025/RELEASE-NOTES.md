## Release overview

The repository's front door now states the release of the source it is in, and that statement is checked against release truth at the two moments that matter: before the reviewed branch is pushed and before the tag is cut. Component versions must move with their source, the skeleton banner reads its own manifest instead of a transcribed literal, and reviewed pull-request and release-note prose is authored for the reader's renderer rather than an 80-column terminal. Audience: readers of the root README and the GitHub Releases page, operators publishing and closing work orders, and reviewers writing the final-review package. This release is the first close-time drive of the surface gate it ships.

## Read before upgrading

- **The README carries one release block.** Between the `DOTLN-RELEASE-BEGIN` and `DOTLN-RELEASE-END` marker comments, `README.md` states exactly one strict `vX.Y.Z`, the release of the source it is in. Updating it is an executor deliverable whenever the planner pins a tagging target above the latest published tag; `worktree publish` and `release close` refuse a block that does not match release truth.
- **Two new preflight rules gate publication and close.** `npm run release -- check-surfaces` previews them on the working tree; `worktree publish` and `release close` run the same rules in committed mode against `HEAD` and refuse before any push, `npm ci`, tag, or GitHub mutation. The publish-time closed-phase gate now folds the committed control log instead of reading the generated projection, so its refusal wording changed from "has not passed final review" to "committed surface check requires closed WO-NNN control state; observed … in phase …".
- **Component versions must move with their source.** For each package directory under `packages/`, if anything under its `src/` differs from the previous release's commit, the `package.json` version must differ from that release's manifest entry. The reverse is not enforced. `@dotln/skeleton` is corrected forward from `0.2.0` to `0.3.0` with a dated note; `@dotln/kernel` remains `0.1.0` with byte-identical source.
- **Final-review bodies are renderer-wrapped from this release forward.** The committed `PR.md` and `RELEASE-NOTES.md` use one physical source line per prose paragraph or list-item paragraph; an accidental soft wrap is refused before publication with the artifact and line numbers. Historical packages, PRs, and tags are not rewritten, and historical-tag re-derivation is unaffected.
- **The shared formatter no longer reflows Markdown prose.** `.prettierrc.json` sets `proseWrap: "preserve"`; `printWidth: 80` remains the code-formatting preference. Existing hard-wrapped Markdown passes unchanged, and new prose may be authored at any width.
- **`check-surfaces` is read-only but not offline.** It consults origin's tag refs to determine the latest published release.

## Substantive changes

- **Front door.** `README.md` §What runs today is rewritten around the release block: no sentence outside the block asserts a current boundary, and historical mentions such as "first shipped in `v0.2.0`" remain time-indexed.
- **Release tooling.** `scripts/release.mjs` gains `check-surfaces` with three rules (release block, component versions, GitHub-body profile) and a committed mode that folds control state from `HEAD:docs/control/resume.jsonl` and reads version-bearing bytes from `HEAD`, so hidden working-tree or index edits and a stale generated projection cannot substitute for what will be pushed or tagged. `worktree publish` runs it after the clean-tree and origin checks and before the `gh` preflight and push; `release close` runs it after synchronization and before `npm ci`, prints the checker's report verbatim on refusal, and withholds the deferred worktree-finish output.
- **GitHub-body profile.** `scripts/github-body.mjs` is a dependency-free checker that refuses accidental soft wraps in prose and list-item paragraphs while preserving headings, blank boundaries, distinct list items, fenced and indented code, tables, block quotes, and explicit hard breaks (two trailing spaces or an odd trailing backslash).
- **Skeleton.** The CLI banner derives its version from `packages/skeleton/package.json` at runtime and fails loudly when the field is missing; a node test binds it. The package version is `0.3.0`, recording the audit projection module that shipped in `v0.3.0`.
- **Process documentation.** The execution guide, playbook, release records README, final-review README, roadmap release boundary, IR compatibility, publication compiler, ADR-0002 amendments, work-order map, and ledger record the two gates, version-axis ownership, and the renderer-wrapped authoring rule; the publication locks were refreshed with their staleness recapture.
- **Ideation, no code effect.** A time-fidelity and bounded-future-reachability candidate is recorded in `11-proteino.md`, the roadmap's Post-1.0 catalog, and the ledger as a future research direction; it changes no clock, schema, simulator, or roadmap rung.

## Progressive polish

- The release and worktree suites gained release-block, component-version, committed-mode, hidden-working-tree, linked-worktree, and wrapped-body fixtures; a unit suite for the body profile runs first in `npm test`.
- `release close` fetches a latest tag that is missing locally before the surface check instead of only before the ancestor check.

## Evidence and compatibility

- Source: the reviewed `wo-025` branch merged into `main` above `v0.3.2`; the exact commit and manifest are in the annotated tag and the machine-derived block that follows these notes.
- Verification: `docs/verifications/WO-025/VER-001.md` (pass; nine criteria confirmed first-hand with the verifier's own surface, committed-mode, publish, close, profile, and banner-mutation probes) and `docs/final-reviews/WO-025/FINAL-001.md` (pass; evidence re-established, a mutation drill of the deliverable's suites, and a dry run of the close command on the reviewed tree against a scratch origin).
- Compatibility: manifest schema version 1, control-log schema 1, kernel schemas, artifact and transformation versions are unchanged; `packages/kernel/src` is byte-identical to `v0.3.2`; no dependency was added; `npm test` remains tag-state-independent.
- Known limitations: the profile covers a supported Markdown subset rather than parsing CommonMark, so a list-item continuation paragraph that follows a blank line and is indented four or more spaces is exempted as indented code and a soft wrap there is accepted; a component README heading that names a version is not checked; the repository cannot control GitHub's own page width; `worktree publish` fails closed rather than fetching when the latest tag is absent locally, while `release close` fetches it.
