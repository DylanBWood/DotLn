# :mute: A stale runtime is reported once per session, and closing a release rebuilds it

A release close regenerates the hooks' runtime pins, but until now nothing rebuilt `packages/*/dist` to match. In the session that prompted this order, three closes fast-forwarded main past a 23:29Z build. Every hook invocation after that, observers included, printed "built adapter unavailable": 344 journal rows, two per Bash call, until someone remembered a 3.9 s `npm run build`. Now `release close` and `worktree finish` compare the regenerated pins with the built bytes after their fast-forward and build only when they differ. If the build does not produce matching bytes, they fail loudly with the checkout or worktree preserved. When a session still meets a stale runtime, it hears one advisory per cause (`pins-differ`, `snapshot-missing` or `runtime-unavailable`) naming the cause and `node scripts/bootstrap.mjs`. `SessionStart` says it before the first tool call, `PostToolUse` observers never speak, and every invocation still writes its journal row. The two refusals, a second writer in the same worktree and a write during the live reviewer gate, are untouched. `resume` and `plan start` print the one line and never build.

Two smaller repairs ride along. Every role's generated procedure now says that, without effective readback, the operator-selected model and effort are recorded with `--source operator-attested`, and `unknown` only when nobody supplied a value. `resume` records supplied values verbatim and maps the legacy `operator-selected-model-effective-effort-unavailable` token to `operator-attested`. Separately, the host and both profiles' skeleton version literal now live in `packages/skeleton/src/version.ts`, which no machinery suite declares, and review selection ignores release-literal-only changes through the existing evidence projection. A skeleton bump alone no longer drags `harness-fixtures` and `process-debt`, about 400 s, into the reviewer's gate, while a behavioural edit to `harness-host.ts` still selects both.

**Read before merging: the per-session marker covers more than the runtime.** Only the three runtime causes have their own marker. Every other advisory maps to one shared `classification` marker per session: authority delegations, shell-classification notices, unreadable state, the attribution pre-check and the `Stop` hook's `pending no-partial-completion, verify-app-before-done`. So after the first of them is shown, the rest are written to the session journal (a `.jsonl` file in `docs/control/local/harness/` named by the SHA-256 of the session id) but not displayed. This is what the order's design specifies, and product 07 lists the four classes, but it goes further than the README's "Runtime advisories appear once per session and cause" suggests. It reproduced in all four Claude sessions that verified and reviewed this order, each of which lost the completion-discipline advisory for its whole dispatch. It is recorded as a planner nomination with a repair shape (key the marker on the advisory itself, or suppress only runtime causes) and a reopening regression, not changed here.

The path here was not clean, and the part that went wrong is itself informative. VER-001 passed. FINAL-001 failed: the new `runtime_refresh` release case was missing from the hard-coded case inventory, and no machinery suite declared `scripts/test-release.sh`, so adding a release case selected nothing that checks release cases. The repair (D005) registered the case and declared the shell under `runner-fixtures`, with a regression proving a shell-only change now selects exactly that suite. VER-002 passed with a negative control. FINAL-002 passed on a fresh `npm test -- --review`: 30 suites, 0 failed, 820.81 s, at the same code identity the repairer and VER-002 measured. `main` did not move during the order, so there was no integration.

Limits. The stale-runtime `SessionStart` message is fixture evidence only; live sessions have shown the host invoking the handler with healthy pins, not rendering a stale message. The first real close after merge, the next skeleton-only reviewer gate and the first post-merge completion on each harness are the reopening observations. Any hook error without a type is also journaled under the `runtime-unavailable` class, including ordinary reads outside the worktree seen by the silent observers, so a post-merge advisory count must separate those rows before comparing with the 344-row baseline.

Patch release v0.22.1 with compiler 0.11.2 and skeleton 0.18.4; no dependency changes. `.claude/settings.json` gains a `SessionStart` entry that reuses the existing `session.mjs` handler, as the operator directed during implementation (D002). The compiler bump meant the WO-050 frozen Decision oracle could no longer run under the current identity, so it now runs in a test-only child that substitutes only its recorded compiler identity, 0.11.1. Production artifact validation is unchanged (D004).
