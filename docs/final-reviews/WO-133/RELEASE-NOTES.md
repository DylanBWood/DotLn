## Release overview

DotLn v0.22.1 stops the local runtime from drifting out from under the hooks after a release, and stops a drifted runtime from repeating itself on every tool call. Until now, a release close regenerated the hooks' runtime pins without rebuilding the compiled packages they point at, so the next session on main met "built adapter unavailable" on every hook invocation, 344 times in the session that prompted this release, until the operator remembered to run a build. Release close and worktree finish now rebuild when, and only when, their fast-forward changed the pinned runtime. A session that still meets a stale runtime is told once per cause, with the cause and the repair command, and is told at session start. Two smaller repairs travel with it: every role now keeps the model and effort the operator selected instead of recording `unknown`, and a release version bump alone no longer adds about 400 seconds of machinery suites to the reviewer's gate. This release is for anyone operating DotLn's lifecycle from Claude Code or Codex.

## Read before upgrading

No migration or operator action is required. No event type, payload, persisted contract, semantic hash or dependency changes, and the two refusals DotLn hooks make, a second writer in one worktree and a write during the live reviewer gate, are unchanged.

Advisory visibility changes, and more broadly than "runtime advisories" suggests. Each session now shows one advisory per cause class. The three runtime causes, `pins-differ`, `snapshot-missing` and `runtime-unavailable`, each have their own class. Every other advisory shares a single `classification` class: authority delegations, shell-classification notices, unreadable control state, the attribution pre-check and the `Stop` hook's `pending no-partial-completion, verify-app-before-done`. After the first of those is shown in a session, the rest are recorded but not displayed. Nothing is lost: every hook invocation still appends its row, including the advisory text, to the session journal in `docs/control/local/harness/`, a `.jsonl` file named by the SHA-256 of the session id. `PostToolUse` observers no longer display advisories at all. A new session shows each class again once. If the marker directory cannot be written, messages stay visible.

Claude Code's generated `.claude/settings.json` gains a `SessionStart` entry that runs the existing `session.mjs` handler. At session start it only compares the pinned runtime with the built and snapshot bytes; it dispatches no work.

The first `release close` or `worktree finish` after this release whose fast-forward changes the pins runs `npm run build` once (about 4 s) before continuing. If the rebuilt bytes still do not match, the command stops with the checkout or merged worktree preserved and names `node scripts/bootstrap.mjs`.

The compiler identity advances to 0.11.2. As with every compiler release, production validation refuses compiled artifacts that carry an older compiler identity; that boundary is unchanged.

## Substantive changes

**The runtime follows main.** `release close` and `worktree finish` compare the regenerated runtime pins with the built and snapshot bytes after their fast-forward and build only on a mismatch, then re-check and refuse to continue if the mismatch remains. `release close` still proves egress and checks release surfaces first, and builds before it composes the release manifest, so the manifest is produced by the rebuilt runtime. `worktree finish` builds before removing the merged worktree. `resume` and `plan start` report drift on standard error and never build. The comparison is source-only, so a missing build can still be diagnosed.

**One advisory per session per cause.** The generated hook prelude's fallback and the runtime's output boundary share one policy and one atomic per-session marker under ignored harness state. The first advisory of a class is shown, naming its cause and, for runtime causes, the bootstrap command; later ones of that class are journaled only. Suppression removes only the advisory message, never a refusal decision. `SessionStart` reports runtime drift before the first tool call.

**Attestation keeps what the operator supplied.** All six generated roles, on both harness profiles, now direct a session without effective readback to record the operator-selected model and effort with source `operator-attested`, reserving `unknown` for a value nobody supplied. `resume` records supplied values verbatim and maps the legacy source token `operator-selected-model-effective-effort-unavailable` to `operator-attested`.

**Version bumps stop selecting machinery suites.** The host version and both profiles' skeleton version come from `packages/skeleton/src/version.ts`, which no machinery suite declares. Review selection compares changed machinery sources through the existing evidence projection, so a change confined to release literals selects nothing, while a behavioural change to the host still selects `harness-fixtures` and `process-debt`. A change to `scripts/test-release.sh` now selects `runner-fixtures`, which holds the release-case inventory guard.

## Progressive polish

Every role's procedure also gains one line: after an authorized product-document edit, run `npm run publication:check`. Product 02 §Harness compiler v1, product 07 §Discipline and §Write once run once, the playbook's release task, both component READMEs and the `.claude/` change log describe the new behaviour. The regenerated harness bundle pins two more runtime files, the compiler's harness module and the skeleton's version module, and every hook's content hash moves with them. The evidence selection moves all four editions to WO-133, and the console's recorded self-host renders follow it. Two stored-stream tests now compile current inputs or follow the current evidence selection instead of fixed historical paths. The publication source locks, decisions index and follow-up projections are refreshed.

## Evidence and compatibility

Source release target v0.22.1, to be tagged from `main` after the reviewed `wo-133` branch merges above v0.22.0. Supported versions: kernel 0.5.0 (unchanged), compiler 0.11.2, skeleton 0.18.4, console 0.1.6 (unchanged). All packages remain private and unpublished, and the lockfile diff is workspace versions only. `main` did not move during review, so nothing was integrated or retimed.

Verification sequence: [VER-001](../../verifications/WO-133/VER-001.md) passed all seven criteria. [FINAL-001](FINAL-001.md) failed because the new release case was missing from the case inventory and no machinery suite declared the release shell script. The repair registered the case and declared the script, with a regression. [VER-002](../../verifications/WO-133/VER-002.md) passed with a negative control. [FINAL-002](FINAL-002.md) passed with the reviewer product gate `npm test -- --review`: 30 suites, 0 failed, 820.81 s, 74 fresh tasks, at the same code identity the repairer's and VER-002's gates measured.

Known limitations, recorded rather than repaired. The shared `classification` class described above is delivered as designed and nominated to planning, with the reopening regression "two distinct non-runtime advisories in one session, two visible messages". A stale-runtime message at `SessionStart` is proven by fixtures; live sessions have shown the host invoking the handler with healthy pins, not rendering a stale message. Any hook error without a type is journaled under `runtime-unavailable`, including silent observer rows for ordinary reads outside the worktree, so an advisory count must separate those rows. The runtime comparison accepts pinned paths only of the current `packages/{compiler,skeleton}/dist/src/[a-z-]+.js|mjs` shape, and a differently named future pin would stop close and finish loudly until widened. `version.ts` is outside machinery selection by construction, and nothing enforces that it stays release metadata. The WO-050 frozen Decision oracle now runs in a test-only child that substitutes only its recorded compiler identity, 0.11.1. The first real close after merge, the next skeleton-only reviewer gate and the first post-merge completion on each harness are the reopening observations.
