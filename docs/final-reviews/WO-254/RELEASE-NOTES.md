## Release overview

DotLn v0.116.0 takes the hooks out of the operator's way. A writer reservation whose holder is a zombie is dead, and the two commands a writer refusal names run from the refused session itself; a Codex release close or turn that stops lets its writer go and reserves it again when it resumes; a `worktree start` the host denies leaves no worktree, branch or carried record behind; an operator message that ends in a question mark is answered, with the evidence, and obeyed only where it asks for an action; a planning pass records a standing rule in one block the operator can read and strike, and `plan check` refuses a rule taken from a question; a Codex session restores every operator message of its dispatch after a compaction; the three shell classifications that fired on nearly every compound command stay in the journal and out of the agent's context; and every role says so once and ends its turn when only the operator can clear a block. The order is [WO-254](../../work-orders/WO-254-the-hooks-get-out-of-the-operators-way.md), filed by the 2026-11-03 planning pass from the operator's recurring failures of that day: a planning pass refused every shell call for four minutes by a reservation whose holder was a defunct process, a release the operator had to type by hand, a `!` command queued behind an agent's turn, a denied activation that left `../DotLn-wo242` behind, a question read as direction and a remark recorded as a rule, and a Codex session that forgot "pause before the final gate" after a compaction. Operators of a DotLn instance, and anyone who runs Codex or Claude sessions under the kit, are the audience.

## Read before upgrading

- **Writer liveness and the admitted recovery commands.** A holder whose process-table state begins with `Z` is dead, as an exited one is: `node scripts/harness.mjs writer --show` reads it `alive: false`, the next guarded call reclaims its reservation with a record, and `node scripts/harness.mjs writer --release` retires it without `--force`. The writer guard admits two commands from a session another reservation refuses, each as that exact command with no pipe, redirect or other command beside it: `writer --show` always, and `writer --release` when the process table proves the holder exited or a zombie. `--release --force` against a live holder stays the operator's, from an operator terminal; a piped spelling is still refused. The runtime's process table now reads `ps -axo pid=,ppid=,stat=,lstart=,comm=`: a fixture that plants a `ps` must print the state column between the parent id and the start time, as the two process-debt fixtures now do ([D005](../../evidence/WO-254/decisions.md#wo-254-d005--a-zombie-is-dead-the-process-tables-state-column-decides), [D006](../../evidence/WO-254/decisions.md#wo-254-d006--the-refusals-own-remedy-runs-where-the-refusal-is-read-by-exact-argv), [D034](../../evidence/WO-254/decisions.md#wo-254-d034--correction-two-process-debt-fixtures-planted-a-process-table-without-the-state-column-d005-added)).
- **A stopped Codex dispatch lets go.** A `release close --publish` attempt that ends before completing releases the Codex session's own reservation and journals `dispatchStopped` with the step and blocker class; the close record carries `writerStop` and its summary says so; a preview leaves the writer alone. The retry reserves the writer again before its prerequisites fetch, fast-forward or rebuild `main`, so a session that took `main` meanwhile refuses it with `main` untouched; with no built runtime that can reserve, the reservation files in `docs/control/local/harness` decide, and a reservation that is not this session's refuses the retry naming `node scripts/bootstrap.mjs` and `writer --show`. A Codex turn that stops without asking for a continuation releases its own reservation once the session's prompt hook has been observed, and the next prompt of a dispatch whose completion event is outstanding reserves it again; a foreign holder at that prompt is named in the prompt's context, not refused. A host that delivers no prompt event keeps today's hold until completion. The release suite's three stopped closes now assert the release where they asserted the retained writer ([D007](../../evidence/WO-254/decisions.md#wo-254-d007--a-stopped-dispatch-lets-go-the-release-closes-command-and-a-stopped-codex-turn), [D027](../../evidence/WO-254/decisions.md#wo-254-d027--a-codex-close-retry-holds-its-writer-before-it-moves-main-round-1-c-f1-d-f1-k-f2), [D039](../../evidence/WO-254/decisions.md#wo-254-d039--a-close-retry-with-no-runtime-that-can-reserve-judges-the-reservation-files-before-main-moves-round-2-c-f1-d-f1-k-f1), [D043](../../evidence/WO-254/decisions.md#wo-254-d043--review-round-3-one-combined-worker-one-finding-fixed-both-runtime-free-writer-checks-read-the-runtimes-own-lane-and-the-ladder-ends)).
- **A denied `worktree start` leaves nothing behind.** Before creating anything, the start makes and removes an exclusive directory where the worktree will stand; a sandbox or permission refusal stops it with nothing created and names the grant to request. A step the host denies after creation (`EPERM`, `EACCES`, "operation not permitted" or "permission denied" in the error, in the activation's spawn error or in the bootstrap's output on either stream) is undone by the same command: the pending sibling receipts and post-close override records it carried out of `main` are put back, the worktree is made writable where a denied step left it read-only, removed and pruned, its branch deleted, and the denial appended to `main`'s ignored `docs/control/local/worktree-start-denials.jsonl` with what was removed, restored and not undone. A registered target's start undoes both worktrees and its registration, and a retry keeps what an earlier attempt made; a worktree whose carried record could not be put back is kept and the message says to move the record first. Any other failure keeps the preserve-and-retry recovery. The bootstrap now runs with its output piped through to the operator and its last 4,000 characters kept ([D008](../../evidence/WO-254/decisions.md#wo-254-d008--a-denied-activation-leaves-nothing-behind), [D031](../../evidence/WO-254/decisions.md#wo-254-d031--a-denied-start-undoes-itself-for-a-registered-target-too-sees-the-bootstraps-denial-and-its-undo-never-hides-the-denial-round-1-c-f2-c-f5-d-f3), [D040](../../evidence/WO-254/decisions.md#wo-254-d040--a-refused-activation-spawn-and-a-bootstraps-standard-output-reach-the-denial-judgment-the-undos-own-log-path-cannot-hide-the-denial-round-2-c-f2-c-f4-d-f2)).
- **A question is a smell with two pathways.** The prompt hook classes an unprefixed operator message whose trimmed text ends in a question mark as `question` on its `OperatorMessageObserved` row, by form and never by meaning; an interrogative opening alone ("Do not run the final gate until I approve.", "How many roots are there") is not a question. Every emitted role root carries the same two pathways and the blocked-turn sentence (below) for hosts whose prompts are unhooked, so each role's cold start grows by 1,206 bytes and the router's by 948; six roots now exceed their cold-start ceilings in `docs/control/budgets.json`, no ceiling is raised, and the optimization is boarded as FUP-f86af3151b401757 ([D009](../../evidence/WO-254/decisions.md#wo-254-d009--a-question-is-a-smell-with-two-pathways-classed-by-form-and-never-by-meaning), [D013](../../evidence/WO-254/decisions.md#wo-254-d013), [D032](../../evidence/WO-254/decisions.md#wo-254-d032--the-role-oracles-startup-pins-include-the-root-instructions-166-bytes-round-1-k-f1)).
