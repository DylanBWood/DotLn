## Release overview

GitHub Copilot CLI is now a third operator-launched harness for DotLn, beside Claude Code and Codex CLI. Type `copilot` at a worktree root with no launch arguments, then `resume: next`, `resume: fix` or `resume: verify`, and you get the same compiled roles, the same skill text and the same plain-command lifecycle. The record names `copilot-cli` as the harness separately from whichever model the CLI routed, and reports the model, reasoning effort and CLI version the CLI itself wrote down. A published table says, for each of fifteen DotLn controls, whether it is enforced, advisory, unsupported or untested under CLI 1.0.86, with the probe row or fixture behind every label and a column for what still holds with approvals turned off. Four live operator episodes carried an order from implementation through a failing independent verification and a repair to a passing one. This release is for anyone who has the CLI installed and wants to run ordinary DotLn work from it without hand-translating six role procedures into a third tool, and without guessing which of DotLn's guarantees survive there.

## Read before upgrading

**Nothing about Claude Code or Codex changes.** `.claude/settings.json` and `.codex/**` are byte-identical to the previous release, no second hook registration is emitted and no handler is copied. The generated `CLAUDE.md` block and `.claude/harness-manifest.json` gain the third profile's rows, the shared five-refusal sentence gains one Copilot clause, and the six role bodies gain the shared boundary and adapter text — identically in both skill roots.

**Accept folder trust yourself, per worktree.** Repository hooks do not load in an untrusted folder, and a probe row is blocked precisely because trust was declined. A main checkout's trust is not evidence for a new worktree.

**Enforced means a bounded pre-effect predicate, not confinement.** Four rows read enforced — writer reservation, live-gate input protection, the planning-branch boundary and the outside-write grant — each backed by both a live denial and a generated-handler fixture. Command sandboxing in this CLI version is experimental and off by default, so shell programs run with your full file, credential and network access whatever the table says, and DotLn's literal-destination checks do not see every indirect file open. DotLn requires neither the sandbox nor a particular approval mode.

**Final review and release close are untested under Copilot.** The same skills load and the helpers are plain `git` and `gh`, but no push, pull request, tag or Release was exercised there. Keep both roles on a qualified harness.

**A fresh session is not mechanical verifier independence.** Cross-session memory defaults to on in interactive sessions and can carry implementer context into a verifier. Verifier independence remains the operator's responsibility, as in both existing harnesses.

**No personal setting is changed for you.** Seven are proposed with file, key, observed value, proposed value, reason and undo. No tracked file and no command in this release writes under `~/.copilot`.

**The verifier cold-start ceiling rises to 25,151 bytes.** The shared role text grows 974 bytes, which put the verifier over its 20,480-byte ceiling; the standing budget route raises it one 4,096-byte step with a dated acceptance rather than trimming a reviewed duty. Every role measures within its ceiling.

## Substantive changes

**A bounded probe, run before anything was profiled.** `node scripts/harness-probe.mjs copilot` refuses without `DOTLN_LIVE_HARNESS=1`, asserts a system-temporary scratch repository and a disposable `COPILOT_HOME`, carries a credit limit on every scripted launch and caps them at twelve across retained records. It registers a fixture hook twice, once in Claude form and once in the CLI's native form, so one record shows which registration fired, how often per event and with which payload keys; the record keeps field-name shapes and enumerated values, never values, paths, prompts or identifiers. Ten scripted launches and two bare interactive sessions answer twelve questions about hook firing, environment, payload fields, tool names, denial, prompt context, Stop messages, sub-agents, session identity, instructions and skills, process ownership and the event log. Existing probe modes and their dated records are unchanged.

**One profile entry, reusing the one hook set.** The Claude-form registration fires, and both its JSON denial and its exit-2 error stop the matching command, including under allow-all, so no native registration was needed. `copilot-cli` is one entry in `contributorProfiles` with the observed version in its `profileId`, every declared availability citing a probe anchor, and the existing `.agents/skills` root. No `.github/` tree, plugin, custom agent or extra `SKILL.md` is created. Shared generated outputs are now emitted once and a byte conflict between profiles refuses generation outright. The two resident-worker profiles are filtered out explicitly and the compiler refuses a Copilot target worker, so resident-launched Copilot stays a non-goal the invariant enforces.

**Input adapters for what Copilot actually sends.** The host maps the native `path` field onto the existing `file_path` classification and refuses a payload whose two spellings disagree, and it bounds the freeform `apply_patch` body carried on the Edit event, extracting every literal destination — including both ends of a move — so the outside-write, planning-branch, live-gate and writer guards see a multi-file patch the way they see a single write.

**Selected-session readback, and counters that never guess.** A reader beside the Codex one reports model, reasoning effort and CLI version from the CLI's own session log as `copilot-session-readback`, which is the CLI's selected value and not an effective-effort claim. A missing, corrupt or unidentified log, `auto` without a resolved model, a null effort, or a log whose cwd or Git root belongs to another worktree each read `unknown` with a named cause; a value the operator supplied stays `operator-attested`. `harness usage` cannot throw for a Copilot session: shutdown totals are labeled session-cumulative, individual recorded model calls are labeled `observed-requests-only` because they can be utility calls, and AI credits from `totalNanoAiu` keep their own scope, source and cutoff even when the token readback is incomplete. Credits never become a token total, and tokens never become dollars.

**Fifteen labeled controls and a seven-item setup record.** The security document publishes the control table with its evidence and allow-all column, and completes the checklist for this CLI: settings locations and precedence, worktree trust, read and write boundaries, approval behavior and its untested exception matrix, network and the built-in GitHub MCP server, what an unavailable sandbox does, enable–verify–undo, and the tested date and version. Compaction continuation is unsupported; the Codex adapter is not reused or relabeled.

**Live qualification, in a scratch repository.** Four bare-entry episodes on CLI 1.0.86 with Claude Sonnet 5 at `xhigh`: an executor to `ready-to-verify`, a fresh verifier that found a planted defect and filed `needs-fix`, a fixer back to `ready-to-verify`, and a fresh verifier to `verified`. Each record carries harness id, CLI version, model, effort and their source, hook invocations by event, denials, approval observations, AI credits and wall clock, and each released its writer after exit. The collector derives each pass from the real control-log phase, the real fixture exit status, the planted-defect sentence in that episode's own report and a released writer; it refuses a reused or pre-reservation session id.

Known limitations, each owned. The qualified workflow is one model on one CLI version; the observed change to a GPT model came from the bare probe, not from a complete workflow. Bare entry, folder trust, permission mode and approval counts are operator attestations, because no helper can observe a launch; one episode's permission mode is recorded as `unknown` because it changed mid-session. Three probe rows report a per-event maximum of 2, which is a timestamp-correlation limit rather than a duplicate-handler count; the single-registration evidence is the trusted Claude-form-only row plus the fixtures plus unique command strings in the shipped settings. Prompt-context delivery and Stop-message visibility were not observed, so the observed-facts block and the operator controls are advisory with explicit commands as the supported route, and once-only loading of the instruction pair remains untested. Sub-agent tool calls arrive without a child identity, so subagent accounting stays advisory and an unobserved agent remains unknown. The usage counters in this order's own receipts were produced by code this release changes, with no independent counter to check them against. The built-in GitHub MCP server, `/delegate`, `--remote`, `--fleet` and autopilot are outside this qualification and DotLn's publication helpers; a persisted off switch for the server is on the proposed-settings list, and no launch argument is imposed. The probe and the qualification spent 196.35 AI credits across the four episodes, against an operator-attested 8,000 of 20,000 monthly with this as the only Copilot workload.
