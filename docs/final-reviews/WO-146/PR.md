# WO-146

An operator can now type `copilot` at a DotLn worktree, with no launch arguments, and run `resume: next`, `resume: fix` or `resume: verify` against the same compiled roles, the same skill text and the same plain-command lifecycle as in Claude Code and Codex. Four live episodes carried a real order from implementation through a failing independent verification and a repair to a passing one. Every DotLn control is now published as enforced, advisory, unsupported or untested against a dated probe of CLI 1.0.86, and a row reads enforced only where a live denial and a deterministic fixture both showed it.

**The unknown this removes.** DotLn's thirteen hook commands all begin `node "$CLAUDE_PROJECT_DIR/.claude/hooks/`, and the Copilot CLI reads `.claude/settings.json` as a repository configuration source and denies a tool call when a pre-tool hook errors. Nobody had observed which of those applied here, so a Copilot session in a DotLn worktree might have been running the hooks, running them twice, or being denied every tool call. The order probes before it profiles: `node scripts/harness-probe.mjs copilot` refuses without `DOTLN_LIVE_HARNESS=1`, runs only in a system-temporary scratch repository with a disposable `COPILOT_HOME`, credit-limits every scripted launch and caps them at twelve, registers a fixture hook in both the Claude and the native form so one record shows which one fired, and keeps field-name shapes rather than values. Ten scripted launches plus two bare interactive sessions answer H1 to H12 in [the retained record](../../discovery/copilot-cli-2026-09-20.md). The existing `claude`, `claude-bare` and `codex` modes and their records are byte-unchanged; `scripts/harness-probe.mjs` gains three lines.

**One profile, one registration.** The Claude-form registration fires and its JSON denial and exit-2 error both stop the matching command, including under allow-all, so no second registration is emitted and no handler is copied. Copilot is one entry in `contributorProfiles`, `profileId: "copilot-cli-1.0.86"`, every declared availability citing a probe anchor, using the existing `.agents/skills` root; `.claude/settings.json` and `.codex/**` do not change by a byte, no `.github/` tree, plugin or custom agent is created, and the six role bodies stay byte-identical across both skill roots. `harnessInstallation` now throws on any byte conflict between profiles for a shared output, which makes single emission structural rather than incidental. `targetWorkerProfiles` filters the new profile out explicitly and the compiler refuses a Copilot target worker, so resident-launched Copilot remains a non-goal that the invariant enforces. The command strings within every hook event group in the shipped settings are unique: five, three, two, one and two.

**What the decoder and the reader learned.** Copilot's native payload carries `path` where Claude carries `file_path`, and its Edit event can carry a freeform `apply_patch` body; the host normalizes both in one place and refuses a patch it cannot bound or one whose two path spellings disagree, so the existing outside-write, planning-branch, live-gate and writer guards see every literal destination in a multi-file patch. A reader beside the Codex one reports model, reasoning effort and CLI version from the CLI's own session log as `copilot-session-readback` — the CLI's selected value, never an effective-effort claim. A missing or corrupt log, an unidentified session, `auto` without a resolved model, a null effort or a log whose cwd or Git root is another worktree each read `unknown` with a cause, and an operator-supplied value stays `operator-attested`. `harness usage` cannot throw for a Copilot session: shutdown counters are session-cumulative, recorded model calls are labeled `observed-requests-only` because they can be utility calls, and AI credits from `totalNanoAiu` are kept with their own scope and cutoff even when the token readback is incomplete — credits never become a token total.

**What is honest about the labels.** Four of the fifteen control rows read enforced: writer reservation, live-gate input protection, the planning-branch boundary and the outside-write grant, each with both a live refusal and a generated-handler fixture. Enforced means a bounded pre-effect predicate at the observed hook boundary; it does not mean arbitrary shell effects, remote tools or hostile same-user processes are confined, and command sandboxing is experimental and off by default in this version. Subagent accounting, read-your-own-output, write authorship, the observed-facts block, usage counters, model and effort readback, completion and handoff, presence, session identity and the operator controls are advisory, because the CLI supplies no child identity, no range-bearing read result and no observed prompt-context or Stop-message delivery. Compaction continuation is unsupported; the Codex adapter is not reused or relabeled. Seven personal settings are proposed with file, key, observed value, proposed value, reason and undo, and none is applied — no tracked file and no command here writes under `~/.copilot`.

**Validation.** `npm test -- --review` passed **34 suites, 0 failures, 491.00 s, 78 fresh tasks, exit 0** at code identity `eb2872b9`, after every reviewed change and every new source file was staged. `npm run test:docs` passes 19 of 19, `publication:check` covers 272 of 272 headings, `harness check` matches 31 generated surfaces, `plan -- check` exits 0 with both operator amendments bound in the planning log, and `git diff --check` is clean in the worktree and the index. All new tests live in the four existing `compiler`, `harness-fixtures`, `harness-probe` and `process-debt` suites; `scripts/test-runner.mjs` gains three source paths and no suite, lane or gate. No gate invokes a live CLI. This is a minor release, `v0.35.0` above `v0.34.0`, with compiler `0.17.0` and skeleton `0.31.0`; the lockfile changes only those internal pins, and no lint or type suppression enters the diff. [VER-001](../../verifications/WO-146/VER-001.md) failed on formatting that made the grouped documentation gate red and hid five checks; the repair is exactly formatter output, which [VER-002](../../verifications/WO-146/VER-002.md) proved by passing the pre-repair bytes through the pinned Prettier and asserting byte equality.

**What a reviewer should know before merging.** Final review and release close are **untested** under Copilot: the same skills load and the helpers are plain `git` and `gh`, but no push, pull request, tag or Release was exercised there, so the playbook keeps both on a qualified harness. The qualified workflow is one model on one CLI version — 1.0.86 with Claude Sonnet 5 at `xhigh`; the observed GPT model change came from the bare probe, not from a complete workflow. Bare entry, folder trust, permission mode and approval counts are operator attestations, because no helper can observe a launch; episode 2's permission mode is recorded as `unknown` because the operator changed it mid-session. The `maxInvocationsPerCorrelatedEvent` of 2 in three probe rows is a timestamp-correlation limit and not a duplicate-handler count, which the record and D005 both state. Cross-session memory is named in four places as the one channel that can carry implementer context into a fresh verifier; a different session identifier is not mechanical independence. The built-in GitHub MCP server, `/delegate`, `--remote`, `--fleet` and autopilot are outside this qualification and DotLn's helpers, with a persisted off switch for the server on the proposed-settings list and no launch argument imposed. The verifier cold-start ceiling rises one 4,096-byte step to 25,151 under the standing budget route for 974 bytes of shared role text, recorded in [D008](../../evidence/WO-146/decisions.md#wo-146-d008---preserve-the-shared-duties-and-make-the-measured-verifier-budget-explicit); the two target-worker profiles change only `runtime.skeletonVersion`, under the operator's bounded criterion-4 authorization in [D009](../../evidence/WO-146/decisions.md#wo-146-d009---allow-only-the-worker-profiles-release-version-metadata-to-follow-the-required-component-bump). Final review changed no source: its one edit is [D015](../../evidence/WO-146/decisions.md#wo-146-d015---correction-d008s-cold-start-figures-and-the-budget-acceptance-quote-a-superseded-measurement), annotating D008's superseded cold-start figures with the delivered 23,154 / 21,061 / 22,279, which leave every role within its ceiling. The probe and the qualification spent the operator's AI credits: 196.35 across the four episodes, against an attested 8,000 of 20,000 monthly with this as the only Copilot workload.
