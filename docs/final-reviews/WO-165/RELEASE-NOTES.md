## Release overview

Entropy Reducer review authority now matches the routes that run it. The Claude print route and the Codex exec route cannot delegate, so reviews work the original lens briefs serially as the reviewer's own checklist, the compiled envelope grants no delegate authority, and new receipts describe that execution shape instead of a fan-out the route forbids.

## Read before upgrading

The current compiled review identity changes; existing immutable reviews and refutations keep their recorded subjects and rendering. A direct compile defaults to `claude-cli-print`; callers may name `codex-cli-exec`, `background` or `fake`, and any other route is refused. The private skeleton exports change shape: `fanOutLens` becomes `lensChecklist` and `deferredProgramKind` becomes `null`. No new transport, tool or delegate permission is introduced, and no live model episode is required.

## Substantive changes

The compiled envelope, role and work order lose `delegate.readonly` and the `delegates` resource; the lens Program becomes a serial sequence of repository reads that keeps every brief's file scope, questions, output shape, word budget and no-fix boundary; the 32-probe ceiling remains. The residue carries the four-item reviewer checklist into the unchanged dispatch protocol, which still rejects a request without lens briefs; multiline custom brief text is escaped onto one line and sparse or non-array brief lists are refused.

Review and refutation dispatches record their route-specific compile inputs. New review receipts state the compiled execution rule (lenses worked serially by the reviewer; no delegate grant or delegate resource limit), show the worker-reported result, and leave per-lens completion explicitly unobserved; they no longer describe a deferred parallel Program. Unknown routes are refused rather than silently compiled.
