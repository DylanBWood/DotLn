# WO-070

An exported launchpad without `packages/skeleton` could not emit its control Beacons. `scripts/resume.mjs` and `scripts/lib/beacons.mjs` loaded the seven build-free Beacon leaves from `packages/skeleton/src`, while `scripts/lib/beacon-observe.mjs` loaded the same library from `dist/`: one library, two module identities, and both inside the package the export leaves behind. WO-033 named the gap on 2026-09-08 and cut this order from it.

This pull request lands WO-070. The seven leaves now live in the private, build-free `@dotln/beacons` workspace. Lifecycle scripts import that source by path before any install, the skeleton imports it by package name, the build stages it for strict type checking without compiling a copy, and a control plane copied to a root with no `packages/skeleton` activates an order and decodes its Beacon.

- **One home, one identity.** `packages/beacons` (`0.1.0`) holds `beacon-codebook`, `beacon-io`, `beacon-provenance`, `beacon-v3-codebook`, `beacon-v3-fs`, `control-beacon-fs` and `control-codebook` with an exports map and a package-owned `types.d.mts` whose codebook-backed unions derive from the codebook constants. Two leaves are byte-identical to their skeleton originals; the other five change only JSDoc type paths. Importing a leaf through its `@dotln/beacons/` name and by its source URL yields the same namespace, the skeleton `dist` holds no copy, and a grep test over `scripts/` rejects any skeleton or compiled-Beacons path to a leaf.
- **Every consumer follows.** The skeleton's TypeScript modules and tests import the workspace by name; the control-plane library (`scripts/lib/beacons.mjs`, `scripts/lib/beacon-observe.mjs`), the benchmark scripts, the script tests and the shared fixture installer import its source by path; the evidence-source inventories name the moved paths and resolve deep `@dotln/` package imports to their source leaves.
- **Activation loads no skeleton source.** Release-tag reading moves to `scripts/lib/release-tags.mjs`, so `dependencies.mjs` no longer pulls `release-records.mjs` and, through it, the skeleton's gate-evidence module at activation; `release-records.mjs` re-exports its twelve former names and keeps its three, so its public surface is unchanged ([D003](docs/evidence/WO-070/decisions.md#wo-070-d003), [D008](docs/evidence/WO-070/decisions.md#wo-070-d008)).
- **Every assembled root carries the workspace.** `runtimeModuleDirectory` in `scripts/lib/harness.mjs` says what a package ships (a built package `dist`, a build-free workspace `src`); the immutable harness snapshot, the authority-probe launchpad and the target-harness fixture use it, and the Copilot qualification root, the live smoke and the test-harness, process-debt and worktree-integration fixtures copy and link `packages/beacons`. A new test imports a copied snapshot from outside every checkout ([D005](docs/evidence/WO-070/decisions.md#wo-070-d005)).
- **`beacons` is a release component.** The evidence editions and the feedback pins record compare its release labels by content, so a later `@dotln/beacons` version bump is a label rather than a judged behavior change that would need a paid live episode ([D007](docs/evidence/WO-070/decisions.md#wo-070-d007)).

**What a reviewer should know.**

- **Compatibility.** No in-tree consumer changes behavior. The seven modules leave `packages/skeleton/src` and `packages/skeleton/dist/src`; a local script that imported them from either path must import the same file name under `packages/beacons/src/` or through `@dotln/beacons/`. No third-party dependency is added: the lockfile gains only the workspace entry, its `node_modules` link, the skeleton's exact pin and the version bumps.
- **Criterion 2 is scoped to the seven leaves.** `gate-evidence.mjs` and `usage-observation.mjs` are still loaded from skeleton source by some scripts and from `dist` by others; neither holds module-level state, and both belong to the plane/kit boundary the operator deferred with WO-069's three carry-ins ([D006](docs/evidence/WO-070/decisions.md#wo-070-d006), [D009](docs/evidence/WO-070/decisions.md#wo-070-d009), `FUP-a058e82c0bbd9b6d`).
- **The snapshot identity hashes only pinned `dist` files,** so a Beacon-leaf-only change reuses an existing harness snapshot, as the unpinned `dist` codebook copies did before this order (D005's recorded limit).
- **One paid live episode ran under operator authorization.** Moving the leaves changes three files the feedback verifier judges (`reactor.ts`, `package-lock.json`, the skeleton manifest), which this pre-2026-09-09 order's Cost line could not have named. The operator authorized one `claude-cli-print` episode with `claude-sonnet-5` at `xhigh` and the deterministic re-mint of the authority edition, once, after the last source edit ([D010](docs/evidence/WO-070/decisions.md#wo-070-d010), bound to receipt 030 by `plan amend-order`). It completed on the first attempt: 697,224 tokens, USD 1.66, 184 s. `docs/evidence/current.json` selects authority `WO-070/001` and feedback `WO-070/001`; artifact identity and verification stay at `WO-161/001`.
- **Boarded, not fixed here.** `scripts/test-evidence-sources.mjs` assumes the selected feedback edition is its own live audit and fails whenever the selection is a carried one; it was failing on `main` and passes again now that the selection is live ([D011](docs/evidence/WO-070/decisions.md#wo-070-d011), `FUP-04bdf07955e1e24f`).
- **Not exercised:** the harness live smoke gained the workspace link but was not run; the builders it shares are covered by the `harness-probe` and `harness-fixtures` suites and the snapshot test. `BeaconActionClass` in `types.d.mts` is a hand-written union mirroring the skeleton's; the build and the encoder's own check catch drift in either direction, and the final review leaves deriving it from the codebook to a later order.

The first full gate failed eight product tests in two suites and thirteen machinery tests in five, all in roots that assembled packages without the new workspace; D005 to D008 repaired them, and the takeover's review workflow found the component-registration and declaration defects that D007 and D008 fixed. [VER-001](docs/verifications/WO-070/VER-001.md) passed all five criteria with its own focused runs of the normative Beacon tests, a namespace-identity check and a type-overlay probe. [FINAL-001](docs/final-reviews/WO-070/FINAL-001.md) reproduced the leaf byte comparison, the module identity, the portability suite and the old-path search, re-ran every check and ran the review gate; it found no defect, and `main` had not moved.
