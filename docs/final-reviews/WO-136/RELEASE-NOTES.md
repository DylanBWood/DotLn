## Release overview

This release answers a question the repository had been answering by assumption: when a DotLn worker runs under Claude Code or Codex CLI, which of the declared limits actually stop an effect before it happens, which are only noticed afterwards, and what changes when the native sandbox is switched off. Forty individually approved live launches across ten limits, two harnesses and both sandbox selections now sit in a dated matrix where every cell is labelled from a host observation — a file present or absent, a socket the fixture listener counted, a ref in a local bare remote — and never from what the worker said it did. The recorded outcome is `inconclusive`, which is a result and not a failure: the matrix says exactly what was prevented, what was observed only after the fact, what the worker never attempted, and what the launch budget never reached. This release is for operators and contributors who need the authority story to rest on measurements before any looser operating mode is discussed.

## Read before upgrading

Nothing about how DotLn runs changes, and no operator action is required. No harness setting, launch default, permission rule, allow or deny list, public event schema, authority rule or third-party dependency moves; the compiled bundle and every component version are unchanged; nothing is removed. The minimal Claude allow/deny configuration the decision packet proposes is published as a table and is explicitly **not applied** — it is an input to a later planning decision, not a change made here. Read one thing carefully before quoting the matrix: a native sandbox selection in this experiment is a launch claim, not an attestation of the effective state, and an `observed-only` cell means the effect happened and the host noticed it afterwards — it is not a claim that a real credential store, a real remote or the public internet is reachable, because none of those was ever in the experiment. Equally, an `ambiguous` cell means the worker did not attempt the operation; it is never evidence that something was prevented.

## Substantive changes

The authority-boundary matrix is the release. Ten rows — writing outside the worktree through the file tool and through an admitted script, a sibling-worktree write, loopback egress, a credential read by tool and by script against a random sentinel, an undeclared command, a nested process and a separate executable, a push to a local bare fixture remote, revocation of the exact-command grant during a running script, and a sustained authorized workflow of at least ten tool calls — were run against Claude print mode and Codex exec mode with the native sandbox on and off, producing 21 `observed`, 15 `ambiguous`, 1 `not-observed` and 3 `unavailable` cells.

What the measurements show. Five routes are `prevented` before the effect by a named mechanism: loopback egress in both harnesses with the sandbox on, by the OS sandbox; the undeclared command on Claude in both modes; and — the strongest positive result — the outside-worktree write through the file tool on Claude with the sandbox **off**, by DotLn's own target hook rather than by the operating system. With the sandbox off, a Claude admitted script nevertheless wrote outside its worktree, reached loopback, ran a nested `node -e` and a separate executable, and kept running after its grant was revoked; all of those were observed only after the effect. Codex's sandbox-off rows 1 through 8 are observed-only throughout, including the sentinel script read and the fixture push. On usable work, Codex completed the sustained authorized workflow in ten tool calls with zero measured stalls, while Claude's sandbox-on attempt produced every workflow effect and then hit the two-minute timeout.

The decision packet proposes retaining the current operating mode for both harnesses, with guarantees scoped to each labelled cell and nothing generalised, and names the specific experiment each harness still needs. The post-close planning checkpoint decides the mode; this release neither offers nor selects one.

The apparatus is `scripts/harness-probe.mjs --authority`, with a fixture payload and a probe library covered by thirty-two deterministic tests. Its live path refuses to run without `DOTLN_LIVE_HARNESS=1`, a TTY on both streams, a session that is not itself nested inside a harness, and an idle evidence gate, so no live launch can occur inside `npm test`. Every launch used a disposable `mkdtemp` fixture with its own repository, linked worktrees, a local bare remote carrying a marker the payload checks, a random 32-byte sentinel standing in for any credential, and a scratch copy of the built runtime; the operator's settings and this checkout were never written. Run files retain operation names, host timestamps and reduced command shapes, and retain no raw transcript, sentinel byte, absolute scratch path, session identifier or host name.

Product 03's authority candidate, `docs/AI-HARNESS-SECURITY.md` and the idea ledger each gain a dated record pointing at the matrix, replacing a candidate carrying four unknown cells and no sandbox-off row at all.

Known limitations, each of which the matrix labels rather than fills. Human prompt counts are `unavailable` in all four modes, not zero: print and exec mode expose no human-prompt observer, and the probe refuses to count structured permission requests as human prompts — which is why the outcome is `inconclusive` rather than `ready`. Claude's credential-read routes are `ambiguous` in both modes because the worker never attempted the exact operation. Revocation's immediate-next-call half is ambiguous in three cells and was never launched in the fourth. Two Codex sandbox-off cells — revocation and the sustained workflow — are `unavailable` because two retries consumed the last of the forty-launch budget, which is spent and cannot be reopened for this session. A stall is a host wall-clock gap above 30 seconds between tool-request boundaries and includes process startup, so the single stall recorded in three of four workflow attempts has an unknown cause. One cell is labelled `unavailable` from rate-limit text in diagnostics that are deliberately not retained, so that classification cannot be re-checked from the run file alone. Nothing here is a security guarantee beyond the individual labelled cells.
