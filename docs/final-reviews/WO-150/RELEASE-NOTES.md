## Release overview

DotLn's executor now carries its economy experiment as standing equipment rather than as something an order has to switch on. Before implementation, every executor dispatch is asked to name at most one economy opportunity for that order — a question, credible alternatives, a deciding observation and a wall-clock budget of at most 900 s — and to record one experiment decision whether it runs the experiment or declines it. Declining with a reason and keeping the current method is a valid outcome, recorded as such. This release is for the operator and for whoever plans the next process-tooling order: it turns a recurring operator reminder plus a manual per-trial equipment step into a standing prompt with an answer on the record, and it says exactly what that costs.

## Read before upgrading

No operator action is required and nothing about authority, gates, hooks, schemas or the kernel changes. What does change is what an ordinary executor dispatch carries: 1,479 bytes, being 1,173 of compiled role text and a 306-byte briefing line that names the equipped support at dispatch. An order that does not want the support writes `{ "tinkerer-economy": false }` in its supports and gets the previous build back byte for byte, including the Origin comment, with every other support unchanged. The support is executor-only; the verifier, reviewer, planner, refuter and release-close roles are untouched on both sides of the switch. One margin deserves attention before the next order that adds executor instruction text: the executor cold start is now 24,327 bytes against its 24,576-byte ceiling, within by 249 bytes, the thinnest margin of any bounded role. The next reviewed executor rule of any size will breach it, and the standing route then raises the ceiling by one 4 KB step with the rule named rather than trimming reviewed instructions. The support adds no gate, agent, schedule, approval step or dependency, and it changes nothing about what an experiment may do.

## Substantive changes

**The default and its opt-out.** `executorSupportDefaults["tinkerer-economy"]` is `true`, so `defaultExecutorSupportIds` carries six ids and the compiled executor role text carries the support's paragraph, byte-identical in both generated skill roots. The paragraph itself is unchanged from WO-145; this release flips one boolean and changes no instruction text. The per-order opt-out removes this support and only this support, which the tests now assert in both directions: the component manifest gains and loses the entry, the executor procedure contains the paragraph exactly once when on and never when off, and every other support's presence is equal on both sides.

**The dispatch briefing names it.** The executor entry briefing already carried a branch for each of the other seven supports and none for this one, so the flip alone would have left a dispatch under the new default silent about the support it was equipped with — the same ambiguity that made the third trial run unequipped. A single branch in `scripts/lib/executor-readiness.mjs` now names the support, the 900 s bound and the two valid outcomes; the bare-dispatch test requires it under the default and forbids it under the opt-out.

**The three trials' history, carried as a starting record.** The order's decisions file carries `lastAdoptedImprovementAt` 2026-09-20 and `experimentsSinceAdoption` 0, with `regression: false` in all three trial records, as the starting values every later experiment record reads. No adaptive pressure modifier, cadence or schedule is implemented; that candidate needs the fixed-cadence baseline this default begins to produce and remains open. The record also states what it does not establish: no trial counted its iterations, so there is no measured per-order saving and none is estimated.

**Role baselines re-based without losing a snapshot.** `packages/skeleton/fixtures/wo150-role-baseline.json` holds the twelve role hashes this release generates and pins its predecessor by SHA-256; that predecessor now serves as the oracle the opt-out must still reproduce byte for byte, and the separate v0.33.2 release snapshot is untouched and still checked against Git history. The historical-baseline case walks the whole fixture chain and asserts every recorded hash rather than one, so a later order cannot quietly drop a link.

## Progressive polish

The regenerated bundle carries a new whole-loadout semantic hash into all twelve role files, the fourteen generated hooks and the harness manifest; in the five non-executor roles that is the only byte that moves, which the tests assert explicitly so that an equipment change failing to move the hash would fail. The skeleton advances to `0.34.0` with the console's exact workspace pin following it; no external dependency changes. The authority and feedback evidence editions were re-minted as WO-150 revision 001 because the changed loadout file is a registered source of both, with a live self-host audit recorded against this base commit; the artifact-identity and verification editions stay where they were and pass unchanged. The work-order index, control projection, decisions index, follow-up register and both publication source locks reflect the completed order. None of this changes observable behavior, saved-data interpretation, compatibility, authority or any operator action.

Known limitations, each on the record. The passing fixtures establish configuration, not behavior: they show the support is equipped by default, removable per order and isolated to the executor, not that any executor will find an economy worth testing. That is why the reopening observation is behavioral — ten equipped executor dispatches after merge, each recording an experiment or an explicit kept-current decline, with fewer than half doing either reconsidering the flip. The pre-registered rule is satisfied by one adopted saving (238.436 s per eligible skeleton test iteration, clearing the 253.276 s whole-trial cost after two iterations in ten orders), but that figure is per eligible development iteration in one sample, not per order. The token side of the reading cannot be compared: only one of three trials recorded a token count, and that count is a broad-scope transcript counter, not a causal allocation. A runtime-derived or unattended executor dispatch inherits the default and its expected outcome there is a kept-current decline naming the absent operator session; no code excludes those classes, because all three such orders are still queued and the per-order opt-out already covers any that wants it.
