## Release overview

This release keeps DotLn's Codex launches out of the operator's Codex settings. Every Codex worker, verifier and probe DotLn launches now runs in its own throwaway home that holds only a link to the operator's authentication, and each launch records before-and-after digests of the operator's user-level `config.toml` and its trust table so a receipt can prove the file did not change. Live on the operator's host, the Codex CLI signed in under such a home, one verifier episode completed through the transport with the configuration byte-identical, and a probe with the writer launch shape watched the CLI write its trust entry into the isolated home instead of the operator's file. The intended audience is anyone running live Codex workers from DotLn, and anyone planning the orders that will run workers against a repository the operator owns, which this containment unblocks.

## Read before upgrading

No operator action is required. Codex episodes launched by DotLn no longer see the operator's `~/.codex` configuration, rules, skills or memories; the launch arguments already ignored or disabled those, so behaviour is unchanged, but the CLI's own session state, logs and caches now land in the per-episode home and are discarded with it. A token refresh during an episode still reaches the operator's `auth.json`, because the home links to it and the CLI writes that file in place; a Codex release that writes it by rename would strand the refresh, and that is the recorded reopening condition. A launch that cannot build its home refuses rather than falling back to the operator's home. A home left behind by an abnormal end holds one link and no secret; the next launch removes it once its launcher has exited and it is older than twice the longest episode deadline, and `harness prune` lists such homes without removing them. Trust entries that earlier launches already wrote into the operator's configuration are not removed by this release. Claude Code and Copilot launches are not isolated and were not measured. Terminal worker events gain an optional `codexIsolation` field and a resident CLI observation an optional `isolation` field; readers that enforce closed shapes must admit them, as the actor contract now does. `@dotln/skeleton` moves to `0.41.0`; `npm run probe:workers` now builds first because the probe imports the built launcher.

## Substantive changes

**One Codex launcher.** `packages/skeleton/src/worker-transport.ts` exports `codexExecArgv`, the only builder of a Codex `exec` argv and the sole owner of the shared `--ephemeral --ignore-user-config` flags, and `startCodexEpisode`, which creates a `0o700` home under system temp, links the operator's `auth.json` into it, hands back an environment with that `CODEX_HOME`, and on `finish()` digests the user-level `config.toml` and its `[projects]` trust-table projection again, counts trusted entries the CLI wrote into the isolated home, removes the home and returns a digest-only record. The transport isolates every `codex-cli-exec` dispatch and exposes the record when the process has ended, however it ended; the worker, verification and source-change hosts write it on their terminal events; the runtime's `assertCodexIsolationUnchanged` refuses an unequal pair, an unknown digest or an unremoved home.

**Every launch site adopts it.** The authority probe, the writing-worker probe, the harness probe, the worker-host probe, the target-worker smoke, the local-model role qualification and the Codex effort probe build their argv through the launcher and run each Codex invocation in its own home, recording the digests beside their rows; the writing-worker probe records one labelled record per invocation, including each concurrent session and a fresh recovery. A search over package sources and scripts for the shared flag returns only the launcher's file, and the probe fixture's Codex stub refuses any home that is not an isolated one.

**The live receipt and its check.** `docs/evidence/WO-159/live-codex.json` records the isolated `codex login status`, the live verifier episode and both launches' digest pairs among its protected surfaces. `receipt.mjs --check` validates the closed, private shape and re-derives the whole receipt from the feedback edition's retained verifier stream, so a false digest, row count, launch selection or episode fact is refused. Fixture receipts built from real worker and verification stores through a fake Codex that writes trust into its home pass the check, and twenty-six forgeries plus eight stream forgeries fail it.

**The WO-054 correction.** The Codex continuation evidence file gains a dated note below its unchanged bytes: its claims that no persistent account setting or user trust setting changed held for the continuation bundle's own emission, not for DotLn's Codex launches, including that order's own probes. The capability table adds a dated Codex launch containment row at level 1 (demonstrable) with dependable as the target, reassesses the continuation row, and product 03's progressive absence candidate records that the containment precondition for operator-owned repositories is met.

## Progressive polish

The harness probe now refuses a retained observation before launching a model episode instead of after. The test runner registers the launcher as a source of the harness-probe and harness-fixtures suites, so the reviewer gate ran 81 tasks against the usual 71. `harness prune` reports stale Codex episode homes by name. The harness bundle was re-emitted for the changed actor contract, differing from the previous snapshot only in its id and one runtime hash. The authority, verification and feedback editions were re-minted as `WO-159/001`, the last from the same live Codex episode as the live row; artifact identity stays at `WO-154/001`. Product 06 records the `v0.48.0` activation.
