# WO-159

Until now every Codex worker, verifier and probe DotLn launched inherited the operator's Codex home, and the CLI wrote a `trust_level = "trusted"` entry for each scratch target into the operator's user-level `config.toml`: WO-111's live proof left two such entries and closed only on an operator-accepted deviation, and a 2026-09-24 census found 36 of 43 trusted entries belonging to DotLn scratch and probe families. This pull request lands WO-159: one launcher in `packages/skeleton/src/worker-transport.ts` builds every Codex `exec` argv and runs every episode in its own `0o700` home under system temp that holds one symlink to the operator's `auth.json` and nothing else, then digests the user-level `config.toml` and its `[projects]` trust table before and after, counts the trust entries the CLI wrote into the isolated home, removes it and records digests only. The transport, the resident CLI actors and seven probe and smoke scripts use it; the worker, verification and source-change hosts carry the record on their terminal events, and the live receipt lists both digest pairs among its protected surfaces, where an unequal pair or an unremoved home fails the check. Live on the operator's host with Codex CLI 0.156.1, `codex login status` succeeded under an isolated home, a `gpt-6-sol` feedback verifier episode completed through the transport with the operator's configuration byte-identical ([live row](docs/evidence/WO-159/live-codex.json)), and a probe with WO-111's source-change prefix watched the CLI write its scratch trust entry into the isolated home while the user file stayed unchanged ([trust probe](docs/evidence/WO-159/trust-probe.json)). The WO-054 evidence file's claim that continuation changes no user configuration is corrected in a dated note below its unchanged bytes.
