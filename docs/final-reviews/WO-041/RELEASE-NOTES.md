## Release overview

DotLn `v0.13.3` is the control-plane patch above the published `v0.13.2`. It gives planning the blinded verifier that code already had. `npm run plan -- refute` compiles a subject from committed files only (the vision's thesis sections and exclusions, the five roles, the capability rows, and each marked order's title, objective, acceptance criteria, and non-goals), dispatches one read-only Entropy Reducer episode wearing the Contra-Auguste mask through an existing transport with no model tools, validates a closed result that names for every order whether it advances a named thesis and capability row, is machinery, or drifts, and writes an immutable receipt pair. A forward-only gate in `npm test` refuses a later planning pass without a matching receipt or with an unanswered hold; a hold is answered only by a changed named criterion with a fresh receipt or by an attributed operator override event in a separate control log. The same release records the operator's 2026-09-07 workflow correction: work orders implement and verify independently of every sibling's phase, routine integration happens inside the final-review window, and only affected claims need new evidence. Two helpers make that mechanical: `npm run release -- prepare` retimes a colliding unpublished target with a dated roadmap note, and `check-surfaces --local` runs first in `npm test` against release tags in the subject's own ancestry. The feedback audit now judges a labeled dependency projection of the skeleton manifest and lockfile instead of their raw bytes, so a release-only version or license change no longer forces a live re-audit. Audience: the operator and any planning session, the sessions that verify and review work orders, and readers of the planning receipts. Skeleton component `0.12.1` carries the transport and audit changes; compiler `0.6.0` and kernel `0.2.1` are unchanged; no dependency, lifecycle phase, legal action, or control-event schema changes.

## Read before upgrading

- **`npm test` has three new steps and one changed step.** It now opens with `node scripts/release.mjs check-surfaces --local`, then runs `scripts/test-release-preparation.mjs`, later `scripts/test-plan-refutation.mjs`, and its feedback check reads the WO-041 edition (`--edition WO-041`). The local surface check selects the branch's order in a `wo-NNN` worktree and the latest closed order on `main`, reads only annotated release tags reachable from `HEAD`, and prints `Tag observation: local ancestors of HEAD only; publication checks origin.`; publication and release close keep the origin observation.
- **The planning gate is forward-only from this merge.** Enforcement dates from the first-parent introduction of `scripts/refute-plan.mjs` on `main`; every ledger heading that names a planning pass dated on or after that date needs a receipt whose subject hash matches the current committed sequence block, order files, vision thesis sections, roles table, and capability rows. Editing any of those after the introduction turns `npm test` red until `npm run plan -- refute` runs again. The six manual redirect receipts and headings already present at the boundary are exempt and are never re-run. Until the introduction commit exists on the first-parent line, the gate reports `enforcement: pending introduction commit`.
- **A hold blocks the planning pull request.** Only two answers discharge one: a changed named criterion with a fresh receipt carrying the dated accepted disposition, or `npm run plan -- override` naming the receipt, the hold, and a reason, with actor flags, an ignored intake capture, and its SHA-256, which appends an attributed event to the new `docs/control/plan-refutations.jsonl`. Override text inside a receipt grants nothing. The third consecutive hold over one sequence stops that pass.
- **The refuter writes model output into committed files.** The receipt writer runs the local-terms screen over the validated result and refuses to write when the ignored operator terms list matches; in a checkout without that list it reports `localTerms: unavailable` and proceeds. The screen reports only a surface, a line, and a count; it never publishes a term.
- **Integration no longer restarts verification by itself.** A new base, a text conflict, a changed tree hash, or a version collision alone is not a failed final review. The integrating final reviewer merges, regenerates projections, retimes with `release prepare`, reruns the affected checks, and records which acceptance claims kept their original evidence. A behavior-changing resolution or an actual acceptance defect still returns through repair and a fresh numbered verification for the affected claims. No sibling phase gates any transition; the operator's one-final-review-at-a-time discipline is voluntary.
- **`release prepare` edits three files and nothing else.** It rewrites the work order's heading version and the README release block's single strict version, and it inserts a dated retiming note under the order's roadmap activation completion, all under the order's declared classification, from origin's tag observation (`--local` uses the fetched local snapshot). It refuses outside the order's `wo-NNN` worktree, on a closed order, on an ambiguous heading or block, and it restores prior bytes if any write fails. It never publishes, bumps a component, or appends a control event.
- **Feedback evidence has a new source contract for new editions only.** `package-lock.json` and `packages/skeleton/package.json` enter the feedback subject as `feedback-package-projection-v1` capsules at logical `.feedback-source/` paths, with `version` and `license` removed at the root and the four known workspace entries and everything else retained. Existing editions keep their raw-byte hashes. `scripts/feedback-evidence.mjs --edition WO-NNN` selects an edition directory and refuses to overwrite one with different bytes; the root `evidence:feedback` command now selects WO-041.
- **The skeleton component is `0.12.1`.** Its transport unions accept the plan-refutation request and result, the worker store refuses to persist plan requests, and the CLI transports select the plan budget and twenty-minute deadline for them. No exported runtime capability changes.

## Substantive changes

- **Planning (`scripts/refute-plan.mjs`, `scripts/lib/plan-subject.mjs`, `scripts/lib/plan-receipts.mjs`, `scripts/lib/terms.mjs`; `plan subject | check | refute | override`).** The committed-only subject builder hashes the map's sequence block, every listed order's bytes, and the judged standard (thesis sections and exclusions, the roles table, and the capability identifier and level cells), so a receipt goes stale when either the plan or the standard moves; planner narrative, the ledger, and earlier verdicts are excluded from what the refuter sees. Receipts form an immutable, addressed chain: a fresh receipt after a hold must carry each prior hold's accepted disposition or repeat it, must differ inside a held order's named criterion, and whitespace or unrelated edits cannot re-roll a verdict. Overrides are control events attributed to the acting session with the capture's SHA-256, and the gate reads them only from the control log.
- **Skeleton (`loadouts/plan-refuter.ts`, `plan-refutation-protocol.ts`, `plan-refutation-host.ts`, `plan-refutation-fake.ts`; edits to `reactor.ts`, `verification-protocol.ts`, `worker-store.ts`, `worker-transport.ts`).** The `plan-refuter.v1` loadout compiles the Entropy Reducer identity, the Contra-Auguste mask, and the architecture-and-semantics lens into a read-only envelope (`repo.read*` and `report.emit` allowed; write, git, remote, settings, and decision effects denied), a one-shot cadence, and six pinned questions. The host authorizes the read and the report through the skeleton's single decider, dispatches from an empty scratch directory with no model tools, and validates the closed `plan-refutation-v1` result positively: extra fields and unknown order ids are rejected, `thesis-advancing` must name a thesis and a capability row, `drift` must name a vision passage, and the horizon holds by construction when any order drifts, when no order advances a thesis, or when the largest gap names an untouched thesis that no later order defers.
- **Release tooling (`scripts/lib/release-preparation.mjs`, `scripts/release.mjs`).** `release prepare [--local]` and `check-surfaces --local`, with the ancestral tag filter so that a sibling worktree's newer tag cannot become this subject's verification baseline while publication still checks origin.
- **Feedback evidence (`packages/skeleton/src/feedback-audit.ts`, `scripts/feedback-evidence.mjs`).** The labeled package projection and per-order edition selection with immutable writes; the WO-041 edition was recorded live on the integrated base through a Codex worker, with both acceptance criteria verified by the independent verifier host.
- **Lifecycle and planning documentation.** Execution guide 07 gains §Independent workflows and integration and the mandatory refutation step in §Operator-opened planning pass; the ideation-verification paragraph, the playbook, the concurrent plan's lane rules, the phase-two plan's procedure and first-pair receipt, the work-order map, WO-033's sync-helper scope, domain model 02's feedback projection note, roadmap 06's retiming rule and the WO-041 activation and retiming notes, the 13 tester surface and roles table, the receipt convention, the docs map, the README release block, the dated `control.plan-refutation` capability row, the publication index rows and both edition locks, and the ledger's two dated sections all agree with the mechanisms.
- **Tests.** `scripts/test-plan-refutation.mjs` (eleven fixture groups over synthetic Git histories and injected transports: the deterministic committed subject and all five stale-source families, narrative blinding, authority refusals and pinned questions, the closed schema and structural holds, the local-terms screen with a synthetic term, override and disposition-chain rules, re-roll refusals, the three-hold stop, transport adapter shape, the forward-only gate, and symlink refusal); `scripts/test-release-preparation.mjs` (seven tests: retiming exactly three surfaces, idempotence, classification following, malformed and ambiguous refusals without partial edits, prerelease preservation, wrong-worktree and stale-plan refusals, and byte recovery after a write failure); two real-Git fixtures in `scripts/test-release.sh` (a sibling's non-ancestor tag is ignored locally while origin is still required, and `prepare` preserves three independent control segments and every ref); and `packages/skeleton/test/feedback-audit-source.test.ts` (metadata stability across all four workspace entries, invalidation by every declared source and by execution, dependency, publication, and unknown fields, and malformed-input refusal).
