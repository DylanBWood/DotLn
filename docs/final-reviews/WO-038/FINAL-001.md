## Adjudications

### 1. `private: true` as a real-publish barrier (VER-001 O1)

The verifier could not execute `docs/LEGAL.md`'s sentence that `private: true` "remains npm's ordinary publication barrier, including when lifecycle scripts are explicitly suppressed", because an unauthenticated real publish stops at `ENEEDAUTH` first. Reading npm 10.8.0's shipped source settles it without credentials: `lib/commands/publish.js` reaches `libnpmpublish` only when `--dry-run` is off, and `libnpmpublish` 9.0.8 throws `EPRIVATE` for a private manifest at the top of `publish()`, before any registry resolution or request and independent of `--ignore-scripts`. A real, authenticated `npm publish --ignore-scripts` of any of these manifests therefore stops at `EPRIVATE`; the dry run never reaches that check, which is exactly why the executor observed exit 0 and why the lifecycle guard exists. The sentence is accurate. Its evidence is npm's source, not an executed publish, and the release notes say so. No change.

### 2. The exemption covers one of the operator's two public author identities (VER-001 O2)

Confirmed on `main`: 63 commits carry the pinned identity and 42 carry the GitHub web identity that authors merge commits created in the GitHub UI. Consequence: merging a work-order PR into `main` is unaffected, because the merge commit lands on the base and is never in `origin/main..HEAD`; but GitHub's "Update branch" on an open work-order PR would place such a commit on the branch, and the next `worktree publish` would refuse it until it is rebased away or carries a matching trailer. The behavior fails closed, cannot admit an unsigned outside commit, and is disclosed in `CONTRIBUTING.md` ("a different author identity requires its own matching sign-off"). It is not a defect against criterion 3, whose fixture terms are met, and the design section asked for an exact identity. Operator-review assumption 1 reads broader than the implementation, so the operator should know which identity is exempt before first meeting the refusal; the PR body and release notes say it plainly. Extending the exemption to a second exact identity would be a code change and belongs to a follow-on if the operator wants it. The check's base is the local `origin/main` remote-tracking ref, which the ordinary fetch keeps current, and the check makes no network call.

### 3. Case-sensitive email comparison (VER-001 O3)

A hand-typed trailer whose email differs from the author's only in letter case is refused, and the refusal line names no identity by design, so the contributor gets no hint. `git commit -s` always emits the exact author identity.
