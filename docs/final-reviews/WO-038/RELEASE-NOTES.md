## Release overview

DotLn `v0.13.2` is the patch release above the published `v0.13.1`. It makes the 2026-09-06 license decision true in every place a tool or a person reads it. The root and every workspace manifest declare `license: Apache-2.0` and stay `private: true`; every workspace refuses `npm publish` through an explicit, tested lifecycle guard; a `license-surfaces` preflight pins the three license files and the legal record's hashes and runs in `npm test`, `check-surfaces`, `worktree publish`, and `release close`; `CONTRIBUTING.md` states the inbound rule, a Developer Certificate of Origin 1.1 sign-off on each outside commit, and `worktree publish` enforces that rule before any branch push. The tag also carries the 2026-09-06 planning pass that decided the posture, including `LICENSE`, `LICENSE-docs`, `NOTICE`, and the legal record's decision section. Audience: anyone reading, forking, or contributing to the repository, and the operator's own publication tooling. No runtime capability, component version, dependency, or schema changes; kernel, compiler, and skeleton sources are byte-identical to `v0.13.1`.

## Read before upgrading

- **Every manifest now declares `license: Apache-2.0` and `private: true`.** `@dotln/kernel` gains the `private` flag that the 2026-09-03 legal record named as the open gap. No package is published; the license is the grant on the source, not a distribution channel, and publishing remains a separate decision.
- **`npm publish` refuses in every workspace.** Each manifest carries a `prepublishOnly` command that prints `DOTLN_PACKAGE_PUBLISH_REFUSED` and exits 1, because npm 10.8.0's `publish --dry-run` returns success for a private package. A real publish is additionally stopped by npm's own private-package check inside `libnpmpublish`, which runs regardless of `--ignore-scripts`. No `publishConfig` may appear until the publication decision, because npm would merge it into the publish options.
- **The release preflight has new rules.** `license-surfaces` requires the license and private fields, the exact guard command, an absent `publishConfig`, the exact `["packages/*"]` workspace layout, the three license-file SHA-256 values, and matching pins in `docs/LEGAL.md`, then runs offline npm dry runs against isolated copies of the manifests with empty npm configuration and no credentials. It fails closed on a new workspace or a new layout until the check is extended. `npm run license-surfaces` runs it alone, `npm test` includes it, and `--committed` reads Git blobs.
- **`worktree publish` now checks contribution sign-offs.** Every commit in the local `origin/main..HEAD` range, including commits reached through merges, must either be authored by the operator's exact pinned public identity or carry a `Signed-off-by` trailer whose value matches the commit's raw author name and email. The refusal happens before the GitHub CLI preflight, the branch push, and the PR. The check's base is the local `origin/main` remote-tracking ref, which the ordinary fetch keeps current; the check itself makes no network call.
- **Only one of the operator's two public author identities is exempt.** The exemption is pinned to the author identity on the license-decision commit. Commits authored under the operator's GitHub web identity, which authors merge commits created in the GitHub UI, count as outside commits. Merging a PR into `main` is unaffected because that merge commit lands on the base, but GitHub's "Update branch" button on an open work-order PR would put such a commit on the branch, and `worktree publish` would refuse it until it is rebased away or carries a matching trailer.
- **`CONTRIBUTING.md` is the inbound rule.** Outside contributions are accepted under Apache-2.0 for code and CC BY 4.0 for documentation with a DCO 1.1 sign-off on each commit; there is no contributor license agreement. `git commit -s` adds the trailer. No Git hook is installed and no harness or Git setting changes.
- **The WO-011 feedback evidence edition was refreshed.** The feedback audit's declared source set includes `package-lock.json` and the skeleton manifest, so the license metadata moved its source pin and the existing runbook required a fresh bounded live verifier. Only the report's source hash changed; the accepted evaluations are the same two passing criteria, reached on the fourth attempt after three format refusals that the receipt records. The historical edition remains readable at `v0.13.1`.
- **WO-033's export default is retargeted.** When the compiled starter export lands, it copies `LICENSE`, `LICENSE-docs`, and `NOTICE` as manifest-listed kit files by default; `--license none` remains an explicit opt-out that writes the no-rights notice. No export command exists yet.

## Substantive changes

- **Package metadata (root, `@dotln/kernel`, `@dotln/compiler`, `@dotln/skeleton`).** `license: Apache-2.0` on all four manifests, `private: true` added to the kernel, the exact `prepublishOnly` refusal on all four, and the lockfile's matching `license` entries. No dependency is added, removed, or changed.
- **License-surface preflight (`scripts/license-surfaces.mjs`, new; wired into `check-surfaces` in `scripts/release.mjs`).** 28 rules on this repository: the workspace layout, the workspace count, license, private, `prepublishOnly`, and `publishConfig` for each manifest, the three file hashes, the three legal-record pins, and four npm dry-run refusals. Every line prints an observed and an expected value. When any manifest rule fails, the dry run is replaced by a failing rule so no lifecycle script runs from an unvalidated manifest. A missing npm, an unrelated failure, or the marker with exit 0 does not count as a refusal.
- **Contribution sign-off check (`scripts/lib/contributions.mjs`, new; wired into `publish` in `scripts/worktree.mjs`).** Raw author name and email, trailers parsed by `git interpret-trailers --parse`, a case-insensitive trailer key and an exact value match, one PASS or FAIL line per commit that names the commit ID rather than the contributor, and a thrown error when the base ref is missing.
- **`CONTRIBUTING.md` (new).** The outbound licenses, the DCO 1.1 rule with an example trailer, the operator exemption and what does not confer it, what `worktree publish` checks and when, the clean-room boundary, the work and review route, and the local gate commands.
- **Tests.** `scripts/test-license-surfaces.mjs` (nine tests: real npm refusals under ambient script suppression, metadata mutations, byte pins with missing files, symlinks, and legal-record drift, new workspaces and layouts, symlinked workspaces in working and committed snapshots, masquerading npm results, committed Git-blob reads, DCO authors and trailers, and an unsigned side branch behind an operator merge); `scripts/test-license-fixture.mjs`, which installs the license fixture into the shell suites; `scripts/test-release.sh`, whose fake npm now executes real offline dry runs and which drives the three named defects through `check-surfaces`; and `scripts/test-worktree.sh`, which refuses an unsigned outside commit before `gh`, the push, or the PR and accepts an operator commit without a sign-off.
- **Documentation.** The README release block at `v0.13.2` and its legal-posture section; `docs/LEGAL.md` §Current state rewritten to the landed metadata, with the decision gates marked; the `docs/README.md` map entry; the execution guide's two preflight paragraphs; the roadmap's activation completion; the planning map's source note and the feedback-refresh candidate; the ledger's dated section; WO-033's retarget note; WO-038's heading and activation completion; both publication edition locks; and the regenerated work-order index.
- **WO-011 evidence edition.** The regenerated `feedback.json`, the audit and verification streams, and the receipt, with the disclosed recovery wrapper and the refresh observation under `docs/evidence/WO-038/`.
