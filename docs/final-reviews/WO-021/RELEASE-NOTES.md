## Release overview

DotLn `v0.8.0` is the minor release above the published `v0.7.0`. The control plane now drives its own car: every appended lifecycle transition projects the selected work order's phase, latest verdict, and latest attested effort into a rebuildable beacon whose exact byte size decodes under an additive codebook and whose mtime is the transition's own time. `npm run worktree -- constellation` reads every worktree by metadata alone and prints one lifecycle-ordered row per order plus a bounded group count, without appending anything. An agent can only sweep those beacons through the existing authority guard: a refusal is recorded before any beacon is read, an allowed sweep records exactly one observation event, and replaying that event reproduces the same fresh, stale, absent, and clock-skew labels and text glyphs from the recorded sweep time. Verifier projections carry host records only, and an optional session capability reveals a separate restricted directory only in that order's authorized briefing. A separate phase-group codebook counts members per phase for up to twelve orders in a sparse file that allocates no data block on the observed host. Audience: the operator and lifecycle peers watching several work orders progress in parallel worktrees, and the later real-worker and senses orders that consume this staleness contract and these bounded codebooks. The kernel and compiler are byte-identical to `v0.7.0`; the walking skeleton advances to component `0.7.0`.

## Read before upgrading

- **Each checkout gains a gitignored `.control-beacons/` root on its first transition.** It holds `public/`, `verifier/`, and `groups/` directories at mode 0700 with mode-0600 files, an optional host-managed `sessions/` directory, and possibly `restricted/` directories with random names. It is a rebuildable cache: the canonical control segments rebuild it, `worktree finish` treats it as disposable at that anchored root only, and the `docs/intake/**` protection still takes precedence over every build-shaped name.
- **A projection warning never means retry.** If a transition prints `host beacon projection unavailable; transition recorded, do not retry the transition`, the append and its checkpoint already happened; inspect `resume status`, fix the projection problem (permissions, a symlinked directory, an unsupported size, or a stray file in `sessions/`), and continue. Repeating the transition would be an illegal second append.
- **`status`, `status --json`, `times`, and `next` emit nothing** and leave every beacon's inode, size, mtime, and ctime untouched; only a state-changing append emits.
- **Agent sweeps write deliberate evidence, not cache.** `npm run worktree -- constellation --agent` names a host request file and `--log` names a `.jsonl` path under `docs/observations/`; the command needs a current `npm run build` and an explicit host envelope granting `observe.beacons.public` or `observe.beacons.verifier` plus one `beaconSweeps` resource unit, and any other log path refuses before a file exists. The append-only log is created mode 0600 and is not gitignored. The request file is host input: a worker cannot grant itself authority by writing JSON.
- **The default staleness threshold is 20 minutes,** declared per request as `staleAfterMs`; a beacon whose mtime is later than the sweep time decodes `clock-skew`, a missing beacon `absent`. None of these labels, and no beacon at all, ever enters an authority decision or changes lifecycle legality, and a fresh beacon says nothing about whether any worker is alive.
- **`resume next --beacon-session` is accepted only for an active order** and only with a capability the trusted host issued for that order through `issueBeaconSession`; every other combination exits 1 without echoing the capability or the restricted name. Keep capabilities out of shared logs and public status. Same-user filesystem access is not isolated by this mechanism.
- **Codebook compatibility.** The v1 episode codebook keeps its meaning; a v1 reader labels a v2 file `unknown-codebook`; the group family uses framing tag 3, is selected only by its own directory and decoder, and is labelled unknown by the individual reader. Individual v3 therefore needs a wider framing radix or a directory-scoped tag.
- **Bounds are host observations, not portable guarantees.** Individual v2 files are densely padded to at most 81,833 bytes; the group file's logical size can reach 192,763,452,654 bytes, allocated sparse on this APFS host at zero data blocks. A host without observed sparse support only permits sizes through the reproduced dense ceiling: small groups are padded, larger groups refuse before allocation. Never copy or open a large sparse group file as content.
- **The skeleton's `tsconfig.json` now enables `allowJs` and `checkJs`** so four JSDoc-typed `.mjs` source leaves (the two codebooks, the filesystem writer, and the control-beacon edge) are strictly checked by the same build and can be imported by the resume and worktree helpers before `npm ci`.
- **The WO-016 reactor-purity test is now an explicit import allowlist** admitting the pure codebook and glyph modules beside the kernel and compiler.

## Substantive changes

- **Codebooks (`packages/skeleton/src/beacon-codebook.mjs`, `control-codebook.mjs`).** The v1 codebook and its encoder/decoder move unchanged into a dependency-free leaf. Codebook v2 encodes phase (8), latest verdict (3), latest attested effort (6), and provenance (2) with `bigint` arithmetic: 288 states, `MAX_V2_CODE = 1150`, `MAX_V2_LOGICAL_BYTES = 81833`. The phase-group codebook v1 encodes eight per-phase counts in radix 13 for at most twelve members: 125,970 vectors, `MAX_GROUP_CODE = 3011928819`, `MAX_GROUP_LOGICAL_BYTES = 192763452654`. `decodeSignalSize` reads v1 and v2; `decodeGroupBeaconSize` reads only the group family; `beaconAge` compares in nanoseconds against the declared threshold. Both normative tables in 02 are equality-tested against the code.
- **Filesystem writer (`beacon-io.mjs`).** One validated temporary-file-and-rename boundary serves v1, v2, and group files; a size that is not a safe host integer or that exceeds the freshly probed ceiling refuses before any file is created; every written file is checked for the exact requested size and mtime and against its declared allocated-block bound. `probeBeaconStorage` re-observes sparse support with a 64 KiB hole before permitting the group maximum.
- **Control-beacon edge (`control-beacon-fs.mjs`).** `emitControlBeacon` writes the eight-field host record into the public, verifier, and any matching restricted directory, refusing self-reported provenance, undeclared fields, or a non-canonical `recordedAt`; `sweepControlBeacons` reads directory listings and `lstat` only, adds the branch-derived expected address so a missing beacon decodes `absent`, and sorts by phase then address; `emitGroupBeacon` and `readGroupBeacon` keep one cache per emitting checkout keyed by the whole swept set and accept only a cache whose decoded counts match the current sweep; `issueBeaconSession` and `restrictedBeaconBriefing` implement the capability and its disclosure rule with generic errors.
- **Reactor and observation (`reactor.ts`, `beacon-observe.ts`, `control-beacon.ts`, `scenario.ts`).** `BeaconSweepRequested` lowers the Observe intent to an `Act` effect `observe.beacons.public` or `observe.beacons.verifier` with resource `beaconSweeps` and authorizes it with no observation in the context; `BeaconObserved` requires its authorized command and the event's own time, binds each persisted decode to the persisted size, and judges age through `Cadence.After` from the recorded origin; `observeBeaconSweep` persists the request, then the refusal or the command, one observation, and the result, calling `persist` before each dependent edge action; the glyph scene renders `✦ fresh`, `◌ blurred/stale`, `○ absent`, and `⚑ flagged/…`.
- **Lifecycle helper (`scripts/resume.mjs`, `scripts/lib/beacons.mjs`).** After every successful append the helper projects the folded state through `projectControlBeacon` and refreshes the group cache; failure warns and preserves the recorded transition; `next --beacon-session` prints the restricted briefing for an active order.
- **Worktree helper (`scripts/worktree.mjs`, `scripts/lib/beacon-observe.mjs`).** The read-only `constellation` command and its `--agent … --log …` form, which validates the log path, imports the current skeleton build, and appends only.
- **Cleanup classifier (`scripts/lib/paths.mjs`, `.gitignore`).** `.control-beacons/` is disposable at the anchored root only and is ignored at the repository root.
- **Tests and fixtures.** A pure suite (normative tables, exhaustive v2 and group round trips, allocation bounds, age boundaries, authorization-before-read across five refusal reasons, authority independence under a throwing clock, and the WO-016 identity extension), a CLI suite (unreadable directory refusal, unreadable garbage decode, escape refusal, and both benchmark smoke forms), a real-Git three-worktree fixture (lifecycle-ordered constellation, byte-identical reads, garbage and absent decoding, audience whitelist, capability disclosure and refusals, anchored disposal, and projection failure), a shared bootstrap fixture that installs the four source leaves into every script fixture, resume-fixture beacon snapshots and decodes around every read-only command, and worktree-fixture assertions that populated projection directories leave with a safely closed worktree.
- **Benchmarks and evidence (`scripts/benchmark-beacon.mjs`, `benchmark-beacon-contention.mjs`, `docs/evidence/WO-021/`).** Bounded, reproducible comparisons of metadata sweeps, per-member JSON, and a single JSON index at 3, 12, 100, and 1,000 members and under one, two, and four reader threads, with the committed JSON results and the storage-bound observations.
- **Documentation.** The domain model's v2 and group tables, record whitelist, perception-and-age section, and preserved function-table option; the architecture's control-beacons paragraphs; the interfaces' constellation row and glyphs; the execution guide's command, request envelope, log containment, capability API, and anchored disposable root; the audit document's audience separation and documentation-backed scan-visibility limits; the compatibility document's codebook axis; the roadmap's dated technical observation; the playbook's constellation guidance; ADR-0002's tooling amendment; the capability table's dated row; the map and the usefulness checkpoint; WO-009's and WO-022's input notes; the skeleton README; the ledger's dated section; the publication index and locks; and the README release block.
