## Release overview

Product documents stop accreting. The document gate now runs `scripts/docs-check.mjs`, which holds each of the fifteen product documents under a recorded byte ceiling, refuses a new dated receipt paragraph or `Candidate —` heading under `docs/product/`, refuses a decision record whose dispatch lacks a control prefix and a short paraphrase, and resolves every in-repo Markdown link and anchor in the root and `docs/` documents; the rule every role reads now says to edit the changed sentence in place and names the check.

## Read before upgrading

`npm run test:docs` gains two suites and a preflight: a product document over its ceiling, a new receipt or candidate shape, an unprefixed dispatch or a broken link fails the gate with the file, the line and the remedy. Ceilings live in `docs/control/doc-ceilings.json` at each document's non-exempt bytes at landing plus two per cent; a consolidation lowers a ceiling in the same change, and raising one requires a resolving planning-document decision named in the entry. The baseline in `docs/control/doc-baseline.json` admits only the shapes, dispatch fingerprints and broken-link occurrences present at landing, counted; it is not regenerated to admit new violations. Relative links are judged from the Markdown file that holds them, including stored PR and release bodies, so a PR body written under `docs/final-reviews/` links with `../../` paths, not `docs/` paths. Roadmap §Release boundary is exempt from the byte count and the shape checks until WO-086 retires its handwritten notes.

## Substantive changes

The check uses the pinned Prettier Markdown parser already installed, so fenced examples, comments and inline code are not shapes or links, headings resolve to the same slugs GitHub renders, and reference definitions, HTML anchors and `?plain=1#L` line references resolve. A hand-written marker pair grants no exemption, a leading byte-order mark is counted and does not disable detection, and a document absent from the ceilings file fails. The generated work-order index shows a pending verification or final-review report as plain text until its verdict is recorded, so the document gate no longer fails on an allocated but unwritten report in every verifying and final-review window; a completed report stays linked and its absence still fails. The integration decision stub emits a control-prefixed dispatch from its recorded phase.
