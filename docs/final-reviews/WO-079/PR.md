# WO-079

When a sibling work order merged first, the second lane's reviewer had to run an eight-step integration by hand from a prose checklist: stash the work, merge main, regenerate every generated projection, union the follow-up register by entry id, retime a release target the sibling took, and remember which checks the new base invalidates. It was remembered rather than executed, and the record shows it: the five final reviews since 2026-09-13 that integrated a sibling ran a median of about 32 minutes against about 25 for the rest, and each one was handled a little differently — a sibling's publication read as a defect once, two retimes, two hand-merges of the register. This change makes it one command, `npm run worktree -- integrate WO-NNN`, run inside the order's own worktree.

**Nothing is destroyed to do it.** Before anything moves, the helper mints a recovery checkpoint ref that captures untracked bytes too, then takes a named `--include-untracked` stash. It fast-forwards a branch with no commits of its own, and starts an uncommitted `--no-ff` merge when the branch has reviewed commits, so history is never rewritten. It applies the stash and never pops or drops it. It makes no commit: a reviewed branch is left with `MERGE_HEAD` pointing at the incoming base so the merge commit stays the reviewer's action. If it is interrupted, an ignored receipt keeps the original bases, the checkpoint and the stash across the boundary, and the command refuses to apply the stash twice.

**Generated and authored content are separated rather than guessed at.** Pure projections — the harness bundle and manifest, the control projection, the work-order index, the decisions index, the generated role skills, the console expected outputs — are resolved by regenerating them with the repository's existing producers, not by picking a side. Mixed documents are re-merged with only their generated fragment masked, so `CLAUDE.md`'s harness block, an edition's lock line and the README release claim regenerate while the authored prose around them still goes through Git's ordinary three-way merge and may still conflict. The follow-up register unions by entry id and keeps both histories as compatible prefixes; a divergent history for one id is refused to authored resolution, because renumbering a source revision would change what a past disposition meant. Everything genuinely authored is listed by name, the command exits nonzero, and `--continue` resumes after those paths are resolved and staged.

**It reports; it does not decide.** The helper runs no product gate, appends no repair, verification or lifecycle event, and certifies no acceptance claim. It prints the affected checks for the integrated tree — selecting `npm test -- --review` from the runner's own declared machinery sources rather than a path heuristic — and writes a dated draft decision naming both bases, the checkpoint, the retained stash and the resolved paths, with the carried-forward claims left explicitly for the reviewer to complete. It refuses outside a matching `wo-NNN` worktree, when the upstream cannot be resolved, and when ignored intake is present without a named external backup whose bytes still match.

**Evidence.** A real-Git fixture clones a bare local origin, checks out `main` and a `wo-998` worktree, merges a sibling that takes a colliding tag, and drives both the fast-forward and the reviewed-commit paths against conflicting generated projections, a conflicting authored file, a register both sides appended, and untracked local bytes. It asserts content, not exit status: the checkpoint is read back for the untracked file, the stash identity is compared before and after `--continue`, `HEAD` and `MERGE_HEAD` witness that no commit was rewritten or created, both register entries are found by id and deep-equal their originals, control segments are byte-identical, and the integrated tree passes `harness check`, the console fixture check, `check-publication` and `work-orders index --check`. The three refusals are asserted against a full snapshot of `HEAD`, the binary diff, the untracked list, both ref namespaces and the raw index file, so "no control event is appended" is covered by the same equality; a stale intake backup and a matching one are covered too, and an unrelated third order's phase is varied between cases and never consulted.

**Validation.** `npm test -- --review` passed **30 suites, 0 failed, 497.36 s, 74 fresh tasks** at final review on the staged tree, outside the sandbox from the start. `npm run test:docs` passed 19, 0 failed. `git diff --cached --check` is clean, publication coverage is 272/272 with both editions current, `harness check` validates 31 generated surfaces. No dependency is added; the only `package.json` movement is the internal `@dotln/skeleton` bump to `0.33.1` and its matching console pin, because the reviewer's integration instruction is skeleton source. This is a patch release, `v0.37.1`.

**What a reviewer should know.** Verification passed first time and recorded seven limits rather than none, and two mattered at final review. The fixture's reviewed-merge case asserted neither the release retime nor the draft decision — its generators only run after the authored resolution — while the per-case line the test prints stated `retimed: v9000.0.2` for both cases as a hardcoded literal. Final review moved both assertions to after `--continue` and made that line read its values back, so both cases now observe the retime; the full gate was rerun afterwards. The second limit, that generators can run while an authored conflict is still unresolved in the fast-forward path, was resolved by reading rather than left open: an unresolved conflict keeps the receipt incomplete and the exit nonzero, `--continue` regenerates over the resolved bytes, and both generators that could see conflicted content are idempotent across the two runs. Two limits stand as recorded: a divergent register history is asserted at unit level but not driven end to end, and the decisions-index conflict is covered only by the checks that follow it. The helper has not yet run a real integration — `main` did not move during this order, so its own final review had nothing to integrate — and no time saving is measured or claimed.
