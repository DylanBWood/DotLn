## Release overview

DotLn can now read back a pull request it opened. `npm run worktree -- observe-pr --store EPISODE-STORE --number N` reads the pull request's head, check runs and review comments through `gh` in JSON mode and appends one `PullRequestStateObserved` event to the same `publication/` log that holds its `PullRequestOpened`. Each check carries its name and state. Each comment carries a role (`automation`, `reporter` or `reviewer`), a class (`ci-failure`, `automated-review`, `human-review` or `resolved`) and its resolution. Every stored string first passes WO-060's source-bundle screen with the forge host as the only allowed host. Identical state appends nothing, and nothing polls. The release is for anyone who publishes through DotLn and wants the resulting feedback in the episode store, and it is the input WO-066 needs to act on that feedback.

## Read before upgrading

The command only reads GitHub: it uses read-only GraphQL queries, writes nothing to the pull request and observes only a pull request whose `PullRequestOpened` the store records. A comment whose text or metadata the screen refuses is kept as a refused item with its shape, field path and, for a declared finding, its UTF-8 span, and without its text; a refused comment id becomes a local `refused:N` placeholder that is not a forge id and must be read again before anything acts on it. Known limits, recorded for planning and not changed here: a NUL byte in a pagination cursor or thread id sent back to `gh` makes the command print part of that value on stderr (nothing is stored); a single token run of several million characters overflows the screen and refuses the whole observation instead of one item; the observation is read page by page, not as one atomic snapshot; and with a refused item present, a remote reordering of the same comments appends a new event because refusal paths are positional. On real pull requests most bot review comments link off the forge host (dashboards, badges, documentation, including `docs.github.com`), so they are stored as refusals without text, and a bot that runs as an ordinary `User` account is stored as a human reviewer; both follow from the declared allowlist and the `Bot` type and are for planning to widen.

## Substantive changes

Automation is decided from the GraphQL actor type: a `Bot` author is `automation`; `User`, `Mannequin`, `Organization` and `EnterpriseUserAccount` are admitted as people, and the pull request's own author is the `reporter`. A failing check run or status (`FAILURE`, `ERROR`, `TIMED_OUT`, `STARTUP_FAILURE` or `ACTION_REQUIRED`) also appears as an `automation` comment of class `ci-failure` whose text is the check name. Comments in a resolved review thread are `resolved`; pending drafts are left out. Every connection is paginated, including the comments inside each review thread, and check reads are pinned to the observed head. A number the store does not record, output that does not decode (named by its field path), a GraphQL error, a changed head or author, stalled pagination and a failing `gh` each refuse with the reason and append nothing, and a forge host the screen cannot admit is refused before any `gh` call.

## Progressive polish

`executeGh` accepts an optional output buffer bound, which only the observer sets (16 MiB); every other caller keeps its default. The `worktree` usage line names `observe-pr`. Product 02 names the event, its log and the command beside WO-064's `PullRequestOpened` paragraph, and product 05 records the operator's personal delegation profile for workflow modes as a specification, with no runtime change.
