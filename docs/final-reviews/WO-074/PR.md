# WO-074

`npm run launchpad -- export <dir>` now writes a launchpad instance into an empty directory from the HEAD commit of the checkout that holds the running scripts, so a fork starts from a pinned, manifest-listed kit instead of a hand-made copy. Before this change nothing produced a starter: the operator's starter repository was an intention recorded in product 03, and WO-075 to WO-078 (the runtime build in the export, the overlay, update and the sibling registry) had nothing to build on.

**The kit.** The export reads every kit file as a Git blob at that commit, never the work tree: the control-plane scripts and suites (`scripts/**`, the kit templates under `scripts/kit/` among them), the build-free `packages/beacons` workspace, the nine build-free `.mjs` package modules the scripts import, `LICENSE`, `LICENSE-docs` and `NOTICE`, the execution guide and the playbook whole, and the implementation-overlay template. It generates a `package.json` with core's script names and exact development pins, a lockfile pruned to the beacons workspace and the closure of those pins, `dotln.config.example.json`, `UPSTREAM.md` (commit, tag, forge remote, kit groups, seeds and upstream pointers) and `KIT-MANIFEST.json` (schema 1: the commit, the tag and a SHA-256 per kit file, sorted by path). Instance seeds are written once and never listed, so a later kit update replaces listed files and touches nothing else: the operating contract with its hand-written clean-room and secrets floor and a marked provenance block, `AGENTS.md` symlinked to it, a sanitized harness-security template, the client README, `.gitignore`, the pre-drafted first order in WO-001's shape with the harness smoke, the local-terms registration step and four generic audit questions, the proposed sequence, the workstream and repository-profile conventions, one README per seeded document root, and an empty grants registry. TypeScript package source, intake, local settings, Beacons, runtime stores and this repository's evidence are never exported.

**Refusals and screening.** A destination that exists and is not an empty readable directory, a symbolic link, a kit file absent at the commit, an unknown option and a local-terms refusal all stop the command before any write. The local-terms list is the launchpad's (`DOTLN_LAUNCHPAD` or the ascent), never the kit's: the export runs the check over every text it will write, the manifest included, and prints `local-terms list: present (N texts checked)` or `local-terms list: unavailable; no text was checked against a local-terms list`, or refuses by file and line without printing the term; a list present but empty refuses too. Two advisories name what the export does not carry: kit paths that differ from HEAD in the work tree, and a destination inside another Git work tree, which must run `git init` before any control-plane command. `--license none` writes `LICENSE-PENDING.md`, a notice that grants no rights and names no license, in place of the three license files, and the generated `package.json` says `UNLICENSED`.

**Read before merging.** The kit carries no compiled runtime and no harness bundle. Inside an export, `activate`, `status` and `implementation-ready` run without a build and emit control Beacons; in a Codex session `next`, `verify`, `fix`, `final-review` and `release-close` refuse until WO-075 carries the runtime, and `npm test`, `npm run build` and `npm run harness` do not run there (decision D007 records the export's own test command as a follow-up). The offline `npm ci` was shown on this host's warm cache; a cold host runs `npm ci` with network. In a hooked session, an export destination outside the roots the role is granted needs an operator-named root or an equipped support, as WO-144 carried in; the fixtures write under the system temporary root. Three follow-ups are boarded: the export's test command (FUP-8fb7ae17dd0fad5b), the operator's public author constant inside byte-identical kit files (FUP-06de60fa5d19fe5a) and fixture data derived from this repository's verification records (FUP-e624167a7f6555f6). The order's own wording gaps, criterion 2's "packages/skeleton source" against step 1's TypeScript reading and step 11's lock location, are planning's to amend.

**Validation.** The fixture suite, one case per criterion, passes 10 of 10 fresh in the executor's, the verifier's and this review's runs. Criterion 6 was run three times from a committed copy of the tree against the main checkout's list, which holds the operator's terms: `present (305 texts checked)`, exit 0, nothing refused, and the exported `scripts/launchpad.mjs` hashed to the reviewed bytes each time.
