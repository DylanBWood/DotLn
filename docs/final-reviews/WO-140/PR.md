# WO-140

A verifier who ran `npm test` inside a harness sandbox used to watch it fail on suites that can never pass there, diagnose the failure, and run the gate again outside: WO-121's VER-001 did this twice, at 17 and 18 of 19, and never recorded a passing run of its own. From this change the runner refuses before the build and every suite when the selection contains a suite that declares `needs: outside-sandbox` and a sandbox is actually in force, naming the suites and printing the command that runs the same selection outside. The refusal costs 0.1 s where the failed gate cost 191 to 515 s plus its diagnosis. Separately, a verification or final-review receipt allocated from now on must say what it cost: entry and handoff token counters with their source, or exactly one cause code from a closed list, never a bare "unknown".

**A marker never refuses by itself.** `CLAUDECODE` reaches sandboxed and unsandboxed commands alike, and `CODEX_SANDBOX` marks a Seatbelt-spawned process, so a recognized marker only says which harness launched the run. What decides is one exclusive create in the directory that harness's sandbox protects — `.claude/hooks`, or the resolved Git directory — and only `EPERM`, `EACCES` or `EROFS` reads as a sandbox in force. Every present marker is probed, because one harness can inherit another's. No marker, a missing directory, a permitted write, a refused removal and a probe that throws all fail open and the gate runs exactly as before; only a selection that needs the outside pays for the probe at all. This pull request's own gate is the fail-open case: its recorded row carries `marker: claude-code`, probe `written`, `inForce: false`.

**A partial run can never be mistaken for the gate.** `npm test -- --inside-sandbox` drops the declared suites and records the distinct identity `npm test -- --inside-sandbox` with `partial: true` and `excludedSuites`, never `npm test`. `findGateCheck` and `reviewedProductGate` — the two functions behind the gate lookup, the lifecycle transition, pull-request publication and release close — reject a row that is partial or names exclusions under any identity, so relabelling the row, or stripping its `partial` flag and leaving the exclusions, does not launder it. A regression fixture asserts all three rejection shapes and then accepts the full run at the same code identity.

**Validation.** The final-review gate `npm test -- --review` passed 29 suites with 0 failures in 535.86 s, exit 0, recorded 2026-09-20T04:43:33.164Z at code identity `05df9155`, after the two new source modules were staged. `harness check` matches 31 generated surfaces, `git diff --check` is clean in the worktree and the index, and no dependency is added — the lockfile carries only skeleton `0.29.1` and the console pin. [VER-001](../../verifications/WO-140/VER-001.md) passed all six criteria independently, including native Seatbelt probes under both real markers and an independent temporary-repository run of the real `runGate`.

**What a reviewer should know before merging.** The order's Cost paragraph and criterion 3 say one of WO-121 VER-001's in-sandbox suite failures was the `.claude/hooks/**` denial. The receipts say otherwise: that failure was `skeleton`'s nested `sandbox-exec`, and WO-121 FINAL-001 §L1 attributes the hooks denial to `git merge`, `git checkout --theirs` and `harness emit`, which are commands, not suites. So only `skeleton` carries the declaration, the hooks path is used as the Claude Code probe instead, and [D001](../../evidence/WO-140/decisions.md#wo-140-d001) records the difference with a planner follow-up rather than declaring a suite to match the sentence. The 2026-09-17 ideation receipt's own known-issue list claimed this wording had already been corrected; it had not. `release` is not declared: WO-121's F1 was a defect that reproduced outside the sandbox too, and its one temporary-root failure inside passed inside in every other receipt.

**Also worth knowing.** The executor's first gate run failed one suite on an instrument defect this order's own evidence created — a live 324 s verifier episode made a replayed stream serialize past the engine's string limit — repaired by comparing one decision at a time ([D008](../../evidence/WO-140/decisions.md#wo-140-d008)). An adversarial subagent the operator asked for reproduced no blocking defect and eleven smaller ones; the consequential repair moved the cost-line judgment to the result transition, where the author can still edit the receipt, so an immutable receipt is never the first to meet the rule ([D007](../../evidence/WO-140/decisions.md#wo-140-d007)). The reviewer's cold-start ceiling was raised one 4 KB step to 24,576 for the two new reviewed rules, with the operator's authorization recorded and nothing trimmed; it now measures 21,299, and the verifier sits at 20,081 of 20,480 ([D005](../../evidence/WO-140/decisions.md#wo-140-d005)). This is a patch, `v0.33.1` above `v0.33.0`, with skeleton `0.29.1` and no kernel, compiler or console change beyond the pin.

**Left open, owned.** No Claude Code or Codex session with its sandbox actually enabled was available on this host, so in-force behavior rests on real Seatbelt denials under the real markers rather than on a real harness launch; that a Codex Seatbelt sandbox refuses the nested `sandbox-exec` is a labelled inference, and whether `CODEX_SANDBOX` is set on Linux is unknown, where that harness would be unrecognized and fail open as the order accepts. With filesystem isolation disabled while Seatbelt stays active, the hooks write succeeds and the gate fails open into the nested-sandbox failures it would have had before. Whether the two WO-068 native cases should skip under a refused probe, which would let `skeleton` drop the declaration, is D001's planner follow-up. `observed-facts` matches gate identities by substring, so a hedged quantity can bind to the partial identity; it is advisory only and boarded to planning in D007.
