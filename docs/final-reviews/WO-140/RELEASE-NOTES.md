## Release overview

Running the product gate inside a harness sandbox used to mean watching it fail on suites that can never pass there, diagnosing the failure, and running it again outside. WO-121's first verification did exactly that twice, at 17 and 18 of 19, and recorded no passing run of its own. From this release the test runner refuses before the build and every suite when the selection contains a suite declared as needing the outside and a sandbox is actually in force, naming the suites and printing the command that runs the same selection outside. It is for anyone who runs DotLn's verifier or reviewer roles from inside a sandboxed harness session. The second half of the release is about honesty rather than time: a verification or final-review receipt allocated from now on states what it cost, in counters or in one named cause, and can no longer say only "unknown".

## Read before upgrading

**Outside a sandbox, nothing changes.** The selection, the recorded identity and the exit status of `npm test` are exactly what they were. A run that merely carries a harness marker gains one `sandbox` field on its recorded row and is otherwise unaffected.

**A marker alone never refuses.** `CLAUDECODE` reaches sandboxed and unsandboxed commands alike and `CODEX_SANDBOX` marks a Seatbelt-spawned process, so a recognized marker only names the harness. One exclusive create in the directory that harness's sandbox protects — `.claude/hooks`, or the resolved Git directory — decides, and only `EPERM`, `EACCES` or `EROFS` reads as a sandbox in force. Every present marker is probed, because one harness can inherit another's. No marker, a missing directory, a permitted write, a refused removal and a probe that throws all fail open and the gate runs as before. Only a selection that contains an outside-only suite pays for the probe.

**Running unsandboxed is still your decision.** Nothing runs the gate outside for you. The refusal names the suites and prints the command; you run it.

**A partial run is never gate evidence.** `npm test -- --inside-sandbox` runs what remains and records the distinct identity `npm test -- --inside-sandbox` with `partial: true` and the excluded suites. The gate lookup, the lifecycle transitions, pull-request publication and release close all reject that row, and reject a row naming exclusions under any identity, so relabelling it `npm test` or stripping its `partial` flag does not make it count. `--inside-sandbox` with nothing left to run is an error rather than an empty pass.

**New receipts must state their cost.** A verification or final-review receipt carries exactly one physical `**Process cost:**` line: entry and handoff counters with their source, or the word `unknown` followed by `cause` and exactly one of `hooks-fallback`, `no-session` or `harness-no-readback`. The `verification-result` and `final-review-result` transitions judge the line while its author can still edit the receipt, and `npm run test:docs` checks it afterwards. No measurement is ever required — a cause code is always admitted — so this never blocks a handoff. Only receipts allocated by a transition that stamped the duty are judged; every existing receipt, and a sibling worktree's receipt allocated before it integrated the rule, passes untouched, and nothing is edited retroactively. A new cause adds a code to the closed list, never a free-text unknown.

**Finding your session's counters.** Every role dispatch briefing now prints the session id on a `DotLn session:` line and the exact `node scripts/harness.mjs usage` command with that id already filled in, in the form the usage guard admits; a resumed Codex session gets the same line from its session report.

## Substantive changes

**Sandbox preflight in the test runner.** A suite declares `needs: outside-sandbox` only when an environmental cause means it cannot pass inside a harness sandbox; a failure inside one is never by itself a reason to declare. `skeleton` carries the declaration, because its native cases nest `sandbox-exec`, which an outer Seatbelt sandbox refuses. `release` does not: WO-121's F1 was a defect that reproduced outside too. The refusal precedes the build, the diagnostics directory and every suite, so a refused run leaves no check row, no gate marker and no partial state. An unrecognized suite need is refused at validation.

**Partial results have their own identity.** `findGateCheck` and `reviewedProductGate` — the two functions behind all four consumers of product-gate evidence — reject any row that is partial or names exclusions, under any check identity. A regression fixture drives the real gate to produce a partial row, then asserts the rejection of that row, of a copy relabelled `npm test`, and of a relabelled copy with the `partial` flag stripped, before accepting the full run at the same code identity.

**Receipt cost lines are records, not mentions.** The check reads one physical line outside code fences, indented or as a list item; a fenced example is not the line. A counter is a plain or comma-grouped integer of tokens, a source is not `unknown`, `none`, `n/a`, `tbd` or a negation, and a cause is the code that directly follows the word, with a second mentioned code refused as ambiguous rather than guessed.

**Role text.** The verifier and reviewer skills now say that in an operator-attended session the product gate runs outside the harness sandbox from the start, that a resident-launched verification runs the inside selection and records its exclusions as a partial result, and how the cost line is written. The reviewer's cold-start ceiling is raised one 4 KB step to 24,576 for those two rules, with a dated acceptance and the operator's authorization recorded; nothing was trimmed to fit, and the verifier's ceiling is unchanged.

## Progressive polish

The generated bundle, manifest, hooks, role text and `CLAUDE.md` were regenerated for the two new rules, and cold-start totals stay inside every ceiling in both generated roots. Product 07 gained the closed cause-code list in its Process budget text and a Gate sandbox preflight entry in its discipline section; the README, the roadmap's release boundary and the publication table-of-contents locks were brought in line. Eighteen synthetic receipts across eight fixture files gained an admitted cost line, because their fixture lifecycles allocate stamped receipts. The authority and feedback evidence editions were re-recorded for the changed sources, with the earlier revision preserved. A stored-stream test that a long live verification episode had pushed past the JavaScript engine's single-string limit now compares one decision at a time and sums the same byte count.
