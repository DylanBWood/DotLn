## Release overview

A Claude session working under DotLn's generated hooks could write or delete a file anywhere the host allowed, and the operator keeps the native sandbox relaxed for throughput. On 2026-09-18 a verifier's stray stderr redirect created a file in the directory above its worktree. From this release, a write whose destination DotLn can name and that resolves outside the project is refused before it runs unless the active role, or a support equipped on it, holds a grant for a root that contains it. The refusal names the destination, the missing grant and `operator override:`. It is for anyone who runs DotLn's contributor roles in Claude Code with a relaxed sandbox. It is a refusal of known mistakes, not confinement: what it cannot see stays with host permissions, and the notes below say exactly what that is.

## Read before upgrading

**Temporary files go in the DotLn scratch directory.** All six contributor roles are granted the host's `os.tmpdir()` root and a per-session DotLn scratch directory beneath it (`dotln/`, then the session key, then `scratch`), and nothing else. Claude role dispatch prints the concrete path; in Codex, `node scripts/harness.mjs scratch` prints it. The directory is not created for you: `mkdir -p` it first, which is granted. On macOS `/tmp` and the Claude Code session scratchpad under `/private/tmp` are outside `os.tmpdir()`, so a write tool call or a literal redirect into either is refused.

**Nothing under your home is granted by default.** Sibling checkouts, the main checkout's ignored intake, Documents and Desktop are granted to no role. `main-intake` and an operator-named absolute root are available grant kinds, and each needs an authority grant admitted through the host registry before a role or support can carry it. An order that must write outside the project names its root on the executing role; order contracts do not become grants by themselves yet.

**What is judged.** Recognized write tools, by path. Shell operands of `touch`, `mkdir`, `tee` and `rm` when the rest of the command stays inside the bounded read vocabulary. A literal output redirect on any program, because the shell opens it: `npm run meta 2>../.x` is refused. Symlinks are resolved and a removal judges the entry it unlinks. The judgment holds from any working directory and resolves relative destinations where the shell will. A literal redirect to the `/dev/null` character device is a discard and needs no grant.

**What is not judged, and stays under host permissions.** A destination spelled with an expansion, substitution or wildcard: `2>$PWD/../.x`, the recorded incident as it actually happened, is still admitted. A quoted operand attached to its operator (`2>'../x'`), a redirected group, and a relative redirect after an earlier unrecognized program in the same command. Anything a program writes by itself. In the recorded review and verification sessions most shell calls were unobserved. A command is judged as a whole, so one expansion-spelled redirect, or a quoted argument containing `<` or `>`, leaves the literal redirects beside it unjudged too.

**Codex.** No project hook fires in the recorded Codex profile. There the rule and the grants are role text only.

**The four older refusals still depend on the working directory.** The writer, live-gate, planning-branch and subagent refusals are judged only while the session's working directory is the worktree root. Away from it they stand down with one advisory, as before; each hook now journals that row.

**Recovery.** `operator override:` admits, as for every refusal. An unreadable grant table, an unavailable root or a path that cannot be resolved admits with one advisory and a journaled cause, and never disables the other refusals.

## Substantive changes

**Outside-write grants are data on roles and supports.** A role or support declares roots from a closed set of kinds: system temporary, session scratch, main intake, and an operator-named absolute root recorded with its source. The compiler binds each root to an exact `outside.write:` effect in a host-registry-admitted authority grant and the effective envelope, refuses a declaration no admitted grant covers, and lowers the per-role union into the generated hook configuration. A support cannot widen the envelope by declaring a root. The manifest lists every role's effective roots with the declaring origin, the source and the authority grant id. A typed correction removes these effects like any other destructive effect.

**A fifth refusal at the existing pre-tool boundary.** Every generated pre-tool hook judges a known destination's physical path against the active role's roots and refuses the first ungranted one; a refusal already established survives a later unreadable destination. Only the permission hook journals, one row per destination, with role, destination, status and, when granted, the kind, origin, source and grant id. A granted write-tool call reports its effect as `outside.write:` followed by the grant kind, for example `outside.write:system-temp`. An in-project write never consults the grant table.

**The hook finds its own project.** A generated hook took its project from the session's working directory, so one persisted `cd` stood the new refusal down without a trace, and a hook whose directory was another repository's root created its journal and advisory marker inside that repository. The runner now accepts the session's directory as the root only when the pinned runtime is installed under it, and otherwise finds the project from the installed runtime's own location; the generated fallback, used when the runtime cannot be loaded, derives its root from the hook file's location. Rows judged away from the root carry `workingDirectory: moved`.

**Literal redirects are named on any program.** A new accessor, `shellRedirectTargets`, names literal output redirects whatever the program is. Only the outside-write judgment consults it, and only when the whole-command reading is opaque, so the live-gate and planning-branch refusals read commands exactly as before. A partial judgment journals its verdict and then one `unobserved` row for the program's own effects.
