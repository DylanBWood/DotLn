# WO-144

A Claude session under DotLn's generated hooks now refuses, before it runs, a write whose destination it can name and that resolves outside the project, unless the active role or an equipped support holds a grant for a root containing it. The refusal names the destination, the missing grant and `operator override:`. All six contributor roles are granted the host's temporary root and a DotLn session scratch directory beneath it, and nothing else: the operator's home, sibling checkouts and main's ignored intake are granted to no role by default. The operator keeps the native sandbox relaxed for throughput, and on 2026-09-18 a verifier's stray stderr redirect created a file in the directory above its worktree; this is the machinery that replaces reliance on the sandbox for that mistake.

**The width, stated plainly.** Judged: recognized write tools by path; operands of `touch`, `mkdir`, `tee` and `rm`; a literal output redirect on any program, because the shell opens it; from any working directory, with symlinks resolved and removals judged. Not judged, and left to host permissions: a destination spelled with an expansion, so `2>$PWD/../.x`, the incident as it actually happened, is still admitted while its literal spelling `npm run meta 2>../.x` is refused; a quoted operand attached to its operator; a redirected group; a relative redirect after an earlier unrecognized program; and anything a program writes by itself, which is most shell calls. Codex fires no project hook, so there the rule is role text. Product 03, product 07 §Discipline, the security runbook, the README and the generated role text all say this.

**How it got here.** The order was failed twice on live evidence. [VER-001](../../verifications/WO-144/VER-001.md) found `2>/dev/null` and the host scratchpad refused in a real session; the repair made the null device a discard and prints the granted scratch path at dispatch. [FINAL-001](FINAL-001.md) found that one persisted `cd` stood the guard down without a journal row and that a redirect on `npm`, `node` or `git` was never named; the repair finds the project from the installed runtime instead of the session's directory, names literal redirects on any program through a separate accessor so the live-gate and planning-branch refusals read commands exactly as before, and stops a hook from writing its journal into another repository. [VER-002](../../verifications/WO-144/VER-002.md) and [VER-003](../../verifications/WO-144/VER-003.md) passed those repairs.

**Validation.** [FINAL-002](FINAL-002.md) reproduced both FINAL-001 repairs live: after a persisted `cd docs`, FINAL-001's admitted command, a relative escaping redirect on `node` and a Write-tool call were each refused before execution and journaled as judged from a moved directory, and a granted scratch write was admitted.
