## Release overview

An operator of a DotLn instance now turns a feature on or off by name in one file: `dotln.config.json` gains a `features` section of named booleans, each optionally carrying the operator's reason, and a generated `docs/control/FEATURES.md` says for every registered feature what it does, whose choice it is (core, instance or both), its default, its effective value and source, which key carries the election and which module reads it, marking a switch nothing reads yet as `unread` and a future consumer by its queued order. The page ends with what no file can change: the refusal classes, the single-writer reservation and the clean-room floor. The first two elections wired through it are the Tinkerer economy (on by default, off with one edit) and a private instance's own destination for ordinary project links; a misspelled feature refuses with the list of real ones.

## Read before upgrading

`npm run meta` now renders `docs/control/FEATURES.md` in every instance and `npm run test:docs` refuses a stale page, so run `npm run sync` or `npm run meta` after this update and commit the page. The `features` section accepts the registry's four named elections (`tinkerer-economy`, `plan-first`, `private-destination`, `desktop-control`); an unknown id, a non-boolean `on`, a non-string `note` or an inventory id whose election lives under another key (`kit.applyInstanceActions`, `release.*`, `build.*`, `drive.sandbox`, the budgets keys) now refuses with the key to edit. A build overlay that still equips or unequips `tinkerer-economy` keeps working this kit release and prints a migration advisory on each emit; declaring `features.tinkerer-economy` with a different value in the same instance refuses until one is removed, and the route retires in a later release. `npm run sync` refreshes the installed harness before metadata; a fixture or script that copies `scripts/lib/config.mjs` alone must now also copy `scripts/lib/features.mjs`, `scripts/lib/build-overlay.mjs` and their imports, because the loader imports the registry. Electing `private-destination` rewrites only the exported instance's known §Secrets paragraph and refuses a customized one; with the key absent nothing changes. The kit's example configuration now shows the four elections and `kit.applyInstanceActions`; copying it declares Tinkerer on explicitly.

## Substantive changes

Configuration and registry: `scripts/lib/config.mjs` validates `features` against the registry in `scripts/lib/features.mjs`, which declares eighteen rows (the four named elections, `kit-instance-actions`, the four `release.*` surfaces, `build-loadout`, `build-profile`, `build-overlay`, `drive-sandbox`, `subagent-cap`, `dispatch-bounds`, `driven-session-ceiling`, `driven-phase-timeout` and `retention`) with their defaults, scopes, sentences, election keys and readers; `readFeatures(root)` resolves the named elections over their defaults and an empty alias table carries the one-release rename advisory.

The command and the page: `npm run features -- list [--json]|render|check` prints the inventory, writes the page under the configured control root and refuses a stale, missing or hand-edited page; `npm run meta` calls the renderer and the document gate's generated check reads it; a queued consumer that has closed produces a planning advisory from `features -- check`, `npm run meta` and `npm run plan -- start`, never a refusal.

Emission: the Tinkerer economy's equipped default reads `features.tinkerer-economy` at emit, with the overlay route mapped onto the same key for one release and conflicts refused; `private-destination` is rendered into the exported instance's §Secrets paragraph by `harness emit` and judged by `harness check`; `scripts/lib/build-overlay.mjs` holds the overlay schema, file-boundary and diagnostics that the harness and the feature reader share.

The kit and the documents: the example configuration declares the four elections with one `{ on, note }` entry; the kit guide gains §Features; product 07 §Where the control plane finds its documents names the section, the forms, the registry, the page and the refresh order; `docs/product/feature-configuration.md` is rewritten as the standing page that points at the generated inventory; the generated-artifact order runs the harness before metadata.
