# WO-203

An update to an exported DotLn kit now shows its plan before it writes anything. Until this change the first time a starter or an instance learned what an update changes was after the files had been written: `export --update` planned and wrote in one step, and a fork taking a starter revision by `git merge` had no view of the kit files the merge would touch. Now `export --update /path/to/starter --preview`, run from core, prints the plan the update would apply and writes nothing, and inside an instance `node scripts/launchpad.mjs preview --from upstream/main` prints the same shape for the fetched starter revision the operator is about to merge. The operator decides when to take upstream changes with the plan in hand, and the update's own summary afterwards is the same rows the preview showed.

**From core.** `updateKit` is split into `planKitUpdate`, which reads the destination, preflights its still-carried inputs, builds core's pinned runtime and judges every kit path and declared instance action without a write, and `applyKitUpdate`, which performs today's writes from that plan; `updateKit` is their composition, so the preview and the update share every judgment by construction. One renderer, `renderUpdatePlan`, prints the counts, one row per kit path (`replace`, `add`, `remove`, or `refused` with the reason and the retained prior hash, or `retained hash: none` for an instance-owned collision), the declared actions and their plan (`apply`, `preserved/already applied` or `preserved/no opt-in`), and under `--preview` the incoming commit and tag, the declared build hash before and after, and `receipt: would write` with the path, or the reason none applies. `--preview` combines with `--apply`, which then runs the same opt-in and action checks and refuses an incompatible action before any write. The fixture snapshots every destination byte, mode and symlink including `.git` plus core's `docs/evidence/siblings/` and `docs/siblings/`, asserts all three unchanged after a preview with no pending manifest, and compares the preview's plan rows with the following update's in both opt-in states (880 matching rows each). The preview still pays the source build, which the README states, and the receipt filename it names is reserved only by the actual update, so its timestamp can differ.

**Inside an instance.** `preview --from` resolves the named revision once under the export's isolated Git environment and reads `KIT-MANIFEST.json`, `scripts/kit/KIT-ACTIONS.json` and the harness manifest at that revision, then plans against the instance's current tree. It prints the kit files the merge will change (`replace`, `add`, `remove`) apart from `unchanged` ones, so an identical revision reports zero changes and a path already converged reads `unchanged`; a locally modified kit file as a refusal, annotated `unchanged upstream; no merge conflict expected` when its incoming hash equals its prior hash; an occupied new kit path as a collision; and every action declared at the revision as manual work after the merge, with an action that cannot fit this instance printed as `cannot apply` with its reason while the kit rows and the other actions still print. It builds nothing, merges nothing and writes no receipt (`receipt: none (a starter merge writes no core sibling receipt)`), and refuses a root or revision without a manifest. The README's new sequence is `git fetch`, `preview --from`, `git merge`, `harness emit`, under the rule "Preview before every update."

**Carry-ins and the gate repairs.** The three Boy Scout items WO-078 left on the update path are disposed ([D004](../../evidence/WO-203/decisions.md#wo-203-d004--carry-in-dispositions-and-the-remaining-pre-build-bound)): absent still-carried source and determinable derived inputs refuse before the build (the fixture asserts the build output's inode and mtime are untouched), post-manifest receipt and registry failures carry the completed plan into the summary and name the destination and receipt state, and the object, text, known-key and stale-line predicates that `config.mjs`, `lib/siblings.mjs`, `siblings.mjs` and `work-orders.mjs` each carried live once in `scripts/lib/validation.mjs`, pinned in the emit closure and the three fixture copy lists. **Read before merging.** The in-instance preview is a manifest comparison, not a prediction of Git's three-way merge: Git can merge some edits it lists as refused, a starter's own edits can keep their retained manifest hashes and then read as `unchanged` in a fork that still holds the original bytes, and files outside the manifests are outside the preview; the README states each. Two follow-ups are boarded by the second verification: a fork that has removed a manifest-listed kit file the incoming revision still carries gets the shared planner's refusal naming the path instead of rows ([D015](../../evidence/WO-203/decisions.md#wo-203-d015--verification-follow-up-a-revision-preview-refuses-when-the-instance-removed-a-kit-file), FUP-9c558fa0f869290e), and the from-core preview lists byte-identical carried paths as `replace`, 865 rows for a real update that changes three kit files and adds one, because the unchanged distinction is confined to revision previews ([D016](../../evidence/WO-203/decisions.md#wo-203-d016--verification-follow-up-the-from-core-preview-lists-byte-identical-paths-as-replace), FUP-bf112b957627334d). Generated compiled and emitted kit paths still get their absence check after the build (FUP-dc79b4b1065bf66e). The receipt's date is now fixed at the end of planning, earlier than the write by the apply duration, with the same fields and path rule; planning receipt 044's regression condition for the split did not otherwise occur, on an 80-case differential probe and the real corpus.
