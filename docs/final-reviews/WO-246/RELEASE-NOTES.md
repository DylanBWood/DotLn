## Release overview

DotLn v0.117.0 keeps a fork's own pull requests on the fork. A planning pass and a kit update now publish their branch through one helper that names the repository `origin` points at, and the hook refuses a `gh pr` or `gh issue` command that would silently reach the fork's parent. It matters most to anyone running an instance forked from the starter: before this release, `gh` in such a clone resolved to the parent unless a default had been set, and one update pull request was opened on the starter by mistake. The release also accepts pull-request titles in the form core itself writes, and makes the fetch behind `update --finish` and the target routes download only what the checkout lacks, under a bound.

## Read before upgrading

- **Authority change: two allow rules.** The emitted `.claude/settings.json` now carries `permissions.allow` entries for `Bash(node scripts/launchpad.mjs update --publish *)` and `Bash(node scripts/refute-plan.mjs publish *)`. A session can run those two helpers, which push a planning or update branch and open its pull request, without a host prompt. No rule names `git push` or `gh`, and the deny list is unchanged. An instance receives the rules through its update's re-emit, and `harness check` compares that file byte for byte, so the rules are withdrawn in core's profiles, not by hand in an instance ([decision](../../evidence/WO-246/decisions.md#wo-246-d014--correction-the-allow-flag-decides-the-bytes-and-names-where-its-contract-was-read)). Decide whether you want prompt-free publication before merging the update that carries this release. Whether Claude Code's auto mode resolves these rules before its classifier is taken from its documentation and has not been observed live; start a fresh session after the update.
- **A new refusal in fork clones.** With both an `origin` and an `upstream` remote that name different repositories and no gh default set, a `gh pr` or `gh issue` command with no repository is refused. Name the repository with `-R`, or run `gh repo set-default origin` once in the clone when both remotes are on one server. Until a fork takes this release it is still exposed, and that same command closes the gap.
- **A stricter attribution check.** A line that opens with a gitmoji, in its Unicode or `:shortcode:` form, is now judged past it. A commit or pull-request line that opens with a gitmoji followed by a session key such as `user-session:` is refused where it was admitted before.
- **A bounded fetch.** `update --finish`, the target close and the target publish refuse a read or fetch that passes ten minutes, leaving the checkout unchanged and naming the by-hand route. `update --finish` accepts `--fetch-timeout SECONDS`; the two target routes have no override.

## Substantive changes

**Publishing the launchpad's own branches.** `node scripts/refute-plan.mjs publish --title TITLE --body-file PATH` (also `npm run plan -- publish`) ends a planning pass on a `planning/DATE-SLUG` branch, and `node scripts/launchpad.mjs update --publish --title TITLE --body-file PATH` publishes an instance's `chore/SLUG` update branch once the merge, the re-emit and the lineage index are committed. Each lints the title and body, refuses a listed private term and AI attribution, proves `gh` and its login for the repository `origin`'s push URL names, pushes there and opens a ready pull request against `main` with `--repo`. Every refusal precedes the first push. A retry after a failed create repeats no push and adopts the open pull request whose head, branch and base match.

**The hook's repository judgment.** The permission hook reads the command as written and the clone's Git configuration, one read of about 5 to 7 ms. Two remotes are the same repository only when their host, owner and name match; an SSH alias spelled from `github.com`, such as `github.com-work`, counts as `github.com`, and any other alias or server is treated as its own. A command that names a repository by flag, by `GH_REPO=`, or by a pull-request or issue URL is admitted, as is any command after `gh repo set-default`, and a clone with one remote sees no change. A clone whose remotes cannot be read is admitted with one advisory. The refusal names each remote by host and offers only the remedies that work for that clone.

**Pull-request titles.** The lint admits a gitmoji followed by a subject, with or without a conventional type, and no longer limits a title's length. A bare subject with neither is still refused. Commit subjects are unchanged: a conventional type, optionally behind a gitmoji, and at most 72 characters. A target publish lints its title as a title only, so a fork needs no workflow to retitle.

**Fetching through a lane that borrows the checkout's objects.** The lane reads the remote branch's commit first and fetches nothing when the checkout already holds it whole; otherwise it downloads and imports only the missing objects, still without touching the checkout's refs or transport configuration before the import.

## Progressive polish

The kit guide, the security guide, the playbook, the architecture page and product 07 state the helpers, the ninth refusal and the finish's bound where their rules already lived. The planner's role text names the publish helper by the spelling the allow rule covers. Flag parsing for the two publish commands and `plan target-publish` shares one helper.
