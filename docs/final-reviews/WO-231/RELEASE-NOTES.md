## Release overview

Application v0.97.1 makes a registered target order's final review lint only the commits its pull request will carry. Before this release `final-review-result pass` linted every commit from the order's activation base to the subject, so an order whose branch had taken in later base-branch commits was judged on the target's own merged history. On 2026-10-24 the operator's fork met the consequence: a verified target order was refused with `subject.length: 90 of 72 characters` on a merged commit no one could repair, 17 commits linted where the pull request carries one. This release reads the described base the publish already uses since v0.96.1, names the range in every refusal, keeps every record bound to the activation base, and fetches nothing at review.

Audience: operators and reviewers of exported instances that publish into a target repository whose base branch moves while an order is open, and maintainers of the target commit lint and the publish helper.

## Read before upgrading

- **The review lints the described range.** `final-review-result pass` on a registered target order resolves the clone's remote-tracking ref for the registered base branch (`refs/remotes/origin/main` when the base branch is `main`), takes the merge base of the subject and that ref, and lints from it when the activation base is its ancestor; otherwise it lints from the activation base as before. The rule is the one `describedTargetBase` applied at publish, now in the shared helper `targetBase` ([D001](../../evidence/WO-231/decisions.md#wo-231-d001--describe-the-same-base-at-review-and-publication)).
- **A refusal names what it read.** Every format, identifier or attribution refusal opens with the number of commits linted, the described base and the subject, adds `activated at base` and the activation base when the two differ, and names the offending commit before the finding, so an operator can see which commit and which range produced `subject.length: 90 of 72 characters`.
- **An absent ref keeps today's range.** A clone with no remote-tracking ref for the base branch is linted from the activation base, and the refusal says the ref was absent and that the activation base was used ([D002](../../evidence/WO-231/decisions.md#wo-231-d002--keep-review-local-and-preserve-the-conservative-fallback)).
- **Review does not fetch; a stale ref is yours to refresh.** The review reads the ref the clone holds. That ref moves at a target close, at a target planning publication or when you fetch by hand; the reviewer's `worktree integrate` does not move it, although the order's Objective said so, and VER-001 corrected that rationale ([D006](../../evidence/WO-231/decisions.md#wo-231-d006--ver-001-boards-the-unnamed-tracking-ref-and-corrects-the-no-fetch-rationale)). A stale ref lints more commits than the forge will show and can refuse a merged subject; fetch the base branch in the target clone and retry. The publish fetches through the lane and lints the same commits again from the fetched merge base.
- **Nothing recorded changes.** `FinalReviewCompleted` keeps `targetSubject.baseCommit` at the activation base, the target gate binds the same reviewed commit, and the publish's Change table, exemptions and lint are unchanged.
- **Known issues.** When the ref is present but stale, on unrelated history or peeling to no commit, the refusal names neither the ref, its commit nor the remedy, and the tree case reads as absent (VER-001 F1, FUP-e4fa2bbf7c3968ec). A ref moved locally onto the subject empties the described range: the review passes over no commit, and the publish's lint then refuses the commit and opens no pull request, leaving a closed order that needs a new commit (VER-001 F2, FUP-378c5638bf515e52; [D005](../../evidence/WO-231/decisions.md#wo-231-d005--ver-001-boards-a-review-range-a-moved-tracking-ref-can-empty)). Both are deferred to the next order that edits the lint. The criss-cross case, several merge bases, is untested; the single merge base Git returns is used.
- **Versions.** Application v0.97.1 is a patch release over v0.97.0, assigned at activation under the order's classification. No component version changes: compiler 0.31.0, skeleton 0.68.0, console 0.5.0, kernel 0.8.0, beacons 0.1.1 and browser-evidence 0.2.0 stay, the lockfile is unchanged and no dependency is added. No role text changed.

## Substantive changes

**The helper** (`scripts/lib/target-base.mjs`, new). `targetBase(read, activationBase, subjectCommit, baseTip)` returns the merge base of the subject and the base tip as the described base when the activation base is its ancestor, and the activation base otherwise, with the activation base beside it; a missing base tip or a failed merge-base read falls back to the activation base. It has no imports, so the review lint still loads no publication runtime.

**The review lint** (`scripts/lib/target-commit-lint.mjs`). `lintReviewedTargetCommits` resolves the clone's remote-tracking ref for the registered base branch with a quiet `rev-parse --verify` peeled to a commit, calls the helper, lints the commits from the described base to the subject, and prefixes each of its three refusals with the range sentence and the offending commit; the attribution sweep names the first attributed commit.

**The publish** (`scripts/lib/target-publish.mjs`). `describedTargetBase` keeps its activation-ancestry refusal and its lane fetch and delegates the base choice to the helper; every existing publish case passes without edits, and its tables and closing sentences are unchanged.

**Tests.** The target-worktree start suite gains five cases: the fork's shape with the base branch carrying a conforming 90-character merged subject, the order fast-forwarded onto the fetched ref, one conforming commit added and the fixture origin taken offline, passing with `FinalReviewCompleted` at the activation base; its paired arm with the ref deleted, refusing the merged subject from the three-commit activation range and naming the absent ref; and three cases asserting the range sentence before a format, an identifier and an attribution refusal. The two existing review-lint cases are byte-identical and still refuse. The runner's exact inventory moves to 69 declarations and 100 names ([D004](../../evidence/WO-231/decisions.md#wo-231-d004--extend-the-existing-exact-inventory-for-this-orders-five-cases)).
