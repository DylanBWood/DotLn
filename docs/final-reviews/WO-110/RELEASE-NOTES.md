## Release overview

DotLn can now hand an inspection episode to a model running on the operator's own machine. This release adds the third `WorkOrderTransport`, over an operator-owned local inference endpoint, and gives the actor catalog's `local-model` entry a real adapter in place of a placeholder. One episode is one bounded HTTP request to an explicit loopback origin, with no child process and no supervisor; the six-field result envelope is validated at the host exactly as it is for the two CLI transports; and an endpoint that is not there becomes a typed unavailability the resident records as a reasoned NoOp. The release is for anyone who wants DotLn's inspection work to have a local, non-remote option alongside the CLI brokers, and for the qualification work that follows: the transport is landed and observed against one live run, and nothing about the local model is yet graded ready.

## Read before upgrading

**The local model is admitted, not enabled.** The catalog's availability for `local-model` is a declared, dated row, `L-U1`, and it ships as `unavailable`. A resident configured with a `local-model` actor records a reasoned NoOp and dispatches nothing to it. Supplying a `ready` row is a later order's decision; WO-138 is the qualification order and still waits on a `ready` WO-137 readiness packet.

**A working endpoint is not readiness.** The live run returned a validated envelope, and readiness still fails because no attributable non-local-egress boundary exists and WO-137 grades the runner `inconclusive`. Do not read the envelope as a grade.

**This runner does not honor the requested model.** The live dispatch named `required-model`, a different identifier was loaded, and the endpoint served the episode anyway. The transport cannot establish which model produced a result, and `model-unavailable` cannot rely on the endpoint refusing an unknown name; it holds for a refused, reset or aborted connection and for an error body naming a missing model. Any consumer that needs the answering artifact bound to the result must obtain that identity from the runner.

**Inspection only.** Writer, verification-evidence and plan-refutation requests are refused on their kind before any request is sent. The local model has no writing profile in this release.

**Additive contract change, minor component bump.** `ActorSpec` and `ActorResult` gain an optional `local` slot, `WorkerTransportName` gains `local-model-http`, and `@dotln/skeleton` moves from `0.31.0` to `0.32.0`; nothing is removed from the exported surface. `HARNESS_HOST_VERSION` follows the component, so the 31 generated harness surfaces are regenerated with new snapshot hashes and no changed logic. The authority and feedback evidence editions are re-minted for this order at revision `001`; the previous editions keep their bytes.

**The live smoke is explicit and operator-run.** `scripts/probes/local-model-transport-smoke.mjs` contacts nothing unless `--live` is passed, refuses to overwrite an existing destination, starts no server and loads no model. Starting, loading, unloading and stopping the runner remain operator steps; the availability record carries the reproduction.

## Substantive changes

**A third transport, over loopback HTTP.** `packages/skeleton/src/local-model-transport.ts` implements `WorkOrderTransport` as a single bounded `fetch` to an explicit `http://127.0.0.1` origin with a port: no DNS name, credential, path, query or redirect is accepted. The wire is the native `/api/v0/chat/completions` shape WO-137 observed, with a `json_schema` response format carrying the same result schema the CLI adapters pass as a file, fixed decoding, `reasoning_effort: "none"` and no DotLn effort value; the effort selector stays a launch claim. The response is read under a 262,144-byte bound, a completion stopped at the token cap is an `output-limit`, a deadline or a `kill()` aborts the request and settles the dispatch as `deadline-exceeded` or `interrupted`, and the decoded result passes through the host's own `parseWorkerResult` before it is returned. The endpoint's schema enforcement is never trusted.

**A real catalog entry with a declared row.** `local-model-actor.ts` and `local-model-contract.ts` supply the adapter, the launch claims and the persisted observation contract. `available()` answers from the declared row and never probes the endpoint; `run()` refuses when the row is not `ready` or when no endpoint request is declared. A `local-model` actor may be declared without an endpoint, so an operator whose runner does not exist yet does not lose the whole resident configuration. The observation records either a validated result or one of the seven typed failure codes, and `scriptResultVerified` treats a local completion claim as not independently verified, exactly as it treats a CLI one.

**The existing contracts learn the new kind.** `ActorSpec` accepts an optional `local: { endpoint, request }` for the `local-model` kind only, with the request's intent effect required to match the actor's; a declaration on another kind is refused. `canonicalWorkerArgs` refuses `local-model-http` instead of building argv for it. The catalog's `until WO-110` placeholder is gone.

**Recorded availability and the live smoke.** The availability record and two machine packets record the installed runner, the 18:10 UTC absence, the 18:38 UTC envelope with shapes only, the unhonored model field and the unchanged readiness grade; `environment.md` gains the dated addendum. The smoke's own tests pin that a fixture summary never reaches the packet and that an unreachable endpoint is a row, not a failure.

**Documentation.** Product 03 §Ports describes the third adapter, its one-request boundary, wire shape, validation, fences, declared row and model-identity limit; §Runtime primitive catalogs replaces the placeholder sentence. The skeleton README documents the `local` declaration in the resident runbook, and the software-engineer edition's table of contents names the transport.
