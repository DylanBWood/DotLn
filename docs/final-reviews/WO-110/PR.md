# WO-110

DotLn had two real work-order transports, both of them CLI brokers, and a local model existed only as a probe record. This change adds the third: `LocalModelWorkOrderTransport` carries the inspection profile to an operator-owned inference endpoint over one bounded HTTP request to an explicit IPv4 loopback origin. It launches no child process and forks no supervisor, because aborting the request ends the episode with the resident that started it. The actor catalog's `local-model` entry stops being a placeholder string and becomes a real adapter whose availability is a dated, declared row rather than a live probe, so the resident can record why no work happened without contacting the operator's machine. The shipped row is `unavailable`, and it stays that way until a readiness row exists.

**What the transport does, and what it refuses.** The wire shape is taken from WO-137's observed protocol rows, not from a vendor promise: the native `/api/v0/chat/completions` path, a `json_schema` response format carrying the same result schema the CLI adapters pass as a file, fixed decoding, and `reasoning_effort: "none"`, without which WO-137 watched a whole token cap disappear into reasoning. The DotLn effort selector stays a launch claim and goes nowhere on the wire. The response is read under a 262,144-byte bound, a completion stopped at the token cap is an `output-limit`, and the six-field envelope is validated again at the host exactly as it is for the CLI adapters; the endpoint's own schema enforcement is never trusted. Writer, verification-evidence and plan-refutation requests are refused on their kind before any request is sent, so the local model gets no writing profile. A refused, reset or aborted connection, or an error body naming a missing model, is a typed `model-unavailable` that the resident turns into a reasoned NoOp; nothing falls back to another actor kind. A local completion claim is never independent verification.

**The live run, and the limit it surfaced.** With nothing listening at 18:10 UTC the smoke recorded an `unavailable` row. After the operator started the runner, one dispatch at 18:38 UTC returned a validated six-field envelope in 14.56 s: status completed, a 161-character summary, one candidate with three evidence strings, recorded as shapes only, with no model-authored text in the packet. That is n=1 on one warm runner against one four-file fixture, and it promotes nothing: readiness turns on an attributable non-local-egress boundary that still does not exist, so the row is `unavailable` as a grade, not as a liveness check. The run also showed that this runner ignores the request's model field: the wire named `required-model`, `dotln-local` was loaded, and the endpoint answered anyway. The transport therefore cannot establish which model produced an envelope, and D007 puts that on WO-138 to obtain from the runner rather than the request.

**Validation.** `npm test -- --review` passed **28 suites, 0 failed, 261.70 s, 72 fresh tasks**, run at final review after the whole subject was staged and outside a harness sandbox in force. The order's two test files pass 15 of 15 on the reviewer's own build, against real loopback HTTP doubles rather than stubbed clients. Final review added six response shapes of its own (a bare `null` body, empty and non-array `choices`, an HTML body, a 503 naming a missing model, an array `content`) and every one ended as a typed, bounded failure. `npm run publication:check` covers 272 of 272 product headings with both editions current, `node scripts/harness.mjs check` matches 31 generated surfaces, and `git diff --check` is clean in the worktree and the index. No dependency is added: the root `package.json` is unchanged and the lockfile moves only the skeleton version and the console workspace pin. This is a minor release, `v0.36.0`, retimed from the collided `v0.35.1` target, with `@dotln/skeleton` at `0.32.0` for an additive surface change and every other component unchanged.

**What a reviewer should know.** [VER-001](../../verifications/WO-110/VER-001.md) failed this order on three real current-subject defects: seven unformatted files and stale authority and feedback evidence editions. It also called the `release-surfaces` failure inherited from base; the repair showed that the rule compares the previous tag with the working tree and that the tag-to-base skeleton diff is empty, so the failure was this subject's own unbumped component, and [VER-002](../../verifications/WO-110/VER-002.md) and final review each reproduced that comparison. Both reports are retained as written. The live envelope, the row's amended reason and the model-identity limit were recorded after `implementation-ready` under an explicit operator override with no transition run or repeated (D007); they sit inside the checkpoint both verifiers judged. The repair's evidence editions were minted twice because the component bump was diagnosed second, so both carry revision `001` and the superseded editions remain as residue (D009). The `.claude` diff is entirely regenerated hashes and the version bump; no hook logic changed. Final review replaced a literal worktree path in the availability record's reproduction block (D011) and recorded, without changing verified source, that a `null` completion body is labelled `transport-failed` rather than `invalid-result` (D012), a cosmetic difference the resident cannot observe. The meter below carries the order row and no dispatch rows: the renderer omits them for a closed order, and the meter was rendered after the result (D013). The catalog's `local-model` entry is admitted before WO-138 qualifies any role for it; at this subject the shipped row offers nothing live, and the planning receipt's reopening condition for that finding is written.
