## Release overview

DotLn can discover concrete maintenance candidates without a model and without an operator waiting. A bounded producer runs the target's declared lint and test checks, compares explicit placement conventions, observes declared generated files with no literal-token references in a bounded corpus, and groups repeated entries in structured repair history. The resident runs it as a script actor and retains the typed observations in its existing script observation event, so the candidates outlive a model window and are ready for WO-100's future preauthorized portfolio. Until now the only candidate producer was a manual review whose program the stepper refuses as deferred, so nothing in the portfolio could actually execute.

## Read before upgrading

No migration or dependency is required. Existing digest-verified script actors keep their contract unchanged; only an actor declaring `outputContract: "work-candidates-v1"` gets the new typed result, and that contract replaces the expected-stdout digest pin with full canonical-output verification on replay. Relative candidate paths and evidence are stored in `ScriptEpisodeObserved` and validated against the canonical stdout digest when the log is replayed. Native execution is macOS-only: discovery fails closed on any other platform, its tests fail rather than skip there, and the suite cannot run inside a harness's own sandbox because macOS will not install a nested one. Conventions are explicit input, `.dotln/discovery.json`, or a selected profile's `dotln-discovery` block; the full WO-073 repository profile system is not implemented by this release. Declared checks run with `HOME` and `TMPDIR` set to the target root, so a check that caches state writes into the tree being observed.

## Substantive changes

An executable Sequence/Guard/Invoke program gathers the observations and is genuinely stepped by the kernel: each stage runs only from an intent the stepper emitted, the residual decides ordering and termination, and no operator await exists anywhere in it. The WorkCandidate contract records kind, paths, evidence references, an optional proposed home and a measured file count, where the count is observed scope rather than any estimate of repair effort. Defaults run package lint and test scripts through the installed npm CLI so lifecycle hooks and package environment behave as the target expects, report their scope as `package.json`, use optional structured repair history, and invent no placement or generated-file convention. Malformed declarations, unsafe paths, symlinks, special files, resource limits and failed launches fail discovery rather than producing a partial result that reads as complete. A pinned producer invocation runs under one target-write-confined, network-denying native sandbox for the whole episode; public direct discovery confines each check separately. No repair, deletion, ranking or work-derivation authority is added.

## Progressive polish

A six-candidate fixture repository and a real scratch Git episode exercise observation changes, native confinement, timeout, unsafe paths, malformed history and output, and tampered replay, alongside the existing resident and scenario regressions. Product 05's 5S / 6S section and the skeleton runbook explain the executable Sort and Shine path. Operator ideation during execution preserved two product candidates without changing any current capability: a future DotLn-owned authority mode requiring faithful runtime enforcement, adversarial bypass tests and uninterrupted authorized work while the operator is away, and an extension of the existing Context Continuity candidate covering progress after compaction or premature turn completion when no tool is running. Both call for selective host-owned continuation and live tests without operator nudges; this release implements and claims neither, and changes no harness permission setting.
