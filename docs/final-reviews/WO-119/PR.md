# A bounded episode now finds a repository's real maintenance work without a model or an operator

DotLn's only candidate producer was the Entropy Reducer's manual review, whose program uses `Program.All` and waits for an operator to dispose of each finding — the stepper refuses `All` as deferred, so the portfolio had no producer it could actually execute. This change adds one: `discover(worktree, conventions)` runs the target's own declared lint and test commands, compares its declared placement conventions, looks for declared generated files that nothing references, and groups repeated entries in structured repair history, then emits typed `WorkCandidate` values carrying relative paths, evidence references, an optional proposed home and a measured file count. Every candidate is an observation with evidence behind it, never a model's opinion, and nothing in the path can repair, delete, rank or derive work. The resident dispatches it as a native `script` actor and keeps the validated report in the existing `ScriptEpisodeObserved` event, so candidates survive a model window without a second state machine.

The program is executable in the sense the order's title means: `discovery.ts` drives the exported `discoveryProgram` through the kernel's stepper, each stage runs only from an intent the stepper emitted, the residual decides ordering and termination, and no `Await` node exists anywhere in it. A six-candidate fixture repository seeds real observables — a lint that exits 1, a test that fails an assertion, two misplaced files, one unreferenced generated file and one repair recorded twice — and the producer finds all six by running them, not by reading a catalog of answers.

Validation: `npm test -- --review` passed once at the reviewed code identity, 27 suites, 0 failed, 794.94 s, 71 fresh tasks and none reused. `git diff --check` is clean and no dependency changed; the only lockfile edit is the skeleton version string. Independent verification ([VER-001](../../verifications/WO-119/VER-001.md)) passed all five criteria, reproducing the live scratch-Git row byte for byte and executing the sandbox probe that a recorded decision cited but no artifact held. Final review ([FINAL-001](FINAL-001.md)) re-derived the two claims that carry the order — that the kernel really steps the program, and that the resident's verified discovery event cannot be reached through a truncated capture — and judged every finding, observation and limit the verification raised.

Read before merging. Native execution is macOS-only: `discovery.ts` fails closed on any other platform and the tests fail rather than skip there, and the suite cannot run inside a harness's own sandbox because macOS will not install a nested one. Conventions are explicit input or a declared profile; without them the defaults run package `lint` and `test` through the installed npm CLI with their scope reported as `package.json`, and invent no placement or generated-file rule. Checks run with `HOME` and `TMPDIR` set to the target root, so a check that caches state writes into the tree it is observing — deliberate and bounded, but worth knowing before pointing it at a repository you care about. Reference analysis tests literal declared tokens, not language-level reachability, and candidate `size` is observed scope rather than any estimate of repair effort. Existing digest-verified script actors are unchanged; only an actor opting into `outputContract: "work-candidates-v1"` gets the new typed result, and that contract drops the stdout digest pin in favour of full canonical-output verification on replay. WO-100 is unimplemented, so the typed output and its schema are verified but no consumer is yet satisfied by them.

Final review made one repair, and it is the verification's own F1. The release staging was half-landed: `packages/skeleton/package.json` declared `0.22.0` while `HARNESS_HOST_VERSION` and every pin emitted from it still said `0.21.0`, contradicting the recorded decision and the release notes. At every release tag those two are in lockstep, so the constant was bumped and the harness bundle re-emitted; the bundle diff is only the runtime snapshot identifier, the `skeletonVersion` literal and each hook's content hash, with no change to any hook's behaviour or to the hand-written Clean Room floor. Re-emitting moved the recorded bundle diff, so authority evidence revision `003` is recorded and selected, with revision `002` preserved — the same cascade WO-048 met and recorded. That nothing behavioural moved is measured rather than asserted: `authority.json` is byte-identical between the two revisions.

Carried forward as nominations rather than repaired here, none of them a criterion failure: two reachable inputs — a repair group recurring 129 or more times, and an over-long repair key — make the producer abort a whole report instead of emitting what it had already gathered, failing conservatively but losing real observations; `outputContract` is accepted on any absolute command, so the digest-pin relaxation is wider than the one pinned producer the order describes; the observation-only producer's ability to write into the observed tree is documented in neither the order, the release notes nor the runbook; and `discovery-cli.ts` is pinned as a harness runtime file but named in neither of the other two source inventories. Final review also found that the evidence-edition mask for `HARNESS_HOST_VERSION` still rewrites `harness-host.ts`, which no longer declares the constant — dead today only because `version.ts` is in no compared source list.

The operator opened two `ideation:` breakouts during execution, and they are documentary only. They promote a product 03 candidate for DotLn-owned authority with minimal native harness restrictions, and extend the existing Context Continuity candidate with continuation after compaction and premature turn completion. No harness setting, permission boundary, launch default or acceptance criterion changes with them; the source capture stays in ignored intake and reaches no committed surface. The receipt records that this provisional capture must be reconciled into main's ignored intake before the worktree is removed.
