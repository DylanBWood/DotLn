## Release overview

The composition compiler arrives, and the walking skeleton now runs a compiled loadout. `@dotln/compiler` is a new pure workspace with zero runtime dependencies and no I/O: it takes a typed `LoadoutGraph` plus an explicit environment and returns either a normalized compiled program or structured diagnostics with concrete corrections. The Seiri link group, five supports linked to one active mechanic, lowers to heterogeneous mechanisms with declared cost: bounded repository scope becomes WorkOrder structure, read-only becomes a permission guard, evidence capture becomes a schema, absent-only cadence becomes a cadence plus a statechart guard, and independent verification becomes a verifier episode. Three editable views (code DSL, function table, statechart JSON) compile to one semantic hash, `fnv1a64:9ca8d0229c6bd8db`, and the compiled diff renders as the RPG item tooltip: `Seiri / Sort / 整理`, GRANTS through INTERRUPT, then COST and SEMANTIC HASH. The skeleton's reactor obtains its WorkOrder, authority envelope, cadence identifiers, statechart guard, and verification subject from the compiled program in place of WO-003's hand-assembled object, and all 21 decision traces are exactly what they were. Audience: anyone reading the compiler as the reference for how a loadout becomes an executable program, the WO-009 worker transport that will consume compiled WorkOrders, and the WO-022 Senses and WO-023 reviewer orders, which now compile against a real compiler instead of a second hand-assembled loadout. This is DotLn `v0.4.0`, the first minor above `v0.3.6`, carrying `@dotln/kernel` `0.2.0` unchanged, the new `@dotln/compiler` `0.1.0`, and `@dotln/skeleton` `0.4.0`.

## Read before upgrading

- **The skeleton's `Loadout` is now the compiler's `LoadoutGraph`.** The four-field provisional object (`identity`, `activeMechanic`, `semantics`, `normative`) is gone; the exported `loadout` is the Seiri graph, and `compileWorkOrder` throws the compiler's diagnostics instead of `unsupported loadout`.
- **The `LoadoutEquipped` payload is the full typed graph.** Every other event keeps its id, type, order, and payload; the two WorkOrder-carrying payloads (`WorkOrderEmitted`, `CommandPersisted`) are deep-equal to before but use canonical property order. The JSONL log grows from 8,805 to 17,661 bytes. Consumers that compared logs byte for byte must account for those three payloads.
- **The CLI banner reads `v0.4.0`.** That is the only byte that changes in default CLI output. `--compiled-diff` is new and additive and composes with `--audit`; `--audit` output grows from 1,082 to 1,630 lines because it prints the equipped graph.
- **Reactor constants come from the compiler.** `MINUTE`, `PULSE_SCHEDULE`, and `QUEUED_PULSE` keep their values but are re-exported from `@dotln/compiler`; `compileLoadoutProgram` is new; `runScenario` accepts an `equippedLoadout` option. The pure reactor now imports `@dotln/compiler` beside `@dotln/kernel`.
- **Compiler v1 is deliberately bounded.** It lowers exactly one active mechanic, at most one participating link group, and at most one explicit pipeline in that group, and it rejects wildcard authority patterns, unknown precedence layers, non-finite numbers, multiplier overflow, and undeclared non-commuting order with a diagnostic rather than a guess. The broader graph types do not imply executable support.

## Substantive changes

- **Compiler package.** New `packages/compiler/` exports the full graph type boundary (`Identity`, `Role`, `Container`, `ActiveMechanic`, `SupportFacet`, `Link`, `LinkGroup`, `ExplicitPipeline`, `AmbientEffect`, `ResourceModel`, `Phenotype`, `PolarAxis`, `AuthorityEnvelope`), finite canonical normalization, three codecs satisfying `decode(encode(x)) = normalize(x)`, the four-step `compileLoadout` (phenotype, link type-check, precedence and commutativity, emission), typed diagnostics, the nine-level precedence trace, per-support declared costs, and the tooltip and view-hash renderers.
- **Diagnostics instead of hope.** An incompatible link returns `SUPPORT INACTIVE` naming the exact missing capability or tag family plus `provide-capability`, `unequip-support`, or `link-compatible-active` corrections; feeding the named capability back into the environment activates the same link. Conflicting hard claims reject with both support ids; a non-commuting pair without a pipeline demands one; equal-precedence ties reject as ambiguous; duplicate ids, dangling references, and container socket overflow are invalid graphs.
- **Precedence governs authority for real.** A winning authority claim, whose target is `authority.` followed by the effect id, rewrites the emitted `AuthorityEnvelope` and the WorkOrder operation lists, so the trace and the kernel's runtime authorization agree; the kernel's `authorize()` accepts an effect the precedence winner allowed. Wildcard patterns are rejected rather than letting a broad losing pattern override an exact winner.
- **Skeleton on the compiled program.** The reactor compiles the equipped graph at `LoadoutEquipped` and reads its cadence, guard, verification subject, WorkOrder, and authority from the compiled program; equipping or unequipping a support changes the running decisions, and changing a compiled schedule id changes the emitted pulses.
- **Evidence.** The node test count rises from 110 to 154: the exact `SUPPORT INACTIVE` text and its executable correction; the three round-trip laws; three-view hash equality with a semantic edit that changes the hash; the nine-way conflict trace and every adjacent precedence pair; wildcard, unknown-layer, hard-conflict, declared-conflict, non-commuting, multi-pipeline, cross-group, and overflow rejections; commuting-permutation identity; exact per-support costs and heterogeneous mechanism types; the exact tooltip, a real compiled unequip reversal, and exact `--compiled-diff` CLI output; a purity test that fails on an ambient clock or randomness read; and the frozen 21-trace WO-003 oracle compared against the compiled run.
- **Documentation.** The domain model gains the LoadoutGraph v1 payload contract; the interfaces document gains the editable-view normalization and semantic-hash contract; the ledger records six adopted ideas; the compiler and skeleton READMEs and the root README front door describe the new surface.
