## Release overview

This release closes the debts the six orders closed on 2026-09-22 left behind. Each of those orders recorded defects it met and did not fix, from an integration helper that could strand a reviewer to live verifier episodes that were refused with no diagnosable cause, and the operator directed that every one of them be fixed in a single order rather than rediscovered later. The result is fifteen fixes across the closeout helper, the hosts, the resident's binding, live episodes and their receipts, the evidence registries, the control fold and the product gate, each with a fixture that fails against the previous source and passes now, plus a sixteenth fix the operator added during repair: the live verifier's output schema now admits only findings the host can accept, which removed a paid refused attempt from the re-mint. For an operator this means fewer rescues: an integration refuses before it writes rather than stranding itself, a refused live episode says why, a supplied effort is never written as `unknown`, a corrupt allocation takes down one order instead of every control read, and the product gate no longer fails on a teardown race with no owner.

## Read before upgrading

A source-change writer that removes a path or turns a file into a directory is now refused unless the removal is the declared Sort move, and a change over the envelope's `files` ceiling is refused with the paths and ceiling named; a target or repair order that must remove a path needs `repo.delete` admitted by an operator decision. Target publication pushes from a host-created bare repository with hooks and fsmonitor off, so a target whose push relied on repository-level configuration (a repository-scoped credential helper, a URL rewrite, an operator's `pre-push` check such as a Git LFS upload) no longer gets it during DotLn publication, while the operator's global and system configuration still apply; the push URL must be origin's configured URL and must name the repository `gh` resolved. Under a readable `CLAUDE_EFFORT` a claude-code lifecycle attestation must be exactly that effort from `claude-session-readback`; any other effort or source, `unknown` included, is refused before an event is appended, so a Claude Code role that attests another session's effort from its shell is refused until a provenance contract exists. A refutation receipt filed from now on records no separate worker statement and renders each attempt's typed reasons instead; filed receipts keep theirs. `resident-bind` no longer requires `--model` and `--effort`; without them a bind records the transport's default and says so. Existing resident stores, allocation events without a section digest, filed Entropy Reducer receipts and binding records keep their bytes and meaning. The skeleton component moves to `0.38.0` and the console to `0.1.10`; no dependency is added.

## Substantive changes

**Closeout machinery.** `worktree integrate` refuses an intent-to-add entry before any fetch, checkpoint or receipt, naming each path and the `git add` remedy, and again at `--continue`; a stash push that fails with nothing stashed leaves no pending receipt, a stash Git stores and then fails to finish resumes with `--continue`, and only a stash entry carrying this integration's name and base counts as its own. The adjacent queue's new `retarget` action moves a deferred item's target onto an existing public follow-up identifier, also at final review, and refuses prose, a missing identifier or any other field; the executor's rule says to sync the register before disposing.

**Hosts and the skeleton.** The source-change host counts the committed change's paths against the envelope's `files` ceiling and refuses removals and type changes without `repo.delete`, exempting only the declared Sort source. Target publication runs no target hook and none of the target's push-time configuration, with a filed probe of both writer profiles and a fixture that plants `pre-push`, `reference-transaction`, `receivepack`, `sshCommand` and an included `fsmonitor`. The skeleton admits an artifact identity carrying an `authorityGrantRegistry`, validated by the compiler's normalizer, so a grant-bearing loadout equips and reaches the source-change host.

**The resident's binding.** A portfolio binding is built from the loaded `portfolios` entry and compiled under the bound repository's registered `authorityProfile`; `--check` refuses a hand-written store that departs from that profile, naming each departure, or whose profile cannot be read. Always-on judges default per transport to `gpt-6-luna` or `claude-sonnet-5` at `xhigh`, and the binding records `modelSource` and `effortSource` as `default` or `operator`.

**Live episodes and receipts.** An `invalid-result` refusal carries a typed detail from a closed vocabulary into the stored event and the CLI line; raw model output never reaches either. The Entropy Reducer's witness records the untracked listing and the frozen copy's added, removed and resized paths with NUL-framed hashes, and its sentence names only what it observes. Claude Code's selected effort is read from `CLAUDE_EFFORT` and recorded as `claude-session-readback`, selected rather than effective. The verifier's output schema states admission's rules: with no failing witness it admits no finding and no `fail` verdict; otherwise strings are 1 to 2,000 characters and arrays 1 to 100 entries drawn from the subject.

**Registries, the fold and the gate.** Every edition check reads registered sources' imports from TypeScript's scanner tokens and refuses an unregistered runtime sibling; the two protocol files are registered and in the feedback subject. A `registrations` document-gate row owes a registration for every JSONL under `docs/` and a stub for every document-gate script. Allocation events record their section-set digest and fold across a list change, with a corrupt authority scoped to its own order. The gate-sandbox fixture disables Git's automatic maintenance, the cause of the `ENOTEMPTY` teardown, and each gate fails naming any tagged root its suites leave behind.

## Progressive polish

Product 02, 03, 06 and 07, the harness security guide, the skeleton README and the Entropy Reducer guide state the new rules with their sources; product 06's always-on default moved from candidate to shipped with its reopening condition. The executor's cold-start ceiling was raised by the standing one-step route to 29,246 bytes to hold two reviewed sentences, with the acceptance recorded. The generated harness bundle and role skills were re-emitted for the new sentences; hook behaviour is unchanged. The WO-142 inventory test that asserted nothing now asserts five inventories, the role oracle that had been red since WO-151 has a new chained baseline, and two committed transcripts had a per-user temporary-directory prefix replaced by a placeholder at final review.
