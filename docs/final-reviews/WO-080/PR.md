# WO-080

A launchpad can now keep one workstream document per outcome under its configured `workstreams` root, and an order joins it with one leading field, `**Workstream:** WS-NNN`. The generated work-order index groups the members under a Workstreams heading with repository, base, phase, verdict, integration state and a stale mark, reads the integration state from each member's registered target repository at an explicit refresh, and records those facts on one JSON line that `index --check` reuses on any host without opening a checkout. The actor board's Work panel reads that same line as a new Workstreams section, additive within `uifa-board-v1`, and the console moves to 0.5.0 with its schema unchanged. Four of product 12's demonstrations run as a real-Git fixture suite over an exported launchpad and three target repositories. A workstream block may mark its track `separate`: its members stay in the grouping and leave the serial Proposed order, which is how the predecessor track WS-002 stops reading as queued core work ([the order](../../work-orders/WO-080-workstream-document-and-index.md), [D001](../../evidence/WO-080/decisions.md#wo-080-d001--keep-target-observations-separate-from-document-truth), [D002](../../evidence/WO-080/decisions.md#wo-080-d002--separate-queue-placement-while-preserving-the-order-card-contract)).

What an operator or an instance meets differently. Membership is sourced from the orders' leading fields; the document's `dotln-workstream` JSON block must mirror their order ids and repository ids, and a mismatch refuses naming the order and the field to add. An order without a `**Repository:**` line is `self`, with its base the launchpad HEAD observed at refresh and its integration target the launchpad's `main`. Integration is `current`, `behind`, `diverged` or `unknown`; stale is `no`, `yes`, `yes` or `unknown`; a target the generating host cannot read shows `unknown`, never current or stale, and a green sibling changes nothing about another member. A later target change becomes visible at the next explicit `npm run work-orders -- index`, not at check. Because the index reader now validates the documents, the planning commands that read the index refuse a malformed document the same way; the operator's instance's interim WS-001 lists WO-011 and WO-012 without the field and will refuse naming them until those orders declare it, as the kit template and [the convention](../../workstreams/README.md) say. The board's Workstreams section shows eight cells per member and links to the member's card when the card is present; an older index without the marker gives an empty section, a malformed marker makes it unavailable while the order-card section stays available, and the five existing fixture cases keep their pinned inputs byte for byte with expected outputs that differ from the base only by the new section ([D003](../../evidence/WO-080/decisions.md#wo-080-d003--retain-the-board-source-reference-and-additive-schema)).

The synthetic pilot. The `workstream-pilot` suite builds service, client and documentation repositories, exports a launchpad from a committed source copy, registers the three clones and runs four named demonstrations: a single-repository member reaching closed from a target worktree (D1), a client proceeding against its pinned contract fixture while the service lands first (D2), an occupied worktree refusing a second writer while another worktree of the same repository stays eligible (the refusal half of D4), and a session restart resuming from `resume: next` under the emitted target bundle (D6). These are mechanical demonstrations, never evidence of usefulness; D3, D4's conflict half, D5 and a workstream-level next safe action remain FUP-b28d36edaa8630b1's candidates, and WO-083 owns the witnessed run ([D004](../../evidence/WO-080/decisions.md#wo-080-d004--keep-the-pilot-synthetic-and-confined-to-its-four-demonstrations)). The row is core-only in exported kits and joins every fresh core gate at about 57 seconds in the recorded runs; the order's one timed fresh plain `npm test` measured 1,134 seconds, above the six-minute stand-down condition, and both of planning receipt 053's reopening triggers are recorded for planning rather than judged as criteria ([D013](../../evidence/WO-080/decisions.md#wo-080-d013--record-the-fresh-gate-threshold-observation-for-planning), [D017](../../evidence/WO-080/decisions.md#wo-080-d017--ver-001-both-of-receipt-053s-reopening-triggers-for-criterion-5-fired)).

Validation: the executor's complete review passed 41 suites and 107 fresh tasks at code identity `6a931dea…`, after two stopped and one failed attempt that exposed fixture integration omissions, each repaired on the record ([handoff](../../evidence/WO-080/handoff.md), [D010](../../evidence/WO-080/decisions.md#wo-080-d010--repair-the-observed-fixture-failures-before-a-fresh-complete-gate) to [D012](../../evidence/WO-080/decisions.md#wo-080-d012--document-the-pilots-core-only-exclusion-in-the-starter)). [VER-001](../../verifications/WO-080/VER-001.md) passed all seven criteria, held 32 index variations against its own Git reads, compared all five older board cases with the base and ran the pilot three ways, and boarded two follow-ups. [FINAL-001](FINAL-001.md) integrated `main` and took in nothing, read the whole diff, reran the affected checks, the board comparison, the index check on the real corpus and the pilot and console suites at the integrated tree, and passed with no finding of its own.

Limits a reviewer should weigh: VER-001's two follow-ups stand. A `self` member's base, integration and stale cells follow the HEAD of whichever checkout runs the refresh, so a refresh from a branch ahead of `main` would record it `diverged`; the lifecycle refreshes the committed index while HEAD equals `main`, and the rule a repair must hold is recorded (FUP-2811605b8e865d2d, [D015](../../evidence/WO-080/decisions.md#wo-080-d015--ver-001-pass-board-the-self-members-checkout-dependent-integration-reading)). The pilot's D4 and D6 read members D2 starts, so a demonstration selected alone fails on setup rather than on its claim, and one of D2's assertions reads back bytes the test wrote (FUP-ec2be6f5cb63ae35, [D016](../../evidence/WO-080/decisions.md#wo-080-d016--ver-001-board-the-pilot-demonstrations-shared-state-and-d2s-self-confirming-proof)). A consistent forged target commit on the committed line passes check by design, because the line is the only source of Git facts at check. FUP-0126 reads needs-review in the register because this order changed its product 12 section ([D019](../../evidence/WO-080/decisions.md#wo-080-d019--final-review-pass-at-the-integrated-identity-ver-001s-f1-and-f2-stay-on-their-rows)).

Application v0.96.0 is a minor release over v0.95.0: console 0.4.8 to 0.5.0 for the additive section, every other component unchanged, `uifa-board-v1.schema.json` byte-identical, no new dependency and no evidence edition re-minted, because the lockfile's console version is the only changed registered source and every edition normalizes it ([D005](../../evidence/WO-080/decisions.md#wo-080-d005--release-only-the-changed-component), [D018](../../evidence/WO-080/decisions.md#wo-080-d018)).
