## Release overview

Application v0.96.0 lets a launchpad describe an outcome that spans several orders and repositories as one workstream: a document under the configured `workstreams` root, one leading `**Workstream:** WS-NNN` field per member order, a grouping in the generated work-order index that shows each member's repository, base, phase, verdict, integration state and stale mark from a committed record, and the same grouping as a new Workstreams section on the actor board. Four of product 12's demonstrations now run as an automated real-Git fixture over an exported launchpad and three target repositories, and a workstream the operator keeps apart from the serial queue can say so and leave the Proposed order list. The visible payoff is that a cross-repository outcome is read in one place, that a member whose declared base has fallen behind its repository is marked stale without anyone opening that repository, and that the predecessor track no longer reads as queued core work.

Audience: operators who plan outcomes across repositories or read the work-order index and the actor board, instances exported from the kit that hold workstream documents, and maintainers of the index generator, the console and the test runner.

## Read before upgrading

- **Workstream documents are validated.** `npm run work-orders -- index`, `index --check` and the planning commands that read the index now read every `WS-NNN-*.md` under the configured `workstreams` root. Each file needs exactly one `dotln-workstream` JSON block whose id matches its filename and whose members mirror the orders' leading `**Workstream:**` fields and repository ids, with `self` for an order that has no `**Repository:**` line; an edge names a member as `from` and an existing order as `to`. A mismatch refuses naming the document, the order and the field to add. An instance whose interim WS-001 lists WO-011 and WO-012 as `self` while those orders declare no field will refuse that way until the field is added ([the convention](../../workstreams/README.md); [D001](../../evidence/WO-080/decisions.md#wo-080-d001--keep-target-observations-separate-from-document-truth)).
- **The index page has a new section and a new record.** `README.md` carries a Workstreams heading before Active, one list line per member, and one `dotln-workstreams` JSON line recording repository, base, phase, verdict, integration, stale and the observed target commit per member with the edges. `index --check` regenerates the grouping from that line and opens no target checkout, so a committed index checks on a host without the clones; a target that moved since the last refresh is seen at the next explicit `index`, not at check. The check sentence on the page changed accordingly.
- **Separate tracks leave the Proposed order.** A block carrying `"track": "separate"` keeps its members under their workstream heading and out of the serial list, their complete Open cards follow the sequenced cards, and `index --check` accepts them absent from the marked sequence. WS-002 now carries that mark, so WO-228 leaves the Proposed order list while `sequence.md` still names it ([D002](../../evidence/WO-080/decisions.md#wo-080-d002--separate-queue-placement-while-preserving-the-order-card-contract)).
- **The board gains a section, not a schema field.** Console 0.5.0 appends a `workstreams` section to the Work panel with the cells `workstream`, `workOrder`, `repository`, `base`, `phase`, `verdict`, `integration` and `stale`; `uifa-board-v1.schema.json` is unchanged and a view without the section still validates and renders. The section shares the index's source reference: an index without the marker gives an empty section, and a malformed marker makes the section and that source unavailable while the order-card section stays available ([D003](../../evidence/WO-080/decisions.md#wo-080-d003--retain-the-board-source-reference-and-additive-schema)).
- **A new product suite joins every fresh core gate.** `workstream-pilot` exports a launchpad and builds three repositories; it is core-only in exported kits and took about 57 seconds in the recorded complete and fresh runs. The order's one timed fresh plain `npm test` measured 1,134 seconds, above the six-minute stand-down condition, and the row exceeds the slowest structural task; both are recorded for planning ([D013](../../evidence/WO-080/decisions.md#wo-080-d013--record-the-fresh-gate-threshold-observation-for-planning), [D017](../../evidence/WO-080/decisions.md#wo-080-d017--ver-001-both-of-receipt-053s-reopening-triggers-for-criterion-5-fired)).
- **Known follow-ups.** A `self` member's base, integration and stale cells follow the HEAD of the checkout that runs the refresh, so a refresh from a branch ahead of `main` records it `diverged`; the lifecycle refreshes the committed index while HEAD equals `main`, and a repair rule is recorded (FUP-2811605b8e865d2d). The pilot's D4 and D6 depend on members D2 starts, so a demonstration selected alone fails on setup (FUP-ec2be6f5cb63ae35).
- **Versions.** Application v0.96.0 is a minor release over v0.95.0: console 0.4.8 to 0.5.0; kernel, skeleton, compiler, browser-evidence and beacons unchanged; no dependency added.

## Substantive changes

**Workstream convention and field** (`docs/workstreams/README.md`, `scripts/kit/workstream.template.md`, `scripts/lib/work-order-workstream.mjs`, `scripts/lib/config.mjs`). The convention README and the kit seed carry the same final text: the document shape, the JSON block, `self`, the integration enum, the stale rule and the separate track. `parseWorkstreamDeclaration` reads the leading field as `parseRepositoryDeclaration` does and refuses a malformed or doubled line; `readWorkstreams` validates every document against the orders and refuses a mismatch by name; `readWorkstreamSnapshot` is the only source of Git facts at check; `projectWorkstreams` builds the grouping. The loader's comment on the `workstreams` root now states what the root carries.

**Index generation and check** (`scripts/work-orders.mjs`). `parseHeader` carries `workstream`; `readIndex` reads the documents and marks separate members, whose sequence position is dropped; `readTargetFacts` reads each member's registered clone (or the launchpad itself for `self`) at explicit generation, resolving `rev-parse` of the configured base branch and `merge-base --is-ancestor` of the declared base, with `unknown` for anything Git cannot establish; `renderIndex` writes the Workstreams section and the record line and filters separate members from the Proposed order and lane pairs; `checkSequenceCoverage` accepts a separate member outside the marked sequence; `main --check` projects the grouping from the committed record; the sources paragraph on the history page states the rules.

**Actor board** (`packages/console/src/text-sources.ts`, `packages/console/src/work.ts`). `parseWorkstreams` requires the generated-index prologue, accepts exactly one marker line, parses its JSON and validates ids, commits, the integration enum and the stale rule; `projectWork` appends the section after usage, keys rows as `WS/WO`, cites the index reference per row and links to the member's card when present.

**Synthetic pilot** (`scripts/test-workstream-pilot.mjs`, `scripts/test-workstream-index-fixture.mjs`, `scripts/test-runner.mjs`). The pilot exports a launchpad from a committed source copy, registers three clones, authors WS-001 and WS-002 with their members, and runs D1, D2, the refusal half of D4 through the emitted writer hook, and D6. The fixture module is shared with the index tests and the board's pinned input. The runner row is a product suite with the core-only kit exclusion every exporting suite declares.

**Tests and fixtures** (`scripts/test-work-orders.mjs`, `scripts/test-launchpad-planning.mjs`, `packages/console/test/board.test.ts`, `packages/console/fixtures/`). Three real-Git index cases cover the columns, the stale and unknown readings, check with targets absent, `self`, the named refusal, the separate track and duplicate edges; the legacy-upgrade oracle asserts the refreshed starter carries the new convention text; three board tests cover the six-case fixture, the empty and unavailable readings and a view without the section; the manifest pins the sixth case and the expected outputs of the five older cases change only by the new section.
