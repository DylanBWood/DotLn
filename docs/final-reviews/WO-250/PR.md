# WO-250 — Reviews converge and every worker counts: the three independent reviews run once over the diff, recheck only what they found, end in one combined recheck and then in the executor's own judgment; a review worker on Codex or Claude launches from any host through one kit command with a canonical brief and a report the verifier can read; every worker launch and re-task on every path counts against the subagent cap; and no review worker starts a gate (v0.111.0)

Until now the executor's text said to restart all three independent reviewers after any new set of code changes and gave no end: WO-237 ran four recheck rounds and a fifth from one reviewer before the operator stopped it. No kit command launched a Codex review worker from a Claude session, so three sessions each wrote their own `codex exec` launcher in an ignored lane. The subagent counter counted direct `Agent` and `Workflow` admissions and their children, admitted a resumed agent uncounted, never saw a `SendMessage`, and never saw a worker a shell command launched, so a planning pass recorded three Codex reviewers as not against the cap. Review workers ran gates that held the live-gate refusal against the executor for 142, 20 and 438 seconds. And the three review reports of an order vanished with the session scratch before the verifier could read them.

Now the reviews are a ladder with an end. Round one puts three fresh reviewers over the whole diff against the merge base; round two has each reviewer whose findings were fixed recheck those fixes alone, admitting a new finding only when it breaks an acceptance criterion or a behavior `main` had; round three, only when round two's fixes changed code again, is one combined worker carrying the three briefs over the delta since round two's reviewed tree; after it no reviewer runs, the executor judges the remaining delta, and the handoff's `self-review:` line records the rounds and the unreviewed lines with the reason. A round whose preceding fixes touch only comments, documentation, formatting, test names or regenerated files is skipped, and a repair after a failed complete run takes the ladder over its own diff, starting at round three when that diff is under fifty changed source lines. `npm run worker -- review --kind criteria|design|consistency|combined --host codex|claude` launches one review worker with a canonical brief rendered from the generated worker definition, the reviewer briefs and admission rule the role text exports, the order's text or a planning branch's changed documents, and the diff stat against the base; it launches through the transports the entropy review uses, Codex under a read-only sandbox with its tool features on and Claude print with `Read`, `Grep`, `Glob` and thirteen pre-approved read commands, writes `docs/control/local/reviews/WO-NNN/round-N-KIND.md` and a `.json` record in a closed findings shape a verifier reads, prints one line, appends a `WorkerLaunched` row to the session's journal and, under Codex, admits its own launch through the counter before any process starts; `npm run worker -- record` writes an `Agent` worker's returned text to the same lane as the same record. Every use counts: the counter counts launches by host, re-tasks (a `SendMessage` or an `Agent` call resuming a known agent) and kit launches (the helper one, `npm run plan -- review` three, `--dry-run` none), `node scripts/harness.mjs usage SESSION` prints `workers: launched N (claude A, codex B), re-tasked M, cap C, remaining R`, and the twenty-first use is refused. A shell command from an agent the host names `dotln-worker` or `dotln-worker-fable` that starts `npm test` in any form, `scripts/test-runner.mjs`, `scripts/target-gate.mjs`, `test:docs` or `test:full`, inside the bounded wrapper or past Node options, is refused with `DOTLN_WORKER_GATE_REFUSED` naming the bounded single-test probe, while a lifecycle phase agent and the session keep their gates; the generated refusals sentence counts eight. Release close moves the order's reviews lane into its retained lane under `reviews/`, beside its journals.

What a reviewer should know. `SendMessage` is now classed `retask` in the hook's tool map, so a consumer that pins the map asserts the entry separately, as the WO-146 worker-profile hash case now does; a counter written before this change reads with its counts. A session that re-tasks its reviewers reaches the default cap of 20 sooner than one that only spawned, and `subagentCap` in `docs/control/budgets.json` is the operator's knob; a full ladder spends seven uses, a clean round one three. `npm run plan -- review` is counted three uses now although WO-244 defines that command later, which over-counts only a command the planner then refuses. A helper-launched worker is a separate process with no agent identity, so for it the gate rule rests on the brief, Codex's read-only sandbox and the Claude print argv, and the helper compares the checkout's contents before and after the episode as detection rather than prevention. The first Codex launch of this order's own review returned nothing because the runner stopped a worker whose stdout passed 1,000,000 bytes, so for a change review the transcript is kept as a bounded tail and the final message has its own file ([D009](../../evidence/WO-250/decisions.md#wo-250-d009--a-worker-keeps-itself-within-a-stated-budget-and-its-transcript-is-never-its-limit)); the worker's budget and limits are constants until a configuration pass ([D010](../../evidence/WO-250/decisions.md#wo-250-d010--the-change-reviews-budget-and-limits-become-instance-configuration-later)). The order's own reviews were the ladder's first observation: three rounds found 31 findings, 7 blocking, of which 23 were fixed and 8 recorded, over 8 uses, and each of the two repairs after a failed complete run took round three alone and found nothing ([D011](../../evidence/WO-250/decisions.md#wo-250-d011--this-orders-own-reviews-under-the-ladder-the-first-observation-of-the-rule), [D013](../../evidence/WO-250/decisions.md#wo-250-d013--the-first-complete-run-failed-on-a-pinned-worker-profile-hash-and-its-repair-took-the-ladder-from-round-3), [D014](../../evidence/WO-250/decisions.md#wo-250-d014--the-second-complete-run-failed-on-the-shared-digest-rule-and-its-repair-took-the-ladder-from-round-3)). The installed executor, verifier and planner roots exceed their effective ceilings by the ladder's sentences, boarded for optimization with equivalent usefulness and no ceiling raised ([D007](../../evidence/WO-250/decisions.md#wo-250-d007)). Four follow-ups stay with planning: the other kit launch paths the counter does not yet see ([D003](../../evidence/WO-250/decisions.md#wo-250-d003--every-use-counts-launches-by-host-re-tasks-and-kit-launches)), the limits as configuration (D010), the review provenance remainder of the journal key, the reviewed trees and the lane derivation ([D016](../../evidence/WO-250/decisions.md#wo-250-d016)), and the `record` command's reading of a prose report that contains a fenced JSON example ([D015](../../evidence/WO-250/decisions.md#wo-250-d015)); the final review corrected the guide's seven-use estimate ([D019](../../evidence/WO-250/decisions.md#wo-250-d019--final-review-the-judgment-the-one-correction-and-the-recorder-defect-left-boarded)).
