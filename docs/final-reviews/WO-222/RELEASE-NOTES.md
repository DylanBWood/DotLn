## Release overview

Application v0.86.0 makes a complete test run fit the machine it runs on. The scheduler takes its lane count from the host, the lesser of eight and half the logical processors and at least one, records it in the per-user host registry so every clone on the host agrees, and budgets each lane's memory as the gate's share of physical memory divided by the lanes; the structural host check refuses a run whose per-lane budget is below the largest task peak the baseline passing rows record. The three exclusive suites, harness fixtures, process debt and worktree integration, keep their reservation but admit up to two measured light peers. The target-worktree suite runs as four file tasks, two at a time, each under its own 900-second deadline, with every one of its 60 case names kept. On the operator's 16-processor, 48 GiB host the complete review's median fell from 2,538.373 seconds over the three latest passing rows at the base to 1,668.518 seconds over three fresh runs at the handoff identity, 34.27% lower, with no task ending at its deadline. The release also adds a maintained gate-execution architecture record for later orders to cite and extend.

Audience: anyone who runs `npm test -- --review` in this repository or in an exported instance, and the planner who reads the architecture record before the next scheduling order.

## Read before upgrading

- **Lanes come from the machine and are shared by every clone on the host.** The first gate or lane acquisition on a host after this release writes `lane-capacity.json` into the per-user host registry with the lesser of eight and half the logical processors; later clones inherit that number even when their own derivation differs, and a request for more slots than the record refuses naming both numbers. The probe wrapper, session registration and structural host check read the record and fall back to their own derivation only while none exists. The record never expires. An invalid or unreadable record refuses every gate on the host with a message that does not yet name the record or the remedy; remove it while no gate runs and the next acquirer records it again (VER-001 F1, [D018](../../evidence/WO-222/decisions.md#wo-222-d018)).
- **Per-lane memory budgets replace the fixed quarter, and a small host can refuse.** A task's budget is the gate share, one half of physical memory by default, divided by the recorded lanes; the probe wrapper, agent-session registration and guard-tree registration use the budget of the registry they select. The structural `host` task refuses when that budget is below 1,509,638,144 bytes, the largest task peak RSS in the three baseline passing rows, naming both numbers: eight processors with 8 GiB, four lanes of 1 GiB, refuse, while sixteen processors with 24 GiB admit. `memory.gateShare` in `docs/control/budgets.json` is the lever; the `taskShare` and `hostLanes` keys no longer change any budget, the kit template omits them, and the starter refresh rewrites `docs/control/budgets.json` ([D003](../../evidence/WO-222/decisions.md#wo-222-d003), [D007](../../evidence/WO-222/decisions.md#wo-222-d007), [D008](../../evidence/WO-222/decisions.md#wo-222-d008)). The probe wrapper's budget falls with the lanes: 3,221,225,472 bytes on the operator's host instead of a quarter of physical memory. The same per-lane figure now bounds a registered agent session's bare process groups, a shell command, MCP server or browser tree outside a gate, where v0.85.0 allowed a quarter of physical memory; no kill was observed in this order, and a budget tied to the host share is boarded with a remedy-naming refusal (FINAL-001 F2 and F3, [D021](../../evidence/WO-222/decisions.md#wo-222-d021--final-review-pass-final-001-at-the-integrated-subject-the-cross-gate-overlap-lease-leads-three-boarded-follow-ups)).
- **An exclusive suite's spare lanes are open to other gates on the host.** The exclusive row holds a host lease of its reserved slots only, six of eight here, and the registry admits any other gate's request that fits the recorded capacity, so a second worktree's heavy task can run beside harness fixtures, process debt or worktree integration; the light-only rule holds inside one gate, and v0.85.0's exclusive lease held all four slots. Keeping the full lease and lending the spare lanes only to the gate's own light peers is boarded (FINAL-001 F1, [D021](../../evidence/WO-222/decisions.md#wo-222-d021--final-review-pass-final-001-at-the-integrated-subject-the-cross-gate-overlap-lease-leads-three-boarded-follow-ups)).
- **Mixed-version hosts wait longer.** A client from before this release asks for all four of its assumed lanes and waits while any other top-level lease exists; beside a new client's eight-lane complete run, an exported instance's document gate waited 1,554.557 seconds for a four-slot lease during this order's execution. Fair cross-gate admission is boarded as FUP-464d273fa299e979 ([D009](../../evidence/WO-222/decisions.md#wo-222-d009)); the architecture record proposes the queue and its mixed-version boundary.
- **Deadline declarations above four are legal.** `DOTLN_GATE_CONCURRENCY` may now reach the recorded capacity, and children read `DOTLN_GATE_CAPACITY` (1 to 8, 4 when absent) with the factor of two per slot unchanged; a runtime archived before this release refuses a declaration above four, so the v0.81.0 upgrade fixture runs its README commands with the declaration removed ([D008](../../evidence/WO-222/decisions.md#wo-222-d008)). On a host with three or more lanes the exclusive suites declare shared load with up to three concurrent tasks and a factor of six. More lanes raise every peer-derived deadline, so a hung task takes longer to be ended; the 900-second task deadlines and the wrapper's outer bound stay.
- **Light peers are classified from a frozen baseline.** `scripts/lib/gate-scheduling-baseline.json` carries each task's latest sample from the three before rows; a shared task under 60 seconds and 512 MiB there may run beside an exclusive suite. The launchpad seeds file qualifies on its latest sample, peaked above 512 MiB in two earlier samples, and ran beside harness fixtures at 594 to 630 MiB in each after run without failing; classifying on every sample is boarded (VER-001 F2, [D019](../../evidence/WO-222/decisions.md#wo-222-d019)). A task absent from the baseline, such as the new target-worktree files or a suite the before rows did not run, is heavy.
- **The three levers are retained on the combined series, not on each lever's own gain.** The exclusive suites' own durations did not fall (harness fixtures 289.445 to 305.818 seconds at the median, the other two with no peer in these runs), summed task duration rose 12.54%, and the target-worktree group span fell 9.24%; each lever reverts when a later pass's complete-run median rises above 2,538.373 seconds ([D014](../../evidence/WO-222/decisions.md#wo-222-d014), [D015](../../evidence/WO-222/decisions.md#wo-222-d015), [D016](../../evidence/WO-222/decisions.md#wo-222-d016)). The series compares three historical identities with one; it is not a same-source ablation.
- **Versions.** Application v0.86.0 is a minor release over v0.85.0, assigned at activation under the order's classification. Skeleton moves from 0.61.0 to 0.62.0 for the deadline contract; the console's skeleton pin and the lockfile follow; the harness host stays at 0.37.0. No command, flag, refusal or dependency is added, and the `npm test` spellings are unchanged.

## Substantive changes

**Lanes from the host** (`scripts/lib/host-resources.mjs`, `scripts/lib/host-lanes.mjs`, `scripts/test-runner.mjs`). `hostLaneCapacity()` derives the lesser of eight and half of `availableParallelism()`, at least one; `acquireHostLaneCapacity()` records it under the lane lock when no record exists and returns the recorded value; `recordedHostLaneCapacity()` reads it. `acquireHostLanes` refuses a request above the recorded capacity by name and writes `capacity` into each lease. `scheduleSuites` defaults its concurrency to the capacity, refuses more, and `runGateChecks` acquires the capacity before the structural phase and records `hostCapacity` and the scheduler label `light-overlap-v2` in the gate row; each task row carries `hostCapacity`, `slotCapacity` and `timeoutMs`.

**Per-lane memory budget** (`scripts/lib/host-resources.mjs`, `scripts/structural-checks.mjs`, `scripts/lib/bounded-command.mjs`, `scripts/lib/host-guard-state.mjs`). `memoryBudgets(repo, { capacity, physicalBytes })` sets `taskBytes` to the gate share divided by the capacity and ignores legacy `taskShare` and `hostLanes` keys; the probe wrapper, agent-session registration and guard-tree registration pass the capacity of the registry they select. `checkHost` compares the budget with `largestTaskPeakRss()` from the committed baseline and refuses below it, printing both numbers and the lane count.

**Light peers beside the exclusive suites** (`scripts/test-runner.mjs`). The three exclusive rows declare `overlap: 2`; an exclusive row reserves every lane but its overlap, and while it runs only tasks in `lightSuiteNames()` may take the spare lanes: shared, under 60 seconds and under 512 MiB on their latest baseline sample. A waiting exclusive row at the head of the queue drains heavy peers before lower-priority work starts. The exclusive row's declared peer concurrency is its overlap plus one, so its deadline factor is twice that. `groupLimit` bounds the launchpad files and the target-worktree files at two concurrent tasks each; `validateSuites` admits `loadSlots` up to eight and `overlap` from zero to two on exclusive rows only.

**Deadlines** (`packages/skeleton/src/gate-deadlines.mjs`, `scripts/lib/suite-evidence.mjs`, `scripts/test-target-publish.mjs`, `scripts/test-launchpad-planning.mjs`). `gateLoad` accepts a concurrency up to `DOTLN_GATE_CAPACITY` (1 to 8, 4 when absent) and keeps the factor of two per slot and the isolated rule; `suiteEnvironment` sets `DOTLN_GATE_CAPACITY` from the scheduler's host capacity. The target-publish case bounds derive their loaded limit through `deadlineLimit` from the same standalone baseline ([D013](../../evidence/WO-222/decisions.md#wo-222-d013)), and the archived v0.81.0 upgrade fixture removes the current declaration from its README commands ([D008](../../evidence/WO-222/decisions.md#wo-222-d008)).

**Target-worktree file lanes** (`scripts/test-target-worktree-start.mjs`, `scripts/test-target-worktree-publish.mjs`, `scripts/test-target-worktree-close.mjs`, `scripts/test-target-worktree-release.mjs`, `scripts/lib/target-worktree-fixture.mjs`, `scripts/fixtures/target-worktree-cases.json`). The 171,587-byte suite is split by its case groups into four files with their shared helpers, including the launchpad command parser both the start and publish files use ([D010](../../evidence/WO-222/decisions.md#wo-222-d010)), in the shared fixture; the base has 39 declarations registering 60 names, not the order's 38, and every name is kept ([D002](../../evidence/WO-222/decisions.md#wo-222-d002)). `expandSuiteTasks` turns the suite into `target-worktree:file:` rows named by each file, as it does launchpad, two at a time, each with a 900-second deadline; a registration-only fixture checks the 39 declarations and 60 names against the committed inventory; `scripts/test-target-worktree.mjs` remains as an import of the four files for direct invocation.

**The measurement instrument** (`scripts/measure-gates.mjs`). Schema 2 records three fresh complete runs with the host's lane capacity and physical bytes, each task's peak RSS, capacity, slot capacity, deadline and peers, and the summarized deadline samples; `measurementGateForRun` selects the canonical `npm test` review row inside the attempt's window instead of the package alias ([D013](../../evidence/WO-222/decisions.md#wo-222-d013)); `measurementGate` publishes the measured fields without machine-local diagnostics ([D006](../../evidence/WO-222/decisions.md#wo-222-d006)); `DOTLN_GATE_MEASURE_DEADLINES=1` keeps successful deadline samples in the gate row ([D005](../../evidence/WO-222/decisions.md#wo-222-d005)); `--check` validates schema 1 five-run and schema 2 three-run series, refusing a task that ended at or reached its deadline.

**Evidence editions and sources** (`packages/skeleton/src/feedback-audit.ts`, `scripts/lib/evidence-sources.mjs`, `docs/evidence/current.json`). The scheduling baseline joins the feedback source paths, the common evidence sources and the runner, host-guard and harness machinery sources; the feedback edition WO-222/001 records a live self-host episode on Codex `gpt-6.1-sol` at `max` with ten passing regressions and ten removal failures, the authority edition is re-minted as WO-222/001, and the harness bundle and manifest are regenerated ([D017](../../evidence/WO-222/decisions.md#wo-222-d017)).
