# The starter's commands page walks a person through every step, with the private terms list first

A person who clones the starter is now sent from its front page to `docs/OPERATOR.md`, the generated commands page that `node scripts/launchpad.mjs commands` prints before any install, and can set an instance up from that page alone. Its first step holds the private terms list's three commands after the clone recipe, so the list is registered before any session publishes. Before this change the page went from the harness check straight to the first planning pass, whose publish refuses while the list is absent, so a person who followed the page failed at their first publish. Each of the seven steps now opens with a paragraph written for a person: what the step does, what to look for and what to do when it fails. This is [WO-277](../../work-orders/WO-277-the-starters-commands-page-tells-a-person-every-step.md), planned as the patch `v1.0.1`; its release close refreshes the starter, which is how the page reaches an instance.

**What changed.** The page stays generated from the kit guide's marked blocks. The seven marker sentences in `docs/KIT.md` became one paragraph each, and the terms list's commands became a second marked block of the first step, so the page and the guide cannot drift. The generator, the step table and every check of the page are unchanged, and no package changes.

- The first planning pass's step says that `WO-001` is already the one entry of the starter's sequence and can run before the pass, and what to do when the pass's publish refuses for an absent list or on a line.
- The step that runs an order says what each of the three phrases does, names the two lines `worktree start` prints for a carried and for an absent list, and gives `resume: fix` for a failed verification or final review.
- The release step says to stop after the merge and keep this instance's bytes of each file both sides changed with `git checkout main -- <path>`, to keep a file this instance deleted with `git rm <path>`, and to restore `.claude/harness-manifest.json` from `main` when the merge stops on it, a route the page carries until WO-282 repairs the emit.
- The starter's front page seed and the guide's first paragraph both send a person to the page first, and the guide now says it is the reference the kit's roles and reviewers work from.
- One sentence of the guide is corrected to what the code does. Without a terms list the publish of a planning branch, of a kit update and of a target's change refuses, while an order's own publish goes on and prints that the files its branch changes were not screened ([D003](../../evidence/WO-277/decisions.md#wo-277-d003--what-the-page-says-of-an-absent-terms-list-is-what-each-publish-does-and-the-guides-sentence-beside-the-new-block-is-corrected-to-it)). The page gives that as the reason the list comes first; whether an order's publish should refuse as well is boarded for planning.

**One test line changed.** The seed front page's SHA-256 pin in `scripts/test-launchpad-export.mjs` moves to the new seed's hash, an expected value the seed's change requires; [D008](../../evidence/WO-277/decisions.md#wo-277-d008--the-front-page-seeds-migration-an-unedited-front-page-takes-the-new-one-a-front-page-that-is-its-owners-is-kept-and-what-the-releases-read-before-upgrading-says) records its cause and what the change means for a starter and for an instance. A regression case the executor added against the order's non-goal was withdrawn before handoff, and its text is kept for the order that next changes the page ([D009](../../evidence/WO-277/decisions.md#wo-277-d009--round-2-confirms-every-fix-and-admits-nothing-the-first-critics-three-points-are-accepted-and-the-case-added-under-d004-comes-out)).

**Also on this branch, outside the order's deliverables.** The roadmap's release table gains the `v1.0.0` row and `docs/control/release-history.json` records the table through `v1.0.0`, both written by the table's own command: `main` has failed one case of the sync suite since the planning commit, and this order's first gate met it ([D005](../../evidence/WO-277/decisions.md#wo-277-d005--step-3s-suite-failed-twice-before-it-passed-once-on-the-executors-own-order-of-work-once-on-a-failure-main-has-held-since-the-planning-commit-which-the-roadmap-tables-writer-repairs)).
