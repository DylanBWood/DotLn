# WO-173

When an executor handed work to a verifier, nothing required it to say which acceptance criteria it believed met and on what. Of 96 failed judgments read on 2026-09-28, 24 failed only on findings an existing check would have shown before handoff, and 13 on a gap the executor had already written in its own decisions. This pull request lands WO-173: the executor judges every criterion on one line before handing off, a met claim that names a gate must stand on that gate's passing row, and an unmet criterion is shown to the operator and the judge at the next dispatch, while a waiver or an amendment can still spare the cycle.

- **The handoff ledger.** `implementation-ready` and `repair-complete` read `docs/evidence/WO-NNN/handoff.md`, one line per declared criterion in the forms a verification report already uses (`**Criterion 3:** met …`, `unmet …`, `unmet, waived by <ordinal>`). An absent ledger, a missing criterion, two lines for one criterion and a line for a criterion the order does not declare are refused, and nothing is appended; each refusal names the identifiers and the accepted forms. An order whose criteria cannot be read records with one advisory, as before ([D002](../../evidence/WO-173/decisions.md#wo-173-d002--the-handoff-ledger-one-line-per-declared-criterion-read-at-both-executor-completions)).
- **A met claim stands on its gate.** A criterion recorded met whose text names `npm run test:docs` makes the completion run the document gate once, inline and last; a failure refuses the claim with the failing tasks. One naming `npm test` or `npm test -- --review` needs a complete passing row at the current code identity, and for the review form one whose suites cover the runner's current review selection, which now includes an order's untracked scripts. A criterion recorded unmet always records, and a handoff is never refused for a red gate. Gate storage the completion cannot read or write is one advisory ([D003](../../evidence/WO-173/decisions.md#wo-173-d003--a-met-criterion-that-names-a-gate-stands-on-that-gates-row), [D015](../../evidence/WO-173/decisions.md#wo-173-d015--repair-gate-storage-a-completion-cannot-read-or-write-never-refuses-the-handoff)).
- **Unmet criteria reach the next dispatch.** The completion event carries `unmetCriteria`; `resume status` lists them; the `verify` and `final-review` briefings list the ones the record has not already waived, with the waiver and amendment routes. The briefings also carry three sentences from the failures pass: a repair closes the class its finding names, a finding outside the declared criteria is boarded with its reproduction, and a recorded off-ramp whose capture hash matches is judged from the record and never put back to the operator ([D005](../../evidence/WO-173/decisions.md#wo-173-d005--three-briefing-sentences-the-ledger-sentence-and-the-unmet-disclosure), [D017](../../evidence/WO-173/decisions.md#wo-173-d017--filler-removed-from-the-briefing-text-this-order-adds)).
- **`npm test` does not repeat a gate that already passed at the same code.** With or without `--review`, it first looks for a complete passing row at the current code identity whose suites cover the current selection; when one exists it prints the row and exits 0 without starting a suite, and records nothing. `--again` (or `--fresh`) runs it. A changed identity, a failed row, a partial row and a plain row under `--review` never satisfy the lookup ([D004](../../evidence/WO-173/decisions.md#wo-173-d004--npm-test-reuses-a-covering-passing-row-at-the-same-code-identity---again-runs-it)).
