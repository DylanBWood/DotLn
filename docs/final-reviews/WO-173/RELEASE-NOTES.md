## Release overview

An executor's handoff now states what it knows. Before `implementation-ready` or `repair-complete` records, the executor judges every acceptance criterion on one line of `docs/evidence/WO-NNN/handoff.md`: met with its evidence, or unmet with the decision that says why. A criterion recorded met that names a gate must stand on that gate's passing row, and a criterion recorded unmet is shown in `resume status` and in the next `verify` and `final-review` briefings with the two routes that can spare a failed cycle, a waiver or an amendment. `npm test` no longer repeats a gate that already passed at the same code identity, and the resident's lock matrix gives each of its eight cells its own deadline. The release is for anyone who runs DotLn's lifecycle as executor, verifier or reviewer.

## Read before upgrading

Both executor completions now refuse a missing or malformed ledger: an absent `handoff.md`, a declared criterion with no line, two lines for one criterion, or a line for a criterion the order does not declare. They also refuse a met claim whose named gate has no passing row at the current code identity (`npm test`, `npm test -- --review`) or fails when run inline (`npm run test:docs`); the refusal names the command and the alternative of recording the criterion unmet with its reason. An unmet line always records, and a handoff is never refused for a red gate. Orders without a numbered acceptance-criteria list record as before, with one advisory. `npm test` and `npm test -- --review` now exit 0 without running when a complete passing row of a covering selection exists at the current code identity; pass `--again` (or `--fresh`) to run anyway. Known limitation: the code identity hashes tracked files only, so before the final review stages an order's new files, an edit to one does not stop reuse; run `npm test -- --again` after editing an untracked source file. The review selection now includes untracked files, so a script an order adds selects the machinery suites that declare it before it is staged. The completion event gains an optional `unmetCriteria` field and `resume status --json` an `unmetCriteria` key.

## Substantive changes

A new module, `scripts/lib/handoff-ledger.mjs`, reads the order's declared criteria and the ledger, checks the gates a met line names, and runs the document gate inline, last; `scripts/lib/gate-reuse.mjs` holds the passing-row lookup that both `npm test` and the completion use. Gate storage a completion cannot read or write, including a damaged live gate index, is reported as one advisory, and the completion records. The `verify` briefing now says a finding names its class and the rule a repair must hold and that a defect outside the declared criteria is boarded with its reproduction; `verify` and `final-review` say a recorded off-ramp whose capture hash matches is judged from the record; `fix` says a repair closes the class the finding names and adds a case the report did not quote; `next` and `fix` say how to write the ledger. The WO-143 lock matrix runs as eight subtests, one per cell, each with a 120 s deadline, so a cell slowed by another lane's load fails alone and by name.

## Progressive polish

The follow-up register advisory, `docs/planning/followups.md` and product 07 now say the final review disposes a listed row whose seam the change opened or whose condition occurred and leaves a row it only matched as it is. The completion advisory that looked up the document gate by a tree hash, which every report write changed, is removed. The role text's completion sentence says what the completion checks. The roadmap, README release line and work-order index record the release.
