## Release overview

For anyone cloning the starter or running an instance of the kit, this release makes an instance's first cycle meet the kit instead of its edges: a fresh clone is Claude-only unless it elects Codex or Copilot, and an existing instance keeps the hosts its own record shows without touching its configuration; the starter refresh adds the seeds a starter lacked and removes the one the kit retired; a `resume: release close` typed before the merge reached main waits for the close to record it instead of being retyped; Git 2.40 is the declared floor beside the Node range, so an old Git fails one check with one message instead of three steps with three; a sequence with no order is admitted; the continuation gate compares under the judged receipt's rule; and the siblings index is harmless in an instance. One verification judged the change and passed every criterion.

## Read before upgrading

After taking this release, regenerate the features inventory with `npm run meta` before the next document gate reads it, since its renderer changed. Render the features page with `npm run features -- render`, re-emit with `node scripts/harness.mjs emit` and start a new session, since an election now decides which host surfaces the emit writes and the host reads the emitted settings when a session starts.

Host surfaces follow the host rows. `features.host-codex` and `features.host-copilot` are off by default; an undeclared row is inferred on from the instance's own committed record, an attestation whose harness is `codex-cli` or `copilot-cli` in `docs/control/resume.jsonl` or an order segment under `docs/control/orders/`, or an observed version of that harness in `docs/discovery/environment.json`. An instance that used a host only in sessions its committed record never attested must elect the row in `dotln.config.json`, or its next emit and its next kit update remove that host's `.codex/` and `.agents/skills/` surfaces together with the directories that leaves empty; files of the instance's own under them stay. An election of `false` beside a record that shows the host is respected. `npm run features -- list` and the generated inventory print each host row's source, and `--json` adds the attestation counts.

`package.json` declares `engines.git >=2.40.0`. `node scripts/harness.mjs check`, `harness evidence` and every `npm test` selection refuse an older Git naming the floor and the version read; in a selection the `host` task runs first and nothing else runs. `node scripts/bootstrap.mjs` and the emit are unaffected. The gate's classification failure now reads `Generated source classification unavailable: git check-attr exited`, followed by git's exit code and its words, and a release close it stops records a blocker of the new class `host-runtime` with the floor judgment beside the message.

In the main checkout, update main first (`git pull --ff-only`) and then type `resume: release close`. A phrase typed before the pull is journaled as a pending release-close dispatch with the role resolved; the merged order's exact helper is admitted under it, fast-forwards main, dry run included, and records the dispatch through `npm run resume -- release-close --work-order WO-NNN`, which then keys every later admission. When main still selects an earlier closed order, the phrase records that order's dispatch and also stays pending; admission stays with the recorded order, so the merged order's helper goes to host permissions and its close records that dispatch after its fast-forward. The publishing close of the recorded order consumes the pending phrase, so a later helper needs a new phrase.

An instance may elect `features.auto-update-upstream`, its standing opt-out of the rule that no planning or entropy pass takes a newer starter release unless the operator asks in that session: `update --finish` and `update --publish` are then admitted under a journaled dispatch without `--operator-request`, and the session journal's admission row names the election instead of a capture. Without the election the refusal is unchanged. The hook reads the plan-first election through the lifecycle's reader, so a malformed value (`"on"`, `"true"`, `1`) now refuses an executor's write with the lifecycle's message, `DOTLN_PLAN_FIRST_REFUSED: the plan-first election cannot be read: …`, where it read as off before; correct the value as `npm run resume -- status` prints it.

The starter refresh adds every seed the export writes that the starter lacks, at the export's bytes and the lineage index rendered from the starter's own ledger, and never overwrites a present seed; it removes `docs/control/doc-ceilings.json` while its bytes are the kit's rendering and keeps a customized one, naming it in `keptSeeds`; its summary line names `seeds added:` and `seeds removed:`. The export's `UPSTREAM.md` lists exactly the seeds the export writes, and `closeout-scope.mjs` no longer names the ceilings file among the gate inputs. The seeded front page gains a link to the documentation map, so a starter whose README is still the kit's rendering has it rewritten once by the next refresh. The seeded first order changes its criterion 3 (the printed status recorded and any match fixed before filing), its checklist item 4 (an empty terms list refuses nothing; the check runs over the files the order writes) and its objective (the review ladder every order runs, no timebox); an instance's customized `WO-001` is not rewritten.

`limits.coldStartBytes.router` reads 21,220 in the kit's budgets template and in this repository, with dated acceptances recorded here for the router, verifier, reviewer, release-close and planner roots under the standing route; a fresh export starts with no cold-start breach. `buildPlanSubject` admits a sequence of 0 to 100 orders and its refusal reads `plan sequence must contain 0–100 orders`; `npm run plan -- check --timing` adds the check's step timings to its output. `node scripts/siblings.mjs index` and `index --check` exit 0 without a declaration, printing `no sibling declaration at docs/siblings/siblings.json; nothing to index`; a registry page left without its declaration still fails the check, naming both paths.

## Substantive changes

Hosts and elections: `scripts/lib/feature-registry.mjs` adds the `host-codex`, `host-copilot` and `auto-update-upstream` rows; `scripts/lib/features.mjs` infers an undeclared host row from the committed control log and the discovery record through a lazy getter, so the hot-path elections never scan the log, and prints each row's source and record in the inventory; `scripts/lib/harness.mjs` selects the profiles by host, refuses a profile for an unelected host by name and removes the directories a turned-off host leaves empty; `scripts/harness-context.mjs` judges the Codex and Copilot skills root only where it is installed; `scripts/launchpad.mjs` predicts an export's bundle with every other host off and an update's with the destination's own host rows, removes the emptied host directories a kit update leaves, and admits an update under the election; `packages/skeleton/src/plan-first-boundary.ts` reads the election through the lifecycle's reader where that reader exists.

The release-close phrase: `packages/skeleton/src/harness-host.ts` journals a pending release-close dispatch in main, keeps the phrase pending beside a recorded dispatch, admits the exact helper under a pending phrase while no dispatch is recorded, and tells a hidden spelling of the dispatched order's helper both exact spellings; `scripts/lib/dispatch-bound.mjs` reads, records and consumes the pending row from the session's own state without a built runtime; `scripts/release.mjs` fast-forwards main even in a dry run when a pending dispatch is owed, records the dispatch after it, stops on a refused recording, consumes the phrase when the publishing close completes, derives the election notice for a changed registry or reader, and names the Git floor judgment beside a `host-runtime` blocker; `scripts/resume.mjs` and `scripts/worktree.mjs` say to update main first.

The Git floor: `scripts/lib/node-engines.mjs` reads `engines.git`, runs one `git --version` through the shared Git library and judges the version read past a vendor suffix; `scripts/structural-checks.mjs`, `scripts/harness.mjs` and `scripts/test-runner.mjs` judge it beside Node, with the host task leading; `packages/skeleton/src/gate-evidence.mjs` names git's exit code and stderr and the `host-runtime` cause; `scripts/lib/release-steps.mjs` adds the class.

Seeds and the refresh: `scripts/lib/starter-seeds.mjs` holds the export's seed list, the export's configuration bytes, the template seed paths, the retired seeds with their renderings and the plan of additions, removals and kept seeds; `scripts/lib/starter-refresh.mjs` writes the additions after judging every destination, removes the retired seed, names a refresh that adds the configuration after it, and keeps a seed-only change from reading as current; `scripts/kit/first-order.template.md`, `scripts/kit/README.client.md` and the seeded map writer carry the corrections and links; `scripts/kit/budgets.template.json` and `docs/control/budgets.json` carry the ceiling and acceptances; `scripts/lib/closeout-scope.mjs` drops the ceilings path.

Planning and documents: `scripts/lib/plan-subject.mjs` admits the empty sequence; `scripts/lib/plan-direct.mjs` names it in the refuter's prompt; `scripts/lib/plan-receipts.mjs` builds the compared subject under the judged receipt's rule and measures its steps behind `--timing`; `scripts/refute-plan.mjs` takes the flag; `scripts/lib/document-kinds.mjs` reads a glob-matched entry-point file only where the working tree holds it; `scripts/siblings.mjs` exits 0 without a declaration.
