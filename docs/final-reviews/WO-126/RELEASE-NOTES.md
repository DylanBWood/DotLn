## Release overview

DotLn `v0.17.0` makes the repository's own lifecycle machinery cost what its evidence earns. Before this release every gate ran on a cadence unrelated to what it prevented: a 37-step serial test chain ran at every turn end and again at the tag; a session owed a byte read of every file changed since its starting revision, so WO-042's reviewer owed 135 files and 5,305,410 bytes after it had already reviewed the diff; three Stop hooks refused to end a turn until the whole suite and a lifecycle transition were recorded; the build deleted the runtime the installed hooks import while it ran; and closeout was a hand-written script. The operator's 2026-09-09 dispatch enumerated eleven such failures after the `v0.16.0` close and put one order at the front of the line. This release answers them with three rules and a mechanism for each. Hard enforcement lives only in the four lifecycle transition commands and the pre-effect guards, while Stop advises. A gate runs once per exact Git tree and its evidence is reused by hash across sessions and at release close. Growth needs a decision: a meter reads the control log, the evidence records, the manifest and the artifact sizes every order, prints the previous-order delta into every PR body and the status line, and fails the fast gate on a budget breach that carries no dated operator acceptance.

The same release preserves the operator's same-day ideation as labeled candidates (context continuity across compaction, recurring review of implementation alternatives, a Tinkerer / Scientist support with an activation-rate modifier, historical comparison after a forced alternative, retained unchosen alternatives, emoji shorthand, browser and desktop hosts for a resident 3D view, and the full eight-system-traps lens) and adds a retained public follow-up register that gives planning entry a bounded feed of every formal candidate and decision instead of a whole-map read.

## Read before upgrading

- **`npm test` is the fast gate, not the whole suite.** It runs the build, the four package suites and the format, harness, index, publication, cold-start budget and meter checks through a bounded concurrent runner with a 120-second budget. `npm run test:full` runs every command the previous 37-step chain ran, and it is the gate the four lifecycle transitions and release close require. `npm run test:docs` is the document-only gate for planning and ideation passes. `--fresh` forces cold execution, `--only` selects one named suite and `--serial` disables overlap.
- **Evidence is keyed by the exact Git tree and reused.** Every check row carries the tree hash and its duration; a required check is satisfied by any recorded green run at the current tree from any session or role; executed suite successes whose reviewed inputs are unchanged compose into later gates across document-only edits, each reused row naming its original tree, time and duration. Recording a lifecycle transition changes the tree, so the transition commands verify evidence before they append. Release close reuses the reviewed `npm run test:full` evidence for an identical tree and otherwise runs it; legacy tags keep their four-command manifest contract, and new manifests record tree hash and duration.
- **Stop only advises.** The three Stop-time units (application evidence, output review, complete scope) are advisory at version 2: the single Stop hook prints one line naming the unmet obligation, releases the writer reservation and never blocks a turn. The same conditions are enforced by `implementation-ready`, `repair-complete`, `verification-result` and `final-review-result`, which refuse without full-gate evidence at the current tree, authored-output reads or checks, and no remaining work.
- **A read obligation covers what the session wrote, not what it inherited.** The observer snapshots the tree's changed paths before and after each Edit, Write, Bash and NotebookEdit call and accumulates only paths whose bytes changed. Paths carrying the `dotln-generated` attribute and files above the 64 KB read cap owe a validation check instead of a byte read, satisfied by their declared suite or by the full gate at the current tree. Codex sessions use the explicit `harness begin`, `harness observe` and `harness delivered` adapter and claim no automatic hooks.
- **The permissions envelope classifies invocations instead of matching substrings, and the `v0.16.0` regexes are its floor.** A heredoc, search pattern, commit message or quoted example naming a denied command is data; the actual invocation is classified through supported wrappers, shells, pipelines, command groups, package execution wrappers, assignments and inline Git configuration, with a literal denial floor over every opaque program's arguments and input and over the effect programs' own command-valued operands. Dynamic program or subcommand operands, `for`, `case` and `function` syntax, command substitution, here-strings, process substitution, redirected groups and unknown wrapper options refuse with a named classification reason instead of the old runtime-unavailable message. Two limits are carried forward from VER-007: some supported `git commit -am` and `git grep` spellings are refused conservatively, and `sed` and `less` remain data programs, so a command-valued operand such as GNU sed's `e` command is admitted although the old regex refused it; it does not execute on the observed macOS host.
- **Attribution refusal covers session trailers and session URLs.** The generated Claude settings carry an attribution block that disables automatic commit and PR attribution; `worktree publish` refuses a PR title or body carrying an AI coauthor, a generated-with footer, any agent session trailer or a session URL; `harness check` detects a missing settings block.
- **Attestation follows a version line.** The discovery record carries an observed major.minor line per harness with its newest observed patch. `resume` accepts the declared effort for any patch on an observed line and records the actual version; a version off the line records `unknown` and names the line; `npm run discover -- harness` appends an observed row from a bounded probe; session entry warns once when the running CLI leaves the line. WO-042's `unknown` attestation is unchanged.
- **The build no longer deletes the runtime the hooks import.** `npm run build` compiles into a staging directory and replaces each complete `dist` file atomically; installed hooks import an immutable pinned snapshot under `.runtime/harness/` that the build preserves. A fresh checkout builds once to rehydrate the snapshot. Python is not a prerequisite.
- **Closeout owns its material.** `docs/control/local/` is read and written by scripts: `harness/**` is disposable session state, everything else is retained, and main's release-influence guard permits the whole lane. `release close` reconciles the subject's ignored intake into main before teardown with byte-verified copies and `.from-WO-NNN` collision suffixes; `--dry-run` prints the plan without writing. The release-close skill forbids closeout scripts.
- **Decisions move out of the ledger.** Per-order decisions and same-day corrections live in `docs/evidence/WO-NNN/decisions.md` with dispatch source, evidence, rejected alternatives and reopening condition; `npm run meta` generates `docs/lineage/decisions-index.md` over them and lists reopen candidates. The ledger is for operator ideation and planning synthesis only; no lifecycle loadout appends to it; an order filed before 2026-09-09 whose acceptance text names a ledger entry discharges it with its decisions file, and the work-order index marks the substitution. The hand-written floor sentence now preserves decisions with their sources and reopening conditions rather than settled decisions.
- **Planning reads a sequence, not a history.** The marked sequence moved to `docs/planning/sequence.md` under an 8 KB budget, and rationale older than the two newest revisions moved byte-identical to `docs/planning/archive/`. `npm run plan -- start` opens the planning branch from clean main and returns the first page of the follow-up register. `planning: refute` and `planning: refute full` load the direct refuter skill, whose two commands print the canonical prompt and file the immutable receipt. Every work order carries a `Cost:` header, the 123 legacy orders with the exact unavailable declaration; the refutation subject hashes that line and a bounded, subject-hashed cost table, and holds an order whose cost is missing or adds process without a stated removal or dated acceptance.
- **The four prose-only feedback units are kind `prose` at version 2 and emit no residue.** The `CLAUDE.md` residue block is one line naming the manifest, and the file is smaller than at `v0.16.0`. Version-1 definitions are retained for replay. The anti-oscillation unit states the operator's rule for applying a correction: identify the category the operator is pointing at and stay inside it, neither widening nor shrinking it, with the worked example that hashes belong to a correction about opaque identifiers and hostnames do not.
- **The feedback edition and the actor board move to WO-126 revision 002 under compiler `0.9.0`.** The console distinguishes advice from prevention and no longer counts a prose or advisory unit as a prevented incident.

## Substantive changes

- **Feedback compiler.** Units carry `mechanism.version` 1 or 2 and an optional `mechanism.kind: prose`; a prose unit is advisory, needs no required evidence, is carried by the role skills and never by a hook, and is skipped by evaluation. Version-2 output review accepts an empty output set, and version-2 application evidence accepts any green attempt at the subject. The attribution predicate matches AI coauthors, generated-with footers, any agent session trailer, a `Session-URL` trailer and Claude or OpenAI session links. Harness profiles declare a tool-effect inventory and a runtime snapshot path; the lowered bundle imports its hooks from that snapshot, carries every Stop unit in one finalizer, adds a pre-tool write observer, installs the attribution settings block, and reduces the instruction residue to one line.
- **Harness host.** A rewritten command classifier tokenizes with quoting and expansion provenance, follows supported wrappers, shells, `eval`, pipelines, groups and package execution wrappers, screens assignment and inline Git configuration values, applies the literal denial floor to opaque programs and to effect programs' command-valued operands after removing only proven message and search data, classifies GitHub API bodies and write verbs, folds executable names on case-insensitive hosts, and reports every refusal as a classification reason. The tool-effect inventory refuses unclassified or spawn-class tools. Session records publish atomically; a refused hook outcome journals a bounded reason class and a digest of the tool-use identity so the meter counts one refusal per tool use; hook process timings and authorship-snapshot costs are journaled; the session hook observes the running harness version through the explicit input, the running executable, a verified ancestor's executable mapping or PATH and warns once off the observed line. The Stop finalizer advises and releases the writer; the transition commands require the full gate, diff check, authored-output reads or checks and no remaining work at the current tree.
- **Gate runner and evidence.** One runner owns every command of the previous chain with a build barrier, a CPU-derived concurrency cap, serialization groups, exclusive hook-heavy suites, generated-file preflights that stop expensive fixtures, split-candidate naming above 30 seconds, negative-fixture lines printed under their suite, live progress, and timeouts recorded as executed failures with the suite name and elapsed time. Check rows carry tree hash and duration in a bounded hot cache with tree-addressed archives, passing stdout omitted and failing output kept in addressed logs, including failed release cases. Executed suite successes are content-addressed by reviewed inputs (every non-document candidate file, the suite's declared documents, installed dependencies, built output, toolchain identities, a projected environment without proxy variables, and Git context) and compose into later gates with their original identity; the aggregate still requires complete coverage at the exact current tree. Forty release scenarios run as named cases from one sealed fixture template, and gate children keep the first occurrence of each exact PATH entry.
- **Lifecycle and closeout.** `resume` records evidence on every completion transition, accepts effort by version line, warns off the line and prints one process-health line in status. `release prepare` writes the meter table into the PR body; `release close` reuses full-gate evidence for an identical tree, records tree hash and duration in the manifest, previews with `--dry-run`, and reconciles intake through `worktree finish`, which also records the subject's gate checks into main. `worktree publish` refuses attribution in the title or body and prints the last five merged subjects with their lengths beside the proposed title. `npm run discover -- harness` appends observed version rows. `npm run harness begin`, `observe` and `delivered` give Codex sessions an explicit authorship and delivery adapter.
- **Meter and budgets.** `npm run meta` prints, for the last five closed orders and the active one, phase durations and attempts, gate seconds, read-obligation counts and bytes, observed tokens and cost beside declared prompt tokens, per-role cold-start bytes, unit, hook and support counts, artifact sizes, PR body bytes, operator corrections, authorship and hook costs, and one row per systems trap with previous-order deltas; a trap that worsens over three consecutive orders and a decision whose metric condition is met become reopen candidates. `docs/control/budgets.json` holds the operator's ceilings with token, dollar and PR-body caps left unset by direction; the cold-start check compares each installed floor plus skill to the previous edition and its budget; the first observation is the immutable baseline.
- **Planning.** The sequence file, the planning archive, `plan start`, the paged follow-up register with sourced dispositions and a checked link from local executor deferrals, the direct refuter phrase with pass and full scopes, carried verdicts by order and receipt hash, dispatch-to-file timing under a 120-second pass budget, the `Cost:` header on every order, and the subject-hashed cost table with the missing-cost and unbalanced-cost holds.
- **Documentation.** Products 02, 03, 04, 05, 07 and 08, the playbook, the root and docs readmes, the refutation receipts readme, the capability table, the work-order template and the publication index carry the write-backs; the unsourced no-telemetry sentences are replaced by the recorded-per-dispatch rule; the ledger gains two ideation sections and loses nothing.
