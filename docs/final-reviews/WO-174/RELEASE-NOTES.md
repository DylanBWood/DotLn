## Release overview

A green `npm test` row now stands for the documents its product cases read and the scripts its review selection runs. The product gate is reused by a code identity that leaves out documentation and control records, so a documentation edit could leave a stale green row behind a case that now fails. Product package cases that read those files now run in the document gate, which every handoff runs fresh, and a read guard fails any other case that reads them. `npm test -- --review` also selects every machinery suite whose entry file imports or names a changed script. This release is for anyone who relies on a reused or publication-bound gate row. It changes the test runner and test tags only; no product runtime behavior changes.

## Read before upgrading

No migration is needed. The gate's code identity, its reuse rule and selection by declared sources are unchanged. A product package case that reads a tracked path the identity excludes (under `docs/`, `.claude/` or `.agents/`, a root Markdown file, or a file marked generated or documentation) now fails its task, and the output names the case and the path. Tag such a case `[document]`: it then runs in `npm run test:docs`. A machinery suite that gains a direct import or a literal first-party script path must declare it, or list it as an exclusion with a written reason, or the runner fixtures fail. Changing `scripts/harness.mjs` now also selects the `harness-fixtures` and `process-debt` suites under `--review`. In the recorded measurement that adds about 500 s of suite time to that review. The document gate took 36 s after the change, against 16 s before.

## Substantive changes

The kernel, compiler, console and skeleton product tasks run under a read observer: a preload that records, per test case, the tracked files read through `node:fs` (the sync, promise and callback forms of `readFile`, `open` and `readdir`). It follows Node children that inherit its options, including a child whose reduced environment keeps them. The task fails when a case outside the `[document]` tag reads an excluded path. The guard observes the run the gate already makes and adds no second run. Forty-three existing cases that read such paths now carry the tag and run in the document gate: 2 in kernel, 22 in skeleton and 19 in console. Kernel gains a `kernel-docs` task. Compiler cases read no excluded path, so compiler gains no document task. No case's assertions changed.

A runner fixture checks each machinery suite's declared sources against its entry file, its direct relative imports and the first-party scripts it names by literal path. An uncovered path fails and names the suite and the path. Seventy-three missing inputs were declared. One of them is `scripts/harness.mjs` for `harness-fixtures`: REVIEW-004's `evidence --wait` exit-code mutant used to pass `--review`, and now that review selects the suite and its case fails the mutant. Four shared helpers are excluded with written reasons. Transitive imports and paths built at run time are outside the check, and its output says so.

## Progressive polish

The console test fixtures, and the skeleton's historical receipt tools, load inside the cases that use them. Importing a product test file therefore reads no excluded input. The console fixture generator reads the manifest when it runs, not at import. It also validates a newly pinned draft before writing it. Two new `[document]` regressions cover the generator's imports and that draft validation. The execution guide's Discipline section states the guard, the document routing and the closure check in two sentences.
