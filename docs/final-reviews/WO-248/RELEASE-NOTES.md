## Release overview

The process-meter block at the bottom of every pull-request body is now one table a reviewer can read without a legend: the order under review alone, a row per dispatch role, eight columns (dispatch, wall clock, tokens, USD, commands, steps, bound stops, bound acceptances), one value per cell, `unknown` written out where nothing was observed, and durations as hours and minutes. The comparison with the previous order is one sentence per metric below the table that names the order it compares with, for example `Against WO-250, the previous closed order: wall clock 4 h 18 min less.` The six-order Work table, the unlabelled per-cell deltas, the blank cells, the `/ 768` declared-prompt-token cell and the omission footer leave the body; `npm run meta` keeps every figure and labelled delta in its terminal text for the planner. This patch is for every instance that stores pull-request bodies through `release prepare`; no command, event or phrase changes.

## Read before upgrading

- The stored body's meter block has a new shape. `release prepare` and the regenerated body replace an existing block for the order they prepare; a body stored while an order was open keeps the old block until that order's next `release prepare`, and closed orders' bodies are records that are not rewritten. A consumer that pinned the old `| Work |` or `| Dispatch | Wall (Δ) |` headers, the `(Δ …)` cell form, the `/ 768` cell or the `unavailable observations omitted` footer updates its pin to the eight-column header `| Dispatch | Wall clock | Tokens | USD | Commands | Steps | Bound stops | Bound acceptances |`, cells of one figure or `unknown`, and the `Against WO-NNN, the previous closed order:` sentences.
- `renderMetaTable(meta, { workOrderId })` now takes the subject order; a call without it renders the header and no rows. Both kit callers pass their order. An instance script that calls the renderer directly passes the order it renders.
- The body compares only with the latest closed order before the subject in the collector's selection (the five most recently closed orders and the open ones). A subject outside that selection renders no rows and no comparison; the collector itself is unchanged.
- Every body carries a row for each of the seven dispatch roles, so a role with no observation reads `unknown` in all five value cells; the verifier boarded rendering only dispatched roles as `FUP-225e0993974f3f4b` (WO-248-D004).
- Component versions: none change. No external dependency changes.

## Substantive changes

**The renderer.** `scripts/lib/meta.mjs` `renderMetaTable(meta, { workOrderId })` renders the subject order's dispatches as one eight-column table, one value or `unknown` per cell and durations through `formatDuration`, then one sentence per metric whose figure is known for both the subject and the latest closed order before it, in that metric's unit, with `less`, `fewer` or `more` by sign and `unchanged (… difference)` at zero; it never compares with an open order and writes no sentence without a closed predecessor. `renderMeta` prints that block for the latest open order and keeps every metric section and labelled delta unchanged.

**The callers.** `scripts/release.mjs` passes the order's id from `release prepare` and from `regeneratedPullRequestBody`; `withMeterBlockLast` and the stored-body shape rule are unchanged, so an old block is replaced and the new one stays last.

**The documents.** Product 07 §Discipline's process-budget item states the block's shape and the comparison's reference; product 08 §PRs and commits now describes the same block in place of the blank-cell and omission-count sentence.

**Tests.** `scripts/test-process-debt.mjs` adds the subject-meter case (exact header, one row per subject dispatch and none of another order, the verifier row of `unknown`, observed zeroes, every duration `N h M min`, no Work table, delta, declared-prompt or omission text, the seven comparison sentences against the named closed predecessor, no sentence with no closed predecessor or an unknown operand, a closed subject keeping its rows and an absent subject borrowing none) and moves the operator-directions assertions to the terminal text; `scripts/test-release.sh` `meter_shape` adds a second open order and checks the generated body's header, cells and subject isolation; `scripts/test-runner.mjs` declares `scripts/lib/github-body.mjs` as a `process-debt` machinery source.
