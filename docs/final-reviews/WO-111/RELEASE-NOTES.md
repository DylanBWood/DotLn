## Release overview

This release records DotLn's first unattended live work. With the operator marked away, the offline resident discovered six seeded 5S imperfections in a scratch repository, derived three bounded orders from them, and advanced its progressive curve probe → widen → peak only after a live Codex worker made each change in an isolated worktree and a fresh-transport verifier passed it. A second window repeated the loop and then showed return: the human `back` edge arrived with a fourth candidate eligible and budget left, and the retained log replayed with and without that edge shows the returned resident cancels the pending dispatch while the no-return control admits it. The intended audience is anyone deciding what the resident can be trusted to do while nobody is watching, and anyone planning the owner-repository portfolio or the full absence curve that come next.

## Read before upgrading

No operator action is required, and no runtime source, generated configuration, dependency or component version changes; the release is evidence, write-backs and one test-fixture registration. One thing to know before running live Codex workers yourself: the worker launch inherits the Codex home, so each launch left a `trust_level = "trusted"` entry for its scratch target in the user-level Codex configuration. The operator accepted that disclosed deviation for this synthetic proof and kept its prevention in the independent runtime follow-up `FUP-3c34a8ffbf61376f` ([D020](../../evidence/WO-111/decisions.md#wo-111-d020)); the receipts still record the clause as unmet, and no general containment is claimed. Until that follow-up lands, a live Codex worker proof will add such entries, and removing existing ones is a separate operator decision. The two windows lasted about 11 and 9 minutes, not an hour; no episode was in flight at either return; and no net-value or optimal-absence figure is measured.

## Substantive changes

**The live proof.** `docs/evidence/WO-111/` holds the seed generator (a fresh scratch target from WO-119's public six-candidate fixture and a separate control launchpad with one reviewed portfolio, no Git remotes), the callers that bind the existing resident, portfolio, source-change and verification hosts to two Codex CLI transports and run the WO-099 mission check beside them, and the collectors. Two receipt editions per window are retained: the originals the first verification judged, and the corrected v2 editions rebuilt offline from the retained event logs after that verification, with per-episode launch claims (effective identity unknown), replay-computed budgets, the no-return cancellation control, the named mission subject and hold scope, the snapshot coverage, the caller's abort and the disclosed configuration change. `node docs/evidence/WO-111/repair-receipts.mjs check` reproduces both v2 editions byte for byte from the ignored stores and asserts the control.

**The Blackjack +3 correction.** The operator's clarification during the order rewrites the presence-curve interpretation in README, products 03, 05 and 06, ADR-0007's dated amendment, the inspirations row and a dated ledger synthesis: the side bet's losing streak maps to elapsed operator absence only, never to an agent's success or failure; the payoff curve rises to a peak and then has a still-useful descending half of progressively smaller work before a smallest-chunk reset; every minute value and work class is illustrative; and the curve belongs to the future automatic selection of further work orders, not to the continuation of an already-dispatched order. WO-111's immediate peak-to-probe reset is a partial trace of that shape. The [full-curve experiment](../../planning/full-absence-curve-experiment-2026-09-24.md) is filed as a planning candidate with a falsifiable comparison and no timings.

**The replan checkpoint.** R2 is answered in the planning map and the critical-path plan: the audit's four-to-twelve-hour implementation spans and this order's windows are different measures with no comparable token or dollar baseline; skeleton source grew from 46 to 102 files recursively (42 to 93 top-level) with no package split selected from count alone; the owner-repository portfolio still needs reviewed target selection and grants; starter export need not wait for the already-merged WO-100; no deferred family is waived.
