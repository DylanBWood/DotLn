# A background worker's activity no longer looks like the operator coming back

DotLn's resident had no way to tell who was acting. Its first draft would have stopped its own work on its worker's first tool call, and the revised draft would have ended `away` on the first tool call of a worker the operator launched before leaving — because it read the launch path as evidence that a person had returned. This change replaces that with an observation carrying its origin. `OperatorPresenceObserved { signal, origin, at, stamp? }` separates three things that were previously one: human presence, actor liveness and task progress. Tool calls, tool results and stops from any session, whichever process launched it, are actor liveness and never presence. Only an explicit `away`/`back` command, or a prompt established as a person's in an unstamped session, moves presence at all.

Origin is a pure function of the hook event kind and the resident's own episode stamp: `classifyPresenceSignal(signal, stamp)` takes nothing else, and the module reads no launch path, no process table and no input device. That is structural rather than tested-for, and a fixture pins it anyway by replaying every event, interaction and stamp combination under three different launch paths and asserting identical decisions. Ingress is equally unwilling to be told: `decodePresenceObservation` recomputes the classification and refuses any observation whose recorded origin disagrees, so a hand-written or replayed event cannot assert `human`.

The rule fails toward `actor`, and in today's installed harnesses that matters more than the human path does. WO-044 observed that Claude's prompt hook input carries no typed-versus-scripted discriminator and that Codex fires no prompt hook at all, so the generated heartbeats write `interaction: "unknown"` and none of them is ever human. In practice, explicit `away` and `back` are the only human signals this release ships; the human-interaction path exists for a future adapter that can actually establish it, and a changed version label will not be accepted as that evidence.

Liveness and presence now run on separate clocks that cannot be confused for each other. An actor that goes silent beyond its budget is marked `stalled` in `actors[…].status` with the deadline it missed, and nothing about that touches `present`, ends a phase or cancels work; a late heartbeat cannot erase a deadline crossed before it arrived, and an observed or lost episode retires its actor so late traffic cannot revive it. The optional policy `humanIdleMs` derives absence from the last human observation and is independent of `decay.idleMs`, which still expires phase allocation; omitting it preserves explicit-only presence exactly as before. On return the resident still cancels only what the policy marks discretionary, and an explicitly requested foreground task keeps its own authority and runs to completion.

Read before merging. Presence here is observation, not authentication: a process that can write the resident's store can assert an origin the classifier accepts for that store. Heartbeat ingress is off unless `DOTLN_RESIDENT_STORE` is explicitly bound, and a failed observation advises on stderr without ever changing a permission decision; resident-launched children additionally receive `DOTLN_RESIDENT_EPISODE_ID`, and no other inherited environment variable crosses into a resident script. Neither prompt content nor tool arguments enter the log — only the event kind, the time and a session or episode identifier. A stall means silence beyond a declared budget, not a dead process, and the 30 s default is a configuration value with no measured basis yet. The four new hooks fire on `PreToolUse`, `PostToolUse`, `UserPromptSubmit` and `Stop`, never on `SessionStart`; the reduced target-worktree bundle keeps only `PreToolUse`.
