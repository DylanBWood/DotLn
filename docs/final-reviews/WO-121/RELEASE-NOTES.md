## Release overview

DotLn's resident can now tell who is acting. Human presence, actor liveness and task progress are three distinct observations instead of one undifferentiated signal, so a background worker's tool calls — from any session, whichever process launched it — no longer look like the operator coming back. Before this release the presence design read the launch path as evidence that a person had returned, which meant an operator-launched worker that kept running after `away` could end the away phase and cancel the resident's own discretionary work. That is now impossible by construction: origin is a pure function of the hook event kind and the resident's episode stamp, and nothing in the path reads a launch path, a process table or an input device.

## Read before upgrading

No migration and no dependency change. Presence here is observation, not authentication: a process able to write the resident's store can assert an origin the classifier accepts for that store. Heartbeat ingress stays off unless `DOTLN_RESIDENT_STORE` is explicitly bound; a failed observation advises on stderr and never changes a permission decision; resident-launched children also receive `DOTLN_RESIDENT_EPISODE_ID`, and no other inherited environment variable reaches a resident script. Only the event kind, the time and a session or episode identifier are recorded — never prompt content or tool arguments. In every currently installed harness profile, no hook heartbeat can be human: Claude's prompt input carries no typed-versus-scripted discriminator and Codex fires no prompt hook, so explicit `away` and `back` remain the only human signals in practice, and the rule deliberately fails toward `actor`. A stall means silence beyond a declared budget rather than a dead process, and the 30 s default is a configuration value with no measured basis yet. The four generated hooks fire on `PreToolUse`, `PostToolUse`, `UserPromptSubmit` and `Stop`, never on `SessionStart`; the reduced target-worktree bundle keeps only `PreToolUse`.

## Substantive changes

`OperatorPresenceObserved { signal, origin, at, stamp? }` joins the resident's event set, and the fold gains three independent pieces of state: the last human observation, a per-actor heartbeat record with status and missed deadline, and per-task progress. Actor heartbeats feed liveness and stall detection only and can never move `present`, end a phase or cancel work. A late heartbeat cannot erase a deadline crossed before it arrived, and an observed or lost episode retires its actor so late traffic cannot revive it. The optional compiled policy field `humanIdleMs` derives absence from the last human observation and is independent of `decay.idleMs`, which still expires phase allocation; omitting it preserves explicit-only presence. On return the resident cancels only phases the policy marks discretionary, and an explicitly requested foreground task keeps its own authority and completes. Ingress recomputes the classification and refuses any observation whose recorded origin disagrees, so a replayed or hand-written event cannot assert `human`. An in-flight resident samples at the next human or actor deadline instead of on every poll.

## Progressive polish

Fixtures replay every event, interaction and stamp combination under three launch paths and assert identical decisions; a negative stream runs all four events stamped and the three activity events unstamped after an explicit `away` and asserts no phase change, no generation change and no cancellation; the actually emitted hook files are executed as processes and asserted to write exactly nine reduced observations with no prompt or tool bytes in the log. Replay is proven free of ambient time by throwing from `Date.now`. A release-fixture race found by verification was repaired: disposable fixture repositories now disable automatic Git maintenance before they receive data and every local clone opts out too, removing a race in which a background repack could delete objects a clone was linking. Git Trace2 observed that overlap directly; no run at the previous release established when the race began, so this release claims the fix and not a date of origin. Clone failures now print their captured diagnostic instead of being silently suppressed.

## Evidence and compatibility

Prepared application v0.27.0 under the declared minor classification, with compiler 0.13.0 and skeleton 0.23.0; kernel and console are unchanged, and the lockfile moves only those two first-party workspace versions. The order originally staged v0.26.0 with skeleton 0.22.0; WO-119 published both labels during this order's verification, so final review retimed the unpublished release under the same classification and recorded the correction rather than rewriting the original decision. Independent verification ran twice: [VER-001](../../verifications/WO-121/VER-001.md) failed the order because `npm test` was not green on a pre-existing release-fixture race and root-caused it; [VER-002](../../verifications/WO-121/VER-002.md) reproduced the repair's discharge in two environments and passed all six criteria with no finding. Final review ([FINAL-001](FINAL-001.md)) integrated the moved `main`, re-established criteria 1 through 4 on the merged tree, regenerated the harness bundle and the evidence editions the merge invalidated, and recorded its own product gate: `npm test -- --review`, 28 suites, 0 failed, 591.34 s, 72 fresh tasks, exit 0. Known limits: presence is observed rather than authenticated, no installed harness profile can yet supply a human-origin heartbeat, the actor heartbeat budget has no measured basis, and the native script fixture needs an outside-sandbox runner.
