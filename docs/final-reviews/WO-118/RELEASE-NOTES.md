## Release overview

Application v0.80.0 shows the resident-owned loop running from an exported starter, the product exit of DotLn's critical path, and ships the three runtime repairs that run needed. In one witnessed scratch run, the resident of a fresh starter instance took a filed intent through all fourteen phases to a resolved pull request while presence was away. It replaced a native writer killed mid-episode without a second commit, resumed the same admitted intent after the resident itself was restarted, and rejected a planted wrong review suggestion with evidence. The instance's own console showed the work live, and the audit view reproduces it afterwards. It serves the operator who will run the loop in their own instance next (WO-083) and the maintainer who needs a dead actor to cost a retry rather than the whole request.

The visible changes:
- A source writer that dies while its resident survives is replaced under the same command and episode, within the source host's two-attempt bound, instead of ending the request refused.
- A starter export carries the compiled console: `node packages/console/dist/src/cli.js live --store .runtime/resident` opens the live view in an instance without building.
- Live status shows resident-owned work: each running continuation step as a logical `vertical-host` actor and live episode, and each intent's decision hold as `intent-needs-human` or `intent-refused` qualified by its step. A finished continuation leaves the actor list.
- The planning gate admits one exact, operator-authorized status writeback to product 00's one-paragraph story and reports it as `authorized-execution-writeback`.
- Product 00, product 12, the README and the capability table record the observed run; `runtime.resident` and `vertical.source-to-pr` are rated 1, demonstrable, from a starter instance.

## Read before upgrading

- **Status consumers see new rows.** `runtime-status-v1` keeps its schema, but its actors now include `vertical-host` rows keyed by continuation step, live episodes include transport `resident` with launch claim source `none`, and holds include `intent-needs-human` and `intent-refused` codes, bare or qualified by a step name such as `intent-needs-human:contract`. No raw diagnostic text reaches the view.
- **Starter updates gain the console workspace.** An exported instance updated to this release gains `packages/console` with its compiled source and tests; the kit README documents the build-free live command.
- **`dotln vertical` pends after a writer's death.** On the operator path a killed writer now leaves the source step pending, so the command prints a pending continuation and exits 1, and a rerun retries the step within the two-attempt bound; before, the issue was refused. No test yet runs this path ([D019](../../evidence/WO-118/decisions.md#wo-118-d019--final-review-follow-up-the-source-host-drops-a-writers-requireshuman-and-the-codex-writers-commit-command-fails-under-its-git-grants)).

- **Live status still misses some endings.** A continuation whose authority expires between steps keeps a stale `vertical-host` row and shows no hold, the budget line counts only portfolio-actor dispatch, and the order list does not change when the work finishes ([D018](../../evidence/WO-118/decisions.md#wo-118-d018--final-review-follow-up-live-status-misses-how-a-resident-owned-continuation-ends), FUP-2b9a8e696b38fb97).

- **Operator action.** The scratch repository still holds this run's open pull request and earlier scratch runs' branches; DotLn merges nothing, so closing them is the operator's call. The scratch instance maps the operator's own login as review automation, which affects only that instance.
- **Versions.** Application v0.80.0 is a minor release over v0.79.0. `@dotln/skeleton` moves from 0.58.0 to 0.58.1, the console's exact pin and the lockfile follow, and no dependency is added.

## Substantive changes

**Actor replacement** (`packages/skeleton/src/vertical-host.ts`). When the source-change step fails with a typed interruption and the resident's launch check still admits another launch (no dispatch hold, no revocation, required capabilities, unexpired authority, the live intent step, the operator away), the vertical host keeps the command pending for the next tick instead of sealing it refused. The source host's existing recovery then proves the old process group gone, checks for a landed commit before a second attempt, and refuses with `recovery-dispatch-exhausted` after two. Invalid results, missing launch authority, revocation and the operator's return remain terminal. Five resident-path cases (death before and after commit, exhausted attempts, revoked authority, the operator's return) and a direct case for an invalid result and absent launch authority cover it; the writer fixture can kill itself before or after its commit.

**Live status of resident-owned work** (`packages/skeleton/src/runtime-status.ts`). The projection resolves each admitted intent's latest started step against its known continuation, shows it as a `vertical-host` actor (available while it runs, unknown while paused) with a live episode that claims no native launch, and projects intent decision holds with allowlisted reason codes. A continuation whose latest step settled terminally leaves the actor list and keeps one hold only when its outcome awaits a human. Tests cover replay and restart, privacy, many finished continuations, a paused one and a running one.

**The console in the starter export** (`scripts/launchpad.mjs`, `scripts/kit/README.client.md`, `scripts/test-runner.mjs`). `@dotln/console` joins the compiled runtime packages and kit workspaces; the launchpad fixture opens the exported console against a resident store; the kit README documents the live command and the status display rule; the runner's kit labels say why the console suites stay core-only.

**An exact status writeback through the planning gate** (`scripts/lib/plan-continuation.mjs`, `scripts/lib/plan-receipts.mjs`, `scripts/lib/plan-subject.mjs`). An amendment decision may carry one `executionWritebacks` entry for product 00's one-paragraph story that names the section, an unchanged reviewed criterion and the reviewed and accepted section hashes. The gate admits exactly those bytes, keeps every other planning input's checks, normalizes only that thesis in the goal-review evidence comparison, and reports the change separately. Product 07 §Operator-opened planning pass documents the field and that a later amendment of the order restates it; a fixture covers forged sections, stale hashes, a changed criterion, withdrawal and committed continuation, with and without goal review.

**Documents and evidence.** Product 00's one-paragraph story, product 12 §Replacing a successful but costly workflow and the README's §What runs today each gain one status sentence; the capability table appends a dated WO-118 reassessment. `docs/evidence/WO-118/` holds the witnessed run's receipt, event summaries, human-event inventory, kill and control-action records, console transcript, status snapshots, audit transcripts, measures and checker, the earlier runs it supersedes, and the final review's supplement of outside directories, export checks and per-episode launch claims.
