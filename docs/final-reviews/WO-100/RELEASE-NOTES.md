## Release overview

The resident can now turn the maintenance problems DotLn's own discovery finds into bounded, verified work, without an operator in the loop but never outside what the operator preauthorized. Until this release the executable discovery producer (WO-119) reported misplaced files, failing lint or tests, stale generated files and recurring repairs, and every one of them waited for a human. A `portfolio` is reviewed text in `dotln.config.json` that names which 5S mechanics may run unattended, on which paths, with which effects and how many files in each presence phase, under what budget, and which commands must independently pass. The resident derives one bounded work order from each candidate the portfolio admits, records it as a durable work order in the index, changes source through the existing source-change host and advances its presence curve only after the existing verification host passes the change. This is the step between discovery and the unattended hour (WO-111), which will bind live hosts to it. The release also moves DotLn's external model selections from Claude Fable 5.1 to Claude Opus 5.5 and from GPT-6 Astra to GPT-6 Sol, both at `xhigh`.

## Read before upgrading

Nothing runs unattended by default. The `portfolios` section of `dotln.config.json` is optional, the resident's `portfolio` binding is optional, and no production host binds the portfolio's execution ports yet, so today's `dotln resident` reports a portfolio actor unavailable and dispatches nothing. A binding must name a full 40-hex base commit and is admitted only inside the compiled floor and each named phase's effective envelope, which must grant a source-change writer; a ceiling outside the named repository's registered authority profile refuses at configuration load. Declaring a portfolio is described in product 07 §Declaring a portfolio. The model migration changes what future external calls select: the Entropy Reducer's compiled reviewer is now Claude Opus 5.5 at `xhigh` (Seisō version 2, with a new semantic hash recorded in the authority and artifact-identity editions), and `npm run entropy -- review|refute` and `npm run plan -- refute --transport …` default to `claude-opus-5-5` and `gpt-6-sol` at an explicit `xhigh`. Pass `--model` and `--effort` to select something else; an entropy review that differs from the compiled pin is recorded as a substitute reviewer. The `portfolio` test suite declares `needs: outside-sandbox`, so `npm test` inside a harness sandbox refuses before any suite and prints the outside command, as it already did for `skeleton`. The skeleton package moves to `0.37.0`; no dependency is added.

## Substantive changes

**A portfolio is reviewed authority, not a model's choice.** It names the mechanics (the Gardener's Sort, and Shine and Standardize as compiled today), repository-relative surfaces, an effect and file ceiling per presence phase, a budget of episodes, wall time and optionally reported tokens, and the exact verification commands for each candidate kind. Candidates come only from the executable producer; operator-authored candidate lists and a model choosing its own work were declined.

**Derivation is pure and bounded.** `deriveWorkOrders` maps each candidate to exactly one outcome in candidate order. An admitted candidate becomes an order whose surfaces are its files plus any declared home, whose size is their count, whose envelope is the phase ceiling intersected with the compiled phase and whose grant is `host-policy`. A mechanic outside the portfolio or a path outside its surfaces becomes a `ProductSuggestion`; an obligation no writer carries, such as deleting a stale generated file, or a kind with no verification command becomes `NeedsHuman`; a candidate that only a later phase admits waits. The derived contract is phase-free, so one candidate keeps one durable WO-120 identity.

**Activation is recorded before anything runs, and only verified work advances the curve.** The resident appends `PortfolioOrderActivated` with the order, its grant and its WO-120 key before the episode starts, and the fold recomputes it from the recorded discovery, binding, phase and budget. The episode materializes the order, changes source through one WO-052 host and verifies it through one WO-054 host. A Sort move must be exactly the old path removed and the home added with the same blob before any verifier runs. A pass needs no human escalation, every criterion passing and no finding; a failed, refused or lost episode resets the curve to its first phase. A spent budget makes the next portfolio phase a reasoned NoOp.

**External model selections moved.** Every active external-CLI selection of Claude Fable 5.1 now selects Claude Opus 5.5 at `xhigh`, and every GPT-6 Astra selection selects GPT-6 Sol at `xhigh`, across the Entropy Reducer pin, the entropy and planning-refutation command defaults, the probe and evidence scripts and the documents that state them. Historical receipts, recorded evidence and Claude Fable 5 selections are unchanged. Defaulting always-on agents to GPT-6 Luna or the latest Claude Sonnet is recorded as a candidate for WO-111.

## Progressive polish

`packages/skeleton/src/sha256.ts` is now registered as an evidence source, so an edit to it stales the editions that depend on it, and its header credits the discovery digest to WO-119. The Entropy Reducer guide and product 03 now say the Fable 5.1 pin lasted through `v0.43.0`. The generated harness bundle was re-emitted with new snapshot paths and runtime-file hashes; no hook behaviour changed.

Known limitations, each on the record. WO-052 checks a committed change's paths only by surface prefix, so nothing counts a Shine or Standardize change's files against its size or refuses a file turned into a directory; the follow-up is due before WO-111 runs a portfolio on an operator repository ([D016](../../evidence/WO-100/decisions.md#wo-100-d016), `FUP-a05fb27e0e8f9bcf`). The budget is charged when an episode ends, so the last admitted episode can overrun what remains, and no current host reports tokens ([D001](../../evidence/WO-100/decisions.md#wo-100-d001), [D006](../../evidence/WO-100/decisions.md#wo-100-d006)). A candidate is attempted once per portfolio version and bound base, with no retry or replenishment. The resident itself does not check a hand-written binding against the repository's registered profile; the configuration loader does ([D006](../../evidence/WO-100/decisions.md#wo-100-d006) follow-up to WO-111). `worktree integrate` strands itself on intent-to-add index entries ([D017](../../evidence/WO-100/decisions.md#wo-100-d017), `FUP-bed0e3123bc66fa8`). The live unattended hour, the full 5S set, publishing and remote grants remain out of scope.
