## Release overview

This release makes the launchpad export self-governing. `npm run launchpad -- export`, given an empty destination directory, now carries the compiled runtime of `@dotln/kernel`, `@dotln/compiler` and `@dotln/skeleton` under `packages/*/dist/src/`, built from the commit's package sources at export time and hashed in `KIT-MANIFEST.json`, and the Contributor harness bundle (settings, hooks, role skills, the marked block) that the export's own `node scripts/harness.mjs emit` writes from that runtime and `node scripts/harness.mjs check` verifies. A fork's sessions are governed by generated hooks and routed to role skills from the first clone, where the WO-074 kit ran on the host's permissions alone. The visible changes:
- The export builds the three packages after proving every pinned input equal to the commit, copies their `dist/src` into the kit at the paths core's scripts import, and lists each file in the manifest; the kit holds no TypeScript package source, no `dist/test` and no build info.
- The export initializes its own Git repository on `main`, seeds the workspace links its emit needs, runs its own emit and check, and refuses by name if any emitted surface differs from the bundle core's compiled packages predicted before the first write.
- The operating-contract template gains the Start here section with the five role Read directives, so a session in a fork resolves its role skill by resume phrase; the client README and the first order describe the fresh-clone bootstrap and what the check covers.
- `node scripts/bootstrap.mjs` has no build step in a kit: it installs and emits the snapshot the hooks import.

The release is for the operator exporting the starter and for any organization that forks a launchpad instance; the overlay (WO-076), update (WO-077), sibling registry (WO-078) and the exported instance's first run (WO-082, WO-118) build on it.

## Read before upgrading

- **The export builds from the commit and refuses anything else.** Every tracked build and emit input (`packages/`, `tsconfig.json`, `package.json`, `package-lock.json`, `scripts/build.mjs`, `scripts/harness.mjs` and `scripts/lib/{config,git,harness,helpers,paths,terms}.mjs`) is compared with the commit's blob by type, executable bit and bytes, regardless of index flags such as `assume-unchanged` or `skip-worktree`; `packages` is walked on disk regardless of ignore rules, and an untracked compilable module or configuration file there refuses too. A mismatch names the input and writes nothing; commit or stash the change, or export from a clean checkout. Run `npm ci` first: an installed root development dependency whose version is not the commit lockfile's pin refuses.
- **The export is already a repository.** It is on `main` with no commit; `git init` is no longer a first step, and an export made inside another repository's work tree is an embedded repository there. Commit, then `npm ci`: the runtime's bin targets are written executable so the install leaves the tree clean.
- **A fresh clone needs one bootstrap.** The hooks import an ignored, content-addressed snapshot under `.runtime/harness/`; after cloning, run `node scripts/bootstrap.mjs` (`npm ci`, then the emit that installs it). Until then each hook reports `snapshot-missing` once per session and host permissions alone decide.
- **Refusals after the first write leave the destination.** A kit file the fork's Git would ignore (a host `core.excludesFile` with `dist/` is the usual cause), an emit whose bytes differ from the prediction, or a failing check leaves the partial export without `KIT-MANIFEST.json` for inspection; remove it before exporting again. Every refusal before the first write, the local-terms screen included, still writes nothing.
- **What runs in a fork.** Every lifecycle command runs, including the Codex dispatches that reserve a writer. `npm run build`, `npm test` and `npm run harness` still need the TypeScript source the kit omits; the export's own test command is planning's (FUP-8fb7ae17dd0fad5b, returned to open by this review). `scripts/console-fixtures.mjs` fails at import in a kit, and `npm run plan -- conditions` reports its collect-sources row as unavailable.
- **Kit files versus instance files.** The generated `.claude/settings.json`, hooks, skills and Codex files are kit files a re-emit rewrites; operator-owned Claude Code settings belong in the ignored `.claude/settings.local.json`. `CLAUDE.md` stays a seed with a hand-written floor; its harness block is checked through the listed harness manifest. `docs/product/08-publication-compiler.md` joins the kit because the reviewer skill cites it.
- **Known limit: Git replace refs.** The provenance reads honor `refs/replace`, so a deliberately written replacement blob equal to an `assume-unchanged` edit passes the guard; no accidental edit, index flag or ignore rule reaches it ([D017](../../evidence/WO-075/decisions.md#wo-075-d017--verification-ver-002-provenance-reads-honor-git-replace-refs), FUP-5c2082d9fc28dbbf).
- **License.** The compiled runtime travels under the decided Apache-2.0 terms with `NOTICE`; it is this project's own output and bundles no third-party file, so no `THIRD_PARTY_NOTICES` file is written; that duty becomes due at the first export that copies a third-party file.
- **Component versions.** Application v0.72.0 is a minor release over v0.71.1. This order changes no component package and adds no dependency; the export carries main's packages at the commit (compiler 0.26.0, skeleton 0.56.0, kernel 0.6.0 at this release).

## Substantive changes

**The runtime in the export.** `scripts/launchpad.mjs` adds `RUNTIME_PACKAGES` (kernel, compiler, skeleton), `BUILD_INPUTS` and `EMIT_CLOSURE`. `exportKit` refuses a checkout without package sources, checks the destination and the kit sources as before, then runs `dirtyPinnedInputs`: `ls-tree` and `cat-file --batch` read the commit's blobs for every pinned path and each file's type, mode and bytes are compared; a walk of `packages` (excluding package-level `dist` and `node_modules`) refuses non-regular entries and untracked `.ts`, `.mts`, `.cts`, `.tsx`, `.js`, `.mjs`, `.cjs`, `.jsx` and `.json` files; Git status adds its untracked-path diagnostics but never proves equality. After the development-dependency pin check, `atomicBuild` rebuilds and every regular file under each package's `dist/src` (no `.tsbuildinfo`) becomes a manifest-listed kit file, bin targets at mode 0755; the three `package.json` files travel as Git blobs. `KIT_WORKSPACES` gains the three packages, so the pruned lockfile carries their entries and `node_modules/@dotln` links.

**The export's own bundle.** Before any write, `expectedHarnessBundle` runs `harnessInstallation` over the fresh build with the operating contract composed by the same `composeHarnessInstruction` rule `emitHarness` uses, so the local-terms screen covers the predicted surfaces and the manifest lists every one but `CLAUDE.md` at the predicted bytes. After the kit lands, the export runs `git init -q -b main` with Git's own environment variables and `DOTLN_LAUNCHPAD` removed, refuses any manifest-listed path the fork's Git would ignore, seeds the workspace links, spawns its own `node scripts/harness.mjs emit` and `check`, and refuses by path if an emitted surface differs from the prediction. `UPSTREAM.md` describes the runtime groups and the bundle; the enclosing-work-tree advisory is retired.

**Kit templates, client README and first order.** `scripts/kit/CLAUDE.template.md` carries the Start here section and a kit block that says what the export carries and how a fresh clone restores the snapshot. `README.client.md` describes the repository the export already is, the install, the check, the bootstrap, what runs in a fork, the kit-file list with the runtime and bundle, and the generated settings and hooks as kit files. `first-order.template.md` item 3 records the check as observed and names the live smoke as the instance's choice.

**Bootstrap and the live smoke.** `scripts/bootstrap.mjs` runs `npm run build` only when `hasPackageSources(root)` (a `packages/*/tsconfig.json`, the new helper in `scripts/lib/paths.mjs`). `scripts/harness-live-smoke.mjs` compares the observed CLI's major.minor line with the compiled profile's instead of pinning 2.1.263, copies every file a role's Read directives name into its scratch, scrubs the parent session's `CLAUDE*` variables, records the launchpad's own check and whether the scratch bundle equals the launchpad's (both required to pass), and records whether a judgment was answered by a refusal or a delegated advisory.

**Gate rows.** The `launchpad` suite grows to 22 cases: the rebuild comparison at the named commit, the export's check with a one-byte drift refusal and the hook-specifier scan, the Codex dispatch reserving its writer on the carried runtime, the pinned-input and emit-closure refusals, four VER-001-F1 regressions (index flags, a missing tracked source, nested ignored directories with spaces, a same-byte symlink), the compiled-plant screen, a host excludes file, an export from a kit, and the fresh clone's snapshot-missing advisory restored by bootstrap. The cold-start comparison runs in a new `launchpad-docs` document row; `test-launchpad.mjs` joins the document-gate stubs.
