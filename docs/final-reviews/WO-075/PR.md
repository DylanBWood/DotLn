# WO-075

`npm run launchpad -- export <dir>` now carries the compiled runtime the kit's scripts and generated hooks import, built from the commit's package sources at export time, and the Contributor harness bundle the export's own `node scripts/harness.mjs emit` writes from that runtime, so a fork's sessions are governed by generated hooks and routed to role skills from the first clone. Before this change the WO-074 kit carried no runtime and no bundle: its Codex dispatches refused, no hook governed a session opened in an export, and WO-076, WO-077, WO-078, WO-082 and WO-118 had nothing to build on.

**The runtime and its provenance.** The export refuses a checkout without package sources, then compares every pinned build and emit input (`packages/`, `tsconfig.json`, `package.json`, `package-lock.json`, `scripts/build.mjs`, `scripts/harness.mjs` and the six library modules the emit loads) with the commit's blob by type, executable bit and bytes, and walks `packages` on disk refusing non-regular entries and untracked compilable files, so an edit hidden by `assume-unchanged` or `skip-worktree`, a missing tracked source, a same-byte symlink or a nested ignored module refuses before any write and Git status is only a diagnostic. An installed root development dependency that is not the commit lockfile's pin refuses too. The build then runs `atomicBuild`, and every regular file under `packages/{kernel,compiler,skeleton}/dist/src` becomes a manifest-listed kit file at the path core's scripts import, bin targets executable; the three `package.json` files travel as blobs, the pruned lockfile carries the four workspaces, and no TypeScript source, `dist/test` or build info travels. `UPSTREAM.md` names the runtime groups and the bundle.

**The export's own bundle.** Before the first write, the bundle is predicted in-process from the fresh build with the operating contract composed by the one `composeHarnessInstruction` rule `emitHarness` uses, so the launchpad's local-terms screen covers the predicted surfaces and the manifest lists every one but `CLAUDE.md` at the predicted bytes. After the kit lands, the export runs `git init -q -b main` with Git's own environment and `DOTLN_LAUNCHPAD` removed, refuses any listed path the fork's Git would ignore, seeds the `node_modules/@dotln` links, spawns its own emit and check, and refuses by path if an emitted surface differs from the prediction; a refusal after the first write leaves the partial export without `KIT-MANIFEST.json`. The hooks import the ignored content-addressed snapshot by relative path, as core's do. The contract template carries the Start here directives, the client README and first order describe the fresh-clone bootstrap (`npm ci`, then the emit; `bootstrap.mjs` has no build step in a kit), and the live-smoke script compares the CLI's version line with the compiled profile's, records the launchpad's own check and bundle equality, and says whether a judgment was answered by a refusal or a delegated advisory.

**Read before merging.** The export is already a repository on `main` with no commit, so `git init` is no longer a first step; commit, then `npm ci`. A fresh clone's hooks report `snapshot-missing` once per session and delegate to host permissions until `node scripts/bootstrap.mjs` restores the snapshot. `npm run build`, `npm test` and `npm run harness` still need the TypeScript source the kit omits; the export's own test command is planning's (FUP-8fb7ae17dd0fad5b, returned to open by this review because its condition occurred). The provenance reads honor Git replace refs, a deliberately written replacement object, boarded as FUP-5c2082d9fc28dbbf ([D017](../../evidence/WO-075/decisions.md#wo-075-d017--verification-ver-002-provenance-reads-honor-git-replace-refs)). The compiled runtime travels under Apache-2.0 with `NOTICE`; no third-party file is bundled, so no notices file is written ([LEGAL](../../LEGAL.md) §Current state). Integration with `main` at `e8fd3e4c` retimed the release from v0.71.0 to v0.72.0 above v0.71.1 and resolved one header-comment conflict; two comments were reworded for main's new comment-labels check ([D018](../../evidence/WO-075/decisions.md#wo-075-d018)).
