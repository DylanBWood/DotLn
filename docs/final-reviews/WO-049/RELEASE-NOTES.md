## Release overview

DotLn can now install its guards into a repository that is not DotLn. `harness emit --target` writes a small, Git-invisible bundle into a foreign worktree whose hooks run the launchpad's pinned runtime, and `check` and `remove` verify and cleanly withdraw it. It is the target-side prerequisite for the source-change host (WO-052), the starter runtime (WO-075), the launchpad export (WO-072) and the live proof (WO-053). The Contributor bundle that governs DotLn's own worktrees is unchanged in behavior.

## Read before upgrading

No migration is required. The target paths are opt-in: nothing changes for `harness emit` and `harness check` without `--target`. `HarnessProfile` gains optional `kind`, `runtime.importRoot` and `runtime.targetId` fields; `importRoot` is emit-time input and is never written into a manifest, settings file or receipt. Security and privacy: the two hook import lines in an installed target carry the launchpad's absolute path inside files that are never Git-visible, and manifests and receipts carry only shapes; target journals and writer reservations are written under the launchpad's ignored local lane, never under the target; the target settings file disables the harness's automatic memory store and attribution. The sandbox is not the containment boundary (the record observed sibling writes under both harnesses); containment is the hook's write check, the Codex named profile and the host's diff check, and the Codex profile carries no hook. The target permission guard denies opaque shell commands, including test scripts and `git commit`, so the installed attribution pre-check cannot decide a commit until WO-052 and WO-053 supply a host route. The retained live smoke records predate the repair, which changed no hook decision path; no live launch was made at verification or review. Attestations supplied as `ultracode` now record `xhigh` with subagents mode and the raw spelling, as `ultra` already did; earlier control events and reports are unchanged. Codex session readback is informational and never refuses a workflow action. `@dotln/compiler` moves to 0.12.0 and `@dotln/skeleton` to 0.21.0; kernel and console versions are unchanged.

## Substantive changes

Compiler: an explicit `target-worker-v1` lowering emits PreToolUse guards only, with no observers, lifecycle obligations or skills, and validates the import root as an absolute path without dot segments, control characters or backslashes. The generated prelude imports the boundary and host modules through percent-encoded `file://` URLs into the launchpad snapshot and denies, naming the runtime, if either import or the guard itself fails.

Emitter and CLI: `emit`, `check` and `remove` accept `--target` naming the worktree, an optional `--runtime-root` naming the launchpad, and `--profile target-worker-claude` (the default) or `--profile target-worker-codex`. Emit validates every destination before its first write, refuses tracked or unowned files, symlinks, exposing ignore rules and another launchpad's managed block, preserves the runtime snapshot, and records a launchpad-side receipt with the runtime hashes and the import root reduced to a shape. Exclude ownership is a marker-delimited block located by exactly one anchored begin and end line whose bytes are compared before any mutation; removal preserves user content after the block and reclaims its separator newline only when the stored prefix hash proves it is the emitter's. Linked worktrees sharing one exclude file serialize their mutations and keep each other's lines.

Host guard: `runTargetHarnessHook` binds the invocation to the target by path digest and to the snapshot by real path, verifies the pinned runtime, redirects journal and writer state to the launchpad lane keyed by the target, and decides writes, shell commands, delegation and interaction against the compiled envelope with the bundle, `.git` and the host scratch directory protected from writes through symlinks and hard links.

Profiles: `target-worker-claude` and `target-worker-codex` in the Contributor loadout cite the writing-worker record rows for each capability, distinguishing an observed capability the profile deliberately omits from one that was unavailable.

Process reporting: Codex briefings, status and usage output report the active thread's model, effort and CLI version from its local session metadata, independently of token-counter availability and without substituting a default; the shared instruction floor gains the evidence-before-claims rule.

Documentation: 02 §Harness compiler v1 describes the profile kind and its fail-closed prelude; 03 §Platform and instance boundary adds the one-sentence boundary; the skeleton README carries the target runbook and its limits; WO-033 names this order as its emit, check and remove half; the compiler README, 06 and 07 carry the version and readback notes.
