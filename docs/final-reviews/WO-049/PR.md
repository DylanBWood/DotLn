# :sparkles: Emit a Git-invisible harness bundle into a foreign worktree

`npm run harness -- emit --target` with the target worktree and `--runtime-root` with the launchpad now writes a `target-worker` bundle into any Git worktree that is not DotLn: three Claude Code PreToolUse guards (permission, writer isolation, attribution), a `.claude/settings.json` carrying the hook registration and deny list, the instruction block as `CLAUDE.local.md`, and a manifest of relative paths and hashes. The hooks import the launchpad's content-addressed runtime snapshot through absolute `file://` URLs, so a launchpad rebuild never changes what an installed target runs. Every emitted path is appended to the target's `info/exclude` inside a marker-delimited block, so `git status` stays empty and `git add -A` stages nothing. `check --target` verifies the installed bytes, the exclude lines, effective ignoring and the runtime pins; `remove --target` deletes exactly the manifest set and restores the user's exclude bytes. The Codex profile receives only the instruction block and manifest, because no Codex hook event was observed; its governance is the WO-051 launch profile.

A target hook whose runtime is unavailable answers `deny` naming the runtime, never an advisory. A write inside the worktree passes; a remote effect, a sibling write, a write to the bundle, an opaque shell command and a second writer are denied. Journals and writer reservations live under the launchpad's local lane keyed by a digest of the target's real path; nothing is written under the target, and no absolute path appears in any emitted file except the two import lines. Emit refuses a tracked or unowned destination by name, a symlinked path, a target ignore rule that would expose the bundle and an exclude block managed by another launchpad, and it never merges an existing settings file. The committed Contributor bundle keeps its relative imports and moves only in pins, snapshot and policy hashes.

VER-001 failed criterion 3: removal located its exclude block by substring, so a user's ignore rule appended after the block was joined to the line before it and a duplicated block was left in place. The repair locates one anchored marker pair, validates the block's bytes before any mutation, keeps the separator when content follows and reclaims it only when the stored prefix hash proves ownership; VER-002 verified both manifestations and four further ownership cases. Adjacent corrections in the same series: the Claude target profile's lifecycle capabilities cite C-W4 as observed but deliberately omitted rather than a Codex unavailability; a backslash in the import root refuses before an unloadable hook is generated; `ultracode` normalizes like `ultra` in attestations; Codex briefings, status and usage output report the active thread's model, effort and CLI version without substituting a default; and the shared instruction floor gains the evidence-before-claims rule. Limits a reviewer should know: the attribution pre-check cannot decide a commit because the permission guard denies opaque shell commands first, so host-authorized execution remains WO-052 and WO-053 work; the retained live smoke records predate the repair, which changed no hook decision path, and no live launch was made at verification or review; the sandbox is not the containment boundary.

Validation: `npm test -- --review` passed all 30 suites (74 fresh tasks) in 793.31 s outside the sandbox; `npm run test:docs` passed all 17 suites in 100.87 s; publication, harness-bundle, meta and release-surface checks are current; `git diff --check` is clean; `@dotln/compiler` moves 0.11.2 → 0.12.0 and `@dotln/skeleton` 0.20.0 → 0.21.0 with no dependency change.
