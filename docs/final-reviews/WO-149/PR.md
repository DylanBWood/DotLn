# WO-149

A Codex-launched lifecycle dispatch now begins its own harness session before anything reads usage, so a Codex verification or review receipt carries real token counters instead of `**Process cost:** unknown; cause no-session`. Claude has had this since its `UserPromptSubmit` hook landed; Codex has no hook boundary, so the dispatch command — the one place every `next`, `fix`, `verify`, `final-review` and `release-close` passes through — writes the record keyed by `CODEX_THREAD_ID` and the dispatch's role, once per thread. WO-099's final review measured the gap it closes: 13 real readings and 0 unknown for `claude-code` against 0 real and 8 unknown for `codex-cli`, which left the process meter with no Codex column and left the operator running `harness begin` by hand.

**Why it is safe to merge.** No hook, gate, key, schema, counter format or dependency changes, and the strict `beginHarnessSession` primitive keeps its repeat refusal untouched — only a lifecycle adapter, `beginHarnessSessionOnce`, reads that one refusal as "nothing to do". Claude's hook-recorded sessions and Copilot's `active-dispatch-unavailable` branch behave exactly as before. A dispatch with no thread identity writes nothing, and `harness usage` on an unknown session now returns null counters with cause `no-session` and an advisory instead of throwing, without creating a record. A dispatch whose harness runtime is not built is still admitted and says so, naming `npm run build`. Both degraded paths have fixtures, and the live row was produced by a real Codex session outside `npm test`.

**What a reviewer should know.** The live row's attributability is physical, not narrative: the fixture tree it dispatched into contains no `scripts/harness.mjs` at all, so a manual `harness begin` could not have written that session, and its `scripts/resume.mjs` hashes to the same bytes as the reviewed source. Its counters are the launching Codex session's totals sampled before and after the invocation, not isolated fixture compute, and the record says so rather than synthesizing a transcript. Two changes travel with the order under recorded operator authorization. The verifier rule — `xhigh` rather than `max`, and a USD 5 launch cap only where the transport has a hard dollar control — is [D005](docs/evidence/WO-149/decisions.md#wo-149-d005); it moves `FEEDBACK_VERIFIER_LIMITS` from USD 3 to USD 5 and shares the one loadout regeneration with the Codex sentence. The WO-138 probe repair is [D007](docs/evidence/WO-149/decisions.md#wo-149-d007), reopening [D003](docs/evidence/WO-149/decisions.md#wo-149-d003): it was needed because this order's `scripts/resume.mjs` edit makes `--review` select `configuration-root`, which the probe's second checkout-root derivation had been failing. One defect is recorded and not fixed here: a begin that throws for any reason other than the already-began refusal fails the whole dispatch after its transition is appended, which is [D009](docs/evidence/WO-149/decisions.md#wo-149-d009) with a named follow-up.

**The change itself.** Twenty-nine lines in `scripts/resume.mjs` — a five-entry dispatch-to-role map, a thread-and-runtime guard, the begin between the recorded transition and the first usage read, and the unbuilt advisory; twenty in `harness-host.ts` for the adapter; twelve in `scripts/harness.mjs` for the `no-session` return. Two fixtures in `scripts/test-process-debt.mjs` cover session creation, byte-identical repeat, the empty-thread case, the measured Codex transcript, the real no-session CLI and the unbuilt tree. The probe now imports the canonical `TOOL_ROOT` and `validateRecordInputs` takes the source bytes to bind, so historical evaluation selects the retained 56,244-byte original through `evaluate --harness-source` while current evaluation still refuses it. Skeleton `0.34.2` and the console's exact pin; the regenerated bundle and a new current-role oracle; the re-minted WO-149 authority and feedback editions at revision 002 with the re-pinned console case; the security document, product 06 and 07, and decisions D001 to D009 with their projections.

No dependency changes: the manifest and lockfile move only the internal `@dotln/skeleton` pin. `main` did not move while the order was in flight, so no integration or retime was needed.
