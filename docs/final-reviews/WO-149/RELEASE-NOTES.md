## Release overview

DotLn's process meter has had a blind spot on one side: every receipt written from a Codex session reported `**Process cost:** unknown; cause no-session`, because counters are only collected against a begun harness session and nothing in Codex ever began one. Claude begins its session from a `UserPromptSubmit` hook; Codex has no hook boundary, so the record was simply missing, and the role text's answer was to ask the operator to run `harness begin` by hand. From this release a Codex-launched `next`, `fix`, `verify`, `final-review` or `release-close` begins its own session — keyed by the thread, labelled with the dispatch's role, written after the transition is recorded and before anything reads usage — and the verification or review receipt that follows carries real token counters with their source. This is for whoever compares what a piece of work costs across harnesses: WO-099's final review measured 13 real readings and 0 unknown for `claude-code` against 0 real and 8 unknown for `codex-cli`, so the comparison had no Codex column at all. It adds no hook, no command, no gate, no receipt format and no dependency.

## Read before upgrading

No event, envelope, schema, key, counter format or dependency changes, and no existing receipt is rewritten. Four things are worth knowing before you upgrade. First, `node scripts/harness.mjs usage` for a session id no longer throws when no session record exists: it prints an advisory, returns null counters with source `unavailable` and cause `no-session`, exits 0, and still creates nothing — the strict `measureHarnessUsage` primitive and Copilot's `active-dispatch-unavailable` branch are unchanged, so anything depending on the throw should read the cause instead. Second, a Codex dispatch against a tree whose harness runtime is not built is still admitted, but it now says so on stderr and names `npm run build`; process cost for that dispatch stays `unknown; cause no-session`. Third, the source-heavy feedback verifier's launch limit moves from USD 3 to USD 5 and the role text now states that independent verifiers use `xhigh` rather than `max`, and that a recorded budget on a transport without a hard dollar control is a limit declaration and not an enforced cap. Fourth, and the one that changes an operator action: `docs/evidence/WO-138/audit.mjs` no longer passes when run directly from the repository root, because the local-model probe now derives its root from the canonical `TOOL_ROOT` and the audit asserts that the current probe source hashes to the build recorded in all 38 episodes. That assertion failing is the binding working as designed; the committed replacement, `node docs/evidence/WO-149/historical-probe-check.mjs`, runs the original audit unmodified in an isolated historical layout and exits 0. Skeleton moves to `0.34.2` and the console's exact pin follows it; the authority and feedback evidence editions are re-minted as WO-149 revision 002 because the Contributor loadout is a registered source of both, and the console's self-host case is re-pinned to that edition.

## Substantive changes

**Codex sessions begin at dispatch.** `scripts/resume.mjs` maps `next` and `fix` to executor, `verify` to verifier, `final-review` to reviewer and `release-close` to release-close, and when `CODEX_THREAD_ID` is set and the harness runtime is present it begins that role's session after the command is admitted and before `currentHarnessSessionReport` or `observedFactsReport` read anything. The begin is idempotent by adapter, not by weakening the primitive: `beginHarnessSessionOnce` delegates to the strict `beginHarnessSession` and absorbs only its exact "Session already began; do not erase its observations" refusal, so a repeated dispatch in the same thread leaves the record byte-identical and every other failure stays visible. No authorship is adopted, so the record's `authoredPaths` is empty and existing dirt stays a baseline. An empty or absent thread identity writes nothing.

**A truthful unknown from the command, not just the receipt.** `harness usage` now catches the missing-session error specifically, writes `DotLn advisory: process cost unknown; cause no-session.` and returns an observation whose `source` is `unavailable` and whose `cause` is `no-session`, which the receipt cost-line check accepts. Every other error still propagates.

**The unbuilt tree says so.** A Codex dispatch that finds no `packages/skeleton/dist/src/harness-host.js` emits `DotLn advisory: Codex session entry unavailable; harness runtime is not built. Run npm run build before the next dispatch; process cost remains unknown; cause no-session.` and proceeds, matching the convention the neighbouring usage advisories already set. Without a thread identity there is no Codex advisory at all.

**One tool root, and the WO-138 episodes still bound to the source that produced them.** The local-model role-qualification probe imports the canonical `TOOL_ROOT` instead of deriving a second checkout root from `import.meta.url`, which is what the `configuration-root` guard had been refusing. Rather than rewrite 38 committed episode hashes to match, `validateRecordInputs` now takes the source bytes to bind and `evaluate` accepts a `--harness-source` option naming the retained file: historical evaluation explicitly selects the retained 56,244-byte original, current evaluation defaults to the current source and refuses the historical set, and the regression pins the retained hash and rejects a one-byte alteration as well as a changed `inputHash`, `promptHash`, `schemaHash` or `harnessBuildHash`. No episode record was rewritten and no guard was exempted.

**The verifier's effort and launch cap are stated.** Independent verifiers use `xhigh`, not `max`. A verifier launch may cap provider spend at USD 5 where its transport exposes a hard dollar-cap control — `claude-cli-print` forwards `--max-budget-usd`, the Codex argument vector has no equivalent — and a recorded budget without that control must be reported as an unenforced limit. `FEEDBACK_VERIFIER_LIMITS.maxBudgetUsd` moves from `3.00` to `5.00`.

None of this changes observable semantics, saved-data interpretation, compatibility, authority or any operator action.

## Evidence and compatibility

This prepares application `v0.40.2` as a patch release over the local annotated `v0.40.1` tag. Compiler 0.17.0, kernel 0.6.0 and console 0.1.7 are unchanged; skeleton moves 0.34.1 → 0.34.2 and no dependency is added or updated. `main` did not move while the order was in flight, so the branch needed no integration and the target needed no retime. The annotated release manifest consumes the committed reviewer product-gate record: `npm test -- --review`, **32 suites, 0 failed, 533.15 s, 76 fresh tasks, exit 0**, tree `0b5cd428d138ddf810b191c8f9b33fb475851b49`, code identity `b23aa5d5a2cc7b92cb595ad7c857ab92b3b873833f3848948dad43815304d823`, recorded 2026-09-21T23:56:14.296Z. `publication:check` passes with 273/273 headings and both editions current at 30 and 45 linked sections, `plan check` exits 0, `harness check` reports 31 generated surfaces, and `release check-surfaces --local`, `format:check`, `work-orders index --check`, `authority-evidence --check`, `feedback-evidence --check`, `verification-evidence --check` and `console-fixtures --check` pass.

Verification took two rounds. [VER-001](../../verifications/WO-149/VER-001.md) failed the order on two majors: acceptance criterion 3's live row had no artifact, and the order's own `scripts/resume.mjs` edit made the final-review gate select a `configuration-root` suite that was already failing on the probe's second root derivation. [VER-002](../../verifications/WO-149/VER-002.md) passed all five criteria and closed all four findings, reproducing each: it ran the full 32-suite gate itself, inspected the live fixture tree on disk to establish that no `harness begin` could have written that session, and checked the retained probe source against the merge-base blob. [FINAL-001](FINAL-001.md) re-ran the gate at the reviewed bytes and found no defect in the delivered behavior.

Known limitations, each on the record. A session begin that fails for any reason other than the already-began refusal still fails the whole dispatch, after its transition has been appended — the risk needs an unwritable session store, a stale `dist` bundle or a control-read failure to reach, and it is recorded with a named follow-up in [D009](../../evidence/WO-149/decisions.md#wo-149-d009). The live row's counters are the launching Codex session's totals sampled around the fixture invocation, not isolated fixture compute, because the fixture's own working directory has no readback. The fixture covers the `next` → executor mapping by execution; the other four dispatch-to-role mappings are established by reading the map against the primitive's accepted roles. The episode binding now trusts caller-supplied source bytes, pinned by a committed hash rather than by the file system, with its tradeoff and reopening condition in [D007](../../evidence/WO-149/decisions.md#wo-149-d007). And the promised Codex column in the meter is not itself an acceptance criterion: no criterion binds the cost table's `tokens` metric, so the first Codex-dispatched order after this one is where that shows up.
