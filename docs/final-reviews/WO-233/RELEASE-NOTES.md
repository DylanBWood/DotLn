## Release overview

Application v0.100.0 makes DotLn clean up after itself. Every temporary root the lifecycle, a gate or an executable fixture creates carries an owner record with its class, process identity, repository, gate or session, creation time and retention, and the lifecycle removes it where it already runs: at gate end for the roots of passing suites, at session end for the session's own scratch and dead worker captures, at release close for everything the prune judges disposable, and at integration for the stash the integration itself made. A complete review reuses a warm export fixture instead of installing into a fresh export per run, the gate row records how many files it created and deleted and what the host's file-event daemon weighed before and after, and the kit carries all of it to every instance. On the machine that filed this order, the operator had deleted 85 integration stashes, 641 session scratch trees and 24,526 temporary roots by hand; nothing the lifecycle creates now outlives its use without a recorded owner, and nothing is handed to the operator to delete.

Audience: operators running DotLn checkouts or exported instances, and contributors changing the gate runner, the lifecycle hooks, worktree integration, release close or the launchpad fixtures.

## Read before upgrading

- **Retention keys.** `docs/control/budgets.json` and the kit template gain an optional `retention` object with hours per class: `gate-fixture-passed` 0, `gate-fixture-failed` 24, `session-scratch` 24, `worker-capture` 1, `warm-fixture` 0 once stale, `legacy-backfill` 48 and `coordination` null. Every key admits `null`, which keeps that class forever. An instance exported before this release reads an absent block as these seeds and keeps `npm run meta`; no control record or past judgment needs editing.
- **Owner markers.** Every owned temporary root holds `.dotln-owner.json`; the root `.gitignore` and the kit's template ignore it, fixture copies exclude it and synthetic Git seeds keep it out of their index. A copied or replaced marker retains its tree and fails the gate's cleanup rather than qualifying a passing row.
- **Session end.** An ordinary Claude Stop is a turn end: a live session keeps its printed scratch across turns. The session's own scratch and dead worker captures go only after its dispatch's completion event is recorded and its writer released; the Codex lifecycle completion supplies the same boundary itself. Another session's roots, live workers and `null`-retention classes are never touched.
- **Gate end.** After a gate records its row it removes the roots its passing suites created, including worker captures and scratch owned by those suites, and keeps a failed suite's roots for the 24-hour diagnosis window with their original end time; the row's `temporaryCleanup`, `filesCreated`, `filesDeleted`, `bytesWritten` and `fileEvents` fields record it. The fixture-root leftover check now runs after that cleanup.
- **Release close.** `npm run release -- close` prunes after its worktree and branch cleanup and records `prune` (candidates, removed, retained, census and blockers) in `release-close.json`; `--dry-run` previews the same candidates. A prune refusal, including a running gate's lanes, is a cleanup blocker with the same close retry command. A removed repository is observed absence, so an expired failed fixture of a closed order is a candidate; an unreadable worktree still stops the plan.
- **Prune and gates.** `harness prune --apply` keeps its spelling and now takes the host lanes lock, refuses while any gate holds lanes and names the gate; a gate's host task started beside an applying prune waits and names the prune. Read-only leftovers are made writable before removal. Untagged legacy `dotln-*` roots older than 48 hours with no live owner, lane, writer or open path are pruned once; unmarked legacy session scratch is retained.
- **Integration.** `worktree integrate WO-NNN` drops its own named stash when its application completes and records `stashDropped`; a continuation keeps the stash until then. The command is admitted in `active` when the worktree's merge base is behind `main`, and the main checkout's current `scripts/worktree.mjs integrate WO-NNN` can run it against the registered worktree; a worktree not behind main takes in nothing. The executor root says to integrate first when main moved, then format, sync and start the one complete run.
- **Independent reviews.** Every execution and fix requires three fresh independent reviewers before its complete run: a criteria adversary, a design improver and a consistency reviewer for write-backs, dependencies, versions, test and fixture dependencies, manifests, pins, generated baselines and evidence sources. `repair-complete` prints the same `self-review:` advisory as `implementation-ready`. No receipt subsystem or hash-invalidation rule accompanies it.
- **Known issues.** Four hand-written lines were added to CLAUDE.md during the fourth repair with no recorded authorization; this release keeps them as verified and the operator confirms or strips them at merge ([D080](../../evidence/WO-233/decisions.md#wo-233-d080--the-four-claudemd-lines-have-no-recorded-authorization-the-reviewed-bytes-stay-and-the-operator-decides-at-merge)). The generated CLAUDE.md block repeats one Codex residue line per rule ([D076](../../evidence/WO-233/decisions.md#wo-233-d076--ver-005-follow-up-the-shared-instruction-file-repeats-per-rule-codex-residue)). The absence rule's ancestor check is named for a property it does not test ([D078](../../evidence/WO-233/decisions.md#wo-233-d078--ver-005-follow-up-the-absence-rules-ancestor-check-is-named-for-a-property-it-does-not-test)). A writer reservation protects every root of its worktree, so an active order's stale warm keys and expired diagnosis roots wait for its release close, and `worktree start` and `plan start` pay a full system-temp census ([D046](../../evidence/WO-233/decisions.md#wo-233-d046--preserve-the-broader-nonblocking-retention-questions)). Playwright's own temporary directories ([D054](../../evidence/WO-233/decisions.md#wo-233-d054--keep-browser-owned-temporary-roots-on-their-existing-planning-route)) and an intermittent source-change launch refusal seen once ([D033](../../evidence/WO-233/decisions.md#wo-233-d033--preserve-the-unexplained-launch-refusal-and-keep-the-identity-floor)) stay on their planning routes.
- **Versions.** Application v0.100.0 is a minor release over v0.99.0, assigned at activation under the order's classification. Skeleton moves 0.69.0 to 0.70.0 for the additive lifecycle behavior and console's exact dependency pin follows; compiler 0.31.0, kernel 0.8.0, beacons 0.1.1 and browser-evidence 0.2.0 are unchanged, and no third-party dependency changes. The executor and verifier role texts changed; the executor root's cold-start bytes carry a dated acceptance of 34,953.

## Substantive changes

**Temporary ownership** (`packages/skeleton/src/temporary-root-records.mjs`, new, re-exported by `scripts/lib/temporary-roots.mjs` and `packages/skeleton/src/temporary-roots.ts`; `scripts/temporary-root.mjs`, new). One build-free module for scripts, the compiled runtime and the shell fixture helper: `createTemporaryRoot` and `ensureTemporaryRoot` write the owner record with the directory's device and inode, `removeTemporaryPath` is the `rmSync` replacement that defers a gate fixture's whole-root teardown to the gate whose ledger it is in and ledgers every removal, `finishTemporaryRoot` records a suite outcome without moving an earlier end later, `pruneSessionTemporaryRoots` removes a session's own scratch and dead captures, `temporaryChurn` folds the per-root ledger segments into the row's counts, and `markUnindexed` writes `.metadata_never_index` at the system-temp `dotln` root and under `.runtime/` on macOS. Fixture copies go through `copyTemporaryMaterial` and synthetic repositories call `excludeFixtureOwnership`.

**Declarations** (`scripts/lib/temporary-root-declarations.mjs`, new; `scripts/structural-checks.mjs`). The `declarations` structural task refuses a raw `mkdtemp` site that names `tmpdir`, a `dotln-` prefix or a literal system-temp path, scanning `scripts/`, `packages/` and `corpus/` and following runtime imports and repository-relative path literals into the evidence fixtures a gate test loads; intake stays outside.

**Gate end and churn** (`scripts/test-runner.mjs`, `scripts/lib/temporary-prune.mjs`, new; `scripts/lib/host-resources.mjs`). Every suite runs with the gate's identity, repository, suite and retention policy in its environment, and a nested suite inside a copied repository keeps the outer gate's ledger. After the terminal row is recorded under the host lanes lock, `finishGateTemporaryRoots` removes or retains every registered root carrying the gate, judging each by its suite's outcome, its owner's liveness and sibling writers and lanes, and retries after progress; the host task samples `fseventsd` with the command column last so macOS does not truncate it.

**Prune** (`scripts/lib/harness-prune.mjs`, `scripts/lib/temporary-prune.mjs`). Three candidate kinds (`temporary-root`, `session-scratch`, `legacy-backfill`) judged by `judgeTemporaryRoot` with a reason for every retention; nested owners judged before their ancestor, which is removed as one tree; an orphan's window started at the first proven-dead observation on apply, never on preview; the apply phase under `withHostLock`, refusing a live lane holder by name; `pruneCensus` by kind and class; and ledger retirement after the gate's metrics are durable.

**Release close, start and preview** (`scripts/release.mjs`, `scripts/worktree.mjs`, `scripts/refute-plan.mjs`, `scripts/launchpad.mjs`, `scripts/lib/temporary-prune-summary.mjs`, new). The close runs the prune after its cleanup rows with the closing order's lane receipt preserved and records it; `worktree start`, `plan start` and `launchpad export --update --preview` print the census.

**Session end** (`packages/skeleton/src/harness-host.ts`, `scripts/lib/executor-handoff.mjs`, `packages/skeleton/src/observed-facts.ts`). The session scratch is an owned root of the host process; `pruneCompletedHarnessSession` runs at the Claude Stop when no background dispatch is running and at the Codex lifecycle completion after the writer release; reusable Codex workers' later turns are observed through `list_agents` and `followup_task` so a worker given another turn keeps its scratch protected.

**Integration** (`scripts/lib/worktree-integration.mjs`, `scripts/worktree.mjs`, `packages/skeleton/src/loadouts/contributor.ts`). The stash drop at completion with its recovery proof and decision line; the `active` admission behind `main`; the registry lookup of the order's worktree and the command writer reservation; the executor root's integrate-first step.

**Export fixture cache** (`scripts/lib/launchpad-fixture.mjs`, `scripts/test-launchpad-export.mjs`). One warm export per manifest-and-lockfile key under `.runtime/fixtures/launchpad/`, one directory per key, as a `warm-fixture` root with a reproducible source commit so unchanged bytes share one key; consumers clone it and link its `node_modules` and pinned tool binaries; the WO-074 criterion 1 case keeps its fresh offline `npm ci`; a nested Node test runner inside the export runs its tests again, now that the fixture environment drops the inherited runner context.

**Kit and instance history** (`scripts/kit/budgets.template.json`, `scripts/kit/gitignore.template`, `scripts/kit/README.client.md`, `scripts/lib/process-budget.mjs`, `scripts/test-instance-history.mjs`, `scripts/fixtures/instance-with-history/`). The retention keys and their validation, the owner-marker ignore rule, the README's cleanup section and Read before upgrading, and the history suite's synthetic integrate and close that asserts zero stash and temporary-root candidates and the preview's prune line; the fixture manifest gains the closed self member without the workstream field.

**Review workflow** (`packages/skeleton/src/loadouts/contributor.ts`, `scripts/lib/handoff-ledger.mjs`, `scripts/resume.mjs`, product 07, the playbook, both installed skill roots). Three fresh independent reviewers on every execution and fix, the consistency brief's scope, the same advisory on both completions and the role oracle re-minted.

**Planning check** (`scripts/lib/plan-receipts.mjs`). The committed snapshot is judged with its committed amendment log and decision bytes, so a later workspace amendment or a pending withdrawal cannot rewrite committed authorization, and the most specific approved source wins over an older prefix.
