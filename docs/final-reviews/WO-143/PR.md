# WO-143

A resident killed while taking its store lock left a `host-lock-recovery` directory that refused every later start until a human deleted it. WO-068's verification measured the window at 4 to 17 ms per transaction and reproduced the wedge, and it was the capability table's recorded blocker for calling the resident dependable. This order closes it. The guard is now an exclusive link to a directory that already holds a complete owner record, so a later start can always judge it: a live owner refuses as before, an unreadable one refuses for inspection, and a dead one is reclaimed after the same positive replay a dead owner's lock gets, with every earlier event byte kept and an in-flight episode recorded lost exactly once.

**What else changed to make "any call boundary" true.** A guard-only patch had two holes, which the executor found and recorded in [D001](../../evidence/WO-143/decisions.md#wo-143-d001--publish-complete-owners-and-fence-recovery-by-acquisition-identity). `host.lock` was written in place and could be left partial, so it is now written privately and linked. The append lock's inspection read an empty auxiliary log, so it now replays the resident's real log, after first excluding a live writer. Reclaim is serialized by one exclusive successor record inside the dead owner's directory, and the winner rechecks the canonical guard before touching shared state, so a delayed claimant cannot disturb a newer holder. The polling loop stops taking the lock once it has killed an episode and records the outcome in one final transaction.

**Validation.** The final-review gate `npm test -- --review` passed 28 suites with 0 failures in 395.32 s under Node 26.9.0, recorded 2026-09-19T19:04:57.804Z at code identity `e76b7b66`. [VER-001](../../verifications/WO-143/VER-001.md) passed all six criteria and did not rely on the executor's fixtures alone: an uninstrumented `dotln resident` killed at 120 random instants restarted every time, 65 of those with a published guard, while the same harness on v0.32.0 wedged on its second kill. The fixtures kill a real resident subprocess at 344 startup and 68 polling filesystem-call boundaries and run thirty kill-and-restart rounds on each path; four of five valid mutants failed them. [FINAL-001](FINAL-001.md) found nothing that contradicts the pass, added the one assertion that fails the fifth mutant (the claim-time recheck, which no test pinned), and corrected two README sentences and one in product 03 that said a refusal names the guard, when `dotln resident` prints only its redacted line.

**What a reviewer should know before merging.** This is a patch, `v0.32.1` above `v0.32.0`, skeleton 0.28.1 only; no event, schema or predicate changes, no dependency, and a v0.32.0 store opens unchanged. An ownerless guard left by v0.32.0 still refuses, by design. One lock cycle now costs about 19 ms against about 5 ms, because it makes five `fsync` calls where it made two; that is inside the 1,000 ms default tick and is recorded with a reopening observation in [D006](../../evidence/WO-143/decisions.md#wo-143-d006--final-review-routing-the-judged-level-and-the-measured-acquisition-cost). The crash cases are slow to run: the resident suite took 211.98 s at verification and the skeleton suite 256.43 s in this gate. A kill can leave an unreferenced `.host-lock-*` directory that nothing reads.

**Left open, owned.** Verification met one defect that predates this order and is identical on v0.32.0: a live holder's release can race a contender into an unretried `ENOENT`, which fails one presence command or resident transaction without losing an event. It is boarded in [D004](../../evidence/WO-143/decisions.md#wo-143-d004--board-up-a-pre-existing-contention-race-met-during-verification) for an order ahead of the first unattended hour. The capability table now reads `runtime.resident` at 2, dependable within the tested local process-crash scope, with that race and the lock cost written into the row. Power loss, network filesystems, PID reuse and same-user interference are outside the claim; WO-111's first unattended hour is the reopening observation.
