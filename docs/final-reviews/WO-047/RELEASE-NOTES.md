## Release overview

DotLn v0.22.0 removes an assumption the deterministic kernel had no business making. Replay rebuilds each step's environment — the RNG seed and the policy value a reactor sees — out of application state, and until now it did that by literal key name: the seed had to live at `state.rngState` or it quietly replayed as zero, and a top-level field called `policy` was promoted into the environment. That was written down rather than accidental, but it meant a framework-free kernel knew the shape of one application's state, and any application organising its state differently had to keep those two names at the top level or replay wrongly. `replay` now accepts an optional projector — a pure function from current state and the event to that environment — so the application says where its own fields live. Callers that pass nothing get exactly what they got before, from an exported function that is now the documented contract rather than an inline convention. For anyone running DotLn, nothing observable changes: every recorded log replays to identical Decisions, byte for byte. The payoff is that the previous release's typed reactor slices, and the state shapes after them, are no longer forced to keep two reserved names at the top level to keep replay honest.

## Read before upgrading

Nothing is required of you. Source release target v0.22.0 includes kernel 0.5.0 and skeleton 0.18.3; compiler 0.11.1 and console 0.1.6 are unchanged from v0.21.2, every third-party dependency is unchanged, and the lockfile diff is the two workspace versions. No event type or payload moves, no persisted contract, semantic hash or artifact identity changes, and no recorded data is rewritten or migrated. Authorization and cadence are untouched. The kernel bump is a minor because the public `replay` signature gains a parameter, not because any existing call changes meaning — the argument is optional and omitting it is the previous behaviour exactly.

One asymmetry to know if you write your own projector. When you omit the projector, the legacy path is preserved completely, including its tolerance of raw JavaScript numbers that JSON cannot carry: a state holding `NaN` at `rngState` still delivers `NaN`. When you supply one, a non-finite seed is refused before the reactor runs, with the message `Replay environment projector must return a finite rngState`. The guard keys on whether a projector was supplied, not on which function it is, so passing the exported `defaultEnvironmentProjection` explicitly is deliberately *not* identical to omitting it for that one case. Every non-number return is refused too, which is stricter than the type promises and is the safe direction. Projector purity is the author's obligation, exactly as reactor purity already is: replay supplies the event's own time and the caller's predicate registry itself, and a projector cannot override either even by returning those keys.

## Substantive changes

**An optional environment projector on `replay`.** `replay(initial, events, reactor, predicates, projectEnvironment?)` takes a pure `(state, event) => Omit<KernelEnv, "now" | "predicates">`. It receives the current pre-step state, so a projector sees the RNG as it evolves rather than only its initial value, and it is called once per event and sampled once, so a getter with side effects cannot deliver one value to the validator and another to the reactor.

**The old contract, exported by name.** `defaultEnvironmentProjection(state)` is the reserved-key projection lifted out verbatim: the numeric `rngState` or zero, with `policy` promoted when present, including when it is null. It is the fallback when the parameter is omitted, and it is now importable and testable rather than buried in a loop. A test greps the kernel module to keep the reserved application-state reads confined to it.

**The skeleton owns its own layout.** `projectRuntimeEnvironment` is passed at all ten replay call sites — scenario live-append and restore, scenario replay, verification, the verification host, feedback self-hosting and its identity check, beacon sweep recovery, and both evidence generators. It returns the same kernel-facing slice the live reactor calls already read, so the live path and the replay path project identically by construction rather than by coincidence.
