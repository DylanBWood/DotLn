## Release overview

DotLn v0.23.0 gives the compiled presence policy a process that actually runs it. Since v0.19.0 the compiler has emitted a presence statechart — progressive absence phases, base-bounded authority, return handling, idle expiry — and nothing in the repository executed it outside a test fixture. This release adds `dotln resident`, one offline local process per launchpad that folds the log, samples the wall clock, drives that statechart, and dispatches one declared bounded script per phase when the policy allows. It is the first thing in DotLn that does work while the operator is away, which is what the project's first sentence has promised from the start. Its defining design choice is that the clock is an input, not an ambient read: every sample is a `ClockSampled` event, so every cadence decision is a pure function of the log and the whole run replays byte-identically. This release is for anyone who wants a policy-driven local loop they can kill at any moment without losing or repeating work.

## Read before upgrading

No migration is required and nothing existing changes behaviour. The `resident` slice is optional and absent from every log that has no resident event, so previously serialized `RuntimeState` bytes are unchanged. No event type, payload or persisted contract already in use is altered, no dependency is added, and the two refusals DotLn hooks make are untouched. Kernel, compiler and console versions do not move; only `@dotln/skeleton` advances, 0.18.4 to 0.19.0.

The resident is opt-in and operator-started. It installs no launchd or systemd unit, derives no work, selects no work order, launches no coding agent, and has no network transport of its own. It runs only the exact commands its owner declared in the store's `resident.json`.

The `script` actor is macOS-only in this release. It runs under `sandbox-exec` with network denied, and on any other platform — or when that sandbox cannot start — the catalog reports a reasoned `ActorUnavailable` and dispatches nothing. It never falls back to another actor kind. A consequence for anyone re-running this release's evidence: the resident fixture deliberately fails rather than skipping on macOS when the sandbox probe is refused, so it must run outside a nested sandbox.

**One operational hazard, disclosed rather than repaired.** The resident takes a short append lock on every transaction, several times per tick. That lock's recovery guard is removed only in a `finally` and, unlike the host lock, carries no owner pid, so it cannot be liveness-checked and reclaimed. A `SIGKILL` landing inside that 4–17 ms window leaves the guard directory behind, and every later `dotln resident` and `dotln presence` against that store then refuses with `host lock recovery is busy or interrupted; inspect before recovery` until a human removes `.resident-append/host-lock-recovery`. No event is lost or truncated and the log remains readable; this is WO-048's inspect-before-reclaim contract behaving as specified. But the project's own phrasing, "the log is the state, so a killed resident costs nothing", reads wider than that, and the crash fixture waits for the guard to clear before killing, so the window has no adversarial coverage. At the documented `--tick 1000` the measured exposure is roughly half a percent of kills.

Configuration is immutable within a store. Changing the policy or any declared script requires a fresh store directory; retain the old one for inspection.

## Substantive changes

**The resident host.** `dotln resident --store DIR --policy ID [--tick MS | --once]` runs one process per launchpad under an exclusive lock. It folds the log into state, records each clock sample as an event, folds presence from explicit events, executes the compiled statechart, and dispatches through the actor catalog when a cadence fires in a phase that allows it. `--once` performs one complete cycle and exits 0, so an outside scheduler can drive it — necessary because neither Claude Code nor Codex exposes a scheduler of its own. Two consecutive `--once` runs produce the same events as one two-tick loop on the same clock.

**Presence is an explicit event.** `dotln presence away|back --store DIR` appends the operator edge, and a separate short append lock means the command stays usable while an episode is running. Presence already in the canonical log wins before a result is admitted. A return cancels pending discretionary dispatch and handles an in-flight episode per the phase's `inFlightOnReturn`: `kill` terminates it, `finish` drains it without advancing the policy. Idle expiry requires a fresh back-then-away edge to re-arm, and repeated absence observations cannot replenish an expired allocation. A backwards wall clock cannot move logical policy time backwards.

**Dispatch is idempotent across a kill.** `ScriptEpisodeDispatched` is appended and fsynced before the process spawns, carrying an identity derived from policy, phase, cadence, due time and arm generation. A restart that finds a dispatched but unobserved episode records `ScriptEpisodeLost` and re-arms per the policy; that identity is never dispatched twice. A second resident against the same store refuses on the lock, and a dead owner is reclaimed only after a full positive replay of the stored state. A torn log refuses for inspection without truncation.

**The actor catalog and the `script` kind.** The catalog is a typed table of `kind`, `available()` and `run()`. A `script` actor runs exact argv — no shell — in a declared absolute working directory with a cleared inherited environment, bounded to 1–180,000 ms and 65,536 bytes of combined output, under a sandbox profile that denies network operations; a loopback connection receives `EPERM`. A disposable supervisor owns the deadline and kills the ordinary process group on timeout, on return cancellation, and on the resident's own death via IPC disconnect. Output is reduced to a SHA-256 and a first line capped at 160 characters. Success requires exit zero **and** a match against the owner-declared expected stdout digest, so a script cannot certify itself. `cli-worker`, `human-handoff` and `local-model` are present and unavailable with their WO-110 and WO-122 reasons.

**Authority is checked before anything spawns.** A phase actor's declared effect class is checked by the kernel's real `authorize` against the phase's effective envelope, and its named surface and resource reservation must fit the phase scope. A refusal records `ScriptEpisodeRefused` and launches nothing.

**One interpreter, one reactor.** WO-067's fixture interpreter moved into `packages/skeleton/src/presence-machine.ts` and the existing compiler fixtures now extend it, so there is exactly one implementation rather than a second copy in the runtime. The resident's state joins `SkeletonState` as an optional typed slice with one fold selected by event type, following the WO-050 pattern, and replay passes the application's explicit environment projector.

## Evidence and compatibility

Source release target v0.23.0, to be tagged from `main` after the reviewed `wo-068` branch merges above v0.22.1. Supported versions: kernel 0.5.0 (unchanged), compiler 0.11.2 (unchanged), skeleton 0.19.0, console 0.1.6 (unchanged). All packages remain private and unpublished; the lockfile diff is a workspace version only. `main` did not move during implementation, verification or review, so nothing was integrated or retimed.

Verification sequence: [VER-001](../../verifications/WO-068/VER-001.md) passed all eight criteria, reproducing every consequential claim independently rather than reading the executor's evidence for it, and recording four non-blocking findings. [FINAL-001](FINAL-001.md) passed with the reviewer product gate `npm test -- --review`: 27 suites, 0 failed, 589.58 s, 71 fresh tasks, exit 0, at code identity `c2caf3bc27ee975516b037b5827bb87aff7d07545e529b13c0c65597b5f5aad7`.

**Merge prerequisite.** This release cannot be tagged until a planning dispatch admits the new `runtime.resident` capability id. The order's own criterion 7 requires that capability row, but the planning-continuation gate accepts appended capability sections only as reassessments of capabilities a planning pass has already judged, so `npm run test:docs` reports `plan` and `plan-refutation-current` red on the reviewed branch. No executor repair can discharge it — the alternatives are deleting the row, which violates the criterion, or authoring a planning receipt, which is the planner's dispatch. It is recorded as a defect in the order as filed rather than in its execution.

Known limitations, recorded rather than repaired. The lock-recovery window described above is nominated to planning, with the repair shape being an owner pid on the guard or taking it off the per-transaction hot path. A `scope.budget` ceiling whose key collides with `scope.changeSize` is silently discarded, because the two are merged by object spread rather than by minimum; the compiled authority envelope's resource limits are checked independently in the same expression, so no authority escape is possible and the exposure is a scope ceiling that binds looser than authored. The NoOp dedupe keys on the reason string alone, so a later absence arm refusing for the same reason leaves no additional log record; the refusal is still evaluated every tick and no fallback dispatch occurs. The script contract verifies a declared output, not that a script did the right work; declared resource amounts are pre-dispatch reservations, not measurements of actual edits. Containment against a hostile same-user process is not claimed, and a deliberately detached descendant is not claimed reaped, though it cannot hold the host past the script deadline. No live model actor, automatic work derivation, presence sensing or installed service ships here; WO-099, WO-100, WO-110, WO-111, WO-121 and WO-122 retain those consumers and their proofs.
