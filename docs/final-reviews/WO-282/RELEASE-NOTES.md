## Release overview

An instance can take a starter release without the two repairs by hand that one reported on 2026-11-14. The emit keeps an instance's own Codex files after a merge that took the starter's harness manifest, the update preview says which side of a conflicted manifest to keep, and a sync carries the dispositions of a follow-up row whose key a reader change moved. This matters to an instance that has a host the starter lacks or that keeps a follow-up register.

## Read before upgrading

**Keep this instance's side of the harness manifest.** If the update's merge conflicts in `.claude/harness-manifest.json`, keep this instance's side; the emit the update ends with rewrites the file. The preview now prints that line above its kit rows whenever it plans the manifest as re-emitted. If the merge took the starter's manifest instead, the emit no longer refuses the instance's Codex files: it admits a `.codex/` file whose bytes equal the hash that `main`'s manifest records for it. A file edited since, or one no manifest records, is still refused with `unowned Codex output refuses replacement`, and nothing is written.

**The update trusts fewer runtime files.** Before it asks the instance's own harness check, the update's plan now compares every present compiled runtime file that the prior, the incoming or an interrupted update's pending kit lists, where it compared the prior kit's alone. A present runtime file that differs from every kit's recorded bytes leaves the check unasked, and the generated surfaces are then refused as locally modified with that reason. An update that passed before can be refused here: restore the runtime file to a kit's bytes and run the update again. A prior runtime file that an interrupted update already removed no longer refuses the retry.

**A re-keyed follow-up row is carried only in the sync that re-keys it.** A sync carries a row's dispositions where it retires the old row and creates the new one in that same sync, the two hold the same section and source text, and the old row's latest disposition was current. A row that a sync under an earlier release already left needing review, a row whose text also changed and a pair that is not unique still need a disposition by hand. A row already carried by hand is not carried again.

**For an instance older than v1.0.0, the guide now states two things that release changed.** An instance's own order no longer switches on core's release-note contract by bearing core's order number. A release still reads an order's reviewed `RELEASE-NOTES.md` where the order's merge commits it; what ended is the refusal of a release whose order committed none, which is now listed by its commit subjects. In the private terms list, a `#` at the start of a line or after a space or tab opens a comment, and a line that begins with `context:`, or its alias `review:`, is a marker: reread entries that hold either.

## Substantive changes

- **The emit's ownership reading.** Ownership of a `.codex/` file is read from the manifest on disk and, where that manifest does not list the file, from `main`'s manifest by path and whole-file hash. A root that is not a repository, has no `main` or whose `main` holds no readable manifest keeps the earlier refusal.
- **The update preview.** A plan that holds `re-emitted: .claude/harness-manifest.json` prints one line above the kit rows naming the file and the side a conflicted merge keeps. The row itself is unchanged.
- **The runtime guard.** The harness check runs only where every present compiled runtime file of the prior, incoming and pending kits holds bytes one of them wrote. An absent prior file is admitted where the pending kit dropped it.
- **The update publish.** A clone whose merge base a grafts file hides, through `info/grafts` or `GIT_GRAFT_FILE`, is refused naming the grafts file and the remedy, before any push. The refusal of a shallow clone no longer calls the clone grafted.
- **The follow-up register.** A candidate re-keyed with its section and text unchanged ends as a duplicate of its new row, and the new row holds the old row's dispositions with their own times, so two worktrees project the same bytes. The stale-request refusal names the register revision to read.

## Progressive polish

The kit guide's section on taking upstream updates says what the preview and the merge show for an elected host's surfaces once the starter is Claude-only, lists the grafts refusal among the histories that cannot be judged, and keeps a from-core replacement apart from the resolution of a conflict in an instance's merge. New cases hold the ownership reading, the preview's line, the runtime guard, the grafts refusal and the register's carry; the sync suite's recovery case now builds a complete release table in its copy before it removes the record.

## Evidence and compatibility

This is the minor release `v1.2.0`, staged by WO-282 above `v1.1.0`. It changes launchpad scripts, their tests and the kit guide; no package source and no component version changes, and no judged feedback source is edited. The release tag and the Release are made at the release close after the merge, and the tag's manifest binds the source identity; nothing is published by this review.

[VER-001](../../verifications/WO-282/VER-001.md) judged all five criteria met and [FINAL-001](FINAL-001.md) passes them. The complete review run, `npm test -- --review`, passed at the reviewed code identity, and `npm run test:docs` passed on the candidate tree. The [executable evidence](../../evidence/WO-282/update-evidence.json) records both arms of the emit with their exit codes, a real preview with its line, and the register's projection before and after the carry. The final review's [probe](../../evidence/WO-282/final-review-001/release-note-entries.json) ran the release's reader of an instance's notes.

Known limits. The emit reads the branch named `main`: an instance whose default branch has another name, or whose local `main` does not hold the manifest that records its emitted files, keeps the earlier refusal and restores the manifest before the emit. The ownership reading covers `.codex/` alone, so a later release that drops another generated host file may need the same repair ([WO-282-D002](../../evidence/WO-282/decisions.md#wo-282-d002--codex-ownership-follows-recorded-bytes-through-a-starter-merge)). Where one branch's sync carries a row while another branch disposes the old row, the union needs a resolution by hand ([WO-282-D016](../../evidence/WO-282/decisions.md#wo-282-d016--the-recheck-closes-with-one-record-repair)). The order's header says no refusal is tightened while its third step widens the runtime guard; the second paragraph of Read before upgrading states the widening ([WO-282-D013](../../evidence/WO-282/decisions.md#wo-282-d013--paired-review-round-1)).
