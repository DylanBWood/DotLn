# WO-069

Every DotLn control-plane script now asks one loader where the documents live, instead of carrying `docs/…` in a string. A launchpad that wants its work orders under `vault/orders` writes one `dotln.config.json` and gets it, across the whole lifecycle — `status`, `activate`, `verify`, `final-review`, `worktree finish`, the generated index, the planning register, the lineage index and the evidence tools. A launchpad that writes nothing gets today's layout byte for byte, which is what this repository does: it ships no configuration file, and the defaults resolve to exactly the eighteen literals that were previously hardcoded.

**What this unblocks.** WO-033's export kit and its target-repository children need a launchpad whose document layout is data rather than code. Before this, the plane ran only inside this repository's tree: `"docs/control` appeared 29 times across `scripts/`, `"docs/work-orders` 18, `"docs/final-reviews` 13, and eleven scripts derived the repository root from `import.meta.url` in four different ways. There is now exactly one such derivation, `TOOL_ROOT` in `scripts/lib/config.mjs`, and it owns kit paths only — `packages/`, `node_modules/`, fixtures — while every document root comes from the launchpad. That split is the whole point: a copied script tree driven from an unrelated directory can no longer write into the wrong checkout's documents.

**How a launchpad is found.** `DOTLN_LAUNCHPAD` if set, resolved against the working directory and required to exist; otherwise the first directory at or above the running `scripts/` checkout that holds a `dotln.config.json` or is a Git top level; otherwise the scripts' own checkout. The working directory never selects a launchpad, and that is deliberate rather than incidental — a copied tree is routinely driven from somewhere else, and a working-directory ascent would let one session write into another checkout's records.

**The schema, and what it does not decide.** `version: 1` plus four optional sections. `roots` maps any of eighteen names to a relative POSIX path inside the launchpad, with `orders` defaulting under `control` and `refutations` under `planning`, so moving a parent moves its children unless the launchpad moves them too. `repositories` is validated only as an object of objects, because WO-071 owns its meaning. `build` carries `loadout`, `profile` and `overlay`; `release` carries the four surface toggles. Validation is positive and unknown keys refuse; an absolute root, one that escapes the launchpad, or one containing `.` or `..` is refused by name, and a malformed file names its own path in the error. Product 10 records this as its own version axis: the schema number is independent of the application release, the IR schema, the artifact identity and every capability version, and the file's absence is the same contract as `version: 1` with no declarations, so no recorded program, manifest or semantic hash changes because the schema exists.

**One scope limit, stated rather than implied.** The compiled packages under `packages/` still resolve their own Git-ignored local harness lane at `docs/control/local/…` and are not part of this loader's subject. WO-070 owns the kit's side of that dependency; product 07 says so in the write-back, and it is the single non-configured write observed when a whole lifecycle ran into a configured launchpad.

**Validation.** `npm test -- --review` passed **36 suites, 0 failures, 501.47 s, 80 fresh tasks, exit 0** at code identity `ed7eb50b`, after every reviewed change and both new source files were staged. `npm run test:machinery` passes 17 of 17 and `npm run test:docs` 19 of 19, which together with the review selection is the complete suite table. `publication:check` passes with both editions current, `plan -- check` exits 0, and `git diff --check` and `format:check` are clean. `package.json`, the lockfile and `packages/` have no diff at all, so nothing was added and no component version moved; no lint or type suppression enters the diff. This is a patch release, `v0.37.2`, retimed from `v0.37.1` because that tag is now the published baseline.

**How it was checked.** [VER-001](../../verifications/WO-069/VER-001.md) failed on five findings, and four of them are the same lesson: replacing a literal with a default-returning accessor looks like this refactor and is not it. Live lineage and planning consumers still read the default ledger; a follow-up projection collected references under the configured roots and validated them against the default ones inside one function; a two-step `here`/`resolve(here, "../..")` derivation slipped past a guard that only knew inline shapes and wrote a report into the tool checkout. All three pass a green literal-root guard, and they were found by driving matched default and configured fixtures instead of counting removed literals. A `const` declared in `try` and read from `catch` also turned a structured licence failure into a `ReferenceError`, and an existing harness fixture's hand-maintained copy list did not gain the new loader — the one failure the product-only gate could not see. [VER-002](../../verifications/WO-069/VER-002.md) rebuilt every counterexample from the finding's own description rather than from the new test, found all five repaired, and mutation-tested the guard with five injected offence shapes. This review mutated the guard independently, drove a configured launchpad from a separate tool checkout, and confirmed all eighteen defaults resolve to their historical literals.

**One correction made at review.** `planHarnessPrune` resolved a worktree's target-receipt directory under that worktree's configuration but its `installation.json` under the current process's, so one launchpad's control root named a path inside another's. Identical under today's defaults; under a moved control root it would have silently skipped every target lane instead of failing. Fixed here as one token, recorded as [WO-069-D017](../../evidence/WO-069/decisions.md#wo-069-d017), with the one remaining instance of that shape — in fixture construction — nominated as a follow-up rather than folded into this diff.
