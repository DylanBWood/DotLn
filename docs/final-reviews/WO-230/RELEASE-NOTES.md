## Release overview

Application v0.96.1 makes a registered target order's pull request describe the change the forge shows. Before this release both session publish forms computed the Change table, the base-tree exemption and the no-change check from the order's activation base, the commit pinned in the order's text at planning time, so an order whose subject had taken in later base-branch commits described every file since that base. On 2026-10-24 the operator's fork met the consequence: a verified target order's draft publish was refused before any push, its table describing 515 files, 17 of them earlier orders' moved records whose identifiers the outward lint refuses, while a diff from the base branch's head lists 83. The same fork's plan gate printed eleven advisories, eight of them asking to rename the kit's own evidence files. This release takes the described base from the merge base of the subject and the base branch fetched at publish, names the activation base beside it when the two differ, keeps every record bound to the activation base, and stops the plan gate advising on the order's own record paths.

Audience: operators and reviewers of exported instances that publish into a target repository, above all one whose base branch moves while an order is open; the planner who reads the plan gate's advisories; and maintainers of the publish helper and the composed body.

## Read before upgrading

- **The table describes the merge base.** `worktree publish WO-NNN --target-worktree` and its `--draft` form fetch the target's registered base branch through the publication lane, read `git merge-base` of the subject (the draft commit, or the records commit) and the fetched commit, and use it as the described base whenever the activation base is its ancestor; otherwise the activation base is kept. The Change table, the base-tree exemption that leaves a path the base already held unreported, and the no-change check all use that base. When the merge base equals the activation base, every byte of today's table, exemptions and body is unchanged, which the existing publish cases show without edits ([D001](../../evidence/WO-230/decisions.md#wo-230-d001--keep-the-activation-evidence-and-describe-the-fetched-merge-base)).
- **The body says which base it describes.** The Change section's closing sentence names the described base and, when it differs from the activation base, adds a clause naming the activation base as the base the order was activated at and the described base as its descendant. The activation base remains the base of every lifecycle event, registry entry, baseline witness and verification; no event or correctable field rebinds it.
- **The fetch comes first, and a failed fetch refuses.** The base branch is fetched before the merge base is read, as release close fetches it, so a stale local tracking ref cannot choose a base. A fetch failure refuses before any push with a message that names `origin`, the registered base branch and the public forge selector, says `prepared work retained; fix the fetch and retry the same command`, and names no path; the draft's prepared commit and its `DraftPrepared` row are kept, and the retry reuses that commit when its tree, parent and title match. A publish whose fetch fails while a push to the same remote would have succeeded is newly refused ([planning receipt 054](../../planning/refutations/2026-10-24-planning-b4ff901f3d0907a0-054.md) records this as a known issue whose condition has not occurred).
- **No-change checks compare against the described base.** A working tree equal to the described base's tree refuses `the target's working tree equals the base; no change to draft`, and a records commit whose tree equals it refuses `records tree equals the described base; no target change to publish`; a subject whose change has already reached the base branch is refused instead of publishing a table the forge would not show. Because the described base needs the fetch, an unchanged tree now prepares its draft commit and records one `DraftPrepared` row before the refusal; nothing is pushed and the next preparation overwrites the ref.
- **A same-tree draft retry can refresh the body.** When a published draft is retried at the same tree and its history is longer than one commit over the activation base, the publish recomposes, lints and edits the pull-request body, because the merge base can have advanced; this pays one pull-request edit even when the base has not moved. A draft that is a direct child of the activation base keeps today's no-edit shortcut ([D005](../../evidence/WO-230/decisions.md#wo-230-d005--refresh-a-published-draft-when-its-merge-base-can-advance)).
- **The plan gate advises on target paths only.** `npm run plan -- check` skips an Execution-plan path under the open target order's own `evidence`, `verifications` and `finalReviews` roots as the launchpad's configuration resolves them, because those files reach a target only as moved kit records the lint exempts from the identifier rule by design. Another order's path, a prefix collision such as `WO-901-extra`, a `..` traversal and any target-side path carrying a launchpad identifier or a review word are advised as before ([D002](../../evidence/WO-230/decisions.md#wo-230-d002--keep-episode-publication-and-planning-time-admission-unchanged)).
- **Known issues.** The episode form (`observeTarget`) keeps the request's base and diff hash by design; reopen when a resident's episode integrates a later base-branch commit before publication and the table misstates the change. A base advance event or a correctable `baseCommit` is declined. The criss-cross case, in which `git merge-base --all` returns several commits, is untested: the single merge base Git returns is used when the activation base is its ancestor, and the activation base otherwise. The fork's three target-side fixture names that carry a platform order id are refused by the lint at their first publish unless renamed, which the filing pass's answer block tells the fork.
- **Versions.** Application v0.96.1 is a patch release over v0.96.0, assigned at activation under the order's classification. No component version changes: compiler 0.31.0, skeleton 0.68.0, console 0.5.0, kernel 0.8.0, beacons 0.1.1 and browser-evidence 0.2.0 stay, the lockfile is unchanged and no dependency is added. No role text changed.

## Substantive changes

**The publish** (`scripts/lib/target-publish.mjs`). `describedTargetBase` refuses a subject that does not descend from the activation base with today's text, fetches the base branch through `fetchRemoteBranch`, reads the merge base of the subject and the fetched commit, and returns it as the described base when the activation base is its ancestor, with the activation base beside it. `publishTargetDraft` defers its no-change check to the described base, computes the base for a same-tree retry from the published head, keeps the direct-child shortcut, reuses the published commit as the retained commit for longer histories, and reads `targetChanges`, `baseTreePaths` and `composeTargetBody` from the described base after the prepared commit is recorded. `publishTargetWorktree` computes the same three from the described base, refuses a records tree equal to it, and keeps its existing refusal for a reviewed commit equal to the activation base.

**The body** (`scripts/lib/github-body.mjs`). `targetChangeSection` and `composeTargetBody` take an `activationBase` that defaults to the described base and render the activation clause only when the two differ; the Change rows and their offsets are unchanged, which the suite's identity case asserts.

**Planning** (`scripts/lib/plan-receipts.mjs`). `targetOrderPathAdvisories` resolves the order's three record roots through `docRelative`, normalizes each named path with `posix.normalize` and skips a path under one of those roots before matching identifiers and review words.

**Tests.** The target-worktree publish suite gains six cases: the paired draft controls at the activation base and after a fast-forward onto the later commit; the redacted fetch failure with its retry; the no-change and non-descent refusals; the final publish that excludes an earlier order's moved record, exempts a path the fetched base held, measures six paths against the merge base and four against the parent, and refuses an already integrated records tree; and the same-tree retry that refreshes the body with one preparation, one create and one edit. The github-body suite asserts byte identity for equal bases and the clause alone for an advanced one. The plan-refutation suite runs the record-roots case under the default and relocated roots. The console workstream page's byte comparison moves from the product suite to the document suite ([D006](../../evidence/WO-230/decisions.md#wo-230-d006--keep-generated-document-parity-in-the-document-suite)); the runner inventory follows with 67 declarations and 95 names.
