# WO-232

A kit release now meets an instance's accumulated records in core's gate before an instance meets them in the field. The core-only `instance-history` suite, part of every fresh gate, clones a committed synthetic instance whose history holds the four record shapes the operator's fork reported since 2026-10-19: a closed order with a bound execution amendment that later gained a leading `**Workstream:**` field, a workstream document over two closed `self` members and one target member, an order whose bound decisions were moved into a target with `target-records`, and a target order activated at a base its base branch has since passed. The suite applies the current kit on an update branch with `launchpad export --update --apply` on the instance directory, runs the instance's own `npm run sync`, `index --check`, `plan check`, document check and `index` there, fails naming the check and the record on any refusal, and fails if a self member reads as anything but current. Three readers now admit what those updates refused. The amendment matcher admits one exact leading `**Workstream:** WS-NNN` line added to an order whose filed source lacked it, in both the current and the legacy title representation, while bindings the previous release made with the field present stay matched, a field-only grouping change on a judged order keeps its `amend-order` route, and any other changed byte still refuses. The workstream check admits a closed member without the field from its document with one advisory, and still refuses an open member without it, a conflicting declaration, a missing document and a declaring order absent from the members. A self member's base and integration target both read the launchpad's `refs/heads/main`, so an index refreshed from a planning or update branch records it current, stale no. Product 07 states the rule where releases are: a kit check added or tightened in a release admits the records the previous release admitted or the release is held, the suite is that check, a Read before upgrading line never asks an instance to edit a closed record by hand, and a necessary migration needs its own planning decision before release.

Why it matters: four of the fork's six starter updates since 2026-10-19 blocked the update, left a gate red or damaged a record. At v0.87.0 the document check failed on decisions that `target-records` had moved into the target; at v0.88.0 and v0.93.0 the document check and the plan gate failed on the same moved records until v0.94.0 carried the repair; at v0.96.0 `npm run sync` refused the index because two closed orders lacked the new Workstream field, and adding the one-line field made the plan gate refuse both orders' bound amendments, which the fork withdrew to merge; at v0.96.1 the final-review lint refused a verified target order (WO-231). Core's gate met none of those records, because its instance cases export a fresh kit, replay a three-file v0.81.0 export or build workstreams in a fresh pilot, so a check that refuses an accumulated record passes every core gate and meets the record first in the fork, after the release. The operator's direction of 2026-10-25 names that pattern as unacceptable ([the order](../../work-orders/WO-232-a-release-does-not-break-the-instance.md), [the filing pass](../../planning/fork-returns-and-review-lint-2026-10-25.md), [D001](../../evidence/WO-232/decisions.md#wo-232-d001--exercise-an-older-exported-instance-without-rewriting-its-records), [D003](../../evidence/WO-232/decisions.md#wo-232-d003--admit-grouping-metadata-without-relaxing-substantive-authority)).

Limits a reviewer should weigh: no live forge or live model took part, the fixture's local forge standing in as the order's evidence gate directs; the bundle is one past state, its generator rebuilds every shape with the current kit so a shape only an older kit emitted can change on regeneration, and each regeneration commits about 4.2 MB; the suite adds about 30 to 73 s to a fresh gate with no stated ceiling; the generator runs on demand and never at a gate; the fork's withdrawn amendments of 2026-10-24 stand as its record, and this order asks the fork to change nothing.
