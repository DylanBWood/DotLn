## Release overview

Application v0.98.0 makes a kit release meet an instance's accumulated records in core's gate before an instance meets them in the field. Four of the operator's fork's six starter updates since 2026-10-19 blocked the update, left a gate red or damaged a record, each on a record shape core's fresh-instance cases never hold: decisions moved into a target, a closed order whose bound amendment stopped matching when it gained a leading Workstream field, a workstream over closed members, and a target order at a base its base branch had passed. This release commits a synthetic instance with that history, updates it with the current kit in every fresh core gate, runs the instance's own checks there, and admits the three record shapes the plan gate, the workstream check and the index refused.

Audience: operators updating exported instances, and contributors changing kit checks, amendment matching or workstream indexing.

## Read before upgrading

- **A self member's cells read main.** A `self` member's base and integration target both read the launchpad's `refs/heads/main`, so an index refreshed from a planning or update branch records it `current`, stale `no`; an unreadable main stays `unknown`. A branch no longer carries a false `diverged` mark into `main` at merge.
- **A closed member may lack the field.** A workstream document member whose order is closed and declares no `**Workstream:**` line is admitted from the document with one advisory naming the document, the order and the field; the order's bytes stay as they are. An open member without the field, a conflicting declaration, a missing document, a declaring order absent from the members and a member listed in two documents still refuse.
- **An amendment stays bound when the field is added later.** An existing execution amendment remains matched when the filed order lacked a Workstream field and one exact leading `**Workstream:** WS-NNN` line was added afterwards, in both the current and the pre-v0.51.0 legacy title representation. Bindings a previous release made with the field already present also remain matched. A field-only grouping change on a judged order still records its authorization through `amend-order`, and that binding retains the field. A changed criterion, objective, dependency block or Cost line still refuses, and `amend-order` still refuses an order outside the judged horizon. No amendment is withdrawn or rewritten by the update; bindings an instance withdrew earlier stand as its record.
- **Every fresh core gate runs `instance-history`.** The suite and its bundle are core-only and are excluded from exported kits. The suite checks that a release admits the records its predecessor admitted. These changes require no instance record edits.
- **Known issues.** The committed bundle holds only fields and bindings its own kit produced, so the suite's base arm fails on the amendment and the self members but never meets the v0.96.0 refusal of a closed member without the field (VER-001 F2, [D010](../../evidence/WO-232/decisions.md#wo-232-d010--retain-the-historical-bundle-and-board-its-next-shape-expansion), FUP-912bcf619a547236). Three guards of the admission hold in the code but no permanent case fails when one is removed (VER-004 F6, [D017](../../evidence/WO-232/decisions.md#wo-232-d017--three-guards-of-the-workstream-admission-lack-a-permanent-case), FUP-c4c7ba9f126d2e4a). The suite exercises the opted-in `launchpad export --update --apply` route, not an instance's own-session preview, update branch and `update --finish` route.
- **Versions.** Application v0.98.0 is a minor release over v0.97.1, assigned at activation under the order's classification. No component version changes: compiler 0.31.0, skeleton 0.68.0, console 0.5.0, kernel 0.8.0, beacons 0.1.1 and browser-evidence 0.2.0 stay, the lockfile is unchanged and no dependency is added. No role text changed.

## Substantive changes

**The fixture** (`scripts/fixtures/instance-with-history/`, new). `instance.bundle` carries two refs, the instance's `main` and a `fixture-target` branch holding the synthetic target's history, 4,174,480 bytes, with its SHA-256 and the two tips in `manifest.json` beside the four shapes and the field report each stands for. `generate.mjs` rebuilds the bundle on demand with the kit's own commands (`activate`, `amend-order`, the completion transitions, `worktree start` and `target-records`), adds the Workstream field to the closed amended order after its binding, and refuses to run inside or beside a live gate; `support.mjs` holds the scratch runner, the committed core copy and the dependency links the generator and the suite share. The evidence README names one inspection command per shape.

**The suite** (`scripts/test-instance-history.mjs`, new; the `instance-history` row in `scripts/test-runner.mjs`). It verifies the bundle's digest, clones both refs, maps the target clone, asserts the four shapes from immutable records before anything can act, snapshots every authored record, commits one unrelated change on `chore/kit-update`, applies the current kit with `launchpad export --update --apply` on the instance directory, requires the offered reader bytes to be installed, runs `npm run sync`, `npm run work-orders -- index --check`, `npm run plan -- check`, `npm run test:docs` and `npm run work-orders -- index` in order, and then requires both closed self members `current`, stale `no`, with base and target equal to main, from the advanced branch; every authored record must be byte-identical afterwards. A failure names the command and its output. `scripts/launchpad.mjs` excludes the fixture and the suite from exported kits so a regenerated bundle never nests an earlier one.

**Amendment matching** (`scripts/lib/plan-continuation.mjs`). `executionAmendmentSource` separates release-label normalization from the Workstream admission: `withoutAddedWorkstream` removes one exact leading `**Workstream:** WS-NNN` line only when the filed source declares none, exactly one was added and it lies in the leading header before `**Objective:**`, preserving every other byte and line ending; when removing it would leave the release-normalized filed source, the writer retains the field so a grouping-only change stays bindable. `executionAmendmentMatch` tries the retained and the field-removed form under the filed-aware representation and again under the historical activation-placeholder representation, and keeps its filed-prefix and execution-appendix checks.

**Workstream check and index** (`scripts/lib/work-order-workstream.mjs`, `scripts/work-orders.mjs`). `readWorkstreams` admits a closed member without the field with one advisory and refuses a member listed in two documents; `readIndex` carries the document's membership into the closed order's index facts without touching its bytes; `readTargetFacts` sets a `self` member's base to its target, the base branch ref, `refs/heads/main` for the launchpad.

**Tests.** `scripts/test-plan-refutation.mjs` gains nine Workstream amendment cases: a field-only amendment keeping its execution route and a previous reader's field-and-body binding surviving an update, each over unlabelled, placeholder and versioned filed titles; a later leading field preserving a closed amendment but no other changed byte, with malformed, duplicate, body and changed-field candidates judged at the matcher; and a legacy amendment admitting later grouping with and without an existing execution record, over LF and CRLF. `scripts/test-work-orders.mjs` gains the closed-member admission with its open, contradictory, missing-document, absent-membership and duplicate-membership refusals, and extends the self-member case with a refresh from a branch one commit past main.
