## Release overview

DotLn `v0.10.1` is the patch release above the published `v0.10.0`. It answers one operator question from the control log alone: which actors did this repository's work, for how long, and in which phases. `npm run resume --silent -- usage` reports every completed phase attempt across every known work order, grouped by harness, harness version, model, effort, opaque account label, and phase, and again per work order; `--json` returns the same `totals`, `byActor`, and `byWorkOrder` for machine consumers. Retries and failed attempts stay separate attempts, an attempt missing either timestamp is counted under `unknown` rather than guessed, and every span is wall-clock time between the phase's request and its completion, so it includes waiting and interruptions and can overlap across concurrent orders. The four completion commands accept an optional opaque `--account-label`, with `DOTLN_ACCOUNT_LABEL` as a per-shell default, so an operator running the same harness under two provider accounts can tell their usage apart without ever publishing which account is which: the label's meaning lives in an ignored local file that no script reads. Audience: the operator deciding where to spend model budget, and lifecycle peers that consume control state. No exported runtime capability changes; kernel, compiler, and skeleton sources and component versions are unchanged. The order's operator-authorized ideation breakout rides along as documentation only: PR and commit editorial guidance, deliberate gitmoji selection, proportionate correction without oscillation, resolving the main checkout for original intake, and the default that ideation returns to execution.

## Read before upgrading

- **Completion actors may now carry `accountLabel`.** The control event schema stays `1`. The field is stored only when `--account-label` or `DOTLN_ACCOUNT_LABEL` supplies it, is never inferred from any other field, and every projection renders an absent label as `not-applicable`. No historical event is rewritten; every stored attestation before this release has no label.
- **`DOTLN_ACCOUNT_LABEL` is read by all four completion commands.** An exported value that is empty or does not match `^[a-z][a-z0-9-]{0,15}$` refuses every `implementation-ready`, `verification-result`, `repair-complete`, and `final-review-result` in that shell until it is corrected or unset; an explicit `--account-label` wins over the environment even when the environment value is invalid. The five shell test suites unset the variable so an operator's default cannot reach fixture evidence.
- **The label is public.** Two distinct labels disclose that two accounts are distinguished, and timing plus other public activity may aid re-identification; this public profile accepts that disclosure when the operator opts in, and a stricter profile leaves the field unset. Choose labels with no identity, e-mail, or plan information.
- **`docs/control/local/` is ignored and never read.** The optional meaning of each label belongs in `docs/control/local/account-labels.md`, one line per label, maintained by hand. No script creates, opens, or validates that directory, so its absence is not an incomplete deliverable.
- **Report headers place the label last.** When a verifier or final reviewer supplies a label, its `**Actor attestation:**` header must serialize the actor as `harness`, `harnessVersion`, `model`, `effort`, optional `raw`, `source`, then `accountLabel`; the completion command compares the header by exact string equality and refuses a mismatch without appending.
- **`status --json` `latestAttestation` gains `accountLabel`.** The projection always carries the key, `not-applicable` when the event has none; the fourteen selected-order keys and `orders[]` are otherwise unchanged. `docs/control/current.md` renders the label after `account` at the end of its attestation line, and the generated work-order index now prints a `Latest attestation` line for every order with a recorded actor.
- **`usage` is read-only and selection-free.** It accepts only `--json`, refuses `--work-order` and any other argument with a usage line, appends nothing, refreshes no projection or Beacon, reads no checkpoint ref, launches no process, and never opens the private mapping.
- **A hand-edited label refuses the whole fold.** The control reader validates every stored `accountLabel`; an invalid value makes every `resume` command refuse until the segment is repaired. The refusal names the grammar but not the line, unlike the neighbouring `recordedAt` validation.
- **Ideation now returns to execution by default.** After an `ideation:` breakout during an active work order, the executor finishes the receipt and continues through the evidence gate to ready to verify; only an explicit pause or capture-only instruction stops it. This supersedes the former opt-in continuation wording in the execution guide, playbook, and docs README.
- **PR titles choose from the full gitmoji catalog, and the final reviewer commits a series.** The former narrow `:memo:` and `:adhesive_bandage:` default mapping is replaced by deliberate relevance-first selection; publication guidance now lives in the publication compiler document's PRs and commits section, and distinct coherent changes are committed separately at final review. Historical titles and commits are unchanged.

## Substantive changes

- **Control usage projection (`scripts/lib/control-usage.mjs`, new).** `controlUsageProjection(control)` folds every order through the existing multi-order reader, pairs each phase request with its completion through the shared generator, and groups completed attempts by `harness`, `harnessVersion`, `model`, `effort`, `accountLabel`, and `phase` with `attempts`, `elapsedMs` (known signed spans only), `unknown`, and the list of `workOrders`; `byWorkOrder` gives each order's totals and the same groups within it; a completion without an actor groups as `unknown` with account `not-applicable`. `renderControlUsage` prints the same numbers as text with a timing disclaimer, a `Total:` line, the actor groups, and one row per work order.
- **Actor attestation (`scripts/lib/control-actor.mjs`, new).** `validateAccountLabel` accepts `undefined` or a string matching the sixteen-character lowercase grammar and refuses everything else, including control and Unicode line-separator characters, by comparing the whole match against the input rather than trusting anchors; `projectActor` adds `accountLabel: "not-applicable"` at read time without touching stored events; `renderAttestation` is the single renderer used by `current.md` and the work-order index.
- **Shared phase pairing (`scripts/lib/control-time.mjs`).** `completedPhaseAttempts(events)` yields every completed attempt with its order, phase, completing actor, and signed or `unknown` duration, keeping one start map per order so interleaved orders never borrow a start; `controlTimeProjection` is rewritten on top of it and keeps its latest-completed-attempt semantics, proven JSON-identical to the `v0.10.0` implementation over all 26 real orders.
- **Control fold (`scripts/lib/control.mjs`).** `scanControl` validates every event's `actor.accountLabel` beside its `recordedAt` validation, so an invalid stored label fails closed before any transition can append.
- **Resume (`scripts/resume.mjs`).** The `usage [--json]` action with its argument refusals, skipped branch selection, and exclusion from the projection and Beacon refresh; `--account-label` on the four completion commands with the environment default and flag precedence, validated before any append and serialized last; the status projection's `latestAttestation` through `projectActor`; the attestation renderer moved to the shared module.
- **Work-order index (`scripts/work-orders.mjs`).** A `Latest attestation` line for each order whose control state records an actor, rendered through the shared renderer with the label.
- **Tests (`scripts/test-resume.sh` and four sibling suites).** A three-order fixture with two harnesses, two models, two labels, a failed verification and retry, a missing endpoint, a negative span, a zero span, an unattested completion, and an incomplete final review, asserting exact totals and every actor and work-order group and re-parsing the text form independently; `cmp` on every segment and a deliberately stale `current.md` across both output forms and three refused argument shapes; an instrumented filesystem and trapped `spawnSync` proving the private lane is never opened and no process runs; eleven invalid label forms, missing and duplicate flags, and an invalid environment default refused before append, both accepted labels, environment fallback and flag override through all four completion commands, report-header parity, and the absent field in stored history; direct pairing assertions for reactivation and interleaved orders; `git check-ignore` on the mapping path; and `unset DOTLN_ACCOUNT_LABEL` at the top of the resume, checkpoint, worktree, release, and work-orders suites.
- **Ignore rule (`.gitignore`).** The anchored `/docs/control/local/` entry with its comment.
- **Documentation.** The execution guide's `usage` paragraph and optional-account-label note; the domain model's attestation shape; the architecture document's projection semantics; the roadmap's activation completion and efficiency-axis caveat; the audit document's candidate rewritten as the adopted convention plus the re-identification note; the playbook's per-terminal setup and usage reading; the docs README's ignored directory and private-mapping section; the root README release block at `v0.10.1`; the planning map; the ledger's dated implementation section; the verification README's actor key order including the optional label; the refreshed publication index and both edition locks; and the regenerated work-order index.
- **Ideation breakout (documentation only).** The publication compiler document's new PRs and commits section; the execution guide's relevance-first gitmoji rule, reviewer-oriented PR and commit writing, proportionate-correction paragraph, main-checkout resolution before intake lookup, and continuation default; the playbook's and docs README's matching paragraphs; the domain model's anti-oscillation paragraph; WO-011's additional incident source; the shortened WO-031 heading and its breakout section; two dated ledger sections; and the receipt under `docs/evidence/WO-031/ideation.md`.
- **Executor evidence (`docs/evidence/WO-031/`).** The implementation report, the fixture transcript, the activation-log usage report in JSON and text, and the segment inventory with SHA-256 digests at activation.
