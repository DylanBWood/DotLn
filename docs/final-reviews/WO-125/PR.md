# Codex workers and refuters accept any observed effort level, so a refuter can run at max

On Codex CLI `0.154.0`, `--effort low|medium|high|xhigh|max` now reaches `codex exec` as `-c model_reasoning_effort="<level>"`, exactly as the five operator-run discovery rows in `docs/discovery/codex-effort-2026-09-11.json` record. `unknown` still adds nothing and keeps the pre-change argument bytes on both admitted versions. Any other value, an explicit level on `0.153.4` or an omitted builder version refuses before any process launch and names the discovery record; a CLI version outside the observed profiles refuses at transport construction. User configuration stays ignored, so a launch never depends on a setting outside the repository, and the requested level is recorded as a `host-launch` claim with effective effort and model still `unknown`, because no probe returned an effort field. `npm run plan -- refute --transport codex-cli-exec --model gpt-6-astra --effort max` constructs the transport, proven with a process double; the live run is the operator's.

The operator-authorized repair expansion makes gate runs safe from the write that voided VER-001's gate. `npm test`, `npm run test:full`, `npm run harness -- evidence` and direct runner or evidence calls hold process-owned markers for their lifetime, and the generated pre-tool hooks refuse Write, Edit, NotebookEdit and write-classified shell commands that could change the candidate Git tree or the installed suite inputs, naming the active command and run. Ignored scratch stays writable; opaque shell commands and subagent spawns are refused while a gate runs; a marker left by an exited owner cannot strand writes. The classifier resolves physical destinations component by component, so case aliases of `node_modules` and `packages/*/dist`, dangling and chained symlinks, parent traversal after a directory link, a working directory reached through a link and pre-existing hard links into tracked or installed inputs are all refused, with fixtures that execute every admitted attempt and prove the inputs unchanged. The final suite-input comparison remains for unhooked edits.

Application target `v0.17.2` (patch) above the local `v0.17.1`; skeleton `0.15.2` with regenerated runtime pins and snapshot; compiler `0.9.1`, console `0.1.4` and the kernel unchanged; no new dependency. A fresh WO-125 feedback edition (revision 001) and authority edition (revision 004) are selected in `docs/evidence/current.json`.

VER-001 found the adapter forwarding unobserved values, an omitted version admitting explicit effort and, at the operator's direction, the mid-gate write; VER-002 found case-variant and dangling-symlink escapes and a fixture that raced its own hold; VER-003 found pre-existing hard links; [VER-004](https://github.com/DylanBWood/DotLn/blob/main/docs/verifications/WO-125/VER-004.md) passed after the third repair. [FINAL-001](https://github.com/DylanBWood/DotLn/blob/main/docs/final-reviews/WO-125/FINAL-001.md) records the review: an independent HEAD-versus-current probe against the whole discovery vectors, the worker, runner, generated-hook and plan-refutation suites, byte identity between the build and the pinned snapshot, a clean-room screen, and the canonical evidence gate on the review tree. Non-blocking: the `console` suite's `release:list` source can time out under full-gate load in code this order does not touch, nominated for a separate order; subagent spawns are refused during a live gate, stricter than the product-07 sentence; the live rows were observed once, by the operator, and remain launch claims without effective readback.
