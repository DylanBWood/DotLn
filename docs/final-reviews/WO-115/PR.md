# WO-115

Until now the terminal was DotLn's only command surface: the actor board and the status host could read, but a UI that wanted to run `resume: next`, activate an intent or step a presence had no contract, and any host that added one would have grown a second workflow state machine. WO-115 closes that gap without adding one.

This pull request lands WO-115. The resident now serves `console-commands-v1`, a typed list of exactly the twenty-three commands that exist as terminal implementations, over a loopback socket bound to `127.0.0.1` with a bearer token that lives in an owner-only descriptor inside the resident store. Each command runs the terminal's own Node entrypoint with a fixed argument prefix, under the terminal permission hook's own classifier and decider against the resident's compiled envelope, and returns the terminal's exit code and exact stdout and stderr bytes. The text console invokes them with `console invoke`, and a browser shell imports the same Node-free client from `@dotln/console/client`. A UI can do exactly what the terminal can, and nothing the terminal cannot.

- **One contract, no effect column.** `packages/skeleton/src/console-commands.ts` maps each ID to an entrypoint and prefix: the eight `resume` actions, `release close`, the five `worktree` actions, `harness emit` and `check`, the skeleton's `--compiled-diff`, `dotln intent`, `presence away`, `presence back` and `status`, `console status`, and `resident-bind --portfolio`. `GET /console-commands-v1` returns that list; the resident writes each request as the command an operator would type, classifies it with `permissionEffect` and decides it with `harnessAuthorization`, so no second authority table exists to drift ([D005](docs/evidence/WO-115/decisions.md#wo-115-d005--judge-console-commands-with-the-terminals-classifier-and-decider)). Commands with no terminal implementation (saved-build selection, equip preview, declaring a portfolio) are documented exclusions, not invented verbs.
- **Terminal refusals, terminal shape.** A missing or wrong token, a foreign `Origin` or `Host`, a malformed or oversized body, an unknown command, a denied effect, prose the classifier cannot classify and the streaming `--watch` option are each refused as exit 1, empty stdout and one `error:` line, the lifecycle CLIs' shape; a refusal by the terminal command itself is its own bytes unchanged ([D007](docs/evidence/WO-115/decisions.md#wo-115-d007--local-transport-terminal-refusal-shape-and-lifecycle), [D010](docs/evidence/WO-115/decisions.md#wo-115-d010--second-independent-review-fail-closed-classification-a-transport-that-outlasts-client-timeouts-and-stronger-fixtures)).
- **A transport that outlasts any command.** Caller, route and request checks answer on arrival; commands run one at a time. Every decoded request's response opens at once and carries a keep-alive byte every 30 s while it waits and while its command runs, so no client idle timeout interrupts a queued or long lifecycle command. A caller that leaves interrupts its command's process group as Ctrl-C would; a caller that leaves while queued, or a request still queued when the resident stops, is refused with a recorded reason ([D013](docs/evidence/WO-115/decisions.md#wo-115-d013--repair-ver-001-f1-open-every-decoded-requests-response-before-the-lane-and-keep-its-receipts)).
- **Receipts and replay.** Each decoded request appends `ConsoleCommandInvoked` and `ConsoleCommandObserved` with actor `console` to the resident's private log, with an argument hash rather than the arguments and with the SHA-256 and length of the result bytes, which are content-addressed under the store's `console/results` directory. `replayConsoleResults` reproduces every result from those receipts without rerunning an effect and names an invocation whose result was never recorded; the resident fold is byte-identical to `main`, so the judged feedback edition stands ([D008](docs/evidence/WO-115/decisions.md#wo-115-d008--console-receipts-carry-digests-the-judged-resident-fold-is-unchanged)).
- **Shared repairs landed once, here.** The runtime status watcher reads the file every 250 ms beside its filesystem watcher and stops that read on close or error, so a missed directory notification cannot leave `console status --watch` stale; the resident crash-child fixture skips console setup; the worktree-integration fixture bases its origin `main` on the source's committed revision so an unintegrated branch is judged on one revision; and skeleton keeps `main`'s shared scheduling, now asserted by the scheduler test after a same-source comparison ([D015](docs/evidence/WO-115/decisions.md#wo-115-d015--repair-ver-002-g1-base-the-integration-fixture-on-the-sources-own-committed-revision), [D019](docs/evidence/WO-115/decisions.md#wo-115-d019--one-shared-repair-for-the-integrated-gate-failures), [D023](docs/evidence/WO-115/decisions.md#wo-115-d023--restore-measured-shared-scheduling-and-end-the-poll-on-watcher-errors)).

**What a reviewer should know.**

- **Compatibility.** Every `dotln resident` run now creates an owner-only `console` directory in its store, listens on a random `127.0.0.1` port and removes its descriptor on orderly stop; a pre-existing `console` path that is not an owner-only directory refuses the start with a named error, and `SIGHUP` now stops the resident in order like `SIGINT` and `SIGTERM`. Console receipts are two unregistered event types in the private resident log; the runtime status projection is unchanged. No third-party dependency is added: the lockfile changes only the internal versions and the console's new `./client` export.
- **The contract carries the outward-facing commands too.** `release.close` and `worktree.publish` push, open pull requests and publish releases exactly as the terminal's `resume: release close` phrase does, under the same `lifecycle.run` classification and the same compiled envelope. The loopback is not a read-only surface; the token never leaves its 0600 descriptor, and product 04 says what each command classifies as ([D006](docs/evidence/WO-115/decisions.md#wo-115-d006--contract-membership-add-the-release-close-helper-run-harness-directly-refuse-streaming)).
- **What the fixtures execute.** The inventory compares bytes and events for all twenty-three IDs on phase-independent parser refusals, and executes success paths for the resume reads, the compiled diff, both status projections and presence away and back; lifecycle, intent, bind and emit successes are not run against the repository, and their parity rests on the identical entrypoint, arguments, working directory and environment ([D009](docs/evidence/WO-115/decisions.md#wo-115-d009--takeover-correction-of-the-fixtures-and-evidence-claims)). The final review additionally drove the shipped `dotln resident` binary through the text host in a fresh process, matched three reads byte for byte, and stopped it with `SIGHUP`.
- **Limits.** A second OS account was not exercised; the local-user boundary rests on the 0700 directory, the 0600 descriptor and the token refusals. Queued requests stay in memory until their lane turn. There is no streaming; `--watch` remains a terminal command. Process-group interruption assumes a POSIX host. The historical cause of the two deadline failures FINAL-001 met is still unknown; they did not recur in any of the seven complete gates that followed, and the settled register rows carry reopening conditions for a recurrence.
