# WO-198

Every gate row now records the shared refs a linked worktree could see when it ran, and a failed gate says in one line which of them moved. The row carries `sharedRefs.start` and `sharedRefs.end`, each with the `origin/main` and `main` commit ids, the count and newest name of the annotated `v*` tags, and the count of `refs/dotln/` refs; when a task fails, the runner compares this run's start with the end of the same check's previous row in that checkout, and its own start with its end, and prints a line such as `shared refs moved: since previous: origin/main 47a6c24d..0be5b31b; during run: tags +v9000.0.1 (count 0..1, newest absent..v9000.0.1)` naming each field that differs. A passing row prints nothing. Before this change nothing on a row said what the shared refs were when it ran, so when a suite that passed in a worktree failed after a sibling merged into `main`, finding out why took the operator about an hour ([WO-179 D012](../../evidence/WO-179/decisions.md#wo-179-d012--failure-unchecked-review-selection-and-unsupported-cause)); the next such failure is attributed by one line, and the snapshot never enters the code identity or the verdict.

**The reader and the comparison.** `readSharedRefs` in `packages/skeleton/src/gate-evidence.mjs` makes four Git reads through one non-throwing helper: a quiet `rev-parse` that records `absent` when Git completes the read and finds no commit (a missing, removed, dangling or non-commit ref), and `unreadable` when Git cannot complete it (exit 128 on damaged `packed-refs`, or a launch failure); the two enumerations record `unreadable` rather than a partial count when they fail. `sharedRefChanges` in `scripts/test-runner.mjs` compares only structurally complete snapshots, treats `absent` as an observed value, so a sibling's first push that creates `origin/main` is named `origin/main absent..0be5b31b` with the new id, and withholds only the field that is `unreadable` on either side. The previous-row lookup is wrapped: a damaged gate-history archive, a legacy row without a snapshot or a malformed earlier snapshot supplies no since-previous baseline, while the run's own start and end are still compared and the failed row and its summary are still recorded ([D017](../../evidence/WO-198/decisions.md#wo-198-d017--compare-observed-absence-and-withhold-only-unreadable-fields)).

**Read before merging.** The line reports correlation, not cause: a named move says a shared ref changed, not that the change failed the task. Movement wholly between two samples, and a tag or ref re-pointed under the same name with the counted fields unchanged, is outside this snapshot. A failed `npm test` run under `node scripts/harness.mjs evidence` records a snapshot-less host row after the runner's row, so the next failure after a ref move prints no since-previous delta; it is boarded for the next order that edits that writer ([D004](../../evidence/WO-198/decisions.md#wo-198-d004--verification-fail-on-a-regression-a-malformed-earlier-snapshot-shows-one-defect-outside-the-surfaces-boarded), FUP-f5f10101e717d59b). A ref Git cannot read because of file permissions reads `absent`, since Git reports it missing. The new `runner-fixtures` cases add about 13 s to that task; its fresh duration in the review row (126.5 s) is above the planning receipt's reopening threshold (27.2 s), a growth that predates this order (main's own task read 72 to 94 s on 2026-10-09 before activation) and is recorded for planning in [D021](../../evidence/WO-198/decisions.md#wo-198-d021--final-review-pass-at-the-integrated-subject-the-receipts-cost-condition-recorded-for-planning).

**Validation.** Five verifications judged the order: [VER-001](../../verifications/WO-198/VER-001.md) to [VER-004](../../verifications/WO-198/VER-004.md) each met every criterion and failed on one defect in the diagnostic path, each repaired at its cause with its own regression (a malformed earlier snapshot, a damaged history archive, an unenumerable shared ref, and a comparison that withheld branch creation), and [VER-005](../../verifications/WO-198/VER-005.md) passed with twelve branch-transition scenarios, a 72-gate damage matrix against `HEAD` and nine Git ref states. This review found `main` at the order's base, so integration changed no judged byte; it re-ran the 17 WO-198 cases (17 of 17 in 13.16 s under the bounded runner), matched the reader against direct Git on the real corpus (153 annotated tags, newest `v0.73.0`, equal on all five values in 41.6 ms) and ran the publication, harness, release-surface, document-ceiling, index and format checks. `npm run test:docs` passes 32 of 32 suites in 122.59 s at the integrated tree; `npm test -- --review` at code identity `a5923da7…` composes a passing row of 38 suites in 7.82 s from the executor's fresh row at the same identity (90 fresh tasks, 1,731.7 s, exit 0) plus the always-fresh format preflight. Details are in [FINAL-001](FINAL-001.md).
