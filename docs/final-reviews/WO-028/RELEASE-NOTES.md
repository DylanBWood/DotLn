## Release overview

DotLn `v0.5.1` is the patch above the published `v0.5.0`. It makes time a recorded fact of the control log rather than a fact recoverable only from one machine. Every lifecycle transition now stamps its host wall-clock append time into the event as an optional `recordedAt` field; `status --json` and the Markdown projection expose the latest event's time and the elapsed milliseconds of each phase's latest completed attempt; and a new read-only `resume times` command labels every event's time by its source, so the 120 historical times that lived only in unpushed local checkpoint refs are preserved as a dated, committed observation instead of being lost with the machine. Audience: the operator reading control state, the lifecycle scripts that consume it, and the queued consumers that need a time (the whole-work-order effort-quality comparison, WO-021's control-plane beacon, and WO-026's index). The order's operator-authorized ideation breakout also corrects the Twelve Days of Christmas analogy, preserves two candidate supports (success under growth, and a bounded system baseline), gives the shipped Entropy Reducer an honest manual operator guide, and records the operator's Codex-actor and release-assignment defaults. The component packages are unchanged: `@dotln/compiler` `0.2.0`, `@dotln/kernel` `0.2.1`, and `@dotln/skeleton` `0.5.0`, with no `src/` change and no dependency added.

## Read before upgrading

- **New control events carry `recordedAt`; readers must tolerate both its presence and its absence.** Every event appended from this release onward carries `recordedAt`, an ISO 8601 UTC timestamp with millisecond precision and a trailing `Z`, placed immediately after `schemaVersion`. `schemaVersion` stays `1`. Historical events lack the field and are never rewritten; absence is valid pre-migration history. A present value that is not in the exact canonical form refuses at append (nothing is written) and at fold with the event's ordinal, so any tool that writes its own control events must emit that exact form or omit the field.
- **`status --json` gains two keys.** `recordedAt` is the latest event's time or `null`; `elapsed` is an object keyed by `implementation`, `verification`, `repair`, and `finalReview` whose values are signed milliseconds or the string `"unknown"`. A strict consumer that rejected unknown keys must accept them. `docs/control/current.md` renders matching `Latest recordedAt` and `Elapsed` lines, and a projection generated by the previous release now triggers the read-only staleness warning until the next legal transition regenerates it.
- **`statusProjection` takes the event array, not a folded state.** Callers of the helper exported by `scripts/resume.mjs` now pass the parsed events directly; `fold` remains exported. `scripts/worktree.mjs` and `scripts/release.mjs` were updated in this change and contain no parse of `current.md`.
- **The elapsed values are wall-clock spans that include waiting.** Each names the latest completed attempt of a phase, not a sum across retries, not model effort, and not operator attention. A negative value exposes a clock that ran backwards; it is reported, not repaired, and never affects legality.
- **Timing is published in this repository's public control profile,** deliberately, as commit dates already are. A stricter profile may omit the optional field or publish a bucketed or delayed observation with the loss of fidelity disclosed. No token, cost, or attention telemetry is added or authorized by the field.
- **The dated observation is a snapshot of the first 135 events.** `docs/discovery/control-event-times-2026-09-04.json` is byte-exact only for the log as it stood at activation; a bare `resume times` over a longer log does not reproduce it, and the file is not a backfill. Recovered times carry second precision and render as `.000Z`.
- **Operator defaults recorded on 2026-09-04.** Codex steps use GPT-6 Astra at `max` unless the operator says otherwise, recorded as operator-attested; release assignment is opt-out, so a work order receives a classified release target unless the operator specifies no release. Publishing a tag or Release still requires its own dispatch.

## Substantive changes

- **Control plane: `recordedAt` at append.** `scripts/resume.mjs` stamps every appended event with the host's UTC time and validates the value before writing; the fold validates any present value on every read and refuses a malformed one with its ordinal. Append order remains the only ordering and legality input: fixtures with the field removed, its values reversed across events, its keys reordered, or every value forced to one date fold to the same phase, legal actions, checkpoint advertisement, attestation, and drift.
- **Control plane: elapsed-phase projection.** The new `scripts/lib/control-time.mjs` derives `recordedAt` and `elapsed` from the event array, and `status --json`, `current.md`, `worktree.mjs`, and `release.mjs` all consume the common `statusProjection(events)`. A phase reports the latest completed attempt, a retry retains the preceding value until it completes, a new activation clears the entries, and an endpoint without the field yields `"unknown"`.
- **Control plane: `resume times`.** A read-only command that prints a JSON observation with one physical line per event, labeled `recordedAt`, `recovered-from-local-checkpoint-ref`, or `unknown`, together with the event count, the count of local refs read, the statement that those refs remain unpushed, and the second-precision caveat. Only an event's own named local checkpoint commit may supply a missing time. A missing ref, a ref outside the event's own work-order checkpoint prefix, a non-commit object, or a recorded-SHA mismatch refuses with an empty stdout and no change to the log, the projection, or any ref. Repeated runs are byte-identical because no observation clock is written.
- **Discovery: the dated recovery observation and its evidence.** `docs/discovery/control-event-times-2026-09-04.json` records the 135 events at activation: none recorded, 120 recovered from 120 local refs, and 15 unknown, matching the work order's observed gap exactly. The directory beside it holds the fixture transcript and three `for-each-ref` captures proving that the evidence run neither pushed, moved, nor deleted a checkpoint ref and that readiness minted exactly one.
- **Tests.** `scripts/test-resume.sh` adds the eight-type append sequence driven through the real dispatcher in one process, the invalid-host-clock refusal that leaves the log untouched, the time-blind masked `cmp` of `current.md` for absent, reordered, and backwards variants, mixed-endpoint, in-flight, retry, and activation-reset projections, and fifteen malformed shapes; `scripts/test-checkpoint.sh` adds the three-label recovery case against a real ref, the byte-identical rerun, five refusal shapes, and the no-git path. Every existing assertion is unchanged.
- **Product documentation for control time.** Architecture §Session lifecycle & resilience and the execution guide's §Model-specific notes carry the dated migration note; the guide's dispatch table gains the `resume: times` row; the playbook, the docs map, and the domain model's actor-attestation paragraph describe the field, the projection, the labels, and the public-profile choice; the ledger records the adopted append-time decision and the labeled recovery; the work-order map notes that WO-021 may consume `recordedAt`.
- **Ideation breakout (documentation only).** The README, Principle 4, and the inspirations register correct the Twelve Days of Christmas analogy to name cumulative startup and replay cost, with the superseded ledger entry named and left intact; the vision adds the candidate question of how a decision's success could create its own failure mode; the pattern library and roadmap preserve the candidate success-under-growth review and the candidate bounded system baseline as `vision`-status sections that select no collector, scheduler, threshold, or cadence; `docs/instance/entropy-reducer/README.md` documents the manual Claude Fable 5.1 `max` dispatch of the shipped reviewer, its frozen-subject and validation duties, the fresh blinded refutation, and the pending typed correction to the Shape-First support's literal-first wording; the roadmap, execution guide, and playbook record the operator's Codex-actor and release-assignment defaults; the ledger adds the dated breakout section.
