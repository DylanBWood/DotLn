## Release overview

A Codex session now holds the worktree's writer from its lifecycle dispatch to its completion without a step of its own. Each of the five Codex dispatches (`next`, `fix`, `verify`, `final-review`, `release-close`) reserves before it can append an event, every Codex completion releases, a refused session is told who holds the writer, for how long and how to release it, a session start reports an operator override left open in the same worktree, and `node scripts/harness.mjs evidence --wait` waits for a live gate and exits with its recorded outcome.

## Read before upgrading

A Codex lifecycle dispatch now refuses, before any event, when another session holds the worktree's writer and that holder is alive or of unknown liveness; release it from an operator terminal with `node scripts/harness.mjs writer --release`, adding `--force` when the owner is alive. A Codex dispatch in a checkout whose harness runtime is not built now refuses instead of proceeding with an advisory; run `npm run build` and retry. A Codex session killed before its completion command leaves its reservation in place, and only the operator release clears it. Release close is dispatched in the `main` checkout: a briefing requested from the subject worktree reserves nothing and directs a `main` session to run `npm run resume -- release-close --work-order WO-NNN` and then the helper in that same session. Rebuild `main` after pulling this merge and before a Codex release-close dispatch there, because a runtime built before this release lacks the reservation entry point and reads a pid-less owner as dead. Operator-control state written before this release records no worktree, so an override opened before the upgrade is not reported at a later session start.

## Substantive changes

The reservation's owner is the Codex host process found by walking the dispatch's ancestors, or a pid-less `thread` owner with unknown liveness when none is found; the npm or node process that exits with the command is never the owner, and a holder without a live pid is never reclaimed as dead. A dead pid-owned holder is still reclaimed and journaled. Every writer refusal, from the Codex dispatch, the Claude hook and the operator release, names the holder's actor prefix, owner, reservation time, age in seconds and the release command. `evidence --wait`, with an optional `--timeout` in seconds, returns when no live gate marker remains and prints the newest check row for the current tree: exit 0 after a recorded pass, 1 after a recorded failure, 2 at the timeout or with no row; an invocation that reused cached rows is judged by its own recorded outcome. The command is on the list a live gate admits, and under Claude Code it runs in the background. A failure to record the gate outcome prints an advisory and never changes the gate's exit code.
