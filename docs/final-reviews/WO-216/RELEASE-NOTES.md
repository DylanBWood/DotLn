## Release overview

Application v0.84.0 makes every gate judge its own bookkeeping before it spends a minute on a suite. Each `npm test` selection and `npm run test:docs` now begins with six structural tasks in a fixed order, `format`, `configuration-root`, `registrations`, `declarations`, `generated` and `host`, which finish in about thirty seconds before a build or any suite starts. A structural failure stops the run there and names the one remedy: `npm run sync` for a stale generated artifact, the suite and path for a missing declaration, the sampled values for host memory pressure. A failed task of any kind stops the scheduler from starting more, running tasks finish and are recorded, and the row lists what never started; `--keep-going` restores the old behavior for independent work. It serves the executor and verifier, who no longer pay a complete run per handoff, and the final reviewer, who pays it once.

The visible changes:
- `npm run sync` regenerates every derived artifact that policy allows, in dependency order and only when its check reports stale, prints one table (artifact, before, after, action) and changes nothing on a second run; it refuses, naming the route, a role oracle without its authorizing decision, a feedback edition whose judged sources changed and manual baseline fingerprints, and it reports a check that timed out as unknown without running its writer.
- `implementation-ready`, `repair-complete` and `verification-result` consume the structural row, the `--only` row of every suite the order's **Preflight:** field names and the document row, all passing at the current code identity; a passing complete row still covers them. `final-review-result pass` requires one fresh complete `npm test -- --review --again` row recorded after that review's `FinalReviewRequested` event, with no reused suite, and records the newest standing one.
- A run stopped by request, SIGINT, SIGTERM or SIGHUP after a task completed records one row with `stopped: true` and only the completed tasks, which supplies no pass; a stop before any completion records nothing. An execution that finished after its row was recorded supplies no pass either.
- `node scripts/harness.mjs evidence --wait` reports the awaited run's own row and verdict, never the structural companion row every runner gate records beside it.
- Gate rows keep no passing output at any depth; a failed check's output stays an addressed log. Rows at this order's final identity average about 23 KB against about 350 KB at the identity the first final review measured.
- The launchpad suite runs as three file lanes (export and verify, update and refresh, seeds and staging), two at a time, each under its own 900-second deadline, with the same 29 cases.
- The executor, verifier and reviewer role text in both roots states the new handoff sequence, and the kit README, product 07 and the playbook state three rules an exported instance met during its registration order: an instance may commit the operator grant its registration writes, `worktree clone` accepts an id the running checkout declares and records it in main's ignored clone map, and `worktree start` carries the main checkout's ignored local-terms list or prints the registration step.

## Read before upgrading

- **`npm test -- --review` at final review must be `--again`.** A composed review row reuses results and never supplies the final-review claim; `final-review-result pass` refuses until a fresh complete review row recorded after the review's `FinalReviewRequested` event stands at the current code identity, and a later failed fresh run displaces it ([D006](../../evidence/WO-216/decisions.md#wo-216-d006--consume-focused-rows-at-handoff-and-a-fresh-review-row-after-dispatch), [D030](../../evidence/WO-216/decisions.md#wo-216-d030--repair-f2-the-newest-standing-fresh-review-row-after-the-dispatch-supplies-the-final-review-claim)).
- **Handoffs stand on the Preflight field.** An order whose **Preflight:** field names no `--only` token hands off on the structural and document rows alone; the queued orders WO-217 to WO-220 name their suites in prose and are a planning obligation before WO-217 activates ([D021](../../evidence/WO-216/decisions.md#wo-216-d021--retain-the-queued-order-and-handoff-policy-planning-obligations), FUP-17266e5072d4a25a). A queued order's older instruction to follow Preflight with a complete run is read under the new rule.
- **A failed structural task is never bypassed.** `--keep-going` continues independent work after a failed suite but not after a failed structural prerequisite; `host` refuses to start a run at warning or critical memory pressure and records the sampled values, which happened live during the repair when two launchpad lanes ran nested kit gates ([D025](../../evidence/WO-216/decisions.md#wo-216-d025--verification-planning-receipt-046s-criterion4-and-criterion9-reopening-conditions-for-wo-216-have-occurred), FUP-90ebeaae273ae404). An unavailable sample reads `unknown` and admits.
- **The structural phase is paid per selection.** Each focused and document run carries about thirty seconds; this order's own rows paid it 96 times, about 47 minutes, against a 545-minute per-order gate baseline. The five closes after this order read the recorded instrument (FUP-182984d482ca59ca); any statistic not below its baseline reopens the design ([D011](../../evidence/WO-216/decisions.md#wo-216-d011--judge-cost-after-five-closes-with-the-recorded-instrument)).
- **`npm run sync` never mints a role oracle or a feedback edition that needs a live episode.** It names the route instead; a regenerated authority, artifact-identity, verification or harness edition is a new revision and the previous one is retained.
- **Handoff document claims stand on the latest passing document row at the code identity, which excludes documents.** Binding that row to the tree, or restoring the inline document gate, is a planning question, with the launchpad lanes' lost exclusive reservation, the stopped row written before tasks abort, the sync fixture's branch dependence, the build receipt digesting the tree after publishing and the playbook's gate paragraphs ([D027](../../evidence/WO-216/decisions.md#wo-216-d027--final-review-fail-final-001-the-await-misreports-criterion-11-refuses-a-standing-fresh-row-and-the-index-keeps-passing-output)). Five hand-kept fixture copy sites still lack a copied-fixture declaration, and `registrations` loads the compiled kernel before the build and the freshness check (FUP-9de14a69403e2b32, [D032](../../evidence/WO-216/decisions.md#wo-216-d032--bounded-follow-ups-taken-in-this-repair-and-the-two-left-with-a-follow-up)).
- **An exported instance's Preflight line names only suites the instance runs.** A core-only row such as `outward-lint` never appears there; the publication commands apply the instance vocabulary and the local-terms list themselves ([D028](../../evidence/WO-216/decisions.md#wo-216-d028--operator-scope-expansion-fix-the-kit-gaps-a-v0830-launchpad-met-during-its-registration-order)).
- **One operator packet and eight further follow-ups boarded by the final review** ([D034](../../evidence/WO-216/decisions.md#wo-216-d034--final-review-pass-final-002-at-the-integrated-subject-one-operator-packet-and-ten-follow-ups-two-corrected-in-this-review)), none blocking, with two document sentences corrected in the review. The one an operator meets first: release close's `worktree finish` copies this worktree's gate rows into main's live index, and the 154 rows recorded before the output-stripping repair hold about 50 MB of passing timeline output; before the close the operator decides whether to strip them under override, change `finish` in a separate order, or accept the growth until 200 later rows move it to the archive. The rest: the remaining test cases FINAL-001 asked for on the completion transitions; `npm run sync` running an evidence writer on any failed check and leaving an orphan edition when its re-check fails; no in-repo case for the local-terms carry on the self-start route or the clone record's siblings-declaration route; the harness host's stop message naming an older stopped row; the release writer not declared under `sync-fixtures`; a kit's first suites naming `format` rather than `kit-verify` as predecessor; the document gate building the base for tasks that never ran after a fail-fast stop; and the playbook's verification paragraph.
- **Versions.** Application v0.84.0 is a minor release over v0.83.0, assigned at activation under the order's classification. ## Substantive changes

**The structural phase** (`scripts/test-runner.mjs`, `scripts/structural-checks.mjs`, `scripts/lib/generated-artifacts.mjs`, `scripts/lib/machinery-coverage.mjs`, `scripts/lib/host-resources.mjs`, `scripts/lib/build-freshness.mjs`). `STRUCTURAL_TASKS` is a fixed ordered list; `classifySuite` marks the six rows structural, `expandSuiteTasks` puts them in every other task's `after` for every selection, and `scheduleSuites` runs them serially before the build or any suite. `generated` composes the existing `meta`, `lineage`, `index`, `release-surfaces`, `siblings`, `harness`, evidence, console-fixture, baseline-fingerprint and `publication` checks with a role-oracle comparison that requires the named case to execute, each as a child case with its own thirty-second deadline, and a runtime freshness receipt the build writes; those rows leave the document gate, which lists no second copy. `declarations` runs `uncoveredMachinerySources` over the whole suite table and every copied-fixture closure declared beside its fixture in a `.fixture-inputs.json` file that the fixture itself consumes when copying. `host` reads the kernel's memory-pressure sample and refuses warning or critical.

**Fail-fast, stopped rows and ordering** (`scripts/test-runner.mjs`, `scripts/lib/gate-reuse.mjs`). After the first failed task the scheduler starts no further task, cancels pending host-lane waits, lets running tasks finish and records them; the row gains `unrunSuites`, `stale` and `failedFirst`, and the printed remedy follows the failure's kind. A stop by request or signal after a completion writes the stopped row synchronously from finished results and the stop message names it. `identityRows` drops stopped rows before any lookup; `latestExecution` orders a finish later than its row's `recordedAt` at that `recordedAt` and `decidingPass` refuses it. Every recorded row is stripped of passing output at every depth of `cases` and `taskTimeline`.

**One regeneration command** (`scripts/sync.mjs`, `package.json`). `syncArtifacts` walks the shared inventory in order, checks each artifact, runs its writer only when stale, re-checks, and reports `regenerated`, `none` or `refused` with the route; a new evidence edition takes the next revision for the selected order and switches `docs/evidence/current.json`; publication locks are rewritten from `check-publication.mjs --print-locks`; `release sync-surfaces` regenerates the owned README claim from the assigned target without retiming it.

**The handoff claims and the final-review gate** (`scripts/lib/handoff-ledger.mjs`, `scripts/lib/lifecycle-evidence.mjs`, `scripts/resume.mjs`). `readPreflightSuites` reads every `--only` token of the **Preflight:** field; `preflightRows` returns the latest passing `--only` row per suite at the identity and names displaced tasks; `requireGateClaims` records the three completions on the structural, Preflight and document rows with their evidence references when no complete row covers, refusing by name otherwise and naming `npm run sync` then a passing structural phase when a structural task was displaced; `requireFinalReviewGate` searches the standing candidates for the newest fresh review row recorded after the latest `FinalReviewRequested` event; the verifier briefing names the Preflight suites.

**The await and the stop message** (`scripts/harness.mjs`, `packages/skeleton/src/harness-host.ts`). `evidence --wait` chooses the latest row at the tree whose check is not `structural`, so a tree holding only companions reads as no run; `evidence --stop` and the host's stop text say that completed tasks are recorded as stopped and supply no pass, and the harness host's stop message names the stopped row the nested runner recorded when one exists.

**The launchpad lanes** (`scripts/test-launchpad-export.mjs`, `scripts/test-launchpad-update.mjs`, `scripts/test-launchpad-seeds.mjs`, `scripts/lib/launchpad-fixture.mjs`, `scripts/fixtures/launchpad-cases.json`). The 29 cases move into three files by their groups with shared helpers in one fixture module; `expandSuiteTasks` turns the `launchpad` row into one `launchpad:file:` row per file with two load slots and a 900-second deadline each; the original entry remains an import wrapper, and the `runner-fixtures` suite checks the case-name set against the base inventory and declares the files it reads.

**The kit items** (`scripts/test-authority-grants.mjs`, `scripts/lib/target-worktrees.mjs`, `scripts/worktree.mjs`, `scripts/kit/README.client.md`). The committed grant registry must be empty in core, and in an exported instance every committed grant must be operator- or registered-repository-granted, with a synthetic kit case; `recordRepositoryClone` accepts an id the main checkout or the running checkout declares and records into main's ignored clone map; `completeSelfStart` and the target start carry the main checkout's local-terms list into the new worktree or print the registration step.

**Role text and generated surfaces** (`packages/skeleton/src/loadouts/contributor.ts`, the six skills, the harness manifest, `packages/skeleton/fixtures/wo216-role-baseline.json`). The executor runs the structural phase, `npm run sync` and the Preflight suites and never the complete gate; the verifier consumes those rows and probes with `--only`; the reviewer starts `npm test -- --review --again` in the background after integration and awaits it with `evidence --wait`; the 34 surfaces are regenerated and the role oracle pins both support settings with the chain through `wo215-role-baseline.json` byte-exact.

**Fixtures.** `runner-fixtures` gains the selection, declarations, host, fail-fast, output-stripping, chronology, stop-route and launchpad-lane cases; a new `sync-fixtures` suite (`scripts/test-sync.mjs`) covers the role-oracle check, stale naming, dependency order, second-run byte stability, the three manual refusals, the timed-out check and a real-inventory copy damaged artifact by artifact; the `resume` suite covers the three handoff routes and the final-review gate's fresh, composed, failed-fresh, old, plain, reused and wrong-identity rows; the WO-166 wait case and the WO-125 F3 gate-lock case carry the companion row; the kit cases above; the WO-179 and WO-195 emitted-roles case expects the new verifier sentence.

**Documents.** Product 07's §Preflight before the full gate body, the two §Discipline bullets, the Standard artifacts clause, the completion, verification, instance and parallel-order passages, §Operator resume phrases and §Where the control plane finds its documents, the playbook's clone-map paragraph, the kit README's first steps and selections, and the evidence README's base observations, timings, case lists and handoff rows change in place.
