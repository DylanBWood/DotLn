## Release overview

DotLn `v0.10.0` is the minor release above the published `v0.9.0`. The walking skeleton gains its first real out-of-process worker. An opt-in demo hands the shared Seiri inspection scenario's single executor step to a real Claude Code or Codex CLI process, launched fresh with an explicit model, effort where the host exposes it, the narrowest observed settings boundary, auto-memory and session persistence disabled, no model tools, and schema-bound output, inside a detached, verified, clean Git worktree that mounts one synthetic inventory read-only. A durable JSONL host under one exclusive lock records every lifecycle step before the shared reactor advances, checks the child process every second, renews a five-second lease only while it is still valid, enforces a three-minute invocation deadline, and publishes each validated completed result as an immutable receipt before the command is acknowledged. A kill, crash, or expired lease leaves the compiled WorkOrder, its continuation, and the pending command intact; the next run either queries the durable receipt without another model call or starts a distinct fresh episode, and a result that arrives after authority expiry is persisted and quarantined without touching candidate state. `dotln status` projects the store read-only from another process while a worker runs. An unavailable model fails closed after exactly one launch with no fallback flag, and a store refuses a different model, effort, or transport than the one it first pinned. The default demo, the verifier, and every other actor remain deterministic fakes, and the dispatching session receives only the six-field result envelope. Audience: the operator running a bounded real inspection on an authenticated machine, and the orders that consume a real episode next (independent verification in WO-010, Senses in WO-022). Kernel `0.2.1` and compiler `0.3.0` are byte-identical to `v0.9.0`; the walking skeleton advances to `0.9.0`.

## Read before upgrading

- **Live runs are opt-in and gated.** `dotln demo` and `npm run test:workers:live` require `DOTLN_LIVE_WORKERS=1` on an authenticated runner that permits child CLI execution and nested sandboxing; the always-run suite uses synthetic subprocess peers and real Git only and needs no authentication.
- **Both transports pin an exact host version.** `ClaudeCliPrintWorkOrderTransport` requires Claude Code `2.1.261` and `CodexCliExecWorkOrderTransport` requires Codex CLI `0.153.4`; any other installed version refuses with `profile-refused` until the canonical launch shape is re-probed and re-pinned. A routine CLI upgrade therefore stops the real transports on purpose.
- **Effort is host-specific.** Claude requires one of `low`, `medium`, `high`, `xhigh`, `max`; Codex requires `unknown` because the installed host exposes no dedicated effort selector, and the adapter refuses to map any other value onto a config override. Effective model and effort are recorded `unknown` on every attempt; accepted launch flags are launch claims, not readback.
- **A store pins its first selection.** The first run writes `WorkerHostConfigured` with the model, effort, and transport; a later run with a different selection refuses with `persisted worker selection differs; no silent model substitution`.
- **A new ignored root.** `/.runtime/` is gitignored for local stores, synthetic demo repositories, and result receipts. It is not on the release-close disposable list, so a demo run inside a work-order worktree leaves a non-disposable ignored directory that must be removed by hand before that worktree can be closed.
- **New runtime events.** `WorkerHostConfigured`, `CommandRedispatchRequested` with `workerDispatchVersion: 1`, `WorkerAttemptStarted`, `CommandReceipt`, `WorkerHeartbeat`, `WorkerLeaseExpired`, `WorkerInterrupted`, `WorkerResultRecovered`, `WorkerResultObserved`, `WorkerResultQuarantined`, `WorkerCompleted`, and `WorkerWorktreeRemoved`. `WorkerResultObserved` and the marked redispatch request are program-consuming and pass through the pinned-artifact comparison; a `CommandResult` carrying `workerResultVersion: 1` is admitted only by the same guard. The event-envelope schema stays `1`, the reactor state gains `workerEpisodeId` and `workerLeaseExpired`, and historical logs and the deterministic fake scenario's bytes are unchanged.
- **Skeleton API additions.** `LiveReactorDriver` accepts an optional `persistEvent` callback invoked before the in-memory log advances; `runScenario` is split into exported `startScenario` and `finishScenario`, and `projectScenario`, `restoreScenarioOpening`, and `ReactorStep` are exported. `@dotln/skeleton` gains a `dotln` bin; the root gains the `dotln`, `probe:workers`, and `test:workers:live` scripts.
- **What the worker sees.** The prompt is the compiled WorkOrder, the pinned artifact receipt, the episode and result ids, the mounted inventory, and fixed output instructions; it contains no transcript history. The WorkOrder's `repo` field is the absolute path of the inventory inside the store's worktree, so a vendor receives a path under the operator's chosen store root. The child inherits the host's environment so the CLI broker can authenticate; nothing from it is logged or stored.
- **Cleanup never forces.** A worker worktree with tracked, untracked, or ignored changes is retained with `dirty worker worktree retained for inspection`; a torn log, an invalid host lock, or an abandoned `host-lock-recovery` guard refuses for inspection and is never erased or truncated.

## Substantive changes

- **Worker transports (`packages/skeleton/src/worker-transport.ts`, `worker-protocol.ts`).** `WorkOrderTransport.dispatch(request, now)` returns separate promises for a `CommandReceipt` and a validated `WorkerResult` plus host-only `alive` and `kill` handles. Claude's canonical shape is `--print`, the required `--model`, the declared `--effort`, `--output-format json`, the inline `--json-schema`, `--no-session-persistence`, `--setting-sources project,local`, `--settings '{"autoMemoryEnabled":false}'`, `--tools ""`, `--disable-slash-commands`, `--safe-mode`, `--strict-mcp-config`, `--mcp-config '{"mcpServers":{}}'`, `--no-chrome`, and `--max-budget-usd 1.00`; Codex's is `exec --ephemeral --ignore-user-config --strict-config`, the required `--model`, `--json`, `--output-schema` naming a private schema file, and `--cd` naming the worktree, with a named read-only filesystem profile, command network disabled, memories, project instructions, MCP, web search, and shell environment inheritance turned off, and 23 features disabled. Neither supplies a fallback model. Raw harness output is captured in a private temporary file bounded at one megabyte with stderr bounded at 64 kilobytes, decoded, validated against the request (exact work-order, episode, and result ids; candidate paths present in the inventory; bounded single-line strings; no extra keys), and discarded. Unsupported versions, unavailable models, invalid outputs, refused profiles, deadlines, output limits, and interruptions are typed `WorkerFailure` codes.
- **Worker host and store (`worker-host.ts`, `worker-store.ts`).** The host checks the existing compiled recovery decision before any adapter runs, refuses a pending command whose WorkOrder differs from the replayed state, allocates a distinct physical episode id per attempt, records the attempt with transport, harness version, model, effort, `selectionSource: "host-launch"`, `effectiveModel`/`effectiveEffort` `unknown`, heartbeat and lease policy, profile, and pinned artifact identity, heartbeats only while the child is alive and the lease is unexpired, kills the child when a lease is missed, publishes a validated completed result as an immutable receipt keyed by command and bound to the whole stable request, persists `WorkerResultObserved` before admission, quarantines a refused observation, and records `CommandResult` and `WorkerCompleted` at the admission time. The store fsyncs each append, checks the next event id, requires regular files, holds a pid lock that a dead host may reclaim once through a serialized recovery guard, and refuses torn logs without truncation.
- **Reactor (`reactor.ts`).** `WorkerResultObserved` and a `CommandResult` marked `workerResultVersion: 1` pass a guard that requires the marked receipt, the pending command's id, no prior result, unexpired authority, the current worker episode with an unexpired lease, and an away operator; any refusal is a traced `NoOp` in the `worker-result-guard` reactor whose branch path is the event type, `quarantine`, and the reason, with the authority envelope in `envInputs`. `CommandRedispatchRequested` with `workerDispatchVersion: 1` refuses the same way on expired authority or a returned operator. Lease expiry and attempt start are folded into state; historical fake-result semantics are unchanged.
- **Worktree lifecycle (`worker-worktree.ts`, `worker-demo.ts`).** Detached worktrees are created from an immutable base commit under a host-owned directory, verified for root, common Git directory, exact base, detached state, path shape, symlink absence, and cleanliness including ignored files, and removed without `--force` only after re-verification. The demo creates a synthetic fixture repository with a fixture identity and disabled hooks and signing, pins the compilation environment to the inventory path and base commit, and records `WorkerWorktreeRemoved` after cleanup.
- **Status CLI (`dotln.ts`, `worker-status.ts`).** `dotln status` with `--store` and optional `--json` folds only stored events into episode phases (`starting`, `running`, `interrupted`, `lease-expired`, `completed`, `quarantined`), heartbeat and lease timestamps, pending commands, and eight recent event headers; it consults no clock, appends nothing, and creates no missing store. `dotln demo` is gated by `DOTLN_LIVE_WORKERS=1`, requires an explicit transport, model, and effort, prints exactly the six-field envelope on success, exits 1 on an incomplete envelope, and reduces every other failure to a fixed sanitized message.
- **Scenario and demo (`scenario.ts`).** The deterministic scenario's opening and completion are shared with the real demo, so the fake verifier, structural deletion refusal, episode termination, verification, and queued-pulse cancellation run identically for both; a restarted host reuses persisted suffix events rather than replaying effects; a completed store can be queried again without dispatch.
- **Discovery and evidence.** A bounded host probe records installed versions and help-visible controls, flags a newly appearing Codex effort selector, and, with `--sandbox`, proves the named permission profile allows a mounted read and denies an unmounted read and a mounted write. The gated live suite records authenticated runs, forces one Claude termination, witnesses status from another process, recovers a fresh episode, and runs Codex. `docs/evidence/WO-009/` holds the sanitized live receipt with both six-field envelopes, the probe, the deterministic and full-suite transcripts, and two labeled earlier failures; the discovery addendum and its JSON block record the observations and the `unknown` effective values.
- **Documentation.** The domain model's transport, envelope, lifecycle, and admission text; the architecture's status banner, disposable-inspection-host paragraphs, and canonical launch shapes; the roadmap's `v0.10.0` rung, dated activation completion, and implementation receipt; the compatibility document's host protocol axes; the roles table; the capability table's dated reassessment; the planning map; the publication index and both edition locks; the ledger's three adopted entries; the root README release block; and the skeleton README's disposable-workers runbook.
