## Source review

`worker-store.ts` carries the order. The small combinators are the right shape: `object` refuses arrays and `null` as well as non-objects; `exact` compares sorted key lists, so a foreign field is refused rather than ignored; `atPath` wraps a decode with the path and shape, which is what makes every refusal message name its file; `present` uses `lstatSync(..., {throwIfNoEntry:false})` rather than `existsSync`, and the comment says why — a dangling symlink is observed for refusal instead of read as absent. `decodeReceipt` is the substantive decoder: exactly `requestKey` and `result`, a lowercase 64-hex key, an envelope with exactly its six fields, an identifier-shaped `episodeId` and `status === "completed"`. `acquire` does the work in the right order — replay and decode the log, decode every persisted command and capsule, scan the directory for receipts and refuse any `.pending`, run the caller's preflight, then require that every receipt found on disk was loaded during it, and only then touch the lock. That last gate is the part a reader should not miss: a receipt that no caller can reconstruct a request for is refused rather than silently ignored, which is what makes the inventory's claim about request keys true.

The host changes are a pure relocation plus an extraction. `WorkerHost.preflight` and `VerificationHost.preflight` build exactly the request the dispatch path builds and call `store.loadResult` before any `record(...)`; `run` then consumes `{request, cached}` instead of constructing its own. `verification-host.ts` keeps the `expire()` call after the preflight, which is correct — expiry must not run before the store has been judged. `preflightVerificationRecovery` replays the full log and validates every historical capsule and result against the caller's pinned model, effort, mount and optional feedback, which is why it needs the caller's context and why `acquire` takes a callback rather than doing it alone. The three callers pass that callback: `verification-demo.ts`, `feedback-selfhost.ts` and, for the inspection side, `worker-demo.ts`, which additionally reconstructs each request at its original `CommandPersisted` boundary so that a completed history with no pending command still gets checked. `worker-demo.ts` also refuses a persisted `WorkerHostConfigured` payload that disagrees with the current selection — "no silent model substitution" — which is a decoded-value refusal in the same spirit as the rest and inside the objective's "recovery-time" scope.

`read-paths.md` is accurate about what it covers and, more to the point, about what it does not: it states plainly that this is "shape/correlation validation, not authentication against a writer able to replace both state and evidence", and that the guarantee "concerns malformed stored artifacts at entry under the existing single-writer protocol". Those two sentences are the difference between an honest inventory and an overclaim, and the write-back to 03 keeps the same scope in one sentence.
