## Release overview

DotLn v0.21.1 makes a recovering worker host inspect everything it is about to trust. A disposable inspection or verification host reclaims a dead predecessor's store by reading files that predecessor left behind — an event log, a host lock, saved result receipts, staged but unpublished results, persisted commands and verification capsules — and until now only some of those were positively decoded on the way in. The host lock was parsed and cast with a single pid check; saved receipts were validated when written but not when read back; a leftover `.pending` staging file was quietly deleted. This release decodes each of them against an explicit shape before recovery changes anything, and when a value does not match, the host refuses with the path of the file and the shape that failed and leaves every byte in place. For an operator, the visible difference is that a corrupted store now stops recovery at the read with a message naming the file, instead of being partially acted on and then failing somewhere less obvious.

## Read before upgrading

Source release target v0.21.1 includes skeleton 0.18.1. Kernel 0.4.0, compiler 0.11.1, console 0.1.6 and every third-party dependency are unchanged from v0.21.0; the lockfile diff is the single skeleton workspace version. No event schema, persisted contract, semantic hash or artifact identity moves, and no recorded data is rewritten or migrated. No package distribution or hosted service is introduced.

One behavioural change needs an operator's attention before upgrading. **A leftover `.pending` staging file no longer self-heals.** Previously `saveResult` unlinked an unpublished staging file and continued; it now refuses by path, and so do `loadResult` and recovery, until someone inspects the file. A crash in the narrow window between writing the staging file and linking it into place therefore leaves that command's store wedged rather than recovering on the next run. This is deliberate — unpublished bytes that may look like a successful result are evidence, and deleting them is the operator's decision, not the host's — and the recovery step is simply to read the file and remove it once you know what it contains. The skeleton README carries the runbook note.

**Custom callers of `WorkerStore.acquire` must supply request context.** `acquire` now takes an optional read-only callback that runs inside the acquisition guard, and after it runs, any saved receipt found on disk that was not loaded during that callback is refused. The shipped hosts reconstruct each receipt's original request from the persisted command and the caller's pinned fixture, model, effort and mounts. Code that called `acquire()` with no callback and relied on receipts being read later will refuse at recovery; the fix is to pass a callback that calls `loadResult` for each persisted command, as `worker-demo.ts`, `verification-demo.ts` and `feedback-selfhost.ts` now do.

Two limits are worth knowing. A refusal raised inside the acquisition preflight is prefixed with the event log's path before the offending receipt's path — both files are named in the message, but the leading one may not be the file you need to open. And the read-path inventory's tripwire, which fails the build when an unguarded filesystem read is added to the three hosts, identifies reads by the text of the call expression, so a module-local rebinding such as `const bytes = readFileSync` would escape it; no such read exists in the current source, and the inventory's manifest comparison pins the complete read set independently.

## Substantive changes

**Worker store — positive decoding before any recovery effect.** `acquire` replays and decodes the event log, then decodes every `CommandPersisted` command and any saved verification capsule through `assertVerificationTask`, the `WorkerAttemptStarted`, `WorkerHeartbeat` and `WorkerLeaseExpired` payloads for canonical ids and a finite lease expiry, and every `cmd_….result.json` in the directory — requiring exactly `requestKey` and `result`, a lowercase 64-hex request key, an envelope with exactly its six fields, an identifier-shaped producing episode and a completed status, with evidence results re-checked against their saved capsule. Only then is the host lock read, as an object with exactly `pid` and a positive safe integer. Presence is tested with `lstat` rather than `existsSync`, so a dangling symlink is observed and refused instead of being read as absent, and refusal messages carry the file path and the shape that failed.

**Worker and verification hosts — the cached result is loaded before the first event append.** Both hosts gained a `preflight` that builds exactly the request the dispatch path builds and loads the cached result through it; `run` consumes that result rather than constructing its own. A malformed receipt is therefore discovered before `CommandRedispatchRequested` or a lease-expiry event is written, so a refusing recovery appends nothing. Attempt numbering and cache identity are unaffected: request keys exclude the episode id, and only an attempt-start event creates an episode.

**Recovery callers — contextual validation inside the acquisition guard.** `preflightVerificationRecovery` replays the full log and validates every historical capsule and result against the caller's workstream, model, effort, mount and optional compiled feedback. The inspection demo reconstructs each request at its original persist boundary, so a history that completed and no longer has a pending command is still checked, and it refuses a persisted host configuration that disagrees with the current model, effort or transport rather than substituting silently.

**A malformed-state corpus and an executable read-path inventory.** Thirty-three declared shapes drawn from the crash-shape families — truncated JSON, a success-shaped receipt for another command, a wrong result version, a missing envelope field, a foreign key, a non-object — plus malformed lease tails, dangling symlinks and direct already-locked host calls, run against real stores seeded through the shipped hosts. Each case asserts that the refusal names the path and shape, that no dispatch occurred, that no result was accepted, and that a full recursive snapshot of the store including symlink targets and file bytes is unchanged. Alongside it, a committed manifest lists every filesystem byte read and JSON parse in the three host modules with its decoder and consumer, and a test walks the source to fail both when a read is added without a manifest entry and when a raw read sits outside a path-named decoder.

## Progressive polish

Documentation and generated-surface refreshes accompany the release: the architecture document's session-lifecycle section gains one sentence on the read-path guarantee beside the existing disposable-inspection-host paragraph, the skeleton README gains the recovery runbook note, the roadmap records the v0.21.1 activation and its retiming, both publication table-of-contents editions gain a line on malformed-state refusal and have their source locks refreshed, and the decisions index and follow-up projections carry this order's three decision records. The regenerated harness bundle differs from v0.21.0 only in runtime pins — the `skeletonVersion` literal, the runtime snapshot identifier and each hook's content hash — with no change to any hook's behaviour, the hand-written Clean Room floor or the skills.

Final review: [FINAL-001](FINAL-001.md) integrated v0.21.0 and retimed the release, re-derived the episode-numbering and request-key invariants that the relocation depends on directly from source, re-ran the order's own suites and the unchanged fixtures on the integrated tree, regenerated the two evidence editions integration had invalidated, and recorded the reviewer product gate: `npm test -- --review`, 27 suites, 0 failed, 662.64 s, 70 fresh tasks.

Known limitations: a leftover `.pending` file wedges its command's store until an operator inspects it, by design; preflight refusals lead with the event log's path before the offending receipt's; the inventory tripwire misses a module-local rebinding of an imported read function; `preflightVerificationRecovery` is stricter about capsules than `acquire` on a path that appears unreachable but was not proven so; and log payloads outside the decoded set keep only the event envelope's validation, which remains outside this release's scope.
