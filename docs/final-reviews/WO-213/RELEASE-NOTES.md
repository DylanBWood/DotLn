## Release overview

Application v0.83.0 keeps absolute home paths out of every committed record and makes an exported instance's ordinary gates check what the instance consumes rather than rerun the platform's regression fixtures. A new or edited line that names a home directory in a JSON, JSONL, log or text record under the document roots now fails `npm run test:docs` at its file and line without printing the path, as a Markdown line already did; the follow-up register projects the home placeholder (the word `home` in angle brackets) in place of a home path; the planning-receipt helper and the four planning-event writers refuse unsafe content before they write; and the records an order writes into a registered target's documentation root, with a planning publication's title, commit message and body, pass the same screen before anything is written, committed or posted. Existing filed records stay as written. It serves the operator whose records are public once published, the operator of an instance whose `npm test` no longer pays for platform fixtures, and the maintainer of a target repository that must never receive a private path through the workflow. A validation system with task-level reuse was built under a later expansion of the same order, failed four verifications and was withdrawn before this release; nothing of it ships.

The visible changes:
- `node scripts/docs-check.mjs` reads `.json`, `.jsonl`, `.log` and `.txt` files under the configured document roots beside Markdown, in any letter case and by bare suffix; a new or edited line naming `/Users/` or `/home/` followed by an account name, including one written directly after a JSON escape, fails with the message `absolute home path in a record`, which asks for a repository-relative path or the home or worktree placeholder, while a private temporary path in a record passes and Markdown keeps its full rule and message; every document reader refuses an unreadable, dangling or non-file input, a link to a directory included, by its repository-relative path and error class, without system-path or parser excerpts, and a FIFO cannot hang the gate.
- The activation baseline declares the 291 record lines in 37 files that held a home path at the base as historical fingerprints; the retained script that computed them refuses a matching line absent at the base, so the baseline cannot be widened by hand.
- The follow-up register substitutes the home placeholder at projection on every host until nothing matches, so the projection is a fixed point and an adjacent chain of home prefixes projects to placeholders; its one stored revision that held a path was rewritten in place by the order's sync with its hash, ref, title, dispositions and status unchanged; a check-mode sync refuses as stale before such a rewrite and passes after it; a union with a branch that still holds the raw revision resolves to the rewritten one.
- `npm run plan -- receipt`, the hold, disposition, amendment and withdrawal commands, `npm run resume -- target-records` and `npm run plan -- target-publish` refuse a record, event, title, commit message or body that names a private path before any write, commit, remote call or control append, naming the part and line and the placeholder remedy, never the path.
- In an exported instance, `npm test` and `npm test -- --review` select `kit-verify` and `harness`, run them fresh as document-kind gate runs and bind the row to the installed runtime's digest; `npm run test:docs` selects the seventeen current coordination checks; shipped platform fixtures run only under an explicit `--only` or `--machinery`; sibling work is proven by the registered target gate alone.
- Runtime inputs follow one policy in selection, digest, inventory, export prediction, snapshot copy and snapshot check: the declared regular workspaces of a valid lockfile, their package metadata and their compiled `dist` or build-free `src`, with execute permission bound as one boolean and bin targets marked executable at build; dot-prefixed entries and `.tsbuildinfo` are left out, other ignored runtime bytes still count, ordinary files directly under `packages/` are ignored, and a symbolic link, a non-regular declaration or a workspace missing on disk refuses by relative path. The harness runtime snapshot is named by that inventory and checked entry by entry, with a refusal that names the snapshot directory and the remedy; a kit prepares its carried runtime for a release without a source build and previews from that installation.
- Integration in a kit verifies the kit instead of building, treats a dangling or unreadable optional declaration as an error rather than as absent, refuses a blocked evidence ancestor before retiming a release and records a selection failure as a pending step the continuation can recover; `reader profile` supplies the balanced default where no profile is declared and reports a dangling link at the profile path as a malformed declaration.
- A `resume:` phrase followed by a newline or a semicolon dispatches and keeps the direction that follows it; a session with no role that runs the whole foreground `npm run resume -- next`, `fix`, `verify`, `final-review` or `release-close` command successfully is bound to that role, while an observed `release-close` never keys the publish admission and a manual `harness begin` refuses every existing state path; `amend-order` refuses for a never-judged seed order and names the decisions route; the meter of an open order in a linked worktree also reads the registered `main` checkout's observations, deduplicating only a copied journal's shared prefix; host-lane waits count the lock waits, record path-free holder observations and reject the acquisition cleanly when a wait notification fails.
- `release.displayName` in `dotln.config.json` names an instance's releases: fresh exports seed `DotLn-Enterprise-Starter`, an absent setting keeps `DotLn`, a declared name is bounded at 64 characters and refuses a lone surrogate, each release keeps the name configured at its release commit, a first export preserves a committed configuration, an ignored local configuration refuses before publication, and starter refresh preserves the instance's configuration or its absence.

## Read before upgrading

- **Records that hold a home path fail the document gate.** An instance whose own committed `.json`, `.jsonl`, `.log` or `.txt` records name an absolute home directory fails `npm run test:docs` after taking this release until the executor of its next order corrects those lines in place on the operator's dispatch and records it in the order's decisions; no instance command computes baseline fingerprints, and this release reaches back into no target repository's history ([D003](../../evidence/WO-213/decisions.md#wo-213-d003)).
- **Seven write paths refuse an input they accepted before.** A planning receipt whose rendered Markdown holds a home or private temporary path, or whose written JSON holds a home path, is refused before any write; so is a hold, disposition, amendment or withdrawal event whose text holds a home path, a record bound for a target's documentation root, a target-scoped planning or product document, and a planning publication's title, commit message or body. Each refusal names the part and line; the role rewrites its own text with the home, worktree or tmp placeholder the refusal names. Nothing is redacted ([D005](../../evidence/WO-213/decisions.md#wo-213-d005), [D006](../../evidence/WO-213/decisions.md#wo-213-d006), [D024](../../evidence/WO-213/decisions.md#wo-213-d024)).
- **Records refuse the home class only.** A private temporary path in a record still passes, because the Entropy Reducer records its frozen copy's temporary path in hash-chained receipts; `/var/tmp` and `/root` stay outside the pattern as before, a home path written after an ANSI control sequence or an escaped solidus still passes the record rule, and the test runner's task record still carries `productReadLog` as an absolute path, so a copied gate record needs a placeholder ([D002](../../evidence/WO-213/decisions.md#wo-213-d002), [D007](../../evidence/WO-213/decisions.md#wo-213-d007), [D024](../../evidence/WO-213/decisions.md#wo-213-d024)).

While an instance's `npm test` or review runs, writes to the active order's evidence, verification and final-review directories are refused; write that evidence before the gate or after it passes. The instance's first order still needs its observed harness smoke, and a sibling's implementation is proven only by `node scripts/target-gate.mjs WO-NNN` ([D009](../../evidence/WO-213/decisions.md#wo-213-d009), [D014](../../evidence/WO-213/decisions.md#wo-213-d014), [D025](../../evidence/WO-213/decisions.md#wo-213-d025)).
- **The runtime snapshot is renamed and checked whole.** The harness bundle regenerated by this release's update names its snapshot from the complete package inventory of the declared workspaces, with the executable bit bound as one boolean and bin targets marked executable at build, and `harness check` compares every file, directory, mode and workspace link of the snapshot; a snapshot altered by hand refuses as differing from its inventory, naming the snapshot directory and the remedy (remove it and run the build bootstrap), while Finder metadata and compiler bookkeeping inside a package are ignored and a release in a kit restores a missing selected snapshot from its verified carried packages before publication. A lockfile-declared workspace missing on disk refuses by its relative path ([D019](../../evidence/WO-213/decisions.md#wo-213-d019), [D021](../../evidence/WO-213/decisions.md#wo-213-d021), [D032](../../evidence/WO-213/decisions.md#wo-213-d032)).
- **Dispatch recognition widens; the publish admission does not; manual session entry narrows.** `resume: next` followed by a newline or a semicolon and further direction now dispatches where the phrase alone did; a quoted, continued or punctuated phrase stays prose. A Claude session that holds no role and runs the whole foreground `npm run resume -- next|fix|verify|final-review|release-close` command successfully is bound to that role after the hook observes the expected control state; wrapped, backgrounded, failed and interrupted commands and a response reporting failure never bind, and a failed read of either canonical snapshot skips the binding with one advisory. An observed `release-close` binds the session but never sets the field that keys WO-178's admission of the byte-exact publish helper; only the operator's `resume: release close` phrase records that dispatch. A manual `harness begin` for a session whose state path exists now refuses instead of adopting it; only the lifecycle's own automatic entry upgrades a valid roleless state ([D016](../../evidence/WO-213/decisions.md#wo-213-d016), [D024](../../evidence/WO-213/decisions.md#wo-213-d024), [D033](../../evidence/WO-213/decisions.md#wo-213-d033)).

The repair counts the first and final lock waits and keeps bounded path-free observations for the next recurrence ([D017](../../evidence/WO-213/decisions.md#wo-213-d017)).
- **The withdrawn validation expansion.** Between the second repair and this release the order carried criteria 15 to 19, a validation system that derived suite dependencies from source, let single-suite passes compose the complete gate and reused tasks across a fix.
