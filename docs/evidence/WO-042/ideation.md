## Composed decision

- **Adjacent Repair** is a selection preference for the Contributor's
  executor/fixer: prefer a bounded repair to an encountered bug over deferring
  it solely because it predates the work order or was not explicitly assigned.
- **Decision Receipts** contributes decision documentation: evidence, choice,
  rationale, rejected options and reasons, and a reversal condition for any
  deferred choice. It supplies no preference for repair.
- **Follow-up Queue** retains diagnosed fixes in order and applies veto,
  reprioritization, scope revision, known-issue and deferral dispositions.
- **Intent to Act** is the default communication support: announce the concrete
  next action in chat, then proceed within existing authority. Observation and
  Recommendation are alternative communication supports, not co-equipped modes.
- **Operator Check-In** supplies the safe boundary before the next queued item:
  process available operator steering and reread the queue without interrupting
  a command already in flight or turning every decision into an approval request.
- The existing Clean Room active, permission guard, bounded Boy Scout guard,
  output review and application-evidence supports retain their own jobs. Neither
  new support grants effects, judges its own implementation, or adds a hook.

The atomic supports link to Clean Room in the Contributor build and emit through
the existing prompt-fragment mechanism into the executor procedure for

their procedure. This is an explicit rung-7 instruction projection; deterministic
