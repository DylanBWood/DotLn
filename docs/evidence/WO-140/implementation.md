## Delivered behavior

- **Sandbox preflight.** `skeleton` declares `needs: outside-sandbox`. `scripts/lib/gate-sandbox.mjs` recognizes a harness by its marker (`CLAUDECODE`, `CODEX_SANDBOX`) and establishes a sandbox only by a denied exclusive create in the path that sandbox protects (`.claude/hooks`, the resolved Git directory). Every present marker is probed; only `EPERM`, `EACCES` or `EROFS` reads as a sandbox; no marker, a missing directory, a permitted write, a refused removal and a throwing probe all fail open. When the write is denied and the selection needs the outside, `npm test` refuses before the build and every suite, names the suites, and prints the command that runs the same selection outside and, when anything would remain, inside. Only a selection that needs the outside pays for the probe.
- **Partial identity.** `--inside-sandbox` drops the declared suites and records `npm test -- --inside-sandbox` with `partial` and `excludedSuites`, never `npm test`. `findGateCheck` and `reviewedProductGate`, the two functions behind the gate lookup, the lifecycle transition, pull-request publication and release close, reject a row that is partial or names exclusions under any identity.
- **Usage readback.** Every role dispatch briefing prints `DotLn session: <id>. Usage readback: node scripts/harness.mjs usage <id>`, in the exact form the usage guard admits; a Codex session receives the same line from its session report.
- **Role text.** The verifier and reviewer skills say the product gate runs outside the harness sandbox from the start in an attended session, that a resident-launched verification records a partial result, and how the cost line is written.
- **Receipt cost line.** `verify` and `final-review` stamp `costLine: "required"` on the receipt they allocate. A stamped receipt carries exactly one physical `**Process cost:**` line with entry and handoff counters and their source, or exactly one cause code from the closed list `hooks-fallback`, `no-session`, `harness-no-readback`. The result transition judges it beside the actor header, while the author can still edit; `npm run test:docs` refuses it afterwards through `meta --check`. Unstamped receipts, which is every receipt that existed before this order, are never judged.
