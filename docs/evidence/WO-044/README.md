## Cost finding for the next planning pass

Most of this session's executor work was machinery rather than the order's
deliverable: re-recording four evidence editions because they embed component
versions (one requiring a live audit), regenerating twenty-four harness
surfaces, raising byte ceilings, the sandbox's protected paths, and queue
ceremony. The operator named this directly. It is recorded here as a
planning input, not repaired in this order.

Suite reuse never helped this session: every full gate ran cold (82 fresh
tasks, 0 reused) because nearly every fixture suite declares the whole
`scripts/` directory as an input, so one edited script re-keys them all.
The recorded reuse fix (canonical permission bits) is correct and necessary,
but it only restores reuse between runs that change no script. The planning
inputs are: narrow suite declarations to the files a suite actually loads,
drop fixture count pins that force a test-file edit for every added suite,
and key evidence editions off content rather than component versions so a
version bump alone does not demand a live audit.

VER-002 and the operator's second scope expansion (2026-09-14) confirmed and
extended this. A fourth reuse cause belongs beside the three above: the
application-level `test:full` gate check is keyed to the whole tree hash
including `docs/` (`gateTreeHash`), while per-suite keys already exclude docs,
so a verifier's report or control-event edit invalidates the executor's green
gate and forces a cold re-run — this is why "nothing was reused in the verify."
Making `test:full` reusable across doc-only and control-only changes is a
reuse-key contract change (it alters what the gate certifies) verifiable only by
full cold gates, so it joins the coupled planning inputs rather than an ad-hoc
repair; see decision D016. Shipped bounded in this order instead (D014): the
harness evidence runner now honours the lifecycle contract, so a failing verdict
records only `git diff --check` and no longer drags the full suite gate — this
removes the cold gate on the fail path. The separate "gate over and over" loop
the operator saw was a convention violation — gate counters written into the
tracked report body re-key the just-run gate — not a code defect; the
freeze-at-cutoff / cite-completion-event convention already stated in the role
skills and the pass message is the fix, which `--fail` now cheapens even when a
session violates it.
