The [skeleton module](../../../packages/skeleton/src/github-issue-source.ts) exports `fetchIssueBundle(repo, number, { directory, cwd? })` and `requireCompleteIssueBundle(result)`. The caller supplies the forge repository and local store. The kit-relative bridge reuses `executeGh` and `parseGitHubTarget` without requiring a repository checkout.

```ts
const result = await fetchIssueBundle(repositoryUrl, issueNumber, {
  directory: sourceStore,
});
const completeInput = requireCompleteIssueBundle(result);
```

The result contains the decoded bundle, hash, `ready` or `stopped` status, omission/absence receipt and stored paths. Canonical bundle bytes live under `fnv1a64-<hex>.json`; each distinct receipt has its own content-addressed filename beside it. Existing unequal bytes or symlinks refuse instead of being replaced. A stopped result can retain unaffected items. The consumer guard throws `IssueSourceRefusal` with code `incomplete` and the refused item, role-omitted comment or absent field. Failed CLI/JSON/field reads store nothing and name a sanitized reason and, for malformed fields, the API path.

`ISSUE_SOURCE_FIELDS` declares the issue, comment, author, edit and connection fields. Each connection is paginated independently; repeated cursors refuse. Equal issue/discussion snapshots bracket the read. The issue's `updatedAt` supplies the revision. Duplicate IDs refuse at their API fields, and history is ordered chronologically by `editedAt` with an ID tie break. Authors become reporter, reviewer or automation roles; Bot actors and the declared `[bot]` suffix identify automation.

Only current title/body text enters `sections`; only current comments enter `discussion`. Every comment left out because its role cannot be determined has an `omitted` receipt entry with its local ID, API path and `undetermined-role` reason. Missing issue authors therefore name every affected human comment individually while independently identifiable automation remains eligible. These omissions stop the result.

GitHub's observed `UserContentEdit.diff` carries a full version, with versions newest first and the newest equal to current text. The [fresh public observation](history-observation.json) found this in all 14 sampled edited subjects; VER-001 observed it in 11 subjects. This is sampled executable evidence, not a documented universal guarantee. The documentation's description of `diff` as a summary did not justify the original interpretation; D003 is corrected in place and D008/D011 preserve the error and correction.

Each full historical version is screened in memory, with text-free refusal metadata retained, but its text is never stored or used as a current section. Receipt history contains only ID, edit time and subject ID. Revisions use conservative whole retained subject spans in current coordinates: title/body for issue edits, and the current entry for comment edits. Missing or refused current items contribute no spans; a role-omitted comment's revisions have empty spans. These spans are coverage, not exact historical diff offsets. Full versions could support a finer mapping, but that is unnecessary for this repair and is explicitly deferred until a consumer needs it.

Every retained text item and each historical version passes WO-060's existing decoder with the parsed forge host as the whole allowlist. Refused text is absent from stored bytes; receipts keep only local ID, shape, field path and span. Missing/unavailable declared fields remain explicit. The declared shapes bound this claim; unrecognized strings can pass. Raw CLI replies, diagnostics, author logins and target selectors are not added as metadata. Source text itself can contain such references.

Image references come only from retained current Markdown/HTML, retaining their original spans and `contentHash: "unavailable"`. The API supplies no verified image-byte hash, so `bundle.images` stays empty. Historical images add no content or reference spans. No image download, forge mutation or model invocation occurs. D002's FUP-0113 reading still leaves the exposure-plan candidate at the first consuming model/private-material boundary.
