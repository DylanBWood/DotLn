# WO-284 handoff: implementation and the repair of VER-001

An instance now sets every time limit of its gate in one file, the kit's own figures leave room for a slower machine, and a tree that is already green is not run again. The limits are one table, `packages/skeleton/src/time-limits.mjs`, read by every step on the gate path; `docs/control/time-limits.json` changes them and `npm run limits` lists them. An instance's gate loads its own configuration in place of the kit's configuration tests. The closeout selection says when the complete run is already satisfied, and the runner answers a forced rerun at a green identity with the standing row. Since the repair, a pass counts only under the time limits it ran under.

This is the executor's handoff after the repair. Verification and final review are separate phases. The branch has no commits; it commits at final review.

## Read first: the repair of VER-001

- [VER-001](../../verifications/WO-284/VER-001.md) failed criterion 1. After a passing run, a supported change to `time-limits.json` left the earlier results reused and standing. A raised key resolved, but the reused task record kept the old figure. A lowered `scale` left the closeout saying the complete run was satisfied, and `--again` ran nothing, though the same task, once run, was ended for time.
- The rule the repaired code holds ([D032](decisions.md#wo-284-d032--a-pass-recorded-under-other-time-limits-is-neither-carried-nor-standing)): a pass says what it says only under the time limits it ran under. A gate row records them as one digest of every figure that applies, none where each is the kit's, and records whether they changed before it ended. A pass is reused, and a complete row stands, only from a row that ran under the limits in force. The rule sits in the two lookups every reader goes through, so it reaches the runner's reuse, its answer to a forced selection, the closeout's satisfied form, a completion's claims and focused rows, the final review's claim, the document row and the evidence command's cache. A row under other limits is still an execution: a later run under any limits displaces an older pass. The digest covers figures, not bytes, so a note, a refreshed `kit` or a `set` equal to the kit's figure changes nothing, and reuse after a change to documents alone is kept.
- The class is covered beyond the cases the report quoted. The new cases cover a raised key, a scale either way, one limit off and `enforce: false`, each after a pass, at a core root and at an installed instance. They also cover an edit that changes no figure, setting the kit back after a later run, a change made while a run is live, the closeout through the real briefing, and a target order's classification of the file. A four-second suite that passed under the kit's figures is run again under a lowered figure and is ended for time, where reuse would have answered for it. The verifier's own reproduction exits 0. Both new runner cases fail when the rule is taken out.
- [D033](decisions.md#wo-284-d033--criterion-1-was-judged-met-from-fresh-runs-alone-a-change-to-the-file-after-a-pass-was-not-examined) records the executor's error: criterion 1 was first judged met from fresh runs alone.
