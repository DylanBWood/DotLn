# DotLn v0.2.0 — patch notes

Layered edition over the release manifest (`docs/releases/v0.2.0.md`), the
WO-003 lineage, and the verification sequence. Source-only release.

## Release overview

**The walking skeleton walks.** DotLn now runs a complete agentic vertical end
to end — intent, bounded authority, cadence, execution, structural refusal,
independent verification, replay — against deterministic fakes, with no model
in the loop. That is the point: it proves the kernel's *shape* is real before
anything unpredictable is plugged into it.

Audience: the operator, and anyone evaluating whether the architecture holds up.
Run `npm run skeleton` and watch a Repo Gardener equip a maintenance contract,
wake on a schedule while you're away, propose evidence-backed deletion
candidates, get structurally refused when it reaches for deletion, and fade when
you return — then replay the whole thing from the log to identical decisions.

## Read before upgrading

Nothing to migrate: this is the first tagged release and there is no prior
installed version, no saved artifact format, and no published package.

Operator-relevant behavior worth knowing:

- **`worktree finish` now refuses on any non-disposable ignored file**, not just
  `docs/intake`. A stray `.env` will block cleanup by design — it names the
  offending path and points at `npm run backup:intake`. It never deletes or
  auto-promotes raw material; reconciling worktree intake into the main checkout
  stays a deliberate operator step.
- **Every `resume` transition now writes a recovery checkpoint** before it
  appends (`refs/dotln/checkpoint/<WO>/<n>`), so mid-loop uncommitted work has a
  restore point. These refs are **local-only** — never pushed, gone on a fresh
  clone.
- **Gitignored intake can never be covered by a checkpoint.** `npm run
  backup:intake` remains the only durability mechanism for raw material.
- **Authority:** the kernel structurally refuses commands outside an authority
  envelope. Refusal is an event, not a politeness — code depending on a denied
  effect silently succeeding will not get it.
- Source-only. A Git tag here implies no npm, binary, container, or hosted
  distribution.

## Substantive changes

**Kernel and skeleton vertical.** The 13-step Repo Gardener + Seiri scenario
runs live and replayed from its JSONL log to identical decision traces. Bounded
work orders are emitted transport-neutrally; a crash after command persistence
recovers through the kernel's outbox exports, re-dispatches from the durable
log, and the adapter dedupes on namespace-tagged command ids so the effect
happens once. Operator return folds into state, cancels future pulses, and turns
an already-queued pulse into a traced no-op.

**Control plane.** An append-only control log (`docs/control/resume.jsonl`) with
a generated projection replaces per-work-order copy/paste bookkeeping. A fresh
session resolves a bare `resume:` phrase to the active work order and the exact
artifacts it must read. Illegal phase transitions refuse and append nothing.

**Operator tooling.** Guarded worktree lifecycle (start / publish / finish),
validated owner-only intake backup, and the immutable numbered artifact
convention for verification and final-review reports.

**Safety guards** (from the repair addendum, both driven by a real incident):
recovery checkpoints before every control-log mutation, and the widened
ignored-material refusal that closed a reproduced `.env`-deletion hazard.

**Product documentation.** IR compatibility horizons, agent-originated product
suggestions, release-note editions, and the execution guide's resume protocol.

## Progressive polish

Aggregated: documentation wording alignment across the playbook, execution
guide, and docs map so narrative descriptions match the shipped guards; test
fixtures corrected to inherit the repository's real `.gitignore` (a fixture bug
that had made a real hazard inexpressible); config-log and receipt entries
back-filled with disclosure. No item in this group changes observable semantics,
compatibility, authority, recovery, or a required operator action — the fixture
correction is called out above rather than hidden here because it changed what
the suite can detect.
