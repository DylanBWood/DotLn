## Supported ranges

The kernel reads and writes event-envelope schema `1` only; `scripts/resume.mjs`
reads and writes control-log schema `1` only. Neither accepts a range, and no
transformation set exists to migrate between versions.

The cadence algebra ships as a complete set of *types*, but only part of it
evaluates at this release. Evaluable: `Once`, `After`, `Every`, `Gate`, `Until`,
`Backoff`. Deferred — constructible, and throwing
`Cadence <kind> evaluation is deferred` on evaluation (`core.ts:22`): `Burst`,
`Calendar`, `Window`, `While`, `Sequence`, `Merge`, `Race`, `Repeat`. Program
evaluation has the same shape, with its own deferred default (`core.ts:53`).

## Known limitations

Carried from the verification sequence and final review; none blocks the
release, and all are recorded rather than implied.

- **Fakes only.** Deterministic fake executor and verifier, one fixture repo. No
  model integration and no real executor at this rung — that is the rung's scope.
- `packages/skeleton/src/cli.ts` has no automated coverage; the CLI payoff is
  proven by execution, not by test.
- The scenario is never driven to a negative (verifier-rejects) outcome by any test.
- `AuthorityEnvelope.requiredEvidence` is empty in the skeleton, so the kernel's
  evidence gate is inert — "evidence per candidate" is not structurally enforced.
- Checkpoint assertions cover 2 of the 9 checkpointing resume actions
  (`R1-COVERAGE`); the shipped code was proven correct by a full-lifecycle drive.
- `worktree publish` throws a raw `TypeError` if `gh` is absent — after the
  branch is already pushed (`WT-6`).
- `worktree finish` half-completes if a merged branch has no upstream:
  `--unset-upstream` throws after the worktree is already removed.
- The four shell suites are macOS-only (`stat -f`, hardcoded `/private/tmp`);
  they fail loudly rather than silently elsewhere.
- **Recovery checkpoints are local-only.** `refs/dotln/checkpoint/*` is never
  pushed and does not survive a fresh clone; gitignored material under
  `docs/intake/` can never be covered by a git checkpoint —
  `npm run backup:intake` remains its only durability mechanism.
