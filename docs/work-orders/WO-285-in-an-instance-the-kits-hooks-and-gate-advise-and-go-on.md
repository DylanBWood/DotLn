**Objective:** A session working in an instance, in its launchpad or in a
registered sibling repository, is not denied a tool call, and an
instance's gate does not fail, for a reason that guards the kit's own
records, order or form, a host property or a bound: the hook or the task
says what it found, names the stop and what it protects, and the work goes
on. A stop that guards the owner's work or private material from loss or
exposure that cannot be undone refuses as it does today. Each stop has an
id, and the instance's owner sets any of them to `refuse`, `advise` or
`off` in `dotln.config.json`; the features page lists every stop with its
class, its level and where that level comes from. Core, which builds the
starter, refuses as it does today, and the same page shows those refusals
as core's own choice. No refusal message, role text or emitted instruction
sends a person to `operator override:` to get past a stop.

**Design (scope discipline):**

- A stop's class decides its level in an instance, and the class is what
  the stop protects. A work row (the census's 28: another session's
  uncommitted work, a write outside the project, the six denied effects, a
  private term or an unreviewed change being published, an update or an
  integration that would drop the owner's edits) refuses in an instance as
  in core. A record, host or bound row (the other 111) advises in an
  instance and refuses in core. Which root is which is `isKitRoot`, as the
  runner already asks. Rejected: nothing refusing in an instance by default
  (axis: what cannot be undone; an overwritten file, a published term and a
  rewritten user setting are not recovered by an advisory, and the
  operator's own example of a useful stop is of this kind). Rejected: every
  stop refusing in an instance as today with only a switch added (axis:
  reach; a new owner is stopped by the kit's bookkeeping before learning
  that a switch exists, which is what the work instance met five times).
- The class of a row is written in the table and read from the census; the
  executor does not re-class a row. A row this pass marks as doubtful
  (the attribution rule, rows S27 and S41, which WO-286 treats as one of
  the author's units) keeps its present behavior here.
- Row S30 is split: an effect the compiled authority names as denied is a
  work row; an effect it merely does not list is a record row.
- A stop that already has a switch keeps it and its default: desktop
  control, plan-first, the starter update's in-session request, instance
  actions and the verbatim screen (rows S01, S02, S06, S50, S69, S70, S123,
  S124). A refuse-class entry of the owner's private terms list refuses at
  any level: the owner wrote it. A time limit is set by WO-284's file, not
  here.
- The table of stops is data in one build-free module,
  `packages/skeleton/src/stops.mjs`, shipped as the worker table's modules
  are: an id, the class (work, record, host or bound), what it protects in
  a phrase, and its switch where it has one. The emit resolves each level
  from the root's kind and its configuration and writes it into each
  hook's configuration, launchpad and target, as it does the
  desktop-control and plan-first values. The host deny rules the emit
  derives from the denied effects (ssh, scp, sftp and a package publish,
  rows S03 and S04) follow their stops' levels as well: at `advise` or
  `off` the rule is not emitted, since a host rule denies before any hook
  can answer. Rejected: reading the configuration in every hook call
  (axis: cost per tool call, which WO-272 measured and cut).
- A stop is one row however many places enforce it, and every place
  reads that row's level, so that an owner who lowers a stop is not met by
  its twin. The dispatch bound is enforced by the hook (S16), by the
  bounded wrapper before it starts its child (S90,
  `scripts/lib/bounded-command.mjs` 59), by a re-dispatch
  (`requireRedispatchBound`, `scripts/lib/dispatch-bound.mjs`) and by the
  gate's structural row (S102). The worker cap and the driven budget are
  enforced by the hooks (S17, S18, S37), by the review helper before a
  Codex launch (`admitCodexLaunch`, `scripts/lib/review-worker.mjs`) and
  by the driver before a phase (`scripts/lib/drive-session.mjs`). Ssh and
  a package publish are each denied by a host rule (S03, S04) and by the
  hook's denied effect. A command reads the level from the root's
  configuration when it runs; a hook has it from the emit.
- `protocolRefusal` takes the stop's id and answers by its level: a denial
  at `refuse`, the advisory at `advise`, nothing at `off`. Each launchpad
  refusal site names its id. `runTargetHarnessHook` gives each reason its
  id and answers the same way, and where the launchpad's hook journals a
  judgment without showing it (the commonest classification gaps), the
  target's hook does the same. A target hook that cannot reach the
  launchpad's runtime allows the call and says that nothing there is being
  judged and which command restores it, since a guard that cannot run
  protects nothing by denying everything. A stop at `refuse` in a target
  worktree honours the recovery controls as the launchpad's does.
- In the runner a failure names the stop it is. A task that holds one
  check names its stop. A task that holds checks of more than one class, as
  the document check holds record checks and the private-path screen
  (rows S110 to S124), reports each failure with its own stop's id. In an
  instance a task is recorded as advised, with its output, when every
  failure in it is at `advise`, and the selection goes on to the tasks
  after it and passes; a task with one failure at `refuse` fails, naming
  that failure, and prints the others as advised. A structural row is
  treated the same way. A task ended for time is no stop of this table: it
  fails as WO-284's file says, whatever the level of its checks.
- The `stops` section holds `"<id>": "refuse" | "advise" | "off"`. An
  unknown id or value is named in one advisory and ignored, and in an
  instance an unknown `features` key is treated the same way, so a
  mistyped line stops no command.
- The features page lists the stops in place of "Not electable": id,
  class, what it protects, its level here, where the level comes from (the
  kit, or this root's configuration) and the line that changes it. In core
  each row reads `refuse` as core's own choice.
- A refusal that remains says its id and the configuration line that
  lowers it. The three texts that name the recovery override as a route
  past a refusal name the setting instead, and the sentence in every
  `CLAUDE.md` says where the levels are. The recovery controls stay what
  they are: `analysis:` and `operator override:`, the operator's last
  resort for pushing something through whatever state the repository is
  in (the operator's word in this pass, journal digest
  `5715e710a470b4e836468382dc2f47a68946060b98de608f31e544d263eeb3f4`). The
  override reaches a target worktree's hooks, which it does not today.
- A lifecycle command that declines its own job (a publish without a
  reviewed change, a close of an unmerged order, a record that would
  rewrite a verdict: rows S42 to S93) is not changed here, apart from a
  bound's own admission inside a command, which is its stop's. Each is listed
  on the features page as a command's refusal with its way forward, so
  what remains is in the open. Rejected: converting them in this order
  (axis: risk; each needs its own answer to what going on means, and the
  hooks and the gate are what stop work in progress).
