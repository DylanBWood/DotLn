**Design (scope discipline):**

- The counting rule, stated here from WO-034: a context restatement is an
  operator message in the run whose substance is already in the fork's
  committed `WS-001`, repository profile or emitted skill (the verifier
  cites the file); a manual handoff is any step between two sessions not
  produced by a printed handoff; an unnecessary interruption is a decision
  packet the verifier finds answerable from committed files; time to a
  trusted return state is the elapsed time from the run's last session end
  to the receipt's `resume: status` showing the next legal action. The
  verifier counts restatements and handoffs from the run's transcripts and
  control log, never from memory; the other two are counted or `unknown`.
- The baseline, stated here from WO-034: the operator's own records of the
  separate-session practice, selected before the first member order
  activates and named by SHA-256, each with the measure it supports, in a
  pre-run baseline block appended to that order's evidence before
  activation. A record not named there is not a baseline, and a recalled
  number is `unknown`. The baseline half is an operator attestation,
  labeled as such, never recounted and never called observed; unmeasured
  values are `unknown`, never a baseline.
- The build is the priming: the receipt lists every vision restatement the
  executor needed by hand, each naming the file or build element that
  should have carried it, and reports from the fork's hook logs which
  compiled units fired and which refusals occurred.
- The target receives one conventional pull request; the launchpad's
  vocabulary stays in the launchpad, and the worktree-local harness bundle
  never enters a target commit.
- The receipt holds sanitized copies of `WS-001` and the profile with the
  fork commit they were read at and each file's SHA-256, so the verifier
  judges them here. Transcripts are committed as text or Markdown, or as
  JSONL only in a form `scripts/check-registrations.mjs` admits.
- The Angular consumer's registry entry changes only through WO-078's
  generator (its once-per-sibling declaration or a receipt), never by hand.
- A run fails when its pull request is not opened through the workflow,
  when a measure is not lower than its observed baseline, or when the
  priming claim is recorded failed; its receipt is still recorded
  (assumption 1).
- **Declined alternatives, recorded:** building the shell in this
  repository; a first Angular order that is a phase table; judging
  `WS-001` and the profile in the fork (a verifier here reads this
  repository; reopen if the copies cannot be sanitized); a hand-edited
