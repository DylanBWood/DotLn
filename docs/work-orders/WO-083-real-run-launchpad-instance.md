**Design (scope discipline):**

- The counting rule, stated here from WO-034: a context restatement is an
  operator message in the run whose substance is already in the instance's
  committed `WS-001`, repository profile or emitted skill (the verifier
  cites the file); a manual handoff is any step between two sessions not
  produced by a printed handoff or by the router's dispatch; an unnecessary
  interruption is a decision packet the verifier finds answerable from
  committed files; time to a trusted return state is the elapsed time from
  the run's last session end to the receipt's `resume: status` showing the
  next legal action. This repository's verifier counts restatements and
  handoffs from the run's transcripts and control log, never from memory;
  the other two are counted or `unknown`.
- The baseline, stated here from WO-034: the operator's own records of the
  separate-session practice, selected before the order activates and named
  by SHA-256, each with the measure it supports, in a pre-run baseline block
  appended to this order's evidence before activation by the planning pass
  that moves this order into the next pair; the operator supplies each
  record then, and an unsupplied value stays `unknown`. A record not named
  there is not a baseline, and a recalled number is `unknown`. The baseline
  half is an operator attestation, labeled as such, never recounted and
  never called observed.
- The build is the priming: the receipt lists every vision restatement the
  executor needed by hand, each naming the file or build element that
  should have carried it, and reports from the instance's hook logs which
  compiled units fired and which refusals occurred.
- The route is whatever core drives orders with at the time: the router
  (`drive: WO-NNN`, WO-192) launching each phase's worker in the target
  worktree from the instance, or the resume phrases in hand-opened
  sessions; either counts as the route, and the receipt records which.
  Intents are an additional entry point, never required (operator
  correction 2, 2026-10-11).
- The target receives one conventional pull request; the launchpad's
  vocabulary stays in the launchpad, and the worktree-local harness bundle
  never enters a target commit.
- The receipt holds sanitized copies of `WS-001` and the profile with the
  instance commit they were read at and each file's SHA-256, so the
  verifier judges them here; sanitization is recorded as a list of the
  removals made, and a removal never merges or drops a counted event.
  Transcripts are committed as text or Markdown, or as JSONL only in a form
  `scripts/check-registrations.mjs` admits.
- The Angular consumer's registry entry changes only through WO-078's
  generator (its once-per-sibling declaration or a receipt), never by hand.
- A run fails when its pull request is not opened through the workflow,
  when a measure is not lower than its observed baseline, or when the
