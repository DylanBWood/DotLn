## Findings

All five are non-blocking observations. None requires repair before final
review.

**F1 — the dated observation is not reproducible by a bare `times` run.**
Because the log has grown past 135 events, `npm run resume --silent -- times`
no longer matches the committed file. The executor receipt says so explicitly
and the file carries `eventCount: 135`. The final reviewer should reproduce it
by folding only the first 135 events, which is what this verification did. No
change is required; this is inherent to a dated observation and is a non-goal
to backfill.

**F2 — `checkpointRef` shape is validated only when recovery needs it.** An
event that already carries `recordedAt` passes `times` without its
`checkpointRef` being examined. This is consistent with the field's purpose and
with `fold`, which has never validated ref shape. No behavioral risk observed.

**F3 — a git failure during a required recovery loses the ordinal.** If `git`
is unavailable *and* an event's time must be recovered, the raw git error
surfaces instead of a line-scoped refusal. The contract still holds — it
refuses rather than guessing — and the shipped no-git case correctly covers the
all-`recordedAt` path where no ref is read. Only the message is less specific.

**F4 — `at line N` is an event ordinal, not a physical line.**
`parseControlEvents` filters blank lines before indexing, so the new
`invalid recordedAt at line N` message would diverge from the physical line
number if the log ever contained a blank line. This is pre-existing behavior
from WO-018, applied here consistently with the existing parse and unknown-type
messages. Time-indexed as not a WO-028 defect.

**F5 — one bounded narrowing of operator intent in the ledger.** The operator
raised the possibility that the success-under-growth question "always follows a
decision". The ledger and pattern library render this as a review attached to a
material decision inside the existing process, explicitly declining to add a
mandatory handoff after every small edit. That is a defensible bounded reading
and the entry is `preserved` rather than `adopted`, so nothing is settled by
it; it is recorded here so the operator can widen it if the narrowing was not
intended.
