## Findings

**F1 — a malformed earlier snapshot crashes a failed gate before it records (blocking: breaks behavior `main` had).** Low severity: the gate still exits non-zero, so no false pass is possible.
- **Observed.** `sharedRefChanges(before, after)` guards only a missing `before` (`scripts/test-runner.mjs:1906-1907`), then reads `before.tags.count` (`:1916`). It runs in the failure block before `recordGateChecks` (`:2525`).
- **Reproduction** (`forged.mjs` and `forged-compare.mjs`, host scratchpad, under `harness bounded`):
  - The fixture has a one-commit repository, a `build` task and a `beta` task that fails while `fail-beta` exists.
  - Before the run, I record a failed `npm test` row one second earlier with `sharedRefs: {start: {}, end: {}}`, then repeat with an `end` that has `originMain`, `main` and `dotlnRefs` but no `tags`.
  - Subject: `runGate(["--serial", "--again"])` rejects with `Cannot read properties of undefined (reading 'count')`, and the index keeps 1 `npm test` row.
  - `HEAD` `b06c6081` (scripts and skeleton source from `git archive`): exit 1, and 2 rows, in both cases.
  - A `null` or string `sharedRefs` is tolerated by both.
- **Why it matters.** Product 07 tells the verifier to vary forged and stale records. The index is a local file that later schema changes, damage or a hand edit can reach. The crash removes the failure row and the summary line, which this order's diagnostic depends on.
- **Rule a repair must hold.**
  - A snapshot that lacks `originMain`, `main`, a `tags` object with `count` and `newest`, or `dotlnRefs` supplies no baseline, the same as a legacy row without `sharedRefs`.
  - The failed row is still recorded with exit 1 and its summary.
  - A runner fixture records an earlier same-check row with `{start: {}, end: {}}` and one whose `end` lacks `tags`, runs a failing gate, and asserts exit 1, a recorded failed row with its own four-field snapshot, and no throw.
