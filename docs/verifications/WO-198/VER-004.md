## Findings

**F5 — the repaired comparison withholds changed fields that both snapshots read (blocking: criterion 2 unmet).** Low severity: the line is diagnostic, and the gate's exit code and row are unaffected. The route is blocking because the line is what criterion 2 judges.

- **Observed.**
  - `sharedRefChanges` (`scripts/test-runner.mjs:1927`) skips a branch whenever either side reads `absent` (`:1935-1937`).
  - `readSharedRefs` (`packages/skeleton/src/gate-evidence.mjs:497`) maps every failed `rev-parse --verify`, whether the ref is missing or unreadable, to `absent`.
  - So a missing branch and a damaged read look the same, and both go uncompared.
  - Separately, `completeSharedRefs` (`:1905`) rejects a snapshot whose count reads `absent`, so one degraded enumeration withholds every other field's comparison.
- **Reproduction:** `absent.mjs` and `mixed.mjs` (host scratchpad, under `harness bounded`), as listed under criterion 2. Checkpoint 12, extracted with `git archive`, is the control.
- **Why it matters.**
  - The order's design records `origin/main` and `main` as "commit ids (or `absent`)" and prints the line when "at least one field differs". `absent..<id>` is such a difference.
  - A first push or fetch that creates `origin/main` needs no repository damage. That is exactly the sibling activity whose effects this order exists to attribute.
- **D012's limit does not hold.** D012 rejected reporting a branch that becomes `absent` because "resolution alone cannot distinguish a missing branch from an unreadable object". `gitmatrix.mjs` (direct Git 2.55.0) shows otherwise:
  - `rev-parse --verify --quiet <ref>^{commit}` exits 1 when the ref is missing, dangling or names a tree, and 128 when `packed-refs` is damaged;
  - `for-each-ref --format=%(objectname) <ref>` exits 0 with no output when the ref is missing, and 128 when `packed-refs` is damaged;
  - only the plain `rev-parse --verify` form, the one `readSharedRefs` uses, exits 128 in every failing state.
- **Escape.** The branch guard is new in this repair. The mixed shape follows an option VER-003 offered. D016 records that error as the verifier's.
- **Rule a repair must hold** (D015's follow-up, `FUP-3ff0f28b45270ead`):
  1. Criterion 2 holds for every field that both compared snapshots read, since the previous row and during the run.
  2. A branch Git reports as not existing reads `absent`: Git completes the read and finds no such ref. A change between `absent` and a commit id is named, as at checkpoint 12.
  3. Only a read Git cannot complete is degraded: an exit other than that clean not-found, such as 128 on damaged `packed-refs`, or a launch failure. A degraded field:
     - is recorded so that it cannot be read as `absent` or as a count;
     - supplies no baseline for its own comparison;
     - is never named.
  4. F4's rule still holds: no throw, and the exit code, the row with a four-field start and end, and the summary are unchanged.
  5. A ref that exists but does not resolve to a commit may be recorded as `absent` or as degraded. The decision names which, and a value recorded as `absent` is compared as `absent`.
  6. A degraded field withholds only its own comparison. A structurally malformed or legacy snapshot still supplies no baseline (F1's rule).
  7. Product 07's third sentence in §Independent workflows and integration is corrected in place.
- **Regression, kept cheap for `runner-fixtures`.**
  - Direct tests of the comparison cover `origin/main` created between two rows, created during a run and removed, and `main` created.
  - They also cover a degraded tag field beside moved branches (both branches named, the tags not) and an all-degraded `packed-refs` snapshot (nothing named).
  - One gate witness, `origin/main` created between two failed gates in a linked worktree, asserts one line naming `origin/main absent..<id>`.
  - The existing F4 gate cases keep passing.

- **Delta line wording.** The line still prefixes each change with `since previous:` or `during run:` and spells tags as `tags +<name> (count a..b, newest x..y)`, richer than the order's sketch. It still uses one line.
