## Findings

**F4 — a shared ref that Git cannot enumerate makes the snapshot throw, so the gate records nothing (blocking: breaks behavior `main` had).** Low severity. The CLI entry exits 1, so no false pass is possible, but a passing gate becomes an unrecorded failure.

- **Observed.**
  - `readSharedRefs` (`packages/skeleton/src/gate-evidence.mjs:479-511`) reads the `v` tags and `refs/dotln/` through `git()`, which throws on any non-zero exit (`:465-474`). Only the two branch reads map a failure to `absent`.
  - The runner calls it at gate start (`scripts/test-runner.mjs:2063`) and again inside the row literal after the last task (`:2431`), with no catch around either call.
  - Main's gate path enumerates no refs: its Git reads are `rev-parse --show-object-format`, `ls-files`, `ls-tree`, `cat-file` and, for a review, `merge-base`.
- **Reproduction** (`probe.mjs`, host scratchpad, under `harness bounded`; `HEAD` `bb84ae82` scripts and packages extracted with `git archive`):
  - **Dangling `v` tag before the run.** A one-commit fixture has `build`, `alpha` and `beta` tasks and annotated `v1.0.0`. A loose `refs/tags/v9.9.9` names a missing object.
    - Subject: a passing `--serial` gate rejects `Tree observation failed: git for-each-ref`, with 0 rows and no summary. With a failing `beta`, it rejects the same way.
    - `HEAD`: exit 0 with 1 row and one summary. With the failing `beta`, exit 1 with the failed row recorded.
  - **Dangling `v` tag during the run** (written through `stopRequested` after the first task):
    - Subject: every task runs, then the end read rejects, with 0 rows, passing or failing.
    - `HEAD`: exit 0 or 1, with 1 row.
  - **Linked worktree.** A worktree on `wo-900` runs `--document --serial`, and the ref is written in the main checkout's shared tag store, before the run and during it.
    - Subject: rejects with 0 rows both times.
    - `HEAD`: exit 0 with 1 row both times.
  - **Damaged `packed-refs`.** After `git pack-refs --all`, one `garbage line` is appended.
    - Subject: rejects with 0 rows.
    - `HEAD`: exit 0 with 1 row.
    - Git 2.55.0 directly: both `for-each-ref` reads and `rev-parse` exit 128 with `fatal: unexpected line in .git/packed-refs`, and `ls-files` exits 0.
- **Controls that do not throw**, on subject and `HEAD` alike:
  - under `refs/dotln/`, a dangling loose ref (counted) and a garbage loose ref (skipped with a warning);
  - a dangling `origin/main` (reads `absent`);
  - a broken symbolic `refs/tags/v8.8.8` (skipped);
  - an annotated `v7.7.7` whose target object is missing (counted).
- **Why it matters.**
  - Tags and `packed-refs` live in the common Git directory. One such ref anywhere fails every linked worktree's gate. During a run, it discards a run whose tasks all passed: up to 27 minutes for a review gate at this identity.
  - The order's objective is a worktree gate that gives the same result when shared refs change.
  - Likelihood is low. A ref naming a missing object needs repository damage, a pruned alternate object store or a hand-written ref. Archive damage (F2) needed similar conditions.
- **VER-001 and VER-002 escape.** `gate-evidence.mjs` is byte-identical to checkpoint 3, VER-001's subject, and upstream did not change it. VER-001 varied branch refs (a tree object and a dangling symbolic ref) but not the enumerations. VER-002 judged the history read only.
- **Rule a repair must hold.**
  - No failure of a shared-ref read, at gate start or at the end, may change the gate's exit code, prevent recording its row or suppress its summary.
  - That covers every Git read in `readSharedRefs`: the two branch reads, the `v` tag enumeration and the `refs/dotln/` enumeration.
  - A read that fails degrades its own field without throwing, the way a missing branch reads `absent`, so the row still carries start and end with the four fields.
  - A degraded field supplies no comparison baseline and is never reported as movement.
  - One option: a `refs/tags/v*` ref whose object Git cannot read is not a readable annotated tag, so it stays out of count and newest. An enumeration that fails outright reads `absent`, which `completeSharedRefs` already rejects as a baseline.
  - Regression: a runner fixture writes a loose `refs/tags/v*` ref naming a missing object, once before a passing gate and once during a passing run through `stopRequested`. It asserts exit 0, one recorded row with a four-field start and end, one summary line and no throw. A failing variant asserts exit 1 and its recorded row. The damaged `packed-refs` case may share that fixture or be a direct `readSharedRefs` test.
