## Observations (non-blocking)

**O1 — any stray file in `docs/control/orders/` refuses every `resume`
command.** `readControl` reads every entry of that directory and `foldSegments`
rejects a name that is not `WO-NNN.jsonl`. I confirmed that a `.DS_Store` there
makes even read-only `status` exit `1` with
`docs/control/orders/.DS_Store: invalid control segment name at ordinal 1`, and
a subdirectory gives `expected a contained regular control segment`. The
refusal direction is right — the alternative is silently ignoring a file that
might hold events — and it is recoverable by deleting the file. But
`.DS_Store` is gitignored, so it can appear from Finder without any warning
from `git status`, and it would block the operator's own `status`. Whether to
ignore exactly `.DS_Store`, or to refuse only on `.jsonl` names, is a decision
worth taking in WO-021, which will sweep control state from directories it does
not own.

**O2 — a `wo-NNN` branch whose order is not yet activated cannot run bare
`status`.** Selection binds the branch name and then requires the id to exist,
so on a branch `wo-903` before activation every command including `status`
refuses with `unknown work order WO-903; open orders: …`. `worktree start`
activates immediately, so the window is normally zero, but a manually created
branch, or a worktree where activation failed, needs `--work-order` on another
order just to read state. Recording it as a boundary, not a defect.

**O3 — the intake backup archive is in `/private/tmp`.** The receipt says
`DotLn-wo030-intake-20260905T053955Z.zip` was produced "outside the
repository", which is literally true, but it is at `/private/tmp/`, while every
earlier work order's archive (`DotLn-wo016-…`, `DotLn-wo017-…`,
`DotLn-wo018-…`) sits in `~/Projects/`, the helper's default destination.
macOS periodically purges `/private/tmp`. I verified the archive's integrity
(`unzip -t` clean), its four files, and that its copy of the capture hashes to
the recorded `858b8458…`; the canonical `0600` capture in the main checkout is
unaffected. If the operator wants the archive to be a durable second copy, it
should be moved beside its siblings.

**O4 — two publication rows were downgraded from `verified` to
`implemented`.** 07 §Operator resume phrases and §Workflow closeout and
releases changed materially in this order, so the executor lowered them, which
is the honest call for staged source. After this report and a passing final

**O6 — the TypeScript 7.0.2 half of the boy-scout item is unverified here.**

**O7 — two append-only proofs changed shape from per-event equality to a raw
byte prefix.** `addedSegmentEvents` now checks
`after.sources.get(path).startsWith(before source)`, and `work-orders.mjs`'s

guarantee now rests on the parse step running first.
