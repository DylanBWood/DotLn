## New defects, boarded up

Found by the independent review subagent and reproduced by this verifier with
`probe-r1-r3.mjs` in session scratch. Neither needs an ordinary launchpad
input, and neither fails an acceptance criterion. The verifier cannot repair
them, so [WO-114-D013](../../evidence/WO-114/decisions.md) records them with
the follow-up "Resident index-source hardening" and reopens D010.

### VER-002-N1 — `dotln resident` refuses start on an unresolvable launchpad

**Severity:** minor. **Criteria:** 4 (documented behavior) and design.
`dotln.ts:124-130` resolves `docPath(findLaunchpad(), "workOrders",
"README.md")` without a guard, only to select the projection's index. With
`DOTLN_LAUNCHPAD` naming a missing directory, and separately with a malformed
`dotln.config.json`, `dotln resident --once` on a valid store exited 1 with
the generic "worker host refused; inspect the store and declared environment
before retrying" and appended 0 events. `dotln presence away` exited 0 under
the same environment. An empty launchpad without an index started and published
orders `unavailable`. Against the pre-WO-114 harness snapshot's `dotln.js`, the
reviewer observed exit 0 and 2 events for the missing-launchpad case. Refusing
a broken launchpad declaration may be acceptable, but 04 and the README do not
state it, and the message names no cause.

### VER-002-N2 — a blocking special file at the index path hangs start

**Severity:** minor (contrived trigger). **Criteria:** design ("never
authority") and 4. `ResidentStore.readIndex` reads the bound path with
`readFileSync` and no regular-file check (`resident-store.ts:137`). With a FIFO
as `workOrderIndexPath`, a child host's `start()` did not complete within 5 s;
it was terminated with 0 events and no status file. The first transaction holds
the append and lifetime locks while it blocks. Missing files, directories,
malformed text and a removed binding target all remain contained and publish
orders `unavailable`.

## Other review results

- A process killed between temporary write and rename leaves one
  `.runtime-status-*.tmp` file. The reviewer's self-kill probe left one, and a
  later start and tick did not remove it. The window predates the repair; the
  implementation used the same temporary-file pattern with syncs. The file is
  private (0600, inside the store), and D013's follow-up includes an optional
  sweep.
- Only `resident-store.ts` reads or writes `.runtime-status-source.json`. The
  console reads only `runtime-status-v1.json`, the board's `collect.ts` reads
  only `events.jsonl`, and `WorkerStore.inspect` ignores both names. A relative
  `workOrderIndexPath` is bound as an absolute path.
- `bindIndex` runs under both the append lock and the lifetime lock, so no
  helper can publish between acquire and bind, and a refused second host does
  not rebind.
- While an episode runs, a failed dispatch-time publication stays stale until
  the observation-deadline sample, a heartbeat or helper event, or the
  episode's outcome. That is consistent with the "later event, tick or restart"
  claim (inference from `resident-host.ts:265-279`).
- Helpers fold with empty predicates, while a library host can pass custom
  ones to `nextCadenceAt()`. The only production caller, `dotln resident`,
  passes none (inference from code; not reproduced).
- The watch host resumed after the store directory was deleted and recreated.
