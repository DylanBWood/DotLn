## Findings

**F1 — class: operator flow (remedy wording); route: follow-up; severity: low.**
In a kit root whose README carries no release markers, `release prepare` with
no observed release tag refuses with "assign the heading and README claim by
hand" (`scripts/lib/release-preparation.mjs` 219), naming a claim the page does
not carry. Reproduction: a synthetic kit root (manifest, no package source)
with README `# Our project`, the activation placeholder and no tag returns
exactly that message. It breaks no criterion (criterion 4 judges assignment
above an observed baseline) and no behavior `main` had (`main` refused the same
input with the same text when every README carried the block). Repair rule:
the remedy names only the heading when a kit root's page carries no markers
and keeps naming the claim where the block is carried or required, with a
release-preparation case for each.
[WO-245-D010](../../evidence/WO-245/decisions.md#wo-245-d010), register row
FUP-3c371de4deb7c876.

**F2 — class: operator flow (report omission); route: follow-up; severity: low.**
`releaseCloseSummary` (`scripts/release.mjs` 487) prints published seeds from
`rewrittenSeeds` and preview changes from `seedChanges`, never `keptSeeds`.
Reproduction: a refreshed row whose `keptSeeds` holds `README.md` as customized
prints a starter-refresh line without `README.md`, while a migrated row prints
`seeds published: README.md`. The close record keeps the whole row, so
criterion 3's row duty holds, and `main` had no kept state to print. Repair
rule: the summary names kept seeds with their reasons beside published seeds,
in the real close and the dry-run preview, asserted in the summary case of
`scripts/test-launchpad-update.mjs`.
[WO-245-D011](../../evidence/WO-245/decisions.md#wo-245-d011), register row
FUP-8bf500303e6adfce.
