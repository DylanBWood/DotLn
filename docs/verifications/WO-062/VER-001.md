## Findings

### F1 — Edit history is stored as document-order sections, on a misread of the API (medium)

Class: fidelity to the source contract, with an unsupported recorded claim. Surfaces: `packages/skeleton/src/github-issue-source.ts`, `packages/skeleton/fixtures/wo062-issue.json` and the order's evidence records.

- **Recorded claim:** D003 says `diff` is "a summary, not full prior content". The handoff, `implementation.md` and the module comments (lines 21–23 and 600–601) say the same.
- **Observed:** I ran read-only `gh api graphql` (gh 2.98.0) on the public `cli/cli` repository. In 11 of 11 sampled edited subjects (5 issue bodies, 6 comments), `userContentEdits` is listed newest first and the newest `diff` equals the current body exactly. The older diffs have whole-version lengths, for example 17219, 16796, 16171 and 16163 characters for one body, and none carries diff hunk markers.
- **Effect:** lines 581–593 add every non-null `diff` as a section `edit:<id>`. I replayed realistic history through the order's fake `gh`. The resulting bundle:
  - holds a copy of the current body and of an edited comment's current text;
  - holds the prior full body;
  - keeps the current text of a comment it left out for an unavailable author, because lines 631–657 still run `readHistory` on that comment;
  - keeps the prior full body as a section when the current body is refused. The result stops, so a consumer that honours the receipt is safe, but a waived stop would read a stale body as content.
- **Live:** the order's smoke script, run on a public `cli/cli` issue, retained 4 edit sections. Two equal current comment text and two are prior comment versions.
- **Expected:** WO-060's `sections` are the artifact's content in document order, and its history model is `revisions` with changed spans. D003 rejected computing change spans because "the API evidence does not establish … prior full content". The API does supply it.
- **Fixture:** the replay fixture is invented (its provenance says so), and its diffs are short summaries, so no test could expose this.
- **Still holds:** criteria 1 and 2 hold on the realistic shape. The bundle decodes, spans resolve and the hash is stable. A declared secret in an edited body is refused in both the body and its newest edit, and a search of the store finds nothing.
- **Repair rule** (D008 follow-up, rules 1, 2, 4 and 5):
  - Sections and discussion hold only current text.
  - History is expressed through `revisions` and the text-free receipt.
  - Withheld text appears in no stored file, including through an edit version.
  - The fixture follows gh's observed shape.
  - The records state the field's real semantics.

### F2 — Comments left out for an undetermined role are not named one by one (low)

Class: completeness of the omission receipt. When the issue author is unavailable, line 638 leaves out every human comment. The receipt records only `$.data.repository.issue.author`, reason `unavailable`. The guard still stops, but a consumer cannot tell which entries are missing.

Repair rule (D008 follow-up, rule 3): the receipt names each comment left out for an undetermined role, by local id or API path and a reason, without its text.
