## Findings

None blocks the verdict.

**F1 — the subject work order was amended by the implementing session after its
own activation checkpoint, without a dated operator-amendment marker.**
`git diff refs/dotln/checkpoint/WO-023/1 -- docs/work-orders/WO-023-compile-entropy-reducer.md`
is 135 insertions and 44 deletions. Those edits assign the `v0.5.0` release
classification, retarget the order from a hand-assembled compile step to the
landed `@dotln/compiler`, add the paragraph that authorizes the compiler-v1
wildcard extension, replace the Non-goal "the composition compiler (WO-008)"
with "a second composition compiler or general wildcard-claim precedence", and
strengthen criterion 2. Three facts keep this non-blocking. Criteria 1 and 3
through 8, the Evidence gate, and the Write-back duty are byte-identical to the
activation checkpoint, so the amendment cannot have manufactured a pass.
Criterion 2 is strictly stronger than the text it replaced, and I verified the
stronger form. The AuthorityEnvelope that forces the compiler extension —
`repo.read*`, `probe.run:scratch*`, `repo.write*`, `git.mutate*`, `remote.*`,
`settings.*` — was already in the activation text at its lines 96 to 102, and
compiler v1 rejected every one of those patterns, so retargeting to the real
compiler and extending it are consequences of the unamended definitions rather
than new appetite. What remains for the operator is a scope question, not an
evidence question: whether expanding the edit surface into
`packages/compiler/src` and rewriting the Non-goal were intended at activation.
The repository's convention elsewhere is an explicit dated amendment — WO-018's
criteria 9 and 10, ADR-0002's Amendments list, and the execution guide's
instruction to add "a dated operator amendment to that work order's **Effort:**
line". The two ideation-breakout sections in this same file follow that
convention; these edits do not.

**F2 — `check-surfaces` reports `@dotln/skeleton: src unchanged` although this
order adds 2 133 lines of skeleton source.** `npm run release -- check-surfaces`
prints `PASS component-version @dotln/skeleton: src unchanged`.
`scripts/release.mjs:453-465` decides that with
`git diff --no-renames --name-only <previous tag> -- packages/<dir>/src`, which
cannot see untracked files, and
`packages/skeleton/src/loadouts/entropy-reducer.ts` stays untracked until the
final reviewer commits the reviewed state. The consequence is bounded: the same
preflight inside `npm run worktree -- publish` runs *after* that commit, where
the file is tracked and the rule sees it; and the miss only ever fails to
*require* a bump, which this order performed anyway (0.4.0 → 0.5.0). Still, any
future order that adds source files without touching existing ones would get a
green pre-commit preflight it has not earned.

**F3 — the compiler now admits a bare `*` effect pattern in a claim-free graph
with no diagnostic.** A graph whose active `allowedEffects` and
`allowedOperations` are `["*"]` and whose denied lists are empty compiles
successfully (`fnv1a64:ce0fa367e4673f04`). Under the kernel's `effectMatches`,
`*` grants every effect. The work order, the compiler README, 02, 04, and the
ledger all describe the new capability as "direct terminal prefix globs", and
the ledger explicitly disclaims "a claim that `*` by itself is a safe profile" —
but nothing in the compiler enforces a non-empty prefix, so that disclaimer
lives only in prose. This does not affect the verdict: no shipped definition
uses it, and every guarantee the order actually asserts (claim-free lowering,
claim-mixed rejection, wildcard-claim-target rejection, inert unequipped
catalog) holds exactly as written.

**F4 — the kernel's prefix glob is string-anchored, not segment-anchored.**
`authorize` grants `repo.readwrite` and `repo.read_and_write` under this
envelope, because `effectMatches` tests `effect.startsWith(pattern.slice(0,-1))`
(`packages/kernel/src/core.ts:310-313`). Anchoring itself is sound —
`xrepo.read.file`, `repo.rea`, and `repo` all refuse. This is pre-existing
kernel semantics that WO-023 does not change and its non-goals exclude, and no
effect name in the system falls into the gap. Recorded so that a later order
introducing effect names knows the guard matches string prefixes, not path
segments.
