## Boarded findings (outside the declared criteria; non-blocking)

**B1 — implementation defect outside the criteria, minor: a FIFO at the
launchpad configuration blocks `dotln resident` before the host starts.**

- **Reproduction:** `mkfifo <launchpad>/dotln.config.json`, then run
  `dotln resident --store S --policy <policy> --once` with `DOTLN_LAUNCHPAD` set
  and `spawnSync` timeout 5000 ms, killSignal SIGKILL.
- **Observed:** killed by SIGKILL at 5,003 ms, with no `events.jsonl` and no
  status file.
- **Cause:** `scripts/lib/config.mjs:641-643` reads the configuration with a
  blocking `readFileSync` after a stat that accepts a FIFO, and
  `dotln.ts:139-148` guards only thrown errors. This predates the order.
- **Why it matters:**
  - Product 04 (`:420-421`) and the console README now say configuration
    failures degrade and "a FIFO cannot block startup".
  - `FUP-4656197433cb8b3d`, settled by this order, has the reopening
    condition "A bad source blocks resident work".
  - D008 reopens that row.
- **Rule:** every configuration source the resident CLI reads is opened
  without blocking and checked as a regular file on the opened descriptor. A
  failure maps to `configuration-invalid`, with a SIGKILL-bounded regression.
  Otherwise the docs are narrowed to what holds.

**B2 — implementation defect outside the criteria, minor (the refuter
proposed nit, because the resident already replays O(history) per
transaction): passive refresh cost grows with the event log.**

- **Measured:** `renderLiveView` on a store with N added `ClockSampled` events.

  | Added events | Log size | Refresh times |
  | --- | --- | --- |
  | 10,000 | 1.7 MiB | 35 / 20 / 19 ms |
  | 86,400 (one day at the default 1 s tick) | 14.4 MiB | 186 / 174 / 194 ms |
  | 259,200 | 43.2 MiB | 611 / 540 / 535 ms |

- **Cause:** every refresh re-reads and decodes the whole log and
  audit-projects it, synchronously on the input thread every 1,000 ms
  (`live.ts:40-56`, `:105-119`, `:180`).
- **Record gap:** D002 declined a trial using evidence about the status-file
  watcher, not this reader.
- **Rule:** per-refresh work is bounded by the displayed window, or a measured
  bound is recorded with a reopening condition that names the event-log reader.

**B3 — implementation defect outside the criteria, minor: after an event-log
outage, the change notice re-announces an old script event.**

- **Reproduction:** `watchLiveView` over one verified `ScriptEpisodeObserved`
  event. Overwrite the log with `{`, then restore the same bytes.
- **Observed:** the recovery notice is `["Script completed (verified)"]`,
  although nothing was appended. An unavailable snapshot replaces the
  baseline (`live.ts:152-162`, `:178`).
- **Refuter's inference, not executed:** a torn read during an append could
  trigger the same false notice without corruption.
- **Rule:** only a successful decode replaces the change baseline, with a
  regression on the post-recovery notice.

**B4 — implementation defect outside the criteria, minor: a dead resident is
invisible.**

- **Reproduction:** SIGKILL a running `dotln resident` under `watchLiveView`.
- **Observed:** no frame in 3 s. The view keeps its last presence line, with
  no stale or unreachable indication. The status file and descriptor remain.
- **Cause:** the passive view never reads `observedAt` or the loopback
  (`live.ts:40-56`, `:87-104`). The Objective says the mode "connects to the
  resident's loopback surface and shows" the views.
- **Rule:** the passive view shows reachability or status freshness, with no
  writes and no command.

**B5 — nits, static, confirmed by the refuter.**

- **B5a:** `orders` omits `workOrders.reason`, which the frame and `status`
  show (`live.ts:355` vs `:96`).
- **B5b:** every client-side failure prints one generic line
  (`live.ts:391-399`), where `console invoke` prints an allowlisted reason.
- **B5c:** with a missing launchpad, console commands run with that missing
  directory as their working directory, so each fails as "could not start"
  (inference, not executed).
- **Rule:** order views include the reason, and client failures report the
  allowlisted refusal without paths or tokens.

**T1 — test weakness, minor.**

- No test runs `console live` with a TTY. The alternate screen,
  pause-until-Enter, deferred redraw and clipping (`live.ts:233`, `:249-328`)
  are therefore unexercised in the gate, and no assertion reads the CLI's
  frames.
- The idle (`live.test.ts:126-128`) and post-close (`:150-154`) checks wait
  less than one 1,000 ms interval.
- The malformed-status step (`:137-139`) may never be sampled.
- The `audit`, `:audit` and `back` aliases are unasserted.
- The FIFO CLI regressions use the default SIGTERM kill.
- The schema-enum parity hard-codes the six reasons instead of
  `WORK_ORDER_SOURCE_REASONS` (the enum equals the constant today).
- **Rule:** commit the terminal-mode regressions (pseudo-TTY or injected
  `isTTY`/`rows`/`columns`) and CLI-frame assertions. Assert every alias.
  Place the idle and close checks past one interval. Use SIGKILL for hang
  regressions. Derive the enum parity from the constant.
