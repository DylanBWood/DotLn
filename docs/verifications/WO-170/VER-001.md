## Findings

### F1 — Medium: lexical collision order selects an older usage observation

**Expected:** when retained copies contain successive observations of the same dispatch, the meter and recovered snapshot retain the latest observation. A copy certified as carried must not be the only place holding a newer value that the summary lost.

**Observed:** after ten collision-preserving copies, the latest dispatch total is 200 tokens but both `collectMeta` and `recoveredUsageSnapshot` report 190. The recovered snapshot nevertheless lists all eleven copy digests in `usageCopies`.

**Cause:** `scripts/lib/meta.mjs:424` sorts copy paths lexically; `retainedUsage` concatenates them in that order; `latestUsage` at line 390 replaces matching dispatch keys with the last row encountered. `usage.jsonl.from-WO-999-10` sorts before `-2` through `-9`. The preservation planner generates these numeric suffixes at `scripts/lib/intake-reconciliation.mjs:180`. Ordinary `recordUsageObservation` calls need not supply `supersedes`, including the current harness and `meta --collect` call sites.

**Reproduction:** the root and reader reviewer independently executed the recovery counterexample in steps 1–4. The root also checked the retained-only meter in step 5.

1. Create source and destination Git fixture repositories in system temporary storage, each ignoring `docs/control/local/` and `docs/intake/`.
2. For indices 0 through 10, call `recordUsageObservation(source, row)` for WO-999/executor with the same `startedAt`, `sessionKey` and observation source. Use dispatch scope, increasing observation cutoffs, and totals `100 + index * 10`.
3. After every append, call `reconcileWorktreeMaterial(source, destination, "WO-999")`. This produces the names through `.from-WO-999-10` using the real preservation API.
4. Call `recoveredUsageSnapshot(destination, "WO-999", null, cutoff)`. At indices 0, 1, 9 and 10, the expected totals are 100, 110, 190 and 200; actual totals are 100, 110, 190 and **190**. The final snapshot certifies **11** copies.
5. Give the destination a closed WO-999 control history and call `collectMeta(destination)` with no snapshot or live usage. Its retained-only order total is also **190**, expected **200**.

This is supported preservation behavior, not a manually invented filename. The existing retained-copy fixture covers different roles but does not exercise repeated observations crossing the numeric suffix boundary. The current 77 recovered snapshots each reference one carried or uncarried copy, so this finding does not invalidate their totals. No prune was applied; possible loss after a certified lane is pruned is an inference from the digest-based `usageRetention` check, not an observed deletion.

**Repair:** choose the latest same-dispatch observation independently of lexical filename order, retain supersession and unknown-value semantics, and add a preservation-backed regression for both readers and the recovery certificate. Recorded durably in [D015](../../evidence/WO-170/decisions.md#wo-170-d015--verification-found-an-older-retained-observation-winning-after-ten-collisions).
