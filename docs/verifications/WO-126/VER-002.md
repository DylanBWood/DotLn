## Findings

### F10 — wrapper and compound forms of a denied effect classify as `shell.run` (criterion 8, major; continues VER-001 F1)

**Expected.** The non-goals exclude "removing the writer guard, the attribution
guard or the permissions envelope". Criterion 8 asks the classifier to classify
the command's own invocation so that quoted data is not mistaken for an effect;
the `v0.16.0` envelope is the floor it must not fall below.

**Observed.** `invocationProgram` strips only variable assignments, a path
prefix and the `env` and `command` wrappers
(`packages/skeleton/src/harness-command.ts:118-158`). Any other leading word
becomes the program, and every program outside the effect table returns
`shell.run`, which `contributor.sandboxed` allows. Called directly on the built
`dist` module and on the pinned `.runtime` snapshot the hooks import, both
returning the same values, against the `v0.16.0` regex at
`main:packages/skeleton/src/harness-host.ts:1427,1441`:

| Command | Now | `v0.16.0` |
| --- | --- | --- |
| `exec git push origin wo-126` | `shell.run` | `remote.unapproved` |
| `time git push origin wo-126` | `shell.run` | `remote.unapproved` |
| `nohup git push origin wo-126 &` | `shell.run` | `remote.unapproved` |
| `timeout 60 git push origin wo-126` | `shell.run` | `remote.unapproved` |
| `nice -n 5 git push origin wo-126` | `shell.run` | `remote.unapproved` |
| `xargs git push origin wo-126` | `shell.run` | `remote.unapproved` |
| `(git push origin wo-126)` | `shell.run` | `remote.unapproved` |
| `{ git push origin wo-126; }` | `shell.run,shell.run` | `remote.unapproved` |
| `eval 'git push origin wo-126'` | `shell.run` | `remote.unapproved` |
| `if true; then git push origin wo-126; fi` | `shell.run,shell.run,shell.run` | `remote.unapproved` |
| `(cd packages && git push origin wo-126)` | `shell.run,remote.unapproved` (denied) | `remote.unapproved` |
| `exec ssh -V` / `time ssh -V` | `shell.run` | `transport.ssh` |
| `npx npm publish` | `shell.run` | `package.publish` |

The path-qualified forms VER-001 named, `bash -c '…'`, `git -c … push`,
`git --no-pager push`, `git "push"`, `git pu\sh`, `\git push` and a
backslash-continued `git push` all classify as `remote.unapproved`, and the
`.claude/settings.json` deny list is a prefix matcher that does not cover
wrappers either.

**Consequence.** `remote.unapproved`, `package.publish` and `transport.ssh` are
the effects that reach outside the repository; the no-commits-before-final-review
rule depends on the first. The repository's own envelope is the only layer
Codex sessions have. `permissionEffect` returns the classifier's effect
unchanged (`harness-host.ts:1691-1696`), so the hook admits these commands; the
`env`-wrapped `ssh -V` was refused live, which confirms the hook follows the
classifier. The process-debt fixture "executable paths and wrappers preserve
denied invocation effects" covers path prefixes, `env`, `command` and
`bash -c` only.

**Repair direction.** Treat the transparent wrappers (`exec`, `time`, `nohup`,
`timeout <n>`, `nice [-n N]`, `xargs`, `caffeinate [-flags]`, `builtin`, `npx`)
like `env`; treat `(`, `{`, `}`, `)` and the control-flow words as separators
rather than programs; re-tokenize `eval`'s literal argument as `bash -c` is;
and for any remaining unknown program, refuse with a classification reason when
its argument tokens contain a denied-effect invocation sequence (`git` then
`push`, `gh` then `pr|release|repo` then `create|merge|edit|delete`, a package
manager then `publish`, or `ssh|scp|sftp`). A quoted argument is one token and
cannot match a two-token sequence, so `grep -rn 'git push'` stays a read.
Add each shape above to the fixture.

### F11 — the attribution guard refuses any command whose text contains `git commit` (criterion 8, moderate; same class as VER-001 F3)

**Expected.** A guard classifies the command's own invocation; quoted data and
search patterns are not effects; a refusal names its reason.

**Observed.** `harnessFeedbackFacts` tests the raw command with
`/\bgit\s+(?:[^\n;]*\s)?commit\b/`, then looks for a quoted `-m` or `--message`
or a `-F` file, and throws a plain `Error("Commit message bytes unavailable; use
an explicit message file")` when it finds none
(`harness-host.ts:1298-1317`). The wrapper reports a plain error as
`DOTLN_HARNESS_REFUSED: host facts or pinned runtime unavailable`. Real
commands through the installed hooks in this session:

| Command | Result |
| --- | --- |
| `echo 'git commit'` | refused, "host facts or pinned runtime unavailable" |
| `echo 'git commit -m x'` | refused, same |
| `grep -n -i -E 'commit-message-bytes\|git commit\|…' packages/skeleton/src/harness-host.ts` | refused, same |
| `echo 'a commit -m x'` | ran |
| `printf '%s\n' 'line one⏎line two'` | ran |

**Consequence.** Reading the guard's own source with a search pattern that
names it is refused, with the message VER-001 F3 showed a session cannot
distinguish from a destroyed runtime. It cost this session three attempts to
diagnose. An unquoted single-word real commit message (`git commit -m fix`)
receives the same runtime message.

**Repair direction.** Take the commit invocation from `shellInvocations`
(program basename `git`, first non-option operand `commit`) and its message
from the tokens, ignore `git commit` that appears only inside a quoted argument,
and throw `HarnessCommandRefused` for a commit without an extractable message
so the wrapper reports the classification reason.

### F12 — an unquoted parameter expansion in the effect position is not refused (criterion 8, moderate)

**Observed.** The classifier refuses `$(…)` and backticks as "Dynamic shell
substitution requires an explicit effect adapter", but `$G push origin wo-126`,
`git $P origin wo-126`, `P=push; git $P origin wo-126`, `git ${X:-push} origin
wo-126` and `git $'push' origin wo-126` all classify as `shell.run`. The
`v0.16.0` regex did not catch these either, so this is a hole in the new
design rather than a regression: the classifier's stated rule is that an
invocation it cannot read is refused, and a variable in the program or
subcommand position is exactly that.

**Repair direction.** Refuse, with a classification reason, an unquoted `$`
parameter, `${…}` or `$'…'` in the program position or as the first operand of
`git`, `gh`, `npm`, `pnpm` and `yarn`; leave `$TMPDIR`-style expansions in
path and data positions alone so ordinary reads are unaffected.
