is met only in part. The order's central mechanisms are real and were
reproduced independently: evidence keyed by exact tree hash cut a 667-second

## Findings

### F1 — a path-qualified program escapes every denied effect (criterion 8, major)

**Expected.** The order's non-goals exclude "removing the writer guard, the
attribution guard or the permissions envelope". Criterion 8 replaces substring
matching with invocation matching so that quoted data is not mistaken for an
effect; it does not license dropping enforcement for real effects.

**Observed.** `invocationEffects` compares `program` to the literal strings
`git`, `gh`, `npm`, `ssh`, `scp`, `sftp`, `claude`, `codex`
(`packages/skeleton/src/harness-command.ts:141-175`). Any path-qualified
invocation therefore falls through to `shell.run`, which the envelope allows.

**Reproduction.** Both inputs use this session's own `session_id`, so the
writer reservation is held and no other guard interferes:

```
printf '%s' '{"session_id":"<this session>","cwd":"<worktree>","hook_event_name":"PreToolUse","tool_name":"Bash","tool_input":{"command":"git push origin wo-126"}}' | node .claude/hooks/permissions.mjs
  -> {"hookSpecificOutput":{...,"permissionDecision":"deny","permissionDecisionReason":"DOTLN_HARNESS_REFUSED: compiled authority does not permit this effect"}}

... same input with "command":"/usr/bin/git push origin wo-126"
  -> {}
```

Running the whole PreToolUse chain — `concurrent-work-requires-worktrees`,
`no-attribution`, `permissions`, `write-observer` — against the path-qualified
form returns `{}`, `{}`, `{}`, `{}`. Direct calls to `invocationEffects`
return `["shell.run"]` for `/usr/bin/git push origin main`,
`/opt/homebrew/bin/gh pr create --fill`, `./node_modules/.bin/gh pr create
--fill`, `/usr/local/bin/npm publish --access public` and `/usr/bin/env git
push origin main`, against `["remote.unapproved"]` for the bare forms.

**Consequence.** `remote.unapproved` and `package.publish` are the two effects
that reach outside the repository, and the repository's no-commits-before-final-review
rule depends on the first. `.claude/settings.json`'s own `Bash(npm publish *)`
prefix matcher misses the same forms, so nothing else catches them. The
superseded classifier used `/\bgit\s+push\b/` and `/\b(?:npm|pnpm|yarn)\s+publish\b/`,
whose word boundaries matched after a path separator; this is a regression, not
a pre-existing hole.

**Repair direction.** Match on the program's basename (and treat a
path-qualified `env` like bare `env`) before the effect table is consulted.

### F3 — a multi-line quoted argument is refused as a runtime failure (criterion 8, moderate)

**Expected.** The classifier classifies the command's own invocation and does
not refuse a read-only command because of its data.

**Observed.** `shellInvocations` splits the source on `\n` before tokenizing
and validates quoting per line (`harness-command.ts:39-110`), so a quote that
opens on one line and closes on another raises `Unclassified shell quotation
or heredoc`. Confirmed for `node -e '<two-line script>'`, `git commit -m
'first\nsecond'` and a two-line `jq` program; single-line quoting, quoted
heredocs, `awk '{ print $1 }'` and `sed -n '1,20p'` all classify correctly.

Every such throw, and the deliberate throws for `cd`, `git --git-dir` and
`$(...)`, propagates past `evaluateHarnessHook` into `runHarnessHook`'s
catch-all, which emits `DOTLN_HARNESS_REFUSED: host facts or pinned runtime
unavailable` (`harness-host.ts:2085-2092`). That is the exact string this
order's observed-gap section attributes to a destroyed `dist`, so a session
cannot tell a classifier refusal from a broken runtime.

**Reproduction.** This verification session hit it three times before
diagnosing it, including on `git rev-parse --git-dir` and on a `node -e`
script; recovering the real reason required importing the pinned runtime and
calling `evaluateHarnessHook` outside the hook wrapper.

**Note.** The catch-all message predates this order. The new tokenizer adds a
new and common class of input that lands on it, and criterion 8 is the place
where the classifier's refusals are specified.

### F4 — the build gained an undeclared `python3` prerequisite (criterion 18, moderate)

**Expected.** "no new dependency", against a repository that maintains
`docs/discovery/environment.json` precisely to declare host facts.

**Observed.** `scripts/build.mjs:66-79` spawns `python3
scripts/atomic-exchange.py` for every package whose `dist` already exists.
`python3` appears nowhere else in the repository, is absent from the discovery
record, and the executor receipt states "No dependency was added".
`scripts/atomic-exchange.py` itself exits with "atomic directory exchange
unavailable on this host" on any platform that is not macOS or Linux.

**Reproduction.**

```
PATH=/var/empty <node> scripts/build.mjs
  Atomic runtime exchange refused: spawnSync python3 ENOENT
  exit=1
```

`build` is the barrier suite of both gates and a prerequisite of `harness`,
`skeleton`, `console` and `plan`, so a host without `python3` cannot run any
gate or lifecycle command. On this host `python3` resolves to a pyenv shim,
which adds a second failure mode outside the repository's control.

**Credit where due.** The failure is clean: the build throws before any
exchange, `dist` was left intact and an installed hook still returned `{}`
immediately afterwards. The atomicity design itself holds.

### F5 — the version probe observes the CLI on `PATH`, not the running harness (criterion 2, moderate)

**Expected.** "`npm run discover -- harness` appends an observed row for the
running harness from a probe."

**Observed.** `probeHarness` runs `claude --version` resolved through `PATH`
(`scripts/discover.mjs:11-19`), and the session-start warning does the same
(`harness-host.ts:1809-1817`), whose comment reads "Version is a bounded CLI
observation, never the session's launch claim." On this host the two differ:
`claude --version` reports `2.1.267`, while this session runs `2.1.266` per
`CLAUDE_CODE_EXECPATH` and `AI_AGENT`. A `discover harness` run here would
record `2.1.267` as the observed row for a session running `2.1.266`.

**Consequence.** Both versions sit on the `2.1` line, so nothing changed for
this dispatch. Where an operator's newest installed CLI is on a different line
from the running session, the record would assert an unobserved version as
observed, and the warning would fire or stay silent for the wrong version —
the class of attestation error criterion 2 exists to prevent.

**Repair direction.** Prefer the session's own executable
(`CLAUDE_CODE_EXECPATH`, or the harness-supplied `harness_version` channel
that already exists in `HarnessInput`) and fall back to `PATH` only when
neither is exposed, recording which channel was used.

### F6 — the largest added recurring cost is neither declared nor metered (criterion 16, moderate)

**Expected.** "every order carries a `**Cost:**` header line stating, in those

**Observed.** The order adds `observeAuthorship`, which calls

120 s), one cost line per order, and the meter's run per order". No
per-tool-call cost appears there, in `budgets.json`, or in any meter row.

**Note.** The order genuinely removes large costs — the byte reads of
inherited and generated outputs, the full suite at every turn end, the
whole-map planner read. This finding is not that the trade is bad; it is that
the order's own accounting standard was not applied to its own largest
addition, which is what criterion 16 asks every order to do.

### F8 — the local gate cache grows without bound and stores full suite output (minor)

`recordGateChecks` appends one row per suite plus one aggregate per gate run,

failing verification is an evidence-bearing report, never a green-code claim"
(`scripts/lib/lifecycle-evidence.mjs:37-41`). A verifier that finds defects
should not have to prove the subject green to say so.

**Observed.** The same function then walks the session's authored outputs and,
for any output whose obligation is `check` rather than `read`, requires
`findGateCheck(root, "npm run test:full", treeHash)` — the full gate, at the
current tree, for every verdict (`:74-90`). The verifier loadout directs "Run
`npm run work-orders -- index` after dispatch and after recording a result.
Refresh before the evidence gate", and `docs/work-orders/README.md` carries
the `dotln-generated` attribute, so refreshing it is always a `check`
obligation. The refresh is not optional: allocating this report moved WO-126
to `verifying` and `npm run harness -- evidence` immediately reported
`FAIL index … docs/work-orders/README.md is stale at line 3; run npm run
work-orders -- index`.

**Consequence.** Every verifier that follows its own skill converts the
`fail`-verdict exemption back into a full-gate requirement — at this subject,
667 s instead of 186 ms. The exemption survives only for a verifier that skips
the index refresh, which the loadout forbids and the gate then catches.

**Repair direction.** Satisfy a generated output's check obligation with that
artifact's own declared `--check` — the wording criterion 3 uses, "its
generator's `--check` (or the recorded evidence run) green at the current
bytes" — rather than with the whole `test:full` aggregate.
