## Implementation review

Most of the design holds up:

- **Cleanup and settlement.** `removeSourceChangeCommands` attempts both removals whatever the other did. It tolerates `ENOENT`, refuses both paths when the route's ownership changed, and returns `{ removed, survived }` without throwing. Cleanup now follows settlement, `WorkerResultObserved` or `WorkerInterrupted`, and the integrity record on every path.
- **Surviving grants.** A survivor returns `command-route-live:<paths>` without recording `SourceChangeRefused`, so the command stays pending. D002 records why, and the restart block repeats cleanup before any verify, effect or admission.
- **Writer requests.** The hold sits after the integrity and worktree checks and before the effect read, in both the fresh and the recovery path.
- **Import.** It packs with the private reader and indexes into the shared store with the object variables removed. It keeps the pack under an owned keep file until the branch exists, and re-verifies every candidate object before and after the ref update.
- **Shadowing.** D014's strict `fsck` on the candidate head closes the private-shadow case both executor workers found.
- **Writer environments.** Both transports receive the two object variables and exactly the two `GIT_CONFIG_*` pairs, with inherited pairs removed. `codexWriterAccess` no longer grants the shared `objects`, `refs` or `logs`.

Three gaps remain. The clean check's entry-type rule is stricter than the Design (F1). The design leaves an unresolvable per-worktree HEAD in the shared Git directory whenever a candidate is not imported (F2). The private store, which sits inside the writer-writable gitdir, has no inventory of its own `info` directory (F3).

## Findings

**F1 — the committed-tree check refuses tracked symlinks and gitlinks.** Blocking.

- **Class:** false refusal; a regression of admission behavior the base had.
- **Criterion:** 7 ("a clean candidate passes").
- **Observed:** `cleanAgainstCommit` requires every `ls-tree` entry to be a regular blob file at mode 100644 or 100755 whose path is its own realpath. An unchanged symlink (120000) fails `isFile()` and its realpath, and a gitlink (160000) fails the type check. Because the check also runs at the baseline before `WorkerAttemptStarted`, `run()` throws `source-change committed tree is dirty: <path>; committed-tree-drift:<path>` before any writer is launched. This repository tracks `AGENTS.md` as a 120000 symlink.
- **Expected:** refuse only an index flag or a byte, mode or type difference from the committed entry (the Design's D044 bullets).
- **Reproduction:** probe 1, with its base comparison.
- **Rule a repair must hold:** judge each tracked entry by its committed type.
  - A 120000 entry must be a symlink whose unfollowed target equals the blob bytes.
  - A 160000 gitlink is judged as the base judged it, through status, not refused.
  - Regular files keep the byte and mode comparison, and a type change still refuses, naming the path.
  - Both transports need cases for a clean candidate beside an unchanged symlink and gitlink (observed) and for a changed symlink target (refused before any after-test).
  - `verification-001-clean-entries.mjs` exits 0.
- **Severity:** high.
- **Disposition:** [WO-204-D026](../../evidence/WO-204/decisions.md#wo-204-d026--the-committed-tree-check-must-judge-symlinks-and-gitlinks-by-their-committed-type), with its follow-up in the register.

**F2 — an unimported candidate breaks the shared repository's Git and its own inspection.** Blocking.

- **Class:** reproduced regression: availability of the operator's repository.
- **Criterion:** none of the numbered criteria by its literal terms. Criterion 12's "shared ref" is the shared `refs/` namespace, which this order keeps clean. Criterion 14 bounds only object loss during an episode. The defect contradicts the Objective's first sentence and is a behavior `main` had.
- **Observed:** `worktree add --detach` registers `<common>/worktrees/<id>/HEAD`. After the writer's commit, that HEAD names a commit that exists only in the private store. `SourceChangeHost.finish()`, the only path that removes the worktree, requires an observed receipt. So after an admission refusal or the writer-requested-attention hold (which the vertical turns into `NeedsHuman`), Git in the target fails. By inference from that source, not probed, the same holds for a pending cleanup or an interruption after the writer's commit:
  - `git log --all`, `git rev-list --all`, `git repack -ad` and `git gc --prune=now` fail with `fatal: bad object worktrees/<id>/HEAD`;
  - `git fsck` reports `invalid sha1 pointer`;
  - `git log` and `git show` in the preserved worktree fail.

  This lasts until the operator removes the worktree. D004 recorded only the gc and repack exit 128 "until host import, then succeed". That premise does not hold for a candidate that is never imported; D027 records the correction.
- **Expected:** as at the base, ordinary Git in the target and in the preserved worktree keeps working after a refused episode.
- **Reproduction:** probe 2, with its base comparison.
- **Rule a repair must hold:**
  - Whenever an outcome leaves the candidate unimported, those five reachability commands exit as at the base.
  - A held candidate's objects stay out of the shared store (criterion 17).
  - The preserved candidate stays inspectable, with plain Git or with a command its refusal record names.
  - The writer gains no write authority over the shared objects, refs or logs, and restart recovery can still re-judge a pending candidate. The live window between the writer's commit and the import stays under D004's follow-up.
  - Cases cover an admission refusal, the hold and a pending cleanup for both transports, and `verification-001-unimported-candidate.mjs` exits 0.
  - If no repair within the declared surfaces meets this rule together with criteria 12 and 17, the repair executor records that in the decisions and stops. The safe default is that WO-204 does not close. The Design's recorded reopening alternative, a files-only writer with a host-owned commit, is what the operator then weighs.
- **Severity:** high.
- **Disposition:** [WO-204-D027](../../evidence/WO-204/decisions.md#wo-204-d027--an-unimported-candidate-must-leave-the-shared-repositorys-git-and-its-own-inspection-working), with its follow-up in the register.

**F3 — the private store's own alternates are neither refused nor inventoried.** Non-blocking.

- **Observed:** the store is `<gitdir>/dotln-objects`, inside the gitdir that `codexWriterAccess` grants for write. Git follows `$GIT_OBJECT_DIRECTORY/info/alternates` (probe 3), and the host's pre-import reads, `fsck` and `pack-objects` run under that environment. `sharedState()` inventories only the shared store's alternates.

- **Disposition:** [WO-204-D028](../../evidence/WO-204/decisions.md#wo-204-d028--refuse-an-alternates-entry-inside-the-private-object-store), in this order's repair as Adjacent Repair or in the next source-change confinement order.
