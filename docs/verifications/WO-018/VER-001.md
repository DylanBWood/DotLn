## Findings

**F1 — advisory. The new module-entry guard is lexical, so an absolute
symlinked invocation path makes the whole `resume` CLI a silent exit-0 no-op.**
`scripts/resume.mjs:980-982` compares `pathToFileURL(resolve(process.argv[1])).href`
against `import.meta.url`. Node realpath-resolves `import.meta.url`, while
`path.resolve` is purely lexical, so any *absolute* argv containing a symlinked
component fails the comparison and `main()` never runs. Reproduced against the
real file: `node <symlink>/scripts/resume.mjs status --json` exits 0 with zero
bytes on both streams, where the physical path prints the full projection; and a
state-changing `activate` through the same path exits 0, prints nothing, and
leaves `resume.jsonl` byte-identical. The guard itself is required — criteria 3
and 5 make `resume.mjs` both a module and a CLI, and `main` had no guard because
nothing imported it — so this is an implementation defect, not a scope excursion.

It is **not reachable from any sanctioned invocation**, which I established
rather than assumed. `npm run resume -- …` passes a *relative* argv resolved
against `process.cwd()`, which Node reports physically even when the shell
reached the directory through a symlink; I confirmed the documented interface
works from inside a symlinked checkout path. `worktree.mjs` spawns
`join(target, "scripts/resume.mjs")` where `target` comes from
`git worktree list`, and `release.mjs` spawns `join(toolRoot, …)` where
`toolRoot` derives from `fileURLToPath(import.meta.url)`; both are physical, so
even the documented absolute-path release-close command is safe. The exposure is
a hand-typed absolute path through a symlink — plausible on macOS, where `/tmp`
and `/var` are symlinks and this session's own `TMPDIR` is `/tmp/claude-501`.

The suites cannot catch it by construction: `scripts/test-temp-root.sh:50`
resolves every fixture base with `cd … && pwd -P`, a WO-013 hardening, so no
fixture can ever present a symlinked invocation path. `realpathSync` on
`process.argv[1]` is the one-line fix. Recorded here rather than repaired
because the failure mode is silent and belongs in the reviewed record even
though no acceptance criterion is unmet.

**F2 — advisory. The new session-label note uses a `classification` value
outside the file's own declared vocabulary.**
`docs/discovery/environment.json:15` declares a closed label set of seven values;
the note at line 143 is stamped `"classification": "operator-attested"`, and the
change set does not extend `labels` (the diff touches that line zero times). I
confirmed the mismatch programmatically. `attestationSource: "operator-attested"`
on the same object is correct and is the field that carries the epistemic claim;
the `classification` slot is the one that must draw from the declared set. A
future audit of this file — `docs/verifications/WO-027/VER-001.md` performed
exactly that check — would now have to either flag the record or silently widen
the vocabulary.

**F3 — advisory. One new audience-index row breaks the file's
source-document-order convention.** The row for
`03-architecture.md#candidate--opinion-cohorts-and-sealed-adjudication` is placed
after `session-lifecycle--resilience`, but its heading is at
`docs/product/03-architecture.md:543`, between `the-agentic-communication-core`
(515) and `composition-system` (605). Resolving all 22 architecture rows to their
heading line numbers gives a strictly increasing sequence except this one.
`check-publication.mjs` passes at 169/169 because `checkCoverage` compares key
sets, not order, so nothing mechanical will surface it. The
`05-pattern-library.md` row added in the same pass is correctly placed.

**F4 — advisory. `worktree finish` changed which checkout it operates on, and no
acceptance criterion names that change.** `scripts/worktree.mjs:125` derives the
`finish` repository root from `resolve(process.cwd())`, where `main:22` derived it
from the script's own location; `release.mjs` correspondingly spawns
`join(toolRoot, "scripts/worktree.mjs")` where `main` spawned `join(root, …)`. The
