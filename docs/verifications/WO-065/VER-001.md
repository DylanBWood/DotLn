## F1 — The automation role cannot match a GraphQL Bot login

**Severity:** high, blocking criterion 1.
**Class:** classification over an unrecorded response shape (fixture fidelity).

**Expected.** Criterion 1 and the Objective require the observer to classify
an automated review comment over recorded JSON, and so over the response shapes
`gh api graphql` actually returns. The Design says `automation` covers accounts
matching a pattern the executor declares.

**Observed.** The query requests `author { login }` without `__typename`
(`scripts/lib/pull-request-observer.mjs:49`). Automation is decided only by
`/\[bot\]$/iu` on that login (`:131-133`). GraphQL returns a GitHub App's login
without the suffix:

- A read-only `gh api graphql` search of public `cli/cli` pull requests on
  2026-09-29 returned `{"__typename":"Bot","login":"dependabot"}` for the PR
  author and `{"__typename":"Bot","login":"cli-triage"}` for a comment author.
- gh's own `Author.MarshalJSON` (`api/queries_issue.go`) renders a bot as
  `is_bot: true` and `app/<login>`.
- Public repairs of the same mistake are brave/pull-merge#405 and
  epics-containers/org-dashboard#9.

The committed fixture's automation author, `fixture-agent[bot]`, is therefore
a shape this API does not return, and the passing test does not establish the
classification. GitHub usernames contain only alphanumerics and hyphens (GitHub
Docs, "Username considerations for external authentication"), so the pattern
can never match a real author here. That makes `automated-review` unreachable from
live responses: only the synthetic `ci-failure` items are ever `automation`.

**Reproduction.** Scratch script `repro-bot/repro.mjs` under the DotLn session
scratch. It runs the committed `observation.json` through `observePullRequest`
with a fake `gh`, once as committed and once with only the automation login
changed to `fixture-agent`:

```text
committed-fixture-login PRRC_1 role automation, class automated-review; PRRC_3 role automation, class resolved
graphql-bot-login       PRRC_1 role reviewer,   class human-review;     PRRC_3 role reviewer,   class resolved
```

The read-only subagent independently reproduced the same outcome with the
login `copilot-pull-request-reviewer`.

**Rule a repair must hold.**

- Automation is decided from the actor type the response carries: request
  `__typename` on every author, and treat `Bot` as automation.
- Decode the typename positively: refuse an unknown value with its field path,
  or map each Actor type explicitly.
- Record fixture authors in the API's shape.
- A test shows a `Bot` author without the suffix classifies `automated-review`
  and a `User` does not.
- `ci-failure`, `reporter` and `resolved` behavior is preserved.
- Update D003 and the evidence README.

This is recorded in [D009](../../evidence/WO-065/decisions.md#wo-065-d009).
