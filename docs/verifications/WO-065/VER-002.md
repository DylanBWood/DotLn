## New defects, boarded, non-blocking (D014)

**F4 — A NUL byte in a value sent back to `gh` echoes response bytes to
stderr.**

- **Severity:** low to medium. **Class:** unvalidated response value reused as
  a process argument (error-path disclosure).
- **Reproduction:** in the committed fixture, set the conversation comments'
  `pageInfo` to `{hasNextPage: true, endCursor: "<marker> https://outside.invalid/x\u0000"}`
  and run `observe-pr` with a fake `gh`.
  - It exits 1 and leaves 1 event.
  - stderr reads ``error: The argument 'args[13]' must be a string without
    null bytes. Received 'cursor=<marker> https://outside.invalid/x…``.
  - A review thread id holding U+0000, with paginated comments, quotes
    `id=<marker>…` the same way.
- **Cause:** `endCursor` is decoded as any string (`:275-278`), and the thread
  id is reused as a variable (`:491`, `:499-501`). `spawnSync` then throws
  (`:212`), and the CLI prints `error.message`.
- **What it contradicts:** the observer's own rule at `:97` ("Even errors must
  not echo an API response") and the README's "No raw API failure text is
  logged".
- **Store:** stays clean.
- **Inference, unverified:** that github.com never sends NUL in cursors or
  node ids, so this needs a hostile or broken forge.

**F5 — One multi-million-character token blocks the whole observation.**

- **Severity:** low. **Class:** unreadable item escalates to a whole refusal
  (the F2/F3 class, through a resource limit).
- **Reproduction:** add a body `"Bearer " + "A".repeat(6_000_000)` beside a
  safe peer.
  - It exits 1 with `error: Maximum call stack size exceeded` and leaves 1
    event, and the peer is not stored.
  - The message carries no content.
  - A 65,536-character run is refused per item.
- **Cause:** WO-060's shape regexes overflow the backtracking stack. The
  subagent located the threshold at about 5.59 million token characters. The
  observer's `screen()` (`:118-126`) does not contain a RangeError, and its
  16 MiB buffer admits such strings.
- **Unverified:** whether GitHub allows bodies that long.

**Rule a repair must hold (F4 and F5).**

- Every response value the observer sends back to `gh` is decoded against a
  bounded grammar without U+0000 or controls. It refuses at its field path
  before the call.
- An error the observer did not raise prints a fixed reason, never
  `error.message` bytes derived from a response.
- A screen RangeError becomes a per-item refused item without text, or the
  screened length is bounded.
- No rejected text, hash or raw response is persisted. Other comments are
  stored, and refusals name a field path.
- The README's no-logging statement is corrected with the F4 repair.

The follow-up also asks planning to judge whether WO-060's text rule should
reject C1 controls and bidirectional overrides. Those pass today, although its
