**F2 — the one-ambiguity refusal has no fixture (criterion 5).** Medium. Class: vacuous test.

The combined reason is split so that "no executable criteria" and "unresolved material decisions" can be told apart.

**F3 — a failing-behavior contract classed new is walked to publication (criterion 5).** High. Class: correctness.
- Observed: `baselineClass` (`vertical.ts:452-496`) recognizes an existing failure only through one bounded pattern.
  - The primitive builds `story.kind` from that rule (`vertical-primitives.mjs:371-383`).
  - The host re-checks with the class the same rule produced (`vertical-host.ts:176-181`).
  - So in production the "classed new" finding can never fire. Its only fixture calls the pure function with a hand-supplied `"new"` (`test-vertical.mjs:379-382`).
- Reproduction (same probe): "Uploads fail for files larger than 10 MB.", "Saving a document throws a TypeError." and "The export endpoint returns HTTP 500." each produce class `new` with 0 host findings, whether the statement is a requirement or a current-behavior observation. "The check is failing." and "The build fails." produce `defect`.
- A checker composed a full run on "Uploads fail for files larger than 10 MB: make `fixture.txt` contain changed by synthetic worker." Every step completed. The baseline recorded `storyClass: new`, `outcome: walked` and `findings: []`, and the run pushed a Deliverable-ready body and resolved, although the target's test fails at the base.
- This is WO-180 D013's hazard, which the order's Observed gap names. It is also D008's reopening condition, so D016 reopens D008.
- Rule: a contract whose active statements assert an existing failure is classed defect, or held `NeedsHuman` as unclassified, and is never silently new.
  - At minimum this covers fail/fails/failed/failing, throws or errors, "is not working", error statuses, and can't/cannot/does not followed by any verb.
  - The class checked for the "classed new" finding comes from a signal independent of the rule that assigns it, for example the contract's supplied statement classes.

**R1 — a failed baseline is reported as non-reproduction (criterion 3's surface).** Medium. Class: diagnostic accuracy.
- Observed: when the baseline primitive throws, is held or is killed on return, `vertical-host.ts:189-201` rewrites a defect-class result to "baseline did not reproduce the named failing behavior" and discards the real reason. - Rule: the non-reproduction stop applies only to a completed baseline whose admitted witness outcome is not `reproduced`. Refused, held and killed baselines keep their own result and reason, and the non-reproduction fixture asserts the witness outcome.

**R2 — the resident path can stall or end (criterion 1's surface).** Medium. Class: liveness.
- Observed, each reproduced by probe:
  - (a) An admitted vertical bound to a phase the machine has left makes `vertical.tick` return true on every tick (`vertical-resident.ts:119`). `ResidentHost.tick` then returns before its own dispatch and before admitting other drafts, until the binding expires.
  - (b) Concurrent operator and resident entries on one intent throw "invalid or repeated intent admission" or "worker store already has a live host" out of `ResidentHost.run`, which ends `dotln resident`.
  - (c) A phase re-armed during preparation makes the resident append an `IntentAdmitted` its own fold rejects (`resident-state.ts:681-704`), which also throws.
- Rule: `vertical.tick` returns true only when it appended durable state. The admission and step-start guards use the same predicate the fold enforces. An existing decision, or a live foreign store holder, is "not this tick", and no exception escapes `vertical.tick`. Ledger validation and the single-writer lock stay.

**R3 — transient conditions become permanent holds (criterion 1's surface).** Medium. Class: liveness.
- Observed: a presence flicker during preparation, a preparation exception, or an operator invocation while resident work is in flight each record `IntentHeld` by draft id. The fold refuses a second decision (`resident-state.ts:656-657`), and no event releases a hold.
- Reproduced: the hold persisted after re-absence and four ticks, and `dotln vertical` returned the same hold.
- Rule: only decisions about the intent's own inputs (authority, ceiling, contract, decode) are durable holds. Scheduling and transient preparation conditions leave the draft undecided, or the order names and implements a recovery event. A hold still dispatches nothing.

**R4 — the authority poll grows the resident log without bound (criterion 1's surface).** Medium. Class: efficiency.

- Rule: in-flight authority polling does not append on every poll. It samples only when the store changed or a deciding deadline passed, as `resident-host.ts:297-299` does. Kill-on-return, revocation and expiry for the running child stay.
