## Findings

**F1 — criterion 3, correctness, blocking for this criterion.**

What happens:
- A plain `npm test` puts the `build` row in its reuse inventory (`test-runner.mjs:1798-1817`) and skips a reused build (`test-runner.mjs:1466`).
- Fresh tasks then run against whatever ignored `dist/` is on disk. `gateCodeIdentity` does not cover `dist/`, and `scripts/build.mjs` writes no identity stamp.
- `coveringTaskResults` also takes a pass from any row at the identity, whatever a later execution there showed (`gate-reuse.mjs:57-137`).

Reproduction on the real table, from a refuter's scratch clone of `HEAD` plus this diff, with the real `build` and `kernel` tasks and one planted untracked test value:

| Step | Identity | Mode | Task results | Exit |
| --- | --- | --- | --- | --- |
| Plain run | A | fresh | build passes, kernel fails | 1 |
| Plain run (dist built from B) | B | fresh | build and kernel pass | 0 |
| Plain run, source back at A, dist still from B | A | composed | build reused, kernel fresh and passing | 0 |
| `--again` | A | forced fresh | kernel fails | 1 |
| Plain run | A | reused | kernel reused from the composed row | 0 |

- The claim check accepted the composed row with no advisory, and accepted it again after `--again` had failed.
- My own run of a synthetic three-task probe gave the same sequence: composed exit 0 at `bc4539c0b4fa`, then `--again` exit 1.

Reach:
- Rebuilding `dist/` at another identity happens in everyday use: `npm run test:docs`, `npm run harness`, `npm run dotln`, or any gate there.
- Returning to the earlier identity also happens: reverting an edit, or restoring a checkpoint.
- The reviewer's `--review` and any `--again` stay fresh.
- D006 records missing build output, which fails safely. It does not record stale output, which passes falsely.
- Receipt 038's reopening condition is constructed here from the gate's own build, not from the environment.

Rule a repair must hold:
- A composed row records a task as passing only when that pass ran against inputs made at its identity.
- The build is reused only when its on-disk output is attested to the identity; otherwise it runs fresh.
- A task's latest executed result at the identity decides reuse.

D031's follow-up names the fixtures. Otherwise the operator waives criterion 3 with `npm run resume -- waive 3`, naming their words.
