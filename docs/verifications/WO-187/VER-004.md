**Repair rule** (D039 F1(a)–(e), in full there):
- (a) **Findings block.** The final-review report carries one block: a `<!-- dotln-findings:start -->` line, a JSON array of `{id, route, class, summary}`, and a `<!-- dotln-findings:end -->` line. `final-review-result` reads only that block. A missing, duplicate or invalid block, a duplicate id, or a bad id, route or summary makes the counts unmeasured, with one advisory naming the cause. A missing or unknown class counts as `unclassed` and is named in one advisory. A failed review with `[]` is unmeasured; a passing review with `[]` records zeros. The result always records.
- (b) **Briefing.** The briefing reads carry-in sections line by line, with no inline-code, lazy-continuation or container inference. A section starts at a documented label form and ends at an exact order-field label after a blank line, or at a heading of the same or higher level. Fences toggle; an unclosed fence advises. Section lines print verbatim, and any other "Known issues" line advises.
- (c) **Handoff.** The self-review line is exactly `self-review: found <n>; fixed <n>; recorded <n>`, after an optional list marker.
- (d) **Cleanup.** Delete the shared projection. State the formats instead of reader rules in the reviewer sentence of `contributor.ts` and in product 07, regenerate, and remeasure.
- (e) **Tests.** One case table per rule, each row with its exact expected output. It covers every block outcome, every briefing input recorded by VER-001 to VER-004, and the handoff forms. Keep the `08845c71` failure, then run the real-order comparison.
