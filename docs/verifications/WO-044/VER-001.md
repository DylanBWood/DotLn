## Findings

### F1 — High: repositories with saved data are discarded as empty

Criterion 10 fails. `scripts/lib/paths.mjs:109` tests only whether `HEAD`
resolves. In a scratch nested repository, an empty commit on another branch
remained reachable (`git rev-list --all --count` returned 1) after `HEAD` was
pointed at an unborn branch. The classifier returned `commits:false, empty:true`.
A second fixture staged a file, then removed its working copy: `git show
:valuable.txt` still recovered its bytes, but preservation marked the repository
`empty-scaffolding` and planned zero files.

Expected: prove the repository is disposable or preserve/refuse it, including
refs and index data. A missing or unreadable `HEAD` is insufficient. The same
assumption appears in `feedback-selfhost.ts` mount cleanup. No user repository
was removed; the reproduction inspected preservation plans on synthetic data.

### F2 — High: derived-worktree cleanup removes a live writer's worktree

Criterion 12 fails. `scripts/worktree.mjs:183` checks dirt and active gates but
never checks the writer reservation. In a detached scratch derivative, the
host's `harnessWriterView` reported `reserved:true, alive:true`; Git status was
clean. The actual `worktree settle WO-999 --dry-run` called it idle, and the
non-preview command removed it while that process remained alive.

Expected: preserve a derivative with a live or uncertain writer and report the
blocker. Check the existing writer protocol before teardown, with appropriate
race protection. The removal reproduction affected only its disposable fixture.

### F3 — Medium: a suite's descendants can prevent gate stop from completing

D011's self-stop repair remains incomplete. `scripts/test-runner.mjs:270`
signals only the immediate child and resolves on its `close` event. A fixture
suite spawned a resident grandchild with inherited stdout/stderr. Aborting the
suite killed its parent, but the suite promise remained pending after two
seconds, beyond the one-second escalation window. It resolved only after the
verifier explicitly killed that known fixture grandchild.

The guide discloses that descendants finish independently; this reproduction
shows they can also keep the gate waiting through inherited pipes. Expected:
stop the owned suite process tree or otherwise complete cancellation without
requiring the operator to wait for an arbitrary descendant. No unrelated process
was signalled.

### F4 — Medium: missing effects and unrelated refusals become observed policy

Criteria 1, 2 and 6 fail at `scripts/lib/writing-worker-probe.mjs:1190` and
`:1371`. A no-op Codex stub emitted only `turn.completed`, made no request and
returned no denial. The report nevertheless labeled X-U2 `observed` and said
the request was auto-denied. A Claude stub emitted one unrelated tool refusal
without attempting the settings-denied command; C-W3 said the deny rule refused
that command. The committed X-U2 run likewise retains zero refusal signals and
no operation-specific request/result evidence.

Expected: retain sanitized evidence identifying each attempted fixture operation
and its outcome; use `ambiguous` when causation is missing. C-W3 also needs a
control that distinguishes the settings deny from the existing noninteractive
allowlist refusal. These are deterministic counterexamples to the recorder,
not claims that a particular live harness would ignore its policy.

### F5 — Medium: recorded effort differs from the launched effort

Criterion 1 and the order's live-actor declaration fail. Both concurrent run
files say the actor used the default effort (`xhigh` for Claude, `max` for
Codex), while their saved arguments select `low`. `launchCatalog` overrides
the effort for concurrent/background launches; `runWritingWorker` still records

and resume also explicitly use `low`.

Expected: record the actual selectors for each launch/step and derive the prose
from them. Effective effort can remain unobserved. Reproduction compared the
existing per-run JSON to its own argument array; no live invocation was needed.

### F6 — Medium: detached probes retain raw output while declaring otherwise

The privacy/minimization claim in the record is false.
`scripts/lib/writing-worker-probe.mjs:328` creates raw stdout/stderr spool files;
after reading them at `:377`, it never removes them. A synthetic detached
process's raw marker remained on disk after `runProcess` returned, while every
run record unconditionally declares `rawTranscriptRetained:false`.

Expected: dispose of the owned spools after reduction, including error paths,
or accurately declare and authorize retention. The verifier inspected only its
synthetic marker and removed that fixture spool. No finding of publication of
real credentials or transcript content is made.

### F7 — Medium: suite mode normalization still differs from Git

Criterion 9 fails beyond the passing 0600 regression.
`scripts/lib/suite-evidence.mjs:46` treats any of `0o111` as Git's executable
bit. Changing a tracked fixture from 0644 to 0645 left `git diff --name-only`
empty and its index mode at 100644, but `canonicalMode` changed from 0644 to
0755. That value contributes to the suite input key.

Expected: match Git's owner-executable-bit semantics. Add this Git-invisible
permission case beside the 0600 regression; retain byte/name/owner-executable
invalidation.

Criterion 5's resident half is not established. The committed
