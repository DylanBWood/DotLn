## Findings

**F1 (blocking).** Class: correctness, path identity; a regression of behavior `main` had.

- Reproduction: base against current with the same fixture. One run used this worktree's scripts, the other `git archive HEAD scripts` (the activation base). The launchpad declares `repositories.target`, and a non-target WO-999 is started by `worktree start`.
- Observed, `status --json` from the order launchpad's own checkout:
  - no override: both select WO-999;
  - `DOTLN_LAUNCHPAD` as a symlink alias, or as a case variant: base selects WO-999; current prints the no-selection sentence, exit 0;
  - scripts called through a case-variant path: same result.
- Cause: `scripts/resume.mjs` lines 1171 to 1186 compare the physical `git rev-parse --show-toplevel` with `repoRoot` unnormalized. `findLaunchpad` resolves `DOTLN_LAUNCHPAD` lexically (`scripts/lib/config.mjs` line 800), and `TOOL_ROOT` keeps the invoked case. `registeredOrder` compares `entry.launchpad` with the same unnormalized value (`scripts/lib/target-worktrees.mjs` line 199).
- Severity: low in effect. It fails safe: no order is selected, nothing changes, and the command says so, though wrongly. It is blocking only by routing: product 07 §Verification review and attack makes a probe-shown regression of `main` behavior blocking.
- Repair rule: the follow-up string in WO-072-D006.
- Limits: tested on one case-insensitive macOS volume. The plain-launchpad regression applies only where repositories are declared or a target registry exists.

**F2 (follow-up).** Class: operator flow, output contract.

- Observed: each no-selection output above came from `status --json` and was plain text with exit 0.
- Impact: `harnessControl` and the Codex continuation parse `status --json` with cwd at the launchpad root. Inference from those call sites: they reach this path only through F1's spellings. JSON callers outside the launchpad were not surveyed.
- Boarded in WO-072-D006 for the next repair within the Boy Scout bound.
