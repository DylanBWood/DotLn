  - `commentFiles` passes both attribute names to one `check-attr -z` call. The output is one triple per attribute per path, so the existing three-field step reads both values, and either `set` excludes the file. This is the same pattern `gateCodeIdentity` uses for `dotln-generated` and `dotln-documentation`.
  - The machinery row needs a build because the registry case imports `dist`.
  - `changedMachinery` compares `.mjs` collectors byte for byte, since `evidenceSourceContent` projects only package manifests. A comment-only edit, the original drift's shape, therefore selects the row.
- **Simpler alternative.**
  - Extracting the anchor by regular expression from `protocolLineage.toString()` and from the `profile.mjs` text is fragile in general. Here the collector is pinned and formatter-ignored, so any change to those literals is itself a hash change judged by the row. D004 records the reopening condition.
  - Duplicating the roughly 15-line extraction in two tests avoids widening the five-source contract with a shared helper. That trade is reasonable and recorded.
- **Maintainer in six months.**
  - The `.gitattributes` comment, the `protection` sentence and the machinery-coverage exclusion reason explain the rule where a maintainer will look.
  - The classification repair names WO-107's commit by an abbreviated SHA, `3e29dd9d`. If that prefix ever became ambiguous, `git show` would fail loudly. Not a defect.
  - The product 03 sentence says "the lane's schema test" right after a list of several lanes; the trailing `(WO-200)` and the `dotln-pinned-bytes` attribute identify it.
- **Platform fit.** The attribute is a typed Git declaration that both rewriters read, rather than a path list or a comment convention.
