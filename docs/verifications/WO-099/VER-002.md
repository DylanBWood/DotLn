## Findings

### F1 — model failure erases a structural drift the host already proved

**Severity:** high, blocking. **Criteria:** criterion 1's outside-surface drift
and criterion 2's correction event and hold.

**Expected:** once the dispatch-time capsule exists, its host-derived findings
remain authoritative whether the model returns a pass, an invalid result or no
result. An outside-surface change therefore records `drift`, names
`contract:surfaces`, raises the hold and appends `MissionDriftObserved`; only an
otherwise unjudgeable capsule is `unknown`.

**Observed:** `startCliEpisode` preserves the observed subject when transport
fails, but returns no normalized judgment. `foldMissionJudgment` interprets a
missing result as `unknown`, supplies an empty finding list and never calls
`validateMissionCheckResult`, the function that adds structural findings. I
drove the real single-phase resident over the fixture's outside-surface diff
with the supplied unavailable runner. The recorded result was:

```json
{"heldVerdict":"unknown","findingCount":0,"failure":"model-unavailable","corrections":0}
```

The same subject normalized directly with an `unknown` model result produces
the finding the cadence lost:

```json
{"verdict":"drift","references":["contract:surfaces"],"evidence":["docs/product/00-vision.md"]}
```

This is not the existing unavailable-verifier fixture, which uses an in-surface
diff and correctly expects `unknown`. It is the conjunction of a verifier
failure and evidence the host can judge without that verifier. The direct
`runMissionCheck` helper already preserves this conjunction; the resident path
does not. [D018](../../evidence/WO-099/decisions.md#wo-099-d018) owns the
follow-up.

### F2 — an untracked symlink crosses the capsule's worktree boundary

**Severity:** high, blocking. **Criterion:** criterion 1's complete current
diff and the design's bounded, read-only capsule.

**Expected:** a repository-relative changed path never grants a read outside
the canonical worktree. An untracked symlink is represented as a symlink (as
Git would record it) or is explicitly omitted/refused; its target file's bytes
never enter the capsule. Reads are bounded before allocation.

**Observed:** `untrackedSection` calls `readFileSync(join(root, path), "utf8")`
without an `lstat` or containment check. `missionPath` validates the link's
repository-relative name, not the resolved target. In a synthetic fixture I
placed a link under the declared source surface whose target was a marker file
in system temporary storage outside the worktree. No private user file was
read. The observation was:

```json
{"linkNamed":true,"outsideBytesIncluded":true,"omittedPaths":[],"verdict":"on-mission","findings":0}
```

The host therefore sent bytes that are not the repository diff and admitted a
pass over them. The same unbounded `readFileSync` also allocates an untracked
file before the 600,000-character capsule bound is applied, so a very large
regular file or special file does not reliably fail closed at the declared
boundary. [D019](../../evidence/WO-099/decisions.md#wo-099-d019) owns the
follow-up.
