### F1 — one ordinary build holds the supervisor permanently, and three documents say it does not

**Severity:** high, blocking. **Criterion:** 4 (the write-backs land). The
behaviour also defeats the objective's "holds every unattended dispatch until a
human answer or a verified repair clears it", because neither clearance holds.

**Expected:** what product 03 §Operator-presence policy states at lines
1952–1953 — "Existing ignored build and runtime trees form the baseline instead
of raising a permanent hold" — and what repair-004 and D031 restate: routine
rebuildable output does not move an entry off its baseline, so the cadence keeps
judging real work rather than its own tooling's residue.

**Observed:** the baseline fingerprints a git directory-collapsed ignored entry
as a hash of `lstat` kind/mode/size/mtime
(`packages/skeleton/src/mission-check-source.ts:147`). Two ordinary build
effects move that metadata on a *collapsed root*, not merely inside it:
`atomicBuild` creates and removes a staging directory directly under `.runtime/`
(`scripts/build.mjs:68`), and `publishBuildTree` renames `tsconfig.tsbuildinfo`,
a direct child, into each `dist/` (`scripts/build.mjs:52`). Both are direct-child
mutations, which move the parent directory's mtime; a nested rewrite does not.
Once moved, the entry never returns to the pin, and the pin is fixed at actor
declaration (`packages/skeleton/src/cli-actor.ts:105` takes
`missionPin(spec.request.subject)`), so every later pulse reports the same
entries as changed. `validateMissionCheckResult` then forbids `on-mission` while
any ignored entry is present, and an outside-surface entry is a host-derived
`contract:surfaces` drift, so the verdict is `drift` outside the surfaces and
`unknown` inside them — both of which hold.

`npm test`, `npm run skeleton`, `npm run dotln`, `npm run console` and every
`evidence:*` script run the build first, so this fires during exactly the
interval the episode supervises.

**Reproduction.** Against the real repository, pin a `MissionSource` over this
worktree (contract `docs/work-orders/WO-099-mission-check.md`, vision
`docs/product/00-vision.md`, decisions `docs/evidence/WO-099/decisions.md`, base
`47910753`, declared surfaces `packages/skeleton`, `scripts`, `docs`), observe a
quiet pulse, run `npm run build --silent`, then observe twice more. The
independently executed result was:

`dist/` roots; the fifth, `packages/skeleton/dist/`, is inside a declared surface

This is a false hold, not a false pass, and so a different class from VER-004 F1:

This judgment protects Gate R's promised reduction in recurring operator
supervision. The fourth repair is real progress: ignored out-of-surface work is
now observed without any private name, byte or salt reaching the judge, and the
host's proof survives a judge that would talk over it. The material choice is a

**Seeking the wrong goal** is the sharpest lens, from the opposite side of
VER-004: an instrument that reports drift over its own build residue is
measuring the tractable part of supervision again, and it trains the operator to
dismiss the record 02 §Feedback says a returning human reads. **Policy
resistance / fixes that fail** is the shape — the repair widened what the capsule
carries and the widening now catches the tooling. **Drift to low performance**
cautions against letting a permanently-held cadence become the normal reading of
"supervised". **Shifting the burden to the intervenor** is measured, not
asserted: the human answer clears, and the next pulse re-raises. **Rule beating**
is the green gate beside the counterexample. **Tragedy of the commons** favoured
deterministic probes and one product gate over another paid live run.
**Escalation** favours a bounded rule at the existing join over a new mechanism.
**Success to the successful** supplies no exemption for an implementation with a
live row and four repairs behind it.

Naive Interventionism argues for the smallest honest change, and the repair has
three bounded options that need no new capsule content. NoOp would leave a
supervisor that stops all unattended work after the first build while three
documents promise it does not, which is the claim-without-evidence the Clean
Room floor forbids. Reopen when a metadata-only move of a baseline entry no
longer forces a hold, when the fixture suite covers a worktree with ignore rules
and a build, when the existing repair cases stay green, and when the three
documents state the property the code has. The observed benefit is a reproducible
repair target, not a measured reduction in operator effort or total workflow
