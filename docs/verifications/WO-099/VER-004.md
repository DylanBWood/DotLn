## Findings

### F1 — work the repository's own ignore rules exclude is invisible to the capsule, and a pass is certified over it

**Severity:** high, blocking. **Criteria:** 1 (out-of-surface drift yields
`drift` naming the clause) and 2 (the drift correction and dispatch hold).

**Expected:** the capsule's changed-path list is what the objective and the
judge's own instructions say it is — every path the work changed, tracked or
untracked. Where that cannot hold, the boundary is named, as `omittedPaths` and
`omittedDecisions` already name theirs, so no pass is certified over work that
was never shown.

**Observed:** `observeMission` lists untracked work with
`git ls-files --others --exclude-standard`
(`packages/skeleton/src/mission-check-source.ts:277`), so every path the
repository's ignore rules exclude is absent from `changedPaths`. Nothing else
compensates: the tracked `git diff` cannot see an untracked file, no omission
reason is set, and `structuralMissionFindings` therefore derives nothing. A
claimed pass over such a capsule is admitted as `on-mission`, and the resident
raises no hold. The judge is meanwhile told, in `missionCheckPrompt`, that
"`diff.changedPaths` is every path the work changed, tracked or untracked", and
the field's own contract in `mission-check-protocol.ts` says "Every path the
work changed, tracked or not. Complete or the observation refuses." No decision,
product section or work-order clause records the exclusion; the nearest record
is [D012](../../evidence/WO-099/decisions.md#wo-099-d012)'s rejected option
"Ignore untracked files because git diff ignores them", refused there for
exactly this reason.

In this repository the excluded set is not marginal. `.gitignore` covers
`docs/intake/**` (the Clean Room's single-copy source material), `.env` and
`.env.*`, `/docs/control/local/`, `/.claude/settings.local.json` (the operator's
own permission settings), `/.runtime/`, `/.beacons/`, `/.control-beacons/` and
`dist/`. A session that writes into any of them while it is away is outside its
declared surfaces and invisible to the check that exists to say so.

**Reproduction:** after the build, import `missionFixture` and `missionRunner`
from `packages/skeleton/dist/test/mission-check.fixture.js`. Create
`missionFixture({ missionOnly: true })`, write the repository's own rules
(`docs/intake/**`, `!docs/intake/**/`, `.env`, `.env.*`, `!.env.example`,
`/docs/control/local/`) into `.gitignore` in the fixture worktree, commit so the
rules are part of the baseline, and take that commit as `baseCommit`. Then write
two out-of-surface files, `docs/intake/employer-notes.md` and `.env`, leaving
the declared surface `packages/fixture` untouched. Observe through
`observeMissionSubject(source, pin)` and normalize
`{ schemaVersion: "mission-check-v1", verdict: "on-mission", findings: [] }`.
Drive the same base through a real `ResidentHost` with `actorCatalog` and
`cliWorkerAdapter({ version: "0.154.0", runner })`, starting at fake time 0,
recording `away` and ticking at time 10. The control repeats the identical work
with no ignore rules. The independently executed results were:


A separate run of the same probe confirmed that the prompt handed to the judge
carries the completeness claim while `changedPaths` is empty

This is a completeness defect, not an argument for carrying every ignored byte:

### F2 — a judge that repeats a host-derived finding replaces the host's own reason

**Severity:** minor. Not blocking on its own; recorded for the same repair pass.
**Requirement:** product 03's rule that the two capsule-derived drifts "survive
any claimed pass", and product 02 §Feedback's account of `MissionDriftObserved`
as the record that "carries the finding itself".

**Expected:** a judge may add findings and may agree with the host's, but it
cannot restate what the host proved. The reason is the host's proof that the
path is outside the declared surfaces or that the clause changed after the pin;
it is the sentence a returning human reads in the correction event.

**Observed:** `validateMissionCheckResult` deduplicates
`[...structural, ...supplied]` into a `Map` keyed on `kind`, `reference` and
`evidence`. `reason` is not part of the key and the supplied entry is inserted
last, so a judge that returns a finding with the host's key and its own prose
wins. The verdict is unaffected — it is still `drift`, and the hold still stands
— and the hold's own one-line reason is host-composed from `reference` and
`evidence`. But the normalized findings, the `MissionHold.findings` and the
`MissionDriftObserved` payload all carry the judge's sentence in place of the
host's.

**Reproduction:** create `missionFixture({ outsideSurface: true,
missionOnly: true })`, observe the subject, take `structuralMissionFindings` of
it, and return those same findings from the runner with `reason` replaced. The
independently executed output was:

```json
{"probe":"judge-repeats-a-host-finding","hostReason":"The diff edits docs/product/00-vision.md, which is outside the declared surfaces packages/fixture.","judgeReason":"Reviewed: this path is covered by the operator's standing exception; no action is needed.","normalizedReason":"Reviewed: this path is covered by the operator's standing exception; no action is needed.","hostReasonSurvives":false,"findingCount":1,"verdict":"drift","heldVerdict":"drift","heldReason":"mission check script_ab334cf3748d06f7 found drift: contract:surfaces (docs/product/00-vision.md)","correctionReason":"Reviewed: this path is covered by the operator's standing exception; no action is needed."}
```

The dispatch stays frozen, so this does not admit unsupervised work; what it
admits is model prose standing where the host's proof should be, in the one
record 02 §Feedback says a non-operator producer writes. The repair is small —
let the host's entry win its own key, or keep the judge's agreement as a
separate field — and it must stay closed under the normalization VER-003 F1
established. [D030](../../evidence/WO-099/decisions.md#wo-099-d030) owns it.

## Goal alignment

This judgment protects Gate R's promised reduction in recurring operator
supervision. The third repair is real progress: the result contract is now
closed under its own normalization at the capsule's bounds, a refused judgment
is recorded as the failed episode it is rather than thrown out of the
observation, and an unreadable decision history is named instead of read as
absence. The material choice is a bounded repair handoff supported by executable
counterexamples, rather than accepting the order on a green suite and a live
receipt.

All eight lenses support that choice. **Seeking the wrong goal** is the sharpest
here: the instrument reports `on-mission` over work it never looked at, which is
worse than reporting `unknown`, and a check that cannot see the operator's own
ignored settings, secrets or clean-room intake is measuring the tractable part
of supervision rather than the part that matters. **Shifting the burden to the
intervenor** describes both findings' consequence — a human rediscovers the
ignored drift, and reads model prose where the host's proof should be.
**Policy resistance / fixes that fail** is visible in F1's shape: each repair so
far has widened what the capsule carries, and this is the same class one layer
earlier, before any bound applies. **Rule beating** is demonstrated by a green
gate beside both counterexamples. **Drift to low performance** cautions against
letting "every path Git reports" quietly become the definition of "every path
the work changed". **Tragedy of the commons** favoured deterministic scratch
probes and one product gate over another paid live run. **Escalation** favours
regressions at the existing joins — `omittedPaths` already carries "named but
not shown" — over new workflows. **Success to the successful** supplies no
exemption for an implementation that already has a live row and three repairs.

Naive Interventionism argues for the smallest honest change: F1 does not require
carrying every ignored byte, and F2 does not require a new field if the host's
entry simply wins its own key. NoOp would leave a supervisor that certifies work
it cannot see, and would leave the correction record forgeable in prose; a
failed verdict with D029–D030 is preferable. Reopen when an ignored
out-of-surface entry is either observed as a finding or named as an omission
that forbids a pass, when a judge cannot restate a host-derived reason, when the
existing repair cases stay green, and when current evidence covers the repaired
source. The observed benefit is a reproducible repair target, not a measured
reduction in operator effort or total workflow tokens.
