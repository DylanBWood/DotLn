## Findings

### F1 — the resident cannot perform or apply the promised repair re-verification

**Severity:** high, blocking. **Criteria:** criterion 1's mid-episode contract
change and criterion 2's passing re-verification clearance.

**Expected:** each cadence completes the pinned capsule with the current
contract, diff and decisions, dispatches a judge authorized for that completed
subject, and clears an existing hold when a fresh `on-mission` judgment covers
changed work.

**Observed:** `startCliEpisode` builds the current subject, then
`cliActorRequest` replaces only `subject` and `episodeId` on the actor's saved
request. The saved command remains bound to the original subject hash.
`validateMissionCheckRequest` requires the command payload hash to equal the
current subject hash, so any real work change is rejected as `profile-refused`
before the model runner is called.

I reproduced the cadence path with the built modules and the supplied
`missionFixture`, reduced to its single mission phase. I declared the actor,
changed and committed the in-surface fixture work, marked the operator away and
ran the due tick with a counting pass runner. The result was:

```json
{"runnerCalls":0,"failure":"profile-refused","recordedVerdict":"unknown","held":"unknown"}
```

This is not the path exercised by the first acceptance fixture. That fixture
calls `runMissionCheck(changedSubject, ...)`, which builds a new request and
command together; the resident reuses the old command.

There is a second independent break in the same promised path. I constructed a
valid pending resident episode from the held state and folded an admitted
`on-mission` observation over a new, different subject hash. The fold recorded
the fresh pass but retained the old hold:

```json
{"hashesDiffer":true,"recordedFreshVerdict":"on-mission","holdAfterPass":"unknown"}
```

That follows directly from `foldMissionJudgment`: after recording the new row,
`if (verdict === "on-mission" || state.dispatchHeld) return;` prevents the
observation from appending or applying `MissionHoldCleared`. The only production
function that can append that event, `clearMissionHold`, has no caller outside
the direct tests and the live collector's human-answer path. The fixture named
"only a passing judgment over changed work clears the hold" calls that function
itself; it does not exercise a resident re-verification.

**Repair shape:** rebuild the command/request from the dispatch-time subject and
current episode identity, then make the resident append a validated
`MissionHoldCleared` event when a fresh admitted pass has a different subject
hash. Cover the combined cadence path, not only the direct helper. D011 owns the
follow-up.

### F2 — incomplete source projection can certify drift as on-mission

**Severity:** high, blocking. **Criterion:** criterion 1's requirement that a
diff outside the declared surfaces yield `drift`, plus its mid-episode contract
change case.

**Expected:** the capsule contains the active diff and contract. If an explicit
size bound prevents that, the result fails closed as `unknown` or a refusal; it
does not silently remove evidence and admit `on-mission`.

**Observed:** `observeMission` uses ordinary `git diff <base>`, so untracked
files never enter either `changedPaths` or `text`. It then silently keeps only
the first 100 changed paths and first 100,000 diff characters. `missionClauses`
silently slices each collapsed clause to 4,000 characters. All three omissions
can hide the only evidence of drift.

Independent probes against the built modules produced:

```json
{"probe":"untracked-path","changedPaths":["packages/fixture/src/judge.ts"],"diffContainsOutside":false,"verdict":"on-mission","findings":0}
{"probe":"path-cap","changedPathCount":100,"outsideListed":false,"diffContainsOutside":true,"verdict":"on-mission","findings":0}
{"probe":"clause-cap","projectedEqual":true,"projectedObjectiveLength":4000}
```

For the path-cap probe, the fixture had 100 tracked in-surface changes followed
by tracked `zz-outside/drift.ts`. The full diff text still named the outside
path, but the structural rule could not see it and the output schema would not
allow a model finding to cite it because evidence IDs come from the truncated
path list. A claimed pass was therefore accepted. For the clause probe, two
otherwise identical contracts differed after byte 4,000 and projected to
byte-identical objective clauses.

The untracked case matters especially in this repository: branch commits are
forbidden before final review, so a new implementation file ordinarily remains
untracked during the very interval the mission check supervises. The existing
fixture commits the work-in-progress before observation and uses a small diff;
the live collector uses the same fixture shape. Neither covers this finding.

**Repair shape:** represent untracked work, and replace every silent cap with a
complete bounded representation or a fail-closed `unknown`/refusal. Add the
three adversarial regressions above. D012 owns the follow-up.
