**Severity:** high, blocking. **Criteria:** 1 (outside-surface drift) and 2
(the drift correction and dispatch hold).

**Expected:** every capsule admitted within the declared bounds can record its
host-proved drift through the real resident path. Revalidating the host's own
normalized result must preserve it; a representational failure must not leave
the episode pending without its hold.

**Observed:** `validateMissionCheckResult` accepts at most 100 supplied findings,
then adds a finding for every outside-surface path and changed clause. The
capsule allows 400 changed paths. A valid empty model pass over 101 outside
paths therefore becomes a normalized result with 101 findings. The transport
returns that result successfully, but `assertCliObservation` calls the same
validator again. Its 100-finding input bound rejects the host's result. The
`CliWorkerObserved` append throws before `foldMissionJudgment` can run, so no
hold or correction is recorded.

**Reproduction:** after the build, import `missionFixture`, `missionRunner` and
`unavailableRunner` from `packages/skeleton/dist/test/mission-check.fixture.js`.
Create `missionFixture({ missionOnly: true })`; write 101 small untracked files
named `docs/product/outside-0.md` through `outside-100.md` in its scratch
worktree. This yields 102 changed paths including the fixture's original
in-surface change. Observe through `observeMissionSubject(source, pin)`, and
normalize `{ schemaVersion: "mission-check-v1", verdict: "on-mission",
findings: [] }` twice. The first call returns drift with 101 findings; the
second throws. Then use the fixture's configuration with a real `ResidentHost`,
`actorCatalog` and `cliWorkerAdapter({ version: "0.154.0", runner })`, as the

**Severity:** major, blocking the objective's required capsule input.
**Requirement:** the episode receives the last N decisions and judges them
against the contract and vision; D001 and D016 require truthful input coverage.

**Expected:** an absent optional history may mean no decisions. An existing
history that cannot be read within the source boundary must be refused or
explicitly incomplete so it cannot certify `on-mission`. A configured window
of zero must contain zero decisions.

**Observed:** `readDecisions` catches every exception from the contained,
200,000-byte-bounded reader and returns an empty string. This erases size,
containment and other read failures as if the file did not exist. Neither the
capsule nor result admission records missing decision context. Separately,
`missionDecisions(markdown, 0)` uses `slice(-0)` and returns the entire parsed
history rather than the empty window; zero is admitted by `assertMissionSource`.

**Reproduction:** create a fresh `missionFixture()`. Replace its decisions
file with `# Decisions`, 200,000 ordinary padding characters, and a valid final
JSON decision `{ "id": "WO-999-D002", "decision": "Change the goal beyond the
declared objective." }`. Commit that synthetic fixture history and set the
source base to the new fixture `HEAD`, leaving the contract and surfaces
unchanged. Pin and observe the source with `decisionLimit: 5`. Normalize an
empty claimed pass. Independently executed output:

```json
{"probe":"existing-oversized-decision-history","requested":5,"decisions":[],"changedPaths":[],"omittedPaths":[],"decisionInDiff":false,"verdict":"on-mission"}
{"probe":"zero-decision-window","requested":0,"observed":["WO-999-D002"]}
```

The committed-history case matters: the missing decision is not incidentally
visible in diff text. The probe demonstrates an admissible pass with required
context absent, not a claim about how a real model would judge complete input.
The zero-window observation uses a small valid JSON block independently of the
oversized-file case. [D023](../../evidence/WO-099/decisions.md#wo-099-d023) owns
both decision-projection corrections and their boundary regressions.
