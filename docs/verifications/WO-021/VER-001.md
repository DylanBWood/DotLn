## Non-blocking observations

1. **The WO-016 reactor-purity assertion is now a module allowlist.**
   `packages/skeleton/test/scenario.test.ts` widens the permitted import list
   from `["@dotln/kernel", "@dotln/compiler"]` to include
   `./control-codebook.mjs` and `./control-beacon.js`. I verified both are
   genuinely pure today: `control-beacon.ts` has only type-only imports plus a
   pure renderer, and `control-codebook.mjs` imports only `beacon-codebook.mjs`,
   which imports nothing. But purity was previously guaranteed by a package
   boundary and is now asserted by naming two files, so a future `node:`
   import into either module would not trip the test. WO-022 could assert
   transitively that no module reachable from the reactor imports a `node:`
   builtin.
2. **A framing tag is no longer free for individual v3.** `versionRadix` is 4;
   tag 0 is reserved malformed, 1 and 2 are individual v1/v2, and 3 is now the
   phase-group family. Nothing is ambiguous today because the group is selected
   only by its own directory and decoder, and the individual reader correctly
   labels tag 3 `unknown-codebook`; 10, WO-022's input block, and the receipt
   all state this. Recording it so the constraint is visible at final review:
   WO-022's individual v3 will need a wider framing radix or a directory-scoped
   tag reuse, not a free slot.
3. **`emitControlBeacon` collapses every failure into one generic message.**
   The blanket `catch` deliberately avoids disclosing a path, but it also
   discards the cause, so an operator who sees `host beacon projection
   unavailable` has no signal distinguishing a permission problem from a
   symlinked directory or an exceeded bound. A sanitized cause class, with no
   path, would keep the disclosure property and improve diagnosis.
4. **A storage probe runs on every lifecycle transition.**
   `probeBeaconStorage` creates and removes a temporary probe file and, on a
   sparse host, `ftruncate`s it to the full 192,763,452,654-byte group maximum
   before every emission. It is instant and allocation-free on this APFS host,
   and re-observing rather than assuming is the honest choice, but it makes each
   transition's projection depend on a filesystem probe: a host that supports a
   64-KiB hole yet refuses the large truncate would warn on every transition.
   The transition itself still records, so this cannot block the lifecycle.
5. **`resume times` is not in the fixture's beacon snapshot assertions.**
   `scripts/test-resume.sh` brackets `status` and `next` only. `times` is not a
   transition and cannot reach `appendTransition`, and I confirmed on the live
   repository that it leaves all three beacons' inode, size, mtime, and ctime
   and the control segment byte-identical — but the guarantee is currently
   structural rather than tested.
6. **`current.md` renders an absent verdict as `none` while the beacon encodes
   `unknown`.** Both denote the same absence and the shipped assertion maps
   them correctly, but AC1's phrasing ("the phase and verdict `current.md`
   reports") is satisfied only under that mapping. Worth naming so a future
   reader does not treat the two vocabularies as a disagreement. Relatedly, the
   fixture compares the decoded verdict against the folded status JSON and
   compares only the `Phase:` line against `current.md`.
7. **A stray file in `.control-beacons/sessions/` would warn on every
   transition.** `emitControlBeacon` throws `invalid session file` for any name
   not matching `<64-hex>.json` while enumerating sessions, and that throw is
   inside the blanket catch, so a single `.DS_Store` there would make every
   subsequent transition report an unavailable projection. The directory is
   host-managed, hidden, and gitignored, so the risk is small; ignoring
   non-matching names would be equally safe.
8. **The `--agent` form never consults the group cache.** Its group row
   therefore always reads `derived from this sweep; no matching cache read`,
   while the plain command reads the cache. Both are correct — the authorized
   observation deliberately covers only the public projection directories — but
   04's sentence about labelling "its host-cache or sweep-derived source" does
   not say the authorized form always takes the derived branch.
