## Blocking finding

**F1 — the final-review report-header agreement check is unproven, and several
new refusal rules have no refusal case (criterion 7).**

Criterion 7 requires the suite to prove that *verification and final-review*
report actor headers are checked before their completion events append, and to
carry one refusal per rule with "no event appended" asserted. The verification
half is proven and load-bearing. The final-review half is not: the suite writes
a correct header before every `final-review-result` call and never exercises a
missing, duplicated, malformed, or mismatched one.

Reproduction — delete the `requireReportActor(...)` call from the
`final-review-result` case in `scripts/resume.mjs`, leaving the verification
call site intact, then run the full suite:

```text

...

worktree tests passed
```

carrying no header refuses with `final-review report must contain exactly one
machine-readable actor header; expected: ...` and appends nothing — but no test
in the repository would notice its removal.

A systematic mutation sweep of the new surface (29 mutants, each verified to
apply and to leave valid JavaScript) found the same shape in five more places.
Killed: the ladder check, the verification header check, drift rendering, the

## Observations — not defects, for the final reviewer

1. **The reviewer's own header can collide with its quoting duty.**
   `docs/final-reviews/README.md` asks the reviewer to list "each completed
   verifier's report header beside its control actor", while
   `requireReportActor` refuses any report containing more than one line
   *starting* with `**Actor attestation:**`. I reproduced this: a report that
   quotes the canonical example at column one — even inside a fenced code block
   — refuses. FINAL-001 must therefore indent, blockquote, or otherwise
   left-pad any header it quotes. Consistent with the order's "duplicate labels
   are ambiguous and refuse" philosophy, but it will bite the very next session
   if unnoticed.
2. **Drift is a distinct-pair set, rendered with an arrow.** `high -> low ->
   high` projects as `high -> low`, because identical pairs are deduplicated as
   criterion 5 requires. The arrow reads chronologically and could suggest the
   order ended at `low`; `- Latest attestation:` carries the actual latest
   value, so the projection as a whole is not misleading. Worth a sentence in
   the guide if a future order revisits the projection.
3. **`worktree start` creates the worktree before activating.** Activation can
   now refuse for a new reason (missing or malformed declaration), leaving a
   stray worktree behind with `worktree created but resume activation failed:
   ...`. Pre-existing ordering, newly more reachable; the PLAYBOOK write-back
   anticipates it by telling the operator to confirm both lines before `start`.
   Natural WO-018 territory.
4. **`"WO-019"` is a permanent string literal in production code.** The strict
   migration boundary is spelled out in the scope fence, so this is as
   specified, and work-order ids are unique so it is inert after close. Noting
   it so a later refactor does not mistake it for an accident.
5. **The committed probe records one personal-settings value.**
   `environment.json` carries codex-cli's persisted `model_reasoning_effort`
   value `xhigh`, read from the operator's local config. The order explicitly
   permits printing only the level, and only the level was printed — no path,
   scope, or surrounding content. It is also load-bearing: that recorded value
   is what makes `--effort xhigh` acceptable for `codex-cli 0.152.1`, so it will
   go stale if the operator changes the setting or upgrades the harness.
6. **Clean-room screen: clean.** I screened all 1826 added lines for the terms
   `CLAUDE.md` names as must-not-re-enter and for credential/host shapes. No
   commercial tracker or ALM product name, no predecessor-system reference (the
   one `v1` hit is `schema-v1`, the control-log schema version), no managed-host
   or corporate-gateway description, no URL, endpoint, credential, or private
   identifier. The ideation breakout's promoted surfaces
   (`03-architecture.md`, `05-pattern-library.md`, `06-roadmap.md`,
   `09-audit-resilience-privacy.md`, `11-proteino.md`) read as explicitly
   labeled candidates and future framing — "Candidate —", "may", "remains an
   explicit scenario choice" — with no speculative experiment presented as
   implemented and no expansion of WO-019's acceptance surface. The ledger
   addition is 235 insertions and zero deletions, and the effort-truth entry of
   2026-08-31 gains a dated "Adopted prospectively by WO-019" bullet without a
   word of it being rewritten. The suggestion-only authority of the Snooping
   Footprint Reducer, the limit of action-gem self-evidence, the
