## Findings for repair

**F6 — a descriptor watch whose supervisor endpoint has closed adopts a process the task never started, so the survivor sweep names and kills it.** Class: recycled ownership identity, a false positive in the survivor sweep. Severity: high. Breaks criterion 3, the survivor sweep and "kills every task group it started", and criterion 8 (`npm run test:docs` green). It is D011's reopen condition, "a recycled identity adopts an unrelated process". It lies inside the order's surfaces: `scripts/test-runner.mjs`, `scripts/lib/host-footprint.c`, `scripts/lib/host-resources.mjs` and `scripts/lib/process-monitor.mjs`.

- **Observed in the gate.**
  - `npm run test:docs` at the subject identity failed twice in a row.
  - Rows recorded 2026-10-03T14:48:05.989Z and 14:54:22.612Z, each `14 passed; 10 failed`.
  - Each time `feedback-evidence` reported `surviving-process {"survivingProcesses":[{"pid":22368,"name":"host-footprint-"}]}`, and pid 48323 in the second run. `entropy`, `plan`, `registrations`, `plan-refutation-current`, `console-docs`, `skeleton-docs`, `kernel-docs`, `lineage-fixtures` and `docs-check-fixtures` then failed preflight on it.
  - The task schedule matches the executor's passing runs at the same identity (05:04:05.812Z and 05:07:31.006Z). In all four runs `feedback-evidence` finishes beside `meta`.
- **Why that survivor is not the task's.** This step is inferred; the supporting evidence is:
  - `scripts/feedback-evidence.mjs` spawns nothing.
  - None of the 42 modules reachable from it through relative imports references `host-resources`, `host-footprint`, `readHostSnapshot`, `captureTaskDescriptors`, `ensureHostGuard` or `test-runner.mjs`.
  - `host-footprint-<digest>` is the census and `--capture` helper. Only the runner, the bounded wrapper and the guard spawn it, through `execFileSync` with fresh pipes.
  - In `ownedProcesses`, every path except the descriptor tag needs ancestry, group or prior-identity evidence that such a helper cannot carry: root, pgid, the `known` pid and birth map, the ppid closure and the parent-unique-ID closure.
- **Mechanism, reproduced directly.** Probe 7 (`reuse2/probe.mjs`):
  1. It spawns a Node child with piped stdout and stderr and captures its marks with `captureTaskDescriptors`.
  2. It waits for `close`, by which point Node has auto-closed this process's ends at EOF.
  3. It spawns a sibling Node process with fresh pipes.
  4. It runs `readHostSnapshot` with the dead child's watch.
  - On iteration 0 the census tagged the sibling, pid 39405 with ppid the probe, with the dead child's key.
  - Totals: 1 tag in 120 sibling iterations, and 0 in 120 each of census-only and after-`spawnSync`.
  - Probe 6 found no false survivor in 300 serial `executeSuite` runs. The trigger depends on allocation timing, which the concurrent docs gate supplied twice running.
- **Why the check passes.** From source:
  - `live_peer` (`scripts/lib/host-footprint.c`) re-validates a watch only by the supervisor's pid and birth, its fd number, and the socket's kernel identity `soi_so == handle`.
  - After the runner's end closes, a new socket can take the same fd number. Node closes the child stdio streams at EOF before `close` fires, and the runner later opens census, capture and task pipes.
  - Kernel identity values are reusable after free, so the check accepts the new socket. Its peer, whichever process holds it, is then adopted.
  - In the runner, that process becomes a member and appears in `survivingProcesses`. `monitor.finish` kills it through `killOwned`, and the ppid closure extends adoption to its descendants. A sibling task started by the same supervisor is reachable, as probe 7's sibling shows.
  - D012 states "disconnected or reused descriptors do not establish ownership". The reproduction contradicts that statement.
- **Expected.** Criterion 3 and the Design's "sweeps for surviving task processes" name and kill the task's own survivors. A task that leaves nothing behind passes. `npm run test:docs` is green at the subject.
- **Rule a repair must hold.**
  - A descriptor mark confers ownership only while the endpoint the supervisor captured is still that same open endpoint. Once the supervisor has closed it, or might have reused its fd number, the watch is dropped, by the runner, the bounded wrapper and the guard alike, before any census can use it. Kernel-identity equality alone never re-establishes ownership.
  - No process the task did not start is adopted, named as a survivor or killed. That covers a census or capture helper, a sibling task or any process spawned after the task's endpoints closed.
  - A deterministic fixture pins the case: after a watched task's endpoints close, a sibling with fresh pipes on a reused fd is not adopted. Another fixture shows the docs gate's ordinary tasks pass.
  - VER-001 F1's descriptor-bearing detach cases stay caught.
  - Afterwards, `npm run test:docs` and `npm test -- --review` pass at the repaired identity.
- **Non-binding notes.**
  - Keeping the supervisor's stdout and stderr ends open, without destroying them, until after the final census and the registration release would prevent the fd and identity reuse. A fully closed child end then reports no connected peer (`unsi_conn_so` 0), so `live_peer` returns 0.
  - The registration the guard reads carries the same watch, so it must be removed no later than the endpoints close.
  - That ordering is untested.
