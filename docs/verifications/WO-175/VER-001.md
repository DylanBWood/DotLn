## Boarded, not failed

- **D012 (FUP-84e5edb1566a4db1), instruction composition.** `temporaryInstruction` is prepended with a leading space and no separator: `…writes stay inside these two roots.Run one…` and `…roots.Attempt to falsify…`. The refutation instruction has no fixture assertion, and the review's substring assertion cannot see the join. Repair rule: both composed instructions start with a non-space character, exactly one space separates the added sentence from the next, and a fixture asserts the exact prefix of both prompts. Ride the next order that edits the protocol, because a repair re-mints five editions and needs a live feedback audit.
- **D013 (FUP-e245dc67344b4261), launch-scope leak.** `launchInTemporaryDirectory` changes the host process's own `TMPDIR` for the synchronous dispatch. The host's schema directory, its raw stdout capture and (for Codex) the isolated home are therefore created inside the worker's writable temporary root. A probe shows a real `runWorkerProcess` child listing `dotln-worker-output-eix3D9` in its `TMPDIR`, with the directory empty after close, so receipts are unaffected on the normal path. Inference: a worker that cleans its temporary root can remove the capture the host later reads by path. Repair rule: the worker's launch environment alone carries the episode `TMPDIR`, and no host-owned temporary appears in it while the worker runs. This needs `worker-transport.ts`, which the order cites read-only.
- **D014 (reopens WO-157-D016; register FUP-6d4ea0b291ebdae5), fixture teardown race.** The runner-fixtures case `code identity follows tracked source and dependency bytes across processes and revisions` commits twice without `maintenance.auto=false`. Its surviving root held only `.git/objects/pack`, D016's signature, and I removed it. Repair rule, from D016: every fixture repository that commits disables auto-maintenance before its first commit, so no detached repack writes during teardown.
