## Nonblocking follow-ups

### VER-001 F1 — An invalid host lane capacity record refuses every gate without naming itself

**Class:** defect in a declared surface; follow-up ([D018](../../evidence/WO-222/decisions.md#wo-222-d018), FUP-66085a13c95d0f34). **Criterion:** none broken (1 holds).

Expected: a refusal names what failed and the remedy. Observed: the `registry` probe forges the record. A value outside one to eight, or a string, refuses with `Invalid recorded host lane capacity`. Malformed or empty JSON refuses with the bare parser message (`Unexpected token 'o', "not json" is not valid JSON`; `Unexpected end of JSON input`). By the code, the gate entry, the bounded wrapper, session registration, `executeSuite` and the structural host check all read the record. Every clone on the host would therefore refuse until someone removes it by hand. Failing closed is right; silently re-deriving would let clones disagree while leases are live.

The record is written by rename, so the reproduction forges it. **Repair rule:** an unreadable or invalid record refuses with one message naming the record by label, the defect and the remedy, with fixtures for both shapes.
