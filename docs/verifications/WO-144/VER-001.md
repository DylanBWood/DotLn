## Blocking findings (route to repair)

### F1 — Discard redirects to `/dev/null` are refused as outside-project writes

- **Criterion:** 2 and the design rule "defaults come from observation".
  Measured against the evidence gate's reopening observation.
- **Observed:** `true 2>/dev/null`, run at `2026-09-19T20:49:41.800Z`, was
  denied before execution:
  `DOTLN_HARNESS_REFUSED: outside-project write to /dev/null (physical destination /dev/null) lacks an equipped outside-write grant for role verifier (WO-144)`.
  - Journal rows 326–329 record `outsideWrite.destination` `/dev/null` with
    status `refused`.
  - An ordinary read-only search whose last stage ended in `2>/dev/null` was
    refused the same way at `20:49:25.462Z` (rows 302–305).
  - For that call the earlier permission hook recorded
    `"effect":"shell.run","allowed":true` (row 308). The refusal is WO-144's
    alone.
- **Expected:** the order protects against creating or deleting files in the
  operator's folders. A discard redirect to the null device does neither. It
  is the most common outside destination in ordinary agent shell use, so
  defaults taken from observation cover it. A refusal here is the order's
  named reopening observation.
- **Cause (code):**
  - `shellWriteTargets` pushes every literal redirect operand, `/dev/null`
    included (`packages/skeleton/src/harness-command.ts:449–455`).
  - `outsideWriteResponse` judges every extracted destination outside the
    root against the role's grants
    (`packages/skeleton/src/harness-host.ts`, `outsideWriteResponse`).
  - No grant kind contains `/dev`.
- **Inference from the same code path, not probed:** `/dev/stderr`,
  `/dev/stdout`, `/dev/tty` and `/dev/fd/N` redirects are refused the same
  way.
- **Fixture gap:** the only `/dev/null` operand in the WO-144 fixtures is
  `/dev/null/child`, which is expected to be refused
  (`scripts/test-harness.mjs:3952`, `:4317`). No fixture asserts that a
  discard redirect is admitted.
- **Reach:** every Claude session in this repository.
  - Roles carry no `/dev` grant.
  - A session with no active role has no outside grant at all (fixture
    "no active role").
  - This session hit the refusal by accident once, in its first twenty or
    so commands, during an ordinary search. The second hit was the
    deliberate minimal reproduction. An earlier piped command with
    `2>/dev/null` was not parsed by the extractor, so it was admitted as
    unobserved.
- **Second-order effect:** each refusal costs a turn. The easy workaround,
  rewriting the command into a form the extractor cannot parse, moves it
  under host permissions without judgment (rule beating).
- **Severity:** high.
- **Repair direction (executor's choice):** either do not treat the null
  device and standard-stream device paths as file destinations, or grant them
  by default with a source. Add admission fixtures for `2>/dev/null`,
  `>/dev/null 2>&1` and `&>/dev/null`. Keep `/dev/null/child` refused.
- **Limits:** only `/dev/null` was probed live.

  `TMPDIR` and `/tmp`.
- **Limits:**

  - Whether subagent tool calls inherit the session's role was not exercised
