### Criterion 1 — pass

`replayScenario` re-derives all five decision traces by calling the kernel
(`evaluateCadence`, `decideProgram`, `authorize`, `guardQueuedPulse`) from
log-carried inputs; it does not read stored trace payloads. Pinned by
`packages/skeleton/test/scenario.test.ts:19-20`, which rewrites every
`DecisionRecorded` payload to `{reactorId:"forged"}` and still requires trace
equality. Perturbation confirms the derivation is live: mutating the presence
payload, the pulse `occurredAt`, or the logged `workOrder` changes the replayed
traces.

Two limits are recorded honestly as non-blocking findings below: one of the five
traces (`seiri-cadence`) is a hand-authored envelope duplicated in both paths,
so its identity is tautological rather than derived; and trace ordering is
hand-maintained in two places rather than structurally guaranteed. Neither is
required by the criterion, which demands identity between the runs, not
provenance per field.

### Criterion 2 — pass

Both tests exist and both are mutation-resistant. Against a mutated copy:
removing `repo.delete` from `deniedEffects`, adding it to `allowedEffects`,
attempting deletion twice, or letting the adapter perform the delete effect each
fail the step-9 test. Skipping `scheduler.cancel()`, returning one of the two
schedule ids, folding presence incorrectly, or dropping the `QueuedPulseNoOp`
each fail the step-12 test. Step 9's refusal is structural — the payload
`{intentIndex:0, reason:"effect denied", authorityEnvelopeId:"auth_seiri"}` is
produced by the kernel guard at `core.ts:73`, not by skeleton politeness.

### Criterion 3 — FAIL

The *implementation* is correct: `scenario.ts:187-188` recovers through exactly
the two named exports, `replayOutbox(decodeLog(log))` and `pendingCommands(...)`.
The *demonstration* the work order mandates is incomplete.

The clause requires the test to demonstrate "**actual re-dispatch after
restart**". A restart means the state came back from durable storage. The test
cannot distinguish that from an in-memory handover:

```text
Harness: scratchpad/recheck (copy of both dists, kernel symlinked, repo untouched)
Baseline                                    → 6 tests, 6 pass, 0 fail
Mutation: replace
    const recovered = replayOutbox(decodeLog(log));
    for (const pending of pendingCommands(recovered)) {
  with
    for (const pending of [command]) {          // never touches the log
                                            → 6 tests, 6 pass, 0 fail
```

With the entire log-derived recovery path deleted and the in-memory `command`
handed over instead, every test stays green. The test pins that *a second
dispatch happens* and that *one effect results* — the second half of the clause
is genuinely demonstrated — but nothing binds the re-dispatch to the durable
log, which is the whole content of the word "restart" and the reason the clause
says this is what "a kernel-only test cannot" show.

This is the same class of defect this repo has previously treated as blocking
(`docs/verifications/WO-002/VER-002.md` line 9, "one blocking evidence-gate
defect"), and it is cheap to close.

## Examined and refuted — do not chase

Recorded so a repair episode does not re-litigate them. Each was independently
attacked and did not survive; in most cases the mechanism reproduces but the
requirement is not in WO-003 or the docs it cites.

- "The loadout is inert." Opacity to the kernel is the clause's *requirement*
  ("opaque to the kernel"), not a defect.
- "Live/replay identity is tautological, so criterion 1 is vacuous." The
  criterion requires identity between the runs, not that each trace field be a
  function of log leaves.
- "The crash+restart never restarts, so no in-memory state is discarded." The
  clause names a *mechanism* (`replayOutbox`/`pendingCommands`), which the code
  uses; it does not require a fresh process. *(The narrower test-adequacy defect
  that survives is Criterion 3 above.)*
- "The presence encoding can be deleted with the suite green." True, and
  recorded as `S4-TRACE-INDISTINGUISHABLE`; but on the away path `Until(Gate(Every))`
  is transparent by design, and no WO clause requires mutation-distinguishability.
- "The CLI timeline is not human-readable" and "the glyph names are ad hoc." The
  clause requires the *full* timeline plus an emoji-glyph scene; richer
  projection is the next rung's work.
- "`finish` deletes ignored files" is real but is not a WO-003 acceptance defect
  — recorded above as an operator-facing risk instead.

## Method

Fifteen independent verification dimensions covering all thirteen steps, the
three acceptance criteria, the cadence/kernel/determinism contracts, scope and
non-goals, the three ad hoc tools, the ideation receipt, and documentation
integrity. Every finding each dimension raised was then attacked by two
independent agents — one mandated to refute it, one to judge scope and severity
against quoted work-order text — and a finding was discarded unless it survived.
Two completeness critics then hunted uncovered clauses and re-ran the most
load-bearing "pass" claims from scratch; the blocking defect in Criterion 3 came
from that pass and was reproduced by hand before being recorded. 171 agents, 0
errors. The repository was not modified by any agent; all probes ran against
copies in a scratch directory.
