### F1 — Criterion 3: filing time substitutes for review completion

**Class/severity:** time-boundary defect; medium.

`scripts/lib/plan-failures.mjs:518` selects the latest `EntropyReviewFiled`
event, compares passing final reviews against its `recordedAt`, and returns
that filing time as `endedAt`. The criterion requires the latest filed
review's actual end. `scripts/lib/entropy-review.mjs` records these separately:
the receipt receives the episode's `endedAt`; filing gets a later clock read.

Checked evidence: `docs/instance/entropy-reducer/runs/REVIEW-003.json`
ended at `2026-09-25T01:32:35.112Z`; its control filing occurred at
`2026-09-25T01:32:53.817Z`. A read-only probe supplied one synthetic
`FinalReviewCompleted` pass for WO-999 at `01:32:44.464Z` through
`sinceEntropyReview`'s optional control argument. Expected count: **1**.
Observed: **0**, with the filing time mislabeled as `endedAt`.

Reproduce from the repository root:

```js

const control = {
  eventSegments: new Map([
    [
      "fixture",
      [
        {
          type: "FinalReviewCompleted",
          workOrderId: "WO-999",
          verdict: "pass",
          recordedAt: "2026-09-25T01:32:44.464Z",
        },
      ],
    ],
  ]),

console.log(sinceEntropyReview(process.cwd(), control));
```

Run as a Node ES module. The existing fixture creates only a filing event,
so it cannot distinguish these boundaries. The current historical count is
20 under either boundary; the probe establishes the omitted interval.

**Repair rule:** use the latest filed review receipt's actual `endedAt`,
preserve the no-review `unknown` and unavailable-count behavior, and test a
pass between completion and filing. Correct D004's mistaken equivalence in
a new decision; preserve the filed record.

### F3 — Criterion 9: queued messages use context from after their send time

**Class/severity:** temporal attribution defect; medium.

The criterion requires each send time, its gaps, and the agent's preceding
text and tools. Retained `survey/extract3.mjs` emits queued messages at
delivery using an earlier enqueue `sentAt`, but reads the current `s.agent`
and `s.lastOperator`. It does not reconstruct that state at send time.
Sorting rows afterward does not recompute the stored fields.

Two independent read-only counts of retained `survey/subject.jsonl` found:

- **371** negative `sinceAgent` values: 349 absorbed queued messages and 22
  delivered next turn; minimum **−2,686 seconds**.
- **10** negative `gapPrevOperator` values; minimum **−196 seconds**.

Reproduce by parsing its 2,396 JSON lines, filtering each numeric field below
zero, counting by `via`, and taking each minimum. Only counts were emitted;
raw messages remain in scratch. The source explains the result: the paired
agent output happened after the operator sent the message. These errors are
distinct from the explicitly accepted limits on interpreting context outside
a session.

**Repair rule:** reconstruct send-time ordering, select agent text and tools
that precede each send, and compute operator gaps in that order. Exercise a
queue delivery with intervening agent output and later operator messages;
regenerate affected survey evidence and state the classification impact.
