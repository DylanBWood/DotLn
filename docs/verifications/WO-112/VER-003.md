### F1 — High, blocking: a writer-planted commit-graph hides an outside-surface change from host admission

**Class and scope:** an admission-integrity bypass in D022's delivered host
check. It is in the order's declared surfaces:
`packages/skeleton/src/source-change-worktree.ts` (`HOST_GIT`, `effect()`), and
`worker-transport.ts` `codexWriterAccess`, which grants the Codex writer write
access to `<common>/objects`.

**Observed:** `HOST_GIT` disables replace refs because they could "hide a file
from the host's diff while the real commit is published". It leaves Git's
commit-graph enabled. Git reads a commit's root tree and parents from
`objects/info/commit-graph` when one exists. The shared-state snapshot covers
refs and `objects/info/alternates` only. So a writer can:

1. commit a tree that also changes a file outside the surfaces;
2. move its own branch, which the snapshot excludes, to that commit;
3. write a valid commit-graph that names the honest tree for that commit.

**Reproduction:** probe F1 has a synthetic writer do exactly this, driven by
the real `SourceChangeHost` through the Codex transport class. The host
returns `observed` for the forged commit. Both integrity checks record
`unchanged`. With the host's own flags, `git diff base commit` lists only
`fixture.txt`; with `-c core.commitGraph=false` it lists `fixture-test.mjs` and
`fixture.txt`.

A push to a local bare remote is first rejected for missing objects, because
pack building also follows the forged tree. After a routine
`git commit-graph write --reachable`, as `gc` or maintenance performs, the push
is accepted and the remote's diff shows both files. If the hidden tree's
objects already exist remotely, for example a revert to an older snapshot, no
rewrite is needed. That last case is inferred from the same traversal, not
executed.

**Expected and repair rule:** the host judges the commit it accepts. Admission
reads must take a commit's tree and parents from the commit object, never from
writer-writable derived metadata. Run host Git with `core.commitGraph=false`,
judge other object-side caches the same way, and keep this probe as a
regression that must refuse as outside the declared surfaces.

**Severity and limits:** High. A hostile or prompt-injected writer, the threat
D022 adopted, gets an undeclared change accepted, and it publishes after
ordinary maintenance. The writer here is a synthetic double, not Codex inside
its sandbox. That Codex's profile admits the write rests on the pinned grant
(subpath write on `objects`), not a live Codex run. The Claude writer's test
command runs under a sandbox profile that writes only its worktree, so this
path was not shown for Claude. This is distinct from D033, which concerns
preserving existing object bytes.

### F2 — Medium, blocking: recovery refuses a persisted, verified receipt after an unrelated later ref change

**Class and scope:** a recovery regression in D027's integrity adjudication, in
`source-change-host.ts` `run()` (the `prior` block) and `checkIntegrity()`.

**Observed:** product 03 keeps the WO-052 contract: "A crash after receipt
persistence reuses both test observations and appends the missing source
observation once." The receipt is saved only after the writer has stopped and
two post-stop integrity checks, the second after the host's after-test, have
recorded `unchanged`. On recovery, the `prior` block re-compares fresh shared
state with the pre-dispatch baseline before it reaches the saved receipt. Any
change made while the host is down is therefore treated as the writer's.

**Reproduction:** this is the fresh adversary's case, re-run in probe F2. A host
is killed by SIGKILL in `afterReceiptSaved`.

| Change before restart | Recovery outcome | Writer launches |
| --- | --- | --- |
| none | `observed` | 1 |
| an unrelated tag | `refused`, `shared-repository-changed` | 1 |
| an updated remote-tracking ref | `refused`, `shared-repository-changed` | 1 |

**Expected and repair rule:** once a post-termination verdict covers every
writer- and test-attributable step and the receipt is persisted, recovery reuses
the receipt. Later unrelated changes are not compared with the pre-dispatch
baseline.

**Severity and limits:** Medium. It needs a host crash in that window and
another actor's change before restart, such as a background fetch. The commit
survives on its branch, but the command closes refused, so finishing the work
needs operator action. The executor's tests cover crashes before receipt
persistence, where re-adjudication is required.

### F3 — Medium, blocking: a retryable or interrupted triage episode seals its review item as needs-human

**Class and scope:** a durable-decision defect in D012/D015's run-time triage in
`scripts/lib/review-comment-loop.mjs`. The body path appends
`ReviewBodyJudged` with a null judgment. On the inline path, a failed episode
becomes `human`, which finishes the item `needs-human`.

**Observed:** the composition's intake path, `vertical-runtime.mjs`
`modelIntake`, raises a failure as retryable when `judgmentRetryable` says so.
It "leaves it undecided for a fresh episode". Product 03's Return "lets the
current child finish … then holds later steps". Triage instead writes a
terminal disposition for the same failure classes. The only escape is a changed
review text or head.

**Reproduction:** these are the fresh adversary's r1 and r2 cases, re-run in
probe F3. For a review body and an inline item, each with `interrupted` and
with `model-unavailable`, both the first and the retried invocation return
`needs-human` with "triage episode failed …". `triageCalls` stays 1, and
`judgmentRetryable` is `true` for both codes.

**Expected and repair rule:** a triage failure that `judgmentRetryable` classes
as retryable leaves the item or body undecided for a fresh episode. Only a
non-retryable failure or a judged `NeedsHuman` becomes needs-human. Keep these
four cases as regressions.

**Severity and limits:** Medium. A brief outage, or an operator Return during
triage, converts an automated comment into operator work. That undercuts the
"every automated review comment resolved" and "no operator tending" parity items
for future runs. The recorded runs hit no such failure, so their scores stand.
The observer and triage are declared doubles; the loop and its durable store are
real.
