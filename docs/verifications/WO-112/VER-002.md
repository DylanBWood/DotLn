### F1 — High: shared-state restoration rewinds another worktree's legitimate commit

**Class and scope:** destructive concurrency regression in D022's delivered
host-integrity implementation. This is an in-order source-change-host defect,
not a failure of the two historical live scenarios.

**Observed:** the host snapshots every ref except its own branch in
`packages/skeleton/src/source-change-worktree.ts:214`. Restoration at lines
235–264 interprets every difference as writer damage and unconditionally
resets or deletes the ref. Only this writer's currently checked-out branch is
exempt; another worktree's branch is not. The host owns its worker-store lock,
not every ref in the shared repository.

**Reproduction:** probe F1 creates a separate `independent` worktree before
the host starts. In the writer/result interleaving, that worktree commits
`independent.txt`. The host returns `worker-changed-shared-repository`, moves
the independent branch back to its pre-run base and leaves its index showing
`A  independent.txt`. The sibling's completed commit has lost its branch tip.

**Expected and repair rule:** a worker's confinement check must preserve
independently owned work. Establish attribution or adequate shared-repository
coordination before restorative mutation; an unexplained ref difference is
not evidence that this writer caused it. Preserve recovery evidence. Merely
adding compare-and-swap prevents a later race but still does not establish
ownership of the initially observed change.

**Severity and limits:** High because ordinary sibling work can be rewound.
The fixture uses a deterministic interleaving and real Git, not two timed
processes. It demonstrates a lost branch tip, not permanent object deletion.
Repair is recorded in D026 / `FUP-13c8972c4cbacdc2`.

### F2 — High: restoring alternates follows a controlled symlink and overwrites an outside file

**Class and scope:** confinement regression in D022's new filesystem restore.

**Observed:** `sharedState()` at
`packages/skeleton/src/source-change-worktree.ts:229` tests only that
`objects/info/alternates` exists, then reads through it. When the saved content
is nonempty, `restoreSharedState()` at line 257 writes through the current
path. The new writer grant includes the objects directory.

**Reproduction:** probe F2 begins with a valid nonempty alternates file. After
the synthetic writer commits, the fixture replaces that entry with a symlink
to a synthetic victim outside the repository, containing a different valid
alternate path. The host refuses the episode but overwrites the victim with
the old alternates bytes while doing so.

**Expected and repair rule:** inspect and restore an owned filesystem entry
without following writer-controlled links, including substituted parent
directories. A refusal must not create an outside write. Preserve suspect
state for diagnosis instead of using an unverified path as a write target.

**Severity and limits:** High because the trusted host turns a changed entry
into an outside write. The overwritten victim was entirely synthetic and
inside the granted temporary fixture; no real user file was touched. This
proves the host flaw, not a new live Codex exploit. Repair is recorded in D026
/ `FUP-13c8972c4cbacdc2`.
