## Limits recorded

- **L1.** The retime and the decision stub are asserted by content only in the
  fast-forward case; the reviewed-merge case guards those two assertions behind
  `if (!reviewed)` and covers them only transitively, through
  `after.complete === true` (which requires an empty `pending`, so both
  generators ran). The per-case JSON the test prints — including
  `"retimed":"v9000.0.2"` — is a hardcoded literal in the test body, not an
  observation, and should not be read as evidence that the reviewed case
  asserted the retime.
- **L2.** In the fast-forward path the generators run while an authored
  conflict may still be unresolved: `git stash apply` reaches stage `applied`
  even when `receipt.authored` is non-empty, and `regenerate()` then runs. In
  the fixture this is harmless because the conflicted file is not a generator
  input. If a conflicted authored file *were* a generator input — the
  work-order heading that `release prepare` reads is the obvious candidate —
  the generator would read conflicted bytes. Reading `strictVersionsIn`'s
  single-match requirement, the expected failure mode is a `pending` entry and
  exit 1 rather than a silent bad write, but I did not construct that case, so
  this is an inference and a limit, not a finding.
- **L3.** `unionFollowups` refusing a divergent same-entry history is asserted
  at unit level (`/divergent history/`), but no fixture drives that refusal
  through `resolveProjections`. Reading the code, the register would stay
  unresolved and appear in `remaining`, printed as an authored conflict; that
  path is inference, not observation.
- **L4.** `docs/evidence/WO-079/decisions.md` regeneration through `meta` and
  the `docs/lineage/decisions-index.md` conflict are set up in the fixture but
  not asserted by content after integration; they are covered only by the
  `harness check` / index checks that follow.
- **L5.** `docs/final-reviews/WO-079/PR.md` exists, untracked, containing only
  a generated process-meter block. It is written by `scripts/release.mjs:2021`
  as a side effect of the release preparation this order ran. Nothing is
  published or committed. Recorded so a reviewer does not read it as a
  pre-empted final review.
- **L6.** The executor's `ImplementationReady` evidence carries the advisory
  "Outputs not read at current bytes" naming 24 of the order's own changed
  files, including every new source file. Codex has no automatic read receipts,
  so this is advisory rather than a finding, but the order's output-read
  observation is unrecorded for its main deliverables.
- **L7.** The order's Cost section quotes final-review durations and a median
  for earlier integrations. Nothing in the deliverable measures a time saving;
  the implementation evidence explicitly claims none, and I reproduced none of
