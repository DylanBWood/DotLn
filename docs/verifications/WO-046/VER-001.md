## Non-blocking observations

- **O1 — the WO-101 runtime deferral pin moved, and the stepper backstop is now untested.** `stepProgram`'s `default:` branch throws `Invalid executable program` (`core.ts:239`) instead of `Program <kind> evaluation is deferred`, and `wo101-deferral-pins.test.mjs` now pins decode refusals rather than stepper throws. This is inside the order's authorized scope — it lists the WO-101 corpus harness among the files it edits, and the kind is still named, with a path, at decode. But `grep` finds no test for the new backstop string, so the last runtime guard for an untyped JavaScript caller has no regression pin, and such a caller loses the kind name that WO-101 FINAL-001 quoted. Nominated as a one-line regression for a later kernel order (WO-048 is queued for host-side on-disk decoding).
- **O2 — deferred *Cadence* kinds inside a persisted `Await` timeout still decode.** The decoder validates all 14 cadence shapes but not evaluability, while `EVALUABLE_CADENCE_KINDS` is six. I checked the consequence rather than assuming it: `stepProgram`'s `Await` case returns the wait without touching `timeout`, and the skeleton's only two `evaluateCadence` call sites (`reactor.ts:702`, `reactor.ts:1107`) use a compiled schedule cadence and a literal `Cadence.After`, so no current path evaluates a persisted timeout. The limit is disclosed in the kernel README, product 02 and D001. If a future consumer evaluates persisted timeouts, the mid-episode failure this order's objective removes for Programs returns for Cadence.
- **O3 — the fold-time guard decodes on every event.** `seiriReactor` calls `programFromState` whenever `state.program !== null` (`reactor.ts:1343`), including events that never consume the program, and the episode path then decodes the same tree again. That is the intended "refuse when it is read" boundary, but its cost is O(tree) per event and unmeasured; D001's reopening condition already names measured decoding cost.
- **O4 — the decoded value aliases persisted state.** For already-parsed input `decodeContinuation` returns the same object reference rather than a copy, so `verificationStateFromRuntime` hands callers a typed alias of `state.verification.continuation` (`json()` is a cast, not a clone). The previous unchecked cast aliased too, so this is not a regression; recorded because the value now carries a stronger type than a raw alias usually implies.
- **O5 — unknown-field strictness exceeds type assignability.** 39 of my 1,573 mutants are refused solely for an extra structural field (for example `$.event.zzz`, `$.pattern.kind`). This is the order's "malformed node" intent and is documented, and no false refusal appeared across 3,321 committed continuations — but any future producer that adds a field to a persisted continuation will fail at read. D001's reopening condition ("a valid existing continuation fails decoding") covers it.
- **O6 — AC3's enumeration is pinned by check, not by construction.** `corpus/harness/program-corpus-lib.mjs` is unchanged and still builds the six kinds from hardcoded builders, so the corpus does not literally enumerate *from* the type. The enforcement the criterion asks for is nevertheless real and bidirectional: a seventh executable kind fails the build unless the constant lists it, and the new corpus test then fails until the manifest's root kinds cover it. Nothing can diverge silently.

## Goal alignment and cost

The order serves the always-on runtime critical path: persisted data must describe work the stepper can actually execute, and the failure must land when the value is read rather than after dispatch. The promised benefit is observed at both skeleton read boundaries — the runtime program and the verification continuation — and the type now makes the illegal state unrepresentable for typed callers instead of relying on a runtime string.

- **Rule beating** was checked against the strongest cheap attack I had: an independent validator transcribed from `types.ts` rather than from the decoder, fuzzed differentially over 1,573 mutants, plus a hostile-shape probe and a compile-level mutation of the AC3 pin. The decoder never accepted a value the type rejects, and the equality pin fails in all four divergence directions.
- **Drift** was checked by regenerating evidence rather than reading it: the changed reactor reproduces the previous edition's bytes exactly, and the committed fixtures and frozen oracle match `main`.
- **Naive Interventionism / NoOp:** NoOp leaves the untyped cast and mid-episode failures. The delivered change is close to the smallest one that removes them; implementing deferred kinds or generic child parameters was rejected with reasons in D001, and I found no cheaper alternative that keeps `Program.T` authoring intact.
- **Shifting the burden:** O1 and O2 are the two places where a later caller could still be surprised; both are recorded rather than repaired here, because repairing them would widen this order's scope.
- **Commons, escalation, success to the successful, seeking the wrong goal:** immaterial. No new dependency, no new process, and the capability row honestly stays at L2/E0 because no real-session continuation evidence exists.
