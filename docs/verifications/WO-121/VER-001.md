## Findings

**F1 — `npm test` is not green: `release:case:runtime_refresh` fails
reproducibly (blocking, criterion 6).**

*Observed.* `npm test` exits 1 with `17 passed; 2 failed`. Reproduction, 3 of 3:
under the full gate, `fatal: unable to read tree (2510d408190a9de303115a9a0877f351f7ec4880)`
in scenario `runtime-finish-matching`; isolated in-sandbox via
`bash scripts/test-release.sh --case runtime_refresh`, `fatal: unable to read
tree (137ba12c947ad770a9deb8d8164661bed5acf422)` in scenario
`runtime-close-changed`; isolated outside the sandbox, `fatal: hardlink
different from source at '…/integrator/.git/objects/pack/tmp_pack_6lMHog'`,
followed by a cleanup failure that leaves the fixture root undeleted. The
failing scenario and object differ per run; that a run fails does not.

*Expected.* Criterion 6 requires `npm test` green.

*Root cause.* `release_case_runtime_refresh` (`scripts/test-release.sh:1066`)
creates `origin` as a plain `git init --bare` (`:70`), pushes into it
(`git -C "$main" push origin main`, `git -C "$subject" push -u origin wo-099`)
and on the next line runs `git clone "$origin" "$fixture/integrator"`. A local
clone hardlinks the source object store, and `receive.autogc` is enabled by
default, so the post-push auto-gc in `origin` can repack the very objects the
clone is linking. Both observed signatures are canonical symptoms of that race:
a repacked-away loose object yields `unable to read tree`, and an object
replaced mid-link yields `hardlink different from source`. The fixture sets no
`gc.auto=0`, no `receive.autogc=false` and no `--no-hardlinks` anywhere — I
grepped the whole file and there is no match.

*Reproduction.* `bash scripts/test-release.sh --case runtime_refresh`; exit 1.

*Candidate fix.* Disable automatic gc on the fixture repositories
(`git -C "$origin" config receive.autogc false` and `gc.auto 0` at `make_repo`),
or clone with `--no-hardlinks`. Either removes the race without changing what
the case asserts.

*Severity and scope, stated honestly.* The race is not presence work and is not
introduced by this order. WO-121's only change to the file is diagnostic: the
clone's `>/dev/null 2>&1` becomes a log file plus `|| { cat log >&2; return 1; }`.
Under `set -euo pipefail` the previous form already aborted on a failing clone,
silently, which is exactly what the executor recorded as a failure with
"suppressed clone output" whose "cause remains unknown"
(`docs/evidence/WO-121/decisions.md:123-133`). That receipt sets the reopening
condition "Reopen a functional repair if the surfaced diagnostic identifies a
reproducible defect"; this finding is that condition met. The operator
dispatched the repair to WO-121 rather than to a new order, on the ground that
criterion 6 requires a green gate and this order owns the touched fixture.

the two.

recomputes `classifyPresenceSignal` and refuses any observation whose recorded
`origin` disagrees, so a hand-written or replayed event cannot assert `human`.
The criteria do not ask for this; it materially strengthens the objective's
"presence is never inferred".
