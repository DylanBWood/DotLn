## F1 — Queued commands time out and disappear from replay

**Severity:** medium (P2). **Criteria:** 1 and 3.

**Expected:** A valid queued invocation eventually returns its terminal result
or an explicit recorded refusal/cancellation. Waiting behind a supported long
command must not silently remove the request from the promised console event
and replay history.

**Observed:** With one `console.status` blocked on a temporary FIFO, a second
authenticated `resume.times` request failed after 301,246 ms with native fetch
`TypeError`, cause `UND_ERR_HEADERS_TIMEOUT`. No custom timeout fired: the
probe's watchdog was 325 seconds. Direct execution of the same terminal
entrypoint and arguments under the console child environment completed with
exit 0 in 757 ms, producing 164,331 stdout bytes and no stderr. After aborting
the first caller and orderly resident shutdown, the persisted observations were:

```json
{
  "invocations": ["console.status"],
  "replay": {
    "results": [{"version":1,"command":"console.status","exitCode":143,"stdoutBase64":"","stderrBase64":""}],
    "incomplete": []
  }
}
```

**Cause:** `packages/skeleton/src/console-loopback.ts:375–383` decodes before
queueing, but response headers and keepalive begin only inside `run`, at
475–479, after the preceding request finishes. At 458–461, a disconnected
queued caller returns before `admit` can append its invocation. The existing
disconnect fixture tests an already-running command, so it misses this state.
Product 04 at line 224 promises a receipt for each decoded request.

**Reproduction:** Node v26.9.0 on the current POSIX host, built subject. Use
the same `missionConfiguration` and `ResidentHost` setup as the existing
WO-115 bound fixture, with both stores under `os.tmpdir()`. Create
`<blocked-store>/runtime-status-v1.json` using `mkfifo`. Start the resident
with a long tick interval and obtain its connection with
`readConsoleConnection`. Then:

```js
const post = (command, args, signal) =>
  fetch(`http://127.0.0.1:${connection.port}/console-commands-v1/invoke`, {
    method: "POST",
    headers: {
      authorization: `Bearer ${connection.token}`,
      "content-type": "application/json",
    },
    body: JSON.stringify({ version: 1, command, args }),
    signal,
  });
const active = new AbortController();
const first = await post(
  "console.status", ["--store", blockedStore, "--json"], active.signal,
);
// This resolves with status 200: the first command has started.
const firstBody = first.text().catch(() => null);
// No explicit cancellation or shortened timeout on this second request.
await post("resume.times", []); // rejects after about 301 seconds
// In finally: active.abort(); await firstBody; stop and await the resident.
// Then inspect events.jsonl and replayConsoleResults(store).
```

The probe used the production server and native fetch, without changing
timeouts or implementation. A FIFO models an admitted command of arbitrary
duration; it is not a claim that ordinary status reads block. Supported long
lifecycle operations use the same serial lane. The missing receipt was checked
again after shutdown, not merely while the second request was waiting.

**Repair target:** Cover queue residence with a live response or an explicit
terminal-shaped refusal, and preserve the receipt/cancellation outcome of
decoded requests whose caller leaves. Add a two-request regression without
changing the terminal handlers or imposing a blanket lifecycle deadline.
The verifier does not prescribe a broader transport redesign.

**Disposition:** [WO-115-D012](../../evidence/WO-115/decisions.md#wo-115-d012--verification-finds-queued-requests-lost-before-admission)
records the evidence, alternatives, named WO-115 repair follow-up and reopening
condition. No waiver applies.
