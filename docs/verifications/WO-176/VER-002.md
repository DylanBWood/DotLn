## Boarded defects (outside the criteria)

**D033, recoverability with a narrow data-loss case** (priority medium, `FUP-e7096aa6bde63c0e`). `materialState` and the recovery bundle read only the top-level repository's refs, objects, index and working files. Removal deletes every object store beneath the path.

- **Submodule commit after a declaration** (`probe2.mjs` case 1).
  - `scratch/r`, with a submodule, is declared disposable.
  - A commit inside the submodule followed by `reset --hard HEAD~1` leaves the state equal to the declared one.
  - The row stays `disposable/declared`, and the bundle lacks the late commit.
- **Repository inside a lane repository** (case 2). `.runtime/x` holding an inner repository is bundled with only its own commit.
- **Reviewer A's further cases.**
  - A bare `.runtime/*.git` is never inventoried.
  - A lane repository created between finish's inventory and its lock is removed without a bundle (module-level; reachability inferred).

**Rule a repair must hold.** The state and the bundle cover every Git directory and object store the removal deletes, or such a repository needs a fresh word. Inventory happens inside the writer lock, or the close blocks on a nested repository missing from the rows. D026's and D032's "every disposable repository's stored commits" claim is corrected.

**Why boarded, not failed.** The removed repository carries a lane classification or an executor declaration, which criteria 1 and 3 require to be removed. Receipt 036's duty is outside the order's criteria (FINAL-001 D024).

**D034, minor** (priority low, `FUP-03ccaaf4c2e6ad49`).
- **(a) Aliased scoped word.** A scoped `--material` word naming the worktree through a symlinked alias is dropped without notice. `probe2.mjs` case 3: an intended preserve gives `disposable/lane`, while the realpath form gives `preserve/declared`. The printed commands use Git's resolved paths, so they work.
- **(b) Conflicting words.** Two words for one repository are accepted, and the last wins.
- **(c) Retry after a pushed tag.** A retry that fails gh preflight after a pushed tag is recorded `refused` with `tagOutcome:null` (`release.mjs:2008-2015`).
- **(d) Bare commands.** Finish and settle blockers caused by material carry the bare `close --publish` command.
- **(e) Nested hook.** Recovery runs `update-ref` in the nested repository, which executes its `reference-transaction` hook (`probe2.mjs` case 4).
- **(f) Unreadable entry.** A lane repository holding a FIFO blocks every close with no settling word. This is reviewer A's reproduction only.

**Rule a repair must hold.** An operator's word takes effect or is refused before cleanup. A published tag is never recorded as refused. Every recorded blocker names a command that settles it. Nested-repository Git commands run with hooks disabled.
