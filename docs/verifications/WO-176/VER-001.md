## Boarded defects (outside the criteria)

**D019, data-loss class (priority medium, `FUP-fac73cbaa42b9187`).** Settlement applies the subject's committed rows and the operator's `--material` overrides to every derived worktree by path.
- **Reproduction** (`repro.mjs`). The subject and derived repositories each hold a different one-commit nested repository at the ignored other-lane path `scratch-material/x`.
  - `inventoryMaterial(derived)` alone reports `undeclared/lane`.
  - With the subject's declared-disposable row it reports `disposable/declared`.
  - `reconcileWorktreeMaterial`'s preview lists it `disposable`, and the `ensureNoIgnoredMaterial` filter leaves no blocker. By `removePreservedWorktree` and the material case's disposable mode, `git worktree remove` then deletes it.
- **Rule a repair must hold.** A nested repository absent from a worktree's own recorded inventory keeps its lane disposition. A row or override binds to the worktree it was given for.

**D020, accuracy (priority low, `FUP-b954a9b6cb652a85`).**
- **(a) Record classification.** `finishPublishedWorktree` records every path-matching worktree that settle keeps by design (checked out on a branch) as retained and cleanup `blocked`, with a bare `release close --publish` command that cannot settle it. When finish is blocked, settle's line `Derived worktree <main>-wo099: kept (checked out on wo-099, not a detached derivative)` (in my trace) adds a second settle blocker to the subject.
- **(b) Remedy timing.** The completion advisory says "declare before close" in the same command that already recorded the row as undeclared. After the merge, the finish blocker leads with that declaration command, which the close never reads; the fixture proves this retry stays blocked. The `--material` command that works comes second.
- **Rule a repair must hold.** A recorded blocker is one a named command can settle. Each printed remedy says when it takes effect.
