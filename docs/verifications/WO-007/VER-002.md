## Findings

### F1 — Minor — one leg of the AC5 replay assertion cannot fail, and the skeleton README overstates it

`packages/skeleton/test/audit.test.ts:837` asserts projection-byte identity over
four inputs. Three are meaningful: an encode/decode round trip, an independent
fresh `runScenario`, and a non-mutation check on the decoded events. The fourth,
`renderAuditProjections(decodeLog(replayScenario(live.log, fixture).log))`,
cannot fail: `replayScenario` returns its input `log` string unchanged
(`packages/skeleton/src/scenario.ts:431`), so that assertion reduces to
`f(x) === f(x)` for a deterministic pure fold.

WO-007's criterion 5 is still satisfied — it asks that re-running the projections
over a replayed log yield identical output, and the fresh-rerun and re-encode
legs prove the substantive property — so this is not an evidence gap for the work
order. It is a redundant assertion plus a documentation claim that reads stronger
than what is proven: `packages/skeleton/README.md`, changed in this subject, says
the audit tests "require byte-identical output over live and replayed JSONL,"
which invites a reader to believe the replayed projection was independently
reconstructed.

The underlying cause is the hand-mirrored replay path that WO-016 already
documents in its dated observed-problem section and exists to remove. The cheap
correction is to narrow the skeleton README sentence to what the test proves
(live, re-encoded, and independently re-run logs) and let WO-016 restore a real
replay leg when `replay()` drives the scenario.

Evidence: `packages/skeleton/test/audit.test.ts:837-849`;
`packages/skeleton/src/scenario.ts:306-444`; `packages/skeleton/README.md:47-52`;
`docs/work-orders/WO-016-skeleton-reactor.md:45-60`.
