## Limits and disposition

These are limits of the delivered lint, not failures of any acceptance criterion
or of any authored claim. None routes to repair, and none needs a new decision
in this order.

1. **Control-character class is narrower than "disguise".** `text.control-character`
   covers C0 except tab, LF and CR, plus DEL, U+2028 and U+2029. Bidi overrides
   and isolates (U+202A–U+202E, U+2066–U+2069) and the C1 range including NEL
   (U+0085) pass; I confirmed `ordinary`+U+202E+`txt` and `ordinary`+U+0085+`text` both
   return `pass`. The order states no control-character criterion at all, so
   this rule is an addition beyond scope and its class is a design choice rather
   than a defect. If the operator wants Trojan-Source coverage on outward text,
   it belongs to WO-064's integration or a fresh nomination, not to a repair of
   this order.
2. **Generic public terms refuse ordinary English.** `Apply the mask layer`
   refuses naming `mask`. This is disclosed in the implementation receipt and
   already boarded: WO-063-D001 reopens when "a public vocabulary entry produces
   a legitimate target false positive," and the committed file is editable by
   design, as the order's operator-review assumption anticipates for the type
   set.
3. **Span precision is code-point aligned to the source.** When a single source
   character NFKC-expands, a match that begins inside that expansion widens to
   the whole source character. No committed term reaches this case, and the span
   always contains the match.
4. **Nothing calls the lint yet.** That is the order's non-goal, correctly
   observed: no publish path, hook, worker prompt or target file changed, and no
   remote effect was performed in either the implementation or this
   verification.
5. **Scope is target-facing artifacts.** This repository's own branch `wo-063`
   and its prepared PR body would be refused by the lint, because DotLn's own
   control plane legitimately uses its own vocabulary. That is the projection
   boundary working as Principle 16 states, not a defect.

No defect was encountered and deferred, so no follow-up decision or repair route
is required. Next legal workflow on this pass is `resume: final review`; that
role owns integration and publication, and this verdict grants neither.
