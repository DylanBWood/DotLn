## Implementation review

The emit's ownership change is the smallest that holds the contract. It reads `main`'s manifest at most once, and only when a present `.codex/` file is missing from the on-disk manifest. It admits a file only on path and whole-file hash, so it can replace only bytes some emit recorded. The guard for a symbolic link or a file that is not regular (`contained`) still runs first. A path-only test, which the order rejects, would let an operator's own file be overwritten. The runtime guard's absent-file condition, `!previous.has(path) || (pending !== null && !planned.has(path))`, is compact; its comment and the guide's step 1 say what it admits. The carry in `projected` is explicit about uniqueness in both directions and about the currency of the disposition carried. Its deterministic `at` lets two worktrees agree, at the cost recorded in D016: the duplicate's time is the earlier disposition's, not the moment of re-keying. The grafts diagnosis follows `plainHistory` for grafts but not for replacement refs (R1-B, recorded).
