## Observations

- **O1 — a refusal now costs all reuse, not just the replica guarantee.** Recorded separately from F1 because it survives F1's fixture repair. `suiteInputHash` has one gate for declared suites: plan refuses → no key. The order's Failure paragraph contemplates the executor "retaining the suite whole-tree with a reason" as an authoring act, and says nothing about a runtime refusal; the runtime behaviour chosen is the strictest available. That is defensible — a whole-tree key for a suite whose declaration is the reviewed artifact is a different contract — but it is undocumented in 07 and unnamed in D001's reopening conditions, and it is what turns an environment quirk into a total loss of the order's benefit.
- **O2 — `GIT_CONFIG_PARAMETERS` carries a proxy setting past the proxy filter.** `suiteEnvironment` drops variables whose **name** matches `/(?:^|_)proxy(?:_|$)/i`, so `HTTP_PROXY` and `CLOUDSDK_PROXY_USERNAME` are removed, but `GIT_CONFIG_PARAMETERS='http.proxyAuthMethod=basic'` passes through into gate children and into the environment digest. This is pre-existing, not introduced here, and the value is a method name rather than a credential; 07's "rotating proxy credentials are absent from both" is narrower than it reads. Worth resolving alongside F1(b), since the same family is in scope.
- **O3 — declared directory modes are keyed but not reproduced.** `observeSuiteInputs` records `["directory", mode]` for a declared directory and that mode enters the key, while `createReplicaContext.create` builds directories with plain `mkdirSync` and the process umask (`suite-replica.mjs:311–314`); `prepareInstalled` does preserve modes for the installed copy. The direction is safe — the key is stricter than the replica — so a directory-mode change causes an unnecessary re-execution and never an unsound reuse. Not worth a change on its own; worth knowing before someone declares a suite whose behaviour depends on a directory mode.
- **O4 — the replica scratch is checked against the candidate tree only.** `createReplicaContext` refuses a `tmpdir()` inside the candidate tree, but a `git: none` replica has no `.git`, so a Git command inside it walks up through the traversable `0o300` parents into `TMPDIR`. If `TMPDIR` ever sat inside some other repository, that repository would be discoverable. Not the case on this host, and no narrowed suite with `git: none` is known to invoke Git; a `GIT_CEILING_DIRECTORIES` entry in the projection would close it cheaply.
- **O5 — `prepareInstalled`'s change detector is currently unreachable.** The "Installed inputs changed after the gate copy" branch compares each call's identity against the first, but `runGateChecks` only ever passes the single `before` snapshot, so the comparison cannot differ. It costs nothing and guards a future caller; noting it so it is not mistaken for tested behaviour.
- **O6 — per-session environments still prevent reuse across roles (WO-129 VER-002 O1, re-measured here).** My canonical gate ran 78 fresh / 0 reused even though the executor's successes for `kernel`, `compiler`, `skeleton`, `worktree`, `process-debt` and `plan-refutation:fixtures` were present and their declared bytes unchanged: every one explains itself as `inputs changed` with `environment` as the only changed class. My projection has 25 keys including `CLAUDE_CODE_EXECPATH`, `CLAUDE_EFFORT`, `CLAUDE_PID`, a session `TMPDIR`, `GIT_EDITOR` and `GIT_SSH_COMMAND`; the executor's Codex session differs in most of them. Each independent role still pays a full fresh gate. This is WO-126-D012's reviewed projection and outside WO-130's criteria, but it caps the order's measured benefit exactly as it capped WO-129's, and it belongs with D001's third reopening condition.
- **O7 — clean-room screen.** The order, decisions, evidence, measurements and fixture transcript show no employer material, credentials, internal service identifiers or key material. Absolute home paths appear in this report only as the two checkout locations already recorded throughout WO-129 and WO-130 evidence, and as the literal `safe.directory` values that F1 turns on. No stop condition.
