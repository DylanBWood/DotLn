## Findings

### Non-blocking 1 — the stated observation window is one day narrower than the evidence set the document names

`docs/planning/capability-table.md:12-14` states:

> The observation window is committed repository evidence dated 2026-08-31
> through 2026-09-01 and present at that revision.

Lines 20-23 then name the environment evidence family as
`../discovery/environment.md`, `../discovery/environment.json`, and
`../discovery/codex-runtime-map.md`, and the Transports row at line 92 cites
`environment.md` in its evidence column. Both environment artifacts were
introduced by `4bae5f3` (2026-08-30, "WO-001: environment truth for the
personal machine"), and a substantial share of that 2026-08-30 material is
still live at the pinned revision:

```text
$ git blame --date=short -e e3f8cbd -- docs/discovery/environment.md
 165 2026-08-30    68 2026-08-31   211 2026-09-01     (444 lines)
$ git blame --date=short -e e3f8cbd -- docs/discovery/environment.json
  71 2026-08-30     3 2026-08-31    65 2026-09-01     (139 lines)
```

`environment.md`'s H1 also still reads `# Environment discovery — 2026-08-30`.
The true span of the named evidence set is therefore 2026-08-30 through
2026-09-01.

This is recorded as non-blocking, and the severity is deliberate:

- **No acceptance criterion is violated.** AC4 binds only "for any counts
  used", and the table uses none (line 58) — the window sentence is
  supererogatory. The roadmap's sole use of the term
  (`06-roadmap.md:257`, "All counts retain scope and observation window")
  ties the concept exclusively to counts.
- **No level claim depends on it.** Transports sits at `0 — latent` with the
  inline note "observed host shapes are not adapters", and its anchor
  resolves to `environment.md:249`, a heading authored 2026-09-01.
- **The error direction is conservative.** The stated window is narrower than
  the corpus actually read, so nothing is overclaimed. The document's own
  exclusion list is purely forward-looking — "Uncommitted WO-005 control
  events, later files, ambient model knowledge, and `docs/intake/`" — so it
  never declares earlier material inadmissible. The intent is sound; only the
  stated range is off.

The concern is durability rather than accuracy of any claim: a later
maintainer re-running this assessment would use that sentence to decide
admissibility and would either wrongly exclude 236 lines of cited discovery
evidence or hit the contradiction. The smallest correction is to write
2026-08-30 through 2026-09-01, or to say "last changed" and note that WO-001
base discovery material remains in scope.

### Refuted candidates

Five parallel audits raised seven candidate findings, every one graded MINOR
by its own finder. Six were refuted. Because five of the seven were variants
of the same claim, the reasoning is recorded so a later reader does not
re-open settled ground.

**Four weaker variants of the window claim were refuted.** They argued from
first-commit date or from the file having been "materially rewritten
in-window". Two specific sub-claims were misreads and are recorded as such:
`environment.json` at the pinned revision carries
`"observedAt": "2026-08-31T19:08:36-04:00"` and `"workOrder": "WO-004"`, and
the `"createdAt": "2026-08-30..."` cited against it is at line 38 inside
`browserBinaries` — the mtime of a Playwright cache directory on the machine,
not the document's date. The variant that survives (above) rests instead on
line-origin blame at the pin, which is the correct measurement and which the
"materially rewritten" defence does not answer. One refutation argued the
reading "proves too much" because `06-roadmap.md` is also first-committed
2026-08-30; that argument fails, because the roadmap is cited once at line 4
as the policy authority and never appears in any row's evidence cell, so it
is not part of the evidence set the window bounds.

**Refuted: the store/replay "JSONL codec ... L2" dimension has no automated
check for an unparseable log line.** The mechanism is real —
`packages/kernel/src/store.ts:8` is a bare per-line `JSON.parse`, so a
malformed line throws an uncaught `SyntaxError`, and no test covers it. But
an unparseable line can only arrive from a durable adapter reading foreign
bytes, and that adapter is precisely what this row's own blocking gate says
does not exist: "The shipped kernel stores a pure JSONL value; no durable
adapter, backup/restore exercise, or real-worker recovery is integrated."
Within the declared scope the failure coverage is genuine — newline
termination after round-trip, malformed payloads persisting nothing (B4),
tampered-log recompute, and edge-assigned id sequencing. The dimension is L2
as claimed. Carried as an observation below.

**Refuted: the composition-compile row's "no usable behavior" parenthetical
is stronger than the repository supports.** The phrase is a verbatim
quotation of the roadmap's own level-0 definition at `06-roadmap.md:146` —
"0 — latent | named idea or need; no usable behavior" — not an independent
empirical assertion. The cited counter-evidence, `compileWorkOrder` at
`packages/skeleton/src/scenario.ts:44-60`, is a loadout identity guard that
returns a hardcoded `WorkOrder` literal; it is not a compiler, and the row's
four declared dimensions (LoadoutGraph, link checking, semantic hash,
compiled diff) have zero implementation. It is already counted under the
walking-skeleton row's "provisional WorkOrder compilation L2" dimension, so
crediting it again here would double-count. The row's own evidence cell
discloses it as "the current hand-built input is provisional".
