## Findings

### F1 — blocking: the staged release target and compiler version collide with the published sibling release

- **Observed:** The subject prepares application `v0.19.0` in several places: the work-order heading, the README release block, 06 §Release boundary, the kernel/skeleton READMEs and D003. It sets compiler `0.10.1`, with that value pinned in the manifest, generated hooks, `COMPILER_PACKAGE_VERSION` and derived policy hashes. But local annotated tag `v0.19.0` already exists and targets WO-067's merge `5bcbd63` on `main` (commit 19:09:58Z, tag 19:14:22Z). WO-045 reached implementation-ready at 19:11:13Z. At `5bcbd63`, `main` has compiler `0.11.0`, kernel `0.2.1`, skeleton `0.16.0`, and evidence editions pointing at WO-067. Of the 72 files `main` changed since the base, 27 overlap this subject: the manifest and all nine generated hooks, `docs/evidence/current.json`, the lockfile, compiler `package.json` and `artifact-identity.ts`, the console selfhost fixtures and manifest, `README.md`, 02, 06, the work-order index, the decisions index, followups and `scripts/test-harness.mjs`.
- **Expected:** An unpublished order's release target is free. Component versions only move forward, and a published tag's content is immutable (product 10 §Separate version axes and §Invariants). WO-045's AC4 and AC6 outputs must hold at the tree that final review publishes.
- **Reproduction:** `git for-each-ref refs/tags/v0.19.0 --format='%(taggerdate:iso) %(*objectname:short)'`; `git merge-base --is-ancestor 'v0.19.0^{commit}' HEAD` (false); `git show 5bcbd63:packages/compiler/package.json`; compare `git diff --name-only 7aeccb1 5bcbd63` with `git status --porcelain`.
- **Impact:** Release close cannot publish `v0.19.0`. Merging as-is would downgrade the compiler from `0.11.0` to `0.10.1` and conflict on the generated bundle and evidence selections. Integrating WO-067's compiler changes also changes runtime source and compiler identity. That invalidates the bundle pins, the policy hash, the artifact-identity/verification/authority editions as their checks decide, and the feedback edition AC6 requires.
- **Repair scope:** First obtain explicit operator authorization to retime, and record a dated migration note (product 10). Then:
  - integrate `main` at or after `5bcbd63`;
  - assign the next free application version and a compiler version above `0.11.0`;
  - regenerate the bundle and manifest, and re-run `bundle-check` against the new activation-base equivalent;
  - regenerate the evidence editions their checks require, plus a fresh operator-run live feedback audit;
  - re-record the console fixtures;
  - correct the release surfaces and D003;
  - rerun `npm test` and the harness fixtures.

  The decoder source, tests and corpus need no change for this finding.
- **Limits:** Remote publication state of `v0.19.0` was not queried; the local annotated tag and `main` ancestry are the evidence. I did not attempt a trial merge.
