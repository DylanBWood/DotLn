## F1 — A completed operator delivery still accounts for a later host queue entry

**Route and severity:** blocking, in the declared prompt-router surface.
**Class:** historical prompt observations are reused after their delivery.
**Criteria:** 1, 9, 10 and 11.

The independent generated-hook probe follows this history:

1. Submit a synthetic notification envelope as an operator paste. The hook
   correctly supplies the private checklist and journals its digest.
2. Deliver that idle operator prompt as a transcript `user` row, without a
   preceding queue entry.
3. Add a later host `queue-operation` enqueue row with the same bytes, then
   invoke the prompt hook for that notification.

**Expected:** the later notification receives no checklist and journals under
`host-task-notification`. **Observed:** it receives the checklist and journals
under `claude-prompt-hook`, with `unattributed` attribution and
`host-route-unavailable` route source. A fresh host notification without the
earlier operator observation correctly receives no checklist.

The same variation with `quality pass: README.md` produces both the checklist
and document-editing guidance for the later host-queued text. The probe observes
guidance delivery only; it performs no requested document edit or lifecycle
transition.

The cause is in `readPromptRoute`, `packages/skeleton/src/harness-host.ts`
1393–1405. `operatorObservations` supplies every earlier matching operator
observation. A delivery retires a waiting queue entry only when `waiting.length`
is nonzero, so the direct delivery in step 2 retires no observation. The later
enqueue then consumes that old observation as its own and is treated as an
operator prompt. This history respects D055's ordering assumptions.

The existing fixtures cover a host notice delivered before a paste and an
operator repeat whose first copy still waits. They do not cover an operator
paste delivered before the later host notice. Thus their passing row and the
executor's three reviews do not establish this exclusion for the changed path.

**Reproduction:** run from the repository root:

```sh
node scripts/harness.mjs bounded -- node docs/evidence/WO-235/verification-004-route-probe.mjs
```

It exited 1 at 2026-10-30T03:20:48.795Z, printing the expected host source and
the observed operator source. The generated session-hook capture, its fresh
notification control, the host-queued command variation and four Stop cases
are retained in [verification-004.json](../../evidence/WO-235/verification-004.json).
These are synthetic replays through the current runtime, not a live Claude
notification observed in this Codex dispatch.

**Repair rule:** account for completed direct deliveries as well as queue
deliveries, so an already-delivered operator observation cannot identify a later
host enqueue as the operator's. Preserve reminders on operator pastes and
repeats whose first copy still waits. Add both reversed-history cases to the
generated-hook fixtures, retain host-message exclusion for checklist and
quality-pass guidance, and add no persistent question state, message index or
workflow condition. [D062](../../evidence/WO-235/decisions.md#wo-235-d062)
records this disposition. The verifier made no implementation repair.
