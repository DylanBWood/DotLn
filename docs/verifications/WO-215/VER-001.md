**F2 — The dry-run preview reports a false skip before main is fast-forwarded (blocking).**

- Class: misreported dry-run preview (correctness and tests, operator flow), in the declared `scripts/lib/starter-refresh.mjs` and `scripts/release.mjs`.
- Observed:
  - The end-to-end probe declares the export sibling and records a clean, bound starter checkout. An integrator then pushes the WO-099 candidate, so `origin/main` advances and main does not.
  - `release close WO-099 --publish --dry-run` prints `Starter refresh starter-fixture: skipped; main has moved past the published tag; the next release refreshes the starter.`
  - After main is fast-forwarded by hand, the same dry run prints `current; would refresh <initial> to <merged head>.`
  - At module level, a dry run with main at `head^` returns the same skip. With main at head, a dirty checkout is reported as refused, so the checks run only once main is at head.
- Cause:
  - A dry-run close takes `head` from `origin/main` (`scripts/release.mjs:2328`, `:2406`) and only checks that main can fast-forward to it.
  - `refreshOne` first compares main's HEAD with `head` (`scripts/lib/starter-refresh.mjs:367-375`), and returns before it reads the clone map, checks the checkout or fetches.
  - In a real close, `updateMain` makes HEAD equal `head`, and `ensureExistingRelease` requires the tag to target `head` (`scripts/release.mjs:1676-1684`). This skip can therefore fire only in a dry run.
  - The executor's dry-run cases run with main already at head.
- Expected: criterion 6's dry run "prints the preview". Step 5 defines that preview as "the checks with the fetch", returning `would refresh <before> to <head>`.
- Severity: blocking, because criterion 6 is unmet. Release close's own dry-run line says it "would fast-forward main", and the order's own release close is the first live refresh. A dry run then cannot surface an unrecorded, dirty or misbound checkout until after publication.
- Repair rule (D011):
  - Judge the preview against the head that release close would fast-forward main to. When main can fast-forward to that head, never report main as past the tag.
  - Run the checkout, branch, cleanliness, binding, fetch, ancestry and manifest checks, and return the would-refresh preview or the outcome a real close would reach at that head.
  - Keep the real close's main-HEAD and tag checks.
  - Add a release fixture case whose dry run runs with main behind `origin/main`.
