## Findings

**FU1 — D013's cleanup recovery cannot be followed once the original checkout is gone (follow-up).**

- Class: operator flow, in the declared surfaces `scripts/lib/starter-refresh.mjs` and product 07's Starter refresh paragraph.
- Reproduction (module probe):
  1. An update's push lands and its disposable cleanup fails, so the ignored record is retained.
  2. The original checkout is renamed away.
  3. `worktree clone starter-fixture <original path>` fails with `directory is unreadable`.
  4. While a replacement is recorded, every preview and retry refuses with the guidance to restore the original.
  5. While the clone map names the missing original, both the preview and the retry refuse with `directory is unreadable: <checkout>` and name no route.
  6. Only moving the checkout back allowed recovery.
- Expected: a refusal that names a route an operator can complete.
- Severity: follow-up. No criterion breaks: the refusal is recorded and blocks with the same retry command, keeping the writer as criterion 5 requires. It also needs a cleanup failure followed by a removed checkout, and main had no starter refresh.
- Consequence: every later release close keeps a `starter-refresh` blocker and the dispatch's writer. This is the planning receipt's criterion:5 known issue, by a concrete cause.
- Repair rule (D018): when the retained record's checkout no longer exists or is no longer a Git top level:
  - name a completable route in both the refusal and product 07, for example an identity-checked discard of the record and its scratch directory once no checkout can still register the disposable worktree;
  - never adopt a replacement checkout's objects;
  - add the moved-checkout case to the existing update fixture, with no extra kit preparation.

**FU2 — The starter refresh fixture leaves the module's scratch directory in the system temporary directory after a mid-test failure (follow-up).**

- Class: fixture hygiene, in the declared surface `scripts/test-launchpad.mjs`.
- Observed:
  - A `dotln-starter-refresh-*` directory created at 2026-10-14T00:16Z remains in the system temporary directory.
  - Its disposable worktree's `.git` file points into the `starter-refresh-fixture` checkout of a launchpad fixture root that has since been removed, and it holds that fixture's `keep.txt`.
  - `refreshOne` creates its scratch directory under `tmpdir()`.
  - The fixture keeps the inherited `TMPDIR`, which `scripts/test-runner.mjs` does not set per task, and `test.after` removes only the fixture's own root.
- Inference from those observations: a run that failed between the faulted update and the recovery step left this directory. The failing run itself was not observed. I did not create the directory and left it in place.
- Severity: follow-up. It breaks no criterion and no behavior main had.
- Repair rule (D018): keep every directory the fixture causes the module to create inside the fixture's removable root, for example by giving the refresh driver a `TMPDIR` there.
