## F1 — Cleanup selects a live CLI from the server installation

**Severity:** blocking. **Class:** escape. **Basis:** authority boundary and regression in preserving another active CLI during lifecycle dispatch or worker cleanup.

**Expected:** D143 authorizes cleanup of abandoned background servers only, with no other Codex session alive. A live CLI remains outside that authority even when its executable is installed beside the server.

**Observed:** given synthetic daemon/server rows and a live CLI row using that installation's executable, `closeLeftoverCodexServers` invokes its termination callback for the live process too. Both interactive and `exec` commands reproduce this. A live CLI outside the installation directory prevents all callbacks, and the abandoned-server control still cleans up.

**Cause:** `leftoverCodexServers` in `scripts/lib/codex-background.mjs` classifies every command beginning with the installation directory as a server and excludes those rows from its live-Codex test. It does not distinguish active CLI commands from background-server roles. The default callback sends `SIGTERM`; `scripts/resume.mjs` calls it at non-Codex lifecycle dispatch, and `scripts/lib/worker-launch.mjs` calls it when a Codex worker returns. The baseline had no such global cleanup.

**Supported input:** the [local help check](../../evidence/WO-276/verifier-004/local-cli-admission.json) confirms that the actual installed executable exists and supports interactive use and `exec`. This is not an invented command vocabulary. An operator can invoke that executable while another host runs a lifecycle command. From the observed callback selection and the default callback's source, the cleanup can terminate that active CLI.

**Reproduction:** run `node scripts/harness.mjs bounded -- node docs/evidence/WO-276/verifier-004/independent-probes.mjs docs/evidence/WO-276/verifier-004/independent-probes.json` and read `live-packaged-cli` and `live-packaged-interactive`: both have `liveProcessSignalled: true`. The signal function is a recording stub. No real process was signalled and no live interruption is claimed. The separate help check launches no worker or model request.

**Repair rule:** distinguish live CLI commands from background-server roles regardless of installation directory; leave live or unclassified processes untouched. Add same-installation live CLI cases while preserving the existing temporary-root, outside-directory live-session and abandoned-server controls. This is an in-scope defensive repair.
