## Findings

### F1 — every canonical gate still keys each suite on the checkout path, through npm's environment (blocking, high)

- **Criterion:** AC2 (the shared key no longer contains the physical path) and AC3 (sibling worktrees share successes); the objective's identity rule; operator-review assumption 2; the Cost line's release-close case.
- **Observed:** `suiteEnvironment` (`scripts/lib/suite-evidence.mjs:36–78`) retains every `npm_config_*` variable, and npm exports `npm_config_local_prefix`, the project directory, to every script and exec child. All three retained host rows list it in `inputEnvironmentKeys`. In this worktree, `npm exec -- node <probe>` projects `npm_config_local_prefix` equal to the checkout path, and `suiteInputIdentity` for `kernel` gives one hash under that environment and a different hash when only that value is replaced by another checkout's path; the only differing digest class is `environment`. Under direct `node` the key differs again because the eleven npm variables are absent.
- **Expected:** at identical candidate bytes, installed roots, toolchain and reviewed environment, a linked worktree or the main checkout at release close reuses the first worktree's successes through the canonical entry points. D003 normalized `PATH` entries under the checkout to `<worktree>` for this reason and left the second carrier in place.
- **Why the fixtures pass:** the sibling fixture calls `observeSuiteInputs` for both worktrees inside one test process, so both inherit that process's single prefix; the AC2 fixture varies Git state and execution facts, never the environment. No fixture observes under differing `npm_config_local_prefix` values or through a real npm child.
- **Reach:** reuse inside one worktree is unaffected, so AC7 stands: the prefix recurs on every run. Every cross-worktree case re-executes all 78 tasks, including the release close on main that the Cost line names as the case to remove. A repair that gives `npm_config_local_prefix` the `<worktree>` identity, or drops it from the projection with D012's forward-and-hash rule checked (npm recomputes it from the working directory), plus a fixture that varies the prefix, would close this.
- **Reproduction:** an ignored probe (`docs/control/local/probe-env.mjs`, deleted after this report) that imports `suiteEnvironment`, `observeSuiteInputs` and `suiteInputIdentity`, prints the projected keys whose values contain the checkout path, computes the `kernel` identity under `process.env`, then under `{ ...process.env, npm_config_local_prefix: "/elsewhere/checkout-of-identical-bytes" }`, and compares `inputHash` and `digests`. Run it with `npm exec -- node <probe>`: `npm_config_local_prefix equals checkout: true`; hashes unequal; differing class `environment`. Run it with `node <probe>`: no npm keys, a third hash.

### F2 — `authority-evidence` reads tag `v0.16.0` from the repository but declares no Git state (non-blocking, low)

- **Observed:** `scripts/authority-evidence.mjs:317` and `:325` run `git show v0.16.0:<path>` with the repository root as working directory, for ten historical WO-042 evidence files and every bundle path; `:69` reads blobs at the baseline's `sourceRevision`, which is a commit id and therefore content-addressed. - **Expected:** the objective keys each suite on the Git state it reads; a suite that reads a tag declares `refs/tags/*` or that tag. A moved or deleted `v0.16.0` would leave a cached success valid.
- **Reach:** low. Release tags are not moved here, and the release close checks tag objects. The repair is one declaration; the existing declaration fixture then covers it.
