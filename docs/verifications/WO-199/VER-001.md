## Findings

**F1 — a signal outside the writer step no longer stops the host (blocking).**

- Class: regression (operator flow), in the declared `dotln.ts` vertical branch and the `vertical-host.ts` step loop.
- Observed and expected:
  - `dotln.ts:92-100` installs `process.on` listeners for the whole run, which removes Node's default exit.
  - The abort is consulted only in the source host and at step boundaries (`vertical-host.ts:113`, `:206`, `:252`).
  - A signal during a judgment step leaves the host running until the step ends, and the step's result is then discarded.
  - A repeated signal returns early (`dotln.ts:96`).
  - At HEAD the vertical branch had no listener (`git show HEAD:packages/skeleton/src/dotln.ts` lines 85–97), so the host ended at once. D060 records the same.
- Reproduction: `node scripts/harness.mjs bounded -- node docs/evidence/WO-199/verification-001-signal-step-probe.mjs` (2026-10-08T03:32:53.168Z–03:35:04.171Z, exit 0). It uses the order's own CLI actor doubles and holds the verification judgment that follows the completed writer step for 30 s. Only the host pid is signalled.

  | Variant | Signal | Exit after signal | Exit |
  | --- | --- | --- | --- |
  | subject | SIGTERM | 29518 ms | 143 |
  | subject | SIGINT | 29536 ms | 130 |
  | subject | SIGHUP | 29541 ms | 129 |
  | HEAD disposition (new listeners dropped) | SIGTERM | 8 ms | by signal |

  An earlier run gave 29540, 29534 and 8 ms. `verification` stays pending in every variant.
- Reach, by source and not probed:
  - Judgment episodes are bounded at 600 s (`VERTICAL_JUDGMENT_LIMITS`).
  - The review-settle poll waits up to 900 s and never reads the signal (`vertical-primitives.mjs:230-272`). It has no child, so even a terminal Ctrl-C waits there.
  - A judgment child is not detached (`worker-transport.ts:118-120`), so a terminal job-wide Ctrl-C does reach a real judgment CLI.
- Severity: blocking, because the change breaks behavior `main` had and a probe shows it.
- Repair rule (D009): after any of the three signals, `dotln vertical` exits non-zero within a stated bound in every step.
  - The run's abort stops in-flight non-writer episodes and waits, or the handler exits once no writer is live and writer settlement has finished.
  - A repeated signal never extends the wait.
  - Keep the writer path's forwarding, 10-second settlement, record and pending step.
  - Add regressions for a judgment step and the settle wait.

**F2 — native toolchain at product runtime (follow-up).**

- Class: platform fit. `SourceChangeHost` now imports `scripts/lib/host-resources.mjs` (`source-change-host.ts:562-580`, `:612-616`, `:825-835`).
- `taskLauncher()` compiles `host-lock.c`, and on darwin `readHostSnapshot` compiles `host-footprint.c`, with clang and xcrun into the user temp root on first use (`host-resources.mjs:116-162`, `:330-370`). At HEAD only gate scripts imported that module, and the product docs name no C toolchain.
- Consequence on a host without one: a launch throws before `WorkerAttemptStarted`. That is inferred and not observed. The compile writes nothing to the repository.
- Breaks no criterion. Criterion 5's "no new dependency" reads as package dependencies, as the order's Cost frames it.
- Boarded in D009: name the prerequisite or refuse with a named reason. Never weaken the launch gate or the birth-identity check.

**F3 — repair writer signal path untyped and untested (follow-up).**

- Class: maintainability and test coverage.
- `RepairHost`'s `source` type (`repair-host.ts:71-80`) omits `signal`. The vertical's `sourceOptions(state)` carries it, and `sourceHost()` spreads it into the child host (`repair-host.ts:205-209`), so a repair writer is interrupted only through that untyped spread.
- No test interrupts a repair writer. RepairHost has no catch around `source.run()`, so an interrupt propagates as in the source-change step (source inference).
- Boarded in D009.

## Attack variations

- **Signal in a non-writer step:** F1.
- **Signal to the host pid alone versus the job:** judged above. A job-wide signal during a real judgment reaches the judgment child as well.
- **Repeated signal:** swallowed, by source (F1).
- **Second live host on the same store:** refused by the store's `host.lock` live-pid check (`worker-store.ts:271-299`). Moving `fence()` after `recoverTermination` therefore cannot kill a live host's writer.
- **Forged or stale records:**
  - A mismatched birth identity is refused, and the group is left alive (test passes).
  - A malformed `processIdentity` or `launchGated` fails decoding (`source-change-host.ts:258-262`, `:338-356`).
  - A legacy log without `launchGated` replays (integrity suite).
- **Death before the start marker:** no writer is admitted, and recovery records `dispatch-not-started` (test passes).
- **Abort before or during launch:** by source, `interrupted()` runs before `dispatch.start()`. The catch path sends SIGKILL to an unreleased supervisor, so no writer starts.
- **Result-commit mismatch:** now `host-admission-result-commit`, where HEAD recorded `WorkerInterrupted invalid-result`. By source, HEAD's rerun then observed that commit through recovery, and the subject seals `refused`. This is stricter and matches the Design's typed refusal, so it is not a finding.
- **Working directory:** not applicable. The CLI resolves `--store`, and the new imports resolve from `import.meta.url`.
- **Real corpus:** no live model writer ran through the vertical. The order's live row is the feedback episode (criterion 4).
- **Linux:** untested. By source, `/proc/<pid>/stat` supplies an integer `birth`, which passes the new identity validation.
