## F8 — A nested suite's gate fixture outlives its gate's accounting and stays forever

**Severity:** medium. **Route:** blocking (criterion 6; a reproduced regression of behavior `main` had). **Class:** a gate-owned root registered outside the gate's ledger, with an owner identity no lifecycle can judge. **Repair rule:** every root whose owner record carries a gate's identity is either removed by its creator's teardown or accounted for by that gate's completion, as removed or as retained with a reason. That includes roots created by suites run nested inside a copied fixture repository. A whole-root teardown defers to a gate only when that gate's completion will see the root. An unreadable process table in a copied fixture never leaves a gate-owned root retained forever on that ground alone. The repair closes the class, not one call site, and keeps the root on the helper. A regression case creates a helper root through a nested `executeSuite` in a copied repository without `scripts/lib/host-resources.mjs`, and proves that nothing of it remains after the outer gate's passing row. The two quarantine roots already left are removed through the lifecycle. Both exit 1. The census lists one root for gate `10b258ee` that its row neither removed nor retained: `dotln-wo185-quarantine-9LOzTD`, 436 KB, created at 20:13:38Z inside the passing runner-fixtures task. The cause is in D044. It moved the WO-185 quarantine case in `corpus/harness/wo102-generators.test.mjs` off a raw root, which `fs.rmSync` removed at teardown, and onto `createFixtureRoot`, with `removeTemporaryPath` as its teardown. The copy lacks `scripts/lib/host-resources.mjs`, so the helper records the owner's birth as null. Four steps then keep the root forever:

1. `removeTemporaryPath` returns without removing a gate-owned gate fixture that has no end, because it defers to the gate.
2. `finishGateTemporaryRoots` reads only the gate repository's own ledger.
3. Removing the copy deletes the only ledger that lists the root.
4. `judgeTemporaryRoot` retains an owner whose liveness is unknown before it consults any gate row, and nothing ever records that birth.

The nested-suite probe reproduces this in the same copied layout. The file at the order's base leaves no root.
