## Findings

### F1 — live lineage and planning consumers ignore configured roots

**Severity:** high. **Contract:** objective, criteria 2–3. **Sources:** [lineage.mjs](../../../scripts/lineage.mjs), [plan-direct.mjs](../../../scripts/lib/plan-direct.mjs), [plan-receipts.mjs](../../../scripts/lib/plan-receipts.mjs).

`lineage.mjs` assigns `ledgerPath` and `indexPath` through `defaultDocRelative`, then uses them in `main(root)`. `latestPlanningPass`, `planJudgmentScope` and `planningPassScope` still consume the default `PLAN_LEDGER`; direct-refutation report projections also retain default `RECEIPTS` paths. These are live consumers, not compatibility constants without a launchpad.

**Reproduction:** initialize a temporary Git repository with a committed synthetic ledger and the supported status declaration. The default fixture uses `docs/lineage/idea-ledger.md`; the matched configured fixture declares `{"version":1,"roots":{"docs":"records"}}` and places the same ledger under `records/lineage/`. Run `DOTLN_LAUNCHPAD=<fixture> node <tool>/scripts/lineage.mjs index`; independently call `latestPlanningPass(fixture, [])` on each fixture.

**Observed:** the default command exits 0 and writes its index; the default planning call returns the dated pass. Both configured calls fail with `ENOENT` naming `<fixture>/docs/lineage/idea-ledger.md`; the configured ledger exists. **Expected:** read and write under `records/lineage`, with the same logical result. This breaks a declared launchpad layout even when the literal-root guard is green. Carry root-aware paths through the live consumers and exercise them in configured fixtures. [Repair record D009](../../evidence/WO-069/decisions.md#wo-069-d009).
