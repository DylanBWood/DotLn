### F2 — an unavailable denial produces no key at all, not "the complete candidate key" amendment 13 names

Amendment 13 says: "Otherwise retain fresh execution under the complete candidate key; record the reason." The implementation retains the fresh execution and records the reason, but assigns no key, so the suite is never cached and never reused even when nothing changed. Every other narrowing refusal does fall back to the complete candidate key and stays reusable at an unchanged tree (`scripts/lib/suite-evidence.mjs:808-812`; asserted in `scripts/test-suite-evidence.mjs:1289-1306`).

Observed — two consecutive gates at a byte-identical tree in this session:

```
FRESH kernel (candidate read denial unavailable: host refused sandbox startup; …)
npm test: 2 passed; 0 failed; 4.70 s; 2 fresh / 0 reused tasks
FRESH kernel (candidate read denial unavailable: host refused sandbox startup; …)
npm test: 2 passed; 0 failed; 4.62 s; 2 fresh / 0 reused tasks
```

The complete candidate key covers every candidate entry, so an undeclared absolute-path read is inside the key and caching it would not reproduce the counterexample D009 closes. The narrower choice is defensible and is recorded, but it is not what the amendment authorizes, and it removes the one reuse case the amendment preserved. Reproduction: `npm test -- --only kernel` twice with no intervening change.

### O1 — a running gate cannot be stopped from inside its own session (observation, adjacent to amendment 14)

While a gate holds the evidence lock, the pre-tool guard refuses every shell effect, including a `kill` or `pkill` naming the gate's own process ids: `DOTLN_HARNESS_REFUSED: write may change gate inputs during active gate`. The harness-level stop tool also refused (`host facts or pinned runtime unavailable`). The only exits are the operator typing `analysis:` or `operator override:`, or running the kill outside the agent's tool path. Observed when the operator directed this verifier to abandon its completion gate: I could not comply, and the operator had to run `pkill` themselves.

This is not introduced by WO-131 — `packages/skeleton/src/harness-command.ts` is unchanged and the gate-lifetime write refusal is WO-125-D003 — but it sits directly against amendment 14's boundary, which places operator controls "ahead of imports, lifecycle reads, runtime pins, writer reservations and gate locks". The prefixes do reach the agent as designed; what has no route is an agent aborting a gate it started once that gate is known to be worthless. The ideation receipt already names concurrent process handling as part of the unimplemented general recovery helper; this is a concrete, reachable instance of it and belongs on that candidate rather than in this order.

### O2 — a failed verification pays a full gate for a check it does not need (observation)

`verificationResult` with verdict `fail` requires exactly one recorded check at the current tree, `git diff --check`; `npm run test:full` is required only for a pass (`scripts/lib/lifecycle-evidence.mjs:38-41`). The only sanctioned command that records that row, `npm run harness -- evidence`, always runs the full gate first (`packages/skeleton/src/harness-host.ts:1571-1585`). On a host where the declared suites cannot reuse — F1's case — recording a failed verdict therefore costs a full fresh gate for a check the lifecycle does not require. Recording this verdict was blocked on exactly that, and the report was left with its verdict unrecorded rather than fabricating the row or spending the gate unasked.

Also outside this order's scope, and also cheap to fix: where the kernel denial is available, that same evidence command composes in roughly a minute at this document-only delta, so the cost falls entirely on the sessions F1 describes.
