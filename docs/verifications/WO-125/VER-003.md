## Findings

### F1 — pre-existing hard links let in-place shell writes change tracked inputs during a live gate (blocking, low)

- **Criterion:** the Execution record: "Live runs refuse agent Write/Edit and write-classified shell commands that could change protected gate inputs, with the active run named." Also product 07 lines 1213–1215: "Generated pre-tool hooks refuse Write, Edit and shell writes targeting protected inputs before dispatch".
- **Observed:** [D004](../../evidence/WO-125/decisions.md#wo-125-d004) chose to "resolve physical write destinations component by component". `prospectiveRealpath` (`gate-evidence.mjs:42–74`) implements that walk, and `gateInputPath` (`:78–148`) classifies the resulting paths. A hard link shares an inode with the file it aliases but has no path relation to it, so the walk cannot see it. A hard link in ignored scratch therefore classifies as scratch (`false`) even when its inode is a tracked file's.
- **Reproduction:** a fixture built as in `scripts/test-harness.mjs` `fixture()` (lines 90–180), with `docs/control/local/hardlink.ts` hard-linked to tracked `fixture.ts` before the gate. A child held a `beginGateRun` marker, and the generated `permissions` hook received `PreToolUse` input.
  - Admitted, and each changed `fixture.ts` and `gateTreeHash` once executed with `sh -c`:
    - `printf 'export const value = 3;\n' > docs/control/local/hardlink.ts`
    - the same write through `| tee docs/control/local/hardlink.ts`
    - the same redirect as a Codex-style `exec_command`
    - `printf '// appended\n' >> docs/control/local/hardlink.ts`
  - Controls: `touch` through the link was admitted and changed no fingerprint. `ln fixture.ts docs/control/local/new-hardlink.ts` was refused during the gate, so the link must predate it.
- **Write and Edit:** a Write was also admitted. The fixture convention executes it in place, which changed the file. Claude Code `2.1.269`'s Write tool, however, replaced the directory entry when I wrote through a hard-linked pair in ignored scratch: the written name got a new inode and its partner kept its bytes. In this harness the Write path therefore does not propagate. I did not test Edit or Codex's file tools.
- **Expected:** refusal naming the active run, as the repair now does for symlink aliases.
- **Impact and limits:** the link must exist before the gate. The final suite-input comparison voids a run changed this way, so the gap wastes a gate rather than producing false evidence. That is the same impact class as VER-002 F1 and F2.
- **Bounded repair:** when the physical destination exists as a non-directory with more than one link (`lstat(...).nlink > 1`), classify it as an input, because the classifier cannot prove the other names are scratch. Add a hard-link case to the runner test and to the generated-hook path matrix. Surfaces: `packages/skeleton/src/gate-evidence.mjs`, `scripts/test-runner.test.mjs`, `scripts/test-harness.mjs`, and 07's repair sentence. The alternative is to record pre-existing hard links as an accepted adapter limit in D004 and to qualify 07's refusal sentence.

## Goal alignment

WO-125 lets a Codex refuter or worker launch at `max`, and its repair keeps verification inputs stable. Both serve the independently verified source-to-deliverable loop on the critical path. The transport half delivers its observation. The guard now covers every path alias I found except hard links.

- **NoOp (pass as filed):** this would certify 07's refusal sentence for a write the guard admits. An agent that once hard-linked a backup into scratch could later void a 13-minute gate with an ordinary redirect. Reopening condition: if the operator records pre-existing hard links as an accepted adapter limit in D004 and 07, F1 reduces to that wording change.
- **Naive Interventionism:** the repair is one conservative check and one fixture case in files the order already names. Valid gate markers, scratch admission and the transport are unaffected, and the change is locally reversible. Its only cost is refusing writes to multiply-linked scratch files while a gate runs, and such files are rare.
- **System traps:**
  - Rule beating: the current fixtures pass without inode handling.
  - Drift to low performance: accepting 07's unqualified claim would normalize a gap that D004's own rationale rejects ("NoOp retains known input-changing writes").
  - Escalation and tragedy of the commons: a third repair cycle costs shared compute and operator attention. To bound it, I swept the alias category in this pass: case, symlinks, link chains and loops, working directories, trailing slashes, hard links and Unicode spellings. Only hard links remain, so one repair can close the category.
  - Shifting the burden: without the check, only the final comparison catches such a write, after the gate's cost is spent.
  - Policy resistance: the check refuses slightly more than necessary during a gate, which I judge acceptable.
  - Success to the successful and seeking the wrong goal are immaterial: the finding targets the stated behavior.
