## Findings

### F1 — case-variant paths into installed inputs are admitted during a live gate (blocking, low–medium)

- **Criterion:** the Execution record: "Live runs refuse agent Write/Edit and write-classified shell commands that could change protected gate inputs". Also product 07 lines 1213–1215: "Generated pre-tool hooks refuse Write, Edit and shell writes targeting protected inputs before dispatch".
- **Observed:** this checkout has `core.ignorecase=true` on a case-insensitive volume.
  - `gateInputPath` (`gate-evidence.mjs:46–83`) compares the installed roots and the `packages/<name>/dist` patterns case-sensitively.
  - `prospectiveRealpath` uses `realpathSync`, which keeps the caller's spelling (`…/NODE_MODULES`). `realpathSync.native` returns the on-disk spelling (`…/node_modules`).
  - `git check-ignore` matches case-insensitively, so the variant is classified as ignored scratch.
  - Against this worktree, `gateInputPath` returns `true` for `node_modules/probe.js` and `packages/skeleton/dist/src/probe.js`. It returns `false` for `NODE_MODULES/probe.js`, `Node_Modules/typescript/probe.js`, `Packages/skeleton/dist/src/probe.js` and `packages/skeleton/DIST/src/probe.js`.
- **Reproduction:**
  - Classification, read-only, from the worktree root:

    ```sh
    node --input-type=module -e 'const {gateInputPath} = await import("./packages/skeleton/src/gate-evidence.mjs"); for (const p of ["node_modules/probe.js", "NODE_MODULES/probe.js", "Packages/skeleton/dist/src/probe.js", "packages/skeleton/DIST/src/probe.js"]) console.log(gateInputPath(process.cwd(), p), p)'
    ```

  - Enforcement: the fixture method below. Through the generated `permissions` hook with a live marker, each of these was admitted:
    - Write `NODE_MODULES/probe.js`
    - `touch Node_Modules/probe2.js`
    - Write `Packages/skeleton/dist/src/probe.js`
    - `printf x > packages/skeleton/DIST/src/probe.js`
  - Once executed, each file landed in `node_modules` or `packages/skeleton/dist`, and the installed-input listing changed.
  - The tracked control `FIXTURE.ts` was refused, because a non-ignored path is protected whatever its spelling.
- **Expected:** refusal naming the active run, as for the canonical spellings.
- **Impact and limits:** such a write is voided later by the suite-input comparison, so it wastes a run rather than producing false evidence. Agents rarely misspell these roots. The finding rests on the Execution record's refusal requirement and on 07's claim.
- **Bounded repair:** in `gateInputPath`, compare the on-disk spelling of the deepest existing ancestor (for example `realpathSync.native`), or fold case for the installed-root and package tests where Git ignores case. Add generated-hook fixture cases for `NODE_MODULES/…` and `Packages/<name>/dist/…`. Surfaces: `packages/skeleton/src/gate-evidence.mjs`, `scripts/test-harness.mjs`, `scripts/test-runner.test.mjs`.

### F2 — dangling symlinks and `..` after a symlinked directory escape classification (blocking, low)

- **Criterion:** the same Execution record sentence. Also [D003](../../evidence/WO-125/decisions.md#wo-125-d003): "Negative and positive fixtures must prove the narrow boundary, including ignored-but-tracked files and symlinks into protected inputs."
- **Observed:**
  - When `realpathSync` fails with `ENOENT`, `prospectiveRealpath` (`gate-evidence.mjs:32–42`) falls back to the parent's real path plus the final name. A dangling final symlink is therefore classified as itself, which is ignored scratch, while writing through it creates its target.
  - `gateInputPath` resolves `..` lexically (`resolve(root, path)`) before any symlink resolution. The kernel resolves the symlinked directory first.
  - The shipped fixture covers only a symlink whose target already exists (`input-link.ts` → `fixture.ts`).
- **Reproduction:** in a fixture built as in `scripts/test-harness.mjs` `fixture()` (lines 90–180):
  - Set up two links in the ignored `docs/control/local/`: `dangling.md → ../../../new-input.md` (absent) and `dirlink → <root>/packages/skeleton`.
  - A child holds a `beginGateRun` marker, and `.claude/hooks/permissions.mjs` receives Claude-style `PreToolUse` input.
  - Admitted, and each changed `gateTreeHash` once executed:
    - Write `docs/control/local/dangling.md`
    - `touch docs/control/local/dangling.md`
    - `printf x > docs/control/local/dangling.md`
    - `touch docs/control/local/dirlink/../probe-new.md`, which created `packages/probe-new.md`
  - Controls: a Write whose `dirlink/..` path is normalized before writing changed nothing, and `touch docs/control/local/dirlink/dist/probe.js` was refused.
- **Expected:** refusal, because each write creates a non-ignored candidate-tree file.
- **Impact and limits:** the link must already exist, since `ln` is opaque and refused during a gate. As in F1, the final comparison voids the run afterwards.
- **Bounded repair:** when the final component is a symlink, resolve its target even if the target does not exist (`lstat` plus `readlink`), and resolve `..` against the physical parent of each symlinked component. Add dangling-link and `link/..` cases. Surfaces: `packages/skeleton/src/gate-evidence.mjs`, `scripts/test-harness.mjs`.

### F3 — the F3 fixture's fixed 30 s hold has no margin and failed the canonical gate (blocking, medium)

- **Criterion:** AC5, "`npm test` green". The gate is `npm run harness -- evidence`.
- **Observed:**
  - The held-gate program in `scripts/test-harness.mjs` sets `const deadline = Date.now() + 30000;` (line 294) for each held stage.
  - While a stage is held, the test runs 60 generated-hook processes in sequence: 14 refusal attempts across 3 hooks, 5 scratch attempts across 3 hooks, and 3 reads. It also executes the 15 admitted scratch attempts (9 through `sh`, 6 as file writes) and computes `gateTreeHash` after each attempt.
  - In the canonical gate the cases took 29,309 ms (runner) and 28,288 ms (evidence). The entry case failed at 31,563 ms: the child printed `Error: held gate timed out` and exited before its next stage was ready (`test-harness.mjs:346`).
  - The failure is intermittent: the executor's final gate and my isolated run passed.
- **Reproduction:**
  - The gate record above, and its log line `FAIL harness-fixtures 142.45 s`.
  - In a scratch copy, `node --test --test-name-pattern="WO-125 F3" scripts/test-harness.mjs` with 14 concurrent CPU-bound `node` processes passed with per-case durations of 31,433 ms, 30,164 ms and 57,768 ms for two stages. Each held stage stayed within roughly ±2 s of the 30 s limit.
- **Expected:** a deterministic fixture whose bound comes from the test, not a hold that expires under ordinary gate load.
- **Impact:** a load-dependent failure voids a roughly 12-minute gate, which is the waste F3 was meant to remove.
- **Bounded repair:** release the held stage by signal and let the test's own timeout bound it. Otherwise, set the hold far above the maximum per-stage work, or split the attempt matrix across stages. Surface: `scripts/test-harness.mjs`.
