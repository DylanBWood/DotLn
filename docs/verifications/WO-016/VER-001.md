## Acceptance criteria

**1. One typed reactor owns every decider — met.**
`packages/skeleton/src/reactor.ts` exports
`export const seiriReactor: Reactor<RuntimeState>`. Its only `from "…"` import
is `@dotln/kernel`. A repository-wide grep places all seven call sites of
`evaluateCadence`, `authorize`, `decideProgram`, and `guardQueuedPulse` inside
that file (lines 371, 423, 485, 509, 514, 554, 590) and nowhere else under
`packages/skeleton/src`; the skeleton tests do not call them either. The AC1
test re-derives this from the source text at run time rather than trusting a
one-time grep.

**2. `replayScenario` is the kernel's `replay()` — met.** Its whole body is
`replay(initialState(), decodeLog(log), seiriReactor, seiriPredicates)`
followed by `projectResult`. There is no event-type branch, no `switch`, no
`for`, and no `fixture` parameter. Every field of `ScenarioResult` is
reconstructed: `timeline` and `log` from the decoded log; `glyphScene`,
`workOrder`, `candidates`, `verified`, `cancelledScheduleIds`, and
`activeScheduleIds` from folded reactor state; `decisions` from the reactor
itself. The three genuinely adapter-only fields — `adapterEffects`,
`adapterDispatches`, `recoveredCommands` — moved to `LiveScenarioResult`, so
replay no longer returns a constant stub for anything.

**3. Complete Decision identity — met.** `Decision<S>` is exactly
`{state, intents, continuation?, schedules, trace}` (`packages/kernel/src/types.ts:363`),
and the AC3 test's `semanticProjection` deep-strict-equals the whole
`decisions` array plus `timeline`, `glyphScene`, `workOrder`, `candidates`,
`verified`, `cancelledScheduleIds`, and `activeScheduleIds`. It also pins the
decision count to the event count on both sides, the exact grant trace
including `now:1200000`, the revocation branch path, the five `DecisionRecorded`
source indices, and the exact candidate list.

One structural note the final reviewer should carry forward. The live host now
feeds each appended event through the same `replay()` one event at a time
(`LiveReactorDriver.feed`), and the kernel derives `env` from state and event
inside its own loop, so incremental and batch replay are the same computation.
Live/replay identity is therefore true by construction — which is exactly what
the objective asked for, "a structural property instead of an agreement between
two hand-written scripts." It does mean the identity assertion alone cannot
kill a reactor mutation; the killing force in this suite comes from the
absolute values pinned in the same test and from the log-level payload tampers.
The mutation drill below confirms that force empirically rather than assuming
it.

## Findings — non-blocking

**F1 — one recorded digest is malformed.** The Stage 2 audit-projection digest
in the implementation evidence receipt is written as
`45f12c35ed5a4df75bc01cb88c5b2dd49224136666a6e5fc2f0320ce972de5a65`, which is
65 hex characters and therefore cannot be a SHA-256. The measured value is the
64-character `…fc2f0320ce972de5a4`; the two agree on the first 63 characters.
Every other digest in the receipt reproduced exactly. Impact is limited to a
later reader trying to check that one line.

**F2 — AC5's "identical to `main`" is literally false for CLI stdout in the
delivered tree.** `cmp` of the subject's default CLI output against `main`'s
fails on line 1, because the mandated component bump changes the banner from
`v0.3.1` to `v0.3.2`; the remaining 25 lines and 839 bytes are identical, and
normalizing the banner reproduces the baseline digest exactly. The Stage 1
capture was taken before the manifest bump, so the receipt's Stage 1 claim was
true when made, and the receipt does disclose the bump separately. The wording
"Stage 2 leaves the default CLI byte-identical" should say "byte-identical
except the version banner" so the claim stays reproducible from the delivered
tree.

**F3 — ADR-0001 was edited in place as well as amended.** The change correctly
appends a dated `## Amendments` section, but it also rewrites the
`## Consequences` paragraph, narrowing "No inherited-context ledger for
external rules is needed (nothing external is inherited)" to "No
inherited-context ledger for the predecessor's runtime or rule stack is needed
because neither is imported." The execution guide's "Settled is settled" rule
permits appending to `Amendments` and says a challenge becomes "a new decision
record proposal, never an in-place edit." The substance of the correction is
right and is already stated in the amendment; restoring the original
`Consequences` sentence would keep the historical bytes intact. Alternatively
the operator or final reviewer can explicitly bless the in-place clarification
and say so.

**F4 — one mutation in the drill has two targets, and only one is killable.**
"Dropped authorization evidence" can mean the recorded projection
(`authorizationEvidence: evidence` in `deletionDecision`'s returned state) or
the `evidence` array passed into that `authorize()` call. The first is killed
by `WO-016 step 9 …`, as the table above records. The second is **not** killed
by any test and cannot be: `auth_seiri` declares `requiredEvidence: []` and the
refusal fires on `effect denied`, so that argument is not load-bearing for this
fixture. I verified this directly — the mutant compiles and 29/29 still pass.
That is an equivalent mutant rather than an escaped defect, but the receipt's
mutation table should name which target it drilled so a later reader does not
over-read the "all thirteen mutants were killed" claim.

**F5 — the AC1 size assertion pins a literal baseline.** The test asserts
`scenario.ts` is shorter than `748` lines, a number copied from `main` rather
than derived from it. It proves the AC9 direction today and silently stops
tracking if the baseline ever moves. Cosmetic.

**F6 — prose-width regression in `01-principles.md`.** Inserting the layer
labels (`_Platform contract._`, `_Personal profile._`, …) after each bolded
principle title pushed 24 non-table lines past 80 columns, against 5 on `main`;
the longest is 104 characters. Prettier passes because the repo sets
`proseWrap: "preserve"`, so this is convention drift, not a failing gate.
`00-vision.md` picked up two such lines the same way.

## Verdict

**Pass.** The walking skeleton is now genuinely an instance of the kernel loop:
one exported `Reactor<RuntimeState>` makes every decision, the live host owns
only fakes and effects, and replay is the kernel's own `replay()` over the same
reactor and the same log. The v0.2.0 "same log, same decisions" claim is a
structural property rather than an agreement between two hand-written scripts,
and the mutation drill shows the surrounding tests have real force rather than
resting on that structure. Stage 1 changed no output byte; Stage 2's only
deltas are the canonical links and the single audit association they justify,
proven in both directions by reconstruction. The documentation and ideation
promotions are honest about what is candidate, what is unresolved, and what
remains unavailable. The six findings are wording and hygiene corrections that
do not affect behavior, contracts, versions, or the captured evidence.
