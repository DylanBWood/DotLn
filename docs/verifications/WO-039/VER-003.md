## F1 — self-refresh does not invalidate a stale reclaim (high, blocking)

**Requirement.** The order's Phase 1 writer-isolation mechanism must establish one writer before dispatch. VER-002's repair obligation explicitly includes owner-refresh mutations. Product 02 and the second repair also promise that a session finding its own recorded owner dead marks that identity unavailable and is then honoured, rather than automatically reclaimed.

**Observed.** `refreshWriterInstance` at `packages/skeleton/src/harness-host.ts:473` replaces the contents under the existing reservation filename. The self-owned dead-owner path at line 659 changes its liveness to `unavailable`, then returns permission at line 669. A contender that already classified the old contents as dead still holds that same filename. `retireWriterInstance` at line 446 unlinks it without detecting the intervening refresh.

The executed schedule was:

1. Seed A's reservation with an exited recorded owner, the same supported input shape used by the existing self-distrust fixture.
2. Start B's generated writer hook. Pause its real filesystem unlink after it has classified A's recorded owner as dead.
3. Dispatch A's generated hook. It marks its own reservation `liveness: unavailable`, keeps the same filename, and allows A to write.
4. Keep A's actual fixture harness alive and its authorized work outstanding. Resume B's unlink.
5. B removes A's refreshed reservation, acquires its own, and also receives write permission.

```json
{"sessionAAllowed":true,"refreshedLiveness":"unavailable","reservationNameUnchanged":true,"sessionAActualHarnessStillAlive":true,"sessionBAllowed":true,"finalReservation":"B","writerEvents":["liveness-unavailable","reclaimed"]}
```

**Expected:** B must not remove the refreshed reservation and receive permission while A's authorization remains active. This does not dispute the chosen self-distrust policy; it demonstrates that its state change is not protected against a stale reclaimer. The new third-repair regression covers replacement by a newly named instance, but not refresh under the same name.

**Repair obligation:** include self-refresh in the ownership protocol and add this interleaving to the generated-hook regression, keeping the first authorized work outstanding. Preserve the selected dead/live/unknown-owner policies. Comparing a stable filename alone is insufficient when the facts under that filename can change.

## F2 — operator release validates one holder and removes another (high, blocking)

**Requirement.** `harness writer --release` must refuse a live holder without `--force`. The third repair claims that operator release acts only on the observed instance and cannot remove a different live replacement.

**Observed.** `releaseHarnessWriterByOperator` reads a view at `packages/skeleton/src/harness-host.ts:1749` and checks that view's liveness. It separately observes the slot again at line 1755 and retires that second instance at line 1757, without validating its owner. The return value and event still describe the first view.

The executed schedule was:

1. Seed dead holder A and start the actual public CLI, `node scripts/harness.mjs writer --release`, without `--force`.
2. Pause its second directory observation after the old dead-holder view passed the liveness check.
3. Dispatch B's generated writer hook. It reclaims A, installs B's reservation, and allows B. B's recorded owner is confirmed alive.
4. Keep B's authorized work outstanding. Resume the operator CLI. It reads B's instance and removes it, while reporting A as the released dead holder.
5. Dispatch C. C also receives permission while B's harness remains alive.

```json
{"sessionBAllowed":true,"sessionBOwnerStillAlive":true,"unforcedOperatorReleaseSucceeded":true,"operatorReportedOldOwnerDead":true,"liveReplacementRemoved":true,"sessionCAllowed":true,"finalReservation":"C","writerEvents":["reclaimed","operator-released","acquired"],"releaseJournalNamesOldHolder":true}
```

**Expected:** an unforced release must preserve B's live replacement; any successful release and its journal must describe the same validated reservation. The instance-aware retire helper does not fix a caller that supplies a new, unvalidated instance.

**Repair obligation:** bind the liveness decision, retirement and result/event to one observed reservation, with safe handling when it changes. Add an operator-release-versus-reclaim regression through the public CLI. Retain the existing explicit-force behavior and ordinary session release checks.
