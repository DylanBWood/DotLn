## Findings

**F1 — The target close's ignored-material listing names a bundle directory (blocking).**

- Class: regression of a main behavior (operator flow and recoverability), in the declared `scripts/lib/target-worktree-close.mjs`.
- Observed, subject:
  - The target's `.gitignore` ignores `.claude/settings.local.json`. After target-records, the launchpad merge and a forge-only target merge, that file is present in the target worktree.
  - `release close WO-999 --dry-run` exits 1: `target has ignored material; source retained: .claude/, .claude/settings.local.json. Move or remove the listed paths, then rerun <node> <launchpad>/scripts/release.mjs close WO-999 --dry-run`.
  - `.claude/` holds six bundle-owned files: four hooks, `settings.json` and `target-worker-manifest.json`.
- Followed, subject:
  - With `.claude/` removed, `--publish` refuses naming `CLAUDE.local.md`, which is bundle-owned but no longer recognized.
  - With that removed, close prints `Cleanup: clean` and removes both worktrees and branches. The clone's `.git/info/exclude` keeps the `# target-worker <key>` block with every bundle path, and the launchpad's `docs/control/local/harness/excludes/<key>.json` keeps the member.
- Observed, base: HEAD's scripts with the same fixture and input refuse with `source retained: .claude/settings.local.json`. With that file removed, the close removes the exclude block. The subject also closes cleanly when only the foreign file is removed.
- Cause: the bundle excludes its paths file by file, so `ls-files --ignored --directory` emits `.claude/` and each file under it (lines 158-176). The filter keeps a directory entry if any foreign file lies under it, even when bundle-owned files do too. It also keeps a file entry that a kept ancestor already covers.
- Expected: main named only the foreign file. The Design lists "each ignored entry outside the bundle once".
- Severity: blocking, because main's behavior is broken and the probe shows it. The refusal now instructs a removal that destroys the bundle, then records clean over residue in the shared clone. From 2026-10-13 the operator makes no repository change by hand, so a role, not the operator, would act on the remedy at the next target close (inference from that direction).
- Repair rule (D012):
  - List only ignored material the bundle does not own.
  - List a directory entry only when no bundle-owned path lies under it; otherwise list its foreign files one by one.
  - Never list an entry together with one of its ancestors.
  - Keep `deps/` as one entry, and keep the remedy and the exact command.
  - Add a fixture: a foreign ignored file in `.claude/` is listed alone, and removing it closes with the exclude block removed.
