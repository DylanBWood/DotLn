## Goal-aligned judgment

The order's useful outcome is a dependable, externally consumable review
interface that removes five manual host steps without weakening evidence,
authority or recoverability. The shipped command, typed requests, live
receipts and same-pass planning entry materially advance that outcome. NoOp
would retain the callerless loadout and manual workflow, so implementing the
command remains justified.

That benefit does not make the present subject releasable. The pending-pointer
finding shifts recovery back to the operator and can discard access to a paid
episode; the missing refutation after-state lets the evidence pass without the
intended confinement witness; and the stale authority edition makes a current
bundle claim from old bytes. Those are respectively shifting the burden, rule
beating and policy-resistance risks. Drift to low performance and tragedy of
the commons are bounded by consume-before-produce, explicit episode costs and
the retained NoOp/cadence decisions. Escalation is limited by routing one repair
cycle, not adding a role or scheduler. Success-to-the-successful is checked by
retaining both transports and the manual path. Seeking the wrong goal is
checked by judging recoverable evidence rather than receipt count or green
fixtures. Naive Interventionism favors the smallest repairs: preserve one
pending pointer, bind the already-required after-state, and re-mint the edition
after bytes settle; no new workflow layer is needed.

## Findings

### Finding 1 — a changed tracked status can orphan a pending explicit review. Severity: major.

**Expected:** A second review while a dispatch is pending for the same committed
subject is refused, leaving the first episode recoverable through `receipt` or
`discard`.

**Observed:** `subjectHash` includes the tracked-status hash. The admission at
`scripts/lib/entropy-review.mjs:886-890` refuses only equal hashes, while
`writePending` at lines 272-284 always rewrites the single current pointer.

**Reproduction:** In a physical temporary Git root with two committed files,
modify `src/a.mjs`, run background `review <HEAD sha>`, modify `src/b.mjs`, then
run `review <same HEAD sha>` again. The independent probe returned
`secondAllowed: true`; the two subject hashes and episode ids differed;
`currentDispatch` named the second episode; and the first scratch parent still
existed. The existing fixture at `scripts/test-entropy-review.mjs:359-380`
retries before status changes, so it does not cover this branch.

**Impact and limit:** The frozen commit does not change and no repository data
is overwritten, but the first paid result and retained scratch copy become
unaddressable through the normal command. D012 names the repair and regression.

### Finding 2 — WO-151's authority edition is stale and blocks the document gate. Severity: major.

**Expected:** The final generated bundle is bound by a current immutable
authority edition, and the entropy document row executes in a green
`npm run test:docs`.

**Observed:** The recorded planner hash in
`docs/evidence/WO-151/authority/001/bundle-diff.json` is
`sha256:02cfeccf...`; both current planner skills hash to
`sha256:e1bcbdb7...`, and the current manifest also differs. The authority
check fails before entropy and five other dependent document suites run.

**Reproduction:** `node scripts/authority-evidence.mjs --check` exits nonzero
with `stale WO-151 revision 001 evidence: bundle-diff.json`.
`npm run test:docs` reports **13 passed, 7 failed**. In contrast,
`feedback-evidence --check`, `artifact-identity-evidence --check`,
`harness check` and publication checks pass, bounding the defect to the
authority edition and its blocked dependents. D013 owns the follow-up.

### Finding 3 — the live refutation has no post-episode confinement witness. Severity: major.

**Expected:** Each live episode records tracked status before and after and an
inventoried scratch delta, so a command-capable Claude worker's receipt shows
what moved.

**Observed:** REFUTATION-002's initial subject has one tracked-status and one
inventory hash. Its confinement object has no after-state or delta. Source at
`scripts/lib/entropy-review.mjs:1365-1455` validates attempts and files the
receipt without calling `trackedStatus` or `scratchInventory` after the
episode.

**Reproduction:** Read
`docs/instance/entropy-reducer/runs/REFUTATION-002.json` and inspect
`confinement`; only `dependencies`, `commandExecution` and
`permissionDenials` are present. The review receipt provides the contrasting
before/after shape. D014 names the fixture and live-evidence repair.
