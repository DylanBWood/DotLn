## Method and independence

`scripts/resume.mjs` and `scripts/work-orders.mjs` are instruments under
verification, and they also recorded this work: `resume verify` allocated this
report, `status --json` supplied the phase, and `work-orders index` refreshed
the index. The gate runs the order's own fixtures. So I also reproduced the
consequential claims with three ad-hoc scripts, run from `$TMPDIR` and not kept
in the repository:

- **Migration comparison.** It extracts each block with its own line scan and
  `JSON.parse`, not the shared parser. It compares the block with the seed
  graph's outgoing edges, its umbrella annotations and the `HEAD` `Depends on`
  paragraph. It projects each open order from raw `FinalReviewCompleted`
  events and raw `git for-each-ref`, `git tag --merged HEAD` and `git cat-file`
  output. It then compares every generated index row with that projection.
- **Activation probe.** It builds two fresh Git repositories from the current
  `scripts/resume.mjs` and `scripts/lib/`, drives `activate` and
  `status --json` through the CLI, and observes the order segment,
  `docs/control/current.md` and `refs/dotln/*` directly.
- **Consumer probe.** It runs `status --json --work-order` for every order with
  control events, as the console collector does, and times each call.
