## V4-F1 — blocking: a partial pass clears a failure through the contract-specific lookup

**Criterion:** 16. **Severity:** high; an unsupported product-gate claim is
accepted by the lifecycle claim helper. **Class:** evidence eligibility.

**Expected:** after a failing task under contract A, a confined partial pass
cannot supply the pass needed to resolve that failure. A subsequent pass
under contract B also cannot answer the failure under A. The old complete
claim must stay displaced until an eligible resolving execution occurs.

**Observed:** the retained probe creates one complete passing result, then
runs these real diagnostics at the same code identity:

1. A failing `beta` diagnostic under A. `coveringGateCheck` returns no row,
   and `requireGateClaims` refuses.
2. A passing `beta --confined-partial` diagnostic under A. The row records
   `partial: true`; the complete claim remains displaced.
3. A passing ordinary `beta` diagnostic with `LC_TIME=C`, contract B.
   The old complete row incorrectly returns, and `requireGateClaims` accepts
   a met product-gate claim. No eligible A pass followed its failure.

The script uses actual runner rows and child executions; it neither edits
the gate index nor changes implementation. Reproduce from the repository root:

```sh
node scripts/harness.mjs bounded -- node docs/evidence/WO-213/ver004-failure-mask.mjs
```

The result records `expectedStandingRow: false`,
`afterPartialThenOtherContractHasStandingRow: true` and
`lifecycleClaimIncorrectlyAccepted: true`. Before the adverse sequence, its
independent counters establish that a targeted success followed by a complete
request in another login shell executes build, alpha and beta once, despite
changed synthetic session labels and different npm spelling.

**Cause established from source:** `latestUnderContract` in
`scripts/lib/gate-reuse.mjs` includes the partial pass; `coveringGateCheck`
accepts `intactExecutionRow(under.row) && passingResult(under.result)` as
resolving the older-contract failure. That integrity predicate does not reject
partial rows. Meanwhile `latestExecution` deliberately treats the same
partial single-suite pass as non-supplying. The classifications disagree.
The existing partial-after-green and failure-then-other-contract tests both
pass; they do not combine these transitions.

**Repair rule:** resolve a failure only with evidence eligible for that
resolution; a partial or confined pass cannot become the bridge that clears
it when a different-contract pass becomes latest. Preserve ordinary passing
diagnostic non-displacement, valid same-contract recovery, chronology and the
existing machinery semantics. Add the combined sequence through both coverage
and lifecycle claims. [D047](../../evidence/WO-213/decisions.md#wo-213-d047)
boards this for `resume: fix`.

**Limits:** this proves the lifecycle helper's admission in a disposable
fixture. I did not record a false pass on this order or publish anything. The
real worktree's passing review row is intact; its tests lack this interaction.
