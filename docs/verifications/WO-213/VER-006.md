## V6-F1 — blocking: runtime-load resolution can omit the loaded module

**Criteria:** 16, 17 and 19. **Severity:** high.
**Class:** input binding / unsupported passing claim.

**Expected:** a supported static runtime load binds the file it actually loads;
an unresolved loader spelling must fall back conservatively rather than issue
a narrower reusable declaration.

**Observed:** both of these literal forms are accepted with `inputs: []`:

```js
const load = createRequire(import.meta.url);
load("./leaf");

await import(new URL("./%6ceaf.mjs", import.meta.url));
```

The first resolves `scripts/leaf.js`; the second resolves `scripts/leaf.mjs`.
After an initial complete pass, changing the leaf to exit 13 changes the code
identity and direct execution exits 13. The declared digest does not change.
The next complete gate carries the old alpha result, executes no fresh task,
exits 0 and passes both `coveringGateCheck` and `requireGateClaims`.

Reproduce from the repository root:

```sh
node scripts/harness.mjs bounded -- node docs/evidence/WO-213/ver006-import-routes.mjs
```

Exit 0 establishes the recorded defect and controls. The ordinary repaired
command spelling with interior `..` now changes its binding and reruns the
failing task. Explicitly declaring `scripts/leaf.js` also rejects the stale
claim. The fixture changes no worktree source or real gate row.

**Cause checked in source:** `namedFiles` compares literal spellings with the
inventory without CommonJS extension resolution or module-relative URL
decoding. The shared import reader recognizes a direct `require` call but
not the alias. The command reader's conservative resolution does not cover
these closure routes.

**Repair rule:** [D069](../../evidence/WO-213/decisions.md#wo-213-d069): bind
supported static loads to their resolved modules or refuse reuse when the
loader spelling is not established. Exercise actual failing children and
both claim consumers. Preserve explicit semantic declarations, containment,
correct path aliases and the operator's declaration-based design.

**Limit:** the probe proves acceptance of these forms; it does not establish
that a shipped core declaration currently executes either form.

## V6-F3 — blocking: ordinary session environment changes defeat reuse

**Criterion:** 17. **Severity:** medium. **Class:** unnecessary validation.

**Expected:** the ordinary executor-to-verifier handoff reuses unchanged
product work. Test environments and their reuse keys must preserve meaningful
inputs without making ordinary host-session differences repeat the suite.

**Observed:** the runner rejected ninety prior task results for `GIT_EDITOR`
being removed, `GIT_PAGER`, `LC_ALL` and `LC_CTYPE` being added, and `PATH`

prior passing review. This is separate from V6-F2's four declared bindings.

**Cause checked in source:** `scripts/lib/suite-evidence.mjs` retains the
filtered inherited environment and hashes it for every task, without
establishing which variables that task reads. The filter includes all `GIT_`
names, locale categories and resolved search directories. Stored contracts
contain hashes, not the historical raw values.

The actual gate's rejection and repeated executions establish the failed
cross-session reuse. The operator explicitly confirmed that these invalidation
causes themselves are failures. The verifier initially misclassified this as
a follow-up and accepted a blanket rerun; both judgments were wrong. The
canonical stop completed with no active gate and no new check recorded.

**Repair rule:** [D071](../../evidence/WO-213/decisions.md#wo-213-d071): use a
stable fixture environment or bind the environment inputs a task actually
depends on. Prove reuse across the ordinary executor/verifier host differences,
while retaining invalidation for changes that affect executable selection,
Node options, Git behavior or locale-sensitive results. Do not manufacture a
matching historical environment or silently ignore every environment input.
