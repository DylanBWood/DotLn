## Findings

### F1 — `npm run meta` prints the addition clause, never the promised removal, and can never mark a shortfall (blocking, criterion 12)

Criterion 12 requires that "`npm run meta` prints, per closed order, the promised removal beside the observed rows and marks a shortfall as a planning input."

`scripts/lib/meta.mjs:897` extracts the declaration with

```
/^\*\*Cost:\*\*\s*([\s\S]*?)(?=\n\s*\n|\n\*\*|$)/m
```

The `m` flag makes the `$` alternative inside the lookahead match end-of-**line**, so the lazy group terminates at the first physical newline. Every `**Cost:**` declaration under `docs/work-orders/` is hard-wrapped, and this project's house style opens that declaration with what the order *adds*. The captured text is therefore the addition clause alone, cut mid-sentence, and the removal clause is dropped.

Observed, `node scripts/meta.mjs --check`:

| Closed order | Printed "promised removal" | Removal clause present |
| --- | --- | --- |
| WO-126 | `adds one fast gate run per turn end (under 120 s), one cost line` (64 of 462 chars) | no |
| WO-128 | `adds one operator-run measurement series inside the order (five` | no |
| WO-129 | `adds one declaration lookup per suite and one explanation line per` | no |
| WO-130 | `adds one plain copy of the installed roots per fresh gate (43 MB of` | no |
| WO-131 | `adds path and environment declarations per narrowed suite and, where` | no |
| WO-127 | prints in full | yes — its declaration is a single unwrapped line |

WO-127 is the control that isolates the cause: it is the one recent declaration that is not hard-wrapped, and it is the one that prints completely.

The second clause fails for the same reason. The truncated string is the only input to the ceiling regex in `reconcileCost` (`scripts/lib/meta.mjs:391–396`), which searches for a "fresh (product) gate … under N s" promise. In every wrapped declaration that phrase lives after line 1, so `ceilingMs` is `null` and `outcome` can be neither `shortfall` nor `met`. All five rows above print `outcome unknown`. The shortfall-as-planning-input branch is therefore unreachable for every real work order — including WO-132's own Cost line, of which 59 of 1,209 characters are captured, so this order's own "under six minutes fresh" promise can never be reconciled against the very rows this verification produced.

Why the evidence gate does not catch it: the committed regression injects a synthetic single-line `cost` string directly into `reconcileCost` (`scripts/test-process-debt.mjs:3190–3247`) and never exercises the extraction at `meta.mjs:897`. The whole `costReconciliation` block is new in this order (`git diff HEAD -- scripts/lib/meta.mjs`), so this is not inherited behaviour that criterion 12 merely failed to improve.

Repair (one line plus one fixture): terminate the capture on a paragraph boundary rather than a line boundary — drop the `|$` alternative so the lookahead reads `(?=\n\s*\n|\n\*\*)` — and add a regression that extracts from a real wrapped work-order file rather than from an injected string.

### F2 — during a live gate the hooks refuse read-only Bash as a write, so "exactly two" is not established for shell reads (non-blocking, criterion 9)

I met this before I had read any of the implementation. While my own `npm test` was live in this worktree, three read-only commands were refused:

```
$ ls scripts/lib
$ grep -n "live gate\|liveGate" packages/compiler/src/feedback.ts | head -40
$ cd … && for f in scripts/lib/suite-replica.mjs …; do …; done; grep …
DOTLN_HARNESS_REFUSED: write may change gate inputs during active gate
scripts/test-runner.mjs (run cabd5ebb-09b1-4b05-913c-fad68c3d68f2, pid 33776).
```

The `Read` tool was admitted throughout the same window, which is how I kept working.

Mechanism. `packages/skeleton/src/harness-host.ts:2245` admits every `shell` tool into the live-gate guard. The read escape at :2272–2278 requires `permissionEffect(...) === "repo.read"`, true only for the literal `metadataCommand` allowlist at :1697–1729. The write-destination escape at :2289–2300 requires `shellWritePaths` (`packages/skeleton/src/harness-command.ts:307–359`) to return non-null, which it does only for `echo/printf/cat/pwd/true/false/touch/mkdir/tee/rm`. Everything else falls to the refusal at :2302. Admission is governed by whether the write set can be *bounded*, not by whether the command reads or writes — which is why `cat fixture.ts` is admitted during the same gate while `head -5 fixture.ts` is refused.

Judgment. Criterion 9 scopes the second kept refusal to "a write to gate inputs or the success record during the reviewer's live `npm test`". `ls scripts/lib` is not a write, so "refuse exactly two things" is not literally established for shell reads. Against that, and why I do not treat it as a defect of this order: the criterion's own fixture blesses opacity-based refusal, since the `for` loop and `$(...)` substitution it names are refused in-gate for exactly the same unbounded-write-set reason; the guard fails closed, so nothing can slip past it and no protection is lost; every refused read has an admitted equivalent through the Read, Grep and Glob tools and the metadata allowlist; and `git show HEAD:packages/skeleton/src/harness-host.ts` carries the same shape, so this order did not introduce the behaviour, only the claim about it. The cost is operator friction inside one gate window, which is real — it is the same class of friction WO-131's VER-001 recorded as O1.

I record this as a limit on criterion 9's claim rather than a repair the order owes. Two clean resolutions exist, both operator decisions: narrow the criterion's wording to say the live-gate guard refuses any command whose write set it cannot bound, or give the guard a read-only classification so the refusal matches the sentence. Either way F3 should follow.
