## Finding F1 — Unicode prose punctuation bypasses the exact-token contradiction guard

**Severity: moderate. Criterion 5 fails.**

**Expected.** WO-042 criterion 5 requires a contradictory authored note that
names an exact opposite-envelope effect id to reject with `INSPECTION
CONTRADICTION`. The promoted
[Authority inspection projection](../../product/04-interfaces.md#authority-inspection-projection)
contract makes whitespace and prose punctuation token boundaries while keeping
internal effect-id dots and colons significant and avoiding substring matches.

**Observed.** `inspectionAuthorityDiagnostics` in
[`authority.ts`](../../../packages/compiler/src/authority.ts) lines 210–233
tokenizes by excluding a small ASCII punctuation set and strips only trailing
dots and colons. Common Unicode punctuation remains inside the token. On the
current compiled source, an authored restriction against allowed effect
`repo.inspect` produces these results:

```text
"Never repo.inspect—ever."  -> ok: true
"Never repo.inspect–ever."  -> ok: true
"Never repo.inspect…ever."  -> ok: true
"Never repo.inspect, ever." -> ok: false; INSPECTION CONTRADICTION
"Never (repo.inspect)."     -> ok: false; INSPECTION CONTRADICTION
```

**Reproduction.** Build the packages, create a linked support from the authority
fixture with `claims: []` and
`inspection: { restrictions: [note] }`, then call `compileLoadout` with
`seiriEnvironment()` for each note above. The first three compile with empty
diagnostics; the final two produce the required diagnostic. I ran this directly
against `packages/compiler/dist`, independently of the new authority-evidence
generator.

**Impact.** An ordinary authored sentence can contradict an allowed effect and
still be accepted despite the documented guard. The note remains visibly
labeled non-enforcing, the projected GRANTS and RESTRICTIONS remain derived from
the effective envelope, and runtime authorization remains correct. The defect
therefore weakens the promised authored-note consistency check without widening
authority.

**Required repair.** Define and use one boundary rule that recognizes the
promised prose punctuation, including Unicode punctuation, while preserving the
complete exact effect id and the documented internal dot/colon behavior. Add
positive fixtures for at least em dash, en dash, ellipsis, and a curly-punctuation
case in both authored-note directions, plus the existing negative substring
cases. Re-run criterion 5, authority evidence, console fixtures, and the full
gate. No other verified surface needs reopening unless that change moves it.
