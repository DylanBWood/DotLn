## Findings for repair

### F5 — criterion 7: a non-top prune racing `git pack-refs --prune` makes refs/stash unreachable

**Severity:** medium. It is low-probability, but the damage is high: every retained stash vanishes from `git stash list` in every worktree until a manual ref repair. No object or reflog line is lost, and the recovery snapshot and reflog allow restoration.

**Expected:** unpublished and unnamed stashes stay retained, as they do under Git's own `stash drop` in the same interleaving.

**Observed:** on the entries-remain path, `dropInventoriedStash` writes a loose refs/stash and also removes the packed `refs/stash` row (`scripts/lib/stash-drop.mjs:143-155`). Git's `pack-refs --prune` releases `packed-refs.lock` before it prunes loose refs. If the prune runs in that gap and keeps the same top, the value still matches what pack-refs recorded, so Git deletes the loose ref. No packed row remains to resolve the ref. The pre-repair subject only locked `packed-refs` and never rewrote it.

**Reproduction:** Git 2.55.0 in a fresh repository.
1. Create three stashes, with the published `WO-901 integrate` entry at the bottom and a loose refs/stash.
2. Add 60,000 loose tags, which Git prunes before refs/stash.
3. Start `git pack-refs --all --prune`.
4. Once `packed-refs.lock` was gone and the packed stash row and loose ref both existed, call `pruneHarness(root, { apply: true, publishedRelease })`. It succeeded.

After pack-refs exited 0:
- `git rev-parse --verify refs/stash` failed and `git stash list` was empty.
- The reflog still held the two retained entries.
- Neither a loose ref nor a packed stash row remained.

A second run with 30,000 tags reproduced it, and `git update-ref refs/stash <last reflog sha>` restored the list. **Control:** the same interleaving with `git stash drop stash@{2}` left refs/stash resolving to the retained top and both entries listed. The packed row remained.

**Reachability:** the installed manuals document that `git gc` runs pack-refs by default (`gc.packRefs`) and that pack-refs prunes loose refs unless `--no-prune`. Ordinary commands trigger `gc --auto` (detached by default) and `maintenance run --auto` (`maintenance.auto` defaults to true), and several worktrees share this common dir.

D016's follow-up names Git's own behavior as the expected state: keep the packed row while entries remain. It also requires a concurrent pack-refs regression.

## Judgment and limits

The intended outcome is that the next order meeting a WO-111 defect runs a command instead of improvising. The repair achieves that for items 1–6, 8 and 9, and for item 7 in sequential use, including the real repository's packed stash stack. F5 keeps item 7 from being safe to run while Git maintenance may be active. That is exactly the retained operator work criterion 7 protects, and the hazard D008 cites for its locks.

Weighed against the traps:
- **Rule beating and drift to low performance:** these would follow from passing on green sequential fixtures and a clean real-state replay while a documented background Git operation can erase the retained entries' ref.
- **Seeking the wrong goal:** judging the removal count rather than the survival of what must be retained.
- **Policy resistance:** the repair must keep the sound sequential behavior, locks, snapshot and inventory ordering while adopting Git's own packed-row rule.
- **Escalation and tragedy of the commons:** these favor one bounded seam repair with a concurrent regression over a redesign or a broad refactor of observations O20–O24.
- **Success to the successful:** the previously green fixtures do not make the packed path authoritative under concurrency.
- **Shifting the burden to the intervenor:** passing would leave the operator to discover an empty `git stash list` and hand-repair refs.

Under Naive Interventionism, the repair should change only the entries-remain packed-row handling and add its regression. NoOp leaves a reproduced way to hide all retained stashes, so it does not meet the order's objective.

Limits:
- The race probe widens Git's window with 60,000 loose tags. The natural window is shorter, and its real-world frequency is unmeasured.
- Observations marked reading or suspected were not executed.
- Criterion 5 rests on unchanged code, VER-001's reproduction and this gate's suite, not on a fresh probe.
- The session's own hooks come from the observer under judgment.
- A fresh VER must judge any repair.
