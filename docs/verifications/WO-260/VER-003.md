## Finding

**F1 — follow-up, escape. A shorthand property hides a `GIT_*` name from
the surface check.** The JavaScript reading in
[scriptReading](../../../scripts/lib/git-surface.mjs) names a `GIT_*`
identifier only after a member dot, or before a colon in an object literal.
The module's own rule says it names one "as an object key". A shorthand
property is an object key, so in

```js
const GIT_CONFIG_GLOBAL = "/dev/null";
spawnSync("git", ["status"], { env: { ...process.env, GIT_CONFIG_GLOBAL } });
```

the scoped name reaches the child Git while the check names nothing. That
shape would let the Observed gap's sixth row recur unnoticed, since Git
2.31.0 ignores `GIT_CONFIG_GLOBAL`. The reproduction is the `js observation: GIT_*
shorthand property` case of
[verification-003-surface.mjs](../../evidence/WO-260/verification-003-surface.mjs).

Severity: follow-up. Criterion 4's clauses name the `ls-tree --format` pair,
the floor mismatch and the export list, and each holds. A search of
`scripts/` and `packages/` finds no `GIT_*` shorthand property, so the
candidate's check is unaffected. The check is new, so `main` had no
behavior this breaks.

Class `escape`: the defect is in the verified subject and inside the
verification's instructed scope. The reader existed when VER-001 and
VER-002 ran, and this repair did not touch it.

The repair rule: name a `GIT_*` identifier written as a shorthand property
as the reading names one before a colon, and add a fixture case.
[WO-260-D037](../../evidence/WO-260/decisions.md#wo-260-d037--ver-003-passes-a-shorthand-environment-name-property-is-boarded-as-a-follow-up)
records the judgment and its reopening condition. `npm run meta` registered
