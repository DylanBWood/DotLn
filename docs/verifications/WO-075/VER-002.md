## F1 — Provenance reads honor Git replace refs

**Severity:** minor. **Route:** follow-up, non-blocking; it breaks no
criterion and no behavior `main` had.

**Expected:** an export that names commit C carries only C's build.

**Observed:** in a fresh scratch clone, the probe appended
`export const verifierReplaced = 1;` to `packages/kernel/src/index.ts` and
wrote that content as a blob. It ran `git replace <original> <replacement>`,
then marked the path `assume-unchanged`. Git status was empty. The export
exited 0 and named the unchanged commit, while `packages/kernel/dist/src/index.js` and
`index.d.ts` differ from the reference rebuild.
`git --no-replace-objects cat-file -p HEAD:packages/kernel/src/index.ts`
shows the original without the edit. `dirtyPinnedInputs` reads the commit
with `ls-tree` and `cat-file --batch`
(`scripts/lib/git.mjs` `readGitObjects`), and both apply refs/replace. No
script under `scripts/` sets `--no-replace-objects` or
`GIT_NO_REPLACE_OBJECTS`.

**Why not blocking:** Git presents a replacement as the commit's content to
every ordinary command in that repository. The kit-file reader `main` already
has reads through the same view (`git show HEAD:scripts/launchpad.mjs`:
`readKitSources` uses `ls-tree` and `readGitObjects`). Reaching the gap also
requires deliberately writing a replacement object equal to the edit. No
accidental edit, index flag or ignore rule reaches it alone: both F1 classes
and the `skip-worktree`, missing-file and symlink variants refuse.

**Rule a repair must hold:** the export's commit reads, for kit sources and
pinned inputs alike, use the commit's original objects
(`--no-replace-objects` or `GIT_NO_REPLACE_OBJECTS=1`) or refuse while
refs/replace exist. A regression must show a replaced blob that equals an
`assume-unchanged` edit refusing before the destination is created. D017 carries this
as its follow-up.
