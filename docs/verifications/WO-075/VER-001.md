## F1 — Local inputs can be exported as the named commit's runtime

**Severity:** major. **Route:** blocking, criterion 1.

**Expected:** exported runtime paths and bytes equal a clean rebuild of the
manifest-named commit. A local input mismatch must either refuse before any
destination write or be excluded by building only the commit's inputs.

**Observed:** both mismatching-input exports exit 0 and announce that their
compiled runtime was built from the unchanged commit's package sources.
The manifest hashes accurately describe the exported files, but those files
do not equal the commit's build.

1. In a clean scratch clone, ignore the directory
   `packages/kernel/src/verifier-ignored/` through `.git/info/exclude`, then
   put `plant.ts` there, exporting `synthetic-verification-payload`. Git
   reports `!! packages/kernel/src/verifier-ignored/`. Export succeeds with
   272 runtime files; `verifier-ignored/plant.js` and its declaration are
   manifest-listed. The clean rebuild has 270 files and no plant.
2. In another clean scratch clone, install offline, run
   `git update-index --assume-unchanged packages/kernel/src/index.ts`, then
   append `export const verifierStatusHidden = 1;`. Git status is empty,
   but the source bytes differ from the commit. Export succeeds with 270
   files, and its compiled kernel index contains the synthetic export and
   differs from the clean rebuild.

The cause is visible in
[dirtyPinnedInputs](../../../scripts/launchpad.mjs), line 583: its ordinary scan
trusts Git status, and its ignored scan uses `--ignored=matching` followed by
an extension filter. An ignored directory entry has no compilable extension
and is dropped. A tracked input hidden by `assume-unchanged` is absent from
status. `atomicBuild` then copies the actual work-tree source/test files into
the build staging area. Neither the later manifest hashes nor bundle equality
can establish that those inputs came from the named commit.

The individually ignored `.ts` control correctly refuses before destination
creation. The clean rebuild control passes. These bound the finding to the
input guard, rather than a general build or manifest failure. The missing
local-terms list in the synthetic fixtures is not the cause: screening terms
does not prove commit provenance, and the individual-file refusal works
without a list.

[WO-075-D014](../../evidence/WO-075/decisions.md#wo-075-d014--verification-f1-the-build-input-check-misses-source-bytes)
records the defect, named repair follow-up, alternatives and reopening
condition. Repair must prove actual input bytes and paths against the commit
regardless of Git status metadata, or build only commit bytes. Add both
regression cases while retaining harmless ignored-file admission and the
clean export checks. The verifier leaves implementation repair to `resume: fix`.
