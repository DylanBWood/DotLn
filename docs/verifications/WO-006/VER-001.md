## Findings

### 1 — Blocking. The harness runbook and ADR-0003 document a Claude posture the machine contradicts, and that ADR-0003 rejects

`docs/AI-HARNESS-SECURITY.md` §Claude Code prints the local block to restore as
`{"sandbox": {"enabled": true, "autoAllowBashIfSandboxed": false}}`, its
§Current posture table records command review as "sandboxed Bash uses regular
permissions", and its §Undo frames auto-allow as the *rollback* direction.
ADR-0003 §Decision 2 requires routing sandboxed Bash "through explicitly pinned
`default` regular permissions", and ADR-0003 §Alternatives rejected names **"Use
Claude's sandboxed-Bash auto-allow mode"** as rejected because it "weakens the
review boundary that this setup exists to provide."

Effective state read across all four settings layers during this verification:

| Axis | Documented | Actual | Layer |
| --- | --- | --- | --- |
| `sandbox.enabled` | `true` | `true` | user |
| `failIfUnavailable` | `true` | `true` | user |
| `allowUnsandboxedCommands` | `false` | `false` | user |
| SSH/key denials | present | 14 deny rules + `~/.ssh` credential deny + 7-path `denyRead`, all intact | user |
| `autoAllowBashIfSandboxed` | `false` | **`true`, persisted** | main-checkout `settings.local.json` |
| `defaultMode` | `default` | `default` — Accept Edits was **not** persisted | user |

The main checkout's `.claude/settings.local.json` additionally carries eleven
`permissions.allow` Bash entries that neither document mentions, several of them
evidently accumulated during WO-006's own execution session — including
`Bash(shasum -a 256 docs/product/08-publication-compiler.md)`, the staleness
demonstration's own hashing command. Because the runbook itself notes that
Claude applies the main-checkout local file to linked worktrees, those rules are
in force repository-wide rather than scoped to the session that created them.

AC8 requires the runbook to inventory the *actual* current posture and to record
the tested date and versions. It does not. This is a stated fact in a
same-diff deliverable contradicted by the machine it describes, which the
Discipline clause classifies as an evidence defect that process immaturity never
excuses.

**Timing, stated honestly.** The permission baseline changed *during* this
verification: the operator switched to sandboxed-Bash auto-allow mid-run because
Manual mode produced an untenable approval storm under parallel subagents, and
directed that the stale documentation should prevent a clean pass until
reconciled. The defect is therefore the record, not the settings, and the
underlying operational decision is sound. The settings files are gitignored and
outside the committed subject; the documentation that describes them is not.

**Repair note.** Three surfaces must move together, and one is not a simple
edit. ADR-0003 is **Accepted** with `Amendments: None`; reversing an entry in
its own §Alternatives rejected is a decision change, so the execution guide's
"Settled is settled" rule and ADR-0003's own closing sentence require an
Amendments entry or a superseding record, not an in-place rewrite of the
Decision body. The amendment should record that parallel-subagent operation made
Manual untenable, that auto-allow was accepted with the compensating controls
(fail-closed startup, no unsandboxed fallback, intact SSH denials) still in
force, and the dated re-test. The runbook's §Current posture, §Claude Code
enable block, and §Undo all need the corresponding correction, and the eleven
persisted allow rules should either be documented or cleared. Note also that
`defaultMode` remains `default` on disk, so the intended Accept Edits mode is
session-only and will not survive a new session.

### 2 — Material. The captured staleness demonstration records lock hashes that no shipped artifact contains

`docs/publication/staleness-demonstration.md` §2 presents a console block as the
literal output of `npm run publication:check -- --expect-stale`. It records:

```text
STALE everyday-ai-user-toc.md: source lock d7af784805e43d70…
STALE software-engineer-toc.md: source lock b204c48e6f24f60a…
```

The shipped editions carry different locks entirely. Verified first-hand by the
lead verifier:

```text
$ grep -A1 '^Source lock:' docs/publication/*-toc.md | grep sha256
docs/publication/everyday-ai-user-toc.md-`sha256:74368b2f651447df…`
docs/publication/software-engineer-toc.md-`sha256:51ccde4962249f76…`

$ node scripts/check-publication.mjs --print-locks
LOCK everyday-ai-user-toc.md: sha256:74368b2f651447df…
LOCK software-engineer-toc.md: sha256:51ccde4962249f76…
```

None of the four hashes in the transcript appear anywhere else in the tree. The
cause is mechanical and was independently reproduced by two audits: the
demonstration was captured at 14:53:08, four product documents cited by both
editions were then edited between 15:29 and 15:42, and both edition lock lines
were regenerated at 15:42:18 with no re-capture. The receipt's "refreshed
edition locks" phrase acknowledges the refresh but sits in a different file.

**This does not impugn the mechanism.** The guard genuinely guards, and the
audit reproduced the full loop in an isolated copy: applying the exact patch the
document quotes yields the recorded source-file hash
`e5a7aff8588e7c11ebb6d16dc5a37dd0eee1c264ff1b060943d35d12b6e5c98c`, flips both
editions to `STALE`, makes the checker exit 1 in normal mode and 0 under
`--expect-stale`, and the revert is complete in the delivered tree. Attack
testing confirmed the lock catches interior byte changes, whitespace-only
interior edits, heading renames, section deletion, and missing lock lines, with
correct per-edition precision. AC4's substance — change a source claim, both
editions flag stale, revert — is met.

What fails is AC4's final clause and the evidence gate's first item: *the
demonstration is captured*. The artifact is a capture of a superseded state, and
its trap is that everything else in it still reproduces exactly, so it reads as
current. A reviewer re-running it gets four mismatching numbers with no note
explaining why. The execution guide's remedy applies directly: record the
discontinuity as a dated note where a reader will hit it, or re-run and re-
capture — never back-fill to make history look tidy.

### 3 — Non-blocking. `headings()` can silently drop product headings while reporting full coverage

`scripts/check-publication.mjs:80`. The fence tracker toggles on any line
matching `/^\s*(```+|~~~+)/` and compares only the first character, so a
fence-looking line *inside* a fenced example closes the tracker early. With an
odd number of such lines the tracker believes it is inside a fence and every
subsequent ATX heading in that document is dropped from `expected` with no
diagnostic. Demonstrated in an isolated replica: a ` ```` `-delimited block
containing one inner ` ``` ` line, followed by a genuine `## …` section, makes
the checker print `PASS index coverage: 125/125 product headings indexed` and
`PASS publication bootstrap checks` and exit 0 while that section has no index
row.

Latent today — no current product document contains a nested fence, and all 125
present anchors were independently confirmed correct. But this is the
guard-that-does-not-guard class, and
`docs/product/08-publication-compiler.md` is precisely the document most likely
to grow a Markdown-fence example.

### 4 — Non-blocking. `slugBase()` strips underscores, enforcing anchors GitHub does not create

`scripts/check-publication.mjs:55`. `stripInlineMarkdown`'s
`.replace(/[\\*_~]/g, "")` removes literal underscores before slugging, but
GitHub's slugger preserves `_`. For any heading containing an underscore the
checker rejects the anchor that works and demands one that jumps nowhere.
Demonstrated in the replica: a `## The resume_state field` heading indexed with
its true anchor produces `FAIL missing …#the-resumestate-field` and
`FAIL extra …#the-resume_state-field`. The same unconditional stripping
mis-handles reference-style and nested-bracket links.

Latent today — no current product heading contains an underscore. Recorded so a
future author does not resolve the failure by writing the broken link the
instrument asks for.

- **`--print-locks` exits 0 on a stale tree.** Documented behaviour — the source
