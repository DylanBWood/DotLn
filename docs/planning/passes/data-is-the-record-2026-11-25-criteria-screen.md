#### Steps flagged under test (D)

**WO-289**
- **Step 4** (`packages/skeleton/src/harness-host.ts`, prompt context; also the boy-scout item on `promptRoute`):
  - It adds a read of the host's transcript (the JSONL at `transcript_path`), looking for an interrupt row after the prior prompt. The host's format is undocumented, and the existing reader matches the interrupt by regex on message text (line 1769).
  - It adds a read of the session journal's prompt and Stop rows. The journal is kit-written JSON whose row shapes exist only in code. A filename search found no schema file for the journal, the session state or the control log, though code validators do exist (inference).
- **Step 8** (`packages/compiler/src/operator-control.mjs`):
  - The existing prompt-prefix reader (`/^(analysis|operator override):/`, line 18) gains a match on dispatch phrases. That is a read of prompt text, and the phrase set is a code table (`harnessPromptIntent`'s regex at `packages/compiler/src/harness.ts`:199, plus the role intents in `contributor.ts`).
  - It also changes meaning: a dispatch phrase now ends analysis.
- **Test-side reads of generated Markdown** (emitted `SKILL.md`): the checks of steps 1, 2 and 5. Criterion 9 also reads hand-written Markdown: `CLAUDE.md`, `scripts/kit/CLAUDE.template.md` and product 07.

**WO-291**
- **Step 1** (`scripts/lib/work-order-repository.mjs`, `parseRepositoryDeclaration`) makes an existing Markdown reader accept more forms. The reader is `readWorkOrderHeader` plus a regex on the `**Repository:**` line, and the step also changes the line's meaning (an id alone now means the base branch's tip at start).
- **Steps 5–7** (`scripts/resume.mjs`, `scripts/lib/control.mjs`, `scripts/work-orders.mjs`, `scripts/lib/work-order-workstream.mjs`) only change what readers do with the parsed form. They add no read.
- **Step 10** (`scripts/lib/plan-continuation.mjs`) reports the first changed line's number. That is a byte or line comparison of the order file, not a Markdown parse (inference; I did not read `executionAppendix`).

**WO-290:** no new read. It reads session state, the journal, the control log and the host's Stop input, which is validated at `harness-host.ts`:384–389. Its rejected alternative of reading the session's message is kept out.

**WO-292**
- **Step 3** (`scripts/lib/drive-session.mjs`) adds a decision, ending the drive, that rests on fields `refusalFindings` (`scripts/lib/drive-diagnostics.mjs`:586–629) pulls out of the hook's refusal text in the host's stream. Those fields are codes matching `DOTLN_[A-Z_]+` and stop ids matching "This is stop <id>[,;]". Step 5 (`scripts/lib/drive-account.mjs`) prints from the same fields.
- **Step 7** (`harness-host.ts`, `measureHarnessUsage`) extends to target lanes an existing read of the host's transcript (`collectSessionUsage` and `sessionTranscript` in `packages/skeleton/src/usage-observation.mjs`).
