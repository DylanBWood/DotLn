### Whose rules these are

The split is an accepted decision and not a new idea. ADR-0006, accepted
on 2026-09-03, says a private owner may want a low-ceremony or fully
permissive implementation and that the platform is not its owner's parent;
it puts operating policy, security posture, evidence standards and
workflow defaults with an implementation, and calls the Clean Room rule
this repository's governance. `README.md` says the same in the sentence
the operator pasted.

What ships contradicts it. Every instance receives the author's ten
feedback units, each already marked `personal-profile` in a field nothing
reads, and thirty-four shared role rules as fixed text. The build overlay
removes only the ten optional supports, and its only other removal drops
the whole bundle. An owner's edit to an emitted role file fails the
harness check and is overwritten. The kit's own feature page prints "Not
electable" over the refusals, the writer reservation and the clean-room
floor. The documents that state the split stay in core, so an instance is
never told.

Why it has not moved, from the doctrine census's dated record: the request
was narrowed three times to something smaller (on 2026-10-07 to the
existing support switches, on 2026-10-30 to a `scope` field in the feature
registry, and on 2026-11-03 WO-241 closed its carry-in as that field), and
the two follow-up rows that would have reopened it waited on events no
scheduled order could produce: a second owner (FUP-0082), and the closing
of WO-207 and WO-096, which were then moved to "Not now"
(FUP-edefd92233980b63). A second owner now exists: the work instance.
